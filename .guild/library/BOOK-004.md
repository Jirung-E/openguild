# 플러그인 구조 개편 설계

2026-09-17 ~ 18 admin 과의 논의로 정한 것. 전체 작업은 [[DEV-402]] 아래 하위 퀘스트로 나뉜다.

## 왜 바꾸나

지금 플러그인은 **정의 파일 하나 + 스크립트 하나(선택) + 동작 하나**다. 스크립트는 "보낼까(`should_send`)" 와 "무엇을 보낼까(`payload`)" 만 정한다.

좋은 점은 단순하고 안전하다는 것이다 — 스크립트는 아무 일도 못 하고, 보낼 곳은 정의 파일에 박혀 있어 허용할 때 그것만 보면 된다. 길드는 플러그인을 기다리지 않아 플러그인이 망가져도 멈추지 않는다.

한계가 치명적이다.

1. **보낼 곳이 하나뿐** — 이벤트마다 다른 곳으로 보내려면 플러그인을 여러 개 만들어야 한다.
2. **한 번에 한 가지만** — "알리고 백업도" 가 안 된다.
3. **길드에 일을 시킬 수 없다** — 알림·백업·퀘스트 수정이 안 된다. `run` 으로 `openguild` 를 부르면 느리고 OS 마다 다르고 무한 반복 위험이 있다.
4. **결과를 못 받는다** — "AI 에게 묻고 답을 댓글로" 가 안 된다.
5. **막거나 고칠 수 없다** — 기다리지 않으니 "조건이 안 맞으면 완료 막기", "저장 전에 제목 고치기" 가 안 된다.
6. **받은 이벤트만 본다** — 댓글 이벤트에서 그 퀘스트의 태그를 모른다.
7. 여러 이벤트를 받으면 `if e.event == …` 가 길어진다.
8. 화면에 보이는 이름(상태 "진행 중")을 모른다.

1·2 는 플러그인 구조의 문제이고, 스크립트를 어떤 모양으로 쓰느냐와는 별개다. 둘 다 이번에 바꾼다.

## 결정

### 정의 파일 — TOML

- `plugin.json` 대신 TOML. 주석을 쓸 수 있고 들여쓰기가 뜻에 영향을 주지 않아 보기 좋게 맞출 수 있다.
- YAML 은 들여쓰기 실수가 조용히 뜻을 바꾸고(`on` 이 참/거짓으로 읽히는 문제까지), Rust 쪽 라이브러리가 불안정해 택하지 않았다. 이 프로젝트는 이미 TOML 을 쓴다.
- `{ … }` 인라인 표는 한 줄에만 쓸 수 있다 — 긴 조건은 `[handlers.when]` 으로 적는다.
- 플러그인 기능은 아직 출시 전이라 **옛 형식을 계속 받을 필요가 없다.** 예제와 테스트 길드의 플러그인은 새 형식으로 옮긴다.

### 줄 단위 핸들러 — Bevy 의 시스템 등록과 같은 생각

정의 파일에 "언제 → 무엇" 을 줄마다 적는다.

```toml
name    = "telegram-quest-status"
scripts = ["main.rhai", "alerts.rhai"]

[[handlers]]                          # 액션 — 스크립트 없이 바로
    id   = "새퀘스트"
    post = ["quest.created"]
    [handlers.action.post]
        url = "https://hooks.example/new"

[[handlers]]                          # 스크립트 함수 호출
    id   = "댓글"
    post = ["comment.added"]
    with = ["subject"]
    call = "댓글_알림"
    [handlers.when]
        "subject.tags" = "notify"

[[handlers]]                          # 바뀌기 전 — 막기
    id   = "리뷰"
    pre  = ["quest.status_changed"]
    with = ["subject"]
    call = "리뷰_확인"
    timeout_ms = 3000
```

- **단계** — 줄마다 `pre`(바뀌기 전) 또는 `post`(바뀐 뒤) 중 **하나**. 후보(`before`/`after`, `on`+`phase`, `pre_execute`, `pre:` 접두어) 중 짧고 짝이 맞고 기존 `pre:` 와 같은 말인 것을 골랐다. `before`/`after` 는 순서 지정과 헷갈려 뺐다.
- **동작** — 줄마다 `call`(스크립트 함수) 또는 `action`(`post`/`run`) 중 **하나**. 둘 다거나 둘 다 없으면 불러올 때 오류. 한 플러그인 안에서 섞어 써도 된다. `call` 이 하나도 없으면 `scripts` 가 필요 없다.
- **함수 이름은 자유.** 여러 줄이 같은 함수를 불러도 된다. 스크립트에 없는 함수를 적으면 불러올 때 오류.
- **`when` 은 거름망, 함수는 할 일.** `when` 을 통과해야 함수가 불린다. 예전의 `when` 대 `should_send` 처럼 거름망이 두 개인 구조가 아니라 우선순위 혼란이 없다. (`pre` 함수만은 막기를 정하므로 거름망이지만, 역시 `when` 뒤에 불린다.)
- **허용 화면**은 스크립트를 읽지 않고도 "언제 무엇이 도는지" 를 보여 줄 수 있다 — 등록이 코드가 아니라 데이터라서다.

| Bevy | 여기 |
|---|---|
| 시스템 함수 | 스크립트 함수 (`call`) |
| `add_systems` | `[[handlers]]` 한 줄 |
| `run_if` | `pre`/`post` + `when` |
| `PreUpdate` / `Update` | `pre` / `post` |
| `before` / `after` | (지금) 적힌 순서 → (목표) `run_before` / `run_after` |
| 시스템 인자의 쿼리 | `with` |
| 시스템이 쓸 데이터를 미리 밝힘 | 권한 선언 |

검토한 다른 모양: 함수 하나로 전부 받기(들을 목록과 처리가 어긋나도 조용함), 이벤트 이름 규칙의 함수(`on_quest_created` — 묶음 구독이 어렵고 오타면 조용히 안 불림), 둘 다 허용(우선순위 규칙 필요).

### 한 이벤트에 여러 줄이 걸릴 때

- **지금은 적힌 순서대로** 돈다. `pre` 에서 두 줄이 같은 항목(예: 제목)을 고치면 뒤 줄이 앞 줄의 결과를 받아 다시 고친다 — 결과가 항상 정해진다.
- **목표는 Bevy 식** — 줄 `id` 로 `run_after` / `run_before` 를 적고, 적지 않은 줄끼리는 순서를 보장하지 않는다. 순환이면 불러올 때 오류, 같은 플러그인 안에서만.
- 그때도 **적힌 순서를 "순서 지정이 없을 때의 기본값"으로 남긴다** — 그동안 만든 플러그인이 깨지지 않게. 순서 없는 줄 둘이 같은 항목을 고치는 문제는 그때 다시 정한다.

### 조건 `when`

- 같음 / 목록 중 하나 / (필드가 목록이면) 포함. 모든 조건을 만족해야 통과(AND).
- `with` 로 읽어 온 데이터에도 쓴다(`"subject.tags" = "notify"`).
- 액션 줄과 스크립트 줄이 같은 문법을 쓴다. 더 복잡한 조건(또는, 크기 비교, 설정값에 따라)은 함수 안의 `if` 로.

### 받을 데이터 `with`

- 모든 이벤트에 **대상(`subject`)** — 퀘스트·캠페인·도서관 문서·규칙 중 하나 — 을 같은 모양으로 싣는다.
- `with` 에는 대상과 연결된 것만 적는다(`subject`, `parent`, `campaigns` …). 외울 것은 이벤트 55개가 아니라 **문서 종류 네 개의 연결 관계**뿐이다.
- 길드가 읽어서 함수 인자로 넘긴다(`fn 댓글_알림(e, subject)`). 스크립트 안에서 조회 함수를 부르는 것보다 낫다 — 무엇을 읽는지 정의 파일에 보이고, 부르기 전에 한 번에 준비된다.
- 이벤트에서 못 쓰는 이름을 적으면 불러올 때 "쓸 수 있는 것" 목록과 함께 오류. `openguild plugin events` 와 스키마가 이벤트별 목록을 보여 준다.
- 이것이 "다른 문서 읽기" 의 모양이다. 허용 화면에 "퀘스트를 읽음" 으로 표시한다(스크립트가 이벤트와 무관한 내용도 밖으로 보낼 수 있게 되므로).
- Bevy 의 쿼리처럼 **시간이 되면 조건에 맞는 목록을 받는** 핸들러는 따로 뺐다 — [[REQ-026]].

### 스크립트가 시키는 일 (명령)

- 길드 명령 대부분을 연다. 먼저 **알림 · 백업 · 외부로 보내기 · 프로그램 실행**. 이름은 CLI 와 맞춘다.
- **권한을 정의 파일에 미리 밝힌다.** 허용 화면에 그대로 보이고, 밝히지 않은 명령을 부르면 오류.
- 명령은 **바로 실행하지 않는다.** 모았다가 함수가 끝나고 길드 잠금이 풀린 뒤 차례로 실행한다 — 스크립트 도중 길드가 바뀌지 않고, 잠금 안에서 자기를 기다리는 교착이 없고, 시간 제한·실패 기록을 한 곳에서 한다. 테스트도 쉬워진다(명령을 기록만 하면 된다).
- 알림이 뜨는 곳 — 앱: 알림 / CLI: stderr 한 줄 / 서버: 로그 또는 접속 화면.
- 무한 반복 막기([[DEV-401]])의 "누가 일으켰는지" 를 명령 실행에도 쓴다.

### 기다리기

- `pre` 줄: 이유 문장을 돌려주면 **막고**, 바꿀 칸을 돌려주면 **값을 바꾼다.**
- `post` 줄도 **끝날 때까지 기다리게** 할 수 있다(예: 백업 복사가 끝나야 명령이 끝남).
- 줄마다 시간 제한과 실패 시 동작을 적는다. **안 적으면 그냥 진행** — 플러그인이 망가져도 길드는 계속 쓸 수 있게.
- 기다리는 중에도 외부 서비스(AI 등)를 부를 수 있다.

### 스크립트 여러 개

- 자기 파일은 `scripts = [...]` 에 적는다. 적힌 파일의 함수는 한 공간에 모여 이름만으로 서로 부른다. 이름이 겹치면 불러올 때 오류.
- 여러 플러그인이 같이 쓰는 도구는 `import "경로" as 이름`. **폴더 밖도 된다.** 경로는 글자 그대로 적고(불러올 때 알 수 있게), 허용 화면에 목록을 보여 준다. **처음에 한 번만 허락받고**, 그 파일이 바뀌어도 다시 묻지 않는다 — 허용 화면에 그 사실을 적는다. 공유할 플러그인은 상대 경로를 권한다.
- 이것은 코드를 불러오는 이야기다. 스크립트가 임의 파일을 읽고 쓰는 것과는 다르다.

### 편의 함수

스크립트는 파일을 못 읽으므로(샌드박스), 슬러그를 사람 말로 바꾸는 일은 **코어가 읽어 주는 함수**로 준다.

| 함수 | 주는 것 |
| --- | --- |
| `guild_name()` | 길드 이름 |
| `status_name(슬러그[, "ko"\|"en"])` | 상태의 화면 이름 (`in_progress` → "진행 중") |
| `status_info(슬러그)` | 그 상태가 아는 것 전부 — `#{ slug, ko, en, color, done, order }` |
| `type_name(접두어)` | 타입 설명 (`DEV` → "일반 개발 작업") |
| `type_info(접두어)` | `#{ prefix, description, color }` |
| `link(종류, 아이디)` | 그 문서로 가는 주소 — `OPENGUILD_WEB_BASE` 가 있으면 전체 주소, 없으면 앱 안 경로 |
| `now()` / `ago(시각)` | 지금 시각 / "3시간 전" |
| `truncate(글, 수)` / `plain_text(마크다운)` | 글자 수로 자르기 / 표시 기호 덜어내기 |

읽기만 하고 밖으로 나가지 않으므로 권한으로 밝히지 않는다. 모르는 슬러그는 슬러그 그대로 돌려준다 — 글 안에서 빈칸이 되는 것보다 낫다.

**언어는 부르는 쪽이 정한다.** 인자를 안 주면 이 기계의 언어 설정을 따르지만, 스크립트가 글을 보내는 곳(텔레그램 방, 팀 웹훅)의 언어는 이 기계 설정과 다를 수 있다. 그래서 `status_name(슬러그, "en")` 처럼 고르거나, `status_info()` 로 **두 언어를 다 받아** 쓰는 쪽을 고를 수 있게 했다. 타입 파일에는 설명 한 줄뿐이라(언어가 하나) 타입에는 언어 선택이 없다 — 타입에도 두 언어를 두려면 파일 모양부터 바꿔야 한다.

`status_info().done` 은 "이게 완료로 세어지는 상태인가" 다. 이게 없으면 스크립트가 `done`/`closed` 같은 슬러그를 외워 박게 되고, 길드가 상태를 새로 만들면 조용히 틀린다.

### 허용 화면

무엇에 동의하는지는 **줄마다** 보여 준다 — 정의 원문만 찍으면, 줄이 여럿이고 줄마다 조건·읽는 데이터·기다림이 붙는 지금은 읽는 사람이 스스로 조립해야 하고 결국 안 읽고 허용하게 된다.

- 줄 하나씩: 언제(바뀌기 전/뒤 + 이벤트) → 무엇(함수 또는 동작), 조건, 읽는 데이터, 기다리는지, 그리고 **바뀌기 전 줄이면 "막거나 값을 바꿀 수 있음"**.
- 길드에 시킬 수 있는 일(권한), 나가는 곳 전부, 불러오는 파일("바뀌어도 다시 묻지 않음" 을 여기서만 알린다).
- 정의가 지목한 환경변수 **이름**. 값은 싣지 않는다 — 이 뷰는 HTTP 로도 나간다.
- 스크립트 원문은 그대로 유지. 요약은 읽기 위한 것이고 원문은 확인하기 위한 것이라, 하나만 있으면 한쪽이 아쉽다.
- 여럿을 한 번에 허용할 때는 한 줄 요약이지만 **가장 센 것**(막을 수 있음 · 권한 · 나가는 곳)은 빠지지 않는다.

CLI(`plugin allow`, `plugin list`)와 앱(관리 → 플러그인)이 같은 재료(`plugins::summary` / `PluginView`)를 쓴다 — 두 화면이 다른 사실을 말하면 안 된다.

### 도구

- **스키마 파일** — `openguild plugin schema --out <파일>`. `plugin.toml` 첫 줄에 `#:schema <경로>` 를 적으면 편집기(VS Code 의 Even Better TOML 등)가 자동 완성·오류 표시를 한다. 이벤트 이름과 `with` 목록은 **지금 이 버전이 아는 것**에서 만들어지므로 문서처럼 낡지 않는다. 줄 안에서 값끼리 걸리는 규칙(이 이벤트가 주는 `with` 만)은 스키마로 못 적으니, 진짜 검사는 적재와 `check` 가 한다.
- **`openguild plugin check [폴더]`** — 적재가 하는 검사를 미리 돌리고(오류), 돌긴 하지만 거의 실수인 것도 짚는다(경고: 아무도 안 부르는 함수, 안 쓰는 권한, 선언 안 한 권한, `scripts` 에 빠진 파일). 폴더를 지목하면 길드가 없어도 된다. 오류가 있으면 종료 코드가 1 — 에이전트와 CI 가 성공/실패로 읽는다.
- **`openguild plugin test [폴더]`** — 폴더의 `*.test.rhai` 안 `test_` 함수들을 돌린다. `fire(이벤트, 값[, with 데이터])` 가 **실제와 같은 실행기**로 돌아(줄 고르기·`when`·`with`·순서) 불린 줄·나온 명령·막힘·바뀐 값·조용히 넘어간 문제를 돌려준다. 다른 것은 둘뿐 — 명령은 적히기만 하고, `with` 는 길드 파일 대신 시험이 넘긴 값을 쓴다(길드 없이 돈다). `set_config(키, 값)` 은 그 시험 하나에만 먹는다. 확인은 `assert` / `assert_eq`(무엇이 달랐는지 찍는다). 실패가 있으면 종료 코드 1.
- VS Code 전용 확장은 지금 만들지 않는다.

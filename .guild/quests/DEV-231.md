DEV-227 이 type/status/rule 을 단수형으로 통일하며 복수형(types/
statuses/rules)을 전부 alias 로 남겼는데, 사용자가 재검토 후 정책을
케이스별로 조정 — "rules만 지워라".

## 결정
- `type`/`status`: 복수형 alias(`types`/`statuses`) 유지 — DEV-062
  이래로 bare 호출(`openguild types`)이 list 로 떨어지던 실사용 관행이
  있었으므로.
- `rule`: 복수형 alias(`rules`) 완전 제거 — `RulesCmd::sub` 가 애초부터
  `Option` 이 아니라 필수였어서 bare 호출 관행 자체가 없었음. 남길
  이유가 없다는 판단.
- `rule new`/`rule create` 는 그대로 유지(사용자가 명시적으로 이건
  안 지워도 된다고 확인) — new 가 canonical, create 는 alias.

## 변경
- `Command::Rules` 의 `#[command(name = "rule", alias = "rules")]`
  에서 `alias = "rules"` 제거.
- 테스트: `cli_singular_type_status_rule_parse_same_as_plural_alias`
  를 `cli_singular_type_status_parse_same_as_plural_alias` 로 축소
  (type/status 만) + `cli_rule_singular_only_no_plural_alias` 신설
  (`rules` 가 이제 에러나는지 검증).
- docs/AGENTS_OPENGUILD_USAGE.md, docs/USAGE.md 의 "rules alias 도
  동작" 문구 정정.
- cli-command-naming 규칙 갱신 — "복수형 alias 유지 여부는 케이스별
  판단" 으로 원칙 조정.

## 테스트 방법
- `openguild rule list` → 동작.
- `openguild rules list` → 에러(unknown subcommand).
- `openguild type`/`types`, `status`/`statuses` 는 그대로 동작(회귀 없음).
- `openguild rule create foo --empty` / `rule new foo --empty` 둘 다 동작.
- `cargo test -p openguild-cli` 통과 (89개).

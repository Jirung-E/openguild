[계획] 구현 계획 (2026-07-03) — 사용자 터치스크린 보유 확인, 실기 검증 가능

BUG-090 교훈 반영: **추측으로 구현하지 않고 계측 → 확정 → 구현** 순서.

## 1단계 — 계측 (WebView2 가 touch 이벤트를 JS 로 주는지 확정)
보드에 임시 디버그 오버레이(BUG-090 때와 동일 방식): `touchstart/touchmove/touchend`(touches 수·좌표)와 `pointerdown(pointerType)` 을 화면에 찍는 빌드 → 사용자가 터치스크린으로 두손가락 핀치 → 결과 보고.
- **이벤트 옴** → 2단계로 (네이티브 변경 불필요).
- **안 옴**(WebView2 IsPinchZoomEnabled 가 Page Scale 줌으로 소비) → gui/src Rust 에서 `with_webview` + COM 으로 `ICoreWebView2Settings.IsPinchZoomEnabled=false` 설정 후 재계측. (Windows 전용 unsafe — tauri 의 platform webview 접근 사용.)

## 2단계 — 구현 (QuestBoard.svelte)
- `.board` 에 `touch-action: none` (브라우저 기본 제스처 차단).
- 커스텀 핀치 핸들러: touchstart(2손가락)에서 초기 거리·중점 기록 → touchmove 에서 거리비 = zoom factor(`cy.zoom({level: startZoom * dist/startDist, renderedPosition: 중점})`), 중점 이동분은 `cy.panBy`.
- 한손가락 드래그 = 기존 cytoscape pan/노드 드래그와 충돌 주의 — cytoscape 의 자체 터치 처리(userZoomingEnabled=false 상태)와 이벤트 위임 경계 확인. 필요시 두손가락일 때만 preventDefault + 개입, 한손가락은 cytoscape 에 양보.
- 탭 = 노드 선택/확장 카드 등 기존 터치 탭 동작 회귀 확인.

## 3단계 — 검증(사용자, 터치스크린)
핀치 줌 인/아웃, 두손가락 중점 따라 줌 중심, 한손가락 pan/노드 드래그/탭 회귀, 마우스·트랙패드(BUG-090 결과) 회귀 없음.

예상 규모: 중형(계측 왕복 1회 + 핸들러 ~80줄 [+ Rust COM 설정 조건부]).

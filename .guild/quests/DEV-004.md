## 변경 사항

### Rust (gui crate)
- `gui/src/commands.rs` 신설 — HTTP route 23개를 그대로 1:1 매핑한 `#[tauri::command]`:
  - meta: `list_quest_types`, `list_quest_statuses`
  - quests read: `list_quests`, `list_deleted_quests`, `get_quest`, `get_quest_by_slug`,
    `list_quest_candidates`, `list_quest_positions`, `list_quest_dependencies`
  - quests mutation: `create_quest`, `update_quest`, `change_quest_status`,
    `change_quest_parent`, `delete_quest`, `restore_quest`, `add_prerequisite`,
    `remove_prerequisite`, `update_quest_position`
  - admin: `admin_create_snapshot`, `admin_list_snapshots`, `admin_restore`,
    `admin_check_drift`, `admin_reindex`
  - 각 핸들러: `core::ops::*` (변경) 또는 `core::services::*` (조회) 호출.
    `AppError` → `String` 변환.
- `gui/src/lib.rs`:
  - `resolve_guild_path()` — `OPENGUILD_GUILD` env → cwd 상위 탐색 → cwd fallback.
    DEV-005 (file association) / DEV-006 (recent guild) 진입 시 OS args 처리 추가 예정.
  - `tauri::async_runtime::block_on(Store::open(..))` 로 Store 생성 후
    `Builder.manage(store)` 로 모든 invoke 핸들러에 공유.
  - `tauri::generate_handler![]` 매크로에 23개 모두 등록. 임시 `ping` 제거.

### Frontend
- `@tauri-apps/api` 신규 의존성 (invoke 호출용).
- `gui/frontend/src/lib/api/transport.ts`:
  - `routeToInvoke(req)` — HTTP path / method 를 invoke cmd + args 로 변환.
    URL query (cascade, relation) 파싱 포함.
  - `TauriTransport.call` — stub 제거, 실제 invoke 호출. 미매핑 path 는 명확한
    에러 메시지로 디버깅 가능.
  - `__test_only.routeToInvoke` export — 매핑 단위 테스트.
- `gui/frontend/src/lib/api/transport.test.ts` — 12 신규 케이스
  (각 HTTP 메소드 / path 패턴이 올바른 invoke 호출로 변환되는지).

## 매핑 규칙

frontend 코드는 그대로 HTTP path 로 호출 (`questsApi.update(id, body)` →
`api.patch('/api/quests/${id}', body)`). `transport.ts` 가 환경에 따라 분기:
- HTTP 환경: `fetch('/api/quests/3', { method: 'PATCH', body: ... })`
- Tauri 환경: `invoke('update_quest', { id: 3, body: ... })`

라우팅 표:

| HTTP method + path                                  | Tauri invoke                                  |
|-----------------------------------------------------|-----------------------------------------------|
| GET /api/quest-types                                | list_quest_types                              |
| GET /api/quest-statuses                             | list_quest_statuses                           |
| GET /api/quests                                     | list_quests                                   |
| POST /api/quests {body}                             | create_quest({body})                          |
| GET /api/quests/{id}                                | get_quest({id})                               |
| PATCH /api/quests/{id} {body}                       | update_quest({id, body})                      |
| DELETE /api/quests/{id}?cascade=a,b                 | delete_quest({id, cascade: [a,b]})            |
| PATCH /api/quests/{id}/status {body}                | change_quest_status({id, body})               |
| PATCH /api/quests/{id}/parent {body}                | change_quest_parent({id, body})               |
| PATCH /api/quests/{id}/restore                      | restore_quest({id})                           |
| GET /api/quests/{id}/candidates?relation=X          | list_quest_candidates({id, relation: X})      |
| POST /api/quests/{id}/prerequisites {body}          | add_prerequisite({id, body})                  |
| DELETE /api/quests/{id}/prerequisites/{pid}         | remove_prerequisite({id, prereqId: pid})      |
| PUT /api/quests/{id}/position {body}                | update_quest_position({id, body})             |
| GET /api/quests/by/{slug}                           | get_quest_by_slug({slug})                     |
| GET /api/quest-positions                            | list_quest_positions                          |
| GET /api/quest-dependencies                         | list_quest_dependencies                       |
| GET /api/deleted-quests                             | list_deleted_quests                           |
| POST /api/admin/snapshot                            | admin_create_snapshot                         |
| GET /api/admin/snapshots                            | admin_list_snapshots                          |
| POST /api/admin/restore {body}                      | admin_restore({args: body})                   |
| GET /api/admin/drift                                | admin_check_drift                             |
| POST /api/admin/reindex                             | admin_reindex                                 |

새 API 추가 시 server route, gui commands, transport routeToInvoke 셋 다 동시 갱신.

### 사용자 검증 필요 (수동)

**핵심: Tauri 안에서 quest list 가 실제로 보이는지.**

1. 사전: `cd gui/frontend && npm run build` (이미 됐으면 skip).
2. `cargo run -p openguild-gui` 실행.
3. 창이 뜨면 **HTTP 서버 없이도** quest 목록이 표시되어야 함 (dogfood 의 27개
   quest: DEV-001~24, BUG-001~4, REQ 없음). 화면에 quest 들 보이면 invoke 가 동작 중.
4. quest 하나 클릭 → detail 화면 → title / description / 서브퀘스트 / 선행퀘스트 모두
   표시.
5. 노드 드래그 → 위치 저장 (`update_quest_position` invoke 호출).
   창 닫고 다시 열어도 위치 유지 (BUG-002 같이 검증).
6. **회귀** — `openguild-server host` + `npm run dev` 후 브라우저 (localhost:5173) 도
   여전히 정상 동작 (HttpTransport 깨지지 않았는지).

문제 발생 시 webview devtools 콘솔 (Tauri 창 우클릭 → Inspect Element) 에서
에러 확인. invoke 에러는 보통 "command not found" 또는 "arg mismatch".

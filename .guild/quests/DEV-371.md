## 배경

문서 감사 결과(admin 지시), `docs/` 의 내부 문서 6종 약 2,200줄이 **길드가
이미 하고 있는 일을 중복**하거나 **완료된 계획서**로 남아 있다.

앱에 번들되는 것은 `README.md` / `docs/USAGE.md` / `CHANGELOG.md` 셋뿐이고
(`tauri.conf.json` resources + `openguild docs`), 나머지는 전부 내부용이다.

## 확인된 것

**중복 — `docs/guild-rules.md`**

| 절 | 길드 규칙 |
|----|-----------|
| 테마 색 (DEV-074) | `frontend-theme-tokens` 중복 |
| UI 배율 (rem) | `frontend-ui-scale` 중복 |
| 저장소 — 파일 진리/DB 캐시 | `file-truth-db-cache` + `index-db-projection` 중복 |
| 릴리즈 | `release-process` 중복 |
| 커밋 & 브랜치 / 개발 순서 / 테스트 / 문서 | **길드에 없음** |

같은 규칙(DEV-074)이 두 곳에 **다른 문장**으로 있었다. 한 규칙에 출처가 둘이면
어긋나도 아무도 모른다 — [[BUG-261]] / [[BUG-267]] 과 같은 모양이다. 게다가
`AGENTS.md` 가 이 파일을 "개발 규칙" 정본으로 가리키고 있어, 에이전트가 길드
규칙 대신 이것을 읽을 수 있었다.

**드리프트 — `docs/architecture.md`**

API 엔드포인트를 28개 적어 뒀는데 실제 서버 라우트는 **88개**다. 60개가
문서에 없다(첨부 스트리밍 업로드, 백링크, admin types/statuses, 캠페인 배너 등).
8/27 에 갱신됐는데도 이 상태 — 손으로 유지하는 목록이라 계속 벌어진다.

**완료된 계획서**

| 문서 | 상태 |
|------|------|
| `dev-plan.md` | ✅ 89 / 미완 4. MVP 계획 종료 |
| `architecture-refactor.md` | Phase 4 가 "DEV-006 남음" 인데 **DEV-006 은 Done** — 이미 틀림 |
| `planning.md` | 5월 기획 확정. 7/2 이후 변동 없음 |
| `storage-design.md` | AGENTS.md 자신이 "13/13 완료(2026-05-17)" 라고 적음 |

## 정한 것 (admin)

| 대상 | 처리 |
|------|------|
| `guild-rules.md` | **제거** — 규칙은 길드에서 관리하는 게 정석. 길드에 없는 절만 규칙으로 옮긴다 |
| `architecture.md` | **도서관으로 옮기고 제거** |
| 계획서 4종 | **제거** — git 이력에 남는다 |

## 주의

- 옮길 때 **엔드포인트 표를 그대로 베끼지 않는다.** 이미 60개가 빠져 있고,
  손으로 유지하는 한 또 벌어진다. 코드(`server/src/routes/mod.rs`)가 정본임을
  명시한다.
- `AGENTS.md` 의 문서 표에서 사라진 항목을 지우고, 규칙은 `openguild rule`,
  설계 배경은 `openguild library` 로 안내한다.
- 지우기 전에 **길드에 없는 내용이 무엇인지** 먼저 확정한다 — 커밋/브랜치
  규칙은 이 파일에만 있다.

## 테스트 방법

1. `openguild rule list` 에 커밋/브랜치 규칙이 있다.
2. `openguild library list` 에 아키텍처 문서가 있다.
3. `AGENTS.md` 가 없는 파일을 가리키지 않는다.
4. `just test` 통과 — 문서 경로를 참조하는 코드가 없는지 포함.

history 테이블 + Quest Detail 에 변경 이력 섹션. 1차 범위는 **status 변경만**.
다른 mutation (create / update / delete / parent / prereq) 은 후속 quest.

## 구현 (2026-05-20)

### Schema
- `core/migrations/0004_quest_history.sql` 신설:
  - `quest_history(id, quest_id, ts, op, old_value, new_value, actor)` 테이블.
  - `idx_quest_history_quest_ts` 인덱스 (quest_id + ts DESC).
  - FK 안 함 — quest 삭제돼도 history 보존 (audit 가치).
- `core::models::QuestHistoryEntry` struct.

### Mutation 기록
- `core::ops::change_status`: 변경 전 status_id 조회 → history INSERT
  (op="change_status", old/new value 는 status_id 문자열).
- 다른 mutation 들 (update_title, change_parent, add_prereq, …) 은 후속 quest
  로 분리.

### 조회 / 노출
- `core::services::quests::list_history(pool, quest_id)`: 최신 → 과거 정렬.
- HTTP: `GET /api/quests/{id}/history`.
- gui invoke: `list_quest_history(id)`.
- frontend: `questsApi.listHistory(id)`, `QuestHistoryEntry` 타입.
- CLI: `openguild quest history <slug>` — `ts  op  old → new` 형태.

### 자동 테스트 +4 (server)
- 초기 상태 빈 history.
- 단일 status 변경 → 1건 기록 (old/new value).
- 다중 변경 → DESC 순서.
- quest 별 격리.

## 회귀

- 기존 mutation 흐름 (journal + file + SQL) 그대로. history INSERT 만 추가.
- migration 0004 — Store::open 이 자동 적용.

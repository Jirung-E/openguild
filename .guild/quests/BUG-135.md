debug 빌드 CLI 가 `--help` 포함 **모든 명령**에서 즉시 stack overflow (release 는 정상, Windows 에서 발견).

## 원인 (진단 완료)
`cli/src/main.rs` 의 `run()` 이 모든 서브커맨드 dispatch 를 담은 단일 함수(~1,560줄)인데, 함수 스택 프레임은 진입 시점에 통째로 할당된다. debug(opt-level=0)에서는 rustc 가 lifetime 마커를 안 내보내 LLVM stack coloring 이 못 돌고 — 실제론 한 번에 한 arm 만 사는데도 **모든 match arm 의 지역값이 프레임에 합산**된다. 이 합산 프레임이 Windows 메인 스레드 기본 스택(1MB)을 초과 → MSVC __chkstk 프로브가 함수 진입에서 가드 페이지를 침 → 어느 arm 이 실행되는지와 무관하게(--help 조차) 전부 터짐.

검증: `-C link-arg=/STACK:8388608` (8MB) 로 재빌드하면 debug 도 정상 동작 — 프레임이 1MB 초과 8MB 미만임을 확인.

release 가 멀쩡한 이유: lifetime 마커 → arm 간 스택 슬롯 공유 + async/임시값 최적화로 프레임이 작음. Linux 는 메인 스택 8MB 라 같은 debug 빌드도 안 터졌을 것 — Windows 1MB 기본값에서만 드러남.

## 수정
run() 을 서브커맨드별 핸들러 함수로 분리 — arm 지역값이 각자 함수 프레임으로 이동해 호출 시에만 할당됨. campaign 은 이미 handle_campaign() 으로 분리돼 있는 패턴 그대로. 분리 후 debug 빌드가 기본 스택에서 동작하는지 실기 확인.

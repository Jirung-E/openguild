## 요청

퀘스트 목록 / 홈 / 퀘스트 보드 / 검색 팔레트 등에서 표시되는 **slug pill 모양이
전부 다르다.** 게다가 **상태(status) pill** 도 비슷한 모양이라 같이 맞춰야 한다.
전수 조사해 통일한다.

## 이미 확인된 사실

[[DEV-362]] 에서 팔레트 칩을 만들다 드러났다 — **공통 정의가 없고 컴포넌트마다
각자 정의**한다. `global.css` 에 공용 클래스가 없다.

`border-radius: 20px|12px|9px` 를 쓰는 컴포넌트만 12개:

```
CampaignCombobox / CampaignHistory / Home / NewQuestModal / QuestHistory
QuestBoard / QuestCombobox / QuestList / QuestListFilter / QuestListItem
SearchPalette / TagPills
```

같은 `quest_id` 를 그리는데도 값이 제각각이다:

| | QuestListItem | QuestBoard `.badge` | QuestBoard `.node-pill` | QuestCombobox |
|---|---|---|---|---|
| radius | 20px | 20px | **9px** | **12px** |
| background | `--c` 18% | 18% | **16%** | **16%** |
| border | 40% | 40% | **55%** | 40% |
| font | sans | sans | **monospace** | **monospace** |
| font-size | 0.75rem | 0.7rem | **10px** | 0.7rem |
| height | auto | auto | **17px 고정** | auto |

**실제로 사고가 났다**: DEV-362 에서 팔레트 칩을 두 번 잘못 맞췄다. 처음엔
테두리를 빠뜨렸고(`.badge` 를 눈으로 베낌), 고친 뒤에도 보드 **노드**의
`.node-pill.mono` 와 또 달랐다. 정본이 없어서 생긴 일이다.

## 범위 — 전수 조사 후 통일

1. **slug/식별자 pill** — `--c`(타입 색) 기반. quest_id, campaign_slug, BOOK-NNN.
2. **상태(status) pill** — 모양이 slug pill 과 비슷해 함께 맞춰야 한다.
   (`QuestListItem` 의 상태 뱃지, 보드 컬럼 헤더, 홈 목록 등)
3. 성격이 다른 것은 **제외** — 태그 칩(`TagPills`), 필터 칩, 이력 칩.
   통일 대상인지 조사 단계에서 판단한다.

## 제안

`global.css` 에 `--c` 를 받는 공용 클래스를 두고 각 컴포넌트가 참조한다.
크기 차이(팔레트 행은 조밀, 보드 노드는 더 작음)는 modifier 나 CSS 변수
(`--pill-h`, `--pill-fs`)로 흡수한다.

Svelte 스타일 스코핑 때문에 컴포넌트 안에서 전역 클래스를 쓰려면 `:global()`
이 필요하다 — 확인하고 진행할 것.

## 주의

공용 UI 전반을 건드리므로 **시각 회귀 위험이 크다.** 각 화면을 실제로 열어
크기·색·테두리를 대조 확인할 것. 라이트/다크 모두.

## 테스트 방법

1. 퀘스트 목록 / 홈 / 보드(노드·컬럼 헤더) / 검색 팔레트 / 콤보박스를 차례로
   열어 slug pill 과 상태 pill 이 **같은 모양**인지.
2. 타입별 색(DEV/BUG/REQ)과 상태별 색이 그대로 반영되는지.
3. 라이트/다크 모두.
4. 보드 노드처럼 크기가 달라야 하는 곳은 **의도된 차이만** 남았는지.

## 전수 조사 결과 (2026-08-27)

퀘스트 본문의 12개 파일 목록을 실제 CSS 로 확인했다. **세 계통**으로 갈려
있었다.

| 계통 | 곡률 | 배경 | 테두리 | 글꼴 | 크기 | 쓰는 곳 |
|------|------|------|--------|------|------|---------|
| **A** | 20px | 18% | 40% | sans | 0.75rem/500 | 목록·홈·상세·캠페인 (다수) |
| **B** | 12px | 16%(slug) / **14%**(상태) | 40% | mono | 0.7rem | 콤보박스 2종 |
| **C** | 9px | 16% | **55%** | mono | 10px / 높이 17px 고정 | 보드 노드, 검색 팔레트 |

같은 `quest_id` 를 그리는데 A 는 sans, B·C 는 mono 다. 상태 pill 도 A 는
18%, B 는 14% 로 배경 농도가 다르다.

**보드 팝업의 `.badge`(0.7rem)와 퀘스트 상세의 `.badge`(0.75rem)** 처럼 같은
파일 계통 안에서도 값이 갈렸다.

## 결정 (admin)

1. **slug pill 은 monospace 로 통일.** 자릿수가 고정폭이라 세로로 정렬돼
   읽히고, 이미 보드·콤보박스·팔레트 셋이 monospace 다.
2. **곡률은 `var(--r-pill)`(999px).** 높이에 따라 자동으로 완전한 알약이 된다.
   기존 `20px` 고정은 기본 배율에서만 알약처럼 보였다 — pill 높이가 22px 안팎
   이라 이미 거의 원형이기 때문이다. UI 배율 200% 에서 높이가 44px 이 되면
   `20px` 은 '모서리 둥근 사각형' 으로 보인다. 즉 통일이면서 배율 버그
   수정이다([[BUG-254]] 계열).

## 수정

### `global.css` 의 `.pill` 이 정본

색은 `--c` 로 받고, 크기 차이는 **변수로 흡수**해 공식(곡률·배경비·테두리비)
은 하나로 유지한다.

```css
.pill      { --pill-fs/py/px, radius --r-pill, bg 18%, border 40%, weight 500 }
.pill.mono { font-family: var(--font-mono); font-weight: 600 }   /* 식별자 */
.pill.sm   { 0.7rem / 0.1 0.45rem }                              /* 콤보박스 */
.pill.xs   { 높이 1.7em / 여백 0.7em / bg 16% / border 55% }      /* 보드·팔레트 */
```

`.xs` 의 치수를 **em 으로** 적은 것이 중요하다. 보드 노드는 원래 px(10px 글자 /
17px 높이 / 0 7px 여백)였는데 px 는 UI 배율을 안 따라간다. [[BUG-244]] 가 검색
팔레트에서 같은 값을 em 으로 옮겨 해결한 방식을 공용으로 올렸다 — `1.7em` /
`0.7em` 이 각각 그 px 비율이다. 글자 크기는 쓰는 쪽이 `--pill-fs` 로 정한다
(보드 0.625rem, 팔레트 0.72rem — 팔레트는 옆의 `.ptype` 과 크기가 같아야 한다).

`--font-mono` 토큰도 함께 만들었다. 앱 안에 고정폭 스택이 **4가지**로 갈려
있었다(`SFMono-Regular` 32곳 / `JetBrains Mono` 12곳 / `Cascadia Code` 5곳 /
`ui-monospace` 1곳). 가장 많이 쓰이던 것을 정본으로 삼았다 — 나머지 사용처
치환은 이 퀘스트 범위 밖이다.

### 옮긴 곳

목록 항목 / 홈 / 퀘스트 상세 / 캠페인 목록·상세 / 콤보박스 2종 / 보드(노드 +
클릭 팝업) / 검색 팔레트. 컴포넌트에 남은 것은 **색과 배치뿐**이다.

캠페인 상세의 `.status-badge` 는 특이했다 — 버튼(`.back/.btn-edit/.btn-delete`)
과 상자를 공유하면서 곡률만 `border-radius: 20px !important` 로 덮고 있었다.
pill 이 아니라 "버튼처럼 생긴 것을 알약으로 우겨넣은" 상태라, 공용 규칙에서
뺐다.

### 재발 방지 — `check:pill`

이 퀘스트의 실제 동기는 "정본이 없어서 DEV-362 에서 두 번 잘못 맞췄다" 이다.
정본만 만들고 검사가 없으면 다음 커밋부터 다시 섞인다.

`scripts/check-pill-single-source.mjs` 가 `.pill` 을 겨냥한 선택자에 **모양
속성**(곡률/배경/테두리/글꼴/크기/여백/높이)을 다시 적는 것을 막는다. 색
(`--c`)·크기 손잡이(`--pill-*`)·배치(margin/flex)는 허용한다 — 그게 modifier
로 흡수하라고 만든 것이기 때문이다.

`check:no-hex` 와 같은 자리다. **justfile 과 CI 양쪽에 넣었다**([[BUG-251]]:
둘이 어긋나면 로컬은 통과하고 CI 만 깨진다).

## 검증

**검사가 실제로 무는지 확인했다.**

| 넣어 본 것 | 결과 |
|---|---|
| DEV-362 가 저지른 실수 재현 (`.pill.mono` 에 `border-radius: 12px` + 테두리 없는 배경 8%) | `EXIT=1`, 2건 지적 |
| 되돌린 뒤 | `EXIT=0` |

작성 직후 검사가 **내가 남긴 누락 1건을 잡았다** — 퀘스트 상세의
`.del-sub-list .pill { padding; font-size }`. 크기 손잡이(`--pill-*`)로 고쳤다.
검사가 없었으면 그대로 새 드리프트로 남았을 것이다.

**빌드 산출물에서 규칙이 의도대로 나오는지** 확인했다(`build/_app/immutable/
assets/*.css` 파싱):

- `.pill` / `.pill.mono` / `.pill.sm` / `.pill.xs` 가 전역으로 1벌씩
- 컴포넌트 규칙은 전부 스코프됨 — `.node-topline.svelte-1dy8b76 .pill.xs`
  (`--pill-fs:.625rem`), `.pslug.svelte-1xdld1b` (`--pill-fs:.72rem`),
  `.pill.status-active.svelte-she0l4` (`--c`) 등. **`:global()` 누출 0건**
- `Unused CSS selector` 경고 0건

`just test` 787(rust) + 515(프런트) 통과, `svelte-check` 0 errors.

## ⚠️ 눈으로 확인하지 못했다

**이번 세션에서 브라우저 도구가 끊겨 실제 화면을 못 봤다.** 값 대조와 빌드
산출물 파싱까지만 했다. 퀘스트 본문이 경고한 "시각 회귀 위험이 크다" 가 그대로
남아 있으므로 아래를 **직접** 봐야 한다.

의도적으로 달라지는 곳(회귀가 아님):

| 화면 | 무엇이 달라지나 |
|------|----------------|
| 목록 / 홈 / 퀘스트 상세의 slug | sans → **monospace**, 굵기 500 → 600 |
| 콤보박스 slug | 곡률 12px → 알약, 배경 16% → 18% |
| 콤보박스 상태 | 배경 14% → 18%, 좌우 여백 0.5 → 0.45rem |
| 보드 팝업 | 좌우 여백 0.5 → 0.45rem |
| **캠페인 상세 상태 뱃지** | 버튼 상자를 벗어나며 **작아진다** (0.825 → 0.75rem, 여백 0.3/0.7 → 0.15/0.55rem) |
| 보드 노드 slug | 곡률 9px → 알약. 치수가 px → em 이라 **배율에서 이제 같이 커진다** |

검색 팔레트는 값이 그대로다(이미 이 공식이었다).

## 범위 밖 — 판단 근거

퀘스트가 "성격이 다른 것은 제외, 조사 단계에서 판단" 이라 한 것들:

- **태그 칩**(`TagPills`) — `--warning` 고정에 배경 12%. 타입/상태 색을 받는
  물건이 아니다.
- **필터 칩**(`QuestListFilter`, `QuestList`) — 선택 토글이라 hover/active
  상태가 따로 있다.
- **댓글 수 / 이력 칩** — 중립색(`--bg-subtle`/`--border`)이라 `--c` 공식이
  아니다.

이들의 `border-radius: 20px` 6건은 남아 있고, [[DEV-369]] 의 곡률 전수 정리가
가져간다.

## 테스트 방법

1. 퀘스트 목록 / 홈 / 퀘스트 상세 / 캠페인 목록·상세 / 콤보박스(퀘스트·캠페인) /
   보드(노드 + 노드 클릭 팝업) / 검색 팔레트를 차례로 연다.
2. slug pill 이 **전부 monospace 에 알약 모양**인지.
3. 타입 색(DEV/BUG/REQ)과 상태 색이 그대로인지.
4. **라이트/다크 모두.**
5. **UI 배율 200%** — 특히 보드 노드의 pill 이 이제 같이 커지는지, 곡률이
   알약을 유지하는지.
6. 캠페인 상세의 상태 뱃지가 작아진 것이 어색하지 않은지(의도된 변화지만
   눈으로 판단할 것).

## 증상

사용자: "삭제하고 나서 원래 있던 위치가 아닌(원래는 Quest List에 있었는데)
Home으로 돌아가는 현상".

## 원인

`gui/frontend/src/routes/quests/[id]/+page.svelte` 의 `confirmDelete()` 가
삭제 후 `goto('/')` 하드코딩. 같은 파일에 `goBack()` 함수가 이미 `?from`
query param 분기 (list / board / home / campaign:<slug>) 를 가지고 있는데
delete 흐름만 그걸 안 씀.

```ts
async function confirmDelete() {
  ...
  await questsApi.delete(detail.id, ...);
  goto('/');  // ← 원래 위치 무시
}
```

## 수정

`goto('/')` → `goBack()` 한 줄 교체. 다른 navigate (parent 변경 / 캠페인 클릭
등) 는 모두 이미 goBack 또는 명시 path 사용해서 일관성 확보됨.

## 검증

- Quest List → Quest 클릭 → 삭제 → List 로 복귀.
- Quest Board → Quest 클릭 → 삭제 → Board 로 복귀.
- Home → Quest 클릭 → 삭제 → Home 으로 (변동 없음, 본 fix 의 정상 동작).
- 캠페인 → Quest → 삭제 → 캠페인 페이지로 복귀.

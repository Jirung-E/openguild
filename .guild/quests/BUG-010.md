`.field-label` 의 `text-transform: uppercase` 가 자식 `<input>` / `<textarea>` /
CodeMirror 까지 캐스케이드되어 입력값이 대문자로 보임.

`text-transform` 은 CSS 표시 변환이므로 **실제 저장값은 입력 그대로 (소문자)**.
즉 데이터는 정상이고 표시만 잘못됨.

## 영향 범위

다음 곳에서 `<label class="field-label">` 가 자식 폼 컨트롤을 감쌌음:
- `gui/frontend/src/routes/quests/[id]/+page.svelte` — 제목 / 긴급도 / 설명
  (CodeMirror) 편집 폼.
- `gui/frontend/src/lib/components/NewQuestModal.svelte` — 신규 quest 생성 모달.

## 수정 (2026-05-22)

CSS 규칙을 라벨 텍스트 span 에만 적용하도록 좁힘:

```css
/* before — label 전체 (자식까지 inherit) */
.field-label { text-transform: uppercase; letter-spacing: 0.05em; }

/* after — 라벨 텍스트 span 만 */
.field-label > span:first-child {
  text-transform: uppercase; letter-spacing: 0.05em;
}
```

`NewQuestModal` 의 경우 `<span class="field-label">` 로 직접 사용된 곳도
있어서 `span.field-label` 도 셀렉터에 포함.

## 회귀

- 라벨 텍스트 ("제목", "긴급도", "설명" 등) 의 시각 외형 (uppercase + 자간) 유지.
- 입력 영역의 표시는 정상 그대로.

## 검증

- `npm run check` → 0 error / 0 warning.
- `npm test -- --run` → 106 passed (변화 없음 — CSS 변경, 단위 테스트 무관).
- `npm run build` → success.
- **수동**: edit 모드 진입 → 제목 input 에 소문자 입력 → 소문자로 표시되어야 함.

## 자동 테스트?

CSS 캐스케이드는 jsdom 의 getComputedStyle 로 안정적으로 검증 어려움
(인라인 / 상속 처리가 실 브라우저와 다름). 수동 시각 확인 후 testing 으로
이동. 추후 E2E (Playwright 등) 도입 시 회귀 테스트로 등록.

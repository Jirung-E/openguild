**플러그인을 길드 잠금을 쥔 채로 기다린다.** 잠금은 길드 전체(`.guild/.lock` 하나)라, 그동안 길드의 모든
변경이 멈춘다. 그 훅이 `openguild` 로 같은 길드를 고치려 하면 **자기 자신을 기다리다 시한에 잘린다.**

## 어디서

| 변경 | 순서 | |
|---|---|---|
| 퀘스트 생성 · 상태 변경 · 퀘스트 댓글 | `pre` → 잠금 → 쓰기 → `post` | `pre` 는 잠금 밖 — 문제 없음 |
| **퀘스트 삭제** | 잠금 → 읽기 → **`pre`** → 쓰기 → `post` | 지워질 내용을 잡으려고 잠금 안에서 읽고 그 자리에서 묻는다 |
| **모든 `post` + `wait = true`** | 잠금 → 쓰기 → **`post`(기다림)** → 해제 | `emit_post` 가 잠금 안에서 불리고 기다리는 줄은 그 자리에서 돈다 |

2026-09-23 실측(스크래치 길드): `comment.added` 에 `wait = true` 훅이 `openguild quest tag add` 를 부르면
**8초(시한) 멈췄다가 잘리고 태그는 안 달린다.** 같은 훅을 `wait = false` 로 두면 0초에 달린다.
`plugins/guild.rs` 주석의 "전달은 잠금이 풀린 뒤라 교착이 없다" 는 기다리지 않는 줄에만 맞다.

## 고칠 것 (admin 과 정한 방향)

- **훅은 어떤 잠금 안에서도 돌지 않는다.**
  - 삭제: 읽기 → `pre` 묻기 → 잠금 → 쓰기. 묻는 사이 누가 그 퀘스트를 고치면 훅이 본 내용이 조금 낡을
    수 있지만, 잠금 안에서 바깥을 기다리는 것보다 낫다.
  - `post` + `wait`: 잠금을 푼 뒤에 그 자리에서 돌린다 — "훅이 끝나야 명령도 끝난다" 는 그대로.
- **`with` 를 변경 순간에 읽어 싣는다.** 지금은 훅이 **도는 순간** 파일에서 읽는다(`related::load`) —
  기본 `post` 훅(기다리지 않는 것)은 이미 잠금이 풀린 뒤라 그 사이 바뀐 문서를 볼 수 있다. 위처럼 기다리는
  훅을 잠금 밖으로 빼면 그 훅도 같아지므로, 사본을 **잠금 안에서** 떠서 이벤트에 싣는다. 훅이 언제 돌든
  "내 변경 직후의 모습" 을 본다.

## 같이 볼 것 — 캠페인 댓글 `pre`

캠페인 댓글은 `pre` 를 **묻지 않고 알리기만** 한다(`emit_pre`). 플러그인 실행기는 `pre` 알림을 받으면
아무것도 안 하고 돌아온다. 그래서 `pre = ["comment.added"]` 로 댓글을 막는 플러그인은 퀘스트 댓글은 막고
**캠페인 댓글은 못 막는 것으로 보인다** — 코드만 읽은 것이라 먼저 재 볼 것. 맞으면 퀘스트 댓글처럼 묻게 한다.

## 시험

- `wait = true` 훅이 같은 길드를 고쳐도 멈추지 않는다(위 실측을 시험으로).
- 삭제 `pre` 훅이 같은 길드를 고쳐도 멈추지 않고, 여전히 삭제를 **막을 수 있다**.
- 훅이 도는 사이 다른 프로세스가 대상을 고쳐도, 훅이 받은 `with` 는 변경 순간의 모습이다.

## 고침 (2026-09-30)

- **기다리는 줄** — 알림을 보내는 순간(`emit_post`, 잠금 안)에는 줄만 세운다. 잠금 객체(`MutationGuard`)가
  사라질 때 잠금을 **먼저 풀고** 그 줄을 돌린다(`after_unlock`). 잠금 객체는 변경 함수가 반환되기 직전에
  사라지므로 "명령은 그 줄이 끝나야 끝난다" 는 그대로다.
- **삭제 `pre`** — `ask_delete_pre` 로 빼서 잠금 전에 묻는다(상태 변경의 `ask_status_pre` 와 같은 모양 —
  `lock_coverage` 시험이 허락하는 자리).
- **캠페인 댓글 `pre`** — 코드로 확인해 보니 맞았다(`emit_pre` 는 보기만 한다). 퀘스트 댓글처럼 잠금 전에
  **묻고**, 막거나 본문을 고칠 수 있게 했다.
- **`with` 사본** — 알림을 보내는 순간 읽어 일감에 싣는다(기다리는 줄 · 보통 줄 둘 다). 줄에 넘기는 길은
  `plugin test` 가 값을 넘기는 자리(`Probe.given`)를 그대로 쓴다.

## 시험

- 기다리는 줄이 **잠금이 풀린 채로** 돌고, 명령이 돌아왔을 때 이미 끝나 있다.
- 삭제 `pre` 가 잠금이 풀린 채로 묻고, 여전히 삭제를 막는다.
- 캠페인 댓글이 `pre` 로 막힌다.
- 줄이 늦게 돌아도(그사이 제목이 바뀌어도) `with` 는 댓글을 단 순간의 제목이다.

네 시험 모두 **고치기 전 코드로 되돌리면 깨지는 것**을 확인했다. 실측도 다시 했다 — 처음의 재현(기다리는 훅이
`openguild quest tag add` 로 같은 길드에 태그를 단다)이 **8초 멈춤 · 태그 없음 → 0.06초 · 태그 달림.**

## 테스트 방법

사람이 볼 것은 없다(코드 안쪽). 위 실측을 해 보려면 스크래치 길드에 아래 플러그인을 들이고 댓글을 단다.

```toml
name  = "wait-writeback"
scope = ["cli"]
[actions.tag.run]
    command = "sh"
    args    = ["-c", "openguild --guild \"$OPENGUILD_GUILD_DIR\" quest tag add DEV-001 hooked"]
[[handlers]]
    post   = ["comment.added"]
    action = "tag"
    wait   = true
```

댓글이 곧바로 달리고, 명령이 돌아왔을 때 DEV-001 에 `hooked` 태그가 붙어 있으면 된다.

CI(develop, 2026-10-11 run 38112335881)의 macOS 작업에서 core 시험 `snapshot::tests::restore_recovers_deleted_source_files` 가
`Store::open` 중 `database is locked` 로 실패했다. 같은 실행의 우분투 · 윈도우와 그전 실행은 통과 — 가끔 실패하는 시험.
admin: "푸시하기 전에 테스트를 안한거냐 테스트에서 못거른거냐?" → "고쳐라".

## 원인

- 이 시험과 `restore_snapshot_restores_index_db` 가 **같은 이름표**(`"restore"`)로 임시 길드 폴더를 만든다.
- 폴더 이름은 `og-snapshot-{label}-{시각 ns}` — 시각으로만 구분한다. macOS 의 시각은 **마이크로초** 단위라 끝 세 자리가
  늘 000 이다. 두 시험이 병렬로 같은 마이크로초에 시작하면 **같은 폴더** → 같은 `index.db` 를 함께 열어 이주(migration)
  중 잠긴다. 확률이 낮아 로컬 `just test` 는 통과했다.
- 서버 시험은 같은 이유로 이미 원자 카운터를 붙였다(`server/src/tests.rs` setup 주석 — 윈도우 시각 해상도). core 의
  임시 폴더 함수들(50여 곳)에는 없었다.

## 고칠 것

core 시험의 임시 폴더 이름에 **프로세스 안에서 하나씩 올라가는 번호**를 붙인다(`crate::test_seq()`). 시각만 쓰는 곳 전부.

## 고침 (2026-10-11)

- core 에 `test_seq()`(시험 전용) — 프로세스 안에서 하나씩 올라가는 번호. core 시험의 임시 폴더 이름 46곳에 붙였다
  (`og-<이름표>-<시각>-<번호>`). 시험 전용 함수라 일반 빌드에 들어간 곳이 없음을 `cargo check`(시험 빼고)로 확인했다.
- 서버 · GUI · CLI 시험에서 시각만 쓰던 7곳에도 그 자리 전용 카운터를 붙였다(서버 라우트 시험은 이미 있었다).
- 같은 이름표 시험 둘이 같은 순간에 시작해도 번호가 달라 같은 폴더를 받을 수 없다.

**재현 시험은 넣지 않았다** — 겹침은 병렬로 같은 마이크로초에 시작할 때만 생겨서, 순서대로 부르는 시험은 고치기 전 코드에서도
통과한다(만들어 보고 확인함). 수정이 맞다는 근거는 이름에 번호가 들어가는 것 자체다.

`just test`(clippy 포함) 통과.

## 테스트 방법

- CI 가 통과한다(가끔 실패라 한 번으로는 증명이 안 된다 — 같은 이름표 두 시험이 같은 폴더를 받을 수 없게 된 것을 코드로 본다).

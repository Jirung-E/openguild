[[REQ-028]] 의 "도서관 문서를 실제 폴더 구조로 꺼내기" 는 데스크톱 로컬 길드(앱 · `openguild library export`)에서만
됐다 — 파일을 이 기계에 쓰므로. 서버(원격 길드 · 웹 화면 · 원격 CLI)에서는 못 했다.

## 할 것

- 서버: `GET /api/library/export.zip` — 고른 것(폴더 · 문서 · 여러 개)을 로컬과 **같은 폴더 구조**로 zip 에 담아 흘려보낸다.
  첨부 zip([[BUG-241]])처럼 스트리밍 · 무압축.
- 원격 CLI: `openguild --remote … library export <폴더>` 가 zip 을 받아 그 폴더에 풀어 준다(있는 파일은 덮지 않는다).
- 웹 화면: 도서관의 내보내기가 zip 다운로드로 된다.

## 한 것 (2026-10-11)

- **서버** `GET /api/library/export.zip` — `?folder=…` · `?id=BOOK-NNN` · `?pick=…`(여러 번, 화면의 열쇠 그대로) · 없으면 전체.
  - 로컬 내보내기와 **같은 함수**(`ops::library_export::export`)로 서버의 임시 폴더에 펼친 뒤 그 폴더를 zip 으로
    흘려보낸다 — 제목 → 파일 이름, ` (2)`, 첨부 폴더 규칙이 두 곳으로 갈라지지 않는다. 다 보낸 뒤 임시 폴더는 지운다.
  - 첨부 zip([[BUG-241]])의 스트리밍 부분을 `stream_zip` 으로 떼어 함께 쓴다(스트리밍 · 무압축 · 쓰기 태스크 패닉 시
    응답을 끊는 DEV-368 장치 그대로). zip 항목에 파일 수정 시각을 싣는다 — 예전엔 풀면 전부 1980-01-01 이었다
    (첨부 zip 도 같이 좋아진다). 이름은 UTF-8 표시가 있어 윈도우 탐색기에서도 한글이 안 깨진다.
  - 파일 이름: `[길드]library.zip`, 폴더 하나면 `[길드]<폴더>.zip`, 문서 하나면 `[길드]BOOK-NNN.zip`. 빈 폴더는 404.
- **원격 CLI** `openguild --remote <URL> library export <폴더> [--folder … | --id …]` — zip 을 받아 그 폴더에 푼다.
  zip 안 이름이 폴더 밖을 가리키면(`..` · 절대 경로 · 드라이브) 버리고, 있는 파일은 덮지 않고 ` (2)`.
- **웹 화면 · 원격 길드의 앱** — 도서관의 [내보내기](경로줄 · 문서 · 고른 것 줄)가 zip 내려받기로 된다. [복사]는
  여전히 데스크톱 로컬 길드에서만(파일을 이 기계에 펼쳐 클립보드에 올린다).

**시험**
- 서버 `test_library_export_zip_keeps_folder_tree` — 전체 · 폴더 하나(그 폴더가 뿌리) · 여러 개 · 빈 폴더 404 ·
  `/api/library/{book_id}` 와 안 겹침 · 임시 폴더가 안 남음.
- CLI — zip 이름이 폴더 밖으로 못 나감, 있는 파일 안 덮음. 프런트 — URL 만들기 3개.

확인: 길드 사본으로 띄운 서버에서 `--remote` 내보내기 결과가 같은 길드의 로컬 내보내기와 **파일 목록이 같다**.
같은 곳에 한 번 더 받으면 ` (2)` 로 붙는다. 헤드리스 WebKit 에서 [내보내기] 를 누르면 `[openguild]library.zip`,
폴더를 고르고 누르면 `[openguild]디자인.zip` 이 내려온다. `just test` 통과.

## 테스트 방법

1. 원격 길드(서버)에 붙은 앱 또는 웹 화면 → 도서관 → [내보내기] → zip 이 내려온다. 풀면 폴더 구조 그대로, 파일
   이름이 제목이고 첨부는 문서 옆 `.attachments` 폴더에.
2. 폴더 · 문서를 골라 [내보내기] → 고른 것만 담긴다.
3. 터미널: `openguild --remote http://<서버>:<포트> library export ./받을폴더 --folder 아키텍처` → 그 폴더에 풀린다.
4. 윈도우에서 풀어도 한글 이름이 안 깨지고, 파일 시각이 1980년이 아니다.

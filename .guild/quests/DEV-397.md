## 무엇

도서관 **폴더를 옮기고 이름을 바꾼다.** 드래그로도 되게 한다.

## 왜

admin: *"도서관에서, 폴더는 드래그가 안된다."*

문서만 드래그할 수 있고 폴더는 드롭 대상이기만 하다. 더 근본적으로 **폴더를 옮기거나 이름을
바꾸는 기능 자체가 없다** — 코어에는 `create_folder` / `delete_folder` / `list_folders` 뿐이다.
빈 폴더가 아니면 지우지도 못하니, 잘못 만든 폴더 이름은 그 안의 문서를 하나씩 옮겨 비우고 지운
뒤 다시 만드는 수밖에 없다.

## 왜 코어 작업인가

폴더는 진짜 디렉터리가 아니라 문서의 `path` 필드다([[DEV-239]] 결정 — 문서를 옮겨도 파일명
(BOOK 번호)이 안 바뀌게 하려고). 그래서 폴더 하나를 옮기면:

- 그 폴더와 **모든 하위 폴더**의 `folders.toml` 경로
- 그 아래 **모든 문서**의 `path`(파일 frontmatter + DB 캐시)

를 함께 고쳐야 한다. 한 번의 변경으로 묶여야 하고(잠금 안에서), 중간에 실패하면 반쯤 옮겨진
상태가 남으면 안 된다.

## 할 것

- core `ops::library::move_folder(from, to)` — 하위 폴더·문서 경로 일괄 변경, 대상이 자기
  자신이나 자기 하위면 거부(`path_is_self_or_descendant` 가 이미 있다), 이름 충돌 거부.
- 서버 endpoint + 데스크톱 명령 + transport 배선.
- 화면: 폴더 타일·트리 항목에 `draggable`, 폴더에 폴더를 떨구면 이동. 메뉴에 "이름 바꾸기".

## 구현

- core `ops::library::move_folder(from, to)` — `to` 는 **새 전체 경로**. 옮기기와 이름 바꾸기가
  같은 연산이다(부모가 달라지면 옮기기, 마지막 조각이 달라지면 이름 바꾸기). 한 잠금 안에서
  하위 폴더 전부(`folders.toml` + 캐시)와 그 아래 문서 전부(frontmatter + 캐시)의 경로를 함께 고친다.
- 거절: 루트 옮기기, 빈 대상, 자기 자신의 하위로, 이미 있는 이름, **없는 부모 밑으로**
  (조용히 만들면 오타 한 번에 엉뚱한 폴더가 생긴다), 없는 폴더.
- 이벤트 `folder.moved` — 바뀐 문서 번호를 `books` 에 싣는다(구독자가 전부 다시 훑지 않게).
  이벤트가 55종이 됐다(CHANGELOG 숫자도 고침).
- 서버 `PATCH /api/library/folders {from,to}`, 데스크톱 `move_library_folder`, transport 배선.
- 화면: 트리·탐색기 양쪽에서 **폴더를 끌 수 있다.** 드래그 짐은 문서면 `BOOK-NNN`, 폴더면
  `folder:<경로>` — 받는 쪽이 가른다. 트리 폴더 줄에 **✎ 이름 바꾸기**.
  제자리·자기 하위로 떨구는 것은 화면에서 먼저 무시한다(흔한 오조작이라 오류를 띄울 일이 아니다).

### 덤으로 고친 것 — 선택이 풀리는 순간의 콘솔 오류

폴더를 옮긴 뒤 목록을 다시 읽으면 선택이 풀릴 수 있는데, 그 순간 자식 컴포넌트의 남은 effect 가
`slug={selected.book_id}` 를 한 번 더 읽어 TypeError 가 났다(Svelte 5 의 prop 은 getter 다).
브라우저 콘솔에서 발견해 `selected?.book_id ?? ''` 로 고쳤다. 선택된 문서를 지울 때도 같은
경로였을 것이다.

## 확인한 것

- 코어 시험 3개: 하위 폴더·문서까지 함께 옮겨지고 reindex 뒤에도 유지 / 이름 바꾸기도 같은
  연산이고 BOOK 번호는 안 바뀐다 / 거절 6가지에서 **아무것도 안 바뀐다**.
- transport 시험: `PATCH /api/library/folders` → `move_library_folder`.
- 실제 브라우저(테스트 길드 웹): 탐색기에서 `아키텍처` 타일을 `보관` 타일에 끌어다 놓으니
  `보관/아키텍처` 로 이동, 트리에서 ✎ 로 `보관` → `보관소` 로 바꾸니 하위가 `보관소/아키텍처` 로
  따라왔다. 콘솔 오류 없음(위 수정 뒤). 확인용 폴더는 원래대로 되돌렸다.
- `just test` 전체 통과.

## 뒤늦게 채운 것 — CLI

코어·서버·화면에만 넣고 **CLI 를 빠뜨렸다**(문서·시험을 맞추다 발견). `openguild library folder
move <from> <to>` — 로컬·원격 둘 다(원격은 `PATCH /api/library/folders`).

- 실제 CLI: `설계`(하위 `설계/결정`, 그 안 문서 1개)를 `보관/설계` 로 → 폴더 셋과 문서 경로가
  함께 바뀌고, 자기 하위로 옮기려 하면 오류로 멈췄다.
- 시험 추가: CLI 파싱, 서버 `PATCH /api/library/folders`(하위·문서가 따라가고 자기 하위는 400).

## 테스트 방법

- 폴더를 다른 폴더로 옮기면 그 안의 문서 경로가 전부 따라 바뀌고, reindex 뒤에도 유지된다.
- 자기 자신·자기 하위로는 못 옮긴다.
- 같은 이름이 있는 곳으로는 못 옮긴다.
- 이름을 바꿔도 문서의 BOOK 번호와 링크는 그대로다.
- 트리·탐색기 두 보기 모두에서 드래그가 된다.

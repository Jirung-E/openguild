DEV-094 (entry 단위 댓글 + 답글) / DEV-012 (메모) 는 GUI / HTTP / Tauri 만
지원하고 CLI 명령이 없음. 사용자: "댓글/메모를 cli에서 가져오는 방법은?".
DEV-016-cli (rules CRUD) 와 동일 패턴으로 CLI 노출.

## 설계

### 새 subcommand

```
openguild quest comment list <slug>            # entry 목록 (id / ts / author / body 요약 1줄)
openguild quest comment show <slug>            # 전체 entry 본문
openguild quest comment show <slug> --id N     # 특정 entry 만
openguild quest comment add <slug> [--author X] [--parent-id N] [--file PATH]
openguild quest comment edit <slug> <id> [--file PATH]
openguild quest comment rm <slug> <id> [--force]

openguild quest memo show <slug>
openguild quest memo set <slug> [--file PATH]
openguild quest memo clear <slug>
```

본문 입력은 `--file PATH` 또는 stdin — DEV-016-cli 의 `read_content` helper
재사용.

### Backend / dispatcher

- core 의 `ops::comments::{list_comment_entries, add_comment_entry,
  update_comment_entry, delete_comment_entry, get_memo, set_memo}` 이미 존재 →
  CLI 는 Backend method + dispatch 만 추가.
- Backend 의 `comments_list / comments_add / comments_update / comments_delete
  / memo_get / memo_set` — local mode 전용 (HTTP 는 unsupported 안내).
- `--json` 출력 지원.

### 표시 포맷

`comment list` 비-json:

```
#1  2026-06-02 01:23  alice         첫 댓글 본문 시작 부분...
#2  2026-06-02 01:24  (이름 없음)   ↩ #1 에 대한 답글...
#3  2026-06-02 02:00  bob           또 다른 top-level...
```

`comment show` 비-json: 각 entry 마다 헤더 + 본문, entry 사이 구분선.

### 메모

메모는 단일 텍스트라 단순:
- `memo show <slug>` — stdout. 부재 시 "(메모 없음)".
- `memo set <slug> [--file]` — atomic 교체. stdin 또는 파일.
- `memo clear <slug>` — 빈 문자열 set.

## 검증

- 직접 만든 길드에서 댓글 추가 → list / show / edit / rm 흐름.
- 답글 (`--parent-id`) 정확히 entry 의 `parent_id` 에 저장 확인.
- 메모 set → show roundtrip.
- `--json` 출력 형식 검증.

트랙패드/마우스 wheel 을 구분하는 휴리스틱 추가 — `ctrlKey || !isTrackpadWheel(e)` 면 줌, 아니면 pan.

`isTrackpadWheel`: `deltaMode !== 0`(LINE/PAGE 단위)이면 마우스로 간주, `deltaMode === 0`(PIXEL)인 경우 `|deltaY| < 50` 이면 트랙패드(모멘텀 스크롤이라 작은 값), 그 이상이면 마우스(노치당 큰 고정폭, Windows 기본 ±100)로 판정.

결과: 일반 마우스의 plain wheel = 줌(이전 동작 그대로), Ctrl+wheel = 줌(유지), 트랙패드 plain two-finger 스크롤만 pan. 업계 통용 휴리스틱이라 일부 특수 마우스(매끄러운 휠)에서는 오판 가능성이 있음 — 그런 경우 보고 부탁드립니다.

반환(returned) 처리 확인 — 트랙패드에서 두손가락 스크롤이 줌되고 핀치 줌이 약한 문제. 실측 telemetry 받아서 진짜 원인 특정하고 재수정했습니다.

## 실측 (admin 노트북 트랙패드, WebView2/Chromium 진단 페이지)

| 제스처 | `ctrlKey` | `wheelDeltaY` | `deltaY` |
|--------|-----------|---------------|----------|
| 핀치 | true | ±120(고정) | 작은 **소수** (0.45, 1.12, 48.31…) |
| 두손가락 스크롤 | false | ±1(작음) | 1.00 |
| 마우스 휠(기지) | false | ±120 배수 | **정수** ±100 |

## 원인 (옛 휴리스틱이 깨진 지점)

옛 `isTrackpadWheel`은 `deltaMode===0 && |deltaY|<50` 으로 판별했는데:
1. 빠른 두손가락 스크롤은 `deltaY`가 50을 넘어 → "마우스"로 오판 → 줌 ("스크롤시 줌됨").
2. 핀치(ctrlKey)는 줌으로 보내긴 했으나 `deltaY`가 미세해 체감 줌이 거의 없었음 ("핀치 안됨").

## 수정

매그니튜드 임계값(`<50`)을 버리고 **정수/소수 + ctrlKey** 기준으로 재작성(`isMouseWheelNotch`):
- `ctrlKey=true` → 줌(핀치/Ctrl+휠). 가장 신뢰도 높은 단일 신호(브라우저가 핀치 때 ctrlKey 합성 — IE10/Chrome M35/FF55).
- 비-ctrl: `deltaY`가 **큰 정수**(노치 고정폭) 또는 `wheelDeltaY`가 **120 배수**면 마우스 휠 → 줌. 그 외(작거나 소수) → 트랙패드 스크롤 → pan.
- 핵심: **트랙패드 delta 는 소수, 마우스 노치는 정수** — 빠른 트랙패드 스크롤이 deltaY 50+ 라도 소수라 pan 유지(임계값 방식의 오판 제거).
- 감도: 마우스 0.0012(옛 cytoscape 체감 복원, "마우스는 정상" 피드백 보존), 핀치만 0.005.

## 근거 (조사)

W3C/WICG InputDeviceCapabilities 스펙상 **휠 이벤트의 마우스/트랙패드 출처를 알려주는 웹 API는 존재하지 않음**(firesTouchEvents/pointerMovementScrolls 둘 다 이 구분 불가). Figma/Excalidraw/tldraw 등도 전부 동일 휴리스틱. 캔버스 pinch/scroll 처리 best-practice 도 "deltaY 임계값 믿지 말고 ctrlKey + 클램핑" 권고 — 이번 수정이 그와 일치.

파일: `gui/frontend/src/lib/components/QuestBoard.svelte` (`isMouseWheelNotch`/`onBoardWheel`). svelte-check/no-hex 통과.

검증 요청: 노트북 트랙패드에서 ① 두손가락 위아래 스크롤 = pan(줌 아님), ② 핀치 = 줌, ③ (마우스) plain 휠 = 줌 속도 이전과 동일, 세 가지 확인 부탁드립니다.

해결 확정 (실기 검증 완료). 실제 보드에 디버그 오버레이를 박아 트랙패드가 보내는 값을 직접 찍어보고 두 가지 진짜 원인을 잡았습니다.

## 실제 보드 실측 (WebView2, 진단 페이지가 아닌 보드 핸들러 계측)

- 트랙패드 스크롤: `wheelDeltaY ≈ -deltaY` (예: dY=44 → wDY=-44), 120 배수 아님. **deltaY 가 정수(44.00)로도 나옴** → 정수/매그니튜드 판별 불가.
- 마우스 휠: `wheelDeltaY = ±120 의 배수`(WHEEL_DELTA 하드웨어 고정).
- 트랙패드 핀치: **DOM wheel 이벤트가 아예 안 옴** — WebView2 가 Page Scale 줌으로 자체 소비. JS 에서 가로챌 수 없는 플랫폼 한계(MS 이슈 #485 미해결).

## 수정

1. **마우스 vs 트랙패드 구분 = `wheelDeltaY` 가 120 의 배수인지** (`isMouseWheelNotch`). 옛 `|deltaY|<50` 임계값이 빠른 트랙패드 스크롤(deltaY 50+)을 마우스로 오판해 줌되던 버그 해결 — wheelDeltaY 는 빠르게 스크롤해도 120 배수가 아니라 pan 유지.
2. **트랙패드 줌은 Ctrl + two-finger 스크롤로** (핀치는 위 한계로 불가). 핸들러가 `e.ctrlKey || mouse` 면 줌. Tauri 의 zoom_hotkeys 기본 off 라 Ctrl+스크롤이 WebView2 에 안 먹히고 JS 로 그대로 와서 네이티브 변경 없이 동작.
3. 감도 유지: 마우스 0.0012(옛 cytoscape 체감), Ctrl+스크롤(트랙패드) 0.005.

## 최종 동작 (admin 실기 검증: "전부 정상작동 확인")

- 두손가락 스크롤(느리게/빠르게) = pan
- Ctrl + 두손가락 스크롤 = 줌
- 마우스 휠 = 줌(이전 속도)

파일: `gui/frontend/src/lib/components/QuestBoard.svelte`. 디버그 오버레이는 제거 완료. svelte-check/no-hex/빌드 통과.

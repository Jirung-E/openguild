## 무엇

도는 중인 서버·앱이 **플러그인을 다시 읽게 하는 명시적 명령**을 준다.

## 왜

플러그인은 길드를 열 때 한 번 읽고 그대로 들고 있다(`Store::install_plugins`). 그래서
`git pull` 로 정의가 바뀌어도 **재시작 전까지 옛 정의가 계속 돈다.** 데스크톱은 허용·철회
때만 다시 꽂고(`reinstall_plugins`), 서버에는 다시 읽는 경로가 아예 없다.

여기서 화면과 실제가 어긋난다 — 플러그인 화면은 매번 디스크를 새로 읽으므로 "동의 대기" 라고
말하는데(지문이 바뀌었으니), 도는 것은 여전히 **옛 코드**다. 동의가 풀려야 할 변경이 다음
재시작까지 계속 실행되는 셈이라 안전 쪽으로도 뒤집혀 있다.

## 자동 감지는 안 한다 (admin 결정)

폴더 mtime 을 봐서 자동으로 다시 읽는 방법을 검토했다가 접었다. admin: *"자동감지하게 되면
의도치 않게 선반영될 가능성이 있음"* — 아직 손보는 중인 정의가 저장되는 순간 돌기 시작하면
안 된다. **사람이 명시적으로** 다시 읽힌다.

## 할 것

- 서버: `POST /api/plugins/reload` — **루프백에서 온 요청만.** 플러그인은 그 기계의 동의로
  도는 것이라, 관리 조작을 원격에 여는 것은 동의를 HTTP 로 받지 않는 [[DEV-380]] 의 결정과
  어긋난다. 응답에 다시 읽은 결과(도는 것·대기·깨진 정의)를 싣는다.
- CLI: `openguild plugin reload` — 원격 모드에서 위 endpoint 를 부른다. 로컬 모드에서는 할 일이
  없다(CLI 는 매 실행마다 새로 읽는다) — 그 사실을 말하고 끝낸다.
- 데스크톱: 관리 → 플러그인 에 **[다시 읽기]** 버튼. 목록 새로고침만 하던 것과 달리 런타임도
  다시 꽂는다.

## 테스트 방법

- 서버가 도는 중에 정의를 고치고 `reload` → 새 정의대로 동작한다(재시작 없이).
- 고치기만 하고 `reload` 를 안 하면 옛 정의 그대로 — 자동 반영이 없다.
- 루프백이 아닌 곳에서 온 `reload` 는 거절된다.
- 정의가 바뀌어 동의가 풀린 경우, reload 뒤에는 **안 돈다**(옛 코드가 계속 도는 상태가 사라진다).

## 구현 / 확인한 것

- 서버 `POST /api/plugins/reload` — `store.install_plugins(Server, …)` 로 다시 꽂고, 응답은 `GET /api/plugins` 와
  같은 모양(`manageable: false`). **같은 기계 판단은 루프백만이 아니다** — admin 의 서버는 Tailscale 주소에 묶여
  있어서, 같은 기계의 CLI 도 `100.x` 로 들어온다. 연결의 이쪽 주소와 상대 주소가 같으면 같은 기계로 친다
  (`routes::PeerAddrs`, `[::]` 에 묶였을 때의 IPv4 매핑 주소도 정규화). 역방향 프록시를 같은 기계에 두는 배치는
  프록시에서 막으라고 문서에 적었다.
- CLI `openguild plugin reload` — 원격이면 위 경로를 부르고 도는 것·대기·깨진 정의를 출력. 로컬이면 "실행마다
  새로 읽는다" 고 말하고 성공(0).
- 데스크톱: 관리 → 플러그인 → **[다시 읽기]** (`plugin_reload`). 허용·철회·추가·빼기는 원래대로 누르는 즉시 다시 꽂는다.
- 시험
  - 서버: `reloading_plugins_is_same_machine_only_and_takes_effect` — 주소 모름/LAN/같은 tailnet 의 다른 기계 → 403,
    루프백·서버 자신의 주소 → 200 + 실제로 꽂힘, 철회 후 다시 읽으면 빠짐. `a_mapped_ipv4_loopback_is_the_same_machine`.
  - CLI: 파싱, `reload_in_local_mode_explains_there_is_nothing_to_do`(실제 바이너리).
  - 화면: 다시 읽기 → 받은 상태로 목록 갱신.
- 실제 바이너리(스크래치 길드, `OPENGUILD_HOME` 격리, 127.0.0.1:3301 서버 + `run` 훅):
  허용만 하고 안 읽음 → 훅 0회 / reload → 1회 / 철회만 하고 안 읽음 → **옛 적재라 여전히 돎**(2회) /
  reload → 더 안 돎(2회 그대로). 100.78.25.64:3302 에 묶은 서버에 같은 기계에서 `reload --remote` → 성공.
  다른 기계에서의 거절은 이 환경에서 직접 못 밟았다(시험이 대신 본다).

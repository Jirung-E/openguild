## 무엇

도는 중인 서버·앱이 **플러그인을 다시 읽게 하는 명시적 명령**을 준다.

## 왜

플러그인은 길드를 열 때 한 번 읽고 그대로 들고 있다(`Store::install_plugins`). 그래서
`git pull` 로 정의가 바뀌어도 **재시작 전까지 옛 정의가 계속 돈다.** 데스크톱은 허용·철회
때만 다시 꽂고(`reinstall_plugins`), 서버에는 다시 읽는 경로가 아예 없다.

여기서 화면과 실제가 어긋난다 — 플러그인 화면은 매번 디스크를 새로 읽으므로 "동의 대기" 라고
말하는데(지문이 바뀌었으니), 도는 것은 여전히 **옛 코드**다. 동의가 풀려야 할 변경이 다음
재시작까지 계속 실행되는 셈이라 안전 쪽으로도 뒤집혀 있다.

## 자동 감지는 안 한다 (admin 결정)

폴더 mtime 을 봐서 자동으로 다시 읽는 방법을 검토했다가 접었다. admin: *"자동감지하게 되면
의도치 않게 선반영될 가능성이 있음"* — 아직 손보는 중인 정의가 저장되는 순간 돌기 시작하면
안 된다. **사람이 명시적으로** 다시 읽힌다.

## 할 것

- 서버: `POST /api/plugins/reload` — **루프백에서 온 요청만.** 플러그인은 그 기계의 동의로
  도는 것이라, 관리 조작을 원격에 여는 것은 동의를 HTTP 로 받지 않는 [[DEV-380]] 의 결정과
  어긋난다. 응답에 다시 읽은 결과(도는 것·대기·깨진 정의)를 싣는다.
- CLI: `openguild plugin reload` — 원격 모드에서 위 endpoint 를 부른다. 로컬 모드에서는 할 일이
  없다(CLI 는 매 실행마다 새로 읽는다) — 그 사실을 말하고 끝낸다.
- 데스크톱: 관리 → 플러그인 에 **[다시 읽기]** 버튼. 목록 새로고침만 하던 것과 달리 런타임도
  다시 꽂는다.

## 테스트 방법

- 서버가 도는 중에 정의를 고치고 `reload` → 새 정의대로 동작한다(재시작 없이).
- 고치기만 하고 `reload` 를 안 하면 옛 정의 그대로 — 자동 반영이 없다.
- 루프백이 아닌 곳에서 온 `reload` 는 거절된다.
- 정의가 바뀌어 동의가 풀린 경우, reload 뒤에는 **안 돈다**(옛 코드가 계속 도는 상태가 사라진다).

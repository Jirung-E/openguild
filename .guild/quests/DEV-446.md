[[REQ-039]] 에서 정한 쿼리 문법의 **해석기와 목록 거르기** — 코어에 한 벌만 두고 CLI · 서버 · 앱이 같이 쓴다.

## 정한 것 (admin, 2026-10-21)

- 문법은 `키:값` 만 — 괄호 · `OR` 낱말은 아직 없다.
- 처음 키: `status` · `type` · `tag` · `campaign` · `urgency` · `due` · `parent`.
- 쓸 곳: 퀘스트 목록부터.

## 문법

```
status:open,in_progress campaign:C-003 -tag:wip urgency:<=2 due:overdue 로그인
```

- 같은 키의 쉼표 = 또는, 서로 다른 조건(띄어 씀) = 그리고, 앞에 `-` = 아닌 것.
- 키 없는 낱말은 지금 검색과 같다(제목 · 본문 · 번호). `"두 낱말"` 처럼 따옴표로 묶을 수 있다.
- 모르는 키는 오류 — 오타(`stauts:`)를 조용히 검색어로 삼지 않는다. 쌍점이 든 글을 찾으려면 따옴표로 묶는다.

| 키 | 값 |
|---|---|
| `status` | slug · 영어 이름 · 한국어 이름 (지금 `--status` 와 같은 비교) |
| `type` | 접두어 (`DEV`) |
| `tag` | 태그 이름 |
| `campaign` | 캠페인 번호(`C-003`) — 그 캠페인에 연결된 퀘스트. `none` = 어느 캠페인에도 없음 |
| `urgency` | `2` · `1,2` · `1-3` · `<=2` · `>=3` · `<2` · `>3` |
| `due` | `overdue`(유효 기한이 지났고 끝나지 않음) · `none` · `<=날짜` · `>=날짜` 등. 유효 기한 = 필수 기한과 연결된 진행 중 캠페인의 끝 날 중 이른 것(화면과 같다) |
| `parent` | 부모 번호(직계 자식) · `none`(최상위) |

## 할 것

- 코어 `query` 모듈 — 글 → 조건 목록(오류는 몇 번째 글자인지 알려 준다) → SQL 조건.
- `ListQuery.q` — 기존 필터와 **그리고**로 합친다.
- CLI `quest list -q "…"`, 서버 `GET /api/quests?q=…`, 앱 `list_quests` 도 같은 값을 받는다(같은 구조체).
- 문서: USAGE, 스킬.

## 시험

- 해석기: 키마다, 쉼표 · 빼기 · 따옴표 · 비교 · 오류 위치.
- 목록: 키마다 맞는 퀘스트만, 빼기, 기존 필터와 함께.

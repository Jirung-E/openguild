댓글 접기 상태가 다른 페이지에 갔다 오면 초기화됨.

## 원인 (QuestCommentsSection.svelte)
`collapsedRoots`(스레드 접기) / `collapsedBodies`(본문 접기, DEV-190) 가
컴포넌트 in-memory `$state` 뿐 — 라우트 이탈 시 컴포넌트가 파괴되며 소실.

## 개선
localStorage 영속 — 보드의 collapsedLanes(DEV-105 fix4) 패턴 그대로:
- 키: guildKey prefix + quest slug 별 namespace (길드/퀘스트마다 독립).
- 저장 대상: collapsedRoots (+ collapsedBodies 도 함께 검토).
- entry id 는 quest 별로 안정적(entry_id)이라 저장에 적합. 삭제된
  entry id 가 남아있어도 무해(매칭 안 되면 무시).
- "모두 접기/펼치기"(DEV-190) 일괄 조작도 저장에 반영.

## 구현 (2026-07-07)
- `guild-storage.ts` 의 `resolveGuildKeyPrefix`/`guildKey` 재사용 — 새 유틸
  안 만듦. 키: `comments.{scope}.{slug}.{collapsedRoots|collapsedBodies}`.
- `onMount` 에서 `guildKeyPrefix` 확정 후, `slug`/`scope` 변화에 반응하는
  `$effect` 로 그 quest/campaign 전용 값을 복원 — 컴포넌트가 라우트 전환
  중 재사용돼 slug 만 바뀌는 경우도 커버.
- `collapsedRoots`/`collapsedBodies` 변화를 각각 지켜보는 `$effect` 2개가
  변경 즉시 저장 — 기존 toggle 함수/`toggleCollapseAll`(DEV-190 일괄
  접기/펼치기) 수정 없이 자동 반영.
- 섹션 전체 접기(`collapsed`)는 대상 아님 — DEV-107 fix1 에서 이미
  admin 피드백으로 영속을 의도적으로 뺀 상태라 그대로 유지.
- 저장된 entry id 가 삭제 등으로 더 이상 없으면 단순히 매칭 안 돼 무해.

## 테스트 방법
- `cd gui/frontend && npm run check && npm test -- --run`.
- 실기: quest 상세에서 답글 스레드/본문 몇 개 접은 뒤 다른 페이지로 이동
  했다가 돌아와서 접힌 상태 유지되는지. 다른 quest 로 가면 그 quest 는
  독립적으로(접은 적 없으면 전부 펼침) 보이는지. "전체 접기"(DEV-190)
  누른 뒤 이동/복귀해도 유지되는지.

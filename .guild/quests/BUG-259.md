## 증상 (admin 보고)

작업기록 페이지에서 문서별 기록을 펼쳐 놓고 다른 페이지로 갔다가 돌아오면
펼쳤던 것이 다시 접혀 있다.

## 재현

`/worklog` 에서 문서 그룹 하나를 펼침 → 규칙 페이지로 이동 → 뒤로가기.
펼침 1개 → **0개**. (실측)

## 원인

`routes/worklog/+page.svelte` 의 `expandedDocs` 가 컴포넌트 지역 상태다.
다른 라우트로 가면 컴포넌트가 파괴되고, 돌아올 때 새로 만들어지므로 빈
`Set` 으로 시작한다. 어디에도 저장하지 않는다.

## 같은 부류 — 기간 단위(`unit`)도 리셋된다

일/주/월/구간 토글도 지역 상태라 같이 초기화된다. 기준 날짜(`anchor`)는
`?date=` 로 URL 에 있어 살아남고, 보기 모드(compact/full)는 이미
`localStorage` 에 저장하는데, 이 둘만 빠져 있다.

## 제안

`sessionStorage` 에 저장한다.

- 뒤로가기뿐 아니라 **네비게이션 링크로 다시 들어와도** 유지된다
  (SvelteKit `Snapshot` 은 히스토리 항목별이라 후자를 못 잡는다).
- 새로고침에도 남고, 앱을 새로 켜면 초기화된다 — "지금 보고 있던 상태" 라는
  성격에 맞는 계층이다. 보기 모드처럼 오래 가는 취향은 `localStorage`,
  이건 `sessionStorage`.
- `unit` 도 같은 계층으로. 이러면 세션 안에서는 유지되고 앱을 새로 켜면
  기본값(일)로 돌아온다 — 기존 첫인상은 그대로다.

## 주의

- `expandedDocs` 의 키는 `날짜|slug` 다. 날짜가 바뀌면 자연히 안 맞으므로
  따로 청소할 필요는 없지만, 무한히 쌓이지 않게 상한을 둘지 판단할 것.
- Svelte 5 에서 `Set` 을 직접 mutate 하면 변화를 못 본다 — 지금 코드가
  새 `Set` 으로 교체하고 있으니 그 방식을 유지할 것.

## 고친 것

세션 저장을 `lib/stores/worklogView.ts` 로 빼고 페이지가 그것을 쓰게 했다
([[REQ-015]] 의 `paneWidth` 와 같은 방식 — 표시 상태는 store 로 빼고 테스트를
붙인다). 펼침 키와 기간 단위 둘 다 `sessionStorage`.

깨진 값에 절대 던지지 않는다. 표시 상태 하나 때문에 페이지 전체가 안 뜨면
원래 버그보다 나쁘다 — JSON 이 잘려 있거나, 배열이 아니거나, 배열 안에
문자열이 아닌 것이 섞여 있어도 조용히 기본값으로 시작한다.

펼침 키는 200개 상한. 키가 `날짜|slug` 라 날짜를 옮겨 다니면 계속 쌓이는데,
`Set` 이 삽입 순서를 지키므로 뒤에서 잘라 **오래된 쪽부터** 버린다.

## 검증

- 단위 테스트 11건(`worklogView.test.ts`). 저장 한 줄을 빼면 2건이 깨지는 것
  확인.
- 실제 화면(미리보기):
  - 2개 펼침 → 규칙 페이지 → 뒤로가기 → **2개 그대로**, 기간도 그대로.
  - 2개 펼침 → 도서관 → 규칙 → 주소로 `/worklog` 재진입(전체 새로고침) →
    **2개 그대로**. 즉 뒤로가기뿐 아니라 링크로 다시 들어와도, 새로고침해도
    유지된다.

## 알아 둘 것 — 기간을 바꾸면 펼침은 자연히 풀린다

키가 `날짜|slug` 라서, 일 → 월 뷰로 바꾸면 날짜 그룹이 달라져 예전 키가 안
맞는다. 버그가 아니라 키의 정의상 그렇다. 같은 기간으로 돌아오면 다시 펼쳐져
있다.

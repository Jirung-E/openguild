## 증상

admin: *"플러그인 허용/철회 버튼에 왜 굳이 플러그인의 이름이 한번 더 나오는거냐"*

설정 → 플러그인 의 버튼 셋이 전부 이름을 되풀이한다.

```
telegram-quest-status
notify 태그가 붙은 퀘스트의 상태가 바뀌면 …
post → https://api.telegram.org/…
quest.status_changed   scope: cli, gui

  [스크립트 보기 — telegram-quest-status]
  [허용 — telegram-quest-status]
```

이름은 **같은 항목 안 세 줄 위에** 이미 있다. 눈으로 보는 사람에게는 순전한
중복이고, 이름이 길면 버튼만 길어져 줄 셋이 다 어긋난다.

## 원인 — 접근성 문제를 눈에 보이는 곳에서 고쳤다

[[DEV-383]] 의 지적이 출발점이었다: *"접근성: … 버튼 이름이 전부 같음"*.
스크린리더로 목록을 훑으면 `허용, 허용, 허용` 으로만 들려서 어느 플러그인
것인지 알 수 없다 — 이건 진짜 결함이다.

그런데 고칠 때 **보이는 텍스트**에 이름을 붙였다. 고쳐야 했던 것은
**접근 이름(accessible name)** 뿐인데 둘을 같은 것으로 다뤘다. 접근성을
보이는 화면의 비용으로 산 셈이고, 그럴 필요가 없었다.

## 수정

보이는 텍스트는 동사만 두고, 이름은 `aria-label` 로 옮긴다.

```svelte
<button aria-label={`${t('settings.pluginAllow', $locale)} — ${p.name}`}>
  {t('settings.pluginAllow', $locale)}
</button>
```

스크린리더는 여전히 "허용 — telegram-quest-status" 로 듣고, 화면에는 "허용"
만 남는다. WCAG 2.5.3(Label in Name)도 지킨다 — 접근 이름이 보이는 문구를
그대로 포함한다.

대상 셋: 허용 · 철회 · 스크립트 보기/숨기기.

## 테스트 방법

- 버튼의 **보이는 문구**에 플러그인 이름이 없다.
- 버튼의 **접근 이름**에는 있다 — 같은 화면에 플러그인이 둘일 때 두 버튼의
  접근 이름이 서로 다르다(그게 원래 고치려던 것이다).

## 릴리스 노트에는 **안 적는다**

[[DEV-383]] 이 이 되풀이를 넣은 것도 같은 미출시 구간이다(`v0.5.3-beta` 이전
커밋 0건). 사용자는 이름이 두 번 나오는 화면을 **본 적이 없다** — 순 변화가
0 이므로 노트에 적으면 없던 문제를 고쳤다고 광고하는 것이 된다
([[BOOK-릴리즈 패키지 절차]] 의 "이번 사이클에 한 일이 아니다" 절).

릴리스 전 태그 대비 검사에서 이 ID 가 "노트에 없음" 으로 잡히는 것은 **정상**
이다. 여기 적어 두는 이유가 그것이다.

## 요청

릴리즈노트 작성 시 **'요약' 부분과 '상세' 부분 사이에 구분선을 넣도록** 규칙을
수정한다.

## 대상

사용자는 "스킬 수정" 이라고 했으나, 실제 릴리즈노트 형식 규범은 규칙에 있다:

- `openguild rule show release-process` 의 **207행 "## 릴리스 노트에는 요약을
  반드시 쓴다"** 절
- 같은 규칙 33행 `## CHANGELOG` 절의 버전 절 템플릿(`### Added` / `### Changed`
  / `### Fixed` / `### Known issues`)

요약은 카테고리 목록 **앞에** 오도록 이미 규정돼 있으므로, 그 사이에 `---`
구분선을 넣는 규정을 추가하면 된다.

## 확인 필요

`extract-release-notes.ps1` 이 요약 절을 파싱하므로, 구분선 추가가 그 스크립트의
파싱을 깨지 않는지 함께 확인할 것. 스킬(`skills/openguild-plugin/`) 쪽에도
릴리즈노트 템플릿이 중복돼 있으면 같이 맞춘다.

---

## 수정 내용 (2026-08-20)

`release-process` 규칙 두 곳을 고쳤다.

1. **`## CHANGELOG` 절 템플릿** — 버전 절 템플릿에 요약 블록과 `---` 구분선을
   넣어, 템플릿만 봐도 구분선 위치를 알 수 있게 했다.
2. **`## 릴리스 노트에는 요약을 반드시 쓴다` 절 형식** — 3번 항목으로 구분선
   규정 추가.

두 가지를 함께 명시했다:

- **구분선 앞에는 빈 줄 필수.** 바로 위가 텍스트면 마크다운이 `---` 를
  setext 제목(h2)으로 해석해 구분선이 아니라 거대한 제목이 된다. 이 함정을
  안 적으면 반드시 밟는다.
- **`extract-release-notes.ps1` 은 영향 없음.** 가드가 `$body -match '^###\s'`
  로 절의 **시작**만 검사하기 때문이다.

## 검증

`pwsh` 가 이 머신에 없어 스크립트를 직접 실행할 수는 없었다. 대신 가드 로직을
동치로 재현해(.NET `-match` 기본 옵션은 `^` 가 문자열 시작에만 걸림) 실제
CHANGELOG 의 `0.5.0-beta` 절로 확인했다.

- 현행 절: 통과(막히지 않음)
- 요약 뒤 `---` 삽입: 통과(막히지 않음) ← 이번 변경이 안전함
- 대조군(요약 없이 `### Added` 로 시작): 여전히 막힘 ← 가드가 죽지 않음

## 테스트 방법

다음 릴리스 때 CHANGELOG 를 새 템플릿대로 작성한 뒤:

```
pwsh scripts/extract-release-notes.ps1 -Tag v0.5.1-beta -Repo owner/repo
```

생성된 `release-notes.md` 에서 요약과 `### Added` 사이에 `<hr>` 이 렌더되는지,
그리고 구분선이 h2 제목으로 잘못 해석되지 않았는지(앞 빈 줄 확인) 본다.

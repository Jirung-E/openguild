## 현재 동작
- arrangeNodesGrouped lane 한정 호출 시 (lane header 의 ⊟ 버튼):
  - lane 내부 edge 만 인접리스트 → BFS.
  - cross-lane edge 한쪽 끝이 lane 내부면 hasExternalEdge 표시 → cluster (size 1) 로 분류 → 다른 single-member 와 함께 위쪽에 단독 정렬.
- 결과: 다른 lane 의 그룹 노드와 별개로 정렬됨 (사용자 보고 동작).

## 사용자 의견 (id=1, 2026-06-04)
"이게 적절한 동작일지 생각해볼 필요" → 현재 명시 분류가 사용자 시각에서 "그룹 일부인데 따로 떠 있는" 인지 부조화.

## 옵션 (별도 quest 권장)

### A. 전역 정렬 (Group 모드) 사용 시 cross-lane 관계 반영 (현재도 그러함)
toolbar 의 [Arrange][Group] 누르면 모든 노드 대상 정렬 — cross-lane edge 도 인접리스트. 이미 동작.

### B. lane 한정 정렬 시 cross-lane 다른 끝과 y 정렬
lane 안 cluster 의 첫 노드 y 를 cross-lane 짝 노드의 y 와 동기화. 시각 단서 (선 따라가면 같은 line 에 있음).
- 단점: cluster height 가 다양 → 같은 y 강제 시 lane 안 다른 cluster 와 충돌.

### C. lane 한정 정렬 시 cross-lane single-member 를 별도 영역 (예: lane 위쪽 띠) 시각 구분 + 라벨 "→ 다른 lane 연결"
- 시각적으로 "이 노드는 다른 lane 의 그룹 일부" 명시. 정렬 자체는 현행.

### D. lane 한정 정렬 자체 deprecate — 전역 정렬만 권장
- 단순. 단 lane 마다 정렬 원하는 사용자 케이스 무시.

## 권장
- A 이미 충족 (전역 정렬 사용 시 정상). lane 한정 정렬은 의도된 좁은 시나리오 (한 lane 만 빠르게 정리).
- C 가 사용자 인지 도움 — 단 구현 양 중간.
- B 는 trade-off 큼.

사용자 보고: 리눅스에서 UI 크기 조절만이 아니라 GUI 자체가 전반적으로
느림. 특히 보드에서 심하게 버벅임. "실제로 연산량이 많은 게 아니라 뭔가
이상한 것 같음" — 정확한 직감으로 보임.

## 유력 원인 가설 (Tauri/Linux 에서 매우 흔한 케이스)

WebKitGTK 의 DMABUF renderer 가 특정 GPU 드라이버(특히 NVIDIA, 일부
Mesa/가상머신) 조합에서 GPU 가속 합성이 깨지고, 소프트웨어 렌더링으로
떨어지면서 앱 전체가 버벅이는 문제. 캔버스 기반 화면(보드 = Cytoscape
canvas)이 가장 크게 체감됨 — "연산량 대비 비정상적으로 느림" 증상과 일치.
Tauri 커뮤니티 표준 완화책이 `WEBKIT_DISABLE_DMABUF_RENDERER=1`.

## 적용한 완화 (1차)

gui run() 최초 진입 시 Linux 한정으로 `WEBKIT_DISABLE_DMABUF_RENDERER=1`
설정(사용자가 이미 지정했으면 존중). 웹뷰 생성 전에 1회.

## 1차 완화 실기 재확인 (2026-07-18, NVIDIA RTX 3060 + 최신 580 드라이버, X11)

실제로 NVIDIA GPU 리눅스 데스크톱에서 직접 확인. `WEBKIT_DISABLE_DMABUF_
RENDERER` 를 켜든 끄든(0/1 둘 다) WebKitWebProcess 가 `/dev/dri/renderD128`
+ `/dev/nvidia0` 를 정상적으로 열어 GPU 가속 경로를 타는 것으로 보임 —
소프트웨어 렌더링 폴백 징후 없음, 에러 로그도 없음. 즉 **이 X11 + 최신
NVIDIA 드라이버 조합에서는 DMABUF 완화책이 딱히 필요하지 않았음** (원래
보고 사례가 Wayland/구형 Mesa 조합일 가능성). 완화책 자체는 무해하고
다른 조합의 사용자에겐 여전히 유효할 수 있어 유지하되, 사용자가 겪은 진짜
원인은 아래 2차로 확인됨.

## 2차 원인 확인 + 수정 (2026-07-18, 실기)

"연산량 대비 비정상적으로 느림"이라는 사용자 직감이 정확했다. 코드
확인 결과 `gui/frontend/src/lib/components/QuestBoard.svelte` 의 wheel
핸들러(`onBoardWheel`, BUG-090)가 매 wheel 이벤트마다 `cy.zoom()` /
`cy.panBy()` 를 **동기** 호출 — 트랙패드 연속 스크롤은 프레임당 여러 개의
wheel 이벤트가 들어오는데, 그때마다 Cytoscape 캔버스 전체를 다시 그려서
프레임당 여러 번 렌더가 발생하고 있었다. 노드/엣지 수가 많아서가 아니라
이벤트 처리 방식 자체의 문제 — "연산량 문제가 아니다"라는 체감과 정확히
일치.

BUG-141 에서 이미 검증된 rAF 병합 패턴(`uiScale.ts` — 프레임당 DOM 쓰기
1회 상한)을 `onBoardWheel` 에도 그대로 적용: 같은 프레임 안에 들어오는
wheel 이벤트는 pan/zoom 값만 누적하고, 실제 `cy.zoom()`/`cy.panBy()`
호출은 `requestAnimationFrame` 콜백에서 프레임당 1회로 상한
(`flushBoardWheel`, `wheelRaf`). `e.preventDefault()` 는 기존처럼 이벤트
핸들러 안에서 즉시 호출 유지. 감도/줌 계산 로직은 그대로 — 여러 이벤트의
줌 배율을 합성(누적 `level` 기준)해서 최종 결과가 기존과 동일하게 나오도록
함.

파일: `gui/frontend/src/lib/components/QuestBoard.svelte`
(`onBoardWheel`/`flushBoardWheel`/`onDestroy` 의 `cancelAnimationFrame`).

## 검증 (실기, 2026-07-18)

`npm run check` (svelte-check) 0 errors, `cargo test -p openguild-gui`
16 passed. 실제 NVIDIA 리눅스 데스크톱에서 이 저장소 자체 길드로 빌드/
실행 후, XTest 로 트랙패드 연속 스크롤(pan) 15연타 + Ctrl+스크롤(zoom)
10연타를 시뮬레이션 — 두 경우 다 정상적으로 pan/zoom 되고 카드 렌더가
깨지지 않는 것을 스크린샷으로 확인. 체감 버벅임 자체는 정성적이라 실사용
피드백 필요.

## 테스트 방법

1. 리눅스에서 빌드 후 실행, 퀘스트가 여러 개 있는 길드에서 Quest Board
   진입.
2. 트랙패드로 빠르게 연속 스크롤(패닝)/Ctrl+스크롤(줌)을 반복하며 버벅임
   체감이 이전 빌드 대비 나아졌는지 확인. 카드 수가 많은 길드일수록 차이가
   더 클 것으로 예상.
3. 보드 외 화면(목록/상세, 설정 슬라이더)도 여전히 느리면 별도로 알려주기
   — 이번 수정은 보드 wheel 핸들러 한정이라 다른 원인이 남아있을 수 있음.

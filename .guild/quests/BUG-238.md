## 증상

홈에 표시되는 **토론 댓글을 클릭**하면 해당 문서로 이동은 되는데,
**그 댓글 위치로 스크롤되지 않는다.** 문서 상단에 그대로 머문다.

댓글이 많은 문서에서는 어느 댓글이었는지 다시 찾아야 해서 클릭의 의미가 없다.

## 기대 동작

문서로 이동한 뒤 해당 댓글로 스크롤하고, 하이라이트 등으로 어느 항목인지
알려준다.

## 구현 고려사항

- 이동 후 **댓글 목록이 로드된 다음에** 스크롤해야 한다. 라우팅 직후에는 대상
  요소가 아직 DOM 에 없어 스크롤이 무시된다 — 이게 현재 실패 원인일 가능성이
  높다.
- 저장소에 이미 앵커 스크롤 유틸이 있다(`gui/frontend/src/lib/utils/
  anchor-scroll.ts`). DEV-359 에서 다듬어졌고 리뷰에서도 결함 없음으로 확인된
  코드이므로, 새로 만들지 말고 이걸 재사용할 것.
- 대상 댓글이 접힌 스레드 안에 있으면 먼저 펼쳐야 한다.

## 수정 내용 (2026-08-20)

원인은 단순했다. `QuestNodeConveyor.openQuest` 가
`/quests/{id}?from=home` 으로만 보내고 **어느 댓글인지에 대한 정보를 전혀
넘기지 않았다.**

반면 스크롤 machinery 는 이미 있었다 — DEV-296 이 작업기록의 `?comment=N`
용으로 만든 것으로, 앵커가 그려질 때까지 재시도 / 접힌 섹션 펼치기 /
`jump-target` 강조까지 갖추고 있다. 새로 만들지 않고 여기에 연결했다.

- `QuestNodeConveyor` 에 `focus?: 'discussion'` prop 추가 → URL 에
  `&focus=discussion` 을 붙인다. 미해결 토론 컨베이어와 마감 지난 컨베이어가
  **같은 `mode="overdue"`** 를 쓰므로 mode 로는 구분할 수 없어 별도 prop 이다.
- `Home.svelte` 의 토론 컨베이어에만 `focus="discussion"` 전달.
- `QuestCommentsSection` 의 기존 스크롤 effect 확장 — `?comment=N` 이 없고
  `?focus=discussion` 이면 **이미 로드된 entries 에서 첫 미해결 토론 댓글**을
  고른다. 홈이 퀘스트마다 댓글을 미리 받아올 필요가 없어 추가 요청이 0이다.

### 재시도 루프를 rAF → 타이머로

`tryScroll` 재시도가 `requestAnimationFrame` 이었다. 숨겨진 문서
(`visibilityState: hidden`)에서는 rAF 가 **아예 발화하지 않아** 첫 실패에서
루프가 영구히 멈춘다. GUI 는 자식 창을 지원하므로 배경 창에서 문서를 열면
해당된다. 32ms 타이머로 바꿨다 — 보이는 창에서는 rAF 2프레임과 체감이 같고,
숨겨진 문서에서도 최소한 재시도는 돈다.

## 검증 — 한계를 분명히 밝힘

`svelte-check` 0 errors. 임시 토론 댓글을 만들어
`/quests/BUG-238?from=home&focus=discussion` 로 들어가 확인했고, **확인 후
댓글은 삭제했다**(`comments --unresolved` 로 잔존 없음 확인).

확인된 것:

- 앵커 `#comment-1` 이 정상 렌더됨
- 수동 `scrollIntoView({behavior:'auto'})` 는 정상 스크롤(0 → 698px, 유지됨)
- API 가 `discussion: true` 를 정상 반환

**확인하지 못한 것 — 스크롤이 실제로 걸리는 것.** Claude 의 브라우저 패널이
hidden 이라 `visibilityState: hidden` 이고, 이 상태에서는 rAF 가 멈춰 smooth
스크롤과 Svelte 의 렌더 플러시가 진행되지 않는다.

중요한 대조 실험: **이미 배포되어 동작하는 `?comment=1` 경로도 같은 환경에서
똑같이 스크롤되지 않았다.** 즉 이번 변경의 회귀가 아니라 환경 제약이다.
다만 이 때문에 `focus=discussion` 의 최종 동작은 **사람이 실제 창에서
확인해야 한다.**

## 테스트 방법

1. 아무 퀘스트에 토론 댓글을 만든다
   (`openguild quest comment add <slug> --author me --file b.md --discussion`).
2. 홈의 "토론 댓글" 컨베이어에서 그 퀘스트 노드를 클릭한다.
3. 문서로 이동한 뒤 **그 댓글 위치로 스크롤되고 잠깐 강조되는지** 확인.
4. 댓글이 여러 개면 첫 미해결 토론 댓글로 가는지 확인.
5. 작업기록의 댓글 활동 클릭(`?comment=N`)이 여전히 동작하는지 회귀 확인.

## 참고 — 별건 (등록 안 함)

마지막 댓글을 삭제하면 **0바이트 `{slug}.comments.md` 사이드카가 남는다.**
첨부 쪽(`write_attachment_list`)은 목록이 비면 파일을 지우는데 댓글은 안
지운다. 검증 중 발견했고 이번 범위가 아니라 손대지 않았다.

`quest list --search foo` 는 검색을 부수 옵션으로 묻히게 함. 사용자가
"검색" 의도로 명령을 찾을 때 발견성 ↓. 또한 의미상 list 의 search 는
**필터링** (다른 필터들과 동급) — 진짜 검색 (관련도 등) 과 다름.

별도 명령 `quest search <query>` 신설로 발견성 ↑. 내부는 동일 backend.
`list --search` 는 호환 alias 로 유지.

## 구현 (2026-05-22)

### CLI
- 새 `QuestCmd::Search` variant:
  - `<query>` 필수 인자 (공백 split AND 토큰).
  - `--title-only` (description 제외, slug 는 항상 매치).
  - `--limit N` (결과 행 수 제한).
  - `--id-only` / `--count` (script 친화, 상호배타).
- 백엔드 호출: `ListQuery { search, title_only, limit, ..default }` →
  기존 `list_quests` 위임.
- 출력: count → 정수만, id-only → slug 한 줄씩, 기본 → `print_quest_list`.

### 호환
- `quest list --search foo` 그대로 동작 (alias).
- `quest list --search foo --title-only` 도 그대로.

## 자동 테스트 +4 (cli)
- search 인자 파싱: `query` 1개.
- `--title-only` 플래그.
- `--limit` + `--id-only` 조합.
- `--id-only` + `--count` 상호배타 (clap 에러).

## 라이브 예시

```
$ openguild quest search slug
DEV-042    [Done] Quest history: slug 기반으로 변경 (status 재배치 안전) ...

6

$ openguild quest search DEV-040 --id-only
DEV-040
```

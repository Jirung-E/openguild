지금은 windows 잡이 자기 서명만 담은 latest.json 을 만들어 릴리스에 올린다. macOS 를 추가하면 잡마다 같은 파일을 덮어써 한 플랫폼만 남는다. 각 잡이 자기 조각(플랫폼 키 + 서명 + 다운로드 URL)을 artifact 로 올리고, 마지막에 합치는 잡이 하나의 latest.json 으로 만들어 릴리스에 첨부하도록 바꾼다.

## 검증 경로 보완 (2026-08-12)

기존 구현은 `updater-manifest` 잡 자체가 태그 전용이고 실제 GitHub Release의 `.sig`만 입력으로 사용해서, `workflow_dispatch`에서는 합성 로직이 아예 실행되지 않았다. 시험 태그는 `releases/latest`를 오염시킬 수 있으므로 릴리스 전 통합 검증 경로가 필요하다.

- 태그 실행: 기존대로 실제 Release에 첨부된 Windows/macOS `.sig`를 진리원으로 사용한다.
- `workflow_dispatch`: 같은 실행의 `openguild-windows-x64-installer`, `openguild-macos-arm64-packages` artifact에서 `.sig`를 모은다.
- 두 경로는 동일한 compose 코드를 사용한다.
- 수동 실행 결과는 `updater-manifest-preview` artifact로 올리고 실제 Release는 만들거나 수정하지 않는다.
- 서명 자체가 없으면 기존처럼 자동 업데이트 비활성 경고 후 성공한다. 일부 플랫폼 서명만 있으면 불완전한 manifest를 배포하지 않도록 실패한다.

## 테스트 방법

1. 변경을 develop에 push한 뒤 `Release` workflow를 `workflow_dispatch`로 실행한다.
2. `updater manifest (latest.json)` 잡이 skip되지 않고 성공하는지 확인한다.
3. `updater-manifest-preview` artifact의 `latest.json`을 열어 다음을 확인한다.
   - `version`이 현재 crate 버전이다.
   - `platforms`에 `windows-x86_64`, `darwin-aarch64`가 모두 한 번씩 있다.
   - 각 URL의 파일명이 같은 실행에서 만든 Windows setup 및 macOS `.app.tar.gz`와 일치한다.
   - 각 `signature`가 비어 있지 않다.
4. 수동 실행이 GitHub Release를 새로 만들거나 기존 Release를 수정하지 않았는지 확인한다.
5. 서명 시크릿이 없는 환경에서는 `has_manifest=false` 경고 후 preview가 생략되고 workflow 전체는 성공하는지 확인한다.
6. 실제 0.5.0 태그 후에는 Release 자산의 `latest.json`도 같은 두 플랫폼을 포함하는지 사후 확인한다.

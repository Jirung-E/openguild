## 무엇이 잘못됐나

플러그인 제작 스킬(`skills/openguild-plugin/skills/openguild-plugins/SKILL.md`)이 **개편
전 형식**을 가르친다. 이걸 그대로 따라 만들면 **적재가 거부된다.**

```
plugin.json 은 더 이상 읽지 않습니다 — plugin.toml 의 [[handlers]] 형식으로 옮기세요
```

352줄짜리 스킬 전체가 [[DEV-403]] 이전 모델이다.

| | 스킬이 가르치는 것 | 지금 |
|---|---|---|
| 정의 파일 | `plugin.json` (4곳) | `plugin.toml` (0곳) |
| 구조 | `"on": [...]` + 동작 하나 | `[[handlers]]` 줄 목록 (0곳) |
| 조건 | 없음 | `[handlers.when]` (0곳) |
| 연결 데이터 | 없음 | `with` (0곳) |
| 검사 도구 | 없음 | `plugin check` · `test` · `schema` (0곳) |
| 스크립트 함수 | 없음 | `notify()` · `backup()` · `send()` · `run()` · `config()` · 상태·타입 이름 (0곳) |

**틀린 것도 있다.** "The hook never blocks the guild" 라고 적혀 있는데, [[DEV-407]] 의
`pre` 줄은 **막는 것이 존재 이유**다. `deleted-audit` 예제가 바로 그것이다.

`description` 도 `plugin.json` 을 짚고 있어서, 그 낱말로 스킬이 **불려 나온다**.

## 왜 남았나

[[DEV-387]] 이 이 스킬을 만든 것은 개편 **전**이고, [[DEV-413]]("문서·스킬 갱신")이
`skills/openguild/reference/plugins.md` 는 새로 썼지만 이 스킬은 손대지 않았다. 지금
둘이 서로 다른 형식을 가르치고 있다 — reference 쪽이 맞다.

## 고칠 방향

reference 가 이미 정확하므로 스킬은 **절차**에 집중하고 형식은 reference 를 가리키게 한다.
같은 것을 두 군데 적으면 또 갈라진다.

스킬에 꼭 남아야 하는 것:
- 순서대로 정하는 법(어디 살까 · 어느 이벤트 · 어느 기계 · post 인가 run 인가 · 막을 것인가)
- 사람에게 물어야 하는 것(토큰·대상)
- **검증 레시피** — 스크래치 길드 + 대역 수신기 + `plugin check`/`test`, 안 나가는 경우까지
- 자주 밟는 함정(동의 지문·작업 폴더·되돌이)

## 테스트 방법

- 스킬을 그대로 따라 만든 플러그인이 `plugin check` 를 통과하고 실제로 돈다.
- `plugin.json` 이라는 말이 스킬에 안 남는다.
- 막는 훅(`pre`)을 만드는 길이 스킬에 있다.
- 형식 이야기가 reference 한 곳에만 있다.

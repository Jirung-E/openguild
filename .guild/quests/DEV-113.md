현재 GUI 는 Tauri command 로 로컬 .guild/index.db 에만 접근. CLI 는 이미 --remote URL / OPENGUILD_REMOTE env 로 원격 모드를 지원하지만 GUI 는 미지원. 추가 작업:
- 설정 UI 에서 'remote URL' 입력 + 저장 (config / app state).
- transport.ts 가 환경별 분기할 때 'remote mode' 면 HTTP 로 그대로 흘림 (이미 web 빌드용 분기 존재 — desktop 에서도 동일 활용).
- Tauri command 들 중 mutating ops 는 HTTP route 와 1:1 대응되어 있어야 함 (전수 점검 — 누락된 admin endpoint 등 server 에 추가).
- 인증 (JWT — DEV-021 종속) 토큰 저장 / 헤더 주입.
- 연결 실패 / 오프라인 fallback UX.
- 원격 모드에선 파일 진리원이 서버측이므로 reindex / drift / snapshot 도 admin endpoint 경유.
sub of DEV-088 (server umbrella). 의존: DEV-021 (JWT) 권장.

## 구현 (완료, MVP — 인증 제외 축소 범위)

DEV-021(JWT) 은 미구현 상태라 인증은 범위 밖으로 두고 "URL 설정 + transport
HTTP 분기"까지만 1차 구현. 신뢰된 네트워크에서만 사용 권장(설정 UI에 명시).

- `lib/stores/remoteServer.ts` 신설 — `remoteServerUrl`(localStorage 영속,
  null=로컬 기본) + `pingRemoteServer()`(`/health` 확인).
- `transport.ts` — 모듈 로드 시 1회 고정이던 `export const transport` 를
  **매 호출마다 모드를 재평가하는 위임 객체**로 변경: Tauri 환경이라도
  `remoteServerUrl` 이 설정돼 있으면 invoke 대신 그 URL 로 HTTP 호출
  (`HttpTransport` 에 base 인자 추가, 기존 `routeToInvoke` 매핑은 그대로 — 즉
  DEV-152 등으로 이미 갖춰진 HTTP route 전부를 그대로 재사용). 브라우저 모드는
  영향 없음(항상 기존 동작).
- (후속 피드백, 2026-06-28) 연결/해제 UI 위치 재배치 — "원격 서버 연결은
  '어떤 길드를 열지'의 선택이라 길드 열기와 같은 화면에서 해야 한다"는 피드백에
  따라 입력/연결확인/적용/해제 버튼을 **Welcome 화면**(`welcome/+page.svelte`,
  길드 폴더 선택 picker 옆 섹션)으로 이전. 설정 페이지의 "원격 서버" 탭은
  **읽기 전용**으로 축소 — 현재 모드(로컬/원격 URL)만 표시, 변경은 Welcome
  화면(로고 클릭)에서 하라는 안내만 남김. `remoteServer.ts` 스토어는 변경
  없이 양쪽에서 그대로 재사용.
- (후속 피드백, 2026-06-28 #2) "원격 길드도 등록하면 일반 길드처럼 접속할
  수 있어야하는데 지금은 어떻게 되어있는건지 이해가 안된다" — 재설계:
  - **실제 버그**: `transport.ts`의 `resolveTransport()`는 Tauri 환경에서도
    `remoteServerUrl`이 설정돼 있으면 무조건 HTTP 로 우회한다. 그런데 로컬
    길드를 여는 모든 경로(`openRecent`/`pickFolder`/`pickGuildFile`/
    `initUninit` → `open_guild_in_current_window`/`init_and_open_guild`)가
    이 값을 클리어하지 않았다 — Rust 의 Store 는 새로 연 로컬 길드로 swap
    되는데 frontend 의 모든 호출은 여전히 옛 원격 URL 로 나가 "로컬을
    열었는데 화면엔 원격 데이터"가 보이는 혼란이 발생할 수 있었음. 네
    경로 모두에 `setRemoteServerUrl(null)`을 호출 시점에 추가해 로컬 열기가
    항상 원격 override 를 이긴다.
  - **UX 재설계**: 원격 연결을 local recents 와 동등한 "최근 길드" 항목으로
    승격. 새 store `lib/stores/remoteGuilds.ts` — `core::recents`(Rust,
    recents.json)와 같은 LRU 패턴(최대 10개)을 frontend 전용 localStorage
    로 재현(원격 URL 은 파일 경로가 아니라 Rust 쪽에 합칠 수 없음).
    `registerRemoteGuild(url)`을 연결 성공 시 호출 — `recents::add()`가
    로컬 열기 성공 시 자동 호출되는 것과 동등한 역할.
  - Welcome 페이지: local recents + remote guilds 를 `UnifiedEntry`(kind 로
    구분) 하나의 목록으로 합쳐 최근 연 순으로 표시. 클릭하면 kind 에 따라
    `openRecent`(로컬, invoke) 또는 `openRemoteEntry`(원격,
    setRemoteServerUrl + 보드로 이동) — 둘 다 "한 번 등록하면 클릭 한 번으로
    재접속" 경험이 동일. 제거(×)/전체 비우기도 양쪽 다 지원.
  - `remoteServer.ts`(활성 연결 하나만 추적, transport.ts 가 읽음)는 역할
    그대로 유지 — "최근 기록"과 "지금 활성 연결"은 별개 개념으로 분리.
- (후속 피드백, 2026-06-29) "원격 서버 연결시 '로컬로 전환' 버튼은 도대체
  왜있는거냐" — 제거. local recents 는 "현재 열려있는 길드" 표시가 원래
  없는데(그냥 목록일 뿐) 원격만 "현재 연결됨 + 전환" 상태 배너를 따로 두는
  게 비대칭이고 역할이 불분명했음. local/remote 완전 대칭으로 — Welcome 은
  순수 "다음에 뭘 열지" 고르는 화면, 로컬로 돌아가려면 그냥 목록에서 local
  항목을 클릭(그 경로들이 이미 `setRemoteServerUrl(null)` 처리). 상태
  배너 + `disconnectRemote()` 제거.
- (후속 버그, 2026-06-29) "웹브라우저로는 원격길드 접속이 되는데 GUI 에서는
  안된다" — 실기로 GUI(Tauri) 에서 재현·확인한 진짜 원인:
  `routes/+page.svelte` 의 `onMount` guard(`launch_mode === 'welcome'` 면
  `/welcome` 으로 bounce — DEV-052)가 **Rust 의 로컬 Store 상태만** 본다.
  원격에 연결(`remoteServerUrl` 설정)해도 Rust 쪽은 여전히 "길드 안 연" 상태
  (`launch_mode` 그대로 `welcome`)이므로, Welcome 에서 연결 후 `/` 로
  이동하자마자 이 guard 가 즉시 다시 `/welcome` 으로 돌려보내 마치 "연결이
  안 되는" 것처럼 보였다. 브라우저 모드는 이 invoke 자체가 없어(Tauri
  전용) 영향 없었던 것 — 그래서 브라우저는 되고 GUI 만 안 됐음.

  수정: `getRemoteServerUrl()` 이 truthy 면 이 guard 를 건너뜀(원격 연결도
  유효한 "길드 컨텍스트"). 실제 GUI(`openguild-gui.exe`, computer-use 로
  직접 조작)에서 재현 + 수정 후 재검증: Welcome 에서 LAN 의 다른 호스트
  (`192.168.0.11:3000`, 실제 `openguild-server`)에 연결 → 보드/Admin
  페이지 모두 원격 데이터로 정상 렌더링(REQ-001 등 quest, Quest Types
  목록) 확인. 더 이상 `/welcome` 으로 bounce 되지 않음.
- (후속 버그, 2026-06-29 #2) "원격 길드로 들어갔을때 길드 제목 표시되는게,
  웹에서 접속시 제목이 표시되지 않고, gui로 접속시
  openguild-welcome-placeholder로 표시됨" — `Nav.svelte` 의 길드 이름이
  항상 Tauri `current_guild_name` invoke(Rust 로컬 Store 전용)만 썼다.
  브라우저 모드는 애초에 이 invoke 자체가 없어 미표시(DEV-141 의 원래
  의도), Tauri+원격 모드는 로컬(미연결) Store 의 placeholder 이름을
  그대로 보여줘 틀린 길드 이름이 나왔다.

  수정:
  - `server/src/routes/meta.rs` 에 `GET /api/guild-info` 신설 — Tauri 의
    `current_guild_name` 과 동일한 `recents::guess_name()` fallback 규칙
    재사용, 브라우저/원격 양쪽이 항상 실제 길드 이름을 받음.
  - `lib/api/meta.ts::getGuildDisplayInfo()` — Tauri-local(원격 미연결)은
    invoke, 그 외(브라우저 또는 Tauri+원격)는 새 HTTP 라우트로 분기.
    `{ name, remote }` 반환 — `remote` 는 Nav 의 "🌐 원격" 배지 표시 기준.
  - `Nav.svelte` — 길드 이름 배지 옆에 원격 연결 시 배지 추가.

  검증: 새로 빌드한 `openguild-server`(이 라우트 포함)로 실제 길드
  (`minecraft_survival_todo`)를 띄우고 GUI 에서 연결 → Nav 에
  "minecraft_survival_todo 🌐 원격" 정확히 표시 확인.

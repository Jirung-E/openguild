## 구현 (간단)

BUG-056 의 `ConfirmDialog` 컴포넌트를 다음 4 사이트에도 적용 — Tauri WebView 의 native `window.confirm()` 이 silent return → 클릭 한 번에 destructive 동작 실행되던 문제 차단.

| 사이트 | 동작 | 위험도 |
|---|---|---|
| AdminStatusesSection | slug rename cascade | 높음 (모든 quest frontmatter cascade) |
| AdminTypesSection | prefix rename cascade | 높음 (파일명 + slug 일괄 변경) |
| admin/+page (`onRestore`) | backup 복원 | 높음 (`.guild/` 덮어쓰기) |
| rules/+page (`select`) | 편집중 다른 slug 선택 | 중간 (미저장 작업 손실) |

제외: admin `onReindex` — 사용자 지시 (idempotent, 파일 truth 불변).

패턴: `confirmXxx` state 추가 → 호출 지점은 state 만 set 후 return → 컴포넌트 최하단에 `ConfirmDialog` mount → `onconfirm` 콜백이 실제 `do<Action>` 호출.

## 테스트 방법

### A. Status rename cascade

1. Admin 페이지 → "Quest Status" 섹션의 임의 status (사용 quest 가 있는 것 — 예: `open`) 의 "수정" → slug 를 다른 값 (예: `backlog`) 로 변경 → "저장".
2. 모달 "Status slug 변경 (cascade)" 표시 + 영향받는 quest 개수 표시.
3. **취소** 누르면 변경 없음. 다시 시도 → **변경** 누르면 cascade 실행 후 토스트 확인.
4. Board / List 가서 그 status 의 quest 들이 새 slug 로 잘 매칭되는지.

### B. Type rename cascade

1. Admin → "Quest Type" → 임의 type (예: `DEV`) 수정 → prefix 를 다른 값 (예: `CORE`) → 저장.
2. 모달 "Type prefix 변경 (cascade)" + 영향 quest 개수 + `XXX-NNN` mention 자동 갱신 안 됨 안내.
3. 취소 / 변경 동작.
4. 변경 후 `.guild/quests/CORE-NNN.md` 가 존재해야.

### C. Backup 복원

1. Admin → "백업 (Snapshots)" → "+ 새 백업" 으로 백업 하나 만들기.
2. 그 백업의 "복원" 버튼 → 모달 "백업 복원" + 영향 안내 + ".pre-restore.db 로 자동 백업" 정보.
3. 취소 / 복원 동작.

### D. Rules 편집중 이동

1. Rules 페이지 → 임의 규칙 선택 → "수정".
2. 본문 일부 변경 후 좌측 다른 규칙 클릭.
3. 모달 "편집중 이동 — 편집 중인 변경 사항이 있습니다. 버리고 이동할까요?" 표시.
4. 취소 → 원래 규칙 편집 유지. 버리고 이동 → 새 규칙 선택, 변경 사항 버려짐.

### E. 공통 키보드

각 모달에서 `Esc` = 취소, `Enter` = 확인, 오버레이 클릭 = 취소.

### F. (회귀) Reindex 는 sweep 제외

Admin → "Reindex" 클릭 시 **native** `confirm()` 그대로 (DEV-119 sweep 안 함) — `window.confirm` 이 silent return 환경이면 그냥 진행됨. 정상.

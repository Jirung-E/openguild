## 문제

`comment add --discussion` 이 **추가 → discussion 토글, 2단계**로 동작한다
(DEV-361 구현). 새 entry 는 항상 `discussion=false` 로 만들어지므로 토글로
설정하는 구조다.

원격 길드에서는 이게 **HTTP 왕복 2번**이고 롤백이 없다. 1번이 성공하고 2번이
실패하면 이미 만들어진 댓글이 **평댓글로 남는다** — DEV-361 이 없애려던 바로
그 상태다. 로컬도 파일을 두 번 쓴다.

## 원인

`services::comments::add_entry` 가 `discussion: false` 를 하드코딩한다.
생성 시점에 토론 여부를 지정할 경로가 아예 없어서, 상위 계층이 토글로
우회할 수밖에 없었다.

## 방침

생성 자체에 `discussion` 을 실어 **파일 쓰기 1회 / HTTP 1회**로 끝낸다.

- `services::comments::add_entry` · `ops::comments::add_comment_entry` 에
  `discussion: bool` 추가
- 서버 `AddCommentRequest` 에 `discussion` (serde default false) 추가 —
  구버전 CLI 가 필드를 안 보내도 동작이 같다
- CLI 는 응답 entry 의 `discussion` 을 보고, 요청했는데 false 면 그때만
  토글로 보정 → **구버전 서버 호환**

## 검증

- 로컬 / 원격 양쪽에서 `--discussion` 1회 호출로 토론 생성
- 구버전 서버(필드 무시) 시나리오에서 토글 폴백이 도는지

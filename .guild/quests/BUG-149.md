# [ci] release.yml에 Linux(deb/rpm/AppImage) 빌드/첨부 job 추가

## 배경

릴리즈 준비 점검 중 발견: CHANGELOG Unreleased 에 "Linux 배포 패키지
(deb/rpm/AppImage) 추가" (BUG-142) 가 올라가 있고, `gui/tauri.conf.json`
의 `bundle.targets` 도 실제로 `["nsis", "deb", "rpm", "appimage"]` 로
Linux 타깃을 포함하고 있다. 하지만 `.github/workflows/release.yml` 은
`windows` job 하나뿐이라, `v*` 태그를 push 해도 GitHub Release 에는
Windows NSIS installer 만 첨부되고 Linux 패키지는 전혀 빌드되지 않는다.
release.yml 의 코드 주석에도 "macOS / Linux runner — matrix 확장" 이
"이 quest 범위 외" 후속 작업으로 명시돼 있어, 의도적으로 비어있던
부분이다.

## 방향

`release.yml` 에 `linux` job 을 추가 — `ubuntu-22.04` 러너에서
`cargo tauri build --bundles deb,rpm,appimage` 실행 후 결과물을
artifact 업로드 + (태그 push 시) GitHub Release 첨부. Windows job 과
동일하게 Node/Rust 설치, cargo cache, tauri-cli 설치를 거치되:
- Tauri v2 Linux 빌드에 필요한 apt 패키지(libwebkit2gtk-4.1-dev,
  libgtk-3-dev, libayatana-appindicator3-dev, librsvg2-dev, patchelf)
  설치 단계 추가.
- Windows job 의 "Build CLI + Server (release)" 단계는 NSIS 커스텀
  템플릿이 상대경로로 두 exe 를 참조하기 때문에 필요한 것 — Linux 번들
  (deb/rpm/appimage) 은 `bundle.resources`/`externalBin` 에 CLI/서버
  바이너리 참조가 없어 해당 단계가 필요 없음(GUI 앱만 패키징하는 게
  기존 동작과 동일한 범위).

## 테스트 방법

로컬(Windows) 에서는 ubuntu 러너를 재현할 수 없어 실기 검증 불가.
아래 중 하나로 검증:
1. `workflow_dispatch` 로 release.yml 수동 실행 → linux job 이 성공하고
   `openguild-linux-x64-packages` artifact 에 `.deb`/`.rpm`/`.AppImage`
   가 들어있는지 확인 (release 생성 없이 dry-run).
2. 실제 `v0.4.0-beta` 태그 push 시 GitHub Release 에 Windows installer
   와 Linux 패키지 3종이 모두 첨부되는지 확인.

## 근본 원인
상세 lazy refresh(`refresh_quest_if_stale`/`refresh_campaign_if_stale`)가 mtime 게이트 `file_mtime <= cached → skip` 로 파일 re-read 자체를 건너뜀. 그런데 또 다른 openguild 프로세스(CLI/server)가 GUI 켜둔 채 편집하면 **파일 + cached_mtime(및 공유 file_mtime_cache)을 함께 갱신** → 이 프로세스의 게이트가 "이미 동기화됨"으로 오판 → 콘텐츠 re-read 스킵 → 실행 중 index.db 뷰가 stale 인 채 남아 reindex 전까지 안 보임. (외부 에디터/`git pull` 은 캐시를 안 건드려 정상 감지됐지만, "다른 openguild 프로세스 편집" 케이스가 누락.)

## 수정
- **콘텐츠 re-read + index.db UPDATE(체크리스트/linked_quests 포함)는 상세 진입 시 *항상* 수행** — 파일 1개 re-parse 라 저렴. 누가(에디터/CLI/다른 프로세스) 고쳤든 상세 페이지는 항상 파일=진리원 반영.
- **파일 write-back(updated_at 보정)만 외부 편집(file_mtime > cached)일 때로 게이트 유지** — write-back 은 파일 재기록이라 매 진입 churn 방지.
- 반환값 = '외부 편집 감지 여부'(bool 의미 보존).
- 파일: `core/src/incremental.rs` (두 함수 + doc).

## 테스트
- 회귀 2건 추가: 게이트가 닫힌 상태(cached_mtime/touch 로 file_mtime <= cached)에서도 콘텐츠가 re-sync 되는지 — quest/campaign 각각. 통과.
- 기존 테스트(외부편집 감지 true/false, churn 없음) 유지. clippy 클린.

## 범위 밖 (후속)
목록/Home/보드 등 **비-상세 뷰**는 여전히 실행 중 외부 편집을 라이브 반영하지 않음 → fs watcher([[DEV-122]]) 영역. 본 수정은 상세 페이지 한정.

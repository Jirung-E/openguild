## 설계 재검토 — DOM/SVG 단일 월드 계층 (2026-08-05)

[[BUG-180]] / [[DEV-316]] 기록을 다시 검토하고 사용자와 원인을 재정리한 결과,
현재 가장 유력한 해결책은 **레인·노드·관계선을 같은 렌더링 계층으로 통일**하는
것이다.

현재 구조는 레인/그리드가 DOM/CSS라 기존 픽셀의 위치만 합성하는 반면,
노드/관계선은 Cytoscape Canvas 안에 구워져 있어 pan/zoom마다 새 Canvas 프레임을
만들어 화면에 제출해야 한다. WebKit이 두 손가락 wheel gesture 중 이 Canvas
프레임의 화면 반영을 늦추면서 새 위치의 DOM 레인과 이전 프레임의 Canvas 노드가
동시에 보이는 것이 디싱크의 핵심으로 판단된다. 논리 상태 자체는 즉시 갱신되며,
`cy.png()`가 새 상태를 정확히 담았던 실기 결과도 이 설명과 일치한다.

### 권장 구조

```text
board viewport
└─ board-world            ← pan/zoom 시 이 부모 transform 하나만 갱신
   ├─ DOM lane layer
   ├─ SVG edge layer
   └─ DOM quest-card layer
```

- 노드는 absolute-positioned DOM 카드로 렌더하고 `left/top`은 월드 좌표로 유지.
- 관계선은 동일 월드 좌표계의 SVG `<path>`로 렌더.
- pan/zoom마다 노드 각각의 transform이나 path를 갱신하지 않고 `board-world`의
  `translate3d(...) scale(...)`만 한 번 변경.
- 실제 카드 드래그/자동 배치/상태 변경 때만 해당 카드 좌표와 연결된 path를 갱신.
- 레인·관계선·노드가 같은 부모 transform을 공유하므로 서로 다른 프레임으로
  어긋날 수 없고, 제스처 중 Canvas repaint/commit 경로도 제거된다.

### 기존 DEV-317 본문에서 수정할 판단

- "pan/zoom 이벤트마다 각 DOM 노드 transform 갱신"은 O(N) style write가 되므로
  사용하지 않는다. 부모 transform 1회가 원칙.
- Cytoscape를 DOM 뒤에 영구 유지하면 Canvas+DOM 이중 렌더/상태 동기화 비용이
  남는다. POC에서는 좌표·선택 로직 재사용을 위해 임시 유지할 수 있지만,
  운영 구조에서는 보드 상태를 별도 store/model로 추출하고 Cytoscape renderer를
  제거하는 방향을 우선 검토한다. 현재 레이아웃이 `preset`이고 레인 좌표·그리드
  스냅·다중 선택·상태 변경을 앱 코드가 이미 상당 부분 직접 처리하므로 현실성이
  있다.

### 트레이드오프 / POC 검증

- DOM 카드 수와 SVG path 수가 늘어나므로 50/200/500개에서 FPS·메인 스레드·메모리
  실측 필요. 500개 이상에서 문제가 확인될 때만 viewport+overscan 가상화 검토.
- 카드별 `will-change`/레이어 승격은 금지하고 부모 월드 계층만 합성 대상으로 둔다.
  큰 월드 전체가 거대한 backing layer가 되는지도 Web Inspector Layers에서 확인.
- CSS scale 중 텍스트 선명도, 박스 선택, 다중 드래그, edge highlight/hit testing,
  저장 viewport 복원을 회귀 항목으로 둔다.

POC 성공 기준은 Safari/WKWebView 두 손가락 pan/zoom에서 레인·카드·관계선이 같은
프레임으로 움직이고, 프레임당 시각 갱신이 부모 transform 1회이며, 200개 노드에서
체감 지연 없이 동작하는 것이다.

실제 macOS release 앱의 트랙패드 확인 결과, 원래 핵심 증상이었던
lane/card/edge 제스처 동기화는 정상으로 확인됐다.

다만 직접 DOM/SVG renderer 전환 뒤 다음 표시·성능 회귀가 발견됐다.

1. 화살표가 기존보다 과하게 휘어 보임.
2. 확대하면 HTML 노드가 저해상도 raster를 늘린 것처럼 흐림.
3. 깊게 축소할 때 GPU 사용량이 늘고 제스처가 심하게 버벅임.

원인을 세 부분으로 나눠 수정했다.

- 새 SVG 구현이 모든 edge에 거리 기반 최소 18px bend를 강제하고 있었다.
  기존 Cytoscape `curve-style: bezier`의 실제 모습에 맞춰, 한 쌍의 노드를 잇는
  edge가 하나면 직선으로 그리고 병렬 edge가 있을 때만 40px step으로 대칭 분리한다.
- edge의 `vector-effect: non-scaling-stroke`를 제거했다. 이 옵션은 축소해도
  화면상 선 굵기를 유지하므로, 깊은 축소에서 논리 좌표 기준으로 매우 굵은 SVG
  curve를 매번 다시 stroke해야 했다. 이제 기존 Cytoscape처럼 선/화살표도 월드
  배율을 함께 따른다.
- `board-world` 전체를 `will-change: transform` 영구 GPU layer로 고정하던 방식을
  제거했다. 바깥 viewport는 제스처 중 임시 transform만 담당하고, 안쪽 world는
  CSS `zoom`으로 현재 raster 배율을 확정한다. 연속 zoom 중에는 배율 차가 20~25%
  이상이고 마지막 확정 후 80ms가 지난 경우에만 중간 확정하며, 입력이 120ms
  멈추면 최종 배율로 한 번 더 확정한다. 따라서 매 frame layout/paint하지 않으면서
  확대 후에는 현재 배율로 선명하게 다시 raster하고, 축소 후에는 거대한 원본

앞선 GPU/선명도 보정에서 사용한 CSS `zoom`이 새 회귀를 만들었다는 실제
release 앱 피드백을 받았다.

- 노드 외곽과 내부 pill/font가 같은 비율로 변하지 않음.
- lane 단색 배경이 위/아래에서 잘려 보임.

CSS `zoom`은 완성된 장면 전체를 기하학적으로 확대하는 camera transform이
아니라 자식의 layout/font를 새 배율로 다시 계산한다. 극단적인 저배율에서는
글자 최소 크기, subpixel 반올림, absolute child 높이 계산이 카드 외곽과 달라질
수 있어 이번 보드 world에는 부적합했다.

다음과 같이 보정했다.

CSS `zoom`을 안쪽 transform으로 바꾼 뒤에도 실제 release 앱에서는 노드 내부
pill/font가 외곽과 따로 변하는 현상이 그대로라는 피드백을 받았다.

수학적으로 `outerScale × innerScale`은 최종 배율이 같지만, WebKit compositor는
중첩된 두 transform layer를 서로 다른 시점/해상도로 raster할 수 있다. 따라서
80ms 중간 확정, 120ms 종료 확정, `committedWorldZoom` 상태를 모두 제거했다.

현재 viewport hot path는 다음 한 줄뿐이다.

```text
board-world-viewport: translate3d(pan.x, pan.y, 0) scale(zoom)
└─ board-world: transform 없음
   ├─ world grid dots
   ├─ SVG edges
   └─ DOM nodes (외곽 + pill/font/icon 전체)
```

단색 lane 배경은 위/아래를 항상 채우는 screen-space layer로 유지하고 X/폭만
같은 pan/zoom 값에서 갱신한다. grid dot은 위 단일 world transform 안에 있다.
`will-change`와 `non-scaling-stroke`는 계속 사용하지 않는다.

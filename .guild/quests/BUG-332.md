## 무엇이 잘못됐나

윈도우에서 `discussion-to-ai` 를 '명령 실행' 으로 `claude -p` 에 물렸더니 파워셸이
**exit code 1** 로 끝난다(admin).

## 왜 — 셋이 겹쳐 있다

**1. stderr 한 줄이 스크립트를 죽인다.** 맨 위에 `$ErrorActionPreference = 'Stop'` 이
걸려 있다. 파워셸 5.1 은 **네이티브 명령이 stderr 에 쓰기만 해도** `NativeCommandError`
를 만드는데, `Stop` 이면 거기서 던진다. `claude -p` 는 진행 표시나 경고를 stderr 로
낸다 — 정상 동작인데 스크립트가 죽는다. 이게 exit 1 의 직접 원인으로 보인다.

**2. 한글이 깨져서 나간다.** `$msg | & cmd.exe /c …` 는 `$OutputEncoding` 을 따르는데
5.1 기본은 ASCII 다. 물어보는 글이 `?` 로 바뀌어 넘어간다. 죽지 않더라도 쓸모가 없다.

**3. 답글용 값이 윈도우에는 아예 없다.** [[BUG-331]] 에서 `OG_TARGET_ID` ·
`OG_COMMENT_ID` · `OG_TARGET_KIND` 를 자식에게 주도록 했는데 **`deliver.sh` 에만** 넣고
`deliver.ps1` 은 빠뜨렸다. 그래서 윈도우에서는 답글을 달 수가 없다.

덤으로, README 에 적어 둔 답글 명령이 **bash 한 줄**이다(`$(cat)`, 파이프). 윈도우에서는
그 명령이 `cmd.exe /c` 로 돌아가므로 그대로 붙여 넣으면 당연히 안 된다 — 윈도우용 예시가
없다.

## 고칠 방향

- 네이티브 명령 둘레에서만 `Stop` 을 풀고, **끝난 코드**로 성공/실패를 가린다. stderr 는
  모아서 영수증에 남긴다 — 죽이지 말고 보여 준다.
- 파이프 인코딩을 UTF-8 로 맞춘다.
- `OG_*` 를 `deliver.ps1` 에도 넣는다.
- README 에 윈도우용 답글 예시를 따로 적는다.

## 테스트 방법

- 윈도우에서 '명령 실행' + `claude -p` 가 **끝까지 돈다**.
- 한글 물음이 안 깨져서 넘어간다.
- 답글이 실제로 달린다(윈도우용 예시대로).
- 명령이 진짜로 실패하면 `delivered.log` 에 **왜** 인지가 남는다.

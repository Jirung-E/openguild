## 무엇을 하고 싶나

> github 페이지로 길드 페이지 제공 가능? 조작은 안되지만 보는건 가능하도록. (admin)

길드를 **정적 파일로 구워** GitHub Pages 같은 곳에 올린다. 서버 없이, 보기만.

## 왜 되나

프런트는 이미 정적 빌드다(`adapter-static`, SPA fallback) — Tauri 가 그 빌드를 그대로
webview 에 넣는다. 올리는 것 자체는 지금도 된다. 문제는 화면이 아니라 **데이터**다. 앱이
`/api/*` 를 부르는데 Pages 에는 받을 것이 없다.

통로는 이미 한 곳이다.

```ts
export interface Transport {
    readonly kind: 'http' | 'tauri';
    call<T>(req: ApiCall): Promise<T>;
}
```

여기에 `'static'` 을 더하면 호출부(페이지들)는 안 건드린다.

## 어떻게

빌드할 때 `.guild/` 를 읽어 JSON 을 미리 굽는다.

```
docs/
├── index.html …          기존 정적 빌드 그대로
└── api/
    ├── quests.json
    ├── quests/DEV-001.json
    ├── campaigns/… library/… rules/…
    └── search-index.json
```

`static` transport 가 `GET /api/quests/DEV-1` 을 `api/quests/DEV-1.json` 으로 바꿔 읽는다.
**상대 경로**라 `/저장소이름/` 아래에서도 그대로 돈다.

읽기 경로는 41개(고정 17 + 문서별). 문서별은 파일 하나씩.

## 순서

**1. 정적 굽기 + `static` transport.** 이것만으로 볼 수 있는 사이트가 나온다.

**2. 쓰기를 transport 한 곳에서 막는다.** `static` 이면 `post/patch/delete/put` 을 즉시
거절. 한 줄이고, 아래 "삼키는 자리" 도 여기서 걸린다.

**3. 편집 버튼 숨기기.** 있으면 좋지만 없어도 못 쓸 물건은 아니다 — 눌러도 오류로 끝난다.
페이지마다 흩어져 있어 손이 가므로 나중에.

## 확인한 것 — 대부분은 조용히 안 사라진다

쓰기는 **낙관적 갱신이 아니다.** 응답을 받고 나서 화면을 바꾼다.

```ts
const updated = await questsApi.changeStatus(...);   // 던지면 아래로 안 감
```

실패하면 토스트가 뜬다. 그래서 "저장된 줄 알았는데" 가 대체로 안 생긴다.

**예외가 있다.** 몸짓으로 하는 저장 몇 개는 실패를 삼킨다.

```ts
questsApi.updatePositions([...]).catch(() => {});   // 조용히 버린다
storedPositions.set(qid, ...);                      // 화면은 옮겨진 채로 남는다
```

보드에서 노드를 끌면 화면은 옮겨진 채 남고 새로고침하면 되돌아간다. 체크리스트 토글·순서
바꾸기도 같은 모양이면 같다. 2번이 이걸 덮는다.

## 한 번 만들어 봤다 — 어디까지 되나 (되돌림)

설계가 맞는지만 보려고 1단계를 끝까지 만들어 돌려 봤다. **된다.** 코드는 되돌렸고
(공개 범위를 안 정한 채 이어 만들면 그 결정을 대신 내리게 된다) 여기 결과만 남긴다.

시드 길드를 구워 정적 서버에 올리니 **7개 화면 중 5개가 그대로 열렸다.**

| 화면 | |
|---|---|
| 홈 · 퀘스트 목록 · 보드 · 캠페인 · 도서관 | 열림 |
| 규칙 · 작업기록 | 막힘 |

못 받은 것은 다섯뿐이었다.

```
backlinks/rule/{slug}.json      역링크 (규칙·도서관)
backlinks/book/{id}.json
rules/{slug}/history.json       규칙 이력
worklog.json
worklog/summary.json
```

**확인된 것들.**

- 굽기는 **라우터를 그대로 불러**(`oneshot`) 답을 파일로 떨구면 된다 — 네트워크도 포트도
  두 번째 구현도 필요 없다. API 가 두 벌이 될 수 없다는 뜻이라 이 방식이 맞다.
- 통로는 `Transport` 에 `'static'` 한 갈래를 더하면 끝이고 **호출부는 안 건드린다**.
- `VITE_OPENGUILD_STATIC` 같은 빌드 깃발로 가르면 평소 빌드는 영향이 없다.
- 상대 경로(`api/quests.json`)로 읽으면 `/저장소이름/` 아래에서도 돈다.
- 전체 314줄쯤이었다(프런트 통로 + 굽는 명령).

**걸린 것.**

- 서버 시험 4곳이 `Command` 를 빠짐없이 훑는다 — 서브커맨드를 늘리면 같이 고쳐야 한다.
- 정적 서버(`python3 -m http.server`)는 SPA fallback 이 없어 `/quests` 로 직접 못 연다.
  Pages 는 `404.html` 로 하므로 index 를 그 이름으로 복사해 두면 된다.

**남은 것 중 큰 것은 검색 하나다.** 나머지(위 다섯 경로, 첨부 복사, 쓰기 막기)는 작다.
검색은 서버가 SQL 로 하던 것이라 색인을 굽고 브라우저에서 훑는 코드가 새로 필요하고,
**색인 크기가 공개 범위에 달렸다** — 그래서 범위를 먼저 정해야 한다.

## 정하고 시작할 것 — **공개 범위**

Pages 에 올리면 **퀘스트 본문·댓글·메모가 전부 공개**다. 비공개 저장소여도 Pages 는 공개로
나갈 수 있다. 기능 이전에 정할 문제다.

- 길드를 통째로? 특정 상태(완료된 것만)나 캠페인만?
- 메모는 개인 기록인데 포함할 것인가(기본은 **빼는** 쪽이 맞아 보인다).
- 첨부파일은 실제 파일이라 같이 복사해야 한다 — 저장소가 무거워진다.

## 남은 걸림돌

- **검색** — 지금은 서버가 SQL 로 한다. 색인을 미리 구워 브라우저에서 훑어야 한다. 작은
  길드는 괜찮고 큰 길드는 색인이 커진다.
- **base 경로** — Pages 는 `/저장소이름/` 아래다. SvelteKit `paths.base` 와 404 fallback.

## 테스트 방법

- 구운 폴더를 아무 정적 서버로 띄우면 목록·상세·캠페인·도서관·규칙이 보인다.
- 편집을 시도하면 **오류가 보인다**(조용히 성공한 척하지 않는다).
- 보드에서 노드를 끌어도 "저장 안 됨" 이 드러난다.
- `/저장소이름/` 하위 경로에서도 새로고침이 된다.

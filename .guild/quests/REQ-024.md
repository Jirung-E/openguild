## 무엇을 막나

두 사람(또는 사람과 에이전트)이 **같은 본문**을 동시에 고치면, 나중에 저장한 쪽이
먼저 저장한 쪽을 **조용히** 덮는다. [[BUG-287]] 의 파일 잠금으로는 안 막힌다 —
잠금은 "읽기와 쓰기 사이에 끼어들기" 를 막을 뿐이고, 이건 **편집을 시작할 때 읽은
옛 내용을 기준으로 만든 결과값**을 쓰는 문제다. 편집기를 연 건 몇 분 전이고 그 읽기는
어떤 잠금 안에도 없다.

대상: 퀘스트 본문·제목, 도서관·규칙 본문, 댓글 수정. (태그·댓글 추가 같은 **집합형**
은 BUG-287 이 "의도" 로 바꿔 충돌 자체를 없앤다.)

## 다른 도구는 (조사, 1차 출처)

| | 같은 본문 동시 편집 | 단일값 |
|---|---|---|
| **지라** | **조용히 덮어씀.** 경고 요청 [JRACLOUD-37142](https://jira.atlassian.com/browse/JRACLOUD-37142) 이 2014년부터 미해결. 복구는 "이력 탭에서 옛 설명 복사해 붙이기" | 덮어씀 |
| **노션** | "텍스트 편집은 자동으로 합친다". 오프라인 페이지를 CRDT 모델로 옮겼다 | "select 속성은 **결국 하나만 저장된다**" ([도움말](https://www.notion.com/help/use-pages-offline)) |
| **위키백과** | "**관련 없는 부분은 자동으로 합치고, 같은 줄을 고칠 때만 충돌**" ([도움말](https://www.mediawiki.org/wiki/Help:Edit_conflict)). 판정은 출발 버전 비교. 기본 충돌 화면이 불편해 [문단 나란히 보기 확장](https://www.mediawiki.org/wiki/Extension:TwoColConflict)을 따로 만들었다 | — |

**지라 방식이 정확히 피해야 할 모양**이고, 위키백과가 이 도구(비실시간·다중 편집자·
파일 기반)와 가장 가깝다.

## 거쳐 온 판단 (admin 과의 논의)

1. **"덮인 내용은 이력에서 보면 된다"** — 틀렸다. 본문 수정은 이력에 아예 안 남는다
   ([[REQ-023]]). 그리고 이력이 있어도 **먼저 쓴 사람은 자기 글이 사라진 걸 모른다**
   — 알림은 나중에 저장한 사람에게만 간다. 지라와 같은 모양이다.
2. **"다르면 현재 내용 뒤에 덧붙인다"**(admin 제안) — 조용한 손실은 없앤다. 그러나
   편집기는 본문 **전체**를 보내므로, 한쪽이 오타 하나만 고쳐도 문서가 **통째로 두 배**
   가 된다. "출발점으로 시작하나" 로 덧붙인 경우만 골라내면 줄지만, 진짜 충돌에선 거의
   같은 두 덩어리가 남는다. **합치는 일을 없애는 게 아니라 도구 없는 나중으로 미룰
   뿐**이다.
3. **진짜 충돌에만 차이 화면** — 채택. git 에서 아픈 것(겹치지 않아도 충돌, 파일에
   표시 박기, 해결 전 못 넘어감, 날 diff)을 빼면 위키백과 방식이 된다.

## 설계

```
저장 → 출발 버전 == 현재?
  ├─ 같음            → 그냥 저장
  └─ 다름 → 3방향 병합(출발점, 현재, 내 것)
       ├─ 겹치는 줄 없음 → 조용히 합쳐 저장            ← 대부분 여기서 끝
       └─ 같은 줄 충돌   ├─ GUI → 문단 나란히 보기로 해결 (내 글은 편집기에 보존)
                         └─ CLI/에이전트 → 저장 거부 + 0 아닌 종료 코드 + 현재 내용
```

- **먼저 쓴 사람의 글은 절대 안 건드린다** — 그게 "현재" 쪽이다. 합쳐지거나, 저장하는
  사람이 둘 다 본 상태로 고른다. 조용히 사라지는 경로가 없다.
- **파일에 충돌 표시(`<<<<<<<`)를 절대 안 박는다.** 박으면 문서가 깨지고 그걸 에이전트·
  플러그인·다른 사람이 그대로 읽는다.
- **에이전트는 거부가 맞다.** 보여줄 화면이 없고, 다시 읽고 다시 적용하는 건 에이전트가
  잘한다. 조용하지도 않다.
- 병합은 **서버가 잠금 안에서** 한다 — 그 순간의 최신 내용이 "현재" 여야 한다.
  편집기는 출발 버전(또는 출발 본문)과 내 것을 보낸다.

### 단일값 — 충돌 감수 (admin 판단)

제목·날짜·긴급도·상태. 합칠 수 없으니 나중 쓴 값이 남는다. 노션도 같다.

### 타입 변경·삭제 — 저장 거부 (admin 판단)

편집하던 퀘스트의 slug 가 그사이 바뀌었거나(`DEV-001` → `BUG-005`) 삭제됐으면 **저장을
막는다.** "이 퀘스트는 BUG-005 로 변경되었습니다" / "이 퀘스트는 삭제되었습니다".

- **막더라도 입력 내용은 편집기에 남긴다.** 거부하면서 편집기를 비우면, 막는 행위가 곧
  글을 잃게 만든다. "BUG-005 로 열기" 를 함께 보인다.
- 서버가 이걸 알아채려면 편집기가 **정수 id 가 아니라 편집하던 slug** 를 보내야 한다.
  정수 id 로 보내면 타입이 바뀐 퀘스트에 **조용히 저장이 성공한다** — 정수 id 가 투영의
  내부 값이 밖으로 샌 문제(DEV-049)가 여기서도 드러난다.

## 구현 후보 (들이기 전에 확인)

- 편집기는 CodeMirror 6 — 공식 병합 화면 확장 `@codemirror/merge` 가 있다.
- 서버 3방향 병합은 Rust 크레이트 후보가 있다.

## 선행

[[BUG-287]] — 병합이 "그 순간의 최신 내용" 을 보려면 쓰기가 잠금 안에서 일어나야 한다.

## 테스트 방법

- 겹치지 않는 두 편집(1번째 줄 / 10번째 줄)이 둘 다 남는다 — 화면에 아무것도 안 뜬다.
- 같은 줄을 둘 다 고치면 GUI 는 충돌 화면, CLI 는 0 아닌 종료 코드. **파일에 충돌 표시가
  없다.**
- 충돌 화면을 닫아도 내 글이 편집기에 남는다.
- 먼저 쓴 사람의 글은 어떤 경로로도 사라지지 않는다.
- 편집 중 타입이 바뀌면 저장이 막히고 새 slug 가 안내되며, 입력 내용이 남는다. 삭제도 같다.
- 단일값은 나중 쓴 값이 남는다.

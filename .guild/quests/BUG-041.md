## 증상

사용자 보고: "최신 빌드뿐 아니라 기존에 릴리즈한 바이너리를 실행해도 GUI 가 안
열림. 다른 길드에서 reindex 시도해도:

```
error: failed to migrate index db: migration 10 was previously applied but is
missing in the resolved migrations
```

## 원인

`sqlx::migrate!` 매크로는 컴파일 타임에 migration 셋을 binary 에 박아넣음 →
release 된 binary 의 migration 셋은 영구 고정. DEV-068 작업으로 빌드된 GUI 가
한 번이라도 길드 DB 를 열면 그 DB 의 `_sqlx_migrations` 에 mig 10 record 가
영구 기록 → 그 이후 mig 10 모르는 모든 binary 가 panic 으로 brick.

사용자가 길드를 실제로 안 열어도 GUI 시동 시 Welcome 모드가 placeholder DB
(`%TEMP%/openguild-welcome-placeholder`) 를 디스크에 만들어 같은 sequence 발생.

## 완전 해결 (5단계)

### 1. `set_ignore_missing(true)` (core/src/db.rs)
sqlx Migrator 가 "DB 에는 있는데 binary 가 모르는 mig" 를 panic 대신 무시.
더해 `run_migrations` 가 `Vec<i64>` (ahead 목록) 반환 — 후속 banner 용.

### 2. `core/migrations/0010_quest_tags.sql` (schema-only stub)
DEV-068 작업이 사용자 DB 에 만든 `quest_tags` 테이블의 schema 와 정합. develop
의 코드는 그 테이블을 사용 안 하므로 무해.

### 3. Welcome / Uninit 모드 in-memory DB (core/src/store.rs + gui/src/lib.rs)
근본 원인 해결: `Store::open_in_memory` 를 prod-safe 로 (cfg test 제거 +
cache=shared + unique URI), Welcome/Uninit 분기에서 호출. 디스크 placeholder
안 만듦, 매 시동마다 fresh in-memory DB → 다음 binary 가 영향받을 일 자체가
없음.

```
[openguild-gui] launch mode: welcome (path: <in-memory>)
```

### 4. Schema ahead banner (Store.db_ahead_versions + Tauri command + SchemaAheadBanner.svelte)
- `Store::db_ahead_versions: Vec<i64>` 필드 — `Store::open` 시 채워짐.
- Tauri command `get_db_schema_status` 가 노출.
- Frontend `SchemaAheadBanner.svelte` — Tauri 환경에서 layout 최상단:
  > ⚠ DB schema 가 현재 GUI 버전보다 새롭습니다. 이 길드 DB 에는 현재 binary
  > 가 모르는 migration (10) 이 적용되어 있습니다. 최신 openguild 로 업데이트
  > 권장.
- dismissed 상태는 ahead 셋 signature 로 localStorage 저장 — 같은 mismatch
  재진입 시 안 다시 뜸, 새 mismatch 면 다시 노출.

### 5. `--version` / `--help` flag (gui/src/lib.rs + windows-sys dep)
Tauri 시동 전에 stdout 으로 답하고 종료. Windows release 는 `windows_subsystem
= "windows"` 로 빌드되어 cmd 에서 직접 실행 시 stdout 이 detach → `AttachConsole
(ATTACH_PARENT_PROCESS)` + `SetStdHandle(CONOUT$)` 로 부모 콘솔 attach 후
stdout/stderr redirect.

## 6단계 (사용자 안내 강화 + 회귀 테스트)

### 회귀 테스트 (core)
- `db::tests::run_migrations_tolerates_unknown_applied_version` — `_sqlx_migrations`
  에 version 9999 record 강제 INSERT 후 `run_migrations` 재호출 → panic 없이
  ahead 에 9999 포함.
- `db::tests::run_migrations_returns_empty_ahead_on_clean_db` — 정상 DB 의 ahead
  는 빈 vec.
- `store::tests::open_in_memory_instances_are_isolated` — 두 in-memory store 가
  schema 만 공유 (cache=shared 의 unique URI 정합), ad-hoc 테이블 INSERT 가
  교차 가시 안 됨.
- `store::tests::open_creates_directories_and_dbs` — 정상 시동 시
  `db_ahead_versions` 가 빈 vec.

### Banner UX 강화
- Tauri command `get_db_schema_status` 가 `binary_version`, `latest_known_migration`
  도 반환.
- `SchemaAheadBanner.svelte` 가 "현재 GUI: v0.1.0-beta (migration N 까지 인식) ·
  이 길드 DB: migration M 적용됨" 식의 명확한 비교 메시지 + "최신 버전 받기 ↗"
  버튼 (GitHub release 페이지 — Tauri shell plugin 으로 시스템 브라우저).
- localStorage dismiss signature 에 binary_version 도 포함 — 사용자가 업데이트
  해서 binary 가 바뀌면 (다른 mismatch 라면) banner 다시 노출.

### 복구 안내 (README)
- 영문 / 한글 양쪽 "Development" 섹션 하단에 "Recovery — older binary refuses to
  open" / "복구 — 이전 binary 가 길드를 못 열 때" 추가.
- 응급 처방: `sqlite3 .guild/index.db "DELETE FROM _sqlx_migrations WHERE
  version = N"`.

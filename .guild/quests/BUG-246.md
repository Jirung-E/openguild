# [gui] 데스크톱 타이틀바가 UI 크기 조절을 따라가지 않음

admin 보고: 데스크톱 앱에서 UI 크기를 조절해도 검색 pill 등 타이틀바 버튼 크기가
그대로다. 창 버튼(닫기/최소화/최대화)은 OS 관례상 고정이 맞지만, 나머지 앱 UI는
배율을 따라야 한다.

## 조사 결과 (BUG-244 작업 중 확인, 수정은 안 함)

UI 크기 조절은 root font-size 배율이다(DEV-101 — `uiScale` 스토어). 따라서 rem 은
따라가고 px 는 안 따라간다. 타이틀바는 두 겹으로 막혀 있다.

**1) 타이틀바 높이 자체가 px 상수**

`routes/+layout.svelte` 가 JS 로 root 에 심는다:

```js
root.setProperty('--titlebar-h', showTitleBar ? (linuxTitlebar ? '40px' : '32px') : '0px');
```

`.tb-bar { height: var(--titlebar-h, 32px) }` 이므로 바 높이가 32px 로 고정이다.
안쪽 요소만 rem 으로 바꾸면 배율 150% 에서 22px 짜리 pill 이 33px 가 되어 **바
밖으로 넘친다**. 코드에도 그 인지가 주석으로 남아 있다(`TitleBar.svelte` — "타이틀바
높이(--titlebar-h)보다 크면 안 들어가므로 상한").

**2) `TitleBar.svelte` 내부가 전부 px**

BUG-244 에서 rem 으로 옮긴 것은 **웹 모드의 `Nav.svelte`** 이고, 데스크톱 타이틀바는
별도 컴포넌트라 그대로다.

| 요소 | 현재 |
|---|---|
| 검색 pill `.tb-search` | height 22px / min-width 260px / padding 0 12px / radius 6px |
| 창 버튼 `.tb-btn` | width 46px (Windows), 24px (Linux) |
| 아이콘 | 16×16px |
| 간격 | gap 2px, padding 0 5px 0 10px |

## 작업 방향

1. `--titlebar-h` 를 배율 반응형으로 (예: `2rem` / Linux `2.5rem`). `+layout.svelte`
   의 px 문자열을 rem 으로 바꾸고, 이 값을 쓰는 곳(QuestList / QuestBoard / Nav 의
   `top`, `min-height` 계산)이 함께 따라가는지 확인.
2. `TitleBar.svelte` 의 앱 UI 요소(pill·＋·최근 문서·설정 등)를 rem 으로.
   곡률·테두리는 BUG-244 에서 만든 토큰(`--r-*`, `--bw`) 사용.
3. **창 버튼(.tb-btn)은 px 유지** — Windows 캡션 버튼은 46 × 타이틀바높이가 표준이고
   크기가 변하면 네이티브 창처럼 안 보인다. 단 타이틀바 높이가 rem 이 되면 버튼
   높이(`height: 100%`)는 자연히 따라간다 — 폭만 고정.
4. 배율 50 / 100 / 200% 에서 넘침·잘림 확인. Linux 타이틀바(별도 레이아웃)도 함께.

## 참고

같은 부류의 기존 이슈: BUG-117(UI 크기 조절이 안 먹는 요소들). 곡률·테두리 px 는
아직 앱 전반에 남아 있다(BUG-244 조사: border-radius 322곳 / border 1px 325곳,
그중 팔레트·Nav 만 토큰화).

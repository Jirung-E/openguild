DEV-288 완결. 앞선 작업으로 규칙/BOOK mutation 이 `.guild/history/{slug}.jsonl`
사이드카에 기록되고 상세 화면·CLI 로 열람까지 됐지만(DEV-290), **작업기록
(worklog)** 은 index.db 캐시 테이블만 집계해서 그 활동이 타임라인·히트맵에
안 나왔다 — 사용자 지적 "DEV-288 구현 아직 안 한 건지?".

## 설계 (BOOK-001 불변식 준수)
사이드카(파일=진리원)를 **일방향 투영**할 캐시 테이블 `doc_history`
(migration 0028) 신설. reindex 6d 단계가 quest/campaign 으로 해석되지 않는
사이드카 중 실존하는 rule slug / BOOK id 만 골라 적재하고, wipe 목록에도
추가해 매 reindex 마다 파일에서 100% 재구축된다. DB→파일 역류 없음.

## 변경
- core/migrations/0028_doc_history.sql (kind/slug/ts/op/old/new + 인덱스)
- reindex: doc_history wipe + 사이드카 → 투영(6d)
- worklog activities/daily_summary SQL 에 doc_history UNION,
  ActivityCounts.doc_changes 추가
- CLI worklog show 요약에 "문서 변경(규칙·도서관) N" (0 이면 생략)
- GUI worklog: rule/book 배지(b-doc) + 요약 카운트 + 딥링크
  (`/rules?slug=` · `/library?id=` — 두 페이지의 기존 쿼리 파라미터 확인함)

## 검증
- core 359 테스트 통과, svelte-check 0 errors.
- 임시 길드 실기: rule create/update/rename · BOOK create/update 가
  타임라인에 `[rule]`/`[book]` 으로 표시, 요약 "doc changes 5".
- HTTP: GET /api/worklog → kind rule/book + counts.doc_changes=2,
  /api/worklog/summary(히트맵) 에도 집계됨 — 로컬·원격 동일.

## 테스트 방법
작업기록 페이지에서 규칙/도서관을 수정한 날짜를 보면 활동 행에 "규칙"/"문서"
배지가 뜨고, 클릭 시 해당 문서로 이동. 히트맵 칸 수치에도 포함.

## 고침 — DOMPurify(A안, admin) + 목록 밖 태그는 글자로

1. **거르기**: `MarkdownView` 가 marked 결과를 `DOMPurify.sanitize` 로 거른 뒤 `{@html}`. 스크립트 · `on…` 속성 · `javascript:` 주소 · iframe · object · svg 등은 지운다. 더 막는 것: `style` 태그와 `style` 속성(스크립트 없이도 앱 화면을 덮어 꾸밀 수 있다), `form` · `button` · `textarea` · `select`. 의존성 `dompurify` 3.4.17(2026-10-12 출시) 고정.
2. **목록 밖 태그는 글자로**: 거르기 전에 marked 의 원문 HTML 토큰에서, 본문에 쓸 만한 태그 목록(a · b · br · code · details · summary · div · img · video · table … )에 없는 태그를 글자로 바꾼다. 실제 길드에서 원문 HTML 로 해석되는 47개가 **전부** 백틱 없이 쓴 자리표시(`<slug>` · `<String>` · `<ts>` …)나 태그 언급이었다 — 지금까지 화면에서 사라지고 있었고, `<style>` 은 뒤 문단을 CSS 로 삼켜 숨겼다(DEV-183 · DEV-131). 이제 글자로 보인다. 태그 찾기는 따옴표 속 `<` · `>` 를 넘어 읽는다(`srcdoc="<script>…"` 에서 끊기면 닫히지 않은 iframe 이 뒤를 삼켰다 — 시험이 잡음).

## 길드 확인(사본, 읽기만)
1,320 파일: 원문 HTML 토큰 47(전부 자리표시 · 언급), 일부러 쓴 HTML 0, 첨부 동영상 0. 코드블록 · 인라인 코드 속 HTML 모양 522 는 원래 글자 — 영향 없음.

## 확인
- 시험 `MarkdownViewSanitize.test.ts`(6): 스크립트 · on… · javascript: · iframe(srcdoc) · svg 제거, details 는 남음 / style · style 속성 · form 제거 / 첨부 동영상 2개(controls · 첨부 경로 바꾸기까지) · 이미지 · 링크 4가지 그대로 / 코드블록 하이라이트 · 글자 그대로 / 자리표시 · `<style>` 언급 글자로 · 뒷문장 보임 / 체크박스 · 표 · cross-link 그대로. 기존 cross-link 시험 6 통과.
- 웹 빌드 + 임시 서버(WebKit): 위험한 본문의 퀘스트 → alert 0, 자리표시 · `<style>` 글자로 보이고 뒷문장 보임, 동영상 플레이어 · 접기 · 코드 하이라이트 · 체크박스 그대로, `javascript:` 링크는 주소가 지워져(파란 글자는 남지만 눌러도 아무 일 없음).
- `just test` 통과(eslint · prettier 포함).

## 테스트 방법
아무 퀘스트 본문에 `<img src=x onerror="alert(1)">` · `[눌러](javascript:alert(1))` · `<details><summary>접기</summary>안</details>` · 첨부 동영상을 넣고 본다 → 경고창 없음, 접기 · 동영상은 그대로.

## 플러그인을 통한 주입 — 확인 결과와 고침

admin: "플러그인을 통해 주입할수도 있는지 확인해봐라(알림창에 끼워넣는식)."

### 앱 화면 — 안전
- 화면에서 HTML 로 넣는 곳은 넷뿐: 아이콘 2(코드에 박힌 고정 모양), 마크다운 본문(위에서 DOMPurify), mermaid 그림.
- 플러그인이 화면에 내보내는 글 — `notify(글)`(토스트), `#{instead: 글}`(토스트), 막은 이유(오류), 설명 · 설정 도움말 · 경고 · 문제 — 전부 Svelte 글자 보간(`{…}`)으로 그린다. HTML 이 해석되지 않는다.
- 플러그인이 `pre` 로 제목 · 본문을 바꾸거나 `run` 이 `openguild` 로 길드를 고쳐도, 결국 본문은 MarkdownView 를 지나 걸러진다.

### 찾은 것 — 예제 `desktop-notify`(맥)의 **명령 주입** → 고침
`notify.sh` 가 `osascript -e "display notification \"$body\" …"` 로 퀘스트 제목 · 댓글을 AppleScript 글자에 끼워 넣었다. 제목이 `x" & (do shell script "…") & "` 면 이 플러그인을 허용한 맥에서 셸 명령이 돈다 — **재현함**(해 없는 `touch` 로 파일이 생김). 이제 글은 `on run argv` 의 인자로 넘긴다 — 같은 글이 알림 글자로만 뜨고 명령은 안 돈다(재현 실패 확인), 보통 알림 정상.
- 시험 `shipped_scripts_do_not_splice_text_into_applescript` — 예제 `.sh` 에서 `osascript -e "…$…"` 꼴을 막는다(옛 스크립트를 잡는 것 확인).
- 윈도우판 `notify.ps1` 은 원래 안전(토스트는 XML 이스케이프, 풍선은 인자).
- CHANGELOG Fixed 에 "복사해 쓰고 있다면 notify.sh 를 새 것으로".

### 나머지 예제
- `discussion-to-ai` — 사용자가 정한 명령에 **stdin** 으로, tmux 는 붙여넣기 버퍼로 넘긴다(명령 글자에 안 끼움). 단 tmux 대상 창이 셸이면 붙여넣은 댓글이 Enter 로 셸 명령이 된다 — "AI 창에 넣는다" 는 설계라 그대로 둔다(문서에 주의 문구 거리).
- `claude-session` — 이름은 `[A-Za-z0-9_-]` 만, 폴더는 따옴표 이스케이프, osascript 는 인자로. 괜찮다.
- 코어의 `run` 동작은 셸 없이 프로그램 + 인자로 띄우고 이벤트는 stdin — 이벤트 글이 명령줄에 들어가지 않는다.

### 남은 것 — mermaid
MarkdownView 가 mermaid 를 `securityLevel: 'loose'` 로 그린다(그림 글자 속 HTML · click 허용) — 본문의 mermaid 블록이 또 하나의 주입 길일 수 있다. 다음으로 확인한다.

확인: `just test` 통과(이번에 넣은 서식 검사가 내 시험의 서식을 잡았다 — `cargo fmt` 후 통과).

## mermaid — 뚫림 확인 · 고침

`securityLevel: 'loose'`(DEV-111 때부터, 이유 기록 없음)였다. 본문에

```
click B "javascript:alert('href')"
```

를 쓰면 그림 노드가 `javascript:` 링크가 되고 **누르면 실행됐다**(웹 빌드 · WebKit 재현). 글자 속 `onerror` 는 mermaid 가 스스로 지웠고 `click … call` 은 안 돌았다.

- `strict` 로 — click 을 끄고 그림 글자 속 HTML 을 걸러 둔다. 고친 뒤 같은 본문: 눌러도 alert 없음, 링크 주소 없음.
- 실제 길드의 mermaid 8개 중 click 을 쓰는 것 0, 글자 속 `<br/>` 줄바꿈을 쓰는 것 3(BUG-237 · BOOK-003 · BOOK-007) — BOOK-003 의 그림을 strict 로 그려 `<br/>` 5개가 그대로 줄바꿈으로 나오는 것을 확인.
- CHANGELOG 의 BUG-387 항목에 덧붙임. `just test` 통과.

이로써 확인한 주입 길: 본문 HTML(거름) · mermaid(strict) · 플러그인이 화면에 내는 글(원래 글자) · 예제 desktop-notify(고침). 남은 HTML 넣는 곳은 아이콘 2(고정 모양)뿐.

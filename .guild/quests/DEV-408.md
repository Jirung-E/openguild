## 무엇

([[BOOK-004]] "스크립트 여러 개")

- `scripts = [...]` 에 적은 파일의 함수는 한 공간에 모여 이름만으로 서로 부른다. 이름이 겹치면 불러올 때 오류.
- `import "경로" as 이름` — **폴더 밖도 허용.** 경로는 글자 그대로(불러올 때 목록을 알 수 있게). 지금은 `import` 자체를 막아 두었다.
- 허용 화면에 불러오는 파일 목록. **처음에 한 번만 허락** — 그 파일이 바뀌어도 다시 묻지 않고, 그 사실을 화면에 적는다.
- 공유할 플러그인은 상대 경로를 권한다고 안내.

## 확인

- 두 플러그인이 같은 공통 파일을 불러 쓴다.
- 변수로 적은 경로는 불러올 때 거절된다.

## 구현 / 확인한 것

- `scripts` 목록을 한 공간으로 합치는 것은 [[DEV-403]] 에서 들어갔다. 여기서는 **불러오기**(`import`)를 열었다.
- rhai 의 `no_module` 을 껐다. 대신 **디스크를 안 읽는 해석기**(메모리 모듈)를 꽂는다 — 코어가 적재 때 파일을 읽어 넘기므로
  엔진 자신은 여전히 파일을 모른다. 넘기지 않은 이름은 풀리지 않는다.
- 경로는 **글자 그대로** 적어야 한다(변수면 적재 때 무엇을 읽을지 알 수 없고 화면에도 못 보여 준다). 폴더 밖·절대 경로도
  되고, 불러온 파일이 또 불러오는 것까지 따라간다(깊이 8, 같은 파일은 한 번).
- 적재 때 거절: 없는 파일, `.rhai` 가 아닌 것, 변수 경로, 불러온 파일 안의 비밀값 리터럴.
- **폴더 밖 파일은 바뀌어도 다시 묻지 않는다**(admin 결정). 대신 허용 화면에 "불러오는 파일" 목록과 그 사실을 적는다.
  폴더 안 파일은 예전처럼 지문에 들어가 바뀌면 다시 묻는다.
- 시험: 두 플러그인이 같은 공통 파일을 불러 실제로 그 함수를 쓰는 것, 불러온 파일이 또 불러오는 것, 넘기지 않은 이름은 안
  풀리는 것, 잘못된 경로 네 가지, 폴더 밖 파일을 고쳐도 동의가 유지되고 **바뀐 내용이 반영**되는 것(폴더 안은 다시 물음).

rules 페이지 패턴 재사용: 좌측 문서 목록(BOOK-NNN + 제목) + 우측 MarkdownView/CodeMirror 편집. 신규/삭제/제목변경. Nav 에 도서관 링크. 첨부(이미지 등) 지원 — DEV-097 의 글로벌 첨부를 도서관 문서로 대체하는 결정 반영. ?id=BOOK-NNN 딥링크(cross-link 대상). 선행: CLI/server CRUD.

## 구현 (2026-07-05)
- **Tauri commands** (gui/src/commands.rs): list/get/create/update/delete_book
  — server BookResponse 와 동일 형태(book_id + 필드들). lib.rs 핸들러 등록.
- **transport.ts**: /api/library ↔ invoke 매핑 (routeToInvoke) + 매핑 검증
  테스트(transport.test.ts).
- **lib/api/library.ts**: libraryApi (list/get/create/update/delete).
- **routes/library/+page.svelte**: rules 페이지 구조 그대로 — 좌측 목록
  (BOOK 번호 + 제목 2줄), 우측 MarkdownView/CodeMirror 편집(첨부 paste/drop,
  cross-link 자동완성, 테마/들여쓰기 설정 공유), 신규(제목만 입력 — 번호
  자동)/제목 변경/삭제(soft, 번호 재사용 안내), ?id= 딥링크 + URL 진리원
  (BUG-104 패턴), 편집 중 이동/삭제 확인 모달(DEV-118/119 패턴), unsaved 가드.
- **Nav.svelte**: Rules 옆 Library 링크.

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`
  (transport 매핑 테스트 포함).
- `cargo clippy -p openguild-gui` (Tauri 커맨드 컴파일 확인 — gui 크레이트
  빌드는 이 세션에서 미실행, 사용자 검증 필요).
- 실기 (GUI):
  1. Nav 의 Library → 빈 목록 → "+ 신규" 로 제목 입력 → BOOK-001 생성.
  2. "+ 작성" 으로 본문 편집 — 한글/이미지 paste/[[DEV-001]] 자동완성 확인.
  3. 저장 후 MarkdownView 렌더 확인. 제목 변경 / 삭제 동작 확인.
  4. `/library?id=BOOK-002` 직접 진입 → 해당 문서 선택된 채 열림.
  5. CLI 로 만든 문서(`openguild library new ...`)가 reindex 없이 목록에
     보이는지 (같은 index.db 캐시).
  6. 브라우저 모드(openguild-server)에서도 1~4 동일 동작 (HTTP 라우트).

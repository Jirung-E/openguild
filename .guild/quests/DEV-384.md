## 할 것 1 — [[DEV-383]] 이 미룬 3건

DEV-383 본문에만 적혀 있어 그 퀘스트가 Done 되면 시야에서 사라진다.

- **동작 후 포커스가 `<body>` 로 날아간다.** 허용을 누르면 다음 플러그인까지
  앱 맨 위에서부터 Tab 해야 한다.
- **라이브 리전이 없다.** 비동기로 뜨는 조회 오류·전달 실패를 스크린리더가
  읽지 못한다.
- **신뢰 상태에서 문구가 모순된다.** "허용 전에는 안 돕니다" 바로 밑에
  "이 길드는 전부 허용돼 있습니다" 가 나온다.

## 할 것 2 — 실제로 쓸만한 예제 플러그인

지금은 기능만 있고 **쓸 만한 예가 하나도 없다.** 문서의 `ai-notify` 는 뼈대일
뿐이고, 사용자가 처음 만들 때 참고할 완성품이 없다.

admin 요청: *"특정 퀘스트에 알림설정을 하면 그 퀘스트의 상태가 변경될시
텔레그램으로 메세지가 간다던가."*

"알림설정" 을 **태그**로 하면 새 개념을 안 만들어도 된다 —
`openguild quest tag add DEV-001 notify` 하면 그 퀘스트만 알림이 간다.
이벤트가 `quest.tags` 를 싣게 된 것이 [[DEV-381]] 이므로 지금은 가능하다
(그전엔 항상 빈 배열이라 이 예제가 아예 안 됐다).

`examples/plugins/` 에 복사해서 바로 쓸 수 있는 것으로 넣는다. 셋 다 다른 축을
보여줘야 한다 — `post`/`run`, 스크립트 있음/없음, post/pre.

## 테스트 방법

- 허용을 누르면 포커스가 그 자리에 남는다.
- 신뢰 중일 때 모순된 두 문장이 같이 안 뜬다.
- **예제가 실제로 적재된다** — 정의 검증과 스크립트 컴파일을 검사로 고정한다.
  예제가 안 도는 건 없느니만 못하다.
- 대역 서버로 텔레그램이 받을 실제 JSON 을 확인한다.

## 결과

### 미룬 3건

- **동작 뒤 포커스를 되돌린다.** 목록이 다시 그려지면 눌렀던 버튼이 사라져
  포커스가 `<body>` 로 떨어졌다. 이름으로 버튼을 기억해 두었다가 `tick()` 뒤에
  다시 잡는다.
- **라이브 리전.** 전달 실패 목록에 `role="status" aria-live="polite"`, 조회
  오류에 `role="alert"`, 처리 중에는 `aria-busy`.
- **신뢰 중일 때 소개문을 바꾼다.** "허용 전에는 안 돕니다" 가 바로 밑의
  "전부 허용돼 있습니다" 와 정면으로 어긋났다. 위치만 알린다.

### 예제 셋 — `examples/plugins/`

| | 동작 | 스크립트 | 시점 |
|---|---|---|---|
| `telegram-quest-status` | post | 있음 (태그로 거름) | post |
| `desktop-notify` | run | 없음 | post |
| `deleted-audit` | run | 있음 | **pre** |

셋이 서로 다른 축을 덮는다. 대역 서버로 실제 동작을 확인했다:

```
# notify 태그 없이 상태 변경 → 0건
# 태그를 붙이고 다시 → 1건
POST /bot123456:FAKE.../sendMessage
{"chat_id":"987654321","disable_notification":false,
 "text":"[DEV-001] 배포 스크립트 정리\nin_progress → testing"}
```

`deleted-audit` 은 지워지기 **전에** 남겼고, `desktop-notify` 는 scope 가
`["gui"]` 라 CLI 실행에서 안 돌았다.

**"알림 설정" 을 태그로 했다.** 새 개념을 안 만들어도 되고
(`openguild quest tag add DEV-001 notify`), 떼면 멈춘다. 이게 되는 건
[[DEV-381]] 이 이벤트의 `tags` 를 채운 뒤부터다 — 그전엔 항상 빈 배열이라 이
예제가 **아예 성립하지 않았다.**

### 예제를 만들다 발견한 것 — `body_env`

텔레그램은 `chat_id` 를 **본문에** 요구한다. 그런데 스크립트에는 I/O 가 없어서
`payload()` 가 환경변수를 못 읽는다 — 그게 [[DEV-376]] 샌드박스의 요점이라
바꿀 수 없다. url 과 헤더만 확장해서는 이런 API 를 못 쓴다.

리뷰가 이걸 지적했었고(#7) 내가 LOW 로 보고 넘겼다. **실제 예제를 만들어 보니
플래그십 예제가 아예 성립하지 않았다.** 리뷰 지적의 값은 심각도 라벨이 아니라
그게 막는 것에 있다.

`"body_env": { "chat_id": "TELEGRAM_CHAT_ID" }` 로 **정의가 지목한 키에만**
넣는다. 본문 전체를 훑어 `${VAR}` 를 푸는 방법도 있었지만 안 했다 — 사용자가 쓴
댓글이 우연히 `${HOME}` 이면 그게 확장돼 나간다. 시험으로 고정해 뒀다.

### 예제가 도는지 검사로 고정했다

`shipped_examples_all_load` 이 예제를 진짜 길드에 복사해 넣고 적재한다. 만들자
마자 물었다 — `const` + `global::` 문법이 `no_module` 에서 안 통해 스크립트가
컴파일이 안 됐다. **예제가 안 도는 건 없느니만 못하다**: 복사해 쓰는 사람은
자기가 뭘 잘못했나 하고 헤맨다.

동작/스크립트 유무/pre 를 각각 하나 이상 덮는지도 함께 본다 — 한쪽으로 몰리면
예제 구실을 못 한다.

### 되돌림 시험 3건 물었다

예제 스크립트 깨뜨리기 · `body_env` 주입 제거 · 본문 전체 확장으로 바꾸기.

## 자진 신고 — [[DEV-383]] 이 깨진 채로 머지됐다

DEV-383 의 되돌림 시험에서 `git checkout -- gui/frontend/src/lib/api/plugins.ts`
로 원복했는데, 그때 그 파일의 변경이 **아직 커밋 전**이라 `no_guild` 필드가 통째로
날아갔다. `just test` 는 그 **전에** 돌렸으므로 통과했고, 그대로 커밋했다.

develop 이 잠시 프런트 타입 검사 실패 상태였다(이번 작업 첫 `svelte-check` 가
잡았다). 여기서 되살렸다.

배운 것 둘:
- 되돌림 시험의 원복은 **백업 파일에서** 한다. `git checkout --` 은 커밋 안 된
  작업을 같이 지운다.
- `just test` 는 **되돌림 시험을 다 끝낸 뒤, 커밋 직전에** 한 번 더 돌린다.
  앞에서 통과한 것은 커밋되는 상태의 증거가 아니다.

admin 보고: 도서관에서 여러 문서에 들어갔다 나왔다 하고 뒤로가기를 해도
이전 문서나 폴더가 아니라 그냥 도서관에서 나가짐.

## 원인
`library/+page.svelte` 의 `syncUrl(id)` 가 문서 선택마다 `goto(...,
{ replaceState: true })` 로 URL 을 갱신 — 매번 현재 history entry 를
덮어쓸 뿐 새로 쌓지 않았음. rules/worklog/퀘스트 보드·리스트도 같은
`replaceState` 패턴을 쓰는데("선택은 페이지 이동이 아니다"라는 절충으로
BUG-104 때 도입됨), admin 확인 결과 그건 명시적으로 요청한 설계가 아니었고
이 버그와도 무관 — 도서관에 한해 pushState 로 바꾸기로 결정.

추가로 explorer 모드의 폴더 이동(`explorerPath`)은 애초에 URL 에 전혀
반영되지 않아, 폴더를 옮겨다닌 것도 뒤로가기로 되돌릴 방법이 없었음.

## 수정
- `syncUrl()` 을 인자 없이 `selectedId`+`explorerPath` 둘 다 읽어 URL
  (`?id=`, `?path=`) 을 구성하도록 재작성, `replaceState` 제거(기본
  pushState) — 문서 선택/폴더 이동마다 새 history entry.
- explorer 모드 폴더 클릭(브레드크럼/타일)을 `gotoFolder()` 로 통일 —
  상태 갱신 + syncUrl 호출.
- `explorerBack()`(← 목록) 도 URL 갱신 누락돼 있던 것 수정.
- URL(뒤로/앞으로가기) → 상태 복원 `$effect` 를 `id`+`path` 둘 다 보도록
  확장, browser-driven 갱신은 already-synced 가드로 재-push 안 함.

## 범위 결정 (admin, 2026-07-07)
rules/worklog/퀘스트 보드·리스트의 동일한 replaceState 패턴은 이번엔
안 건드림 — 이번 요청은 도서관 한정 버그 신고였고, 나머지를 바꾸는 건
더 큰 범위의 별도 검토가 필요.

## 테스트 방법
- `cd gui/frontend && npm run check && npm test -- --run` (프론트만 변경,
  Rust 쪽 변경 없음).
- 실기: 도서관에서 폴더 여러 개 들어갔다 나왔다 + 문서 여러 개 열어본 뒤
  브라우저/앱 뒤로가기 → 직전 문서/폴더로 한 단계씩 되돌아가는지(마지막에
  도서관 진입 전 페이지로). 앞으로가기도 대칭적으로 동작하는지.

## 증상

퀘스트 목록에서 **'댓글 포함' / '첨부 이름 포함'** 을 켜고 검색한 뒤 다른
페이지에 갔다 오면 체크가 풀려 있다. 검색어·타입·상태 등 나머지 필터는
그대로 유지되는데 이 둘만 초기화된다.

## 원인 (확인함)

`QuestList.svelte` 에서 두 플래그가 **영속 계층에 배선되지 않았다.**

```ts
let searchComments = $state(false);
let searchAttachments = $state(false);
```

목록의 나머지 필터는 전부 `QuestFilterState` 를 거친다 —
`snapshotFilter()` → `questFilters` store(뷰 전환용 in-memory) +
`serializeFilter` → localStorage(전체 리로드용). REQ-010 이 플래그 2개를
추가하면서 이 경로에 넣지 않아, 컴포넌트가 다시 마운트되는 순간 `false` 로
돌아간다.

`search` / `titleOnly` 가 갖고 있는 URL 동기화(`?search=` / `?title_only=`)도
없다. 두 플래그는 `search` 의 **수식어**인데 검색어만 URL 로 옮겨가고 범위는
빠져, 링크를 공유하면 다른 결과가 나온다.

## 수정 방침

`QuestFilterState` 에 두 필드를 넣어 나머지 필터와 같은 길을 타게 한다 —
`EMPTY_FILTER` / `serializeFilter` / `deserializeFilter` / `snapshotFilter` /
`applyFilter`, 그리고 `?search_comments=` / `?search_attachments=` URL 동기화.

`isFilterActive` 에는 **넣지 않는다.** 검색어가 비어 있으면 이 플래그만으로는
결과가 달라지지 않아, '필터 활성' 표시만 켜지고 보이는 변화가 없다.

## 배경

`quest-filter.ts` 에 테스트가 하나도 없다. 직렬화 왕복 테스트가 있었으면
필드 누락이 바로 잡혔을 자리다 — 같이 붙인다.

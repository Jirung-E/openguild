core/src/recents.rs 의 path() 가 OS user data dir 하나의 recents.json 을 반환. 모든 recents::tests 가 같은 파일에 read/write → 병렬 실행 시 race로 3건 정도 fail (assertion left=0 right=2 등). 격리 실행 (--test-threads=1) 시 통과. fix: cfg(test) 시 env var 또는 thread-local 로 임시 path override.

## 증상

```
cargo test -p openguild-core --lib
...
test recents::tests::add_existing_path_moves_to_top ... FAILED
test recents::tests::add_truncates_to_max ... FAILED
test recents::tests::name_falls_back_to_dir_basename ... FAILED

test result: FAILED. 220 passed; 3 failed
```

격리 실행 시:
```
cargo test -p openguild-core --lib recents -- --test-threads=1
test result: ok. 7 passed
```

## 원인

`core/src/recents.rs` 의 `recents_path()` 가 `directories` crate 의 OS user
data dir (`%LOCALAPPDATA%/openguild/openguild/data/recents.json`) 을 반환.
모든 테스트가 같은 단일 파일에 read / modify / write → tokio multi-thread
runtime 하에서 race.

## 작업 (옵션)

### A. cfg(test) thread-local override
`recents_path()` 안에 `#[cfg(test)] thread_local!` 로 임시 dir override 가능
하게.

### B. 환경 변수 기반 override
`recents_path()` 가 `OPENGUILD_RECENTS_DIR` env 우선 사용. 각 테스트가
fresh_tmp 디렉토리 set 후 path() 호출.

### C. serial_test crate
`#[serial]` attribute 로 recents 테스트만 직렬. 의존 추가 부담.

권장: **A** (가장 격리, 의존 추가 X).

## 영향

테스트만 flaky — 실 사용 (CLI / GUI) 동작에는 영향 없음. release 차단 요소
아님.

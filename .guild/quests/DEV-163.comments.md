# ADR: openguild-server 역할 = host 전용

## 결정
`openguild-server` 는 **HTTP host + 런타임 HTTP admin 전용**으로 한다.
데이터 조작과 **모든 오프라인 정비**는 `openguild`(CLI)가 담당한다. 실행 중
host 의 조작은 **HTTP admin endpoint** 로만 한다(별도 프로세스 금지).

## 맥락 — 현재 명령 비교
| 명령 | CLI | server | 성격 |
|---|:--:|:--:|---|
| host | — | ✓ | server 고유(존재 이유) |
| 데이터 CRUD | ✓ | — (HTTP) | CLI 고유 |
| reindex / snapshot / restore / check-drift | ✓ | ✓ | 🔁 중복 |
| info(진단) | ✗(ping) | ✓ | server에만 |
| check-counters / vacuum / journal-tail | ✗ | ✓ | server에만 |
| migrate-to-files | ✗ | ✓ | 일회성 |

## 세 질문
1. **CLI 명령을 server가 똑같이 가질 필요? — 없다.** 모두 `.guild/`+index.db
   작업이라 CLI Local 모드가 동일하게 한다. 중복의 유일한 정당화는 "host 에
   CLI 없이 server 만 배포"인데, 그 경우라도 *실행 중* host 에 별도 프로세스로
   정비를 돌리면 index.db 동시 writer + 인메모리 stale 위험이 크다.
2. **CLI에 있어야 하는데 server에만 — 있다.** vacuum, journal-tail, check-counters,
   진단 info, (그리고 migrate-to-files).
3. **호스팅 중 조작 — 필요. 단 HTTP로.** 풀/상태 일관성 + 락 충돌 회피를 위해
   런타임 정비는 admin endpoint 를 거쳐야 한다. 현재 snapshot/reindex/drift/restore
   만 있으니 vacuum/journal-tail/counters 를 endpoint 로 추가하면 `openguild --remote`
   ·GUI 로 라이브 host 를 완전 관리할 수 있다. → server 서브커맨드를 늘릴 게 아니라
   HTTP admin 을 늘려야 한다.

## 역할이 중복되는 명령어 (점검 결과)
- **`backup` ≡ `snapshot`**: server 가 `snapshot` 과 그 alias `backup` 을 둘 다 보유 →
  중복 alias. 게다가 CLI 는 `backup`, server 는 `snapshot` 으로 이름 불일치. → CLI
  의 `backup`/`backups`/`restore` 명명으로 통일.
- **`check-drift --resync` ⊃ `reindex`**: resync 가 곧 reindex. 기능 포개짐(드리프트
  탐지가 추가가치라 제거는 아님, 인지만).
- **`ping`(CLI) vs `info`(server)**: 둘 다 상태 확인 성격으로 일부 겹침 → CLI 에
  진단 info 를 두면 정리됨.

## 정리 작업 (서브퀘스트)
- **DEV-162** — vacuum·journal-tail 을 CLI + HTTP admin + GUI 로 노출. (prereq DEV-023)
- **DEV-164** — CLI 오프라인 정비 완비: check-counters, 진단 info, migrate-to-files 이전.
- **DEV-165** — server 중복 정비 서브커맨드 제거(host 전용화) + backup≡snapshot 정리.

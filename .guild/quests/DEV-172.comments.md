현재 상태 실측 (서버 모드, 본문 편집기에서 `[[` 자동완성 팝업을 띄워 DOM 계측):

- **스크롤바는 이미 커스텀이다.** 팝업 `ul` 의 스크롤바 gutter = **10px** — global.css 의 전역 `::-webkit-scrollbar { width: 10px }`(반투명 thumb / 투명 track / 8px radius)가 그대로 적용된다. OS 기본(약 15px)이 아니다.
- 다만 **overlay 는 아니다** — OverlayScrollbar 컴포넌트가 아니라 webkit 스크롤바라 폭 10px 를 실제로 차지한다. 댓글의 caret 팝업(BUG-157 에서 overlay 로 통일)과 다른 점은 이것뿐이고, 이 퀘스트(caret 팝업으로 통일)를 하면 자연히 정리된다.

같이 확인한 것 (모두 정상):
- 팝업이 조상 overflow 에 잘리지 않는다 — 툴팁이 `body` 직계 자식으로 붙어 있다(BUG-115 의 `tooltips({parent: document.body})` 가 살아 있음).
- 방향키 스크롤 이동량 = **19px**, 항목 높이 18.8px — 팝업 높이(140px)만큼 튀지 않는다(BUG-163 수정 유효).
- 후보 수 154건(`[[BUG-1` 기준) / 998건(빈 `[[`) 모두 렌더 — BUG-115 의 maxRenderedOptions 상향 유효.

측정 중 툴팁 좌표가 `top:-10000` 으로 나온 적이 있는데, 이는 헤드리스로 조작하며 페이지가 컴포지팅을 안 하는 상태의 계측 artifact 로 보인다(CodeMirror 는 커서 위치를 측정 못 하면 툴팁을 화면 밖에 대기시킨다). 실제 사용 중 팝업이 엉뚱한 위치에 뜬다는 보고가 있으면 별도 항목으로.

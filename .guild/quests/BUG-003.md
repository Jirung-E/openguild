## 증상

`openguild-server check-counters --fix` 가 drift 를 발견하면 "보정됨" 로그를 찍지만
실제로 `.guild/index.db` 의 `quest_counters` 테이블은 갱신되지 않음. 두번째 호출은
"발견 이슈: 0" 보고 (file counter 는 fix 후 일치 상태이므로). 결과적으로 다음
`quest new` 호출이 SQL `quest_counters.last_number + 1` 로 INSERT 시도 → 기존 quest
번호와 충돌 → `UNIQUE constraint failed: quests.quest_type_id, quests.number`.

## 재현 (2026-05-17 dogfood)

1. 외부 도구로 `.guild/quests/BUG-001.md` 직접 생성 (number=1).
2. SQL counter (`quest_counters.last_number`) 는 그대로 0.
3. `openguild-server check-counters` → "type BUG: 0 → 1" 로 drift 보고.
4. `openguild-server check-counters --fix` → "→ 1 으로 보정됨".
5. `.guild/types/BUG.toml` 의 `[counter] last_number = 1` 로 갱신됨 ✓
6. **그러나** `index.db` 의 `quest_counters` 는 `1|0` 그대로 ✗
7. `openguild quest new --type BUG ...` → UNIQUE constraint 에러.
8. SQL 수동 UPDATE 후에야 정상 동작.

## 원인 분석

`core/src/counter.rs::check_counters` 는 type 파일 (`*.toml`) 만 읽고 쓴다.
`index.db.quest_counters` 는 건드리지 않음.

런타임 `quest new` 는 SQL counter 를 사용 (`services/quests.rs:create`):
```sql
UPDATE quest_counters SET last_number = last_number + 1 ...
```

→ file-as-truth 와 SQL-cache 사이 동기화 누락.

## 수정 (2026-05-18)

옵션 1 (가장 작은 변경) 채택:

- `core/src/ops/counter.rs` 신설 — `check_and_fix_counters(store, auto_fix)`:
  - 내부에서 file-only `core::counter::check_counters` 호출.
  - `auto_fix=true` 면 각 issue 의 prefix → quest_type_id 조회 후
    `UPDATE quest_counters SET last_number = ?` 추가 실행.
  - index.db 에 type 이 없으면 (reindex 미실행 등) warn 로그 후 skip.
- `core/src/ops/mod.rs` 에 `check_and_fix_counters` 노출.
- `server/src/main.rs::run_check_counters` 가 새 함수 사용.
  - async fn 으로 변환, `Store::open` 후 호출.
  - 출력 메시지 "→ 6 으로 보정됨" → "→ 6 으로 보정됨 (file + SQL)".

테스트 3건 추가 (`core/src/ops/counter.rs::tests`):
- `fix_propagates_to_sql_counter`: file drift → fix → SQL 도 갱신 확인.
- `no_fix_means_no_sql_update`: auto_fix=false 면 SQL 그대로.
- `fix_then_create_quest_succeeds`: 핵심 시나리오 — drift 상태에서 fix 후
  즉시 `ops::create_quest` 호출 → BUG-002 정상 생성. UNIQUE constraint X.

## 증상

`openguild-server check-counters --fix` 가 drift 를 발견하면 "보정됨" 로그를 찍지만
실제로 `.guild/index.db` 의 `quest_counters` 테이블은 갱신되지 않음. 두번째 호출은
"발견 이슈: 0" 보고 (file counter 는 fix 후 일치 상태이므로). 결과적으로 다음
`quest new` 호출이 SQL `quest_counters.last_number + 1` 로 INSERT 시도 → 기존 quest
번호와 충돌 → `UNIQUE constraint failed: quests.quest_type_id, quests.number`.

## 재현 (2026-05-17 dogfood)

1. 외부 도구로 `.guild/quests/BUG-001.md` 직접 생성 (number=1).
2. SQL counter (`quest_counters.last_number`) 는 그대로 0.
3. `openguild-server check-counters` → "type BUG: 0 → 1" 로 drift 보고.
4. `openguild-server check-counters --fix` → "→ 1 으로 보정됨".
5. `.guild/types/BUG.toml` 의 `[counter] last_number = 1` 로 갱신됨 ✓
6. **그러나** `index.db` 의 `quest_counters` 는 `1|0` 그대로 ✗
7. `openguild quest new --type BUG ...` → UNIQUE constraint 에러.
8. SQL 수동 UPDATE 후에야 정상 동작.

## 원인 분석

`core/src/counter.rs::check_counters` 는 type 파일 (`*.toml`) 만 읽고 쓴다.
`index.db.quest_counters` 는 건드리지 않음.

런타임 `quest new` 는 SQL counter 를 사용 (`services/quests.rs:create`):
```sql
UPDATE quest_counters SET last_number = last_number + 1 ...
```

→ file-as-truth 와 SQL-cache 사이 동기화 누락.

## 수정 (2026-05-18)

**1차 수정 (불완전)**: file fix 시 SQL 도 같이 UPDATE. file<max 케이스만 처리,
"file 은 OK, SQL 만 깨짐" 케이스는 못 잡음 — 사용자 dogfood 에서 재현:
```
file BUG.toml [counter].last_number = 6
SQL  quest_counters.last_number     = 0
→ check-counters: "발견 이슈: 0" (file 검사만 함)
→ quest new: UNIQUE constraint 에러 (SQL 0+1=1 → 충돌)
```

**2차 수정 (완전)** — `check_and_fix_counters` 가 **두 가지 drift 모두 검사**:

1. **file drift** (`file_report`): file `[counter].last_number < 실제 max` —
   기존 `core::counter::check_counters` 그대로 사용. auto_fix=true 면 file 갱신
   + 같은 prefix 의 SQL 도 동기화 (1차 수정 동작).
2. **SQL drift** (`sql_drift`): file `[counter].last_number ≠ SQL last_number` —
   2차 추가. file 을 source of truth 로 SQL 갱신.

`CombinedReport { file_report, sql_drift }` 로 두 종류 분리 보고. CLI 출력에서도
구분:
```
발견 이슈     : 0 (file) + 1 (SQL)

• type BUG [SQL drift]:
  file last_number     : 6
  SQL  last_number     : 0
  → 6 으로 보정됨 (SQL ← file)
```

테스트 4건 (`core/src/ops/counter.rs::tests`):
- `file_below_max_fixes_both` — 1차 시나리오.
- `sql_drift_only_synced_from_file` — **사용자 보고 케이스** (file OK, SQL 깨짐).
- `fix_then_create_quest_succeeds_when_only_sql_drifted` — SQL drift 만 있는
  상태에서 fix → create_quest 가 BUG-007 정상 생성.
- `dry_run_no_writes` — auto_fix=false 시 file 도 SQL 도 안 건드림.

## 검증 (dogfood, 2차)

```bash
# 1. SQL 만 망가뜨림 (file 은 OK)

# 2. 검사만 — SQL drift 발견되어야 함

# → "발견 이슈     : 0 (file) + 1 (SQL)"

# 3. fix 실행
openguild-server check-counters --fix
# → "→ 6 으로 보정됨 (SQL ← file)"

# 4. 즉시 새 BUG quest 생성 — 막혀있던 시나리오가 이제 통과
openguild quest new --type BUG --title "test"
# → BUG-007 정상 생성. UNIQUE constraint 에러 없음.
```

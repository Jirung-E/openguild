## 왜 먼저인가

**되돌리기가 가장 어려운 결정**이다. 플러그인이 한 번 이름을 구독하기 시작하면
그 이름은 계약이 된다. 나머지 서브퀘스트는 나중에 바꿔도 되지만 이건 아니다.

## 문제

journal 의 `op` 51종은 내부 함수명이라 공개 계약으로 쓸 수 없다 —
동사 위치가 뒤섞이고(`add_attachment` vs `campaign_checklist_add`), 같은
개념을 다르게 부르고(`add_comment_entry` vs `add_campaign_comment`), 내부
사정이 새어 나오고(`set_comments` 는 파일 일괄 쓰기), 무엇보다 `toggle_*`
6종은 **해결/해제를 구분하지 못한다.**

그대로 노출하면 함수 이름을 다시는 못 바꾼다.

## 할 것

**1. 공개 이름 — `리소스.동사`**

```
quest.created · quest.updated · quest.deleted · quest.restored
quest.status_changed · quest.tags_changed · quest.due_changed
comment.added · comment.updated · comment.deleted
comment.resolved · comment.unresolved · comment.pinned · comment.unpinned
campaign.* · book.* · rule.* · attachment.*
```

`toggle_*` 은 `args` 를 보고 **양쪽으로 갈라서** 낸다. 내부 이름과 1:1 이
아니어도 된다 — 그게 매핑을 두는 이유다.

**2. 와일드카드** — `quest.*`, `*.created`. 51종(앞으로 더 늘)을 일일이 쓰게
하면 플러그인 작성이 고통스럽고, 새 이벤트가 생겨도 기존 구독자가 못 받는다.

**3. 페이로드 래핑** — **이름만 계약이 아니다.** 지금 `args` 는 요청 구조체를
그대로 직렬화한 것이라 필드를 바꾸면 플러그인이 깨진다. 한 겹 감싼다:

```json
{ "event": "comment.resolved",
  "ts": "2026-09-07T…+09:00",
  "guild": "openguild",
  "quest":   { "id": "DEV-007", "title": "…", "status": "in_progress" },
  "comment": { "id": 3, "author": "…", "discussion": true } }
```

**4. 누락 검사** — 새 mutation 이 생겼는데 공개 이름이 없으면 **조용히
구독 불가**가 된다. `check:guards`(DEV-372)와 같은 방식으로 막는다:
내부 op 목록과 매핑표를 대조해 빠진 것이 있으면 실패.

의도적으로 공개하지 않는 것(`set_comments` 같은 내부 일괄 쓰기)은 목록에
**이유와 함께** 명시적으로 제외한다 — 빠뜨린 것과 뺀 것을 구분한다.

## 시점 — 성공한 뒤에만

journal 은 `// 1. journal append (의도 기록)` 로 **하기 전에** 쓴다. 뒤에서
실패해도 남으므로 그대로 구독하면 **실패한 시도까지 나간다.** 이벤트는
mutation 이 성공한 뒤에 낸다.

`journal::append` 54곳 중 53곳이 `result` 를 `None` 으로 넘겨 **결과가 아예
없다**는 점도 같은 이유다 — `create_quest` 의 args 에는 새로 부여된
`DEV-007` 이 없다.

51종 전부에 명시적 `emit` 을 다는 완전한 형태는 이번 범위가 아니다. 공개
이름을 내부와 분리해 두는 것이 목적이고, 그러면 나중에 갈아타도 플러그인이
안 깨진다.

## 테스트 방법

- 매핑표의 모든 공개 이름이 실제 내부 op 에 대응한다(양방향).
- 새 op 을 추가하고 매핑을 안 넣으면 검사가 **실패**한다(되돌리기 시험).
- `toggle_comment_resolved` 가 args 에 따라 `comment.resolved` /
  `comment.unresolved` 로 갈린다.
- 와일드카드 매칭 — `quest.*` 가 `quest.created` 를 잡고 `comment.added` 는
  안 잡는다. `*.created` 는 리소스를 가리지 않는다.
- 페이로드가 내부 구조체 변경에 흔들리지 않는다(필드 이름 고정).

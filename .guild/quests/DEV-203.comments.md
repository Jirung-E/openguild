[계획] 구현 계획 (2026-07-03)

**신규**: `gui/frontend/src/lib/components/MarkdownEditor.svelte`. **교체 4곳**: quests/[id], campaigns/[slug], QuestNoteSection, rules/+page.

1. Props 설계:
   - `value: string` ($bindable) — CM ↔ 외부 양방향.
   - `heightKey: string | null` — localStorage 영속 높이(null=비영속), 리사이즈 핸들 포함.
   - `attach: { mode: 'media-only' | 'full'; onError: (m: string) => void; onAttach?: ... }` — memo/rules=media-only, quest/campaign=full(첨부 섹션 콜백).
   - `placeholder?`, `disabled?`.
2. 내부 고정(공통): basicSetup + markdown() + theme Compartment(라이브 전환) + indentExtensions(editorSettings) + crossLinkAutocomplete + Mod-Shift-z redo + OverlayScrollbar. — DEV-202 누락 사고의 재발 방지 핵심: 이 목록이 단일 지점이 됨.
3. 이관 절차(회귀 최소화): ① 컴포넌트 신설 + rules 부터 교체(가장 단순) → ② memo → ③ quest → ④ campaign. 각 단계에서 svelte-check + 수동 스모크(입력/자동완성/첨부/높이 기억/다크 전환).
4. 파괴 금지 확인 목록: 편집 이탈 가드(setUnsaved)는 호출측 유지, 저장 버튼/단축키도 호출측. 컴포넌트는 "편집기 위젯"만.
5. DEV-172(본문 자동완성도 caret 팝업 통일)와 겹침 — 추출 후 하면 1곳 수정으로 끝나므로 **이 퀘스트를 DEV-172 의 선행으로** 권장 (prereq 제안).

예상 규모: 중형(신규 ~200줄 + 4곳 診 감축). 위험: CM 인스턴스 수명주기(교체 시 destroy) — 기존 각 페이지의 onDestroy 패턴 이식.

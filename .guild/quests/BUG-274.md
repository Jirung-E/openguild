## 증상

데스크톱 앱에서 언어를 English 로 바꿔도 **Rust 가 만든 문장은 계속 한국어로**
나온다. 영어 UI 한가운데 한국어 한 줄이 끼는 화면이 된다.

## 원인 둘

**1. 데스크톱 앱은 언어를 Rust 쪽에 안 알린다.**

프런트의 `setLocale()` 은 스토어와 `localStorage` 에만 쓴다
(`gui/frontend/src/lib/stores/locale.ts`). Rust 의 `locale::current()` 는
`~/.openguild/locale.json` 을 읽는데, 그 파일을 쓰는 곳은 **CLI 의
`openguild locale <lang>` 과 서버뿐**이다. GUI 에는 그 경로가 아예 없다(확인함 —
`gui/src/commands.rs` 에 locale 커맨드가 없다).

`cli/src/main.rs` 의 주석은 "저장된 언어(~/.openguild/locale.json, **GUI 와
공유**)" 라고 적어 뒀는데, 읽기만 공유고 쓰기는 공유가 아니다.

**2. 사용자 대면 메시지의 절반이 `tf!` 를 안 거친다.**

`core` 의 `AppError::BadRequest` / `NotFound` 중 한국어가 든 것이 15곳인데
`tf!` 를 쓰는 건 8곳이다. 1번을 고쳐도 나머지 7곳은 여전히 한국어로 나온다.

## 어디서 드러났나

[[DEV-383]] 에서 플러그인 화면의 안내문을 `no_guild` 플래그로 바꿔 프런트가 문구를
만들게 했다. 그건 그 화면만 막은 것이고, 적재 오류(`plugin.json 형식 오류: …`)와
전달 실패 메시지는 여전히 Rust 가 만든 한국어가 그대로 렌더된다. 플러그인만의
문제가 아니라 **Rust 문장이 GUI 에 나오는 모든 자리**가 같다.

## 고칠 방향

- GUI 에서 언어를 바꿀 때 `locale::save()` 를 태우는 경로를 만든다(Tauri 커맨드).
  시동 때 한 번 맞추는 것도 필요하다 — 이미 저장돼 있던 값과 어긋날 수 있다.
- 남은 7곳을 `tf!` 로 감싼다. 새로 추가되는 것도 놓치지 않게 검사를 붙일지 판단.
- 아니면 반대 방향 — Rust 는 **코드**만 넘기고 문구는 프런트가 만든다
  ([[DEV-383]] 의 `no_guild` 방식). 어느 쪽으로 갈지 먼저 정할 것.

## 테스트 방법

- 데스크톱에서 English 로 바꾸고 앱을 다시 켜도 Rust 메시지가 영어다.
- 같은 상태에서 CLI 를 실행하면 CLI 도 영어다(같은 파일을 본다).
- 깨진 `plugin.json` 이 있는 길드를 English 로 열면 오류가 영어로 나온다.

## 정함 (2026-10-04, admin)

추천대로 "가" — 앱이 언어를 바꿀 때 Rust 쪽도 맞추고, 번역이 빠진 오류 메시지를 채운다.

## 고침

- 앱 명령 `set_locale` — `~/.openguild/locale.json`(CLI · 서버와 같은 파일)에 쓴다. Rust 는 이 파일을 매번 읽어 바로 먹는다.
  화면의 언어 스토어가 시동 때 한 번, 바꿀 때마다 부른다(데스크톱일 때만 — 웹은 서버 자기 설정을 따른다).
- 사람에게 가는 오류(`AppError::BadRequest` · `NotFound` · `Cancelled`) 중 한국어만 적힌 **18곳**을 `tf!(한국어, 영어)` 로
  (댓글 이모지 · 작성자, 배너 이미지, 토론 resolve, 완료 전환 거부, 날짜 형식, 플러그인 동의 · 소스 · 값 파일, 스크립트 읽기 · 컴파일 · 함수 겹침).
- **다시 새지 않게** 시험 `user_facing_errors_are_bilingual` — core 소스에서 저 오류들에 한국어 글자를 그대로 넣으면 실패.

## 남은 것 → BUG-350

플러그인 실행 중 문제 칸에 뜨는 문장(전달 실패 · 적재 · 스크립트 실행 오류 등)은 `AppError` 가 아니라 글자로 만드는 것이라 이번
범위 밖이다 — 88곳. 따로 세웠다.

## 시험

- 가드 시험(고치기 전 파일 하나로 되돌리면 실패하는 것 확인), 프런트: 데스크톱이면 시동 · 변경 때 `set_locale`, 웹이면 안 부름.

## 테스트 방법

1. 앱 설정에서 언어를 English 로 바꾼다.
2. 날짜 칸에 `2026-1-1` 처럼 잘못 넣고 저장하거나, 토론이 아닌 댓글을 resolve 해 본다 → 오류가 영어로 나오면 정상.
3. 터미널에서 `openguild locale` → `en` 이면 정상(앱과 CLI 가 같은 설정을 본다).

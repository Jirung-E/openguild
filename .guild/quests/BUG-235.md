## 증상

cross-link 에 마우스를 호버해서 문서 미리보기 팝업이 뜬 상태에서(자동완성
팝업이 아니라 호버 시 뜨는 해당 문서 미리보기), 팝업의 버튼이 아니라 본문의
cross-link 텍스트(`a.xlink` 칩) 자체를 클릭해서 문서로 이동하면 미리보기
팝업이 사라지지 않고 새 페이지에도 남아있음.

## 원인

`MarkdownView.svelte`(DEV-256)에서 팝업 안의 "페이지 이동" 버튼(`goPage`)은
`onnavigate={() => (hoverTarget = null)}` 경로로 팝업을 정리하지만, 본문에
렌더된 `a.xlink` 앵커 자체를 직접 클릭하는 경로에는 별도 핸들러가 없어
SvelteKit 기본 anchor 인터셉트로만 이동하고 `hoverTarget` 이 안 지워졌음.

## 수정

컨테이너에 click 위임 핸들러(`onContainerClick`)를 추가해, `a.xlink` 클릭 시
열림/닫힘 타이머를 정리하고 `hoverTarget = null` 로 팝업을 즉시 닫도록 함
(기본 네비게이션 동작은 그대로 유지).

## 테스트 방법

1. quest/campaign 본문에 실재하는 cross-link `[[...]]` 가 포함된 문서를 연다.
2. cross-link 칩에 마우스를 올려 280ms 후 미리보기 팝업이 뜨는지 확인.
3. 팝업이 뜬 상태에서 (팝업 버튼이 아니라) 본문의 cross-link 칩 자체를
   클릭해 이동한다.
4. 이동한 페이지에 이전 미리보기 팝업이 남아있지 않은지 확인 (수정 전엔
   남아있었음).

## 현재 동작

- `core::drift::auto_resync(store)` 는 존재하지만 호출처가 **수동 명령만**:
  - `openguild-server check-drift --resync` (CLI)
  - `GET /api/admin/drift` (HTTP, **check 만** — auto-fix X)
  - Tauri `admin_check_drift`
- 파일시스템 watcher (`notify` crate 등) 없음.
- 사용자가 `.guild/quests/*.md` / `.comments.md` 등을 외부 편집기로 수정하면
  GUI 의 index.db 캐시는 stale → 페이지 새로고침 / 재시작해도 안 갱신.

## 사용자 의문

> "openguild에서 reindex 하는법? 페이지 이동할때 다시 캐싱하도록 해야할지도.
> 서버에는 reindex가 있다. 자동으로 되던가?"

**답: 자동 아님.** 수동 명령만 있음.
- 그런데 이 명령도 openguild-server에만 있다. openguild (일반 cli)에도 있어야 한다.

## 작업 (옵션 — 선택 / 조합)

### A. GUI 안에서 reindex 노출
- Admin 페이지에 "Reindex 실행" 버튼 (이미 `admin_run_reindex` 명령 있음 — UI 만
  연결).
- 효과: 사용자가 외부 편집 후 GUI 에서 한 번 클릭 → 동기화.
> reindex는 Admin 페이지에 있을 필요가 없지 않을까? 일반 사용자도 최신 내용으로 업데이트 하기 위해 접근 가능해야한다.

### B. 페이지 이동 시 자동 drift check + 필요시 reindex
- 페이지 라우터 / store action 에 `auto_resync(store)` 콜.
- 매번 전체 reindex 는 비싸므로 `check_drift` 만 먼저 → drift 있을 때만 resync.
- 효과: 외부 편집 후 다음 페이지 진입 시 자동 정합.

### C. 파일시스템 watcher
- `notify` crate 로 `.guild/quests/` watch → 변경 감지 → debounce 후 partial
  reindex.
- 가장 자동화되지만 구현 복잡 (debouncing / 무한 루프 방지 — GUI 가 직접 쓴 파일도
  trigger 되므로 self-ignore 필요).

## fix (2026-06-03 같은 날) — store-bump 패턴

사용자 보고: "상단 버튼으로 reindex 가 잘 안 되는 거 같다".

원인: 초기 구현이 `invalidateAll()` 만 호출 — SvelteKit 의 `+page.ts` 의
`load()` 함수만 트리거. 우리 페이지들 (Home / QuestList / QuestBoard) 은 모두
**컴포넌트의 `onMount` 안에서 직접 fetch** 패턴 → `invalidateAll` 의 트리거
대상이 없음. reindex API 자체는 성공하지만 UI 는 stale.

수정:
- `gui/frontend/src/lib/stores/reindex.ts` 신설 — `reindexBump` writable store +
  `bumpReindex()` 헬퍼.
- `Nav.svelte` 가 reindex 성공 후 `bumpReindex()` 호출 (이전 `invalidateAll`
  대체).
- 각 데이터 컴포넌트:
  - `Home.svelte` — `loadHomeData()` 추출 + `$effect(() => { $reindexBump; ... })`
  - `QuestList.svelte` — `loadData()` 추출 + 같은 패턴
  - `QuestBoard.svelte` — `loadBoardData()` 추출 + 같은 패턴
- 패턴 (각 컴포넌트):
  ```ts
  let lastBump = $state(0);
  $effect(() => {
      const bump = $reindexBump;
      if (bump !== lastBump && bump > 0) {
          lastBump = bump;
          loading = true;
          loadXxxData();
      }
  });
  ```
  - `lastBump` 비교로 초기 0 (마운트 시) 무시 — 실제 bump 만 처리.
  - `loading = true` 로 스피너 표시.

검증:
- `npm run check`: 0 errors.
- `cargo test help_output_has_no_quest_id_leaks`: 통과.

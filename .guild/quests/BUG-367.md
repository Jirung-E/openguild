## 문제

출력을 `head` 같은 것에 넘기면 읽는 쪽이 먼저 닫을 때 CLI 가 panic 한다.

```
$ openguild plugin events | head -3
...
thread 'run' panicked at library/std/src/io/stdio.rs: failed printing to stdout: Broken pipe (os error 32)
```

`println!` 이 닫힌 파이프에 쓰다 터지는 흔한 Rust 문제다. 결과는 맞지만 스크립트 · AI 가 오류로 오해한다.

## 고칠 것

- 닫힌 파이프는 조용히 끝낸다(exit 0 또는 141). 모든 명령에 한 번에 적용.

## 고친 것

- `main` 에 panic hook: **닫힌 stdout 에 쓰다 난 panic 만** 골라 메시지를 지우고 exit 0(ripgrep 과 같게). 다른 panic 은 원래대로 보인다.
- 가리는 기준은 std 문구 `failed printing to stdout` + 오류 번호 32(EPIPE) / 232(윈도우 — OS 문구가 한국어로 번역돼도 번호는 같다).
- SIGPIPE 를 기본값으로 되돌리는 흔한 방법은 쓰지 않았다 — `run` 플러그인 훅의 자식이 먼저 끝나면 그 stdin 에 쓰다 CLI 가 통째로 죽는다.
- 플러그인 전달 대기(`LocalBackend` 의 Drop)는 panic 이 풀리며 그대로 돈다.

## 확인

- 시험 1개(stdout · 32 · 232 만 삼키고, stderr · 다른 오류 · 다른 panic 은 아님).
- `openguild plugin events | head -2`, `openguild quest list | head -1` — 메시지 없음, exit 0.

## Test plan

- 윈도우 PowerShell 에서 `openguild quest list | Select-Object -First 1` 이 오류 없이 끝나는지 본다.

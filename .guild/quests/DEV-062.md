CLI `types` / `statuses` 가 현재 list 만 — add / update / delete subcommand 추가.

## 배경

DEV-014 에서 GUI Admin 에 type / status CRUD UI 가 들어왔지만 CLI 는
조회 (`openguild types`, `openguild statuses`) 만 가능. 헤드리스 환경 /
스크립트 / 자동화에서 type · status 관리 못함.

Backend `core::ops::meta` 는 이미 다 갖춰져 있어서 (`create_type` /
`update_type` / `delete_type` / `create_status` / `update_status` /
`delete_status`) CLI 는 thin wrapper.

## 인터페이스 (제안)

### Types
```bash
openguild types add <PREFIX> --color <#hex> [--description <desc>]
openguild types update <PREFIX> [--color <#hex>] [--description <desc>] [--clear-description]
openguild types delete <PREFIX>
```

### Statuses
```bash
openguild statuses add <name_en> --color <#hex> [--name-ko <ko>] [--sort-order <N>]
openguild statuses update <slug> [--name-en <en>] [--name-ko <ko>] [--color <#hex>] [--sort-order <N>] [--clear-name-ko]
openguild statuses delete <slug>
```

- 모든 mutation 은 `--json` 플래그 지원 (agent 호환).
- 삭제 가드 (사용 중 → BadRequest) 는 backend 가 처리 — CLI 는 에러 메시지
  포맷팅 + exit code 1.

## 구현

- `cli/src/commands/types.rs` / `statuses.rs` 의 subcommand 트리 확장.
- HTTP backend (remote 모드) — 현재는 read 만 라우트 있음. 별도 quest
  필요 (server 의 admin meta 라우트) 또는 본 quest 범위에 포함할지 결정:
  - 옵션 A — local 모드만 (`--remote` 없을 때) 동작. 본 quest 만으로 완성.
  - 옵션 B — server 도 같이. 작업량 ↑.
  - 우선 A 로 시작 + B 는 별도 quest.

## 검증

- `openguild types add FOO --color "#fff"` → 파일 + index.db 갱신, GUI
  에서도 즉시 보이는지.
- `openguild statuses add Blocked --color "#f00" --name-ko 막힘` → 동일.
- 삭제 가드 — 사용 중 type/status 삭제 시 stderr 에 사유 + exit 1.
- `--json` 출력 — `{ "prefix": "FOO", ... }` 같은 신규 row.

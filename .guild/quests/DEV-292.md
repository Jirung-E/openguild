퀘스트 `.md` 에 관계가 두 형태로 존재:
1. frontmatter `parent` / `prerequisites` — 진리원(메타데이터). 제자리, 문제 없음.
2. 본문 auto-block(`openguild:auto-begin`~`auto-end`) — 렌더된 관계
   (## Parent / ## Sub-quests / ## Prerequisites)를 본문에 중복 기록.

## 문제 (2번)
- DB/frontmatter 데이터를 tracked 본문에 **중복**.
- **다른 퀘스트의 제목**까지 끌어와 렌더 → 관계 변경 시 연관 퀘스트 파일들을
  재작성해야 함(change_parent 가 본인+옛/새 부모 3개 파일 재작성하는 이유).
  교차파일 결합 + 재작성 churn.
- BOOK-001 불변식("tracked 파일에 파생 데이터 중복 최소화")과 약하게 충돌.
- 후속(successor)은 auto-block 에 아예 없어 관계 뷰가 반쪽.

## 가치 (유지 이유)
- plain-text / GitHub 에서 관계가 보이는 git-native 가독성(프로젝트 차별점).

## 결정 (2026-08-09)
- auto-block 은 GitHub 관계 탐색용으로 유지한다.
- 관계 항목은 제목 없이 quest ID 상대 링크만 표시한다.
- `Parent` / `Sub-quests` / `Prerequisites` / `Successors` 네 방향을 표시한다.
- 관계의 진리원은 계속 frontmatter `parent` / `prerequisites`이며 auto-block은 파생 표시다.
- 선행 관계 추가·삭제 및 삭제·복원·slug 변경 시 양쪽 auto-block을 함께 갱신한다.

관련: [[BOOK-001]] 불변식, DEV-225(파일 배치).

## 테스트 방법
1. `cargo test -p openguild-core`를 실행한다.
2. 두 퀘스트 사이에 선행 관계를 추가한 뒤 두 `.md`를 확인한다.
   - 후속 퀘스트에는 `Prerequisites`가 표시된다.
   - 선행 퀘스트에는 `Successors`가 표시된다.
   - 두 항목 모두 `[DEV-NNN](DEV-NNN.md)` 형식이며 제목은 포함하지 않는다.
3. 선행 관계를 제거하면 양쪽 auto-block에서 관계가 함께 사라지는지 확인한다.
4. 관계가 연결된 퀘스트를 삭제·복원하거나 type을 변경해도 상대 파일의
   `Prerequisites` / `Successors`가 현재 slug 기준으로 갱신되는지 확인한다.

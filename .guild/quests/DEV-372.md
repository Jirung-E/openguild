## 배경

릴리스 사전 점검 중 **검증 장치 자체에 구멍**이 셋 나왔다. 앞의 둘은 원인이
같다 — 같은 목록을 세 곳에 손으로 맞추고 있다.

## 1. `just test` 가 CI 와 어긋난다

`justfile` 의 주석은 이렇게 말한다:

```
# Frontend 검증 — check.yml 의 gui-frontend job 과 **같은 순서·같은 항목**.
# BUG-251: `check:no-emoji` 가 빠져 있었다(BUG-169 의 재발 방지 검사).
```

**그런데 또 빠져 있다.** CI 의 마지막 단계 `npm run build` 가 `test-frontend`
에 없다. 가드 7종은 맞아 있는데 빌드만 없다.

`just test` 만 믿으면 **프로덕션 빌드가 깨져도 로컬에서 통과**한다. 0.5.3
준비 중 `npm run build` 를 따로 돌려서야 알았다.

## 2. 가드 등록이 손으로 세 곳

가드 하나를 추가하려면 `package.json` / `justfile` / `check.yml` 을 각각
고쳐야 하고, 한 곳을 빠뜨려도 **아무 말이 없다.** [[BUG-251]] 이 그래서 났고
위 1번도 같은 원인이다. `check:viewport`([[BUG-264]])도 이번에 손으로 넣었다.

검사가 검사되지 않는 상태다.

## 3. [[BUG-262]] 에 회귀 테스트가 없다

핵심은 `detail = { ...detail, ...updated }` 인데 `+page.svelte` 안에 있어
단위 테스트가 없다. 실서버에 붙여 *병합 결과 == 재조회 결과* 를 확인했지만,
누가 재조회를 되살리거나 병합을 망가뜨려도 아무것도 안 잡는다.

[[BUG-266]](여백) / [[BUG-269]](선택 칠하기)는 테스트를 두지 않는다 — 각각
svelte-check 의 unused selector 와 코드 주석으로 근거를 남겼고, 특히 269 는
칠해진 픽셀로만 드러나 jsdom 으로 고정할 수 없다.

## 할 것

1. `just test-frontend` 에 `npm run build` 추가.
2. **`check:guards`** — `scripts/check-*.mjs` 가 `package.json` 에 등록돼
   있는지, 그리고 CI 의 gui-frontend job 이 돌리는 `npm` 명령 집합과
   `justfile` 의 `test-frontend` 가 **같은지** 검사. 이 검사가 있었으면
   BUG-251 과 위 1번이 둘 다 잡혔다.
3. 상태 병합을 순수 함수로 빼서(`applyStatusUpdate`) 테스트로 고정 —
   상태 필드는 갱신되고 관계·태그·첨부는 유지된다는 계약.

## 테스트 방법

`just test` 통과. 새 검사는 **되돌려서 무는지** 확인한다:

- `justfile` 에서 한 줄 빼면 `check:guards` 가 실패
- `package.json` 에서 가드 하나 빼면 실패
- `applyStatusUpdate` 를 재조회로 되돌리면 테스트 실패

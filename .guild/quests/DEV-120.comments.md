## 구현 (간단)

`admin/+page.svelte::onReindex()` 의 성공 path 끝에 `setTimeout(() => window.location.reload(), 600)` 추가. 600ms 동안 토스트 "reindex 완료 — 데이터 새로고침" 잠시 보인 뒤 full reload — 모든 페이지 / store 가 fresh 데이터로.

대안 (`invalidateAll`, 페이지별 refresh) 도 검토했으나 이 프로젝트 대부분 onMount 직접 fetch 패턴이라 SPA invalidate 가 효과 없음. full reload 가 가장 확실.

confirm 은 DEV-119 sweep 에서 사용자 지시로 제외 — native `confirm()` 그대로.

## 테스트 방법

### A. 기본 (reindex 후 자동 새로고침)

1. Admin 페이지 → "Reindex" 버튼.
2. native confirm 떴을 때 OK.
3. 토스트 "reindex 완료 — 데이터 새로고침" 잠깐 (~0.5s) 표시 후 **페이지가 자동으로 새로고침**.
4. 새로고침 후엔 Admin 페이지의 snapshots 목록 / drift report 가 최신.

### B. 다른 페이지의 변경 즉시 반영

1. 외부 에디터로 quest md 파일 직접 수정 (예: title 변경).
2. Admin → Reindex 클릭 → 자동 reload.
3. Board / List / Quest Detail 로 이동 → 새 title 이 즉시 보여야.

### C. 실패 시 reload 안 일어남

1. (가능하다면) reindex 가 실패하는 상황 만들기 — 예: 손상된 quest 파일. 어렵다면 skip.
2. 실패 토스트 "reindex 실패: ..." 표시 + **reload 안 일어남**.

### D. 토스트 가시성

토스트가 너무 짧게 사라지면 사용자가 못 봄 — 현재 600ms. 실제로 "reindex 완료" 글자가 보였다 사라지는지 체감 확인.

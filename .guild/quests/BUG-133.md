admin 보고: reindex 했을 때 도서관 첨부파일이 안 보이게 됨.

## 조사 결과 — 백엔드/reindex 는 무관, 프론트 데이터 흐름 문제
reindex(core/src/reindex.rs) 는 library_docs/library_folders 캐시 테이블만
`.guild/library/*.md` + folders.toml 에서 재구축 — 첨부파일 sidecar
(`.guild/library/{BOOK-NNN}.attachments.json`, core/src/ops/attachments.rs)
는 전혀 건드리지 않는다. `sync_attachment_blobs` 도 물리 파일 vs 캐시
정합만 맞추고 orphan 파일을 함부로 되살리지 않도록 보수적으로 동작
(BUG-087). 디스크 데이터는 안전.

진짜 원인은 프론트엔드: `list_books`(list()) 는 payload 절약을 위해
attachments 를 항상 빈 배열로 반환(설계 의도, get_book 에서만 채움).
그런데 도서관 페이지는 문서를 선택해도 단건 조회(`libraryApi.get`)를
호출한 적이 없었다 — 그동안 화면에 첨부파일이 보였던 건 addAttachment/
update 응답을 로컬 books 배열에 수동 병합해온 부수효과였을 뿐이다.
reindex 후 admin 페이지가 `window.location.reload()` 로 전체 새로고침을
하면 그 임시 병합 상태가 날아가고, list() 로 다시 채워진 books 는
attachments 가 처음부터 빈 배열 — 복구할 방법이 없었다.

quest/campaign 상세는 선택 시 단건 조회(get_quest 등)로 항상 첨부를
채우는데, 도서관만 그 패턴을 안 따르고 있었다는 게 BUG-124(PATCH 응답이
비어있던 문제)와 같은 뿌리의 다른 증상.

## 수정
`library/+page.svelte` — `selectedId` 가 바뀔 때마다 `libraryApi.get(id)`
로 단건 조회해 그 문서의 attachments 만 갱신(본문/제목은 이미 list() 로
있어 재조회 불필요). 응답 도착 전 다른 문서로 선택이 바뀌면 무시(경쟁
상태 방지).

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`.
- 실기: 첨부파일 있는 문서 확인 → 설정에서 reindex 실행(전체 새로고침) →
  같은 문서 다시 열어 첨부파일이 그대로 보이는지.

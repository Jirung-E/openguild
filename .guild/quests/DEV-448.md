쿼리 문법([[DEV-446]])에 **`commented:`** — 댓글이 달린 때로 거른다(admin, 2026-10-23: "'이 날짜 이후로 댓글이 달린 퀘스트' 는 검색이 안되나? gui, cli, server 모두").

## 왜 지금은 안 되나

댓글을 달아도 퀘스트의 `updated_at` 은 안 바뀐다 — 댓글은 사이드카라 본문 파일을 다시 쓰지 않는다([[DEV-433]] 결정). 그래서 `--updated-after` · 고급의 '갱신' 은 댓글만 달린 퀘스트를 못 찾는다(시험용 길드에서 확인). '댓글 포함' 검색은 내용만 본다.

## 문법

```
commented:>=2026-10-20     마지막 댓글이 그날 이후 — 그날 이후 댓글이 달린 것
commented:<2026-10-01      마지막 댓글이 그 전 — 한동안 조용한 것
commented:2026-10-23       그날 마지막 댓글
commented:none             댓글이 없는 것  (-commented:none = 댓글이 있는 것)
```

- 비교 대상은 **마지막 댓글의 날짜**(댓글에 적힌 시각의 날짜 부분). `>=` 는 "그날 이후 하나라도 달렸다" 와 같다.
- 퀘스트 댓글만 본다(캠페인 댓글은 퀘스트에 달린 것이 아니다).
- 코어 해석기 한 곳이라 CLI `quest list -q` · 서버 `?q=` · 앱 목록의 쿼리 칸에 한 번에 생긴다.

## 할 것

- 코어 `query` — 키 `commented`, 값 검사(`due` 와 같은 꼴), SQL.
- 문서: CLI `-q` 도움말, USAGE, 스킬 reference/quest.md, 앱 쿼리 도움말.
- 시험: 해석 · 목록(댓글 날짜 · none · 빼기).

## 한 것 (2026-10-23)

- 코어 `query`: 키 `commented` — 마지막 댓글 날짜(`MAX(substr(ts, 1, 10))`, 댓글 없으면 NULL)와 비교. `>=` · `<=` · `<` · `>` · 날짜 하나 · `none`. 틀린 값은 해석할 때 "commented 는 none · 날짜 · >=날짜 · <날짜 …".
- CLI `-q` 도움말, USAGE, 앱 쿼리 도움말(`?`)에 한 줄 — "댓글은 갱신 시점을 안 바꾼다" 와 함께.
- **스킬(admin: "변경 있는 문서 찾기 시 본문 업데이트 시간만이 아니라 댓글이 달린 시간도 확인해야"):**
  - SKILL.md Pitfalls — `--updated-after` 만으로 "그 뒤 바뀐 것" 을 찾는 실수 → 퀘스트는 `--updated-after D` 와 `-q 'commented:>=D'` 를 둘 다, 캠페인은 `campaign list --json` 의 `updated_at` 과 `campaign comment list --json` 의 `ts`.
  - reference/quest.md "What changed since a date" — 두 목록을 합치는 명령 그대로.

## 시험

- 해석: 틀린 값 위치. 목록: `commented:>=날짜` · `<날짜` · 날짜 하나 · `none` · `-commented:none`(퀘스트 셋에 날짜가 다른 댓글).
- 실제 프로그램(시험용 길드 사본 836개): 오늘 댓글만 단 퀘스트가 `commented:>=오늘` 에는 나오고 `--updated-after 오늘` 에는 안 나옴. `none` 521 + `-commented:none` 315 = 836.
- `just test` 통과.

입력칸 · 팝업 · 모달을 공통 부품으로 — [[DEV-428]] 의 "하지 않는 것" 을 admin 이 다시 정했다.

admin: "적용해보자" — DEV-427 · 428 에서 "단계를 줄여 한 번에 적용하고 이상한 곳을 고친다" 가 잘 됐으니
입력칸 · 팝업도 같은 방식으로. (예전 결정: "그 화면을 고칠 때 같이 옮긴다 — 한 번에 65개 화면을 갈아엎지
않는다".)

## 지금 (2026-10-11 측정)

- 입력칸: 16개 파일에 25가지 정의. 글자 크기(sm · md), 모서리(sm · md), 여백이 제각각.
- 팝업(메뉴 · 팝오버) · 모달: 23가지. 토큰 덕에 배경 · 테두리 · 그림자는 거의 같지만 모서리 · 그림자 단계가
  몇 곳 다르다.
- 모달 뒤 어두운 막: 0.55 · 0.6 · 0.65 세 가지, 라이트에서도 같은 진하기.

## 할 일

- `global.css` 에 `.input` · `.popup` · `.modal-box` 와 `--backdrop` 토큰
- 화면마다의 정의를 옮기고 배치만 남긴다
- `check:tokens` 가 화면에서 이 부품들의 모양을 다시 정하는 것을 막는다
- [[BOOK-009]] 부품 절

## 한 것 (2026-10-11)

- `global.css` 에 `.input` · `.popup` · `.modal-box` 와 `--backdrop` 토큰. 모양만 정하고 폭 · 위치 · 안쪽 배치는
  각 화면이 정한다.
- **입력칸** 20개 파일 — 화면마다의 배경 · 테두리 · 글자색 · 글자 크기 · 여백 · 모서리를 지우고 `.input` 을 붙였다.
  글자 크기는 버튼과 같은 sm(12.8px), 여백도 버튼과 높이가 같게 — 나란히 놓으면 줄이 맞는다. 예전엔 sm · md 와
  모서리 sm · md 가 섞여 있었다.
  - 남긴 것: 퀘스트 목록 검색칸의 오른쪽 여백(지우기 버튼 자리), 캠페인 제목 편집칸의 큰 글자(token-ok),
    고정폭 글꼴을 쓰던 칸의 글꼴.
  - 대상 아님: 명령 팔레트 검색칸 · 설정 숫자칸(테두리 없이 상자에 녹아 있다), 색 고르기, 보드 레인 머리 고르기.
- **팝업** 9가지(날짜 고르기 · 빠른 설정 · 반응 고르기 · 타이틀바 메뉴 · 더보기 메뉴 · 위키 자동완성 · 링크
  미리보기 · 연관 추가 메뉴 · 보드 레인 설정) → `.popup`. 빠른 설정의 모서리(xl → lg), 타이틀바 메뉴의 그림자
  (lg → md), 레인 설정의 모서리(md → lg)가 맞춰졌다.
- **모달** 13가지 → `.modal-box`. 명령 팔레트 모서리 lg → xl.
- **막** 0.55 · 0.6 · 0.65 → `var(--backdrop)` (다크 0.6, 라이트는 더 옅게 0.4).
- `check:tokens` — 화면에서 `.input` · `.popup` · `.modal-box` 의 모양을 다시 정하면 실패(버튼과 같은 규칙).
- 문서 [[BOOK-009]] 부품 절 · 규칙 `frontend-design-language` 한 줄.

확인: 12개 화면(새 캠페인 · 새 퀘스트 · 퀘스트 목록 · 삭제 확인 · 댓글 · 도서관 · 규칙 · 태그 · 빠른 설정 ·
보드 설정 · 캠페인 목록 · 명령 팔레트) × 다크 · 라이트, [[DEV-428]] 빌드와 나란히 — 깨진 곳 없음. 모달 안
입력칸이 14 → 12.8px 로 조금 작아지고 모달 높이가 줄었다. 라이트에서 모달 뒤 막이 옅어졌다.
`just test` 851 통과.

## 테스트 방법

1. 새 퀘스트 · 새 캠페인 · 도서관 새 문서 · 규칙 이름 바꾸기 등 입력칸이 있는 창을 연다 — 입력칸 모양이
   어디서나 같고, 옆의 버튼과 높이가 맞는다. 누르면 테두리가 파랗게.
2. 메뉴 · 팝오버(빠른 설정 · 더보기 · 링크 미리보기 · 날짜 고르기)의 모서리 · 그림자가 같다.
3. 모달 · 확인 창의 모서리 · 그림자 · 뒤 막이 같다. 라이트에서 뒤 막이 너무 어둡지 않다.
4. UI 크기를 바꾸면 함께 커진다.
## 후속 — 취소 · 하는 일 단추 순서 (2026-11-08)

admin: "퀘스트 삭제 시도시에는 취소가 왼쪽인데, 보드에서 상태변경 시도시에는 취소가 오른쪽임. … 공통 컴포넌트로
통일해야함. … 편집 뒤의 저장/취소 도 순서 맞춰야함."

- **문제.** 이 퀘스트는 모달의 **겉모양**(`.modal-box` · 막)만 맞췄고 단추 줄은 화면마다 직접 썼다. 그래서 확인 창
  (ConfirmDialog · 퀘스트 삭제)은 [취소][삭제], 보드 상태 바꾸기 · 새 퀘스트 · 새 캠페인 · 관리의 추가 · 삭제 · 환영 화면의
  비우기 · 빼기 · 편집 뒤 저장 줄(퀘스트 · 댓글 · 메모 · 캠페인 · 규칙 · 도서관 · 작업 기록 · 태그 · 설정)은 [저장][취소] 였다.
- **고침.** 공통 부품 `ActionButtons` — 단추 둘만 그리고 순서는 언제나 **[취소][하는 일]**(맥 · 대부분의 웹, 공통 확인
  창이 이미 이 순서). 줄의 정렬 · 간격은 화면이 정하던 그대로. 약 35곳을 옮겼고 ConfirmDialog 도 이걸 쓴다. 보드의
  따로 만든 확인 단추(`dialog-ok` · `dialog-cancel`)는 공통 `.btn` 으로.
- **검사.** `check:actions` — 취소 글을 직접 단 단추(`<button>{t('….cancel')}`)를 막는다. "추가 ↔ 취소" 토글 단추와
  닫기 X 는 쌍이 아니라 그대로.
- 시험: `ActionButtons.test.ts`(순서 · 확인 창 순서 · 끄기).

### 후속 테스트 방법

1. 퀘스트 삭제 · 댓글 삭제 · 보드에서 노드를 다른 레인으로 옮길 때의 확인 창 — 모두 [취소][하는 일].
2. 새 퀘스트 · 새 캠페인 창, 관리의 타입 · 상태 추가 · 삭제, 환영 화면의 목록 비우기 — 같은 순서.
3. 퀘스트 본문 · 댓글 · 메모 · 규칙 · 도서관 · 캠페인 편집 뒤 저장 줄 — [취소][저장].
## 후속 2 — 공통 부품을 안 쓰던 곳 · 단추 줄 정렬 (2026-11-08)

admin: "여기 말고도 공통 컴포넌트를 써야하는데 안쓰고있는곳이 있나 더 찾아봐라." → 찾은 다섯 가지를 모두(admin: "1~5 전부 해라").
admin: "퀘스트 생성창이랑 편집의 저장/취소는 왜 왼쪽 정렬임?" → 정해 둔 이유 없이 화면마다 왼쪽이었다.

1. **확인 창을 직접 만든 곳 7곳 → `ConfirmDialog`** — 보드 상태 바꾸기, 환영 화면 비우기 · 빼기, 관리의 타입 · 상태 삭제,
   퀘스트 타입 바꾸기 · 삭제. 경고 줄 · 경로처럼 꾸민 글은 `children`, 일하는 중이면 `busy`.
2. **모달 틀 `Modal`** — 막 · 상자 · 제목 · 닫기 X · Esc · 포커스 · 스크롤 잠금 · 단추 줄. 새 퀘스트 · 새 캠페인 · 관리의 추가 ·
   연관 고르기 · 캠페인 연결 · 보드 설정 · 편집 충돌 · 확인 창이 쓴다. X 가 세 가지(`close-btn` · `x` · `hide-close`)이던 것이 하나.
   폭은 sm · md · lg · xl 넷.
3. **고르기 `.seg`** — 설정 화면 8묶음(`theme-toggle` · `th-btn`), 퀘스트 목록 [트리 | 리스트](`vt-btn`), 편집 충돌의
   [지금 것 | 내 것 | 둘 다](`pick`). 설정의 작은 단추(새 테마 · 내보내기 · 가져오기 · 지우기)는 `.btn.btn-sm`.
4. **입력칸 `.input`** — 퀘스트 제목 편집칸(`.input.lg`), 태그 거르기 칸, 정렬 고르기 3곳(`.input.sm`). 캠페인 제목도 `.input.lg`.
5. **`Combobox`** — 퀘스트 · 캠페인 고르기가 같은 코드 두 벌이던 것을 하나로. 두 컴포넌트는 찾는 것 · 칩만 정한다.
- **단추 줄은 오른쪽 끝** — `ActionButtons` 가 정한다(바깥 줄이 flex 든 block 이든). 새 퀘스트의 "템플릿으로 저장" 은 왼쪽 끝.
- 검사 `check:actions` 에 `Modal` 밖의 `aria-modal` 금지를 더했다. 시험 `Modal.test.ts`(첫 포커스 · Esc · X · 막 · busy).

### 후속 2 테스트 방법

1. 새 퀘스트 · 새 캠페인 · 관리의 새 타입 창 — 제목 오른쪽 X, 아래 [취소][만들기] 가 오른쪽 끝. Esc · 막 · X 로 닫힌다.
2. 퀘스트 편집 · 댓글 · 메모 · 규칙 · 도서관 편집 — [취소][저장] 이 줄 오른쪽 끝.
3. 보드에서 노드를 다른 레인으로 → "확인" 창. 보드 설정 창은 표가 길면 안쪽이 스크롤되고 제목은 남는다.
4. 설정 화면의 테마 · 언어 · 들여쓰기 등 고르기, 퀘스트 목록의 [트리 | 리스트] — 같은 모양.
5. 퀘스트 상세 → 연관 추가 → 기존 연결 / 캠페인 연결 — 검색 · ↑↓ · Enter · Esc.
## 후속 3 — 같은 줄의 높이 · 보드 도구줄 · 관리 "추가" 색 (2026-11-08)

admin: "새 타입 추가 버튼은 왜 파란색임?" / "보드 툴바에서 어색했던 부분" / "버튼마다 높이가 다른것도 통일해봐라. 여기 말고도
같은줄이거나 비슷한 기능인데 높이 다른곳 더있는지도 찾아봐라."

- **관리 "추가" 는 초록** — 원래 파랑이라 DEV-428 때 색을 그대로 뒀었다. 다른 만들기 창과 같이 `btn-primary`.
- **보드 도구줄** — 고르기(`3열` · `그룹`)가 WebKit 기본 모양(둥근 양끝 · 위아래 화살표)이라 [정렬][그룹] 이 한 덩어리로
  붙지 않았다 → 기본 모양을 끄고 단추와 같은 상자 + 아래 화살표. 아이콘만 든 단추(25px)가 글자 단추(30.5px)보다 낮던 것 →
  도구줄 전부 `--ctl-h-sm`.
- **높이 토큰 셋** `--ctl-h` · `--ctl-h-sm` · `--ctl-h-xs`(글 한 줄 + 여백 + 테두리) — `.btn` · `.btn-sm` · `.input` · `.input.sm` 이
  최소 높이로 쓴다. WebKit 에서 `select.input` 이 20px 로 납작하던 것(기본 모양이 여백을 무시)도 기본 모양을 끄고 화살표를 그려 고쳤다.
- **찾아서 맞춘 곳**(WebKit 으로 모든 화면 · 편집 · 모달 상태를 돌며 같은 줄 요소의 높이를 잼): 정렬 고르기 ↔ 방향 단추(목록 ·
  도서관), 댓글 작성자 칸 ↔ [M↓] · 팝업 단추, 답글 쓰기 ↔ 반응 단추, 날짜 칸 ↔ 달력 단추.
- **그대로 둔 것**: 보드 레인 머리의 이름(글) ↔ 설정 아이콘, 댓글 · 메모 머리의 접기 제목(글) ↔ 작은 단추 — 제목 글과 단추라
  같은 종류가 아니다. 검색칸 안의 지우기 X(칸 안에 든 것).
## 후속 4 — 곡률 (2026-11-08)

admin: "곡률도 통일해야함."

- **규칙**: 높이 `--ctl-h` · `--ctl-h-sm` 단계는 `--r-md`(6px), `--ctl-h-xs` 단계는 `--r-sm`(4px). 알약 칩은 `--r-pill`.
- WebKit 으로 모든 화면 · 상태의 조작 요소를 높이 단계 × 곡률로 묶어 어긋난 것을 고쳤다: 날짜 칸의 달력 단추(4 → 6), 규칙
  검색칸(4 → 공통 `.input`), 댓글 [M↓] · 팝업 단추(4 → 6), 반응 추가(10 → 4, 옆 "답글 쓰기" 와 같이), `.seg.xs`(판 6 → 4).
- 관리의 타입 · 상태 표는 화면이 따로 그리던 단추(36px · 곡률 4)를 공통 `.btn.btn-sm` 으로 — 표 단추가 작아졌다.
- 그대로: 맨 위 메뉴(nav), 설정 탭, 달력 칸 · 오늘 단추, 작업 기록 칸 — 조작 단추가 아닌 다른 부품.

## 후속 5 — 고르기 · 줄 높이 다시 · 새 퀘스트 상태 (2026-11-09)

윈도우 확인(23dc397b)과 admin 이 짚은 것.

- **고르기 `Select` 하나**: 꺾쇠가 두 가지였다(도구줄만 회색 아이콘, 나머지는 그라디언트). 이제 모든 고르기가 `Select` 를 쓰고
  꺾쇠는 **글자색** 작은 삼각형(admin: 회색이면 "안 펼쳐질 것 같이 생겼다", 모양은 도구줄 것). 설정의 글꼴 고르기(브라우저 기본
  모양이었다)도. `check:actions` 가 `Select` 밖의 `<select` 를 막는다.
- 작은 삼각형 아이콘(`caret-down-sm` · `caret-right-sm`)을 7 × 4 로 키우고 가운데에 — 목록 필터 줄 "고급 ▸" 도 함께(admin: 작고 가운데가 안 맞았다).
- **같은 줄 높이**(창 폭 760 · 1000 · 1400 × UI 80 · 100 · 125 · 150% 로 나란한 두 칸을 비교):
  - `.seg` 높이를 단계 토큰으로 못박음 — 배율에 따라 옆 단추와 1px 어긋났다.
  - 작업 기록 날짜 줄 → 작은 단계(날짜 칸 `DateField small`).
  - 목록 필터 줄 → 작은 단계: 칩 · 검색 칸(`SearchField small`) · 쿼리 `?` · 고급의 날짜 칸. 처음엔 칩을 키웠는데 줄이 뚱뚱해져(admin) 반대로 맞췄다.
- **너무 높은 입력칸**: 관리 타입 · 상태 추가, 태그 편집, 환영 화면 입력칸이 `font: inherit` 로 글자가 커져 36px — 덧쓰기를 지웠다.
  남은 것: 퀘스트 제목 편집(`.input.lg`, 일부러 큼), 설정의 숫자칸(슬라이더 옆 작은 칸).
- 새 퀘스트의 상태 "게시됨": 입력칸 같은 흰 칸 → 상태 알약(`.pill`, 상태 색).
- 교차 확인: 실제 Safari(WebDriver) · 웨일 · Playwright WebKit 측정값이 같다.

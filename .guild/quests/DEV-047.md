`quest show` 출력의 `parent : id=42` 같은 raw id 표시는 사용자가 누가 부모
인지 알 수 없어 UX 후진. sub-quests / prerequisites 와 동일한 표기 (slug
+ status + title + 색) 로 통일.

## 구현 (2026-05-22)

### Schema (Backend)
- `core::models::QuestDetail.parent: Option<QuestRow>` 추가.
  - `#[serde(default, skip_serializing_if = "Option::is_none")]` — 호환성:
    기존 client 가 parent 필드 없이 보내도 deserialize OK; root quest 응답엔
    parent 키가 아예 생략.
- `core::services::quests::fetch_parent(pool, quest)` 신설 — parent_quest_id
  Some 이면 QUEST_SELECT 로 한 row 조회. soft-deleted 부모는 None.
- `get` / `get_by_slug` 가 fetch_parent 호출하여 QuestDetail.parent 채움.

### CLI 표기 변경
- `print_quest_detail`: 이전 `parent : id={p}` → `parent : {slug} [{status}] {title}`
  (sub-quests/prereq 와 동일 패턴). slug 에 type.color, status name 에
  status.color.
- detail.parent 가 None 이지만 parent_quest_id 가 Some 인 경우 (soft-deleted
  부모 등) → `parent : id={p} (불러올 수 없음)` 폴백.

### Frontend
- `gui/frontend/.../types/index.ts::QuestDetail`: `parent?: Quest | null` 추가.
- frontend 화면 출력 변경은 없음 — 타입만 노출. 추후 별도 quest 에서 Quest
  Detail 페이지에 parent 카드 추가 검토.

## 자동 테스트 +2 (server)
- `test_quest_detail_includes_parent_row`: 자식 quest 조회 → 응답에 parent
  객체 + id / title 확인.
- `test_quest_detail_parent_omitted_or_null_for_root`: root quest → parent
  필드 omitted 또는 null.

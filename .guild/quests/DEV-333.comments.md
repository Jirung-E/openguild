구현 — `library tag` / `rule tag` (list / add / remove / set). quest tag 와 동일한
동작·출력 형식이며 **로컬·원격 모두** 지원한다.

- 공통 로직은 `run_doc_tag_cmd(list, set)` 하나로 — 대상별로 조회/저장 클로저만
  갈아끼운다. 세 곳(quest/library/rule)이 제각각 달라지는 걸 막기 위함.
- 로컬: `ops::library::set_book_tags` / `ops::rules::set_rule_tags`.
  원격: `PATCH /api/library/{id}/tags` / `PUT /api/rules/{slug}/tags`.
  (규칙 slug 는 공백을 포함할 수 있어 `urlenc` 를 통과시킨다 — BUG-166.)
- `BookDto` 에 `tags` 추가 — 원격 응답(BookResponse 가 LibraryDocRow flatten)에
  이미 실려 오는데 CLI DTO 가 버리고 있었다.
- 규칙 목록 조회(`list_rules`)는 **동기 함수**다(파일 직독, DB 캐시 없음) —
  `block_on` 을 붙였다가 컴파일 에러로 확인.

## 검증

로컬 (임시 길드):

```
$ openguild library tag add BOOK-001 rust cli
✓ BOOK-001 tags: cli rust
$ openguild library tag add BOOK-001 "docs 참고"     # 공백 구분 한 인자
✓ BOOK-001 tags: cli docs rust 참고
$ openguild library tag remove BOOK-001 cli
✓ BOOK-001 tags: docs rust 참고
$ openguild library tag set BOOK-001 최종
✓ BOOK-001 tags: 최종
```

파일 진리원 확인 — `.guild/library/BOOK-001.md` frontmatter 에
`tags = ["최종"]`, `.guild/rules/coding-style.md` 에 `tags = ["규칙"]`.

원격 (`--remote`, 같은 길드에 서버 기동):

```
$ openguild library tag add BOOK-001 원격추가 --remote http://127.0.0.1:8813
✓ BOOK-001 tags: 원격추가 최종
$ openguild rule tag add coding-style 원격 --remote ...
✓ coding-style tags: 규칙 원격
```

단위 테스트 4건 — add 의 dedupe/순서 보존, remove 의 없는 태그 무시,
set 의 전체 교체, 인자 0개 = 전체 삭제. cargo test 707 passed, clippy 통과.

## 현황 (step 1 — backend 만)
CLI subcommand / HTTP route / GUI 는 미완. backend Rust API 만 사용 가능.

## 사용

### Rust API (현재)
```rust
use openguild_core::ops;
ops::set_quest_tags(
    &store,
    quest_id,
    vec!["backend".into(), "performance".into()],
).await?;
```

### frontmatter 직접 편집도 가능
```toml
+++
quest_id = "DEV-001"
title = "..."
status = "open"
...
tags = ["backend", "performance"]
+++
```
→ 다음 reindex (또는 `drift::auto_resync` 자동 호출 시) 에 `quest_tags` 테이블 sync.

### 정규화
- trim + 빈 문자열 제거.
- 중복 제거 (순서 보존, 같은 tag 의 첫 등장).
- 대소문자 구분 — `"BACKEND"` 와 `"backend"` 는 다른 tag.

## 설계
- frontmatter 의 `tags: Vec<String>` 이 진리원.
- `quest_tags` 테이블 (migration 0010) 은 캐시.
- `ops::set_quest_tags` 가 file + DB 양쪽 갱신 (transaction).
- 다른 mutation (status / title 변경 등) 시 `write_quest_file` 이 기존 frontmatter 의 tags 자동 보존.
- 빈 vec 면 frontmatter 에서 키 자체 생략.

## 테스트
backend 만이라 GUI 시연 path 없음. 대신:

### 자동 (cargo test)
- `set_quest_tags_syncs_db_and_file` — DB row + frontmatter 둘 다 갱신.
- `set_quest_tags_normalizes_input` — trim / 빈 / 중복.
- `set_quest_tags_empty_clears_all` — 빈 vec 으로 모두 삭제.
- `other_mutations_preserve_tags` — status 변경 후 tags 유지.
- `reindex_loads_tags_from_frontmatter` — frontmatter → DB sync.

### 수동
1. `.guild/quests/DEV-001.md` 의 frontmatter 에 `tags = ["foo"]` 추가.
2. `openguild-server reindex` 실행.
3. `sqlite3 .guild/index.db "SELECT * FROM quest_tags"` → row 보임.
4. GUI 에서 quest 의 다른 속성 (status / title) 변경.
5. file 의 `tags = ["foo"]` 가 살아있는지 확인.

## 사용 (DEV-068 step 2 — CLI subcommand)

```
$ openguild quest tag list DEV-001
backend performance

$ openguild quest tag add DEV-001 frontend
✓ DEV-001 tags: backend performance frontend

$ openguild quest tag add DEV-001 "ci optimization"   # 공백 구분 한 인자도 split
✓ DEV-001 tags: backend performance frontend ci optimization

$ openguild quest tag rm DEV-001 frontend
✓ DEV-001 tags: backend performance ci optimization

$ openguild quest tag set DEV-001 a b c
✓ DEV-001 tags: a b c

$ openguild quest tag set DEV-001                     # 인자 0 = 전체 삭제
✓ DEV-001 tags: (모두 제거)
```

- 모든 subcommand `--json` 옵션 지원.
- 정규화 (trim + 빈 제거 + dedupe + 순서 보존) 는 ops::set_quest_tags 에서.
- 대소문자는 별개 — `"Backend"` 와 `"backend"` 둘 다 보존.

## 한계
- HTTP 모드는 미지원 (현재 backend 에 tag 관련 endpoint 없음).
- 향후 HTTP route (`PATCH /api/quests/:id/tags`) + Tauri command + GUI 작업이 후속.

## 테스트
1. `quest new DEV` → `quest tag set <slug> foo bar` → `quest tag list <slug>` → "foo bar".
2. `quest tag add <slug> baz` → "foo bar baz".
3. `quest tag rm <slug> foo` → "bar baz".
4. `quest status <slug> testing` (다른 mutation) → tag 유지 (write_quest_file 의 보존 로직).
5. file 직접 편집 (frontmatter `tags = ["x", "y"]`) → `reindex` → `quest tag list <slug>` → "x y".

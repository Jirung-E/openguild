## 현황 (step 1 — backend 만)
CLI subcommand / HTTP route / GUI 는 미완. backend Rust API 만 사용 가능.

## 사용

### Rust API (현재)
```rust
use openguild_core::ops;
ops::set_quest_tags(
    &store,
    quest_id,
    vec!["backend".into(), "performance".into()],
).await?;
```

### frontmatter 직접 편집도 가능
```toml
+++
quest_id = "DEV-001"
title = "..."
status = "open"
...
tags = ["backend", "performance"]
+++
```
→ 다음 reindex (또는 `drift::auto_resync` 자동 호출 시) 에 `quest_tags` 테이블 sync.

### 정규화
- trim + 빈 문자열 제거.
- 중복 제거 (순서 보존, 같은 tag 의 첫 등장).
- 대소문자 구분 — `"BACKEND"` 와 `"backend"` 는 다른 tag.

## 설계
- frontmatter 의 `tags: Vec<String>` 이 진리원.
- `quest_tags` 테이블 (migration 0010) 은 캐시.
- `ops::set_quest_tags` 가 file + DB 양쪽 갱신 (transaction).
- 다른 mutation (status / title 변경 등) 시 `write_quest_file` 이 기존 frontmatter 의 tags 자동 보존.
- 빈 vec 면 frontmatter 에서 키 자체 생략.

## 테스트
backend 만이라 GUI 시연 path 없음. 대신:

### 자동 (cargo test)
- `set_quest_tags_syncs_db_and_file` — DB row + frontmatter 둘 다 갱신.
- `set_quest_tags_normalizes_input` — trim / 빈 / 중복.
- `set_quest_tags_empty_clears_all` — 빈 vec 으로 모두 삭제.
- `other_mutations_preserve_tags` — status 변경 후 tags 유지.
- `reindex_loads_tags_from_frontmatter` — frontmatter → DB sync.

### 수동
1. `.guild/quests/DEV-001.md` 의 frontmatter 에 `tags = ["foo"]` 추가.
2. `openguild-server reindex` 실행.
3. `sqlite3 .guild/index.db "SELECT * FROM quest_tags"` → row 보임.
4. GUI 에서 quest 의 다른 속성 (status / title) 변경.
5. file 의 `tags = ["foo"]` 가 살아있는지 확인.

## DEV-068 step 5 — Quest List 의 tag 필터 + 검색 통합

step 4 (Quest Detail UI) 후속. tag 의 풀 사용성 완성.

## 변경

### Backend
- `QuestRow` 에 `tags: Vec<String>` 필드 (`#[sqlx(skip)]` — sqlx 자동 매핑 X).
- `services::quests::list` 가 결과 fetch 후 별도 query 로 `quest_tags` 한 번에
  fetch → HashMap<quest_id, Vec<tag>> → 각 row 의 tags 채움. N+1 회피.

### Frontend
- `Quest` 타입의 optional `tags`.
- `filterQuests(quests, types, statuses, search, titleOnly, tagFilter)` 의
  `tagFilter: Set<string>` (default 빈 set):
  - AND 매치 — 선택된 모든 tag 가져야.
  - search 토큰도 tag text 매칭 (기존 title/desc/slug 외).
- `QuestList.svelte` 에 tag chip 행 추가 — view-toggle 옆.
  - allTagOptions: 모든 quest 의 unique tag 합집합 (sorted).
  - 각 chip 클릭으로 filter 토글. active 시 강조 색.
  - "× 전체 해제" 버튼 (필터 있을 때만).
- 빈 길드 / tag 없는 길드 → chip 행 자동 숨김.

## 사용
1. Quest 들에 tag 부여 (CLI `quest tag set <slug> ...` 또는 Detail UI).
2. Quest List 진입 → tag chip 들 자동 표시.
3. 원하는 tag 클릭 → 그 tag 가진 quest 만 표시.
4. 여러 chip 클릭 → AND (모두 가진 quest).
5. 검색에 tag 단어 입력 → 매치.

## 테스트
1. quest_tags 비어있는 길드 → chip 행 안 보임.
2. tag "backend" 가진 quest 3 개 / "frontend" 가진 5 개 / 둘 다 1 개.
3. backend chip 클릭 → 4 개 (3 + 1).
4. backend + frontend 둘 다 클릭 → 1 개.
5. "× 전체 해제" → 모두 다시 표시.
6. 검색 "backend" 입력 → title / desc / slug / tag 매치.
7. Tree 모드에서도 tag 필터 동작 (조상 자동 포함).
8. List 모드에서도 동작.

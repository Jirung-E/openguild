## CommentScope 패턴 (기록 — 향후 확장용)

CLI 의 댓글/메모 핸들러는 `run_comment_cmd` / `run_memo_cmd` 공용 함수 + `CommentScope::{Quest, Campaign}` enum dispatch 로 추출됨 (fix2). Backend 의 `*_scoped` 메서드 6개가 scope 별 ops 로 분기.

**향후 다른 엔티티에 댓글을 붙일 때** (예: 길드 규칙에 댓글?) 이 패턴 그대로:
1. `CommentScope` 에 variant 추가
2. `noun()` 에 표시명
3. `*_scoped` 6개에 match arm (해당 ops 모듈 연결)
4. 해당 Cmd enum 에 `Comment { sub: CommentCmd }` 추가 — UX (필터 / --author 규칙 / rm 의 positional ID) 가 자동으로 동일해짐

GUI 쪽 대응 패턴은 `makeCommentsApi` 팩토리 (api/comments.ts) + 컴포넌트의 `scope` prop — endpoint base 만 바꾸면 됨. 주의: HTTP 경로 규약이 quest 는 `/api/quests/by/{slug}/...`, campaign 은 `/api/campaigns/{slug}/...` 로 다름 (기존 라우트 패턴 따름) — 새 scope 추가 시 그 엔티티의 기존 경로 규약 확인.

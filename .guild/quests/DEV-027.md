## 현황

`openguild quest list` 는 인자 없이 전체 alive quest 를 `id DESC` 순으로만 반환.
`core/src/services/quests.rs::list`:
```rust
let sql = format!("{QUEST_SELECT} WHERE q.deleted_at IS NULL ORDER BY q.id DESC");
```

quest 가 늘어남에 따라 (현재 33+) "open 상태의 BUG 만 본다" / "긴급도 높은 것만"
같은 흔한 사용 패턴이 불편.

## 제안 옵션

### 필터
| 옵션 | 의미 |
|---|---|
| `--type DEV` (또는 `BUG`, `REQ`, ...) | type prefix 필터, 다중은 `--type DEV --type BUG` |
| `--status open` (또는 `testing`, `done`, ...) | status 필터, 동의어 (`in_progress` / `in progress` / `in-progress`) 허용 |
| `--urgency 1-2` 또는 `--urgency 1` | 단일 값 또는 범위 |
| `--parent DEV-001` | 해당 quest 의 직계 자식만 (또는 `--no-parent` 로 top-level) |
| `--has-prereq` / `--no-prereq` | 선행 quest 유무 |

### 정렬
| 옵션 | 의미 |
|---|---|
| `--sort id` (기본 desc) | quest_id 순 — 기본값 |
| `--sort urgency` | urgency 1 (critical) 먼저 |
| `--sort status` | status sort_order 순 |
| `--sort updated` | 최근 갱신 먼저 |
| `--reverse` | 정렬 방향 뒤집기 |

### 제한
| 옵션 | 의미 |
|---|---|
| `--limit 10` | 처음 N 개만 |
| `--offset 20` | 페이지네이션 (limit 와 같이) |

### 조합 예시
```bash
openguild quest list --status open --type BUG --sort urgency --limit 5
# → 열린 BUG 중 가장 긴급한 5개
openguild quest list --status testing
# → 검증 대기 quest 만
openguild quest list --parent DEV-001
# → DEV-001 의 직계 서브퀘스트만
```

## 수정 방향 / 설계 결정 사항

- **클라이언트 측 필터링 vs 서버 측**: SQL WHERE 으로 처리 (서버 측). 클라이언트는
  단순. 정렬도 SQL ORDER BY.
- **JSON 출력 보존**: 동일한 필드, 단지 결과 셋만 작게.
- **회귀**: 인자 없이 `quest list` 호출 시 현재 동작 그대로 (전체 alive, id DESC).
- **GUI 영향**: QuestBoard / QuestList 페이지가 이미 정렬은 자체 처리 중 (lane /
  position). API 변경 시 옵션 받지 않아도 동작해야 함 (default 가 기존 동작).

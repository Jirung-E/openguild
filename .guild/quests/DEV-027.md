## 구현 (2026-05-18 ~ 19, MVP + 보강)

### 필터 옵션
- `--type <PREFIX>` — **다중 입력 3가지 형태 모두 지원**:
  `--type DEV BUG` (공백), `--type DEV,BUG` (콤마), `--type DEV --type BUG` (반복).
  대소문자 무시.
- `--status <slug-or-name>` — 동일 (다중). 'Open' / 'open' / 'in_progress' /
  'in-progress' / 'In Progress' 모두 같은 매칭 (SQL `LOWER` + `REPLACE`).
- `--urgency N` — 1 ~ 4. 범위 밖이면 BadRequest.
- `--child-of <slug>` — **그 slug 가 parent 인 직계 자식들** 을 보여줌.
  (이름이 "parent" 였으나 의미 모호 해소 — `--child-of` 로 rename.)
- `--no-parent` — top-level (parent_quest_id IS NULL) 만. `--child-of` 와 상호배타.

### 정렬 옵션
- `--sort` — **다중 키** (`--sort urgency,id` 또는 `--sort urgency id`). 각 키
  기본 방향:
  - `id` (DESC: 최신 먼저)
  - `urgency` (ASC: 1=Critical 먼저)
  - `status` (sort_order ASC: Open 먼저)
  - `updated` (DESC: 최근 갱신 먼저)
  - `created` (DESC: 최근 생성 먼저)
- `--reverse` — 모든 sort 키의 기본 방향 뒤집음.
- 대소문자 무시. 마지막 키가 `id` 아니면 자동으로 `q.id DESC` tiebreaker 추가.

### 제한 / 출력 옵션
- `--limit N` (음수 BadRequest, 0 OK 빈 결과).
- `--offset N` (음수 BadRequest, limit 없이도 가능).
- `--id-only` — quest_id (slug) 만 한 줄씩 — pipe / xargs 친화.
- `--count` — 매칭 개수만 정수 출력.
- 위 두 옵션 상호배타.

### 정규화 규칙
- 빈 문자열 `?type=` / `--type ""` → 필터 미지정으로 취급 (= 전체).
- `?sort=ID` / `?sort=URGENCY` → 대소문자 무시 매칭.
- 콤마 구분 `?type=DEV,BUG` → SQL `IN (?, ?)`.

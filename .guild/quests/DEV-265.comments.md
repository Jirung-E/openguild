## 조사: "VSCode 는 어떻게 했나" (2026-07-17, 웹 리서치)

결론부터 — **VSCode 도 못 했다.** VSCode 의 커스텀 타이틀바 창 버튼은
리눅스에서도 자체(윈도우풍) 스타일 그대로이고, 바로 그 불만이 공식 이슈로
올라와 있다: microsoft/vscode#65241 "Custom title bar uses Windows styling
on Linux distributions" (duplicate 로 닫힘, 시스템 테마 버튼 구현 안 됨).
Ubuntu/Fedora/KDE/elementary 스크린샷 전부 동일하게 안 어울린다는 내용.
VSCode 의 공식 탈출구는 `window.titleBarStyle: "native"` — 커스텀을 포기하고
진짜 네이티브 데코레이션으로 되돌리는 설정이다.

**진짜로 시스템 모양을 그리는 앱은 Chromium** 인데, 방식이 다르다:
웹 레이어가 아니라 브라우저 셸(C++)에서 GTK API 로 테마를 직접 질의해
프레임 버튼을 GTK 스타일로 렌더하고, 버튼 배치도 gsettings
(org.gnome.desktop.wm.preferences button-layout / gtk-decoration-layout)를
읽어 따른다. 이건 GTK 네이티브 렌더 통합이라 Tauri 웹뷰(HTML/CSS 레이어)
에선 동일 재현 불가 — "시스템이 그린 진짜 버튼"은 decorations:true(네이티브
데코레이션)일 때만 가능하다는 구조적 제약은 우리와 VSCode 가 같다.

## 그래서 우리가 할 수 있는 것 (구현 제안)

1. **플랫폼별 근사 스타일(권장, 1차)** — 창 버튼 컴포넌트를 플랫폼 분기:
   - Windows: 현행 유지(이미 Windows 관례).
   - Linux: GNOME/Adwaita 근사 — 원형 호버 배경, Adwaita 글리프 간격/크기,
     닫기 빨강 없음(Adwaita 관례) 등. KDE 등 완전 일치는 포기(Chromium 급
     통합 없이는 불가), GNOME 기준 1종.
2. **버튼 배치까지 시스템 따르기(2차 옵션)** — Rust 측에서
   `gsettings get org.gnome.desktop.wm.preferences button-layout` 을 읽어
   invoke 로 노출 → 좌/우 배치·버튼 구성(최소화 숨김 등)을 따라감.
   Chromium 이 하는 것의 저비용 버전.
3. **네이티브 복귀 설정(탈출구)** — VSCode 처럼 설정에 "네이티브 타이틀바
   사용" 토글(Linux 한정): `window.setDecorations(true)` 런타임 전환 +
   커스텀 타이틀바 숨김. 완벽한 시스템 모양을 원하는 사용자용.

## 사용자 제보 방식 검토 (2026-07-17): "OS 버튼은 시스템 제공 + 나머지만 앱이 그림"

맞는 방향이고 실존하는 API 패턴입니다. 다만 플랫폼별 지원 현황이 갈립니다
(Tauri 2.11 소스 확인):

- **macOS — 가능(정식 지원)**: `tauri.conf` 의 `titleBarStyle: "Overlay"`
  가 정확히 이 방식 — 신호등(트래픽 라이트) 버튼은 시스템이 그대로 그리고,
  타이틀바 영역은 투명 오버레이가 되어 앱 콘텐츠가 그 아래까지 렌더됨.
  (tauri-utils config: "The style of the macOS title bar" — macOS 전용
  필드임을 소스에서 확인.) 현재 macOS 는 커스텀 타이틀바 미사용이므로,
  적용하려면 tauri.macos.conf.json + 프론트의 드래그 영역/좌측 여백 처리
  추가 필요.
- **Windows — Tauri 미지원**: 이 방식의 Windows 구현체가 바로 Window
  Controls Overlay(WCO). Electron 은 titleBarStyle: hidden +
  titleBarOverlay 로 지원하지만(VS Code/Discord 가 쓰는 그것), Tauri/wry 엔
  아직 없음. 커뮤니티 플러그인 tauri-plugin-decorum 이 유사 UX(스냅 레이아웃
  호버 포함)를 제공하나 버튼 렌더 자체는 여전히 웹 레이어 — '진짜 OS 버튼'
  은 아님. 현행 Windows 커스텀 버튼이 이미 Windows 관례 모양이라 실익은
  스냅 레이아웃 메뉴 정도.
- **Linux — 구조적 난점**: 대응물은 GTK HeaderBar(CSD) — GTK 가 시스템
  테마 버튼을 그리고 나머지 영역에 앱 위젯을 배치하는 공식 API. 단 Tauri
  콘텐츠는 단일 웹뷰라, 타이틀바에 있는 기존 HTML 컴포넌트(검색 pill,
  네비게이션, ☰ 메뉴)를 GTK 네이티브 위젯으로 재작성해야 함 — 웹 타이틀바와
  혼합 불가. gtk_window().set_titlebar(HeaderBar) 접근은 기술적으로 가능
  하나 이식 비용이 큼.

## 종합 제안 (기존 3안과 병합)

- Linux 1차: Adwaita 근사 스타일 + gsettings button-layout (기존 제안 유지).
- macOS 진출 시: titleBarStyle Overlay 채택 (제보 방식 그대로 — 정식 지원).
- Windows: 현행 유지, wry 의 WCO 지원 추가되면 재검토.
- Linux 완전 네이티브가 꼭 필요해지면: GTK HeaderBar 재작성(대공사) 또는
  '네이티브 타이틀바 사용' 설정 토글(저비용 탈출구).

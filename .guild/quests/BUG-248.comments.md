## 증상

검색 결과가 짧아 팔레트 목록에 스크롤이 생기지 않은 상태에서 굴리면 **배경
페이지가 스크롤된다.**

## 원인

팔레트만 **기존 스크롤 잠금 장치를 쓰고 있지 않았다.**

BUG-199 가 "모달이 떠 있는 동안 뒤 페이지가 스크롤되던 문제" 를 잡고
`lockBodyScroll` + `use:modalScrollLock` 을 만들어 뒀다. NewQuestModal /
ConfirmDialog / 어드민 3종 / 퀘스트·캠페인 상세 / welcome 이 전부 쓰는데
검색 팔레트만 빠져 있었다.

`.palette` 는 `position: fixed` 지만 그것만으로는 아래 문서로 가는 휠·터치를
막지 못한다 — BUG-199 주석에 적힌 그대로다.

## 수정

- `.backdrop` 에 `use:modalScrollLock`. 이 엘리먼트는 팔레트가 열려 있는
  동안에만 존재하므로 잠금 수명이 열림/닫힘과 정확히 일치한다(BUG-199 가
  `onMount` 대신 오버레이에 걸도록 바꾼 이유와 같다).
- `.rows` 에 `overscroll-behavior: contain`. 배경 잠금과 **별개로** 필요하다 —
  잠금은 페이지 스크롤을 막고, 이건 목록 끝까지 굴렸을 때 이 스크롤러 밖으로
  새는 것을 막는다.

## 검증 (브라우저 실측)

| 단계 | body overflow | overscroll |
|------|---------------|------------|
| ① 열린 상태 | `hidden` | `contain` |
| ② Esc 로 닫음 | (빈값) | (빈값) |
| ③ 다시 엶 | `hidden` | `contain` |
| ④ backdrop 클릭으로 닫음 | (빈값) | (빈값) |
| ⑤ 닫힌 뒤 스크롤 | 정상 동작 |

닫는 두 경로(Esc / backdrop) 모두에서 확실히 풀린다. `.rows` 의
`overscroll-behavior-y` 도 `contain` 으로 계산됨을 확인했다.

**휠 입력 자체를 주입해 배경이 안 움직이는지는 확인하지 못했다** — 브라우저
창이 숨겨진 상태에서 입력 주입이 타임아웃난다(이 환경의 알려진 제약).
`overflow: hidden` 은 프로그램적 `scrollTop` 은 허용하므로 그쪽으로는 검증이
성립하지 않는다. 잠금이 걸리고 풀리는 것까지가 확인 범위이고, 잠금 자체의
동작은 BUG-199 에서 이미 검증된 같은 코드다.

## 잠금 유틸에 테스트를 붙였다

`body-scroll-lock.ts` 에 테스트가 하나도 없었다. **새면 페이지가 영구히
스크롤되지 않는** 코드인데, 이번에 네 번째 사용처가 늘었다. 5건 추가:

- 잠금/해제 시 스타일, 원래 값 복원
- 겹쳐 잠갔을 때 마지막 해제에서만 풀림(참조 계수)
- 같은 해제를 두 번 불러도 계수가 더 줄지 않음
- 해제를 반복한 뒤에도 다음 잠금이 정상 동작

`just test` 484건 통과 (기존 479 + 5).

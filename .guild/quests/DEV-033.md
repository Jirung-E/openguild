DEV-027 의 backend 옵션을 frontend GUI 에서 사용할 수 있도록 UI 추가.

## 현황

`gui/frontend/src/lib/api/quests.ts::list()` 가 인자 없이 호출. backend 는 인자
받지만 frontend 는 전체 가져와 클라이언트 측 필터링.

## 제안 변경

### 1. API 어댑터 (작은 변경)
```ts
// quests.ts
list: (q?: ListQuery) => api.get<Quest[]>(
  '/api/quests' + (q ? '?' + toQuerystring(q) : '')
)
```

### 2. UI 컴포넌트
- QuestList 페이지 상단에 필터 toolbar:
  - type checkboxes (DEV / BUG / REQ — `--type` 다중)
  - status checkboxes (Open / In Progress / Testing / Done / Cancelled / On Hold)
  - urgency selector (1-4)
  - sort dropdown (id / urgency / status / updated / created)
  - reverse 체크박스
  - search input
- 필터 변경 시 즉시 API 재호출 (debounce 200ms).
- URL 동기화 — `/quests?type=DEV&status=open` 형태로 query param 반영 →
  bookmarkable.

### 3. Board 페이지
- QuestBoard 의 lane 은 그대로 모든 quest. 필터는 toolbar 에서 적용 시
  matched 만 highlight, 나머지 dimmed.
- 또는 hide unmatched (선택 UX 결정).

## 영향 범위

- `gui/frontend/src/lib/api/quests.ts` — `list` 가 query 받음.
- `gui/frontend/src/lib/api/types.ts` — `ListQuery` 타입 신설 (backend struct 와 매핑).
- `gui/frontend/src/lib/components/QuestList.svelte` (또는 별도 컴포넌트) —
  필터 toolbar.
- `gui/frontend/src/routes/+page.svelte` 또는 `/quests/+page.svelte` — URL 동기화.
- (선택) Board 도 동일 필터 반영.

## 우선순위 사유

사용자면 가치 큼. CLI 만 쓰면 필요 없음.

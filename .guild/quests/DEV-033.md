DEV-027 의 backend 옵션을 frontend GUI 에서 사용할 수 있도록 UI 추가.

## 현황

`gui/frontend/src/lib/api/quests.ts::list()` 가 인자 없이 호출. backend 는 인자
받지만 frontend 는 전체 가져와 클라이언트 측 필터링.

## 제안 변경

### 1. API 어댑터 (작은 변경)
```ts
// quests.ts
list: (q?: ListQuery) => api.get<Quest[]>(
  '/api/quests' + (q ? '?' + toQuerystring(q) : '')
)
```

### 2. UI 컴포넌트
- QuestList 페이지 상단에 필터 toolbar.
- 필터 변경 시 즉시 API 재호출 (debounce 200ms).
- URL 동기화 — `/quests?type=DEV&status=open` 형태로 query param 반영 →
  bookmarkable.

### 2.1 CLI 옵션 1:1 노출 (2026-05-24 보강)

DEV-027 / 028 / 029 / 030 의 `quest list` 옵션을 모두 GUI 에서 사용할 수
있어야 함:

| CLI 옵션 | GUI 컴포넌트 |
|---|---|
| `--type DEV,BUG` (다중) | type multi-checkbox (DEV / BUG / REQ / …) |
| `--status open,in_progress` (다중) | status multi-checkbox |
| `--urgency 1-3` (범위) | urgency dual-slider (min/max) |
| `--has-prereq` / `--no-prereq` | tri-state toggle (any / has / none) |
| `--has-sub` / `--no-sub` | tri-state toggle |
| `--created-after`, `--updated-since` | date range picker |
| `--search <kw>` | search input (DEV-037 에서 이미 도입) |
| `--title-only` | search 옆 토글 (DEV-037) |
| `--limit N` | 페이지 크기 selector / "더 보기" |

### 2.2 정렬 기준 (2026-05-24 보강)

`sort` dropdown — CLI 의 `--sort` 와 1:1:
- `id` (기본, 생성 순)
- `urgency` (높은 순 = 1 위)
- `status` (sort_order 순)
- `updated_at`
- `created_at`
- `type` (prefix 알파벳)

그 옆에 ascending / descending 토글 (CLI `--reverse`).

선택 결과는 URL `?sort=urgency&desc=1` 형태로 동기화. localStorage 로
마지막 선택 기억.

### 3. Board 페이지
- QuestBoard 의 lane 은 그대로 모든 quest. 필터는 toolbar 에서 적용 시
  matched 만 highlight, 나머지 dimmed.
- 또는 hide unmatched (선택 UX 결정).

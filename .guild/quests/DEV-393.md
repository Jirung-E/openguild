## 무엇

1. **플러그인**을 설정 페이지에서 관리 페이지로 옮긴다.
2. 관리 페이지를 **탭**으로 나눈다.

## 왜 — 두 화면의 기준

| 화면 | 기준 | 지금 들어 있는 것 |
|---|---|---|
| 설정 | **앱 전체** — 어떤 길드를 열든 같다 | 정보 · 표시 · 편집기 (전부 개인 설정) + 플러그인 |
| 관리 | **지금 연 길드** | 타입 · 상태 · 태그 정의 · 백업 · 정합성 점검 · 정비 |

플러그인 화면의 내용은 전부 지금 연 길드의 것이다 — 목록은 그 길드의 `.guild/plugins/`,
동의와 설정값도 길드별로 따로 남는다. 앱 전체 화면에 길드 전용 내용이 들어가서 "아직 길드를
열지 않았습니다" 같은 상태를 따로 다뤄야 했다.

"동의·토큰은 이 기계에만 남으니 설정" 이라는 반론은 성립하지 않는다 — 관리 페이지의
**백업**도 git 에 안 올라가는 이 기계 전용 데이터다. 관리 = "이 길드(공유든 이 기계
전용이든)", 설정 = "이 앱".

관리 페이지는 섹션 여섯이 한 페이지에 세로로 이어져 있다. 설정 페이지는 이미 탭이다.

## 탭 구성 (안)

| 탭 | 들어갈 것 | 성격 |
|---|---|---|
| 퀘스트 구성 | 타입, 상태 | 길드 공유 구조(git) — 서로 엮여 있다 |
| 플러그인 | 목록 · 동의 · 설정값 · 전체 허용/해제/자동 허용 | 이 길드의, 이 기계 전용 |
| 백업 | 스냅샷 만들기 · 복원 | 이 기계 전용. 복원은 되돌리기 어려워 진단과 떨어뜨린다 |
| 진단 | 정합성 점검 · reindex · 정비(journal) | 문제가 생겼을 때만 |

태그 정의는 [[DEV-392]] 에서 따로 뺀다.

## 할 것

- 설정 페이지의 플러그인 부분(마크업·상태·핸들러·스타일)을 컴포넌트로 떼어 관리 페이지 탭으로.
  동작은 그대로 — 관리 조작은 로컬 데스크톱에서만, 웹은 읽기 전용.
- 설정 페이지에서 플러그인 탭 제거. "길드 없음" 상태 처리는 관리 페이지가 길드를 요구하므로
  대부분 사라진다 — 남는 경로가 있는지 확인.
- 화면 시험(`settings/plugins.test.ts`)을 새 위치로 옮긴다.
- 선택한 탭을 URL 이나 기억으로 유지할지 — 설정 페이지와 같은 방식으로.
- 플러그인 설정으로 안내하는 문구·문서(USAGE, 스킬: "설정 → 플러그인")를 새 위치로 고친다.

## 구현

- `lib/components/admin/AdminPluginsSection.svelte` — 설정 페이지의 플러그인 부분(상태·핸들러·
  마크업·일괄 조작 확인 창·스타일)을 그대로 떼어 냈다. 탭 `$effect` 대신 붙을 때(`onMount`) 읽는다.
- 관리 페이지: 설정 페이지와 같은 세로 탭(좁은 화면에서는 가로 한 줄) —
  **퀘스트 구성**(타입·상태) / **플러그인** / **백업** / **진단**(정합성 점검·reindex·정비).
  인증 없음 경고는 탭과 무관하게 패널 맨 위.
- 설정 페이지에서 플러그인 탭·스크립트·스타일 제거.
- 문구 키 `settings.plugin*` → `plugins.*`, 탭 이름 `admin.tab*`.
- 사용자에게 보이는 안내를 "관리 → 플러그인" 으로: USAGE, 예제 README·텔레그램 스크립트 주석,
  스킬 두 곳(Admin → Plugins), CHANGELOG, 코어 오류 문구 둘(`body_env` 값 없음, 설명 너무 김),
  데스크톱 시동 로그.
- "길드 없음" 상태 처리는 컴포넌트에 남겼다 — 관리 페이지로 옮겨도 해가 없고, 원격/환영 화면
  경로에서 들어오는 경우를 따로 증명하지 않았다.

## 확인한 것

- 플러그인 화면 시험 6개를 컴포넌트 시험(`AdminPluginsSection.test.ts`)으로 옮겨 통과.
- 관리 페이지 시험 4개(`routes/admin/admin.test.ts`): 탭 넷과 순서, 첫 탭에 백업·진단 없음·
  플러그인을 안 읽음 / 플러그인 탭을 누르면 그때 읽어 그림 / 진단 탭에 섹션 둘 / 설정
  페이지에 플러그인 탭 없음.
- `just test` 전체 통과.

## 테스트 방법

- 관리 페이지에 탭 넷, 각 탭에 해당 섹션만.
- 플러그인 탭에서 허용·철회·설정값 저장·전체 허용/해제/자동 허용이 전과 같이 동작한다.
- 설정 페이지에 플러그인 탭이 없다.
- 웹에서는 플러그인 탭이 읽기 전용이다.
- 문서의 "설정 → 플러그인" 안내가 남아 있지 않다.

# [gui] 연관 퀘스트/캠페인 연결 팝업 — 바깥 클릭으로 안 닫히고 크기가 작음

사용자 보고: 캠페인이나 퀘스트에서 연관 퀘스트를 추가할 때 (1) 팝업
바깥을 클릭해서 닫을 수 있어야 하고 (2) 팝업 자체가 너무 작아서 보기
불편함.

## 조사 — 고쳐야 할 곳

`.ov`(백드롭) + `.modal-sm` 패턴이 두 페이지에 **각자 복제**돼 있었다.
해당 파일의 팝업 5개가 모두 같은 문제:

| 파일 | 팝업 |
|------|------|
| `quests/[id]/+page.svelte` | 서브/선행/후속 퀘스트 추가(콤보) |
| ″ | 캠페인 연결(콤보) |
| ″ | 타입 변경 확인 |
| ″ | 삭제 확인 |
| `campaigns/[slug]/+page.svelte` | 퀘스트 연결(콤보) |

**원인 1 (안 닫힘)**: `<div class="ov" role="presentation">` 에 클릭
핸들러가 아예 없었다. 반면 공용 `ConfirmDialog` 는 이미 올바른 패턴을
갖고 있어(`e.target === e.currentTarget` 가드) 그대로 따라가면 된다.

**원인 2 (작음)**: `.modal-sm` 이 `max-width: 30rem`(480px) 이고
콤보박스 목록은 `max-height: 220px`(≈5줄). 콤보 팝업은 "목록"이 본문
인데 확인 모달용 폭을 그대로 써서, 퀘스트 제목이 잘리고 후보 대부분이
스크롤 뒤로 숨었다.

## 수정

- **백드롭 클릭 닫기** — 5곳 전부. 콤보 3곳은 그냥 닫고, 확인 모달
  2곳(타입변경/삭제)은 `!changingType` / `!deleting` 가드를 함께 둬서
  **요청이 진행 중이면 안 닫히게** 했다(요청은 날아가는데 UI 만 사라져
  결과를 못 보는 상태 방지).
- **콤보 팝업 확대** — `.modal-combo` 넓은 변형 신설
  (`max-width: calc(56rem * var(--popup-scale))` = 기본 896px).
  `.modal-sm` 자체는 그대로 둬서 삭제/타입변경 등 다른 사용처는 무영향.
- **목록 높이** — `.cb-list` `max-height: 220px` →
  `min(70vh, 600px)`. vh 를 함께 써야 작은 창에서 화면을 넘지 않는다.
  QuestCombobox / CampaignCombobox 양쪽 동일.

사용자와 목업으로 크기를 합의(44rem 안 → "좀 더 키워도 될 것 같다" →
56rem 확정).

## 테스트 방법 (1 실기 확인 완료)

1. 후보 12건인 스크래치 길드에서 5개 팝업 전부 실기 확인:
   - 폭 896px, 목록 434~474px(창 높이 720 기준 70% 상한), 후보 11~12건이
     스크롤 없이 표시, 긴 제목 말줄임 없음(`scrollWidth === clientWidth`).
   - 목록 **내부** 클릭은 안 닫히고(버블링 가드 동작), **백드롭** 클릭에서만
     닫힘 — 퀘스트 상세 콤보/캠페인 연결/캠페인 페이지 콤보 3곳 모두 확인.
2. `svelte-check` / `npm run test`(299) / `build` 클린.
3. (사용자 확인) 데스크탑 앱에서 실제 사용감 — 특히 `--popup-scale`(컨텐츠
   폭 설정 0.9~1.3배)이 곱해질 때 폭이 과하지 않은지, 확인 모달의 진행 중
   가드가 의도대로인지.

**윈도우에서 `openguild` 명령이 무엇을 하든 매번 약 1.2초 걸린다**(2026-10-01, 윈도우 세션 측정 — Windows 11 Home,
Defender 실시간 검사 켜짐). 길드를 열지 않는 `--version` 도 같다. 저장 자체는 0.03초.

에이전트 · 플러그인(`run` 훅)이 `openguild` 를 여러 번 부르면 그만큼 쌓인다 — 퀘스트 하나 다루는 데 명령 10번이면 12초.

## 측정 (윈도우)

| 실행 파일 | 크기 | 시작 |
|---|---|---|
| 러스트 hello | 0.1MB | 0.012초 |
| 더미(23MB 블롭만) | 23MB | 0.72초 |
| openguild 0.5.1-beta | 17.1MB | 0.63초 |
| openguild 0.6.0-beta | 24.5MB | 1.22초 |

- 크기별 더미: 약 0.03초 + **29ms/MB** — 서명 없는 새 실행 파일을 백신이 실행 때마다 검사한다. 서명 · 평판 있는
  것은 안 낸다(node.exe 87MB 0.029초, cargo.exe 0.048초).
- 0.5.1 → 0.6.0: 파일 17 → 24.5MB(+0.21초), **시작 준비**(크기 보정 뒤 잔차) 0.10 → 0.48초.

## 고칠 것 (돈 안 드는 것부터)

1. **시작 준비 0.48초를 찾아 줄인다** — 명령을 고르기 전에 무엇을 하나. 의심: clap 명령 트리를 전부 만들며
   도움말 문구를 두 언어로 다 만드는 것(`tf!`), 그 밖에 시작 때 읽는 파일.
2. **실행 파일을 줄인다** — 릴리스 설정(strip, LTO, codegen-units=1, panic=abort 검토), 큰 의존성 · 묶인 자원 확인.
3. **배포본 코드 서명** — 근본 해결. 인증서가 필요하다(비용). 정식 배포 때.

## 알아낸 것 (2026-10-04, 윈도우 세션 측정)

- **"시작 준비 0.48초" 는 우리 코드가 아니다.** 맥에서 우리 시작 작업은 2ms, 윈도우에서도 느릴 때 프로세스 CPU 는 3~19ms 이고
  나머지는 기다림이다. 실행 방법(Process.Start · cmd · PowerShell)과 상관없고, DLL 목록도 0.5.1 과 같다.
- **정체는 파일마다 따로 붙는 OS(백신으로 추정) 검사 상태다.** 같은 파일이 어느 순간 1.15초 → 17ms 로 떨어지고 그대로 머문다.
  해시가 같은 사본은 계속 느리고, 8월에 설치한 0.5.1 은 지금도 0.57초다 — 사용자에게는 "늘 느림" 으로 보인다.
  예전에 잰 "29ms/MB" 는 느린 상태에서만 보이는 모습이다.
- 그러니 근본 대책은 **배포본 서명**이다(검증은 못 했다 — 인증서가 있어야 한다).

## 고침

- 릴리스 설정(`Cargo.toml` `[profile.release]`): `strip = true`, `lto = "fat"`, `codegen-units = 1`.
  - 윈도우: 24.8 → 19.3MB, 느린 상태 1.15 → 0.97초(−16%). 빠른 상태는 둘 다 17ms. 빌드 2분 → 4분.
  - 맥: 23.9 → 13.9MB.
- 서명은 비용이 드는 일이라 이 퀘스트에서 하지 않는다.

## 시험

- 윈도우에서 `openguild --version` · `quest show` 시간을 0.5.1 · 지금 · 고친 것으로 잰다.

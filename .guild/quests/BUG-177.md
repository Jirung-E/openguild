`openguild quest new` 를 하면 **매번** `check drift` 가 거짓 경고를 낸다.

```
⚠ drift found:
  sibling (.comments/.memo) is newer (1):
    - DEV.toml
```

## 원인

`ops::quests::sync_type_counter_file`(DEV-242)이 새 번호를 `.guild/types/{prefix}.toml`
의 `[counter].last_number` 로 끌어올리며 **파일을 쓴다**. 그런데 그 경로의
`file_mtime` 캐시를 갱신하지 않아, 다음 `check drift` 가 "파일이 캐시보다
새롭다"고 본다. 댓글/메모 쓰기 경로는 이미 `file_mtime::touch` 를 호출한다
(`ops/campaign_comments.rs` 등) — 타입 파일 경로만 빠져 있다.

부수 문제: 분류 라벨이 `sibling (.comments/.memo)` 로 나온다. 타입 정의 파일은
sibling 이 아니다 — 사용자가 원인을 오해하게 만든다.

## 왜 중요한가 (성능과 직결)

거짓 drift 를 보면 사용자는 `check drift --resync` 를 돌리게 되고, 그건
**전체 reindex** 다. DEV-246 으로 길드 열기를 4.1초 → 18ms 로 줄여놨는데,
이 경고 하나가 사용자를 수동 풀 reindex 로 유도한다.

## 수정 방향

- 타입 파일을 쓴 직후 `file_mtime::touch` 로 캐시 갱신(댓글 경로와 동일 패턴).
- drift 분류 라벨을 실제 파일 종류에 맞게 — 최소한 타입/상태 정의 파일을
  sibling 으로 부르지 않도록.

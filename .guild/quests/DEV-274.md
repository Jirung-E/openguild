# [cli] docs 명령 출력 분리 — 기본 목차, --section 섹션별, --full 전체

사용자 요청: `docs` 명령이 항상 문서 전체를 출력해 사람도 불편하고
(스크롤) 에이전트도 토큰 낭비. 전체 출력은 별도 옵션으로 분리하고,
'목차' 출력과 '각 섹션' 출력 옵션이 필요.

## 구현

`openguild docs <name>` 의 기본 동작을 **전체 본문 → 목차**로 변경:

| 명령 | 출력 |
|------|------|
| `docs` | 문서 목록 (기존과 동일) |
| `docs <name>` | **목차** — 번호 + 레벨 들여쓰기한 제목 목록 (신규 기본) |
| `docs <name> --section <번호\|제목>` | 그 절만 (하위 절 포함) |
| `docs <name> --full` | 전체 본문 (기존 기본 동작) |

- `--full` 과 `--section` 은 clap `conflicts_with` 로 상호배타.
- **목차 추출**(`doc_headings`): ATX 제목(`#`~`######`)만 파싱하되
  **코드펜스(``` / ~~~) 안의 `#` 은 제외** — USAGE.md 처럼 셸 예시가
  많은 문서에서 주석 라인이 제목으로 잡히는 오탐 방지. 닫는 펜스는 여는
  마커와 같은 종류일 때만 인정.
- **섹션 슬라이싱**: 대상 제목 라인부터 "같거나 더 상위 레벨의 다음
  제목" 직전까지 → 하위 절이 자연히 포함된다(예: `## 2. Command catalog`
  선택 시 `### 2.1 …` 도 함께).
- **매칭 규칙**: 숫자면 목차 번호(범위 밖이면 안내 에러), 아니면 제목
  부분일치(대소문자·공백 무시). 여러 개 일치 시 침묵 통과하지 않고
  후보 목록을 번호와 함께 에러로 안내 — 잘못된 절을 조용히 읽는 사고
  방지(DEV-250 의 "미존재 slug 침묵 통과 방지"와 같은 취지).
- `--json` 모두 지원: 목차는 `{name, toc:[{n,level,title,line}]}`,
  섹션은 `{name, section, n, body}`, 전체는 `{name, body}`.
  (기존엔 `--json` 이어도 raw markdown 을 그대로 뱉었음 — 이제 목차/섹션
  모드는 파싱 가능한 구조로.)

## 하위호환 주의

`docs <name>` 의 기본 출력이 바뀌므로, 전체 본문을 기대하던 기존
스크립트/에이전트 워크플로는 `--full` 을 붙여야 한다. CHANGELOG 및
배포 스킬 레퍼런스에 반영 필요.

## 테스트 방법

1. `cargo test -p openguild-cli` — `cli_parse_docs`(--full/--section 파싱
   + 상호배타), `doc_headings_skips_code_fences`(코드펜스 제외/레벨/라인)
   통과.
2. 실기: `openguild docs usage`(목차만), `--section 2`/`--section "command
   catalog"`(그 절 + 하위), `--full`(전체), 모호한 검색어로 후보 안내
   에러, 범위 밖 번호 에러 확인.

PR 시 cargo clippy + cargo test + npm test + svelte-check + vite build 자동 실행.

## 구현 (2026-05-20)

### Workflow 파일
- `.github/workflows/check.yml` 신설.
- 트리거: `main` / `develop` 으로의 PR + 직접 push.
- 두 job 병렬 실행:
  - **backend (cargo)**: clippy `-D warnings`, test `--test-threads=1`.
  - **frontend (npm)**: `svelte-check`, `vitest --run`, `vite build`.
- 캐시 정책: `~/.cargo/registry` + `~/.cargo/git` 만 캐시 (CLAUDE.md 정책 대로 `target/` 제외).
- 노드 캐시: `actions/setup-node@v4` 의 npm cache + `gui/frontend/package-lock.json` key.

### 부수적인 clippy 정리
- `core/src/ops/counter.rs`: `field_reassign_with_default` — `CombinedReport` 초기화 시 struct update syntax 로 변경.
- `core/src/recents.rs`: `collapsible_if` — `&&` + `let` chain 으로 평탄화.
- `cli/src/main.rs::Command`: `large_enum_variant` — CLI 의 한 번 실행 특성상 무시 (`#[allow]`).

### 의도적으로 빠진 것
- `cargo fmt --check` — 기존 코드베이스 대규모 정렬은 별도 quest (~840 줄 변경).
  CI 통과 후 fmt 일괄 적용 + 강제 step 추가.

## 회귀

- 모든 기존 테스트 통과 (cli 45, core 123, gui 12, server 120; frontend 63).
- 로컬에서 워크플로의 각 step 직접 실행으로 시뮬레이션.

## 검증

로컬 시뮬레이션 (CI 가 실행할 명령과 동일):
- `cargo clippy --workspace --all-targets -- -D warnings` → 0 error.
- `cargo test --workspace -- --test-threads=1` → 300 passed.
- `npm run check` (svelte-kit sync + svelte-check) → 0 error / 0 warning.
- `npm test -- --run` (vitest) → 63 passed.
- `npm run build` (vite) → success.

실제 GitHub Actions 실행 결과는 PR 머지 후 다음 PR 부터 관찰.

## 후속 (별도 quest 후보)

- `cargo fmt` 일괄 적용 + workflow 에 `cargo fmt --check` step 추가.
- 빌드 산출물 (frontend `build/`, gui 바이너리) artifact upload — 릴리즈 시.
- `main` 머지 시 배포 워크플로 분리 (현재는 검사만).
- Windows / macOS runner 추가 — tauri build matrix.

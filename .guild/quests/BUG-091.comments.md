기존 수정(WAL→DELETE journal_mode 분기, `db.rs::is_network_url`)은 맞는 방향이지만 **더 앞단에서 막혀서 발동조차 못 했음**.

## 진짜 원인 (이번에 재현된 에러로 특정)

사용자가 보고한 에러: `선택된 경로가 유효한 디렉토리가 아닙니다: UNC\(주소)\(길드이름)`

`.guild` 파일을 더블클릭 → `inspect_guild_path()`(gui/src/commands.rs) → `recents::normalize_abs()`(core/src/recents.rs) 호출. 이 함수가:

```rust
let abs = std::fs::canonicalize(path)...;          // UNC 입력 시 \\?\UNC\server\share\... 반환
raw.trim_start_matches(r"\\?\")                      // → "UNC\server\share\..." (앞의 \\ 가 사라짐!)
```

Windows 의 `canonicalize()` 는 UNC 경로를 항상 `\\?\UNC\server\share\...` 형태(verbatim, `UNC\` 마커 포함)로 반환합니다. 기존 코드는 `\\?\` 4글자만 잘라내서 `UNC\server\share\...` 가 남는데, 이건 앞에 `\\` 가 없어 `Path::is_dir()` 가 유효한 네트워크 경로로 인식 못 합니다 — 그래서 길드가 한 번도 못 열리고 "유효한 디렉토리가 아닙니다" 에러로 막혔습니다. 기존 WAL/journal_mode 수정은 길드가 **열린 뒤** index.db 접근 단계의 문제라 이보다 늦은 단계 — 애초에 못 열리니 도달 자체를 안 했습니다.

## 수정

`core/src/recents.rs` 에 `strip_verbatim_prefix()` 신설 — `\\?\UNC\` 는 `\\` 로 복원(`UNC\server\share` → `\\server\share`), 일반 `\\?\C:\` 는 기존처럼 그냥 제거. 동일한 버그가 독립적으로 5곳에 복붙되어 있어서(`recents.rs`/`store.rs`/`migrate.rs`/`maintenance.rs`/`gui/src/lib.rs`) 전부 이 함수로 통일.

부수효과: `store.rs::sqlite_file_url()` 도 같은 헬퍼를 쓰게 되면서, UNC 경로가 `sqlite://server/share/...` 형태(스킴 `sqlite://`)로 정상 변환됨 — 이게 바로 `db.rs::is_network_url()` 이 WAL 대신 DELETE journal_mode 로 분기하는 판단 기준이라, 기존 BUG-091 1차 수정이 UNC 케이스에서는 사실 한 번도 발동되지 않고 있었던 것도 같이 해결됨.

## 검증

- `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --release` 전부 통과(171+304+77+16, 0 fail).
- `strip_verbatim_prefix` 신규 단위 테스트 3개 추가(UNC/로컬드라이브/패스스루) — `core/src/recents.rs`.
- **네트워크 공유 폴더에서 직접 실행 재현은 못 했음**(이 환경에 UNC 공유가 없음) — 사용자 환경에서 동일하게 `\\서버이름\공유폴더\` 의 `.guild` 더블클릭으로 재검증 부탁드립니다.

해결 확정 — 사용자 실기 검증 완료(`\\서버\공유폴더\` 의 `.guild` 더블클릭으로 정상 오픈, 2026-07-02).

최종적으로 버그는 **3개 층**이 겹쳐 있었음:

1. **경로 인식** (1차 수정, 커밋 19dc538): `normalize_abs` 가 `canonicalize` 의 `\\?\UNC\` verbatim prefix 를 잘못 잘라 `UNC\server\...` 가 남음 → "유효한 디렉토리가 아닙니다" 에러. `strip_verbatim_prefix()` 로 해결.
2. **공유 권한** (환경): 공유폴더가 쓰기 불가 상태라 `Store::open` 의 디렉토리 생성이 os error 5. 사용자가 공유 권한 부여로 해결. (부수: `Store::open` 의 `create_dir_all` 에 경로 포함 context 추가 — 진단성.)
3. **sqlite URL 파싱** (2차 수정, 이번): UNC 를 `sqlite://server/share/...` URL 로 만들면 sqlx 의 URL 파서가 `server` 를 host 로 해석해 파일 경로가 깨짐 → code 14 "unable to open database file". **원래 1차 구현(0426e29)의 journal_mode 분기가 이 URL 형태를 전제했는데 그 전제 자체가 성립 불가였음.** URL 경유를 없애고 `SqliteConnectOptions::filename(경로)` 직접 전달로 해결 — `db::create_pool_from_path(path, read_only)` 신설, store/maintenance/migrate 전환. 네트워크 판별도 `is_network_url`(URL) → `is_network_path`(경로, verbatim 방어) 로 교체되어 WAL→DELETE 분기가 이제 실제로 발동.

교훈: URL 문자열은 UNC 를 표현할 수 없다 — 파일 DB 는 항상 경로로 열 것 (`db.rs` 의 `create_pool` 은 in-memory 전용으로 축소).

## 후속 수정 (2026-08-01, 사용자 보고: "마우스 호버시엔 잘 뜨는데 방향키로
포커스되어있을때는 안뜸")

원인: cross-link 자동완성 목록(`[[` 팝업)은 "가상 포커스" 방식 — ↑/↓
로 항목을 이동해도 실제 DOM focus 는 계속 textarea 에 남아있고(타이핑
유지를 위해), `wikiSel` 이라는 숫자 인덱스만 바뀐다. `use:titlePopup`
은 hover/focus DOM 이벤트에 의존하는데, 이 목록의 키보드 이동은 진짜
focus 이벤트를 발생시키지 않아 안 뜸.

## 수정
`title-popup.ts` 에 수동 트리거 `showTitlePopupNow`/`hideTitlePopupNow`
export 추가. `QuestCommentsSection.svelte` 의 기존 "선택 항목 스크롤"
$effect(↑/↓ 이동 시 실행)에서 같이 호출 — 스크롤과 같은 타이밍에 팝업도
띄움. 자동완성이 닫히면(wiki=null) 수동 팝업도 정리.

## 테스트 방법
1. 댓글 편집기에서 `[[` 입력해 자동완성 목록 띄우기.
2. 마우스 안 움직이고 ↑/↓ 만으로 항목 이동 → 제목 툴팁이 뜨는지.
3. 마우스 hover 는 기존대로 동작하는지(회귀 확인).
4. Esc/Enter/바깥 클릭으로 목록 닫을 때 툴팁도 같이 사라지는지.

﻿툴팁이 위/아래 항목을 통째로 가리는 문제 수정(admin 보고). DEV-325 에서 제안한 '키보드 선택 시 제자리 펼침'을 목록 두 곳에 적용했다.

- 검색 팔레트 결과 행, 댓글의 cross-link 자동완성 항목: 키보드(↑/↓)로 선택된 항목만 말줄임을 풀어 **그 자리에서** 펼친다. 마우스 호버는 기존 팝업 유지(훑는 동작이라 높이가 계속 바뀌면 더 어지럽다).
- 호버로 이미 떠 있던 팝업은 키보드로 넘어가는 순간 닫는다 — 안 그러면 펼침과 팝업이 동시에 떠서 여전히 가린다(실측으로 발견해 수정).
- 펼쳐지면서 행 높이가 바뀌므로 스크롤 보정을 다음 프레임에 다시 계산.
- 우측 액션 버튼은 첫 줄에 고정(align-items: flex-start) — 늘어난 행에서도 위치가 안 흔들린다.

실측(서버 모드, 긴 제목 퀘스트로): 선택 전 행 36px·제목 잘림 → ↓ 선택 후 80px·잘림 해소·**툴팁 없음**·액션 버튼 여전히 표시. 호버 시에는 팝업이 뜨고 펼침 없음.

사용자 보고: `tag list`, `rule list` 등을 `--json` 으로 출력하면 pretty 하게
출력되지 않음. 전수조사 결과 포함해 등록.

## 조사 결과 (2026-07-17)

CLI 의 JSON 출력 경로가 두 갈래로 갈라져 있음:
- `json_str(&v)` — JSON_COMPACT(--compact 플래그, DEV-211)를 존중해
  기본 pretty / --compact 시 한 줄. **올바른 경로.**
- `println!("{}", serde_json::json!({...}))` — serde_json Value 의 Display
  는 항상 compact. --compact 여부와 무관하게 늘 한 줄로 나옴. **버그 경로.**

버그 경로가 총 **25곳**, 15개 함수에 분포:
- handle_rules 3곳 (rule list/set/create/delete/rename 계열)
- handle_tag 1곳 (tag list — defs/used/undefined_in_use 합성 응답)
- handle_worklog 3곳, handle_quest 3곳, run_attach_cmd 2곳,
  run_comment_cmd 2곳, run_memo_cmd 2곳, handle_library 2곳,
  handle_types/statuses/backup/locale/journal-tail/campaign print_detail/
  run() 각 1곳.

공통 원인: 즉석에서 serde_json::json! 매크로로 합성한 임시 객체는 json_str
헬퍼를 안 거치고 바로 println. 수정은 기계적 —
`println!("{}", json_str(&serde_json::json!({...})))` 로 감싸거나 값 변수로
뽑아 json_str 경유.

## 작업

- 25곳 전부 json_str 경유로 통일.
- 회귀 방지: "직접 json! 출력 금지" 를 잡는 테스트/린트(grep 기반 테스트,
  BUG-016 help-leak 테스트와 같은 방식) 추가 검토.

# [cli] --json 출력 pretty 불일치 — json_str 미경유 통일

사용자 보고: `tag list`, `rule list` 등을 `--json` 으로 출력하면 pretty 하게
출력되지 않음. 전수조사 결과 포함해 등록.

## 조사 결과 (2026-07-17)

CLI 의 JSON 출력 경로가 두 갈래로 갈라져 있음:
- `json_str(&v)` — JSON_COMPACT(--compact 플래그, DEV-211)를 존중해
  기본 pretty / --compact 시 한 줄. **올바른 경로.**
- `println!("{}", serde_json::json!({...}))` — serde_json Value 의 Display
  는 항상 compact. --compact 여부와 무관하게 늘 한 줄로 나옴. **버그 경로.**

## 실제 규모 (재조사, 2026-07-19)

이번에 다시 스캔한 결과 **68곳**(quest 필드에 적힌 "25곳"보다 훨씬 많음
— 그 사이 DEV-262 등에서 새로 추가된 println 도 같은 함정에 또 빠져
있었음). 사실상 CLI 전역에 흩어진 대부분의 mutation 명령(add/remove/
update/delete/set/clear 등)의 `{"ok": true, ...}` 응답이 여기 해당.

## 수정

- 개별 콜사이트를 하나하나 고치는 대신, `json_println!($v:expr)` 매크로를
  추가(`println!("{}", json_str(&$v))` 로 확장) — `println!("{}",
  serde_json::json!(` 로 시작하는 모든 콜사이트를 기계적으로
  `json_println!(serde_json::json!(` 로 치환(뒤따르는 괄호 구조는 원본과
  동일해 텍스트 치환만으로 안전).
- `comments_search`(DEV-262 에서 이미 SQL LIMIT 제거함)를 포함해 전부
  영향 없음 확인 — 이 함수 자체는 println 을 안 함(값만 반환).
- 회귀 방지 테스트 `no_bare_println_json_value_regression` 추가 — 자기
  소스(`include_str!("main.rs")`)를 스캔해 `println!` 뒤에 바로
  `serde_json::json!(` 이 이어지는 패턴이 남아있으면 실패. (BUG-016
  help-leak 테스트와 같은 "소스 자체를 스캔" 방식.)

## 테스트 방법

1. `cargo test -p openguild-cli` — 기존 105건 + 신규
   `no_bare_println_json_value_regression` 통과(총 106건).
2. `cargo test --workspace` 526건 통과, `cargo clippy --workspace
   --all-targets -- -D warnings` 클린.
3. 스크래치 길드 실기 확인 — `rule new --json`(pretty 2-space 확인) vs
   `rule new --json --compact`(한 줄 확인), 둘 다 기대대로 동작.

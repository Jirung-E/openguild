## 구현 — 목록 재수신/재파싱 제거 (조건부 GET)

DEV-357 에서 첨부·정적 자산은 조건부 요청이 되게 했지만 `/api/quests` 는 그대로였다.
화면을 옮겼다 돌아올 때마다 목록 275KB(gzip 36KB)를 다시 받아 500여 개 객체로
다시 파싱하고 있었다.

**서버** (`server/src/routes/quests.rs`) — 직렬화한 응답 본문으로 FNV-1a 64 ETag 를
만들고, `If-None-Match` 가 같으면 `304 + ETag + Cache-Control: no-cache`.
클라이언트가 스스로 캐시를 무효화하게 하지 않은 이유: 원격 모드에서는 **다른
클라이언트가 바꾼 것**을 알 수 없어 "고쳤는데 목록에 안 보인다"가 된다.
신선도 판단은 매번 서버가 한다.

**클라이언트** (`transport.ts`, `quests.ts`) — `getWithEtag()` 가 URL 별로
`{etag, 파싱된 데이터}` 를 들고 있다가 304 면 **파싱해 둔 배열을 그대로** 돌려준다.
`cache: 'no-store'` 로 브라우저 캐시가 304 를 가로채지 못하게 했고, Tauri 경로는
기존 호출로 그대로 떨어진다.

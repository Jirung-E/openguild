## 무엇

플러그인을 **길드 밖 폴더에서도** 가져다 쓴다. 클로드 플러그인처럼 **소스(마켓)** 를 등록하고,
그 소스가 내놓는 플러그인 중 이 길드에서 쓸 것을 고른다. 이 퀘스트는 **코어와 CLI** 까지다
(데스크톱 화면은 [[DEV-400]]).

admin: *"plugin add도 필요해보임. 외부 폴더에 있는 플러그인에 연결할 수 있도록."* →
*"플러그인 폴더는 유지하면 좋겠는데. 그냥 클로드 플러그인 같은 느낌으로 하는건 어떨지?"*

## 왜

지금 플러그인을 넣는 방법은 `.guild/plugins/` 에 파일을 만드는 것 하나뿐이다. 그래서
- 여러 길드에서 같은 훅을 쓰려면 폴더를 복사해 두어야 하고(고칠 때마다 전부),
- 만들어 둔 개인 훅 모음을 새 길드에 붙일 방법이 없고,
- 이 저장소의 `examples/plugins/` 도 저장소를 가진 사람만 쓸 수 있다.

## 층 셋

| 층 | 무엇 | 어디 |
|---|---|---|
| 길드 플러그인 | `.guild/plugins/` — **그대로 둔다.** 이 길드에 딸린 것, git 공유 | 길드 |
| 소스 | 플러그인 여럿을 담은 폴더를 "여기서 가져다 쓴다" | `~/.openguild/plugin-sources.json` (기계) |
| 사용 중 | 그 소스의 것 중 **이 길드에서 쓸 것** | 같은 파일, 길드별 |

**복사하지 않는다.** 소스 폴더의 코드를 그 자리에서 적재한다 — 원본을 고치면 바로 반영되고
(동의는 지문이 바뀌어 다시 묻는다), 여러 길드가 같은 플러그인을 나눠 쓴다.

## 적재 — 경로 목록 하나

```
적재 경로 = [ .guild/plugins/ 아래 폴더들 ] + [ 이 길드에서 쓰기로 한 소스 플러그인 폴더들 ]
```

갈래가 둘로 늘지 않는다. 지금의 길드 폴더 스캔이 그 목록의 첫 항목이 될 뿐이다.
동의·지문·scope·설정값은 전부 그대로다 — `add` 는 **어디를 훑을지**만 늘린다.

## 막는 것

| 상황 | 동작 |
|---|---|
| 이름 충돌(길드에 `notify`, 소스에도 `notify`) | 적재에서 거부 + 어느 경로끼리 겹쳤는지 표시. **동의가 이름으로 저장**되므로 섞이면 안 된다 |
| 소스 경로가 사라짐(외장 디스크 분리) | 깨진 정의처럼 이유와 함께 목록에 남긴다 — 조용히 빠지면 "왜 안 돌지" 가 된다 |
| 길드 안 경로를 소스로 | 거부 — 이미 훑는다 |
| `plugin.json` 을 하나도 못 찾는 폴더 | 거부 |

## 명령

```
openguild plugin source add <경로> [--name <이름>]   # 마켓 등록(기계 전체)
openguild plugin source list / remove <이름>
openguild plugin available                           # 소스들이 내놓는 것
openguild plugin add <이름>[@<소스>]                  # 이 길드에서 쓴다
openguild plugin add <경로>                           # 편의: 소스 등록 + 사용까지
openguild plugin remove <이름>                        # 안 쓴다(파일은 안 지운다)
```

`plugin list` 는 출처를 함께 보인다 — `(길드)` / `(소스이름)`.

## 소스 폴더 모양

- 그냥 폴더: 하위 폴더마다 `plugin.json` — 길드 폴더와 같은 규칙. 별도 파일 없이 소스가 된다.
- 이 저장소의 `examples/plugins/` 가 그대로 소스가 된다.

## 이번에 안 하는 것

- **git URL 소스, 버전·업데이트.** 폴더만 먼저. 소스 종류를 늘릴 자리는 남긴다.
- **"이 길드는 이걸 쓴다" 를 git 으로 공유.** 소스가 git URL 이어야 말이 되므로 위와 함께 미룬다.

## 구현

- `core/src/plugins/sources.rs` — `~/.openguild/plugin-sources.json`(소스: 이름 → 폴더, 사용 중:
  길드 → `{source, folder}`). 동의 파일과 같은 규칙(못 읽는 파일은 안 덮어씀, 임시 파일 후 rename).
- **적재는 폴더 목록 하나** — 길드 폴더가 첫 항목, 그 뒤에 이 길드에서 쓰는 소스 플러그인.
  `Plugin.source` 에 출처를 싣고 `PluginView` 에 `source`·`dir` 을 더했다.
- 사람이 부르는 이름은 **정의의 `name`** 이다(폴더 이름과 다를 수 있다) — `available`·`add`·
  `remove` 가 전부 그 이름으로 찾는다. 처음엔 폴더 이름을 보여 줘서 `plugin add hello-log` 가
  "소스에 없다" 로 실패했다(실환경에서 밟음).
- CLI: `plugin source add|list|remove`, `plugin available`, `plugin add <이름|이름@소스|경로>`,
  `plugin remove <이름>`. 경로를 주면 소스 등록 + 사용까지, 그 폴더에 플러그인이 여럿이면 등록만
  하고 고르게 한다(통째로 켜지 않는다). `plugin list` 는 출처를 `(소스)` 로 보인다.

## 확인한 것

- 코어 시험 3개: 소스 플러그인이 길드 것과 한 목록에 나오고 **원본 폴더에서** 적재된다 /
  `remove` 하면 빠지고 파일은 남는다 / 이름 충돌 거부 + 사라진 소스는 이유와 함께 /
  길드 안·빈 폴더·없는 경로를 소스로 등록하면 거절.
- 실제 CLI(임시 길드 + 길드 밖 폴더에 플러그인 둘): `source add` → `available` → `add hello-log`
  → `allow` → 퀘스트를 만들자 **훅이 실제로 돌아** 데이터 폴더에 `hello.log` 가 생겼다.
  길드에 같은 이름을 두자 겹침 오류에 소스 경로까지 표시, 소스 폴더를 치우자 `plugin list`·
  `source list` 에 이유가 뜨고 되돌리니 다시 `(mine)` 으로 돌았다. 길드 안 폴더를 소스로 주면 거절.
- `just test` 전체 통과.

## 실제 바이너리 시험이 잡은 결함 둘

`cli/tests/plugin_sources.rs` — 사람이 치는 순서 그대로(`source add → available → add → allow →
이벤트 → remove`) 실제 `openguild` 를 돌리고, 훅이 돌았는지 파일로 본다. 폴더 이름과 정의
이름을 일부러 다르게 뒀다.

1. **폴더 하나짜리 플러그인을 `plugin add <경로>` 하면 실패했다.** 소스 자체가 플러그인이면
   기록할 폴더가 없는데 폴더 이름을 적어, 쓸 때 경로를 **두 번** 이어 붙였다("소스에 없다").
   문서에만 적고 직접은 안 돌려 본 경로였다. 이제 그 경우 폴더를 `"."` 로 적는다.
2. **`plugin remove <이름>` 이 다른 플러그인까지 뺐다.** 기록을 폴더 이름으로만 비교해서, 폴더
   하나짜리 소스가 둘이면(둘 다 `"."`) 한꺼번에 빠졌다. `(소스, 폴더)` 짝으로 비교한다.
   되돌리면 새 시험(`removing_one_single_folder_source_keeps_the_other`)이 실패한다.

그 밖의 시험: 흐름 전체(훅이 실제로 돌고 remove 뒤 원본이 남음) / 사라진 소스는 목록 오류로 /
길드와 이름이 겹치면 한쪽만 실리고 오류.

## 테스트 방법

- 소스를 등록하고 `add` 한 플러그인이 `plugin list` 에 뜨고, 허용하면 **실제로 이벤트에 반응한다**.
- 원본 폴더를 고치면 동의가 풀린다(지문).
- 이름 충돌·없는 경로·길드 안 경로·plugin.json 없는 폴더가 각각 거부/표시된다.
- `remove` 하면 목록에서 빠지고 **파일은 남는다**.
- 길드 플러그인은 소스와 무관하게 예전처럼 동작한다.

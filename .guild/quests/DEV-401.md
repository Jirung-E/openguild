## 무엇

플러그인이 일으킨 변경이 **같은 플러그인을 다시 부르는 무한 반복**을 막는다. 이벤트에 "누가 일으켰나"(거쳐 온 플러그인 목록)를
싣고, 그 목록에 이미 있는 플러그인에는 이벤트를 보내지 않는다. 횟수는 세지 않는다(admin 결정, 2026-09-17).

- 이벤트에 `origin: { by: "user" | "plugin", chain: [...] }`.
- A → B 는 된다(스크립트가 만든 백업을 backup-archive 가 복사). A → A, A → B → A 는 막힌다. 목록이 서로 다른 플러그인으로만
  자라므로 반복이 반드시 끝난다.
- `run` 훅 자식에게 `OPENGUILD_PLUGIN_CHAIN`(지금 목록 + 자기 이름)을 넘기고, CLI 는 그 값을 자기 이벤트의 origin 으로 쓴다.
- CLI 원격 모드는 요청 헤더(`X-OpenGuild-Plugin-Chain`)로 넘기고, 서버는 그 요청이 낸 이벤트에 붙인다. `post` 훅도 같은 헤더를
  붙여 보낸다(자기 서버 API 를 부르는 경우).
- 사람 조작(GUI·직접 친 CLI)은 목록이 비어 있다.

## 왜

지금도 `run` 훅이 `openguild quest tag add` 같은 명령을 부르면, 그 변경이 다시 같은 훅을 부른다 — 끝나지 않는다. 스크립트가
길드 명령을 직접 부르는 기능(논의 중)이 생기면 더 쉽게 생긴다.

## 확인 방법

- 코어 시험: 목록에 있는 플러그인은 건너뛴다 / 다른 플러그인은 받는다 / 이벤트 JSON 에 origin 이 실린다 / run 자식 환경변수.
- 실제 바이너리: `quest.tags_changed` 에 걸린 `run` 훅이 `openguild quest tag add` 를 부르는 플러그인 — 한 번만 돈다.
  원격 모드(스크래치 서버)도 같은지.

## 구현 / 확인한 것

- 코어 `events::origin` — "누가 일으켰나" 를 한 곳에서 읽는다(`current()`): 이 작업에 붙인 값(서버 요청) → 프로세스 기본값
  (CLI 가 시작할 때 `OPENGUILD_PLUGIN_CHAIN` 에서 읽음) → 없으면 사람. 나중에 스크립트가 길드 명령을 직접 부르면 그 실행을
  `origin::scope` 로 감싸면 된다. 백그라운드 자동 백업 작업도 요청의 값을 들고 간다.
- 이벤트에 `origin: {by: "user"|"plugin", chain: [...]}` (스크립트도 `e.origin` 으로 본다).
- 전달: 목록에 이미 있는 플러그인은 건너뛴다. `run` 자식에게 `OPENGUILD_PLUGIN_CHAIN`(받은 목록 + 자기 이름, 설정값·부모
  환경의 같은 이름은 덮음), `post` 요청에 `X-OpenGuild-Plugin-Chain` 헤더(JSON 을 퍼센트 인코딩 — 한글 이름).
- CLI 원격 모드는 같은 헤더를 붙이고, 서버는 요청마다 그 헤더를 읽어 그 요청의 변경에만 붙인다(다음 요청으로 새지 않음).
- 못 읽는 값은 사람으로 본다(손으로 넣은 값 때문에 명령이 실패하지 않게).
- 시험: origin 단위 5, 전달 건너뛰기(`a_plugin_never_hears_a_change_it_already_caused`), 실제 변경에 실리는지, 스크립트가
  보는지, run 자식 환경변수, post 헤더, 서버 요청별 구분(`a_request_from_a_plugin_is_marked_as_such`). 건너뛰기와 서버
  미들웨어를 각각 빼면 해당 시험이 실패함을 확인.
- 실제 바이너리(스크래치 길드, `OPENGUILD_HOME` 격리): `quest.tags_changed` 에 걸린 `run` 훅이 `openguild quest tag add` 로 새
  태그를 다는 플러그인(안전을 위해 5회에서 스스로 멈춤).
  - 수정 전 흉내 — 훅이 `env -u OPENGUILD_PLUGIN_CHAIN` 으로 목록을 지우고 부르면: 5회(상한까지) 돎.
  - 수정 후: 1회. 훅은 실제로 새 태그(t1)를 달았고 다시 불리지 않았다.
  - 원격(127.0.0.1:3311 스크래치 서버, 서버 scope 훅이 `--remote` 로 같은 서버를 부름): 수정 후 1회, 흉내 5회. 서버는 끝나고 껐다.
- 확인 못 한 것: 데스크톱 앱(GUI 조작은 사람이라 목록이 비는 것 — 코드상 기본값 그대로), Windows. 실제 옛 바이너리로 돌리지
  않고 "목록을 지운 자식" 으로 수정 전을 흉내 냈다.

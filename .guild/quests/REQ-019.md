## 요청 (admin)

> 도서관 페이지에서 태그들이 쭉 보이는게 불편. 접을 수 있어야함.
> 비슷한 문제가 있는곳이 있는지 확인해봐라.

## 전수 조사

태그 필터는 **3개 화면 4개 렌더 지점**에 있고, 넷이 사실상 같은 마크업이다.

| 화면 | 파일 | 지금 |
|------|------|------|
| 도서관 (사이드바) | `routes/library/+page.svelte` | 전부 펼침, `flex-wrap` 무제한 |
| 도서관 (탐색기 뷰) | 같은 파일 — **같은 코드가 두 번** | 동일 |
| 규칙 | `routes/rules/+page.svelte` | 동일 |
| 퀘스트 목록 | `lib/components/QuestList.svelte` | 동일. 단 ≤640px 는 한 줄 가로 스크롤([[BUG-194]]) |

**캠페인 목록은 해당 없음** — 캠페인에는 태그 개념 자체가 없다. CLI 도움말이
"태그 정의 카탈로그 … quest/도서관/규칙 공유" 라고 못박고 있고, 목록 페이지의
필터도 상태(전체/진행/완료) 하나뿐이다.

[[DEV-364]](pill) / [[DEV-272]](글꼴)와 같은 모양의 문제다 — 같은 물건이
복붙돼 있어서 한 번 고치려면 네 번 고쳐야 한다.

## 정한 것 (admin)

| 질문 | 결정 |
|------|------|
| 접는 방식 | **기본 접힘 + "태그 N" 토글** |
| 상태 기억 | **화면별로 세션 동안**(sessionStorage) |
| 공통화 | **묶는다** — `TagFilterRow` 하나로 |

## 주의

- **접혀 있어도 고른 태그는 보여야 한다.** 필터가 걸린 채 숨으면 목록이 왜
  줄었는지 알 수 없고 되돌릴 수단도 없다.
- 도서관의 두 렌더 지점은 **같은 필터**다 — 뷰를 바꿔도 접힘 상태가 이어지게
  같은 저장 키를 쓴다.
- i18n 키가 화면마다 갈려 있다(`questList.filterAddSuffix` vs
  `library.tagFilterOnPost`). 한국어는 같고 영어만 미세하게 다르다 — 공통화
  하면서 한 벌로 모은다.
- ≤640px 의 가로 스크롤(BUG-194)이 접기와 겹치지 않는지 볼 것.

## 테스트 방법

1. 도서관/규칙/퀘스트 목록에서 태그 줄이 기본으로 접혀 있고 "태그 N" 이 보인다.
2. 눌러 펼치고 다른 페이지에 갔다 오면 펼친 상태가 유지된다.
3. 태그를 고른 뒤 접으면 **고른 태그와 전체 해제 버튼은 계속 보인다.**
4. 도서관에서 사이드바 ↔ 탐색기 뷰를 바꿔도 접힘 상태가 이어진다.
5. 앱을 새로 켜면 다시 접혀 있다.

## 구현

`lib/components/TagFilterRow.svelte` 하나로 모으고 네 곳이 그것을 쓴다.
접힘 상태는 `utils/tag-filter-collapse.ts`(sessionStorage, 화면별 키).

기본은 접힘 — "▾ 태그 N" 토글 하나만 보인다. 실측으로 도서관 사이드바에서
**145px → 25px**.

### 접혀 있어도 고른 태그는 보인다

필터가 걸린 채 통째로 숨으면 목록이 왜 줄었는지 알 수 없고 되돌릴 수단도
없다 — 원래 불편보다 나쁜 상태다. 접힌 상태에서는 **고른 칩 + "+N" + 전체
해제**만 남긴다(실측 55px).

칩 순서는 원래 목록 순서를 지킨다. 고른 것만 앞으로 당기면 펼쳤을 때 칩이
자리를 옮겨 방금 어디를 눌렀는지 놓친다.

### 죽은 CSS 26건

컴포넌트로 옮기고 나니 세 파일에 태그행 CSS 가 통째로 남았다(svelte-check
가 `Unused CSS selector` 로 26건 보고). 전부 걷어냈다 — 남겨 두면 다음
사람이 그걸 고치고 화면은 안 바뀌는 일이 생긴다.

### i18n 도 한 벌로

`questList.tagFilter` / `rules.tagFilter` / `library.tagFilterAria` 가 전부
'태그 필터' 로 같았고, 툴팁도 한국어는 같고 영어만 미세하게 달랐다
(`— remove filter` vs `filter off`). `tagFilter.*` 한 벌로 모았다.

## 검증

- 단위 테스트 11건. 접혀도 고른 태그가 남는지, 순서가 유지되는지, 화면마다
  따로 기억하는지, 이상한 저장값이 접힘으로 읽히는지.
- 화면(도서관, 태그 12개):
  - 기본 접힘 — "▾ 태그 12", 칩 0, 높이 25.
  - 펼침 — 칩 12, 높이 145.
  - '보안' 을 고르고 접음 — 칩 1(보안) + "+11" + "× 전체 해제", 높이 55.
    문서 목록도 2건으로 걸러진다.
  - 사이드바 ↔ 탐색기 뷰를 바꿔도 펼침이 이어진다(같은 저장 키).
  - 규칙으로 갔다 오면 도서관은 펼침 유지, 규칙은 별도로 접힘(태그 6).
- 퀘스트 목록(태그 4) 동작 동일.
- 375px: `nowrap` + `overflow-x: auto` 로 한 줄 가로 스크롤([[BUG-194]])이
  그대로 살아 있고 문서 가로 넘침 없음.

## 캠페인은 해당 없음

캠페인에는 태그 개념 자체가 없다 — 태그 카탈로그가 "quest/도서관/규칙 공유"
이고 캠페인 목록의 필터는 상태 하나뿐이다.

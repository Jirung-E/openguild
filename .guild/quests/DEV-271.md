# 웹에서도 검색팔레트/접힌 메뉴 보이도록

## 배경

검색 팔레트(전 문서 검색)와 ☰ 메뉴(캠페인 목록/작업기록/태그 목록)가
`TitleBar.svelte` 안에만 구현돼 있는데, `TitleBar` 는 `usesCustomTitlebar()`
가 true 인 경우(Tauri 데스크탑)에만 렌더된다(`+layout.svelte`의
`showTitleBar`). 서버로 배포한 웹(브라우저) 버전은 `detectEnvironment()`
가 `'tauri'` 가 아니라 TitleBar 자체가 렌더되지 않아서, 이 두 기능(검색
팔레트 열기 + 캠페인/작업기록/태그 페이지 이동)에 접근할 방법이 웹에는
아예 없었다.

## 근본 원인 추가 발견

Nav.svelte 에 웹 전용 fallback UI 를 추가하면서, `guildContextActive`
스토어로 가드하려다 또 다른 버그를 발견함 — `routes/+page.svelte` 의
onMount 가 `if (detectEnvironment() !== 'tauri') return;` 로 시작해서,
웹에서는 `markGuildContextActive()` 가 절대 호출되지 않아 이 플래그가
항상 false 다. (이 자체도 잠재적 버그지만 이번 quest 범위 밖 — 별도
후속 필요할 수 있음.) 그래서 Nav 의 웹 전용 UI 는 이 플래그로 가드하지
않고 `showWebExtras`(= `!usesCustomTitlebar()`) 하나로만 게이팅 — 웹
배포는 서버가 이미 특정 길드 하나에 바인딩돼 있어 "길드 미선택" 상태
자체가 없으므로 이걸로 충분.

## 구현

`gui/frontend/src/lib/components/Nav.svelte`:
- `<nav>` 목록에 캠페인/작업기록/태그 링크 추가(웹에서만 — 데스크탑은
  TitleBar 의 ☰ 메뉴로 이미 있어 중복 방지).
- `.nav-right` 에 검색 버튼 추가(웹에서만) — 클릭 시 기존
  `SearchPalette.svelte` 컴포넌트를 그대로 재사용해 열림(TitleBar 가
  하던 것과 동일한 컴포넌트, 새로 안 만듦).

## 테스트 방법 (실기 완료)

1. `npm run build` + `npx svelte-check` — 둘 다 클린(0 error/warning).
2. 실제로 `npm run dev`(vite, 웹 모드) + `openguild-server`(스크래치
   길드) 를 같이 띄워 브라우저로 접속 → Nav 바에 "캠페인 목록"/
   "작업기록"/"태그 목록" 링크와 검색 아이콘 버튼이 실제로 나타나는지,
   검색 버튼 클릭 시 검색 팔레트 다이얼로그(검색어 입력창 포함)가 정상
   열리는지 확인. 확인 후 스크래치 서버/길드 정리.

## Test plan (2차 — 사용자 피드백 반영분)

브라우저(`openguild-server host` 접속)에서:

1. **중앙 pill** — 창 폭을 바꿔도 검색 pill 이 항상 화면 중앙인지. 최근 본
   문서 버튼이 없을 때(기록 0건)와 있을 때 pill 위치가 같은지.
2. **좌우 버튼** — pill 왼쪽 ＋ 로 퀘스트 생성 모달, 오른쪽 시계로 최근 본
   문서(검색 팔레트 recent 모드)가 뜨는지. 데스크탑 앱과 배치가 같은지.
3. **☰ 메뉴** — 창을 좁혀 링크가 접히면 ☰ 가 나타나고, **클릭하면 실제로
   펼쳐지는지**(이전엔 nav 의 overflow:hidden 에 잘려 안 보였음). 항목 클릭 시
   이동 + 메뉴 닫힘.
4. **겹침 접기** — 창을 서서히 좁힐 때 링크가 pill 을 침범하지 않고 그 전에
   ☰ 로 접히는지. 넓힐 때 되돌아오는지(진동 없이).
5. **길드 이름** — pill 에 길드 이름이 보이는지. 원격 연결이면 지구 아이콘.
6. 언어 전환 시 링크 라벨 폭이 바뀌어도 접힘 계산이 따라오는지.
7. 데스크탑 앱에서는 이 UI 가 **보이지 않아야** 한다(타이틀바가 담당) —
   중복 렌더 회귀 확인.

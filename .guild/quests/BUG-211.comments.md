수정 — `lib/api/transport.ts`:

`questListQueryToArgs(query)` 를 분리해 ListQuery 의 bool 8개
(title_only, no_parent, has_prereq, no_prereq, has_sub, no_sub, reverse, slim)
와 정수 2개(limit, offset)를 실제 타입으로 복원한다. bool 표기는
serde_urlencoded 가 HTTP 경로에서 받아주는 것과 맞췄다(`true`/`1`/빈값 → true).

**ListQuery 에 필드를 추가하면 이 목록도 갱신해야 한다** — 주석으로 명시.

## 이 문제를 왜 서버 테스트가 못 잡았나

server 테스트는 HTTP 경로(`Query<ListQuery>`)만 탄다. serde_urlencoded 는
문자열을 알아서 강제 변환하므로 BUG-210 의 slim 테스트 2건은 전부 통과했다.
Tauri 경로는 args 를 JSON 으로 역직렬화하는 **다른 코드 경로**인데 여기엔
테스트가 없었다. 그래서 이번엔 그 변환 함수에 단위 테스트를 붙였다
(`questListQueryToArgs.test.ts`, 6건) — bool/정수/문자열/빈 쿼리/실제 조합.

전체 테스트를 돌려 두 건을 더 잡았다. 릴리스 빌드는 통과했지만 **테스트
코드는 빌드 대상이 아니라** 처음엔 드러나지 않았던 것들이다.

1. `cli/src/main.rs:8156` — 테스트 안의 `ListQuery` 리터럴에 `slim` 누락
   (컴파일 실패). 겸사겸사 `list_query_to_querystring` 에도 slim 을 실었다.
   CLI 원격 모드가 로컬 모드와 어긋나지 않도록 — 지금은 항상 false 지만
   필드가 빠져 있으면 나중에 조용히 무시된다.
2. `lib/api/transport.test.ts` — 기존 테스트가 `limit: '5'`(문자열)를
   **기대하고 있었다**. 그게 바로 이번 버그였다. 문자열 기대를 number 로
   고치고, `slim=true` → `slim: true` 케이스를 추가했다.

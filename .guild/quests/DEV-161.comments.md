# server HTTP API vs core/CLI/Tauri 기능 격차 감사 (DEV-161)

## 결론
server의 **관리 CLI 동작은 대체로 최신**(core 함수에 위임)이나, **HTTP API 라우트**가
Tauri 명령/CLI보다 뒤처져 원격·브라우저 모드에서 누락 기능이 있다. 동작이 틀린 곳은
없고(스냅샷 등 core 위임), 격차는 (A) 라우트 미구현 + (B) stale 문서다.

## A. HTTP 라우트 누락 (Tauri/CLI엔 있는데 서버 API엔 없음)
1. **템플릿 (DEV-060/158)**: `/api/templates` 없음. Tauri `list_templates`/`save_template`,
   CLI `template list/show/add`만 존재 → 원격/브라우저 모드에선 템플릿 기능 전무.
2. **첨부 섹션 (DEV-156)**: `/api/quests/{id}/attachments` (list/add/remove) 없음.
   Tauri `add/remove_quest_attachment`만. (본문 첨부 blob 서빙 `/api/guild-files/*`는 있음.)
3. **타입 변경 (DEV-055)**: `/api/quests/{id}/type` 없음. Tauri `change_quest_type`만.
4. **타입/상태 CRUD**: `/api/quest-types`·`/api/quest-statuses`는 GET(list)만. 생성/수정/
   삭제/이름변경 라우트 없음. Tauri `admin_create_type`/`admin_create_status` 등 +
   CLI `types`/`statuses` 풀 CRUD는 존재.

## B. stale 문서/주석 (동작은 정상, 설명만 옛것)
5. `server/src/main.rs` 헤더(5–7행) 및 67행: snapshot을 아직 `{ts}.db`(index.db 복사)로
   설명. 실제 `run_snapshot`/`run_restore`는 core의 파일 기반 스냅샷(BUG-076,
   `snapshots/{ts}/`)을 호출하므로 동작은 최신 — 문서만 갱신 필요.
6. `info --detailed`의 snapshot 현황 표기도 같은 맥락에서 점검 권장.

## C. 영향 / 우선순위
- **데스크톱(Tauri) 단독 사용**: 영향 없음 — 모든 기능이 Tauri 명령으로 동작.
- **원격(openguild-server host) + 브라우저 GUI** 또는 **`--remote` CLI**: 템플릿·첨부
  섹션·타입 변경·타입/상태 관리 불가.
- 권장 순서: A-1(템플릿)·A-2(첨부) 먼저 — 사용자 노출 기능. A-3/A-4는 관리 기능(빈도
  낮음). B는 즉시 가능한 저비용 수정.

## D. 후속 quest 제안
- 라우트 추가는 본 감사(DEV-161) 후속으로 분리 권장:
  - "server: 템플릿·첨부 HTTP 라우트 추가" (A-1/A-2)
  - "server: 타입 변경 + 타입/상태 CRUD HTTP 라우트" (A-3/A-4)
  - "server: snapshot 관련 stale 문서 갱신" (B) — 또는 본 quest에서 바로 처리.

*(본 리포트는 DEV-161 범위 = 코드 변경 없는 감사. 실제 라우트 구현은 후속 quest에서.)*

## 재감사 (2026-06-23 기준) — server HTTP API vs core ops

DEV-163/165 로 **server = host 전용**이 되어 "server CLI 가 core 를 못 따라감" 항목은 무의미해짐(서버 정비 CLI 자체가 없음). 남는 건 **HTTP API 가 core 기능을 노출하는가**(= 브라우저/원격 모드에서 가능한가) 뿐.

### 원 감사 이후 해소됨
- admin vacuum / journal tail / snapshot 삭제(DELETE /api/admin/snapshots/{ts}) HTTP 노출 (DEV-162/175).
- 댓글 discussion / resolved 토글 HTTP 노출.
- 정비 명령은 CLI(openguild …) + HTTP admin(/api/admin/*) 로 일원화 (DEV-165/166).

### 남은 HTTP API 갭 (데스크탑 Tauri invoke 로는 되지만 HTTP 엔 없음)
1. **types / statuses CRUD** — server 라우트에 GET(/api/quest-types, /api/quest-statuses)만 있고 create/update/delete/rename 라우트가 없음. frontend admin.ts 는 `/api/admin/types|statuses` 를 호출하므로 **브라우저 모드에서 404**. (desktop 은 invoke 로 동작.) tag-defs 는 /api/tag-defs 로 CRUD 노출됨 — 불일치.
2. **첨부(attachments)** — save_attachment / add·remove·list_quest|campaign_attachment 에 HTTP 라우트 없음(/api/guild-files/{*rel} 서빙만). DEV-156 에서 "Local 전용" 으로 의도된 것이라 브라우저 모드 첨부 관리는 미지원.
3. **check counters** — HTTP admin 에 없음(drift/reindex/vacuum/journal/snapshot/restore 만). CLI/Tauri 전용.

### 결정 필요
server=host 전용이므로 위 갭은 **브라우저/원격 모드**에서만 문제. (a) 데스크탑 전용으로 확정하고 문서화할지, (b) HTTP 파리티를 맞출지. 최소한 #1(types/statuses)은 frontend 가 이미 호출하는데 라우트가 없어 브라우저 모드가 깨지므로 — 라우트 추가 또는 브라우저 모드에서 admin 비활성화 중 택일 필요.

## 구현

### 1. `/api/search` 의 Tauri 경로 신설

- `gui/src/commands.rs` — `search_docs` 커맨드. 영역 파싱과 오타 거부를
  서버 핸들러(`meta::enhanced_search`)와 **같은 코드 모양**으로 맞췄다.
  두 경로가 다르게 굴면 그게 다음 버그다.
- `gui/src/lib.rs` 등록.
- `transport.ts` — `GET /api/search` → `search_docs`. `limit` 은 숫자로
  변환해서 넘긴다(문자열이면 Tauri 역직렬화가 그 자리에서 실패).
  `in` 은 Rust 예약어라 커맨드 쪽이 `r#in` 이지만 invoke 인자 이름은 `in`.

### 2. `LIST_QUERY_BOOLS` 에 두 키 추가

`search_comments` / `search_attachments`.

## 재발 방지 — 주석으로는 못 막았다

BUG-211 이 이 함정을 잡고 `transport.ts` 에 긴 주석까지 남겼는데도, REQ-010 이
필드를 추가하며 집합을 갱신하지 않아 **같은 방식으로 재발**했다. 주석은 읽을
때만 작동한다. 테스트로 묶었다.

`transport.test.ts` 에 4건:

- `/api/search` → `search_docs` 매핑, `in`/`limit` 전달, 없을 때 인자 생략
- **`LIST_QUERY_BOOLS` 가 `ListQuery` 의 bool 필드와 정확히 일치** —
  `core/src/models/quest.rs` 를 실제로 읽어 `pub X: bool` 을 뽑아 비교한다.
  Rust 쪽에 bool 필드를 추가하고 이 집합을 안 고치면 그 자리에서 깨진다.

수정 전 코드로 되돌려 **4건 모두 실패**하는 것을 확인했다.

## 검증

- `just test` 479건 통과 (기존 475 + 4).
- `cargo tauri build` 로 `.app` 빌드 → `/Applications/openguild.app` 교체
  (0.5.1-beta). 설치된 바이너리에 `search_docs` 문자열 존재 확인.
- **데스크톱 앱 안에서 실제 검색까지는 확인하지 못했다** — Tauri 웹뷰를
  외부에서 조작할 수단이 없다. 브라우저 경로(서버 모드)는 이전 커밋에서
  실측했고, 이번 변경은 그 경로를 건드리지 않는다.

## 부수 사항

- `.dmg` 번들링은 실패한다. 0.5.0 설치용 볼륨이 `/Volumes/openguild` 에
  마운트돼 있어 `bundle_dmg.sh` 가 같은 이름으로 만들려다 충돌한다.
  `.app` 은 정상이고 배포 dmg 는 CI 가 만든다.
- 앱이 **실행 중인 상태에서** 교체했다. 이미 열려 있던 프로세스는 지워진
  번들로 계속 돌므로, 새 코드를 보려면 앱을 껐다 켜야 한다.

# [cli] campaign update 명령 추가 — 제목/기간 변경

`openguild campaign` 에 제목/본문을 수정하는 명령이 없다. 서브커맨드는
new/list/show/history/start/end/link/unlink/delete/checklist/comment/attach/
memo 뿐이고, `update_campaign` 을 호출하는 CLI 경로는 `campaign_set_status`
(start/end 전용) 하나다.

core `ops::campaigns::update_campaign` 은 title/description/status/start/end 를
모두 받고 서버는 `PATCH /api/campaigns/{slug}`, GUI 는 `update_campaign`
커맨드로 이미 노출한다 — **CLI 만 빠져 있었다**(quest 는
`quest update --title/--description-file` 이 있어 비대칭).

`.guild` 프론트매터는 CLI 로만 수정한다는 규칙 때문에, GUI 없이 캠페인 이름을
고칠 방법이 아예 없었다. 실제로 C-005 제목이 초기 범위("DB 투영 불변식")에
묶여 있어 고쳐야 하는데 CLI 로는 불가능했다.

## 구현

- `CampaignCmd::Update { slug, --title, --description, --description-file,
  --start, --end }` — quest update 와 같은 옵션 규약(비ASCII 본문은 파일로).
- `Backend::campaign_update` — Http 는 기존 `campaign_update` 클라이언트
  메서드 재사용, Local 은 slug→id 해석 후 core ops 호출
  (`campaign_set_status` 와 같은 흐름).
- 아무 필드도 안 주면 **거부** — no-op 이 되어 "고쳤다고 착각"하기 쉬우므로.

## 실사용 검증

`campaign update C-005 --title "베타 0.5.0"` → `C-005 [active] 베타 0.5.0`
(다른 캠페인들과 같은 `베타 X.Y.Z` 규칙으로 통일). 필드 없이 호출하면
`nothing to update — one of --title / --description(-file) / --start / --end
is required` 로 거부.

## Test plan

1. `campaign update <slug> --title "새 제목"` → show 에 반영, `.guild` 파일
   프론트매터도 갱신됐는지.
2. `--description-file` 로 한글 본문 → 깨짐 없이 저장되는지.
3. `--start 2026-08-01 --end 2026-08-31` → 기간 반영.
4. 필드 없이 호출 → 에러(no-op 방지).
5. `--remote <URL>` 로 같은 명령 → 서버 경유로도 동일 결과.
6. 존재하지 않는 slug → 명확한 에러.

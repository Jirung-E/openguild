## 증상

UI 크기를 조절해도 검색 팔레트의 가로 폭이 그대로다. 안의 글자·칩만 커지고
상자는 고정이라 제목이 잘리고 발췌가 한 줄에 거의 안 들어간다.

## 원인

`.palette { width: min(560px, 62vw) }` — **px 고정**이라 배율(root font-size)을
따라가지 않는다. 62vw 는 뷰포트 기준이라 이것도 배율과 무관하다.

BUG-246 이 타이틀바의 px 를 rem 으로 옮겼는데 팔레트는 범위 밖이었다.

## 같은 부류로 함께 고친 것

전수 조사해 팔레트의 고정 px 를 전부 분류했다.

| 값 | 처리 |
|----|------|
| `width: min(560px, 62vw)` | → `min(35rem, 62vw)` **(보고된 건)** |
| `max-height: 340px` (목록) | → `21.25rem` — 세로도 같은 이유로 고정이었다 |
| `.dp-resize` 7px / 34×3px | → rem — 크기조절 핸들도 UI 요소다 |
| `mark` 의 `2px` / `0 1px` | → `var(--r-xs)` / rem (REQ-014 에서 내가 넣은 px) |

**px 로 남긴 것**

- `box-shadow: 0 10px 34px` — 그림자는 배율을 따라가지 않는 게 관례다.
- `@media (max-width: 640px) { width: calc(100vw - 16px) }` — 화면 가장자리
  여백이라 물리 치수가 맞다.

`35rem` / `21.25rem` 은 기본 배율에서 각각 560px / 340px — **기존 치수를 그대로
재현**한다(100% 에서 아무 변화 없음).

## 검증 (브라우저 실측)

**1920px 화면** — 배율에 정확히 비례한다.

| 배율 | 팔레트 폭 | 35rem 계산값 |
|------|----------|-------------|
| 0.5 | 280 | 280 |
| 1.0 | **560** | 560 |
| 1.5 | 840 | 840 |
| 2.0 | 1120 | 1120 |

**1280px 화면** — 560 → 793.6 으로 커지다가 `62vw`(793.6) 상한에 걸린다.
상한은 의도된 것이라 그대로 뒀다 — 좁은 화면에서 팔레트가 창을 거의 다
덮지 않게 하는 장치다.

목록 최대 높이도 340 → 510 → 680px 으로 따라간다.

`just test` 515건 통과, `check:no-hex` 통과.

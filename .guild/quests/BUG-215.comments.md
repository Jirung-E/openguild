수정 — 터치 기기(`pointer: coarse`)에서는 `basicSetup` 대신 `touchSetup()`.

`lib/utils/editor-setup.ts` 신규. CodeMirror 문서가 "basicSetup 은 import 와
배열 리터럴일 뿐이니 필요하면 복사해서 고쳐 쓰라" 고 안내하는 그대로, 복사본에서
아래만 뺐다:

- **`drawSelection()`** — 이 버그의 원인. 네이티브 선택/캐럿을 숨긴다.
- `dropCursor()` / `rectangularSelection()` / `crosshairCursor()` — 마우스 전용
  (드래그&드랍 위치 표시, Alt+드래그 사각 선택, Alt 커서). 터치에선 의미 없음.

줄 번호·접기·괄호 매칭·자동완성·들여쓰기·문법 강조·히스토리는 그대로 유지.
데스크톱 경로는 **손대지 않았다** — 기존 `basicSetup` 그대로다.

## 왜 "끼운 뒤 끄기" 가 안 되나

`drawSelection` 은 `EditorView.nativeSelectionHidden` 팩싯에 true 를 넣는데
combine 이 `values.some(x => x)` 다. 나중에 false 를 넣어도 true 가 이긴다.
게다가 이 팩싯은 public export 도 아니다. 그래서 처음부터 빼는 것 외엔 방법이
없다.

## 테스트

`editorSetup.test.ts` 3건 — 터치 구성엔 선택 레이어가 없고, basicSetup 엔
있으며(대조군), 터치 구성도 문서/거터가 정상. 팩싯을 직접 읽을 수 없어
**관측 가능한 결과(선택 레이어 유무)** 로 판정한다.

## 미검증

**실제 길게 누르기 제스처는 폰에서 확인 필요하다.** 여기서는 네이티브 선택이
살아 있는 조건(캐럿 색 복원 + 자체 레이어 부재)까지만 확인했다. OS 선택 핸들
동작은 실기가 아니면 재현할 수 없다.

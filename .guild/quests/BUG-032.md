## 수정 (2026-05-27)

### 1) 곧 시작 conveyor — fade mask 조건부
`-webkit-mask-image` (양 끝 fade) 가 marquee 가 안 돌고 있을 때도 적용되어
왼쪽 fade 가 카드 시작 부분을 가리는 거슬림. `.conveyor.marquee` 클래스
추가로 `needsMarquee=true` 일 때만 mask + grab 커서. 평소엔 깔끔.

### 2) 진행중 카드 남은기간 — 7일 임계값
`.remaining` 항상 빨강이라 한참 남은 캠페인도 시각 경보 → 피로. `now` 와
`ended_at` 비교해서 ≤ 7일이면 `.urgent` modifier (빨강), 그 외는 회색.
`upcoming` 모드의 `.accent` (파랑) 은 종전대로.

### 3) Date picker icon 검정 — 근본 해결
BUG-026 의 `filter:invert(0.85)` 가 일부 환경 (OS dark mode / WebView2
다크 렌더) 에서 native icon 이 흰색이라 invert 가 다시 검정으로 만들어
버림 (BUG-031 1차 분석 후에도 재발).

해결: filter invert 폐기. `input[type='date'] { color-scheme: dark }` 를
global 로 적용 — 환경 무관하게 native picker 가 dark theme 으로 렌더
되어 아이콘이 light 색으로 일관 표시. 컴포넌트별 color-scheme override
금지 (주석으로 안내).

### 4) Quest due 설정 안 됨 — Tauri 핸들러 누락
DEV-076 에서 server route `/api/quests/:id/due` 추가했지만 GUI 의 Tauri
transport invoke 매핑 누락. 일반 모드 (server) 는 동작했지만 데스크탑
앱은 fetch 가 invoke 로 라우팅되어 핸들러 없음 에러.

추가:
- `gui/frontend/src/lib/api/transport.ts` `routeToInvoke`: `sub === 'due'
  && method === 'PATCH'` → `set_quest_due_dates`.
- `gui/src/commands.rs::set_quest_due_dates` — server 의 route 와 동일
  contract (JSON 키 존재로 변경 의도 구분).
- `gui/src/lib.rs` invoke_handler 에 등록.

### 5) 우클릭 차단
Tauri 데스크탑 앱에서 웹 기본 우클릭 (Inspect / Reload / Back / Forward)
이 노출되어 데스크탑 답지 못함. `+layout.svelte` 의 `onMount` 에서
`detectEnvironment() === 'tauri'` 일 때만 `document.addEventListener
('contextmenu', e => e.preventDefault())`. 브라우저 dev 모드는 그대로.

### 6) 캠페인 버튼 배치
이미 BUG-031 에서 `.section-head` 안으로 이동 완료. 사용자 빌드 캐시
이슈로 미반영된 상태였던 듯 — 본 빌드에서 재확인 OK.

### 7) 본문 ↔ Sub-Quests 간격
description / no-desc 가 `<MarkdownView>` 직접 노출되어 다음 section
(Parent / Sub / Prereq) 과 거의 붙어 보임. `<div class="description-
block">` wrapper + `margin-bottom: 2rem`.

### 8) 곧 시작 conveyor 클릭 → 캠페인 이동
pointerdown 즉시 `setPointerCapture` 호출이 click 이벤트 흐름을 가로채
카드의 `onclick={open}` 이 발화 안 함. 임계값 (5px) 까지는 capture 안
하도록 변경 — pointermove 가 임계값 넘었을 때만 drag 로 확정 + capture.
순수 click 은 자연스럽게 카드까지 도달 → `goto(/campaigns/slug)` 정상.

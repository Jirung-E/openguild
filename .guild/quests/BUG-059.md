## 증상

사용자 보고: "GUI 켤 때 reindex 잘 안 되는 듯. '새로운 파일' 은 잘 감지하는데 '변경된 파일' 은 못 한다."

## 원인

`core/src/drift.rs:detect_drift` 가 시간 임계값으로 `index.db` 파일 mtime 을 사용:

```rust
let index_mtime = repo_fs::mtime(paths.index_db()).unwrap_or(...);
if file_mtime > index_mtime { fresh_files.push(slug); }
```

문제:
1. SQLite WAL 모드에서 `index.db` mtime 은 마지막 mutation 이 아니라 마지막 WAL checkpoint 시각. checkpoint 는 1000-page 임계 / 연결 close 등 휴리스틱.
2. `Store::open()` 시 sqlx 마이그레이션 체크 / 연결 셋업이 main `.db` 를 한 번 write 하는 경우 mtime 이 NOW 로 튐.
3. 결과: 사용자의 외부 편집 시각보다 `index.db` mtime 이 더 새것이 되어 `file_mtime > index_mtime` 이 false → 변경 감지 실패.

"새로운 파일" 은 mtime 무관하게 slug 집합 차집합 (`file_slugs - index_slugs`) 로 잡으므로 정확.

## 수정

`app_meta` 테이블 신설 + `last_indexed_at` ISO 타임스탬프 마커:

1. **migration 0014**: `app_meta(key, value)` 테이블 + `('last_indexed_at', '')` seed.
2. **reindex()**: transaction commit 직전에 `last_indexed_at = now_local_iso8601()` UPSERT.
3. **detect_drift()**: 마커를 SystemTime 으로 파싱해서 임계값으로 사용. 마커가 없거나 빈 값이면 기존 동작 (index.db mtime) 으로 fallback (legacy DB 호환).

마이그레이션이 backward-compat 이고 시간 비교만 변경되므로 ops 의 모든 mutation 경로를 건드릴 필요 없음. 트레이드오프: ops 활동 이후 첫 startup 은 false-positive drift 한 번 발생 → 추가 reindex (idempotent, 가벼움) 한 번 더 돌아감. 실 사용자 영향은 거의 없음.

## 테스트

`core/src/drift.rs::tests`:
- `drift_uses_last_indexed_at_marker_not_index_db_mtime` — 마커를 24h 전으로 set + 새 파일 작성 → fresh 에 잡힘.
- `drift_falls_back_when_marker_empty` — 빈 값 fallback panic 없음.

기존 8 + 신규 2 = 10 drift 테스트 모두 통과.
reindex 테스트 11개도 영향 없음.

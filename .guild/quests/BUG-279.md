## 증상

admin: *"deleted-audit을 활성화했는데, 실제로 퀘스트를 지우니까 플러그인이
자동으로 비활성화됨."*

허용한 플러그인이 **한 번 동작한 뒤 스스로 꺼진다.** 아무 오류도 안 난다.

## 원인 — 훅이 자기 지문을 밟는다

두 결정이 각각은 옳은데 겹치면 덫이 된다.

1. `run` 은 **플러그인 폴더를 작업 디렉터리로** 삼는다
   (`delivery.rs` 의 `.current_dir(&plugin.dir)`). `desktop-notify` 의
   `sh notify.sh` 처럼 옆 파일을 부르려면 그래야 한다.
2. 동의 지문은 **폴더 안의 모든 파일**을 본다([[DEV-381]]). `run` 이 실행하는
   옆 파일(`hook.py`)을 갈아끼우는 우회를 막으려고 그렇게 했다.

`deleted-audit` 은 `cat >> deleted.log` 다. 작업 디렉터리가 플러그인 폴더이므로
**로그가 플러그인 폴더 안에 생긴다.** 그 순간 폴더 지문이 바뀌고
`is_granted` 가 false 가 된다 — 훅이 자기 동의를 깬 것이다.

이건 예제 하나의 실수가 아니다. **출력을 옆에 쓰는 모든 `run` 플러그인이
같은 방식으로 스스로 꺼진다.** 게다가 조용하다: 한 번은 돌고, 그 다음부터
안 돈다.

## 2차 피해 — 동의 파일이 훅의 출력을 삼킨다

지문은 텍스트 파일을 **원문 그대로** 담는다(사용자가 무엇에 동의하는지 볼 수
있어야 하므로, 64KB 까지). 그래서 admin 의
`~/.openguild/plugin-consent.json` 안에 **지워진 퀘스트의 내용**이 들어가 있다:

```
deleted.log  '{"guild":"test-guild","id":"BUG-006","status":"open","title":"잉?",…
```

동의 파일이 있어야 할 이유가 없는 데이터를 들고 있고, 훅이 도는 만큼 계속
커진다.

## 수정 (admin 확정: 기계별 데이터 폴더)

**코드와 데이터를 가른다.** 정의·스크립트·옆 프로그램은 git 으로 따라오는
코드이고 지문의 대상이다. 훅이 만드는 것은 그 기계의 데이터다.

- 작업 디렉터리를 `~/.openguild/plugin-data/{길드}/{플러그인}/` 로 바꾼다.
  없으면 만든다. git 에 안 올라가고 지문과 완전히 분리된다.
- 코드 폴더는 `OPENGUILD_PLUGIN_DIR` 환경변수로 알려준다. `desktop-notify`
  처럼 옆 파일을 부르는 것은 그 값을 쓴다.
- 찾을 수 있어야 하므로 경로를 화면(설정 → 플러그인)과 `plugin list` 에 띄운다.

`post` 는 작업 디렉터리가 없으므로 영향 없다.

## 테스트 방법

- 폴더에 파일을 쓰는 `run` 훅을 허용하고 **두 번** 발화시킨다. 두 번째도
  돈다(예전에는 안 돌았다). 되돌리면 두 번째가 안 돈다.
- 훅이 만든 파일이 플러그인 폴더에 **안 생긴다**.
- 동의 지문이 훅 실행 전후로 **같다**.
- `OPENGUILD_PLUGIN_DIR` 가 코드 폴더를 가리킨다.
- 배포하는 예제 넷이 새 규칙으로 그대로 돈다.

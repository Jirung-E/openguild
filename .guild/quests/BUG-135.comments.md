수정 완료. 조사 중 진단이 한 단계 더 깊어짐:

**최종 원인**: run() 프레임이 아니라 **clap derive 가 생성한 Command 빌더 함수**였음. run() 을 핸들러로 분리한 뒤에도 여전히 터졌고, 프로브로 이분탐색한 결과 `Cli::command()` (clap Command 트리 빌드) 진입에서 overflow — 수백 개 Arg 빌더 체인의 임시값이 opt-level=0 (lifetime 마커 없음 → LLVM stack coloring 불가)에서 전부 합산되어 그 한 함수의 프레임이 1MB 를 넘김. 매크로 생성 코드라 함수 분리 불가.

**수정 2건**:
1. main() 이 run() 을 8MB 스택 스레드에서 실행 (rustc 자신도 쓰는 관용구) — 근본 해결.
2. run() 의 거대 match arm 11개(Types/Statuses/Template/Rules/Library/Worklog/Backup/Restore/MigrateToFiles/Info/Quest)를 handle_* 함수로 분리 — 기존 handle_campaign 패턴. run() 자체 프레임도 실제로 컸으므로(분리 전 probe 로 확인) 유지. 부수 효과로 1,560줄 단일 함수가 dispatch 만 남게 정리됨.

**검증**: debug 빌드 기본 스택(1MB)에서 --help / ping / quest list(--table/--json --compact 포함) 전부 정상. 전 테스트 스위트 + clippy 통과. release 도 정상.

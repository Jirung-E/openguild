| 그 이름의 세션이 | 띄우는 명령 |
|---|---|
| 없음 | `claude -n DEV-001` (새로 만듦) |
| 하나 | `claude -r <세션 id>` (이어서 열기) |
| 여럿 | `claude -r DEV-001` (claude가 그 이름으로 거른 고르기 목록) |

- 세션은 claude를 띄운 **폴더마다** 따로 모입니다. 설정 '세션 폴더'를 비우면 길드 폴더입니다.
- 이름은 세션 파일마다 마지막으로 붙은 이름(`custom-title`)을 봅니다.
- 설정: 명령 글(기본 `/session`), 명령 댓글 처리(막기 / 기록 한 줄), 세션 폴더.
- 터미널: 맥은 '터미널' 앱(처음 한 번 macOS가 제어 허용을 묻습니다), 리눅스는 x-terminal-emulator / gnome-terminal, 윈도우는 `wt.exe`가 있으면 그것, 없으면 파워셸 창입니다.
- scope는 gui · cli입니다. 서버에서 돌면 창이 서버 기계에 뜨기 때문입니다.

**확인한 것:**
- `claude 2.1.312`: `-n 이름`으로 이름을 붙이고, `-r 이름`으로 엽니다. `-p`(비대화) 모드에서 이름이 겹치면 "matches 2 sessions" 오류가 나고, 대화 모드는 그 이름으로 거른 고르기 목록을 띄웁니다. 다만 `-p`로 만든 시험 세션은 목록에 안 보여서, 여러 개일 때 목록에 실제로 뜨는 모습까지는 못 봤습니다.
- `open.sh` dry-run: 같은 이름 2개 → `claude -r 이름`, 1개 → `claude -r <id>`, 0개 → `claude -n 이름`.
- scratch 길드에 설치해 CLI로 `/session` 댓글:
  - 막기 모드: 댓글이 막히고 안내가 나옵니다.
  - 기록 모드: "터미널에서 `DEV-002` 세션을 열었습니다" 한 줄이 남습니다.

  - 가짜 `osascript`로 받아 보니 넘어온 명령은 `cd '<세션 폴더>' && claude -n DEV-002`였습니다.

- 윈도우 세션 폴더 이름 규칙(`C:\a\b` → `C--a-b`)도 확인하지 못했습니다.

**막혔을 때의 안내 — 방안**
1. **막고 안내(지금 기본):** 코어 변경이 없습니다. 하지만 앱에는 빨간 오류 안내가 뜨고 입력칸에 `/session`이 남습니다.
2. **기록 한 줄로 바꿔 남기기(지금 설정으로 고름):** 오류가 없고 언제 열었는지 기록이 남습니다. 대신 댓글이 쌓입니다.
3. **코어에 '처리됨' 답 추가(추천):** pre 함수가 `#{ handled: "..." }`를 돌려주면 변경은 하지 않되 **성공**으로 다룹니다.
   - 앱: 안내 토스트(파랑)를 띄우고 입력칸을 비웁니다.
   - CLI: 안내를 출력하고 exit 0으로 끝냅니다.
   - 서버: 200 + `handled`를 돌려줍니다.
   - 이 플러그인뿐 아니라 모든 '댓글 명령'에 쓰입니다.
4. **명령 단추:** 플러그인이 퀘스트 화면에 단추를 내놓는 새 기능입니다. 가장 깔끔하지만 가장 큽니다.

2. 필요하면 세션 폴더를 설정합니다.

## 맥 실제 실행 (임시 길드, 2026-10-31)

임시 길드의 DEV-001 에 `/session` 댓글(CLI) → "플러그인이 대신 처리했습니다 — 터미널에서 DEV-001 세션을 엽니다", 댓글은 안 남음.

- 터미널 앱에 새 창이 열리고 `cd '<길드 폴더>' && claude -n DEV-001` 이 돌았다(창 제목 `claude -n DEV-001`, claude 의 작업 폴더 = 길드 폴더).
- 처음 보는 폴더라 claude 의 "이 폴더를 믿습니까" 화면이 먼저 뜬다 — claude 쪽 동작이다.
- 확인 뒤 claude 를 끄고 창을 닫았다.

못 한 것: 이미 그 이름의 세션이 있을 때 `claude -r <id>` 로 이어 여는 경로. 그러려면 시험 폴더를 믿음 처리하고 세션에 실제로 말을 걸어야 해서 하지 않았다.

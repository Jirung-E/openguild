## 증상

첨부 '전체 다운로드' 를 눌렀는데 **파일이 하나만 저장된다**(브라우저 모드).

## 원인 (계측으로 확정)

우리 코드는 정상이다. `AttachmentSection.svelte` 의 `downloadAll()` 은
브라우저 모드에서 첨부마다 `<a download>` 를 만들어 200ms 간격으로 클릭한다.

첨부 3개짜리 퀘스트에서 anchor 클릭을 가로채 계측한 결과 **3건 모두 정확한
이름과 URL 로 시도**됐다:

```
seed-note.md  → /api/guild-files/attachments/seed-note-….md
preview.png   → /api/guild-files/attachments/preview-….png
config.json   → /api/guild-files/attachments/config-….json
```

즉 **브라우저가 같은 출처의 연속 자동 다운로드를 2번째부터 차단**하는 것이다
(Chrome 계열의 "여러 파일 다운로드" 정책 — 주소창에 허용 프롬프트가 뜨거나
조용히 막힌다). 지연을 늘려도 근본 해결이 안 된다.

Tauri(데스크톱) 모드는 폴더를 고른 뒤 `copy_guild_file` 로 직접 복사하므로
이 문제가 없다 — **브라우저 모드 한정**이다.

## 왜 차단되는가 — 우리가 자초한 구조 (추가 조사)

브라우저는 **사용자 제스처와 붙어 있는 다운로드**만 허용한다. 그런데 현재
루프는 파일마다 `await` 를 두 번 건다:

```js
for (const a of list) {
    browserDownload(await guildFileUrl(a.path), downloadName(a));
    await new Promise((r) => setTimeout(r, 200));
}
```

`guildFileUrl` 은 브라우저 모드에서 **실제로 기다리는 게 없다** — `isTauriLocal()`
분기를 지나 URL 문자열을 조립해 돌려줄 뿐이다(`utils/banner.ts:55~64`).
그런데도 `async` 라 `await` 가 걸리고, 여기에 200ms 타이머까지 더해져 2번째
파일부터는 제스처 컨텍스트에서 떨어져 나간다. 그 상태의 자동 다운로드가 바로
브라우저가 막는 대상이다.

즉 "브라우저 정책 때문에 어쩔 수 없다" 가 아니라, **우리 코드가 차단 조건을
만들고 있었다.**

## 수정 방향 (zip 은 채택하지 않음)

처음엔 서버 zip 스트리밍을 1순위로 적었으나 철회한다 — **사용자가 압축을 풀어야
한다**(사용자 지적). 파일 3개 받자고 압축 해제를 강요하는 건 퇴보이고, [[BUG-188]]
때문에 스트리밍 구현까지 필요해 비용도 가장 크다. 첨부가 수십 개일 때만 이득인데
그건 예외적 상황이다.

### 1순위 — 폴더 선택 후 직접 쓰기 (File System Access API)

`showDirectoryPicker()` 로 폴더를 받고 각 파일을 `createWritable()` 로 쓴다.
**데스크톱(Tauri) 경로와 똑같은 흐름**이 되어 코드 모양도 수렴한다.
압축 해제 없음, 권한 팝업 한 번, 파일명 그대로.

Chrome/Edge 지원. Safari/Firefox 미지원 → 아래 폴백.

### 2순위 폴백 — 제스처 안에서 한 번에 발사

URL 을 **미리 전부 계산해 두고**(브라우저 모드에선 동기로 가능), 클릭을
`await` 없이 연속 실행한다. 그러면 브라우저가 "여러 파일 다운로드" 를 **한 번**
묻고, 허용하면 N개가 그대로 받아진다. 폰(iOS Safari)에서 접속하는 경우가 이
경로를 탄다.

폴백에서도 안 되는 환경이 있으면, 개별 다운로드로 유도하는 안내를 띄운다.

## 테스트 방법

브라우저 모드(서버 접속)에서 첨부가 2개 이상인 퀘스트를 열고 '전체 다운로드'
를 누른다 — 첨부 개수만큼 파일이 저장되는지 확인. 데스크톱 앱에서도 폴더 선택
후 전부 복사되는지 회귀 확인.

## 수정 내용 (2026-08-21)

`AttachmentSection.svelte` 의 브라우저 경로를 `downloadAllInBrowser()` 로 분리.

### 공통 — URL 을 먼저 다 만든다

클릭 사이에 `await` 가 끼면 제스처가 끊긴다. `guildFileUrl` 을
`Promise.all` 로 **미리 전부 해결**한 뒤에야 저장을 시작한다.

### 1순위 — 폴더 선택 후 직접 쓰기

`showDirectoryPicker()` → 각 파일 `createFileHandle` + `createWritable`.
**데스크톱(Tauri) 경로와 같은 흐름**이라 압축 해제도, 다운로드 팝업도 없다.

`res.body.pipeTo(writable)` 로 **스트리밍**한다 — `arrayBuffer()` 로 받으면
[[BUG-188]] 의 1.5GB 첨부가 메모리에 통째로 올라간다. [[REQ-005]] 가 지적한
서버 측 버퍼링과 같은 함정을 클라이언트에서 반복하지 않는다.

폴더 선택 **취소(`AbortError`)는 오류가 아니다** — 조용히 끝낸다.

### 2순위 폴백 — 제스처 안에서 연속 발사

폴더 쓰기를 지원하지 않는 환경(Safari/iOS — 폰 접속이 이 경로)에서는
`await` 없이 앵커 클릭을 연속 실행한다. 그러면 브라우저가 허용을 **한 번**
묻고, 허용하면 전부 받아진다.

허용 프롬프트를 놓치면 여전히 1개만 받고 끝나므로 안내를 띄우되,
**"차단됐다" 고 단정하지 않는다** — 우리는 결과를 알 수 없고 대개는 정상
저장된다. 그래서 빨간 오류가 아니라 **info 토스트**로 알린다.

## 테스트 방법

1. 브라우저(Chrome/Edge)에서 첨부 2개 이상인 퀘스트 → '전체 다운로드' →
   폴더를 고르면 **첨부 개수만큼** 그 폴더에 저장되는지.
2. 폴더 선택을 취소했을 때 오류가 안 뜨는지.
3. Safari/iOS 에서 → 허용 프롬프트가 뜨고, 허용하면 전부 받아지는지.
4. **데스크톱 앱 회귀** — 폴더 선택 후 일괄 복사가 그대로 동작하는지
   (이 경로는 건드리지 않았다).

## 증상

첨부 '전체 다운로드' 를 눌렀는데 **파일이 하나만 저장된다**(브라우저 모드).

## 원인 (계측으로 확정)

우리 코드는 정상이다. `AttachmentSection.svelte` 의 `downloadAll()` 은
브라우저 모드에서 첨부마다 `<a download>` 를 만들어 200ms 간격으로 클릭한다.

첨부 3개짜리 퀘스트에서 anchor 클릭을 가로채 계측한 결과 **3건 모두 정확한
이름과 URL 로 시도**됐다:

```
seed-note.md  → /api/guild-files/attachments/seed-note-….md
preview.png   → /api/guild-files/attachments/preview-….png
config.json   → /api/guild-files/attachments/config-….json
```

즉 **브라우저가 같은 출처의 연속 자동 다운로드를 2번째부터 차단**하는 것이다
(Chrome 계열의 "여러 파일 다운로드" 정책 — 주소창에 허용 프롬프트가 뜨거나
조용히 막힌다). 지연을 늘려도 근본 해결이 안 된다.

Tauri(데스크톱) 모드는 폴더를 고른 뒤 `copy_guild_file` 로 직접 복사하므로
이 문제가 없다 — **브라우저 모드 한정**이다.

## 선택지

1. **서버에서 zip 스트리밍** (`GET /api/quests/{slug}/attachments.zip`)
   — 다운로드가 1건이라 브라우저 정책에 걸리지 않는다. 가장 깔끔한 UX.
   **주의**: [[BUG-188]] 의 1.5GB 첨부가 있으므로 zip 을 메모리에 만들면 안
   된다. 반드시 스트리밍(무압축 store 방식이면 CPU 도 아낀다).
   `REQ-005` 가 지적한 "대용량 첨부 전체 버퍼링" 과 같은 함정.
2. **여러 파일 다운로드 허용을 안내** — 첫 클릭 후 브라우저가 프롬프트를
   띄우므로 안내 문구만 추가. 구현은 싸지만 사용자가 매번 허용해야 한다.
3. **현상 유지 + 개별 다운로드 유도** — '전체 다운로드' 버튼을 브라우저
   모드에서 숨기거나 비활성화.

1번이 정답으로 보이나 서버 작업이 필요하다.

## 테스트 방법

브라우저 모드(서버 접속)에서 첨부가 2개 이상인 퀘스트를 열고 '전체 다운로드'
를 누른다 — 첨부 개수만큼 파일이 저장되는지 확인. 데스크톱 앱에서도 폴더 선택
후 전부 복사되는지 회귀 확인.

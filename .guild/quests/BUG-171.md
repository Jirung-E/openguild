릴리즈 페이지의 릴리스 노트가 두 번씩 표시된다.

## 실제 본문 (v0.4.1-beta, GitHub API 로 확인)

```
**Full Changelog**: https://github.com/Jirung-E/openguild/compare/v0.4.0-beta...v0.4.1-beta

**Full Changelog**: https://github.com/Jirung-E/openguild/compare/v0.4.0-beta...v0.4.1-beta
```

본문 184자 전체가 이 두 줄이다.

## 원인

`release.yml` 의 `Create GitHub Release`(softprops/action-gh-release@v2) 단계가
**windows 잡과 linux 잡 양쪽에** 있고, 둘 다 `generate_release_notes: true` 다.
같은 태그를 대상으로 하므로:

1. 먼저 끝난 잡이 릴리스를 만들고 자동 생성 노트를 본문에 넣는다.
2. 나중 잡이 같은 릴리스를 갱신하면서 다시 노트를 생성한다. 액션 문서:
   *"If body is specified, the body will be pre-pended to the automatically
   generated notes."* — 기존 본문이 body 가 되어 새로 생성된 노트 **앞에**
   붙는다 → 같은 내용이 2개.

잡이 늘어나면 그 수만큼 늘어난다(macOS 추가 시 3개).

## 함께 드러난 문제 — CHANGELOG 가 릴리스 페이지에 아예 없다

자동 생성 노트에는 PR 목록만 들어가는데 이 저장소는 PR 없이 직접 커밋하므로
compare 링크 한 줄만 남는다. `CHANGELOG.md` 에 정리한 0.4.1 절(Fixed 13건)이
릴리스 페이지에는 전혀 표시되지 않았다.

## 수정 방향

`generate_release_notes` 를 버리고 **CHANGELOG.md 의 해당 버전 절을 본문으로**
명시한다(`body_path`). 본문을 명시하면 나중 잡이 같은 내용으로 덮어쓰므로
(append_body 기본 false) 잡 순서와 무관하게 항상 1개다 — 잡 구조를 바꾸지
않고 중복이 사라지고, 릴리스 페이지에 실제 변경 내역이 표시된다.

추출은 pwsh 스크립트 하나로 두 잡에서 공용(ubuntu 러너에도 pwsh 있음) —
OS 별로 로직을 두 번 쓰지 않는다. compare 링크는 CHANGELOG 의 직전 버전
헤딩에서 이전 태그를 얻어 스크립트가 직접 붙인다.

## 수정 내용

- `scripts/extract-release-notes.ps1` 신설 — 태그(`vX.Y.Z`)에 맞는 CHANGELOG
  `## X.Y.Z` 절을 뽑아 파일로 쓰고, 직전 버전 헤딩에서 이전 태그를 얻어
  `**Full Changelog**` compare 링크를 붙인다. 절이 없거나 비면 throw(가드).
- `release.yml` 의 두 잡 모두 `generate_release_notes` 를 버리고
  `body_path: release-notes.md` + `append_body: false`. 나중 잡이 같은 내용으로
  덮어쓰므로 실행 순서와 무관하게 본문은 항상 하나.
- `release-process` 규칙에 자동화 사실과 가드(태그 전 CHANGELOG 절 필수,
  `generate_release_notes` 금지) 명시.
- ubuntu 러너에도 pwsh 가 있어 두 잡이 스크립트 하나를 공용한다.

### 로컬 검증 (v0.4.1-beta 로 실행)

- 추출 결과 1565자, 이전 버전 `0.4.0-beta` 자동 인식, compare 링크 정상.
- 추출 본문과 CHANGELOG 0.4.1 절이 **완전 일치**(diff 무차이, compare 링크만
  추가됨).
- 도중에 두 가지 실제 버그를 잡았다:
  - `Get-Content` 가 Windows PowerShell 5.1 에서 ANSI 코드페이지로 읽어 한글이
    깨졌다 → `[IO.File]::ReadAllLines(..., UTF8Encoding($false))` 로 명시.
    (CI 는 pwsh 7 이라 안 드러났을 문제)
  - `[IO.Path]::GetFullPath(a, b)` 2-인자 오버로드는 .NET Framework(5.1)에
    없다 → 직접 rooted 판정.
  - 스크립트는 기존 `seed-test-data.ps1` 과 같이 **BOM 있는 UTF-8** 로 저장
    (BOM 없으면 5.1 이 한글 주석을 깨뜨려 파싱 자체가 실패).

## Test plan

CI 는 태그를 밀어야 실행되므로 다음 릴리스(0.5.0) 때 확인:

1. 릴리스 페이지 본문에 CHANGELOG 해당 절이 **한 번만** 나오는지.
2. 본문 끝에 compare 링크가 한 줄 있는지(이전 태그가 맞는지).
3. 한글이 깨지지 않는지(pwsh 7 + BOM 없는 출력).
4. windows/linux 잡의 완료 순서가 바뀌어도 결과가 같은지(재실행으로 확인).
5. (가드) CHANGELOG 절 없이 태그를 밀면 릴리스 잡이 실패하는지 —
   의도된 동작. dry-run 이 필요하면 `workflow_dispatch` 는 릴리스 단계를
   건너뛰므로 태그 없이는 검증되지 않는다는 점 유의.

## 배경

BUG-056 에서 ConfirmDialog 컴포넌트 도입 + 댓글/규칙/캠페인/체크리스트 삭제 4건을 인앱 모달로 전환. 하지만 남은 `window.confirm()` / `confirm()` 호출들은 그대로였음.

Tauri WebView 의 native confirm 은 환경에 따라 silent return — 사용자가 클릭 한 번에 destructive 동작이 실행됨.

## 수정 범위

| 위치 | 종류 | 위험도 |
|---|---|---|
| `AdminStatusesSection.svelte` | slug rename cascade | 높음 — 모든 quest frontmatter + history cascade |
| `AdminTypesSection.svelte` | prefix rename cascade | 높음 — 파일명 + slug + DB history cascade |
| `routes/admin/+page.svelte` (`onRestore`) | backup 복원 | 높음 — `.guild/` 덮어쓰기 |
| `routes/rules/+page.svelte` (`select`) | 편집중 다른 slug 선택 | 중간 — 미저장 작업 손실 |

## 제외

- `routes/admin/+page.svelte` (`onReindex`) — 사용자 지시 (idempotent, 파일 truth 불변).

## 패턴

각 사이트마다:
1. `confirmXxx` state 추가 (객체 또는 null).
2. 원래 호출 지점은 state 만 set 하고 return.
3. `ConfirmDialog` 인스턴스를 컴포넌트 최하단에 mount.
4. `onconfirm` 콜백이 실제 작업 함수 (e.g. `doSaveEdit`, `doRestore`, `applyPendingSelect`) 호출.

기존 inline 삭제 모달 (AdminStatuses/Types 의 confirmDelete) 은 sweep 대상 아님 — 이미 동작.

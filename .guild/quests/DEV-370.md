## 배경

퀘스트/캠페인 상세 페이지 상단의 '뒤로' 버튼은, 타이틀바에 앞/뒤 네비게이션
버튼이 생기기 전에 브라우저의 뒤로가기를 대신하려고 둔 것이다. 이제 타이틀바가
그 일을 하므로 같은 기능이 두 벌이다.

## 할 일

- 상세 페이지의 '뒤로' 버튼을 없앤다.
- 그 자리에 있던 여백·정렬이 무너지지 않는지 확인한다(제목 줄의 좌측 정렬이
  버튼 폭을 전제하고 있을 수 있다).
- 웹(브라우저)에서 여는 경우에는 타이틀바가 없다 — 브라우저 자체의 뒤로가기가
  있으므로 문제없지만, **자식 창**처럼 타이틀바도 브라우저 크롬도 없는 화면이
  있는지 확인하고, 있다면 그 경우만 남길지 판단할 것.

## 확인 대상

- `routes/quests/[id]/+page.svelte`
- `routes/campaigns/[slug]/+page.svelte`
- 그 밖에 같은 '뒤로' 를 두고 있는 상세 화면(규칙/도서관 문서 등)

## 정한 것 (admin)

자식 창에서는 **타이틀바 앞/뒤 버튼을 노출**한다. 상세 페이지의 '뒤로' 는
양쪽 모두 제거.

## 한 것

- 퀘스트 상세 / 캠페인 상세의 '뒤로' 버튼 제거. 죽은 `.back` CSS 와 더 이상
  안 쓰는 `isChildWindow` import 도 함께 정리.
- `TitleBar`: 자식 창에서 통째로 숨기던 `.tb-left` 를 풀고, **홈과 ☰메뉴만**
  숨긴다. 앞/뒤는 항상 보인다.
- `goBack()` 은 남긴다 — **삭제 후 복귀**가 계속 쓰고, 그쪽은 `?from=`
  fallback 이 필요하다([[BUG-015]] / [[DEV-011]]).

## DEV-255 의 전제가 반만 맞았다

DEV-255 는 "자식 창은 다른 곳으로 이동할 일이 없다" 며 앞/뒤까지 숨겼다.
문서 안의 cross-link 를 타고 들어가는 경로가 있으므로 절반만 맞다. 지금까지는
상세 페이지의 '뒤로' 가 그 구멍을 메우고 있었는데, 그것을 없애면 자식 창에
돌아갈 수단이 하나도 안 남는다. 그래서 앞/뒤만 되살렸다 — 홈과 ☰메뉴는
여전히 숨긴다(단일 문서 창을 목록이나 다른 길드로 데려가는 것은 그 창의
목적이 아니다).

## 정렬 — 실제로 깨지는 자리였다

퀘스트 상세의 `.top-bar` 는 `justify-content: space-between` 으로 왼쪽 '뒤로'
와 오른쪽 편집/삭제를 양끝에 붙이고 있었다. 자식이 하나만 남으면
space-between 은 그것을 **왼쪽에** 놓는다 — `flex-end` 로 명시했다. 편집
모드처럼 자식이 아예 없을 때 줄이 사라져 제목이 위로 튀지 않도록 `min-height`
도 함께 뒀다.

캠페인 상세는 `.top-actions` 에 이미 `margin-left: auto` 가 있어 그대로 맞다.

## 검증 (미리보기 1400×900)

- 퀘스트 상세: '뒤로' 0개, `.top-bar` 오른쪽(1076)과 편집/삭제 오른쪽(1076)이
  일치 — 오른쪽 정렬.
- 캠페인 상세: '뒤로' 0개, 상태 pill 이 왼쪽 끝(284), 액션이 오른쪽 끝(1116).
- 페이지 전체에 `←` 로 시작하는 버튼이 없다.

**못 본 것**: 자식 창의 타이틀바. `TitleBar` 는 Tauri 전용이라 미리보기에서
렌더되지 않는다. 검색 팔레트의 "새 창으로 열기" 로 문서를 띄워, 홈·☰ 없이
앞/뒤만 보이는지 확인이 필요하다.

## 함께 발견 — 캠페인 **생성** 화면의 '뒤로'

`routes/campaigns/new/+page.svelte:53` 에 `← 뒤로` 가 남아 있다. 이 퀘스트의
범위(상세 페이지)는 아니고, 생성 폼에서는 '취소' 성격이라 남길 이유도 있다.
다만 그 라벨은 **i18n 을 안 거치고 한국어가 하드코딩**돼 있다(`t()` 미사용).
별건으로 판단이 필요하다.

## 후속 (admin 요청) — 빈 줄을 없애고 편집/삭제를 slug pill 줄로

'뒤로' 를 없애자 위쪽 한 줄에 버튼만 남았다. 그 줄(`.top-bar`)을 통째로 없애고
편집/삭제를 **slug pill 과 같은 줄**(`.header`) 오른쪽 끝으로 내렸다.

- `.header` 에 `align-items: center` — pill 은 글자 높이, 버튼은 패딩이 붙어
  더 크므로 세로 중앙을 맞춰야 나란해 보인다.
- `.top-actions` 는 `margin-left: auto` 로 오른쪽 끝. `.header` 가
  `flex-wrap: wrap` 이라 좁은 화면에서 버튼이 다음 줄로 내려가도 오른쪽에
  붙는다.
- `.header` 에 `min-height: 2rem`. 편집 모드로 들어가면 버튼이 사라져 줄이
  6px 낮아지고 아래가 통째로 위로 튄다(실측 32 → 26). 예전 `.top-bar` 가
  min-height 로 잡아 주던 것을 그대로 옮긴 것이다.

### 검증

| 화면 | 결과 |
|------|------|
| 1400×900 | pill 과 버튼이 같은 줄, 버튼 오른쪽 끝 1076 = header 오른쪽 끝 |
| 560×900 | 여전히 한 줄, 넘침 없음 |
| 375×812 | pill 줄 / 버튼 줄로 나뉘고 버튼은 오른쪽 정렬, 가로 넘침 없음 |
| 편집 모드 | 버튼이 사라져도 header 높이 32 그대로 — 아래가 안 튄다 |

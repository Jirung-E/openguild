증상 1: `openguild rule new <slug>` 를 --file/--empty 없이 실행하면 CLI 가
멈춤(hang) — 안내 없이 stdin 대기.

원인: `read_content()` 공용 헬퍼(comment add / memo set / rules set·create
가 전부 사용)가 --file 없으면 무조건 stdin 을 blocking read 하는데, stdin
이 파이프/리다이렉트 없는 터미널(tty)이면 사용자가 뭘 기다리는지 안내가
전혀 없었음. 이미 DEV-186("댓글 add UX — tty 안내")에 문서화된 문제의
연장선 — rule new 도 같은 공용 헬퍼를 쓰므로 동일 증상.

증상 2: `rule create` 가 canonical 이라 `rule --help` 에 new 대신 create
로 표시됨. quest/campaign/template/backup 은 전부 `new` 가 canonical인데
rules 만 반대였음.

## 수정
- `read_content()`: stdin 이 tty 면 즉시 에러(사용법 안내 + --file/--empty
  제안) — comment add/memo set/rules set·create 전부 한 번에 해결.
- RulesCmd::Create: `#[command(alias = "new")]` (create canonical) ->
  `#[command(name = "new", alias = "create")]` (new canonical) 로 스왑.
- docs/AGENTS_OPENGUILD_USAGE.md, docs/USAGE.md, scripts/seed-test-data.ps1
  의 예시를 `rule new` 로 갱신.

DEV-186 은 이 중 (a) tty 안내만 해결 — (b) -m/--message 인라인 옵션은
아직 미구현으로 계속 Open.

## 테스트 방법
- `echo | openguild rule new test-slug` 또는 파이프 없이 실행 시 즉시
  에러 메시지(멈추지 않음).
- `openguild rule --help` → New 가 표시(create 는 alias 로만 동작).
- `openguild rule create foo --empty` 도 여전히 동작(하위호환).
- `cargo test -p openguild-cli` 통과.

구현 완료 — 증분 동기화가 신규/삭제/관계변경까지 직접 처리한다.

## 변경 (core/src/incremental.rs)
- **db_map 에서 soft-delete 필터 제거.** `deleted_at IS NULL` 로 걸러서 삭제된 퀘스트의 파일(진리원이라 그대로 남는다)이 매번 "신규 파일"로 보였고, INSERT 시 `UNIQUE(quest_type_id, number)` 충돌로 skip → full fallback. 실측 6건(BUG-062/174/175, DEV-301/303/304)이 이 경로였다 — 현실에서 fallback 을 부르던 주범.
- **신규 파일**: fallback 대신 `insert_new_quest()` 로 직접 INSERT.
- **삭제된 파일**: `DELETE FROM quests WHERE id = ?` + `report.deleted`.
- **수정된 파일**: 선행/태그 변경도 `resync_quest_relations()` 로 그 퀘스트만 재동기화(예전엔 수정 하나만 있어도 full).
- **2-pass**: 서로를 참조하는 신규 파일들 때문에 (1) 전부 INSERT → (2) 관계 재동기화 순서로 처리.
- 타입·상태 정의가 없어 해석 불가한 파일은 그대로 full reindex 로 넘긴다(안전망 유지).

## 측정 (릴리스 빌드, 퀘스트 651개 길드, `core/examples/bench_open.rs`)
- 이전: **4,123ms** (needs_full=true → 전체 재색인)
- 이후: **18ms** (`skipped=0 needs_full=false`, full reindex 생략)
- 신규+수정 파일이 섞인 상태: 31ms
- 실제 삭제 3건 반영: `deleted=3 needs_full=false`, 59ms (파일 3개 삭제 후 재확인 `✓ no drift`)

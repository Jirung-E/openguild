## 무엇이 잘못됐나

CLI 로 `plugin add` · `plugin allow` 까지 했는데 **앱에서 보면 추가가 안 되어 있다**(admin).

## 짚이는 두 가지

**1. 앱이 시동 때 읽은 것을 들고 있다.** 앱과 서버는 시작할 때 한 번 적재하고 그대로 쓴다.
CLI 는 매번 다시 읽으니 CLI 에서는 보이고 앱에서는 안 보인다. 고치는 길은 이미 있다 —
관리자 → 플러그인 → **다시 읽기**. 하지만 **사용자가 그걸 알 도리가 없다**. 화면에 아무
신호가 없으니 "안 됐다" 로 보인다.

**2. 길드 경로가 다르게 적힌다.** 어느 길드에서 쓰는지는 **경로를 열쇠로** 기록한다
(`guild_key` = 정규화한 절대 경로). CLI 가 적은 열쇠와 앱이 찾는 열쇠가 다르면 목록이
비어 보인다. 맥에서는 `/tmp` ↔ `/private/tmp`, 윈도우에서는 드라이브 문자 대소문자나
짧은 경로(`C:\PROGRA~1`)가 갈릴 수 있다. `canonicalize` 가 대부분 맞춰 주지만 **윈도우에서
확인한 적이 없다**.

동의(`plugin-consent.json`)는 이름을 열쇠로 쓰니 이 문제와 무관하다 — 그래서 "허용은 됐는데
목록에 없다" 가 될 수 있다.

## 먼저 할 일 — 어느 쪽인지 가른다

```
openguild plugin list            # CLI 에서 보이나
type %USERPROFILE%\.openguild\plugin-sources.json     # used 의 열쇠가 어떤 모양인가
```

그 열쇠와 앱이 연 길드 경로가 **글자까지 같은지** 본다. 다르면 2번, 같으면 1번이다.

## 고칠 방향

- **1번이면** — 정의·목록이 바뀐 것을 앱이 알아채고 "다시 읽기" 를 권하거나, 화면을 열 때
  스스로 다시 읽는다. 지금은 사용자가 알 길이 없는 것이 문제다.
- **2번이면** — 열쇠를 경로 글자에 기대지 않게 한다. 길드에는 이미 `.guild` 파일이 있으니
  거기 붙는 안정된 식별자를 쓰는 쪽이 맞다.

## 테스트 방법

- CLI 로 `add` + `allow` 한 뒤 앱을 열면 목록에 있다(또는 "다시 읽기" 안내가 보인다).
- 같은 길드를 다른 모양의 경로로 열어도(`/tmp` 대 `/private/tmp`, 대소문자 다른 드라이브)
  같은 길드로 잡힌다.

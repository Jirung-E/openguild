## 조사 결과 (2026-07-15, 수정 없음 — 코드 읽기만)

### 0. 사용자 보고의 직접 원인

"Reindex 알림이 업데이트 확인 알림과 모양/위치가 다름":
- 업데이트 확인 알림(UpdateBanner) = **우하단** 카드 (border-left 강조, z 60)
- Reindex 알림(admin 페이지 로컬 토스트) = **우상단** 박스 (z 1000)
- 앱의 명목상 표준(ToastHost) = **우상단** 스택 (z 2000)

즉 3개가 전부 다른 구현·다른 위치. admin 은 ToastHost 를 안 쓰고 자체
복제본을 렌더하므로 ToastHost 를 고쳐도 admin 엔 반영 안 됨 — "저번에
통일하라고 했는데 재발"의 구조적 원인.

### 3. 부수 발견

- `admin/+page.svelte:168` — Reindex 확인이 **네이티브 `confirm()`**.
  단 27행 주석에 "reindex 는 사용자 지시로 sweep 제외 (DEV-119)" 라고
  명시돼 있음 — 과거 결정이므로 이번에 바꿀지는 별도 확인 필요.
- Reindex 성공 시 토스트 표시 800ms 후 `window.location.reload()` — 토스트가
  읽기도 전에 리로드로 끊김. 통일 시 함께 재검토 권장.
- 네이티브 `confirm()` 은 위 1곳 제외 전부 인앱 ConfirmDialog 로 이미 정리됨
  (DEV-119/BUG-123). 확인 다이얼로그 쪽은 문제 없음.

### 4. 통일 방안 (제안 — 착수 전 결정 1개 필요)

**결정 필요: 표준을 어디에 둘 것인가.** 원 보고 문구가 "업데이트 확인 알림
*처럼* 표시되어야" 였음 — 즉 기준이 UpdateBanner(우하단 카드)라면:
- (A안) ToastHost 를 우하단 카드 스타일로 개편 + admin 로컬 구현 제거
  → showToast() 로 흡수 + alert() 17곳 치환. 모든 단발 알림이 우하단으로 통일.
- (B안) 표준은 기존 ToastHost(우상단) 유지, admin 만 showToast() 로 이관
  + alert() 치환. UpdateBanner/SchemaAheadBanner 는 "행동 필요·상태 유지형"
  이라 단발 toast 와 다른 부류로 그대로 둠 (버튼·진행률·릴리즈노트 때문에
  toast 큐로 흡수 불가).

어느 쪽이든 공통 작업: admin 의 showSuccess/showError/showInfo →
showToast() 치환(onmessage 흐름 유지 가능, 시그니처 거의 동일해 기계적),
로컬 마크업/CSS 40여 줄 삭제, alert() 17곳 치환 + fallback i18n 키 추가.
예상 규모: 파일 6개, 순수 치환 위주 — 세션 1회 분량.

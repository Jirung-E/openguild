## 배경

현재 Quest List (`/?view=list`) 는 부모 quest 아래로 자식이 폴드된 트리
형태. 트리 형태는 관계 파악에 좋지만:
- 평면 정렬 (urgency / created_at 등 기준) 이 어색 — 부모 단위로만 정렬됨.
- 검색 결과를 평면으로 보고 싶을 때 트리 강제.

## 제안

View mode 토글:
- **Tree** (현재 기본): 부모 > 자식 들여쓰기 + 폴드.
- **List** (신규): 모든 quest (parent 무관) 평면. 부모 정보는 별도 컬럼 표시.

UI:
- List header 에 view-mode toggle 버튼 (트리 / 리스트 아이콘).
- URL 매핑: `?view=list&mode=tree` vs `?view=list&mode=list`.
  - 기존 `?view=list` 는 `mode=tree` default.
- localStorage 로 마지막 선택 기억.

## 구현 스케치

### Frontend
- `lib/components/QuestList.svelte` 에 `mode: 'tree' | 'list'` $state.
- $derived: tree 모드는 기존 폴드 로직, list 모드는 단순 flat map.
- toggle 버튼 = 두 아이콘 (e.g. lucide tree / lucide list).
- 정렬 기준 (DEV-033 합쳐) 은 두 모드 다 동일하게 적용 가능 — list 모드
  에선 더 자연스러움.

### Backend 무변동
- list 모드는 기존 `list_quests` 결과 그대로. 트리 모드만 클라이언트 측
  부모 그룹핑.

## 검증
- Tree 모드: 기존 동작 그대로.
- List 모드: 모든 quest 평면. urgency 정렬 시 부모/자식 무관 정상 정렬.
- toggle 즉시 반영. URL 갱신 + 뒤로가기로 모드 복원.
- localStorage 마지막 선택 기억 → 다음 방문 시 그 모드로.

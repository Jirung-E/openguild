# [gui] 타이틀바 검색 팔레트 옆에 '최근 본 문서' 버튼 추가

사용자 요청: 검색 팔레트 옆에 "지금 열려있는 탭" 버튼 추가.

## 범위 확정 (사용자 확인)

앱에 탭 개념이 없고 "새 창으로 열기"(자식윈도우, DEV-255)만 있어 해석이
갈려 확인한 결과 → **현재 창에서 최근 방문한 문서 목록**(브라우저 '최근
탭' 식)으로 확정. 뒤로가기는 한 칸씩만 가므로 "아까 그 문서"로 바로
점프하는 수단이 없었다.

## 구현

- **`stores/recentDocs.ts` 신규** — 방문 기록 store.
  - 추적 대상은 **문서 성격 라우트만**: 퀘스트/캠페인 상세, 규칙
    (`?slug=`), 도서관(`?id=`). 목록/보드/설정/관리 등 탐색 화면은 제외
    (다시 찾아갈 일이 적어 노이즈). 판별은 순수 함수
    `classifyDocRoute(href)` — 규칙/도서관은 쿼리로 대상을 고르는 구조라
    경로만으론 판별 불가해 쿼리까지 파싱한다.
  - 재방문은 새로 쌓지 않고 **맨 앞으로 승격**, 상한 12개.
  - 영속은 **sessionStorage** — "지금 보고 있는 세션의 최근"이라는 의미에
    맞고 앱 재시작 시 초기화되는 게 자연스럽다(길드 recents 와 별개).
    손상된 값은 필드 단위 방어 후 빈 목록으로 폴백.
- **`+layout.svelte`** 에서 `afterNavigate`/`onMount` 로 기록. 제목 보강은
  실측 결과 **`document.title` 이 대부분 비어 있어**(퀘스트 상세 포함)
  화면의 `main h1` 을 우선 읽고 document.title 은 폴백. 본문은 라우트
  전환 직후 아직 로드 전이라 150ms×10 회 짧게 재시도하되, 그 사이 라우트가
  바뀌면 중단(엉뚱한 제목이 붙지 않게). 실패해도 라벨(DEV-001 등)만으로
  목록은 성립.
- **UI 2곳** — 데스크탑은 TitleBar 검색 pill 옆 시계 버튼(pill 이 absolute
  중앙이라 `.tb-center` wrapper 로 묶어 나란히), 웹은 타이틀바 자체가 없어
  Nav 우측(DEV-271 이 검색 버튼에 쓴 것과 같은 fallback 규칙). 드롭다운
  항목은 종류 칩 + 식별자 + 제목, 바깥 클릭/라우트 이동 시 닫힘.
  기록이 없으면 버튼 자체를 숨김.
- 자식창(단일 문서 보기)에서는 기록하지 않음.

## 테스트 방법 (1·2 실기 확인 완료)

1. 웹 모드에서 퀘스트 2건을 순서대로 방문 → 최근 목록이 최신순으로 쌓이고
   제목이 h1 로 보강되는지, 버튼/드롭다운이 렌더되는지, 항목 클릭 시 이동 +
   자동 닫힘 확인 완료.
2. `recentDocs.test.ts` 9건(라우트 분류 3, store 6) + 전체 297건 통과,
   `svelte-check`/`build` 클린.
3. (사용자 확인) 데스크탑 앱에서 타이틀바 검색 pill 옆에 버튼이 자연스럽게
   붙는지(중앙 정렬 유지), 규칙/도서관 문서도 기록되는지 확인.

**정한 것(2026-10-27, admin "다 진행해라" — 제가 정하고 진행합니다. 바꿀 것이 있으면 말씀해 주세요).** 구현은 DEV-458.

- **줄 모양** — `pre` / `post` 대신 `every` 를 적는다. 거르기는 [[REQ-039]] 의 쿼리 문법 그대로(`query`), 대상은 `of`(기본 `quest`, `campaign` · `library`).

      [[handlers]]
          id    = "마감 알림"
          every = "1h"                                  # 분 m · 시간 h · 하루 d, 최소 1m
          query = "status:open,in_progress due:overdue"
          call  = "마감_알림"                           # fn 마감_알림(e) — e.items 가 맞는 목록

  - 맞는 것이 없으면 함수를 부르지 않는다. `action` 줄이면 본문이 이벤트 JSON(목록 포함)이다.
  - `when` · `with` · `wait` · `group` · 순서는 안 쓴다. 거르기는 `query` 가 하고, 한 줄씩 따로 돈다.
  - 쿼리는 **불러올 때** 해석해 오타를 그때 알린다 — 화면 · CLI 와 같은 오류 문장.
- **누가 시간을 재나** — 앱(`gui`)과 서버(`server`)만. CLI 는 명령이 끝나면 꺼지므로 안 돈다. `scope` 에 둘 다 없으면 `plugin check` 가 경고한다.
- **두 번 도는 문제** — 이 기계의 플러그인 데이터 폴더에 줄마다 마지막으로 돈 시각을 적고, 파일 잠금으로 한 번만 돈다. 같은 기계에서 앱과 서버가 같은 길드를 열어도 한 번이다. 다른 기계는 각자 돈다 — 동의가 기계마다인 것과 같다.
- **언제** — 30초마다 확인한다.
  - 기록이 없으면(처음 허용) 곧 한 번 돈다. 그 뒤로는 `every` 마다.
  - 앱이 꺼져 있던 동안 놓친 것은 켜질 때 **한 번만** 돈다(쌓아 두었다가 여러 번 돌지 않는다).
- **받는 것** — 함수는 `fn 이름(e)` 하나를 받는다. 다른 줄과 같은 모양이다.
  - `e.event` 는 `"every"`, `e.items` 는 맞는 목록, `e.count` 는 개수. `e.line` · `e.every` · `e.query` · `e.of` 도 실린다.
  - 목록의 한 건은 짧은 요약이다:
    - 퀘스트: id · title · status · type · urgency · tags · due · updated_at · comment_count
    - 캠페인: id · title · status · start · end
    - 도서관: id · title · folder · tags · updated_at
- **시험** — `plugin test` 에 `tick("줄 id", 목록)`. 그 줄을 주어진 목록으로 돌려 `fire` 와 같은 결과를 돌려준다(길드 없이).

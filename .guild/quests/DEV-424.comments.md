만들었습니다 — `ComposeDock` 한 곳에서 받아 댓글 · 답글 · 메모(퀘스트 · 캠페인)가 다 됩니다.

- **Ctrl+Enter**, 맥은 **⌘Enter** 도. Shift · Alt 를 섞은 것은 아니다(`utils/submit-shortcut.ts`).
- **한글 조합 중인 Enter 는 안 보낸다** — `isComposing` 이나 `keyCode 229`(조합 중을 알리는 옛 방식)면 거른다.
- `onsubmit` 이 없는 자리는 아무 일도 없고, `submitDisabled`(빈 글 · 저장 중)면 단추처럼 안 간다.
- **편집기(M↓)에서도** — CodeMirror 는 자기 keymap 이 Mod-Enter 에 '빈 줄 넣기' 를 걸어 두어서, 편집기 안의 키는 내려가기 전에(capture) 받는다. 일반 입력칸은 올라올 때 받는다 — 위키 링크 후보(`[[`)가 떠 있으면 Enter 는 후보 고르기 몫이라 그쪽이 먼저 가져간다.
- 툴팁: 글자 단추(댓글 추가 · 답글 추가 · 메모 저장)에 "단축키: Ctrl+Enter"(맥 ⌘Enter), 팝업의 동그란 보내기 단추는 "+ 댓글 추가 (Ctrl+Enter)". 동그란 단추에 `aria-keyshortcuts`.

확인
- 시험: 키 판정 4(조합 중 · Shift/Alt · 맥/윈도우 이름), 입력칸 6(Ctrl/⌘ · 그냥 Enter · 조합 중 · 보낼 수 없음 · 보내기 없는 자리 · 위키 후보가 가져감 · 툴팁), 편집기 1(보내고 빈 줄이 안 생김 — capture 를 빼면 실패하는 것도 확인).
- 웹 빌드 + 시험 길드 서버, WebKit 과 Chromium(윈도우 UA): 입력칸 Ctrl+Enter · ⌘Enter → 달리고 칸이 비워짐 / 그냥 Enter → 줄바꿈만 / 빈 칸 Ctrl+Enter → 안 감 / 편집기 Ctrl+Enter → 달리고 끝에 빈 줄 없음 / 답글 Ctrl+Enter → 그 댓글에 답글 / 메모 편집기 Ctrl+Enter → 저장되고 편집이 닫힘. 툴팁은 WebKit(맥) "⌘Enter", Chromium(윈도우) "Ctrl+Enter".

## 테스트 방법

1. 퀘스트 댓글 칸에 글을 쓰고 Ctrl+Enter(맥은 ⌘Enter) → 바로 달린다. 그냥 Enter 는 줄만 바뀐다.
2. **한글로 쓰다가 마지막 글자가 조합 중일 때** Ctrl+Enter → 마지막 글자까지 들어간 댓글이 달려야 한다(글자가 빠진 채 달리면 안 됨). 입력기에 따라 첫 번째는 글자 확정만 되고 한 번 더 눌러야 달릴 수 있다.
3. [M↓] 로 편집기를 켜고 같은 것 → 달리고, 편집기에 빈 줄이 안 남는다. 답글 · 메모 편집도 같다.
4. '댓글 추가' 단추에 마우스를 올리면 "단축키: Ctrl+Enter" 가 보인다.

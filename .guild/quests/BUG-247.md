## 증상

데스크톱 앱(Tauri)에서 강화 검색이 동작하지 않는다. 브라우저(서버 모드)에서는
정상이다.

## 원인 — 두 가지, 둘 다 데스크톱 전용

`transport.ts` 가 HTTP 경로를 Tauri `invoke` 로 옮기는데, REQ-009 의 범위가
**core / server / cli** 였고 그 배선이 빠졌다.

### 1. `/api/search` 에 매핑된 invoke 핸들러가 없다

`routeToInvoke` 에 `/api/search` 항목이 없고, `gui/src/commands.rs` 에도
대응 커맨드가 없다. 그래서 호출 즉시 에러:

```
TauriTransport: GET /api/search 에 매핑된 invoke 핸들러 없음.
```

영향: 도서관 첨부 이름 검색([[REQ-011]]), 검색 팔레트 넓게 토글([[REQ-012]]).
규칙 검색([[REQ-013]])은 목록 응답만 쓰므로 영향 없다.

### 2. `search_comments` / `search_attachments` 가 bool 로 변환되지 않는다

`LIST_QUERY_BOOLS` 에 두 키가 없어 문자열 `"true"` 로 넘어간다. HTTP 경로는
`Query<ListQuery>`(serde_urlencoded)가 알아서 강제 변환하지만 Tauri 경로는
JSON 역직렬화라 그 자리에서 실패한다:

```
invalid type: string "true", expected a boolean
```

**BUG-211 과 정확히 같은 함정**이다 — 그 주석이 바로 위에 달려 있는데도
필드를 추가하며 이 집합을 갱신하지 않아 재발했다.

영향: 퀘스트 목록의 '댓글 포함' / '첨부 이름 포함'([[REQ-010]]).

## 수정 방침

- `gui/src/commands.rs` 에 `search_docs` 커맨드 + `lib.rs` 등록,
  `transport.ts` 에 `/api/search` 라우트. 서버 핸들러(`enhanced_search`)의
  영역 파싱·오타 거부 동작을 그대로 맞춘다.
- `LIST_QUERY_BOOLS` 에 두 키 추가.
- **재발 방지**: `ListQuery` 의 bool 필드와 `LIST_QUERY_BOOLS` 가 어긋나면
  깨지는 테스트를 붙인다. 주석만으로는 두 번째 재발을 못 막았다.

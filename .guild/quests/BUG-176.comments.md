## 원인 확정 (코드 확인)

리다이렉트 때문이 아니다. **URL 에 길드 정보가 없어서**다.

흐름을 따라가면:

1. A 길드 보드 = `/`
2. 타이틀바 로고 버튼 → `goto('/welcome')` (push) → 히스토리 `[/ , /welcome]`
3. 웰컴에서 B 선택 → `invoke('open_guild_in_current_window')` 로 **Rust Store 를
   B 로 교체** → `goto('/')` (push) → 히스토리 `[/ , /welcome , /]`

뒤로가기를 누르면 `/welcome` → 한 번 더 누르면 `/` 인데, 이 `/` 는 A 시절의
항목이지만 **URL 이 똑같은 `/`** 이고 백엔드 Store 는 이미 B 다. 그래서 A 가
아니라 B 보드가 그려진다 — 사용자가 본 `B → Welcome → B` 와 정확히 일치한다.

즉 "뒤로가기로 이전 길드" 는 현재 모델에서 **성립하지 않는다**. 길드 정체성이
URL/히스토리에 전혀 실려 있지 않고, 열려 있는 길드는 프로세스 전역 상태 하나뿐이다.

## 선택지 (사용자 결정 필요)

**A. 뒤로가기가 실제로 이전 길드로 돌아가게 한다**
- `goto('/', { state: { guildPath } })` 로 히스토리 항목에 길드 경로를 심고,
  보드 진입 시 `current_guild_path` 와 다르면 그 길드를 다시 연다.
- 기대대로 동작하지만, 뒤로가기 한 번이 **길드 재오픈(무거운 작업)** 을
  유발한다. 경로가 사라졌거나 열기 실패 시 처리도 필요하고, 원격 길드와
  섞이면 규칙이 더 복잡해진다.

**B. 잘못된 화면을 보여주지 않게만 한다 (보수적)**
- 히스토리 항목에 길드 경로를 심는 것까지는 같되, 다르면 **웰컴으로 보낸다**
  (또는 "이 화면은 다른 길드의 기록입니다" 안내).
- 뒤로가기로 길드가 바뀌지는 않지만, **B 를 A 인 것처럼 보는 오해가 사라진다.**
- 구현/위험 모두 작다.

**C. 길드 전환을 히스토리에 남기지 않는다**
- 웰컴에서 길드를 열 때 `goto('/', { replaceState: true })` — 최소 변경.
- 다만 A 시절의 `/` 항목은 여전히 남아 같은 오해가 가능하다(완전한 해결 아님).

## 권고

**B** 를 기본으로 하고, 원하시면 A 를 후속으로 분리하는 것을 권합니다 —
뒤로가기가 무거운 상태 전환을 일으키는 건 예측하기 어렵고, 실패 경로(경로
삭제/권한)를 사용자가 뒤로가기 도중에 만나게 되는 것도 좋지 않습니다.

어느 쪽으로 갈지 알려주시면 이어서 구현하겠습니다.

## 후속 수정 — 웰컴에서 뒤로가기 깜빡임 (사용자 지적)

첫 구현은 `afterNavigate` 에서 되돌렸다. 그러면 **이전 길드 화면이 한 프레임
그려진 뒤** 웰컴으로 돌아온다 — 깜빡임이자, 애초에 안 보여주려던 그 화면을
잠깐 보여주는 셈이다.

사용자 제안("웰컴으로 돌아오면 아예 히스토리를 비우는 게 낫지 않냐")은
브라우저 API 로는 불가능하다(뒤로 스택을 지우는 수단이 없다). 대신 같은
체감을 만든다:

**웰컴에 있는 동안은 뒤로가기를 렌더 전에 취소한다** (`beforeNavigate` +
`nav.cancel()`).

- 웰컴에서의 뒤로가기가 갈 곳은 결국 이전 길드의 항목뿐이고, 그 항목은 URL 에
  길드 정보가 없어 지금 열린 길드가 그려진다 — 이 버그의 본체다. 그러니
  막는 것이 곧 올바른 동작이고, 길드 선택은 웰컴에서 명시적으로 한다.
- 판정은 **동기**여야 한다(`guildSwitchingPossible()`). 비동기로 판단하면
  이미 렌더가 시작돼 깜빡임이 남는다 — 첫 구현이 그랬다.
- 데스크탑(Tauri)에서만 — 브라우저 배포는 길드 전환 자체가 없어 뒤로가기를
  막을 이유가 없다.

`afterNavigate` 의 표식/판정은 안전망으로 남겨둔다(앞으로가기 등 웰컴을
거치지 않는 경로).

## 실기 검증 (브라우저)

게이트를 임시로 풀고 SvelteKit 링크 클릭으로 실제 SPA 이동을 만들어 측정:

| 단계 | 경로 | 화면 |
|---|---|---|
| 시작 | `/library` | 도서관 |
| 웰컴으로 SPA 이동 | `/welcome` | Welcome |
| **뒤로가기** | **`/welcome`** | **Welcome (그대로)** |

다른 화면이 한 프레임도 그려지지 않았다 — 깜빡임 없음.

게이트를 복구한 뒤 브라우저 모드 회귀도 확인: 같은 절차에서 뒤로가기가
`/library` 로 정상 이동(가드 비활성이 의도대로).

주의: 합성 `PopStateEvent` 로는 검증되지 않는다 — URL 만 바뀌고 SvelteKit
라우팅은 일어나지 않아 가드가 아예 타지 않는다. 앱 내 `<a>` 클릭으로
실제 네비게이션을 만들어야 한다(처음에 이걸로 잘못된 음성 결과를 봤다).

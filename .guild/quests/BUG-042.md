## 증상

사용자: "GUI 에서 퀘스트가 안 보여서 reindex 를 시도해보니 에러"

```
reindex 실패: Error: internal error: error returned from database:
  (code: 787) FOREIGN KEY constraint failed
```

CLI / server 도 동일 — `openguild-server reindex` 가 같은 FK 787.

## 원인

`core/src/reindex.rs` 의 quest INSERT 는 `.guild/quests/*.md` 의 **파일 정렬 순**
으로 i=0,1,2,... id 부여. parent_quest_id 는 `frontmatter.parent` slug → 새 id
매핑.

문제: parent 가 자기 자신보다 뒤에 INSERT 될 quest 인 경우 (예: `DEV-001.md`
의 `parent = "DEV-094"` 일 때 — DEV-094 가 i=93 정도). DEV-001 INSERT 시점에
DEV-094 row 가 아직 없는데 sqlx 가 sqlite 의 `PRAGMA foreign_keys = ON` 을
default 로 켜놓아 즉시 FK 검증 → **787 패닉**.

sqlx 의 connection options 이 자동으로 `foreign_keys = ON` 을 설정한다는 게
사일런트로 기여 (`sqlx-sqlite-0.8.6/options/mod.rs:185`).

## 수정

`reindex` 의 transaction 시작 직후 `PRAGMA defer_foreign_keys = 1` 적용.
SQLite 3.6.19+ 의 기능 — FK 검증을 transaction commit 시점까지 미룸. 같은 tx
안에서 INSERT 순서가 어떻든 commit 시 일관성만 맞으면 통과.

```rust
let mut tx = pool.begin().await?;
sqlx::query("PRAGMA defer_foreign_keys = 1")
    .execute(&mut *tx)
    .await?;
// ... 기존 DELETE / INSERT 들 ...
tx.commit().await?;
```

이 PRAGMA 는 **transaction 범위** — commit 후 자동 해제, 다른 connection /
transaction 에 영향 X.

## 검증

같은 DB 에서:
- 수정 전: `openguild-server reindex` → FK 787 panic.
- 수정 후: `openguild-server reindex` →
  ```
  ✓ index.db 재구축 완료
    types        : 3
    statuses     : 7
    quests       : 139
    dependencies : 41
    positions    : 130 복원
  ```

GUI 의 reindex 버튼도 같은 core 함수 호출 — 자동 작동.

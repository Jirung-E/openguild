원인 1 수정 — `routes/rules/+page.svelte`, `routes/library/+page.svelte`:

`loadList()` 에 `mutated` 인자를 추가하고 `loadQuestIndex(mutated)` 로 바꿨다.
이 함수는 마운트 시에도, 생성/삭제/이름변경 후에도 호출되는데 이전엔 구분 없이
`force=true` 라 페이지 진입마다 memo 를 무시하고 4종을 통째로 다시 받았다.
마운트 경로는 이제 memo 되는 `loadQuestIndex()` 를 타고, 실제 변경이 있었던
호출부(생성/삭제/이름변경, 각 4곳)만 `true` 를 넘긴다. 저장/제목변경 직후의
직접 `loadQuestIndex(true)` 호출은 진짜 변경이므로 그대로 뒀다.

## 남은 몫 — 원인 2 로 이어짐

목록 페이지 왕복(/?view=list ↔ /rules)은 아직 16회에 9.14MB / +37.1MB,
`/api/quests` 8회(= 목록 진입마다 1회, 1.13MB). 이건 인덱스가 아니라
**목록/보드/홈 페이지가 자기 데이터로 퀘스트 전량을 매번 받는** 것이라
성격이 다르다. description 은 목록 렌더에 쓰이지 않으므로 경량 응답
(원인 2)으로 같이 해결된다. 잔여 보존 재측정은 그 뒤에 하는 게 맞다.

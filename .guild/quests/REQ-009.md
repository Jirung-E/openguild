## 요청

댓글 / 첨부파일 이름 / 메모 내용 등도 검색할 수 있는 **강화된 검색**.

**기본 검색을 바꾸는 것이 아니라 추가 기능**이다 — 지금의 빠르고 예측 가능한
동작은 그대로 두고, 더 넓게 훑고 싶을 때 쓰는 별도 경로를 만든다.

## 현재 검색이 보는 범위 (조사 완료)

| 경로 | 대상 |
|------|------|
| 서버/CLI `quest search` (`core/src/services/quests.rs:161~179`) | title + description + slug. 공백 split AND, 각 토큰이 셋 중 하나에 `LIKE` |
| 검색 팔레트 (`SearchPalette.svelte`) | 전체 목록을 클라이언트에 적재 후 label/title/tags 필터 |

즉 **댓글·메모·첨부 이름은 어디서도 검색되지 않는다.**

## 대상별 준비 상태 — 여기가 설계의 핵심

같은 "검색 대상" 이라도 데이터가 있는 곳이 제각각이다.

| 대상 | index.db 캐시 | 비고 |
|------|--------------|------|
| 퀘스트 본문/제목 | `quests.title/description` | 이미 검색됨 |
| **댓글** | `quest_comments.body` / `campaign_comments.body` | ✅ 캐시 있음 — 바로 가능 |
| **메모** | `quest_memos.content` | ✅ 캐시 있음. **단, 아래 "비공개" 주의** |
| 도서관 | `library_docs.body` | ✅ |
| **첨부 이름** | ❌ **없음** | 사이드카 `{slug}.attachments.json` 뿐. `attachment_blobs` 는 [[BUG-188]] 로 **폐기**(0029) |
| 규칙 | ❌ 없음 | 전체가 파일 직독 (`file-truth-db-cache` §4) |

### ⚠️ 메모는 비공개 데이터다

`.guild/.gitignore` 가 `quests/*.memo.md` 를 제외한다 — 메모는 **공유되지 않는
개인 기록**이다. 검색 결과에 섞이면:

- 화면 공유 / 데모 중에 사적인 메모가 노출될 수 있다.
- 원격(서버) 모드에서는 **다른 사람의 로컬 메모가 아니라 호스트의 메모**가
  나간다 — 인증이 없는 현재 구조에서는 더 민감하다.

**기본 포함이 아니라 명시적 opt-in**(예: `--include-memo` / 결과 필터 토글)이
맞아 보인다. 결정 필요.

## 제안 방향

1. **별도 진입점** — 기본 검색은 그대로. 예:
   - CLI: `openguild search <query> [--in comments,memo,attachments,rules,library]`
   - HTTP: `GET /api/search?q=…&in=…`
   - 팔레트: 별도 모드(접두 `all:` 같은 것) 또는 "더 넓게 검색" 액션
2. **첨부 이름 검색은 캐시가 필요**하다. 선택지:
   - (a) 사이드카 JSON 을 조회 시점에 스캔 — 문서 수만큼 파일 I/O
   - (b) `attachment_index` 캐시 테이블 신설 + reindex 투영 + 쓰기 시점 증분
     갱신 — [[REQ-008]] 의 `doc_links` 와 **완전히 같은 패턴**이라 그대로 따라갈
     수 있다(BOOK-001 단방향 유지, 언제 지워도 reindex 로 재구축).
   - **이름만** 색인한다 — 파일 내용은 색인하지 않는다(BUG-188 의 대용량 첨부).
3. **결과에 출처를 표시**한다. "어디서 맞았는지"(본문/댓글/메모/첨부)를 안
   보여주면 왜 이 문서가 나왔는지 알 수 없다.

## 결정이 필요한 사항

1. 메모 포함 정책 — 기본 제외 + opt-in 이 맞는가?
2. 첨부 이름 — 캐시 신설(b) 대 조회 시 스캔(a)?
3. 진입점 — CLI/HTTP/팔레트 중 어디까지 이번 범위인가?
4. 매칭 방식 — 지금처럼 `LIKE` 유지인가, SQLite FTS5 도입인가?
   (FTS5 는 한국어 형태소 없이도 부분일치가 까다로워 `LIKE` 유지가 무난할 수
   있다. 다만 대상이 늘면 성능 차이가 생긴다.)

## 테스트 방법

1. 댓글에만 있는 단어로 검색 → 그 퀘스트가 나오고, 출처가 "댓글" 로 표시되는지.
2. 첨부 파일 이름으로 검색 → 해당 문서가 나오는지.
3. 메모에만 있는 단어 → **기본 검색에서는 안 나오고**, opt-in 했을 때만 나오는지.
4. 기존 검색 회귀 — title/description/slug 검색 결과가 이전과 동일한지.

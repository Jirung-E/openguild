admin 보고/요청:
1. 작업기록 페이지 주/월/구간 뷰에서 각 메모의 일자가 링크로 표시되고
   있는데 그럴 필요 없음 — 그냥 텍스트로.
2. 규칙/작업기록 페이지에서 날짜/규칙 선택 시 뒤로가기/앞으로가기가
   제대로 동작하지 않음: PageA→Rule1(기본표시)→Rule2→Rule3 이동 후
   Rule3에서 뒤로가기→Rule2(정상), Rule2에서 다시 뒤로가기→Rule1이 아니라
   Rule2에 머무름(한 단계가 씹힘), 그 다음 뒤로가기에야 PageA로 이동.
   (작업기록의 날짜 선택도 동일 증상.) 이전에 "날짜 선택은 뒤로가기 영향
   안 받게" 요청했던 것을 번복 — 이제 뒤로가기/앞으로가기가 선택을
   단계적으로 정확히 되짚도록 구현.

## 원인
`rules/+page.svelte`/`worklog/+page.svelte` 모두 slug/date 파라미터 없이
진입(nav 링크, PageA→Rules/Worklog 첫 진입)하면 onMount 가 entries[0]/오늘을
컴포넌트 state 로만 자동 선택하고 URL 에는 반영하지 않았음. 이후 사용자가
여러 규칙/날짜를 선택할 때마다(BUG-120 이후) pushState 로 새 history
entry 가 쌓이는데, 최초 진입 지점(slug/date 없는 bare URL)은 여전히
"선택 없음" 상태로 history 에 박제돼 있었다.

`$page.url` 을 구독하는 $effect 는 slug/date 가 **있을 때만** 반응하도록
짜여 있어서(없으면 무시), 뒤로가기로 이 bare 진입 지점에 돌아와도
selectedSlug/anchor 를 리셋하지 않고 직전 값에 그대로 머물렀다 — 그래서
"한 단계 씹힌 것처럼" 보였음(실제로는 history 이동은 됐지만 화면이 안
따라감).

## 수정
- onMount 에서 자동 선택 직후, 그 상태를 URL 에 `replaceState` 로 명시
  기록(진입 지점 자체가 항상 URL == 상태가 되도록).
- `$effect` 가 slug/date 가 사라진 경우도 처리하도록 확장 — 첫 규칙/오늘로
  리셋.
- worklog 주/월/구간 뷰의 메모 날짜를 `<button>`(링크) → `<span>`(텍스트)로.

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`.
- 실기: 규칙 페이지에서 규칙 3개를 순서대로 선택 후 브라우저/앱 뒤로가기를
  3번 눌러 PageA까지 한 단계씩 정확히 되짚어가는지. 작업기록도 날짜
  3개 선택 후 동일하게 확인. 주/월/구간 뷰의 메모 날짜가 더 이상 클릭
  가능한 링크로 안 보이는지.

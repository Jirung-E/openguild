## 왜 스크립트가 필요한가

JSON 만으로는 **"어떤 이벤트를 보낼지"** 와 **"어떤 모양으로 보낼지"** 를
표현할 수 없다. "미해결 토론 댓글만 AI 에 보낸다" 같은 것이 실제 요구다.
여기서 조건 문법을 발명하기 시작하면 결국 DSL 을 만들게 된다.

## 왜 rhai 인가 (JS 를 접었다)

이 저장소에 JS 런타임이 없다(확인함). CLI 에서도 돌리려면 3개 바이너리에
새로 넣어야 하고, **AI 를 부르려면 스크립트에 네트워크를 줘야 하니 샌드박스가
무의미해진다** — 셸과 위험이 같아지면서 엔진 값만 치른다.

rhai 는 순수 Rust 인터프리터라 core 에 넣어도 이질적이지 않다. 결정적으로
**I/O 를 안 줘도 된다.**

## 핵심 제약 — rhai 에 I/O 를 주지 않는다

```
rhai        판단·가공만. 파일도 네트워크도 없다. 순수 함수.
코어        내보내기(post/run)를 담당.
```

이 분리가 이 설계의 전부다. 스크립트가 폭주해도 밖으로 못 나간다. 네트워크가
필요한 순간 코어의 액션으로 넘긴다.

이벤트에는 `phase`(pre|post)와 `ok`/`error` 가 실려 오므로([[DEV-374]])
"성공한 것만", "실패했을 때만", "생기기 직전에" 같은 판단이 전부 스크립트
몫이 된다. 코어는 조건 문법을 하나도 정의하지 않아도 된다.

```rhai
// transform.rhai
fn should_send(event) {
    event.name == "comment.added" && event.ok && event.comment.discussion
}
fn payload(event) {
    #{ text: `[${event.quest.id}] ${event.comment.author}: ${event.comment.body}` }
}
```

## 정해야 할 것

- **폭주 방지** — 무한 루프를 막을 연산 상한 / 시간 제한. rhai 가 지원하는
  범위를 확인해 반드시 건다. 안 걸면 스크립트 하나가 CLI 를 멈춘다.
- **오류 처리** — 스크립트가 던지면 그 이벤트만 건너뛴다. 길드 동작에 영향
  없어야 한다.
- **바이너리 크기** — 3개 바이너리에 들어간다. 현재 CLI 16MB / 서버 13MB.
  **넣기 전과 후를 실측**하고, 감당 못 할 수준이면 이 서브퀘스트를 재검토한다
  (계약과 배선은 rhai 없이도 성립하므로 되돌릴 수 있다).

## 테스트 방법

- `should_send` 가 false 면 액션이 호출되지 않는다.
- `payload` 가 만든 모양이 그대로 전달된다.
- 스크립트가 던져도 다른 플러그인과 길드 동작이 멀쩡하다.
- **무한 루프가 상한에 걸려 멈춘다** — 이게 안 되면 넣으면 안 된다.
- 스크립트에서 파일/네트워크 접근이 **불가능**하다(샌드박스 확인).
- 바이너리 크기 증가분 기록.

## 결과

`core/src/plugins/script.rs` — 적재 때 컴파일하고(`Plugin.compiled`) 전달
스레드에서 이벤트마다 돌린다. 순서는 **판단 → 가공 → 전달** 이고, 셋 다
mutation 이 지나간 뒤다.

### 바이너리 크기 — 약 **+3.0 MB / 바이너리**

| | 넣기 전 | 넣은 뒤 | |
|---|---|---|---|
| CLI (`openguild`) | 16.37 MB | 19.35 MB | **+3.0 MB (+18.2%)** |
| 서버 (`openguild-server`) | 13.47 MB | 16.43 MB | **+3.0 MB (+22.0%)** |

admin 이 "크기 무관하게 진행" 으로 확정했으므로 재검토는 하지 않는다. 다만
**측정에 함정이 하나 있었다**: 의존성만 추가하고 바이너리에서 아무도 부르지
않으면 링커가 통째로 걷어내 **증가분이 0 으로 보인다.** 위 숫자는 각 main 에
`Script::compile_source` 를 임시로 도달 가능하게 만들고 잰 것이다. 뒤집어
말하면 **[[DEV-377]] 이 배선하기 전까지 실제 배포물은 안 커진다.**

부수 비용도 하나 있었다. rhai 가 `Add<_> for String` 구현을 하나 더 들고
오면서 `cli/src/main.rs` 의 `String + &String` 추론이 모호해져 컴파일이
깨졌다. `as_str()` 로 못 박았다 — 라이브러리 하나가 워크스페이스 전체의 추론에
영향을 준다는 점은 기억해 둘 만하다.

### 샌드박스는 두 겹

`no_module` 로 `import` 를 **컴파일 단계에서** 없앴다(기본 모듈 해석기는
디스크를 읽는다). 그 위에 엔진에는 아무 함수도 등록하지 않았다 — 파일도
프로세스도 소켓도 이름이 없다. 시험이 양쪽을 다 붙들고 있다.

### 폭주 방지도 두 겹

`set_max_operations(500,000)` 과 `on_progress` 벽시계 상한(2초). 하나면
그것이 틀렸을 때 막을 게 없다. 되돌림 시험에서 **둘 다 빼면 테스트가 영원히
돈다** — 45초에 강제 종료했다.

### 계획에 없던 것 — 동의 지문에 스크립트 원문을 넣었다

`plugin.json` 은 그대로 두고 `transform.rhai` 만 고치면 **보내는 내용이 통째로
바뀐다.** 스크립트에 I/O 는 없지만 이미 동의한 목적지로 무엇을 실어 보낼지는
정할 수 있다 — [[DEV-375]] 의 동의가 정의만 보면 그 구멍으로 빠져나간다.
둘을 함께 지문에 넣었다. `script` 경로가 플러그인 폴더를 벗어나는 것도 막는다.

### 되돌림 시험 5건 전부 물었다

`should_send` 결과 무시(1건 실패) · 상한 둘 다 제거(영원히 돎) · 지문에서
스크립트 제외(1) · 경로 탈출 검사 제거(1) · `no_module` 제거(1).

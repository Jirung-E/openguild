## 증상

퀘스트 상세에서 글자를 드래그하면 선택 색(파랑)이 **본문 상자를 넘어 창 양
끝까지** 뻗는다(admin 보고).

## WebKit 전용이다

admin 실측: **크롬(Whale)에서는 정상**, 사파리와 데스크톱 앱(WKWebView)에서
재현. 브라우저 엔진 차이다.

계측기를 실제 상세 페이지에 붙여 보니 `getClientRects()` 는 **폭 780** 이라고
하는데 화면은 창 전체(1512)가 파랬다. 즉 Range 의 기하가 아니라 **칠하는
방식**의 문제다.

WebKit 은 여러 블록에 걸친 선택에서 문단 사이 빈 공간까지 칠하고(selection
gap), 그 폭을 **가장 가까운 selection root** 로 잡는다. 판정은 대략
`문서 루트 / out-of-flow / float / overflow 가 visible 이 아님 / flex·grid
아이템 / 테이블 셀`. 본문 카드(`.md`)는 배경·테두리·패딩만 있어 어디에도 안
걸리므로, 조상을 타고 올라가 결국 `main`(창 전체)이 기준이 됐다.

크롬은 이 gap 칠하기를 오래전에 좁혀서 증상이 없다.

## 후보를 눈으로 골랐다

코드로 재는 값에는 안 잡히므로(위 780 vs 1512) 실험 페이지를 만들어 사파리에서
직접 확인했다. 내용이 같고 감싸기만 다른 상자 셋:

| | | 결과 |
|---|---|---|
| A | 지금 코드 | 넘침 |
| B | `overflow: hidden` | **가둬짐** |
| C | `contain: paint` | **가둬짐** |

## C 를 골랐다

`overflow: hidden` 도 듣지만 본문 카드가 **스크롤 컨테이너**가 된다.
`scrollIntoView` 는 가장 가까운 스크롤 조상을 움직이므로, 페이지 내
검색([[REQ-018]])의 다음/이전 이동과 댓글 딥링크([[BUG-258]])가 페이지 대신
**카드 안**을 스크롤하게 된다. `contain: paint` 는 칠하기만 가두고 스크롤
구조를 안 건드린다.

자손 중 밖으로 나가야 하는 것이 없음을 확인했다:

- `.md` 안에 absolute / fixed 자손 없음
- 넓은 코드블록은 `pre` 가 자체 `overflow-x: auto` 로 스크롤
- 링크 미리보기 팝업은 `.md` **바깥**에 렌더된다

`MarkdownView` 는 퀘스트·캠페인 상세, 댓글, 규칙, 도서관이 전부 공유하므로
한 곳 수정으로 모두 적용된다.

## 남는 경우

이 수정은 **본문 상자 안**의 선택을 가둔다. 제목부터 본문까지 걸쳐 드래그하면
여전히 창 폭으로 번진다 — 그걸 잡으려면 `.container` 를 같은 방식으로 가둬야
하는데, 거기엔 `position: absolute` 인 연관 퀘스트 메뉴(`.rel-menu`)가 있어
잘린다. 필요하면 별도 퀘스트로 다룬다.

## 검증

admin 이 사파리에서 실제 상세 페이지로 확인 — 정상.
frontend 655 pass, `npm run check` 0 errors, 가드 6종 통과.

자동 테스트는 두지 않았다. 이 증상은 **칠해진 픽셀**로만 드러나고
(`getClientRects()` 는 정상값을 준다) 엔진별로 다르다 — jsdom 으로는 무엇도
고정할 수 없다. 대신 `.md` 의 주석에 왜 `contain: paint` 인지, 왜
`overflow: hidden` 이 아닌지를 남겼다.

BUG-180/DEV-316(2026-08-01, macOS 실기) 조사 결론: 트랙패드 2손가락
제스처 중 노드가 배경보다 늦게 따라오는 문제는 WebKit(Safari/WKWebView/
WebKitGTK) 이 제스처 인식 중 `<canvas>` 컴포지팅 자체를 정책적으로 미루는
구조적 원인 — cytoscape 옵션/캡처/마스킹 등 앱 레벨 우회를 11가지 방식으로
시도했으나 전부 실패(자세한 이력은 BUG-180/DEV-316 댓글 참조).

## 근거 있는 해결 방향

lane 배경/그리드 스냅 점은 이 문제가 전혀 없는데, 정확히 "캔버스가 아니라
DOM 엘리먼트 + CSS transform"으로 그려지기 때문(WebKit 이 지연시키는 건
캔버스 컴포지팅뿐, DOM transform/opacity 변경은 항상 즉시 반영). 퀘스트
카드 노드도 cytoscape 캔버스 대신 **DOM 엘리먼트로 직접 그리면** 이 문제
자체가 성립하지 않게 됨.

## 예상 범위 (착수 전 재검토 필요)

- cytoscape 는 레이아웃/드래그/선택 등 로직·좌표 계산용으로 계속 쓰되,
  실제 노드 시각 표현(카드 배경/뱃지/텍스트)만 별도 DOM 엘리먼트로 렌더
  — cytoscape 의 자체 캔버스 렌더는 끄거나 숨김.
- 노드 위치 동기화: cy 의 pan/zoom/노드 좌표 변경 이벤트마다 대응 DOM
  엘리먼트의 style.transform 갱신(lane 배경과 동일 원리).
- 클릭/드래그/선택 등 인터랙션을 DOM 이벤트로 새로 구현하거나 cytoscape
  이벤트와 이중 연결.
- 노드 개수가 많을 때 DOM 엘리먼트 수가 캔버스보다 무거울 수 있음 —
  실측 필요(가상화/windowing 고려 여지).

큰 아키텍처 변경이라 구현 전 설계 검토(스파이크/POC) 먼저 필요.

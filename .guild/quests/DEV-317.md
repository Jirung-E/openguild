BUG-180/DEV-316의 macOS 실기 조사에서, 두 손가락 제스처 중 DOM 레인은
즉시 합성되지만 Cytoscape Canvas의 새 프레임은 WebKit 화면 반영이 늦어져
노드/관계선만 뒤따라오는 것으로 판단했다. Canvas2D/WebGL 전환, 강제 render,
cy.png() 스냅샷/더블버퍼 등은 이 경계를 없애지 못했거나 캡처 비용과 깜빡임을
추가했다.

## 2026-08-05 최종 구현

```text
board viewport
└─ board-world             ← pan/zoom 시 transform 한 번
   ├─ DOM lane layer
   ├─ SVG edge layer
   └─ DOM quest-card layer
```

- Quest Board의 Cytoscape renderer와 입력 어댑터를 모두 제거했다.
- `BoardGraph`를 앱 전용 위치/선택/viewport 모델로 분리했다. 외부 renderer가
  아니며, 기존 레인 좌표·그리드 스냅·선택·배치 API를 보존하는 작은 상태 모델이다.
- pan/zoom hot path는 노드 수와 무관하게 `board-world`의
  `translate3d(...) scale(...)` 한 번만 갱신한다. 레인·노드·관계선이 같은
  부모 transform을 공유하므로 서로 다른 시각 프레임으로 어긋나지 않는다.
- 카드 내부는 Quest 데이터와 기존 테마 토큰을 쓰는 실제 HTML 배지/제목/댓글/
  토론/기한 요소다. 노드별 고해상도 SVG data image와 raster decode 메모리는 없다.
- 관계선은 같은 월드 좌표계의 SVG `<path>`다. 노드 drag/배치 때만 움직인 카드와
  연결된 path를 requestAnimationFrame 단위로 갱신한다.
- mouse drag pan, trackpad wheel pan, mouse/Ctrl wheel zoom, touch pan/pinch,
  단일·다중 drag, Ctrl/Meta click, box selection을 직접 처리한다.
- 기존 상태 변경 확인/취소, snap, undo/redo, 정렬, lane 접기·숨김·순서,
  filter dim, 관계 highlight/선택, popup, flash, viewport 저장/복원 로직은 유지했다.
- `cytoscape`와 `@types/cytoscape` 직접 의존성을 제거했다. `npm ls`에 보이는
  Cytoscape는 Markdown Mermaid가 내부 레이아웃에 쓰는 전이 의존성으로,
  Quest Board 코드/번들 진입점과 무관하다.

## 트레이드오프

- Canvas 한 장 대신 노드 수만큼 DOM element와 관계 수만큼 SVG path가 생긴다.
  따라서 수천 개 노드에서는 DOM 메모리와 최초 mount/style/layout 비용이
  Canvas보다 커질 수 있다.
- 반대로 제스처 중에는 546개 카드를 다시 그리거나 각각 갱신하지 않고 부모
  transform만 바꾸므로, 이번 문제의 hot path 비용과 WebKit Canvas commit
  지연은 제거된다. 카드별 `will-change`를 두지 않아 546개의 별도 합성 레이어도
  만들지 않는다.
- 실제 길드 규모에서 부족할 때만 viewport+overscan 가상화를 추가한다. 가상화는
  제스처 중 mount/unmount하지 않고 제스처 종료 후 갱신해야 프레임 일관성을 지킨다.

## 2026-08-05 추가 검증 — native WKWebView / 격리 UI 회귀

현재 소스로 debug `openguild-gui`를 다시 빌드하고 실제 저장소 경로를 넘겨
Tauri의 guild launch 경로가 정상 기동되는 것을 확인했다.

macOS의 실제 `WKWebView`를 사용하는 스냅샷 하네스에서는 self guild 기준
DOM card 547개, SVG edge 183개, 보드 Canvas 0개를 확인했다. 트랙패드와 같은
작은 delta의 wheel 입력 24회를 연속 전달했을 때 `board-world` transform도
24개의 서로 다른 값으로 진행했고, 시작/중간/끝 스냅샷에서 lane/card/edge가
같은 위치 관계를 유지한 채 함께 이동했다.

다만 자동화용 WKWebView는 창이 숨김 상태라 `requestAnimationFrame`이 정지했다.
하네스에서 이 부분만 timer로 대체했고 wheel도 합성 입력을 썼으므로, 이 결과를
사람이 보이는 Tauri 창에서 실제 두 손가락 트랙패드를 사용한 검증으로 과장하지
않는다.

별도의 6-quest/2-edge 길드에서는 실제 브라우저 포인터 입력과 API 저장값을 함께
대조해 다음 회귀를 확인했다.

- 같은 lane drag가 DB 좌표를 변경하고, undo는 기준 좌표로, redo는 이동 좌표로
  정확히 복원했다.
- Meta 다중 선택과 popup의 `연관 전체 → 선택`이 동작했고, DEV-001과 선행
  DEV-006이 함께 선택됐다.
- 다른 lane drop 취소는 status/좌표를 모두 유지했다. 확정은 DEV-001을
  `open → in_progress`와 새 좌표로 저장했고, undo가 status와 좌표를 함께 복원했다.
- grid snap은 드롭 좌표를 실제 격자 중심 `(318, 324)`에 저장했다.
- 전체 정렬은 모든 대상 좌표를 저장했고, undo가 정렬 전 좌표 전부를 복원했다.

초기 하네스에서 undo 좌표가 복원되지 않은 것처럼 보였던 값은 Svelte DOM 반영을
기다리지 않고 읽은 테스트 오류였다. 실제 포인터 입력 뒤 DOM과 API를 충분히
기다려 대조하자 정상 복원이 확인됐다.

현재 자동화 드라이버는 보조키를 누른 채 포인터 drag하는 입력을 WKWebView에
유지하지 못해 box selection 실입력 검증은 완료하지 못했다. 따라서 남은 수동
완료 조건은 다음과 같다.

1. 보이는 macOS release Tauri/Safari 창에서 실제 두 손가락 pan/zoom 시
   lane/card/edge가 같은 프레임에 붙어 움직이는지 확인.
2. 실제 `Ctrl/Meta + drag` box selection과 실제 터치 장치 pinch 확인.
3. filter, lane 숨김·접기·순서 변경, dark/light 및 한국어/영어 조합의 최종
   육안 점검과 필요 시 Web Inspector Memory/Layers 비교.

자동 회귀와 native WebKit 구조 검증은 통과했지만 1번이 이 버그의 핵심 재현

## 2026-08-05 실제 트랙패드 확인 및 렌더 회귀 보정

macOS release 앱에서 실제 두 손가락 pan/zoom을 확인한 결과, 원래 핵심
증상이던 lane/card/edge의 프레임 불일치는 해소됐다. 이후 발견된 화살표 모양,
확대 선명도, 깊은 축소 GPU 부하는 다음과 같이 보정했다.

- 모든 edge에 강제하던 최소 18px bend를 없앴다. 단일 관계는 기존처럼 직선,
  동일 노드 쌍의 병렬 관계만 40px step으로 대칭 분리한다.
- SVG `non-scaling-stroke`를 제거해 선과 marker도 월드 배율을 따르게 했다.
- `will-change: transform`인 거대 영구 layer 대신, 바깥 viewport의 제스처 중
  임시 transform과 안쪽 world의 확정 CSS `zoom`을 분리했다. 연속 zoom에서는
  80ms 간격 및 20~25% 배율 차에서만 중간 확정하고, 입력 종료 120ms 뒤 최종
  배율을 확정한다. 확대 후 현재 배율로 다시 raster해 선명도를 회복하면서,
  깊은 축소에서 거대한 원본 backing layer를 계속 합성하는 비용을 줄인다.

self guild production bundle에서 DOM node 547 / SVG edge 183 / Canvas 0,
단일 edge 직선 183 / 강제 `will-change` 0 / `non-scaling-stroke` 0을 확인했다.
전체보기 zoom 0.0309255에서는 논리 world 6,852×25,514px가 실제 약
212×789px로 렌더된다. `svelte-check` 0/0, frontend 35 files/367 tests,
production build, `git diff --check`, release GUI rebuild가 통과했다.

새 release 앱에서 화살표, 확대 선명도, 축소 GPU/체감 프레임의 실제 트랙패드
재확인을 위해 상태는 `Testing`으로 둔다.

### CSS zoom 후속 회귀 보정

실제 release 앱에서 노드 내부 pill/font가 외곽과 다른 비율로 변하고 lane
위/아래가 잘리는 회귀가 확인됐다. CSS `zoom`이 자식 layout/font를 재계산한
부작용이므로 안쪽 확정 배율을 `transform: scale(...)`로 교체했다.

lane은 viewport 전체 높이의 screen-space 단색 배경과 world-space grid dot으로
분리했다. 배경은 X/폭만 pan/zoom을 따르고, dot은 카드/edge와 함께 세로로도
움직인다. zoom 0.0309255에서 node 284×80px가 화면 8.7828×2.4740px,
pill/title 역산 높이가 17.0003/30.0000px였으며 lane top/bottom은 board-wrap과
정확히 일치했다. release rebuild 후 실제 트랙패드 재확인을 위해 Testing으로 둔다.

### 중첩 scale 제거

안쪽 transform 방식에서도 실제 WebKit에서 내부 요소가 따로 변하는 현상이 남아,
중간/종료 배율 확정과 `committedWorldZoom`을 전부 제거했다. 이제 grid/edge/node는
바깥 `board-world-viewport`의 `translate3d(pan) scale(zoom)` 하나만 공유하고,
안쪽 world에는 transform/zoom이 없다.

Tailscale production 주소 `http://100.78.25.64:34173`로 직접 접속해 단일
viewport transform, node 547 / edge 183 / Canvas 0, node와 pill의 동일 배율을
확인했다. 인증 없는 전체 인터페이스 노출 대신 Tailscale IP에만 바인딩했으며,
외부 기기 실제 확인을 위해 Testing으로 둔다.

### 터치 UI click 가로채기 수정

외부 터치 장치에서 노드는 열리지만 새 퀘스트, 레인 헤더, 보드 도구와 팝업
버튼이 눌리지 않는 회귀가 확인됐다. `board-wrap`의 `touchstart`가 노드가 아닌
모든 터치를 보드 pan으로 시작하면서 `preventDefault()`를 호출했고, 브라우저가
tap 뒤 생성해야 할 `click`까지 취소한 것이 원인이었다.

버튼 종류를 예외 목록으로 관리하지 않고 입력 경계를 반대로 제한했다. 이제 보드
제스처는 `.board-node` 또는 명시적인 빈 `.board` 입력면에서 시작한 경우에만
처리한다. 그 밖의 toolbar, lane header, dialog와 향후 추가될 UI는 touch event를
그대로 브라우저에 넘긴다. 두 손가락 pinch도 같은 경계를 사용하므로 팝업 위의
두 손가락 터치가 보드 zoom으로 새지 않는다.

입력 경계 회귀 테스트를 추가했고 `svelte-check` 0 errors/0 warnings,
frontend 36 files/370 tests, production 및 release GUI/server build,
`git diff --check`가 통과했다. Tailscale 전용 production 서버에서 새 퀘스트
모달 열기/취소, 보드 설정 모달 열기와 노드 팝업 닫기를 확인했다. 실제 터치
장치 재확인을 위해 Testing으로 둔다.

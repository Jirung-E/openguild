작업 기록 상세 페이지에서 특정 날짜(예: 2026-07-05)를 열면 "로딩" 화면에서
멈춘 채 넘어가지 않는다는 admin 보고.

## 조사 (2026-07-07)
- 서버/CLI(로컬 모드) 로 동일 쿼리를 직접 호출해보면 즉시 정상 데이터를
  반환 — 백엔드 로직/데이터 자체는 문제 없음.
- 실제 원인: `gui/frontend/src/routes/worklog/+page.svelte` 의 타임라인
  `{#each g.rows as a (a.ts + a.slug + a.kind + a.summary)}` 키가 유일하지
  않았음. 짧은 시간 안에 상태를 반복 토글하면(이 guild 의 2026-07-05 데이터가
  실제로 그런 케이스 — 같은 초(19:27:15)에 DEV-006 상태가 12번 왔다갔다)
  ts/slug/kind/summary 조합이 중복될 수 있음.
- Svelte 5 는 keyed `{#each}` 의 중복 키를 허용하지 않고 렌더 시 throw —
  `report`/`notes` 를 막 세팅한 직후(로딩→로딩완료 전환 렌더) 이 예외가 나서,
  `loading` state 자체는 코드상 false 로 바뀌지만 그걸 반영할 렌더링 자체가
  깨져 화면은 "로딩" 그대로 굳어버림. 앱을 재시작해도 데이터 자체가 그대로라
  매번 재현됨.

## 수정
- 키를 index(`ri`) 기반으로 변경 — ActivityRow 는 여러 테이블 UNION 이라
  안정적인 고유 id 가 없고, 목록이 읽기 전용(재정렬 애니메이션 불필요)이라
  index 키로 충분.

DEV-024 작업 중 "multi-line 이 첫 줄만 저장된다" 라고 보고됨. 재현 시도 결과
**실제 저장은 정상**, **CLI 출력 포맷 혼동** 이 원인이었음.

## 재현 시도 (2026-05-18)

bash:
```bash
openguild quest update DEV-027 --description "line1
line2
line3"
# 출력: DEV-027 [Open] ... \n           line1
# 파일: line1\nline2\nline3  ← 실제 정상 저장됨!
```

PowerShell here-string `@"..."@`: 동일하게 파일 정상 저장.

## 원인

`cli/src/main.rs:691` 의 `print_quest()`:

```rust
if let Some(d) = &q.description && !d.is_empty() {
    println!("           {}", d.lines().next().unwrap_or(""));  // ← 첫 줄만
}
```

`d.lines().next()` 가 의도적 — list 출력에서 description 미리보기로 한 줄만 표시.
list / search 에선 맞는 동작.

하지만 `new` / `update` 후 호출자도 같은 `print_quest()` 사용 → 사용자가 `update`
직후 출력만 보고 **"저장이 잘렸다"** 오해. 실제 파일은 OK.

## 수정 (2026-05-18)

`cli/src/main.rs`:
- `DescMode { Preview, Full }` enum 신설.
- `print_quest()` → preview (기존 동작 유지, list 에서 사용).
- `print_quest_full()` 신설 — multi-line description 전체 표시.
- `QuestCmd::New` 와 `QuestCmd::Update` 후 호출을 `print_quest_full` 로 교체.
  description 변경이 일어난 직후이므로 사용자가 전체 결과를 확인할 수 있게.

다른 명령 (`list`, `status`, `parent`, `start`, `done`, `restore` 등) 은 그대로
`print_quest` (preview) 유지 — description 변경 안 됐고 list 미리보기와 일관.

## 영향

기능 영향 없음 (실제 저장은 처음부터 정상). UX 만 개선:
- 이전: `update --description "multi\nline"` 후 첫 줄만 보임 → 잘린 것처럼 보임.
- 이후: 전체 multi-line 표시 → 사용자가 입력값 그대로 저장됐는지 즉시 확인 가능.

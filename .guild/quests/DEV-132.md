DEV-108 후속 (사용자 요청). 고정 4종 (👍 ✅ ❓ ❌) 외에 사용자가 직접 이모티콘을 추가할 수 있게. 후보: (a) settings 에서 reaction set 편집 (.guild 설정 or localStorage), (b) reaction bar 의 '+' 버튼 → emoji picker. 저장 포맷은 이미 일반 문자열 (reactions attr) 이라 backend 변경 불필요 — UI 만.

## 구현 (2026-07-07)
(a)+(b) 결합 — 기존 '+' 팝업 picker 에 "직접 입력" 필드 추가, 입력한
이모지는 즉시 그 댓글에 반응으로 토글되면서 동시에 길드 전체 커스텀
목록에 저장돼(guild-storage.ts 의 guildKey, quest/campaign 무관 — "자주
쓰는 이모지"는 개인 취향이라 scope 로 안 나눔) 다음 픽업에도 보임.
- `QuestCommentsSection.svelte`: `customReactions: string[]` — localStorage
  키 `commentCustomReactions`(guildKey 프리픽스만 결합), `allReactions =
  [...REACTION_SET, ...customReactions]` 로 picker 렌더.
- 고정 4종은 삭제 불가, 커스텀만 hover 시 × 로 개별 삭제 가능.
- 백엔드/CLI 변경 없음 — `reactions` attr 은 이미 임의 문자열 허용
  (`toggle_comment_reaction` 에 이모지 화이트리스트 없음, CLI `comment
  react` 도 "임의 문자열 허용" 이라고 이미 문서화돼 있었음).

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test --
  --run`.
- 실기: 댓글의 '☺+' 팝업 열기 → 하단 입력창에 이모지 붙여넣고 "추가" →
  즉시 반응이 걸리고 picker 에도 추가되는지. 페이지 새로고침 후에도
  커스텀 이모지가 picker 에 남아있는지. 커스텀 이모지에 마우스 올려 ×
  클릭 → picker 에서 사라지는지(단, 이미 걸린 반응 자체는 유지 — 목록에서
  만 빠짐).

## 진단 (admin 보고)

근본 원인: **snapshot 은 index.db 사본일 뿐, restore 는 index.db 만 되돌리고 `.guild/` 파일은 재생성하지 않음** (snapshot.rs:228 "파일 시스템 측은 자동 갱신 안 함"). 즉 백업이 '진실(파일)'이 아니라 '캐시(index.db)'를 백업함.

증상별:
1. **보드/리스트엔 보이는데 파일 없음** — restore 가 DB 행만 복원. quest/comment/memo/campaign 은 DB 캐시라 화면엔 뜨지만 `.md` 파일은 재생성 안 됨.
2. **캠페인 댓글/메모 복구 안됨** — DB(campaign_comments/memos)엔 있지만 파일 미재생성(=1번과 동일).
3. **길드 룰 복구 안됨** — rules 는 **DB 테이블이 아예 없음**(파일 전용). snapshot 에 포함된 적이 없어 복원 불가.
4. **깜빡임** — restore 가 **살아있는 index_pool 위에서 index.db 를 fs::copy 로 덮어씀**(재오픈/reload 없이). SQLite 연결이 교체된 파일과 불일치 → 깜빡/이상 표시. (restore_snapshot 주석도 "store 새로 열기 전 호출 권장"이라 경고.)

추가 소실(파일 전용 = snapshot 에 없음):
- 첨부 sidecar `.attachments.json`(DEV-156)
- tag/type/status `.toml`, 길드 마커 `{name}.guild`
- (attachment blob 은 attachment_blobs 로 DB 에 있어 reindex self-heal 로 복원 가능 — 단 restore 흐름에서 호출 안 됨)

⚠️ 위험: restore 후 'reindex'(파일→DB) 를 돌리면 파일이 없으니 **DB 까지 비워져** 데이터가 완전 소실됨. 현재 안내 메시지가 reindex 를 권하는데 위험함.

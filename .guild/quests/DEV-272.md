# [gui] 폰트 설정 기능

사용자 요청(2026-07-20): UI 폰트를 사용자가 설정할 수 있게.

## 방향 (착수 시 구체화)

- 설정 페이지(테마/UI 크기 옆)에 폰트 선택 추가 — 시스템 폰트 목록 조회
  또는 큐레이션된 후보(시스템 기본/맑은 고딕/Pretendard/Noto Sans KR/
  monospace 등) 중 선택.
- 본문/코드 폰트 분리 여부 검토(코드블록은 mono 유지).
- 저장은 커스텀 테마 프리셋(DEV-249, `~/.openguild/themes.json`)과 같은
  파일 영속 or localStorage — 기존 uiScale/theme 패턴 따라가기.
- CSS 는 `--font-family` 토큰 하나로 root 에 주입하는 방식이 기존 테마
  토큰 체계와 맞음.

## 정한 것 (admin)

| 질문 | 결정 |
|------|------|
| 후보 제공 | **큐레이션 목록 + 직접 입력** |
| 본문/코드 | **따로** (`--font-sans` / `--font-mono`) |
| mono 46곳 | **전부 통합** |

시스템 글꼴 열거는 채택하지 않았다 — Rust 의존성이 붙는 데다 **웹/서버
모드에서는 아예 못 쓴다.** 모드마다 다른 UI 가 되는 것을 피했다. 직접 입력이
있으므로 목록 밖 글꼴도 쓸 수 있다.

## 전제가 없었다 — 먼저 갖췄다

착수해 보니 `font-family` 가 컴포넌트에 **4종 46곳**으로 흩어져 있었다.

| 스택 | 곳 |
|------|-----|
| `'SFMono-Regular', Consolas, monospace` | 28 |
| `'JetBrains Mono', ui-monospace, monospace` | 12 |
| `'Cascadia Code', 'Courier New', monospace` | 5 |
| `ui-monospace, SFMono-Regular, Menlo, monospace` | 1 |

[[DEV-364]] 가 `--font-mono` 토큰을 만들어 뒀는데 **쓰이는 곳이 한 곳뿐**이었다.
그리고 갈린 기준이 역할이 아니었다 — 같은 `.slug` 인데 캠페인은 JetBrains,
작업기록은 SFMono 다. 작성 시점이 다른 흔적이다.

이걸 두고 설정 기능만 얹으면 **46곳 중 1곳만 바뀐다.** 그래서 전부 토큰으로
모으고 `check:font` 를 붙였다.

### 실측 — 지금 실제로 어떻게 보이나 (macOS)

`document.fonts.check` 는 폴백까지 true 를 주므로 못 믿는다. 렌더 폭으로 쟀다
(serif 기준선 763.71 과 비교):

- `SFMono-Regular` / `JetBrains Mono` / `Cascadia Code` / `Consolas` /
  `ui-monospace` → **전부 이 맥에 없다.**
- `Courier New` / `Menlo` → 있다.

그래서 41곳은 이미 **Menlo** 로 같게 그려지고 있었고, 실제로 달라 보이던 것은
admin 페이지 5곳(Courier New)뿐이다. Windows 에서는 Consolas·Cascadia Code 가
OS 에 있으므로 거기선 세 그룹이 진짜로 갈렸다.

## 구현

- `--font-sans` / `--font-mono` 가 정본. `html` 이 sans 를 쓴다.
- 고른 이름을 **기본 스택 앞에 덧붙여** root 에 심는다. 통째로 갈아끼우지
  않는 것이 요점 — 설치 안 된 글꼴을 골라도 폴백이 받아 주고, 한글이 없는
  글꼴을 골라도 한글은 폴백으로 그려진다.
- 영속은 `localStorage`(theme / uiScale 과 같은 계층, 길드 무관).
- **CodeMirror 는 자체 baseTheme 에서 `.cm-scroller` 에 `monospace` 를 박아
  둔다** — 덮지 않으면 정작 가장 필요한 편집기가 설정을 안 따라간다. 두
  곳(MarkdownEditor / worklog)에 토큰을 넣었다.
- 직접 입력은 **위험 문자에서 자른다**(지우지 않는다). 지우기만 하면
  `Foo; } body { display: none` 이 `Foo body display none` 이라는 그럴듯한
  이름으로 남아, 사용자는 자기가 뭘 저장했는지도 모른다.

### UI

설정 > 표시에 'UI 글꼴' / '코드 글꼴' 두 줄. 드롭다운 + '직접 입력' + **견본**.
목록에 있다고 그 글꼴이 설치돼 있다는 뜻은 아니므로(열거를 안 하기로 했다)
견본으로 실제 적용 여부를 눈으로 확인하게 했다.

'직접 입력' 상태는 저장값과 **별개로** 들고 있어야 한다 — 고른 순간에는 아직
이름이 없어서 저장값만 보면 드롭다운이 곧바로 되돌아가 입력칸이 안 열린다
(구현 중 실제로 밟았다).

## 예외 하나

`TitleBar` 의 `Segoe Fluent Icons` 는 **아이콘 소스**다(창 버튼 글리프).
사용자 글꼴로 바뀌면 버튼이 네모로 나오므로 가드의 ALLOW 에 등록했다.

## 검증

- 단위 테스트 17건. 폴백이 남는지, 이름 아닌 것이 이름 자리에 안 들어가는지,
  sans/mono 가 서로를 안 덮는지.
- `check:font` 가 CSS 와 JS(CodeMirror 테마) 양쪽을 잡는 것 확인 — 각각
  되돌려서 실패시켰다.
- 화면(미리보기): UI 글꼴을 Courier New 로 → `--font-sans` 가
  `'Courier New', <기본 스택>` 이 되고 렌더 폭 320.1 → 391.85. mono 는 그대로.
  새로고침해도 유지. **없는 글꼴(`NoSuchFontXyz`)을 넣으면 폭이 320.1 로
  기본과 정확히 같다** — 폴백이 받아 준다.
- 코드 글꼴을 Courier New 로 → 태그 pill 이
  `"Courier New", SFMono-Regular, …` 로 계산된다. 퀘스트 상세의 slug 는
  의도대로 sans 유지([[DEV-364]] 정정).

## 남은 위험 — 보드 노드

노드 상자는 px 고정(`BOARD_NODE_WIDTH`)인데 안의 글자는 이제 사용자 글꼴을
따라간다. **폭이 넓은 글꼴을 고르면 노드 안에서 넘칠 수 있다.** 지금도
글꼴이 다른 기기에서는 같은 위험이 있었지만, 설정으로 열리면서 더 쉬워졌다.
실기에서 보고 필요하면 노드 안만 예외로 둘지 판단할 것.

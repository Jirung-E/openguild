사용자 실사고(BUG-137 테스트 중): 브라우저 dev(`just dev-frontend`)에서
`/api/quests`, `/api/quest-types`, `/api/quest-statuses`,
`/api/campaigns/summaries/active` 등이 전부 **404**.

## 원인

- `gui/frontend/.env.development` 가 **gitignore 대상**(`gui/frontend/
  .gitignore`: `.env.*`, 예외는 `.env.example`/`.env.test` 뿐)이라 신규
  클론에는 없다.
- 없으면 `VITE_API_URL` 이 빈 문자열 → `transport.ts` 의 API base 가
  상대경로 → 프론트가 `/api/*` 를 **Vite dev 서버(:5173) 자기 자신**에
  요청 → 404. (vite 에 `/api` 프록시도 없음.)
- 서버(:3000)는 정상: 실기 확인 시 위 4개 엔드포인트 전부 200.
- 게다가 `.env.example` 주석이 *"개발용은 `.env.development` 에 이미
  localhost:3000 설정되어 있음"* 이라고 단언 → 실제론 없어서 사용자를
  오도.

즉 BUG-137(SSR 500) 자체는 정상(ssr=false 적용). 이건 별개의 dev 환경
결함 — "처음 받은 사람은 dev-frontend 가 API 404".

## 수정 방향 (택1 또는 병행)

- (권장) `gui/frontend/vite.config.ts` 에 dev 프록시 추가:
  `server.proxy['/api'] = 'http://localhost:3000'`. 그러면 VITE_API_URL
  없이도 상대경로 `/api` 가 :3000 서버로 전달 → env 파일 불필요, prod
  (서버가 정적+API 동일 origin 서빙)와도 일관.
- 또는 `.env.development` 를 gitignore 예외로 커밋(dev 설정, 비밀 아님).
- `.env.example` 의 오해 소지 주석 정정.

## 테스트 방법

깨끗한 상태(.env.development 없음)에서:
1. 한 터미널 `just dev-server`(길드 dir), 다른 터미널 `just dev-frontend`.
2. 브라우저에서 홈/보드/목록 로드 시 API 404 없이 데이터가 뜨는지.
3. (프록시 방식이면) VITE_API_URL 미설정에서도 되는지 확인.

## 증상

앱이 새 스킬을 들고 와도 `~/.openguild/skill-marketplace/` 가 갱신되지 않는
경우가 있다. 실패가 **조용해서** 사용자는 옛 스킬을 계속 쓴다.

## 원인 — 시각으로 판단한다

[[DEV-264]] 의 동기화는 파일별 **mtime 비교**다 — `src > dst` 일 때만 복사.
이 기계에서 실물로 재현된다:

```
앱 번들 원본        8월 27 13:40   version 0.5.0
~/.openguild 사본    9월  4 19:30   version 0.5.2
```

사본이 더 새것이라 앱을 실행해도 덮어쓰지 않는다. 지금은 사본 쪽이 더 좋은
내용이라 결과가 맞지만, **규칙 자체가 위험하다.** 로컬 사본이 어떤 이유로든
최신 mtime 을 갖게 되면(저장소 CLI 실행, 백업 복원, 파일 복사, 편집)
**그 뒤로 앱이 아무리 새 스킬을 들고 와도 영영 무시된다.**

저장소를 클론한 개발자는 전원 이 상태다 — 저장소 CLI 를 한 번이라도 돌리면
사본 mtime 이 앱 빌드 시각보다 항상 최신이 된다.

[[BUG-261]] 과 같은 성질의 결함이다: 판단 기준이 실제 의미(버전)가 아니라
곁가지(시각)이고, 어긋나도 아무 말이 없다.

## 고치는 법

**버전으로 판단한다.** 번들의 `plugin.json` 버전과 사본의 버전이 다르면
mtime 과 무관하게 트리를 통째로 덮어쓴다. 버전이 같으면 기존 mtime 규칙을
유지한다 — 저장소에서 같은 버전으로 내용만 고치며 개발하는 흐름이 있다.

`sync_bundled_docs`(문서)는 그대로 둔다. 그쪽은 버전 개념이 없고 갱신이
안 돼도 조용히 틀린 답을 하게 만들지 않는다.

## 테스트 방법

`cargo test -p openguild-core user_dirs`

- 버전이 다르면 사본이 더 새것이어도 덮어쓴다 (이 버그)
- 버전이 같으면 사본이 더 새것일 때 건드리지 않는다 (개발 흐름 보존)
- 사본이 없으면 전부 복사한다
- `plugin.json` 이 없거나 깨져 있어도 던지지 않는다

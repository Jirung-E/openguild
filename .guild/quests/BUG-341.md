**같은 초에 백업이 둘 생기면 목록 순서가 뒤바뀐다**(2026-10-01, BUG-340 확인 중 사본 길드에서 재현).

- 같은 초에 두 번째 백업은 이름 끝에 `-01` 이 붙는다(BUG-108). 목록은 **파일 이름**으로 줄 세우는데,
  `…230-01.db` 가 `…230.db` 보다 앞에 온다(`-` 가 `.` 보다 작다). 그래서 새것이 옛것 앞에 선다.
- 그러면 `openguild restore`(대상 없이 = 가장 최근)와 앱의 복원이 **더 오래된 백업**으로 되돌린다.
  시점 복원(`restore --at`)도 "가장 최근" 을 목록 끝에서 고르므로 같다.
- 오래된 것 지우기(`prune_old_snapshots`)는 타임스탬프로 줄 세워 맞다 — 목록만 틀렸다.

## 재현

자동 백업을 매번 뜨게(`OPENGUILD_AUTO_BACKUP_OPS=1`) 하고 퀘스트 둘을 1초 안에 만든다 → `backup list` 에서
`-01` 이 먼저 나오고, `restore` 하면 둘째 퀘스트가 사라진다.

## 고칠 것

`list_snapshots` 도 `prune_old_snapshots` 처럼 타임스탬프(`snapshot_timestamp_of`)로 줄 세운다. 같은 초
여러 개(`-01`, `-02` … `-10` 이상)도 순서가 맞는지 시험.

## 고침 (2026-10-01)

- `order_key` — 앞 15자(시각)와 같은 초 번호(`-01` → 1)로 줄 세운다. 목록(`list_snapshots`), 오래된 것 지우기,
  자동 백업의 "마지막 백업 시각" 이 모두 이것을 쓴다(문자열로 세우면 `-100` 이 `-99` 앞에 선다).

## 시험

- 같은 초 `…`, `-01`, `-02`, `-10` 과 앞뒤 초를 거꾸로 만들어도 목록이 시간 순이고, "가장 최근" 이 맨 끝 것이다
  (고치기 전: `-01` 들이 `….db` 앞에 서서 실패).

## 테스트 방법

사람이 볼 것은 거의 없다 — 백업을 1초 안에 두 번 만든 뒤(관리 → 백업 만들기 두 번) 목록에서 위아래 순서가
만든 순서와 맞으면 정상.

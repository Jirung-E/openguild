**처방에서 `--guild "$OPENGUILD_GUILD_DIR"` 를 걷어내지 말 것**(admin).

이 일이 끝나면 훅이 길드에서 돌므로 CLI 의 자동 탐색(cwd 부터 `.guild` 를 거슬러 찾기)이
걸려서 `--guild` 없이도 된다. 그래도 남긴다.

- `OPENGUILD_GUILD_DIR` 는 설정이 아니라 코어가 `run` 자식마다 무조건 넣는 값이다
  (`delivery.rs:280`) — 없을 수가 없으니 쓰는 데 비용이 없다.
- 훅이 중간에 `cd` 를 하면 자동 탐색은 깨지지만 환경변수는 살아 있다.
- 탐색은 **위로** 올라간다. 길드 안에 길드가 있으면 엉뚱한 쪽을 잡을 수 있다.

<!-- og-comment id="2" ts="2026-09-28T00:54:46+09:00" author="admin" -->
**"길드 위치" 는 그 길드가 초기화된 자리 — `.guild` 파일이 있는 폴더(길드 루트)다**(admin, 2026-09-28). 코드로는 `plugin.guild_root` 이고 `OPENGUILD_GUILD_DIR` 와 같은 값이다.

작업 폴더를 사용자가 고르게 하지는 않는다 — 이 자리 하나로 정한다.

**더 고침 (2026-10-22):** 작업 폴더로 `plugin.guild_root` 를 그대로 주면 윈도우에서 `\\?\C:\…` 꼴일 수 있다 — cmd 는 그런 작업 폴더를 UNC 로 보고 거절하고 PowerShell 5.1 도 못 다룬다(BUG-294 와 같은 까닭). 환경변수에 넣는 값처럼 앞부분을 뗀 경로를 준다. just test 통과.

**직접 확인(2026-10-23):** 실제 훅의 `pwd` = 길드 루트, `.guild` 보임. 예제 discussion-to-ai(받은 편지함 · 명령) · deleted-audit 의 기록은 모두 데이터 폴더에, 길드(git 저장소로 만든 사본)의 `git status` 에는 변화 없음. 허용 화면 · 웹 화면 표기 "데이터 폴더". BUG-279(훅이 쓴 파일로 동의가 풀림)는 시험이 지킨다. **못 본 것:** 윈도우(작업 폴더에 `\\?\` 를 뗀 경로를 주게 고쳐 둠).

**다시 고침 (2026-10-23, CI 윈도우 실패):** 시험 도우미 `RunLab::data()` 를 쓰는 시험이 유닉스 전용(`sh`) 하나뿐이라, 윈도우에서는 안 쓰이는 함수가 되어 `cargo clippy -D warnings` 가 막았다(`method data is never used`). 맥 `just test` 로는 안 걸린다 — 맥에서 윈도우 대상 검사는 ring(C) 때문에 안 된다. 쓰는 쪽과 같은 `#[cfg(unix)]` 를 달았다. 윈도우 전용 시험(손자 거두기)이 상대 경로를 길드 루트에서 찾는 것은 이미 맞다. just test 통과.

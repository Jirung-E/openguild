답글의 답글(level-2)을 쓸 때도 입력창이 스레드 맨 아래에 나타남 —
어떤 답글에 다는지 시각적 연결이 끊김.

## 원인 (QuestCommentsSection.svelte)
답글 폼이 `{#if replyFormRoot === root.id}` 로 **스레드(root 카드) 단위**
하나만, 항상 reply-list 렌더가 끝난 뒤(맨 아래)에 붙음 — replyingTo 가
level-1/level-2 어느 댓글이든 무관하게 위치가 같다. 폼 상단에
"↩ #N 에게 답글" 표시(replyTarget)는 있지만 위치 자체가 대상 옆이 아님.

## 개선
replyingTo 대상 댓글 **바로 아래**에 폼을 렌더 — level-1 답글에 달면 그
level-1 아래(l2 목록 위), level-2 에 달면 그 항목 아래. DEV-120 의 자동
focus/scroll 은 유지.

## 구현 (2026-07-07)
- `groups` derived 에 `level1AncestorOf: Map<entryId, level1Id>` 추가 —
  level-1 entry 는 자기 자신, level-2 entry 는 소속된 level-1 id.
- `replyFormLevel1` derived: 답글 대상이 root 면 `null`(=폼은 스레드 맨
  아래, 새 level-1 자리라 기존 위치가 맞음), level-1/level-2 면 그
  level-1 id.
- 답글 폼 마크업을 `{#snippet replyFormView(rootId)}` 로 추출해 두 위치에서
  재사용: (a) `level1ByRoot` each-loop 안, 해당 level-1 의 l2 블록 바로
  뒤(`replyFormLevel1 === r.id`), (b) 기존 스레드 맨 아래(`replyFormLevel1
  === null`, root 에 대한 답글일 때만).
- `enterReply`: 답글 대상이 root 가 아닌데 그 스레드가 접혀 있으면(폼이
  render 되는 level1 each-loop 자체가 안 그려짐) 먼저 펼침.

## 테스트 방법
- `cd gui/frontend && npm run check && npm test -- --run`.
- 실기: quest/campaign 상세에서 (1) root 댓글에 답글 → 폼이 스레드 맨
  아래(기존과 동일). (2) level-1 답글에 "답글 쓰기" → 폼이 그 답글 바로
  아래(l2 목록 위)에 뜨는지. (3) level-2 답글에 "답글 쓰기" → 같은
  level-1 그룹 옆에 뜨는지. (4) 스레드를 접은 상태에서 안의 답글에
  답글 쓰기 시도 → 자동으로 펼쳐지며 폼이 보이는지.

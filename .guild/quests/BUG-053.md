사용자: 'GUI 에서 상태 바꾼 quest 들이 되돌아오는 경우가 있다, 기준 모르겠음'.

## 결론 — 시스템 버그 아님, cancelled

사용자 지적 후 분석 정정: 시스템 동작은 모두 의도된 design 대로 정상.
직접 원인은 **운영 실수 (agent 의 `git stash` pop 누락) + 사용자 패턴 (GUI 변경 commit 누락)** 의 결합. quest cancel.

## 재현 확인 (참고)

BUG-046 의 quest_history 에 testing→done 두 번 기록, 사이에 done→testing reverse 가 history 에 없음. DB 가 reverse 됐는데 정상 mutation 아님.

stash@{0} 안에 사용자의 06-05 08:50 GUI 변경 (BUG-040 + BUG-047 testing→done) 이 갇혀 있었음. Claude 가 DEV-070 작업 시작 시 `git stash -u` 호출 후 pop 안 함 → working tree 가 testing 으로 보이는 동안 GUI 가 reindex → DB 도 testing 으로 sync → 사용자 입장 silent revert.

## 시스템 동작 검증 결과

| 동작 | 의도된 design / 정상 |
|------|---------------------|
| `git stash -u` | git 정상. 변경분 일시 보관. |
| `git restore <file>` | git 정상. last commit 으로 복원. |
| `git checkout <branch>` 자체 | 무해 (모든 branch tip 의 quest file 동일 — 이번 라운드 검증). |
| `drift::auto_resync` 가 fresh file 감지 → reindex | BUG-049 의 의도된 시동 기능. |
| reindex 가 file→DB sync, history 안 적음 | design 원칙 (file 진리원, reindex 는 rebuild 이지 mutation 아님). |
| `change_status` 의 no-op early return (DB 동일 시) | BUG-011 의 의도된 동작. |

→ 사용자가 본 silent revert 는 위 정상 동작들의 결과. 시스템 버그 아님.

## 운영 규칙 (이번 case 의 진짜 fix)

1. **Agent 의 `git stash` 후 작업 끝나면 반드시 `stash pop` 또는 명시 drop** — AGENTS.md 에 추가 권장.
2. **사용자 GUI 변경분은 commit 권장** — 안 하면 다음 git 동작 (restore / stash 누락 / branch checkout 의 carry over 충돌) 에 취약.
3. 본 라운드 stash@{0} / stash@{1} 의 처리: 사용자가 내용 확인 후 pop / commit 또는 drop.

## 향후 (별도 quest 권장 — observability 개선)

사용자가 silent revert 자체를 추적할 방법이 없음 — observability gap 은 별개 개선 가치 있음:
1. reindex 가 status 변경 시 quest_history 에 op='reindex_status_sync' 같은 entry 추가 — 흔적 남김.
2. drift::auto_resync 호출 시 fresh_files 의 status 변경을 GUI banner / toast 로 명시 알림 (현재는 `tracing::info!` 만 — 사용자에게 안 보임).
3. snapshot 자동 — 사용자 GUI 변경 직전 + reindex 직전 에 즉시 snapshot ('pre-revert' 안전망).

→ 위 항목들은 본 quest 의 범위 외. 필요 시 별도 DEV quest 등록.

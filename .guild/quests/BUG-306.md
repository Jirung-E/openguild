## 무엇이 잘못됐나

도서관에서 폴더를 만들었다 지우고, **같은 이름으로 다시 만들면** DB 오류가 그대로 나온다
(admin).

```
error: internal error: error returned from database:
(code: 2067) UNIQUE constraint failed: library_folders.path
```

## 왜

지우기는 행을 남기고 `deleted_at` 만 찍는다(soft delete). 그런데

- 존재 검사는 `WHERE path = ? AND deleted_at IS NULL` → "없다"
- 유니크 제약은 `path` **하나**에 걸려 있다 → INSERT 가 남아 있는 그 행과 부딪힌다

파일 쪽(`folders.toml`)은 옛 항목을 지우고 새로 넣으므로 멀쩡했다 — **캐시만** 깨졌다.
그래서 오류 뒤에도 파일에는 폴더가 생겨 있어, 화면과 DB 가 어긋난 상태가 된다.

## 고친 것

같은 경로가 이미 있으면 **되살린다**(`ON CONFLICT(path) DO UPDATE … deleted_at = NULL`).
폴더는 경로가 곧 정체성이라 되살리는 것이 맞다. 살아 있는 폴더를 또 만들려 하면 지금처럼
거절한다.

## 같은 함정이 더 있나 — 확인함

`UNIQUE` 가 걸린 다른 칸을 훑고 실제로 지웠다 다시 만들어 봤다.

- 캠페인(`campaign_slug`) — 슬러그가 자동 번호라 재사용 자체가 없다. 정상.
- 타입(`prefix`) · 상태(`slug`) — 지운 뒤 같은 이름으로 다시 만들어도 된다. 정상.
- 도서관 문서(`number`) — 번호를 재사용하지 않는다. 정상.

폴더만 걸렸다.

## 테스트 방법

- 폴더를 만들고 → 지우고 → **같은 이름**으로 다시 만들 수 있다.
- 목록에 한 번만 나온다(되살린 것이지 새로 넣은 것이 아니다).
- 살아 있는 폴더를 또 만들려 하면 여전히 거절한다.

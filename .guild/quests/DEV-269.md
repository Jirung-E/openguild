# [skill] SKILL.md에 quest/comment/rule/library 기록 판단 기준 추가

## 배경

사용자 질문: 스킬을 쓰는 에이전트가 "이건 quest로 남길 만한가/댓글로
남길 만한가/규칙으로 남길 만한가/도서관에 남길 만한가"를 스스로 판단하게
하려면 어떻게 해야 하는지.

## 방향

Claude 자신의 auto-memory 시스템(무엇을 언제 저장/저장하지 않을지 명시한
트리거 기준 + 배제 기준 구조)과 동일한 패턴을 SKILL.md에 이식.

각 타입별 트리거:
- Quest: 아직 안 잡혀있고 지금 작업과 스코프가 다른 실제 버그/할 일일 때만.
- Comment: description에 없는 why/블로커/결정 사항이 생겼을 때만(description
  내용 반복 금지).
- Rule: 사용자가 접근 방식을 교정했거나, 앞으로 계속 적용될 정책/컨벤션을
  말했을 때만(1회성 결정을 규칙으로 승격 금지).
- Library: 코드에서 재유도 불가능한 조사/설계 노트. **사용자 피드백 반영**:
  코드 읽으면 알 수 있는 내용이라도, 코드베이스가 크고 복잡해서 재발견
  비용이 실제로 클 때는 적어두는 게 낫다(모듈 맵, 비직관적 데이터 흐름,
  파고들어야 알 수 있었던 gotcha 등) — 다음에 문제를 더 빨리 찾고 재조사
  수고를 던다. 작고 단순한 코드는 스킵(코드 읽는 게 더 빠름).

## 구현

`skills/openguild-plugin/skills/openguild/SKILL.md`에 "## What's worth
recording (judgment calls)" 절 추가 — "Before you start" 절과 "Quest
lifecycle" 절 사이.

## 테스트 방법

`claude plugin validate ./skills/openguild-plugin` + quest-ID leak grep
로 로컬 검증 완료(순수 문서 변경, 실기 불필요).

## 무엇이 잘못됐나

`openguild plugin list` 가 읽기 어렵다. **`--json` 이 오히려 낫다**(admin).

지금 한 줄은 이렇게 생겼다.

```
· deleted-audit  [cli,gui,server]  막을 수 있음 · run sh -c cat >> deleted.log; echo >> deleted.log  (동의 대기 — 안 돕니다)
```

이름·범위·특징·상태가 한 줄에 다 들어가는데 **자리가 안 맞는다**. 플러그인마다 이름
길이가 달라 눈이 세로로 못 내려간다. 게다가 `run` 의 명령을 통째로 붙여서 줄이 길어지고,
정작 중요한 "막을 수 있음" 이 그 사이에 묻힌다.

## 고칠 방향

세로로 읽히게 **자리를 맞춘다**. 줄의 앞쪽은 폭을 맞춘 열로, 명령처럼 길고 덜 중요한 것은
줄여서 뒤로 보낸다.

```
✓ deleted-audit         cli gui server   막을 수 있음 · run sh
· telegram-quest-status cli gui          post api.telegram.org   (동의 대기)
✗ broken-one                             정의 오류: …
```

- 상태는 맨 앞 기호 하나로 — 지금처럼 괄호로 뒤에 붙이면 줄마다 끝나는 자리가 다르다.
- `run` 은 **명령 이름만**(`run sh`), `post` 는 **호스트만**(`post api.telegram.org`).
  전체는 `allow` 미리보기와 `--json` 에서 본다.
- 설명 줄은 지금처럼 들여쓴다.

## 고침 (2026-10-10) — 폭을 글자 수가 아니라 칸 수로

검증에서 떨어졌던 "열이 세로로 맞는다" 를 고쳤다. 원인은 폭을 `chars().count()`(글자 수)로
센 것이다 — 한글 · 한자 · 일본어 글자는 문자 1개지만 터미널에서 **두 칸**을 먹는다.
`긴명령`(3자)은 9칸, `시험플러그인`(6자)은 12칸이라 글자 수로 맞추면 3칸 밀린다.
영문만 쓰면 글자 수 = 칸 수라 안 보이던 버그다.

- `unicode-width` 를 CLI 의존성에 추가(0.2) — East Asian Width 가 `W`/`F` 면 2로 센다.
- 헬퍼 둘로 빼냈다 — `pad_to_width(s, w)` · `max_width(cells)`. 시험할 수 있게, 그리고
  [[BUG-353]] 이 같은 것을 쓰게.
- 러스트 폭 지정자(`{s:<w$}`)도 글자 수로 채우므로 쓸 수 없다. 공백을 직접 붙인다.

### 시험

`cli/src/main.rs` 에 3개 — 한글만 / 영문·혼합 / 폭을 넘는 경우(자르지 않는다).

실제 출력(한글 3 + 영문 1 + 혼합 1):

```
✓ a-short       cli  run true
✓ 긴명령        cli  run true
✓ 되부르기      cli  run true
✓ 섞인-mixed    cli  run true
✓ 시험플러그인  cli  run true
```

`cli` 열이 다섯 줄 모두 **16칸**에서 시작한다(고치기 전 13 · 14 · 16).

### 남은 것

같은 원인이 `render_table`(공용 표 헬퍼)과 머리글 아래 `─` 줄에도 있다 — `quest list` ·
`type list` · `tag list` · `rule list` 가 전부 해당된다. admin 결정으로 **[[BUG-353]]** 으로 뗐다.

## 테스트 방법

1. 한글 이름 플러그인을 길이가 서로 다르게 둘 이상 두고 `openguild plugin list`
   → `cli` 열이 세로로 맞는다.
2. 긴 `run` 명령이 줄을 늘리지 않는다(예전 그대로).
3. `--json` 은 줄이지 않은 전체 그대로.

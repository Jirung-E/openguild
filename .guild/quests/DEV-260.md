# [gui] 메뉴바 항목이 화면을 벗어나면 타이틀바 ☰ 메뉴로 이동 (overflow menu)

창 폭이 좁아져 메뉴바(Nav)의 항목이 화면을 벗어나면(잘리면), 넘치는 항목을
타이틀바의 ☰ 메뉴 안으로 이동시켜 항상 접근 가능하게 유지. 창이 다시
넓어지면 메뉴바로 복귀 — 브라우저 툴바의 overflow menu(priority+
navigation) 패턴.

## 구현 (2026-07-19)

- **`$lib/stores/navOverflow.ts` 신규** — Nav 가 넘친 항목({href, label,
  active})을 발행하고 TitleBar ☰ 가 구독. 둘은 +layout 의 형제라 스토어로
  연결. label 은 발행 시점에 로컬라이즈 — Nav 가 locale 변화에 반응해
  재발행.
- **Nav.svelte** — 링크 목록을 `navItems` 배열로 일원화(홈~도서관 +
  DEV-271 웹 전용 3개). 실제 링크와 동일 마크업의 숨김 measurer 를 nav
  안에 항상 전부 렌더해 자연 폭을 측정(보이는 목록은 잘려 있어 전체 폭을
  알 수 없음). ResizeObserver 를 nav(가용 폭)와 measurer(라벨/폰트 변화 —
  언어 토글·UI 크기 변경 시 measurer 크기가 바뀜) 둘 다에 등록 + window
  resize 이벤트 폴백(RO 콜백은 rAF 루프 의존이라 일부 환경에서 누락 가능).
  오른쪽 항목부터 잘라 visibleCount 만 렌더.
- **분기**: 데스크탑(usesCustomTitlebar)은 넘친 항목을 스토어로 발행 →
  TitleBar ☰ 메뉴 상단에 구분선(tb-menu-sep)과 함께 렌더, active
  하이라이트 유지. 웹(타이틀바 없음)은 Nav 자체의 "⋯"(더 보기) 버튼
  드롭다운으로 — DEV-271 로 웹 Nav 가 9개 링크가 돼 overflow 가 특히
  잦아진 상황 커버.
- **열린 질문 결정**: Reindex/설정 버튼은 overflow 대상 아님(페이지
  링크만, 퀘스트 가정대로). 커스텀 타이틀바 없는 환경은 "…" fallback 으로
  범위 내 처리.

## 테스트 방법 (1~3 실기 확인 완료)

1. 웹 모드(vite dev + server) 520~560px 폭: 앞 3~4개만 보이고 "⋯" 버튼
   표시, 클릭 시 나머지(규칙/도서관/캠페인/작업기록/태그)가 우선순위
   순서로 드롭다운에 나타남 — 확인 완료.
2. 900px 이상으로 넓히면 9개 전부 메뉴바로 복귀 + "⋯" 사라짐 — 확인 완료.
3. `npx svelte-check` + `npm run build` 클린.
4. (사용자 확인 필요) 데스크탑 앱에서 창 폭을 좁혀 넘친 항목이 ☰ 메뉴
   상단에 구분선과 함께 나타나는지, 활성 페이지 하이라이트가 유지되는지,
   UI 크기/언어 변경 시에도 재계산되는지 확인.

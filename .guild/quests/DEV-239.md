도서관에 폴더(계층) 기능 — 파일탐색기 스타일로 보여주고, 경로 기반 링크도 지원
(기존 BOOK-NNN 관리번호 링크는 유지).

## 조사 결과
- `library_docs` 테이블(0021 migration)은 현재 완전 flat — id/number/title/body/
  created_at/updated_at/deleted_at 뿐, path/parent 컬럼 없음. 폴더 도입 시 스키마
  마이그레이션 필요.
- 샘플 목업(HTML)을 admin 에게 보여줌 — 좌측 폴더 트리(확장/축소) + 우측 문서
  미리보기(경로 breadcrumb + BOOK-NNN 배지 동시 표시), 하단에 경로/관리번호 두
  링크 형식이 모두 유효함을 표기.

## 설계 결정 필요 (admin 확인 전 보류)
1. 파일-진리원 레이아웃: `.guild/library/{BOOK-NNN}.md` 평면 유지 + DB 에 path
   컬럼만 추가(디스크 폴더 없음) vs. 실제 디스크에 하위 폴더 생성해 파일도 이동?
   (전자가 BOOK-NNN slug 안정성엔 유리 — 폴더 이동해도 파일명 안 바뀜)
2. 경로 링크 문법: `[[아키텍처/라우터 설계]]` 같은 이름 기반 경로를 cross-link
   정규식에 추가로 지원? 아니면 경로는 GUI 트리 탐색 전용이고 링크는 계속
   BOOK-NNN 만? (이름에 공백/슬래시 들어갈 수 있어 정규식 설계 필요)
3. 폴더 자체도 문서 없이 존재 가능한 순수 컨테이너인지, 아니면 폴더도 "문서"라서
   본문을 가질 수 있는지?

## 설계 결정 (admin, 2026-07-07)
1. DB `path` 컬럼만 추가 — `.guild/library/{BOOK-NNN}.md` 파일은 항상 평면 유지.
   frontmatter 에도 `path` 를 함께 기록해 reindex 시 복원 가능. 빈 폴더는 별도
   `.guild/library/folders.toml` 레지스트리로 명시적 존재를 기록(순수 컨테이너).
2. 경로 링크 문법 확장 없음 — `[[경로/제목` 으로 타이핑해도 자동완성이 찾아주되
   실제 삽입/저장되는 링크는 항상 `[[BOOK-NNN]]`. cross-link 정규식 변경 불필요.
3. 폴더는 순수 컨테이너 — 본문 없음, BOOK 슬롯 없음.
4. GUI 보기 방식은 트리(사이드바+미리보기, 샘플1) / 탐색기(고정크기 아이콘
   그리드, 샘플2) 토글 — admin 이 두 목업을 비교 후 토글 방식으로 확정.

## 구현 (2026-07-07)
- **core**: `repo::library` — `BookFrontmatter.path`, `normalize_folder_path`
  (세그먼트 검증: 공백뿐, `.`/`..`, 역슬래시 금지), `path_is_self_or_descendant`,
  `FoldersFile`/`FolderEntry` + `.guild/library/folders.toml` read/write.
  `core/migrations/0022_library_folders.sql` — `library_docs.path` 컬럼 +
  `library_folders` 캐시 테이블.
- **core::ops::library**: `create_book`/`update_book` 에 `path` 파라미터 추가
  (`update_book` 의 `Some("")` = 최상위 이동). `create_folder`/`delete_folder`
  (빈 폴더만 삭제 허용 — 문서/하위폴더 있으면 거부)/`list_folders`.
- **reindex**: `library_docs.path` 를 파일 frontmatter 에서 복원,
  `library_folders` 를 `folders.toml` 에서 복원.
- **replay**: `create_folder`/`delete_folder` 는 path 만으로 완전히 replayable.
- **server**: `/api/library` POST/PATCH 에 `path` 필드, `/api/library/folders`
  (GET/POST/DELETE — DELETE 는 쿼리 `?path=`, 슬래시/한글은 axum Query 가
  percent-decoding 처리).
- **cli**: `library new/update --path`, `library folder list/new/delete`.
  HTTP 백엔드는 reqwest `.query()` 로 안전하게 percent-encode(문자열 concat
  대신 — 폴더 경로에 슬래시/한글 포함 가능).
- **gui**: Tauri 커맨드 `list_library_folders`/`create_library_folder`/
  `delete_library_folder` + `create_book`/`update_book` 에 `path` 인자 추가.
  `transport.ts` — `/api/library/folders` 정적 라우트를 `/api/library/{book_id}`
  동적 라우트보다 먼저 매칭(순서 중요, book_id 로 "folders" 오인 방지).
  `lib/utils/library-tree.ts` — folders(빈 폴더 포함)+books(path) 를 계층
  구조로 빌드하는 순수 함수(`buildLibraryTree`) — tree/explorer 모드 공용.
  `lib/components/LibraryFolderTree.svelte` — 재귀 폴더 트리 렌더(자기 자신
  import). `routes/library/+page.svelte` — 보기 방식 토글(localStorage
  `openguild.libraryViewMode`), 새 폴더/폴더 이동/폴더 삭제 UI, explorer 모드는
  고정 크기(92px) 타일 그리드가 폴더 전용 진입점이고 문서 클릭 시 전체 폭
  상세로 전환("← 목록"으로 복귀 — 편집 중이면 확인 다이얼로그).
  `questIndex.ts`/`editor-links.ts`/`textarea-wikilink.ts` — cross-link
  자동완성이 `[[폴더/제목` 경로로 타이핑해도 BOOK 문서를 찾음(매칭만 경로 기준,
  CodeMirror 쪽은 자체 필터를 꺼야(`filter: false`) label 이 id 가 아닌 경로일
  때도 후보가 안 지워짐).

## 테스트 방법
- `cargo test -p openguild-core ops::library:: reindex:: repo::library::` /
  `cargo test -p openguild-server test_library` (path/폴더 CRUD, reindex 복원,
  replay).
- `cd gui/frontend && npm run check && npm test -- --run` (library-tree,
  textarea-wikilink 경로 매칭, transport 폴더 라우트 매핑 신규 케이스).
- 실기 (GUI):
  1. 도서관 페이지 — 트리/탐색기 토글 전환, 새로고침 후에도 선택한 보기 유지.
  2. "+ 폴더" 로 폴더 생성 → 트리에 표시, 탐색기 모드에서 타일 클릭으로 진입.
  3. 문서 생성 시 폴더 선택 → 해당 폴더 하위에 표시. "폴더 이동" 으로 다른
     문서를 옮기면 즉시 반영.
  4. 문서/하위폴더 있는 폴더는 삭제 거부, 비운 뒤 삭제 성공.
  5. 본문 편집기에서 `[[아키텍처/` 타이핑 → 해당 폴더 안 문서가 자동완성에
     뜨고 선택 시 `[[BOOK-NNN]]` 삽입.
  6. 브라우저 모드(openguild-server)에서도 1~5 동일 동작.

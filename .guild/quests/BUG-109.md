증상: 보드에서 grid snap 을 끄고 노드를 드래그해 다른 레인(상태)으로
옮기면, 상태 변경 확인 다이얼로그에서 확인해도 노드가 목표 레인이
아니라 이전 레인 쪽으로 되돌아와 보임.

## 원인 (gui/frontend/src/lib/components/QuestBoard.svelte)

레인 변경이 확정되면:
1. `questsApi.changeStatus(...)` 로 서버 반영
2. `node.data('statusId', newStatus.id)` — statusId 만 새 값으로 갱신
3. `applyStatusChange(...)` 호출 → 그 안의 `applyLaneVisualCompression()`
   이 **모든 노드**를 `absX`(아직 갱신 전 — 여전히 이전 레인 기준 값)
   기준으로 위치 재계산 → 방금 옮긴 노드가 잘못된(이전 레인 근처) 위치로
   재배치됨.
4. 그 다음에야 `node.data('absX', absX)` 로 새 절대좌표 갱신 (moved 블록
   안, 3번보다 한참 뒤).

3번에서 틀어진 위치를 되돌리는 건 그 아래의
```
if (clampedX !== toPos.x || finalY !== toPos.y) {
    node.position({ x: clampedX, y: finalY });
}
```
뿐인데, gridSnap 이 켜져있으면 snapToGrid 가 드롭 좌표를 그리드에
맞춰 거의 항상 toPos 와 달라져 이 조건이 걸려 정상 위치로 덮어써짐 —
버그가 가려져 있었음. gridSnap 이 꺼져있으면 드롭 좌표가 이미 클램프
범위 안이라 `clampedX === toPos.x` 가 되어 조건이 안 걸리고, 3번에서
틀어진 잘못된 위치가 그대로 남는다.

## 수정
레인이 바뀐 경우(`laneChanged`)엔 좌표가 같더라도 무조건
`node.position(...)` 을 재적용하도록 조건에 `laneChanged ||` 추가.

## 테스트 방법
1. 보드 툴바에서 grid snap 끄기.
2. 카드를 다른 상태 레인으로 드래그 → 확인 다이얼로그에서 확인.
3. 카드가 목표 레인 안에 정확히 위치하는지 확인 (이전엔 이전 레인
   쪽으로 되돌아갔음).
4. 페이지 새로고침 후에도 목표 레인에 남아있는지 확인 (DB 저장 좌표
   정합성).
5. grid snap 켠 상태로도 회귀 없는지 재확인.
6. `cd gui/frontend && npm run check` / `npm test -- --run` 통과.

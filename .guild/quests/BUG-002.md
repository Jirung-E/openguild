## 증상

GUI 를 새로 켜면 노드들이 이전 드래그 상태가 아닌 lane 한 가운데에 1열로 줄지어 표시됨.

## 초기 조사 (2026-05-17)

- `.guild/index.db` 의 `quest_positions` 에 데이터는 저장돼 있음 (25 rows, x/y 값 정상).
- `/api/quest-positions` HTTP 엔드포인트도 25개 정상 반환.
- `QuestBoard.svelte` 의 `init()` 에 의심 로직:
  ```js
  const x = p.x >= laneLeft && p.x < laneLeft + LANE_W
            ? p.x
            : laneLeft + LANE_W / 2;
  ```
  → `p.x` 가 현재 lane 범위 (`laneLeft .. laneLeft + LANE_W`) 밖이면 lane 중앙으로 clip.
- 그리고 position 매핑 실패 시 (`!pos`):
  ```js
  pos = { x: li * LANE_STRIDE + LANE_W / 2, y: ... };
  ```
  → 같은 lane 의 노드들이 모두 `lane 중앙 x` 에 1열로 쌓임.

## 추정 원인

다음 중 하나 (재현 후 확정):

1. **status 변경 후 lane clipping**: 노드 status 가 바뀌면 저장된 좌표가 새 lane 범위 밖
   → lane 중앙으로 clip → 같은 lane 의 여러 노드가 같은 x → 1열로 보임.
2. **신규 생성 quest 위치 미저장**: `quest new` 가 `quest_positions` 행을 만들지 않아
   `init()` 의 auto-arrange 분기 (column) 로 빠짐.
3. **`reindex` 자동 실행**: 어딘가에서 `reindex` 가 호출되어 `quest_positions` 가 wipe 됨.
   (현재 코드 상 자동 호출되는 곳 없음 — 확인 필요)
4. **사용자가 보는 길드 ≠ index.db 길드**: 다른 guild 디렉토리 사용 시 그 곳의 데이터가 비어
   있을 가능성.

## 재현 절차 (예정)

1. 새 guild 초기화: `openguild init --name test-pos /tmp/test-pos`
2. quest 3개 생성, 임의 위치로 이동.
3. 서버 정지 / 브라우저 닫기.
4. 서버 재시작, GUI 열기 → 위치 유지 여부 확인.
5. status 변경 후 (다른 lane) GUI 재시작 → 어떻게 표시되는지 확인.

## 가능한 수정 방향

- **`init()` clipping 로직 완화**: 좌표가 범위 밖이어도 lane 내 가까운 위치로만 보정
  (강제 중앙 clip 대신).
- **신규 quest 생성 시 자동 position 부여**: `create_quest` 가 빈 영역의 좌표를 산출하고
  `quest_positions` 에 INSERT.
- **`reindex` 가 position 을 보존**: file → SQL 재구축 시 `quest_positions` 삭제하지 않음
  (또는 별도 store 에 보관).
- **position 을 `.md` 에 저장**: file-as-truth 원칙대로 frontmatter 의 hidden 필드
  (`+++` 안 `[board] x = 162, y = 108`) 로 옮김. reindex 안전.

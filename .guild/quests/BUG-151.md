# [installer] GUI 자동업데이트 시 openguild-server 가 구버전으로 방치됨

사용자 질문("GUI에서 업데이트할 때 CLI랑 서버도 같이 업데이트되지는
않음?")으로 조사하다 발견.

## 동작 분석 (gui/nsis/installer.nsi 기준)

Tauri 업데이터는 새 setup.exe 를 `/UPDATE`(+passive) 인자로 실행한다.
이 모드에서:

- **이전 설치 제거 안 함** — `PageLeaveReinstall` 이 `$UpdateMode = 1`
  이면 uninstall 없이 `reinst_done` 으로 직행. 기존 파일은 덮어쓰기만.
- **컴포넌트 페이지 skip** — passive 라 `MUI_PAGE_COMPONENTS` 가
  `SkipIfPassive` 로 건너뛰어져, 섹션 기본값이 그대로 적용된다:
  - `SecGui` 기본 체크 → GUI 갱신 ✅
  - `SecCli` 기본 체크 → **CLI(openguild.exe) 갱신 ✅**
  - `SecServer` 기본 **해제**(`Section /o`) → **server 미설치.** 업데이트
    모드는 기존 파일을 지우지도 않으므로, 처음 설치 때 서버를 선택했던
    사용자의 `openguild-server.exe` 는 **구버전 그대로 남는다** ❌
  - `SecPath` 기본 체크 → PATH 재확인(이미 있으면 no-op, 무해)

즉 GUI 자동업데이트 후 GUI/CLI 는 새 버전, 서버만 구버전인 **버전
스큐**가 조용히 발생한다. 스키마가 바뀐 릴리즈면 구버전 서버가 신버전
길드 DB 를 여는 조합(BUG-041/schema-ahead 류)이 그대로 재현될 수 있다.

부수 관찰: 반대로 처음에 CLI 를 해제하고 설치한 사용자는 업데이트 시
CLI 가 기본 체크라 새로 생긴다(경미 — 유해하진 않음).

## 수정 방향 (검토)

NSIS 설치 시 각 섹션의 선택 상태를 레지스트리(UNINSTKEY 아래 등)에
기록하고, `.onInit`(또는 컴포넌트 페이지 pre)에서 `/UPDATE` 모드일 때
이전 선택을 읽어 `SectionSetFlags` 로 복원 — "설치돼 있던 컴포넌트만
그대로 갱신"이 되게 한다. 간단 대안: `/UPDATE` 모드에선 `$INSTDIR` 에
`openguild-server.exe` 가 이미 존재하면 SecServer 를 강제 활성화
(파일 존재 = 이전에 선택했다는 증거 — 레지스트리 없이도 동작).

## 테스트 방법

1. 구버전 installer 로 서버 포함 설치 → 신버전 setup.exe 를
   `/UPDATE /P` 로 실행 → `openguild-server.exe --version`(또는 파일
   버전)이 신버전인지 확인.
2. 반대 케이스: 서버 없이 설치 → 업데이트 후에도 서버가 새로 생기지
   않는지 확인.

## 문제

`rule delete` · `quest comment remove`(`--force` 없이), `library delete`(`--yes` 없이)는 확인을 묻는다. 터미널이 없으면(AI · 스크립트 · 플러그인 훅) 묻지 못하고 **취소하는데 exit code 가 0** 이다.

```
$ openguild rule delete x </dev/null; echo $?
규칙 'x' 을 삭제할까요? (y/N) (취소)
0
```

부르는 쪽은 성공으로 읽는다 — 지웠다고 믿고 다음 단계로 간다. `quest delete` 는 `--yes` 가 없으면 거부하고 실패로 끝나는 것과도 다르다.

## 고칠 것

- 터미널이 없어서 취소된 것은 0 이 아닌 코드로 끝낸다. 사람이 `N` 을 눌러 취소한 것도 같게 할지 정한다.

## 고친 것

- 네 곳(`quest/campaign comment remove`, `rule delete`, `library delete`, `library folder delete`)의 확인을 `confirm_delete` 하나로 모았다.
- **답이 아예 없으면(입력 끝)** 지우지 않고 오류로 끝낸다(exit 1): "확인할 답이 없어 지우지 않았습니다 — 터미널 없이 부를 때는 --force 를 붙이세요".
- 사람이 `N`(또는 그냥 Enter)을 누른 것은 지금처럼 취소 · exit 0 — `rm -i` 와 같다. `yes | …` 처럼 파이프로 `y` 를 넣는 스크립트는 그대로 된다. `y` / `yes` 는 대소문자 무시(예전엔 명령마다 달랐다).
- 스킬의 함정 설명을 새 동작으로 고쳤다.

## 확인

- 시험 1개(답 없음 · y · YES · n · Enter).
- 시험용 길드: `rule delete … </dev/null` → exit 1, 안 지워짐. `echo n |` → (취소) exit 0. `echo y | library delete` → 지워짐.

## Test plan

- 터미널에서 `openguild rule delete <이름>` 을 플래그 없이 실행해 묻는 화면이 예전과 같은지, N 이면 취소되는지 본다.

## 무엇

줄에 `with = ["subject", "parent", "campaigns"]` 처럼 적으면 길드가 읽어서 함수 인자로 넘긴다([[BOOK-004]]).

## 할 것

- 문서 종류별 연결 관계 표(퀘스트 → parent, campaigns … / 캠페인 → quests … 등). 이벤트별로 쓸 수 있는 `with` 는 대상 종류에서 나온다.
- 못 쓰는 이름은 불러올 때 **쓸 수 있는 목록과 함께** 오류.
- `openguild plugin events` 가 이벤트별 `with` 를 보여 준다.
- `when` 에서도 이 데이터를 쓸 수 있게 넘긴다.
- 허용 화면에 "퀘스트를 읽음" 같은 표시를 위한 정보를 낸다.

## 확인

- `comment.added` 에서 `with = ["subject"]` + `when "subject.tags" = "notify"` 로 notify 퀘스트의 댓글만 걸러진다(지금은 불가능).

## 구현 / 확인한 것

- 줄에 `with = ["subject", "parent"]` 를 적으면 그 함수는 `fn 이름(e, subject, parent)` 로 받는다. 인자 수가 안 맞으면 적재 때
  **그 모양을 적어** 알려 준다(`fn on_comment(e, subject, parent)` 처럼).
- 받을 수 있는 것은 **대상의 종류**가 정한다(`related::RELATIONS`) — 퀘스트: `subject`·`parent`·`children`·`prereqs`·
  `campaigns`, 캠페인: `subject`·`quests`, 도서관 문서·규칙: `subject`. 나머지 대상(폴더·타입·상태·태그·노트·백업)에는 없다.
  댓글·첨부처럼 대상 종류가 여럿인 이벤트는 그 종류의 것을 모두 적을 수 있고, 실제 대상에 없는 것은 `null` 로 온다.
- **파일에서 읽는다**(`plugins::related`). 전달은 mutation 이 끝난 뒤 별도 스레드에서 도는데, 거기서 캐시(index.db)를 비동기로
  부르는 대신 진리원인 `.guild/` 파일을 동기로 읽는다 — 캐시가 늦어도 틀리지 않는다. 한 이벤트 안에서는 같은 것을 한 번만 읽는다.
- `openguild plugin events` 가 이벤트마다 `with` 로 받을 수 있는 것과 pre 여부를 보여 준다(외우지 않게). 허용 화면의 줄에는
  "읽음: subject" 가 붙는다.
- 예제 `telegram-quest-status` 가 이걸 쓴다 — 댓글 알림도 그 **퀘스트의 태그**로 거른다. 지금까지 못 하던 것이고, 설정 도움말의
  "댓글에는 적용 안 됨" 도 지웠다.
- 시험: 적재 검사(받을 수 없는 것 → 쓸 수 있는 목록, 중복, 동작 줄 금지, 인자 수), 파일에서 읽은 관계(부모·하위·선행·캠페인,
  캠페인의 퀘스트, 없는 것은 null), 그리고 **실제 이벤트로** "notify 태그 퀘스트의 댓글만" — 런타임이 데이터를 안 넘기면 실패함을
  확인. 배포 예제를 실제 페이로드에 태우는 시험도 `with` 를 넘긴다.
- 실제 바이너리(스크래치 길드): `with = ["subject", "campaigns"]` 로 태그·연결 캠페인 수를 받아 notify 퀘스트의 댓글만 기록.

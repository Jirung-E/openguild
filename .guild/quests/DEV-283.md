DB 투영 불변식(BOOK-001) 구현 — 역류 경로 B1. BUG-145의 근본 수정.

incremental 시동 sync와 상세 lazy refresh가 파일 mtime을 근거로
frontmatter `updated_at`을 다시 쓰던 경로를 폐지한다. git checkout/pull은
내용이 같아도 mtime을 바꾸므로, 캐시가 tracked 파일을 변조하는 구조 자체를
없애야 한다.

## 결정

- quest와 campaign 모두 동기화/새로고침 중 tracked 파일을 쓰지 않는다.
- mtime은 재파싱 후보 감지와 cached mtime 갱신에만 사용한다.
- title, 본문, 상태, `updated_at`을 포함한 권위 값은 파일에서 DB로만 투영한다.
- DB의 `updated_at`이 파일과 다르면 파일을 고치는 대신 DB를 파일 값으로 복구한다.

## 트레이드오프

외부 편집기가 본문만 바꾸고 frontmatter `updated_at`을 갱신하지 않으면,
내용은 DB에 반영되지만 표시되는 수정 시각은 이전 값으로 유지된다. 파일을
유일한 진리원으로 두고 `index.db`를 완전히 폐기가능하게 만들기 위해 의도한
정책이다.

## 테스트 방법

1. `cargo test -p openguild-core incremental`
2. `cargo test --workspace --release`
3. 테스트 길드에서 quest/campaign 파일의 mtime만 바꾼 뒤 앱 또는 CLI를 열고,
   해당 tracked 파일에 diff가 생기지 않는지 확인한다.
4. DB의 `updated_at`만 임의로 오래된 값으로 만든 뒤 sync하여 파일은 그대로이고
   DB가 frontmatter 값으로 복구되는지 확인한다.

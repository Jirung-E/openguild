## 요청

페이지 안에서 글자를 찾는 기능(Ctrl/Cmd+F)이 필요하다.

## 지금 상태

- **Tauri 데스크탑에는 찾기가 아예 없다.** WebView 는 브라우저의 기본 찾기
  UI 를 제공하지 않는다.
- 웹/서버 모드에서는 브라우저 기본 찾기가 동작한다.
- 글로벌 검색 팔레트(`SearchPalette`)는 **단축키가 없다** — 타이틀바/Nav 의
  길드 pill 을 마우스로 눌러야만 열린다. 즉 `Ctrl/Cmd+F` 는 비어 있다.
- 퀘스트 목록은 전부 DOM 에 렌더된다(가상 스크롤 없음).
- 보드는 노드가 DOM 이지만 transform 된 월드 안에 있어, 일치 항목으로 가려면
  스크롤이 아니라 **뷰포트를 옮겨야** 한다.

## 정한 것 (admin)

| 질문 | 결정 |
|------|------|
| 범위 | **문서형 화면부터** — 퀘스트/캠페인 상세, 규칙, 도서관, 작업기록. 보드 제외 |
| 웹 모드 | **양쪽 다 우리 것으로** (브라우저에서도 가로챈다) |
| 팔레트 단축키 | 이번엔 안 한다 |

## 설계 메모

- **DOM 을 건드리지 않는다.** `<mark>` 를 끼워 넣으면 Svelte 가 소유한
  DOM 을 침범해 재렌더와 충돌한다. CSS Custom Highlight API
  (`CSS.highlights` + `::highlight()`)로 Range 만 칠한다. 지원 여부를 먼저
  확인하고, 없으면 대안을 정한다.
- 가로채는 곳에서만 `preventDefault` 한다 — 우리 찾기가 없는 화면에서까지
  삼키면 웹 모드에서 네이티브 찾기가 사라져 오히려 퇴보다.
- 입력 중(textarea/CodeMirror)에는 편집기 자체 찾기와 겹치지 않게 할지 판단.

## 테스트 방법

1. 퀘스트 상세에서 Ctrl+F → 본문·댓글의 글자가 강조되고 개수가 보인다.
2. Enter / Shift+Enter 로 다음·이전, Esc 로 닫기.
3. 화면 밖 일치 항목으로 이동하면 스크롤이 따라간다.
4. 규칙·도서관·작업기록에서도 같게 동작.
5. 보드/목록에서는 웹 모드 기준 네이티브 찾기가 그대로 남는다.

## 구현

`Ctrl/Cmd+F` → 우상단에 작은 찾기 바. 입력, `N/M` 개수, 이전/다음(↑↓),
닫기(✕). Enter = 다음, Shift+Enter = 이전, Esc = 닫기.

### DOM 을 건드리지 않는다

일치 항목을 `<mark>` 로 감싸는 흔한 방법은 **여기서 못 쓴다** — Svelte 가
소유한 DOM 에 남의 노드를 끼워 넣는 것이라, 그 부분이 재렌더되는 순간 서로
어긋난다. `Range` 만 만들어 두고 CSS Custom Highlight API 로 칠한다
(`CSS.highlights` + `::highlight()`). 문서는 그대로다.

이 미리보기(Chromium)에서 API 동작을 확인했다. **Tauri 는 WKWebView 라
여기서 검증되지 않는다** — 없을 때는 칠하지 않고 **이동만** 한다(찾기가
통째로 죽는 것보다 낫다).

### 문단 경계

텍스트 노드를 그냥 이어 붙이면 앞 문단 끝 "…abc" 와 다음 문단 시작 "def…"
가 "abcdef" 로 잡힌다. 화면에서는 붙어 있지 않은 글자다. 블록 태그에서
끊어 **문단 단위**로 모은다. 반대로 한 문단 안의 인라인 마크업
(`**굵게**`)은 이어 붙여야 화면에서 보이는 대로 찾힌다 — 그래서 한 일치가
여러 텍스트 노드에 걸칠 수 있고, Range 가 그걸 넘어간다.

### 가로채는 곳에서만 가로챈다

`isFindablePath` 가 true 인 화면에서만 `preventDefault` 한다. 어디서나
삼키면 **웹 모드에서 네이티브 찾기가 그 화면에서 통째로 사라져** 오히려
퇴보다. 실제로 보드에서 `Cmd+F` 를 보내면 바가 안 열리고 기본 동작도 안
막힌다(실측).

## 구현 중 밟은 것 — `$effect` 무한 루프

질의가 바뀌면 다시 찾도록 `$effect` 안에서 `recompute()` 를 불렀더니
`effect_update_depth_exceeded` 로 터졌다. `recompute()` 는 `matches`/
`current` 를 **쓰는데**, 그 안의 `paint()`/`revealCurrent()` 가 같은 값을
**읽는다** — 이펙트가 자기가 쓴 상태를 의존성으로 잡아 무한히 다시 돈다.
입력 이벤트(`oninput`)에서 직접 부르도록 바꿨다.

## 검증

- 단위 테스트 22건. 문단 경계를 넘지 않는지, 인라인을 가로질러 찾는지,
  겹치는 일치를 안 만드는지, 여러 노드에 걸친 Range 가 맞는지, 경로 게이트.
- 화면(퀘스트 상세): "퀘스트" → `3/4`, 나머지 3개는 노랑·현재 1개는 강조색.
  Enter 로 1→2→4, Shift+Enter 로 3, 끝(6/6)에서 Enter 면 1/6 로 순환.
  Esc 로 닫으면 강조가 남지 않는다.
- 규칙 화면에서도 열리고, 보드에서는 안 열린다(기본 동작도 안 막음).
- 새 탭에서 전 과정을 다시 밟아 **콘솔 오류 0건** 확인.

## 못 본 것

- **Tauri 실기.** CSS Custom Highlight API 지원과 `Cmd+F` 가로채기가 WKWebView
  에서 같은지 확인이 필요하다.
- 캠페인 상세·작업기록은 경로 게이트만 확인했고 실제 검색은 안 해 봤다
  (같은 컴포넌트·같은 경로라 다를 이유는 없다).

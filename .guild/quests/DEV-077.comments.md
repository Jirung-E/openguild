## 변경
Quest Board 의 그룹 정렬 (arrangeNodesGrouped) — cluster 의 y 좌표 점유 방식 개선.

## 이전 (회귀 위험 가능 — UI 확인 필요)
```
isolated      (lane 별 row 0..N)
[1 row gap]
cluster A     (모든 참여 lane 의 row N+1..N+hA)
[1 row gap]
cluster B     (모든 참여 lane 의 row N+hA+2..)
...
```
→ cluster A 가 lane 1,2 만 써도 cluster B 는 무조건 그 아래.

## 이후
각 lane 의 "다음 빈 row" 를 따로 추적:
- cluster 시작 row = 참여 lane 들의 next-row 의 max.
- 다른 lane 만 사용하면 더 위에 들어감.
- 같은 lane 공유하는 cluster 끼리는 순차 (1 row gap 으로 분리).

예: cluster A (lane 1, 2) → row 0 부터. cluster B (lane 3, 4) → 도 row 0 부터 (lane 안 겹침). cluster C (lane 2, 3) → max(A 의 lane 2 next, B 의 lane 3 next) 부터.

## 본문의 두 번째 요청 — 새 quest 추가 시 위에서부터 채움
본 라운드 범위 밖. 별도 quest 권장 — `quest new` 의 position 결정 path (gui/src/commands.rs + frontend NewQuestModal) 가 다음 빈 row 계산.

## 테스트 (사용자 GUI 검증 필요)
1. 두 그룹: A (lane 1, 2 의 노드 만), B (lane 3, 4 의 노드 만).
2. Group 정렬 트리거 → 두 그룹 모두 row 0 부터 시작 (y 같음).
3. cluster C 가 lane 2 공유 → C 가 A 아래로.
4. 회귀: isolated + 단일 cluster 케이스도 기존과 동일 (lane 모두 같은 시작 row).
5. cross-lane edge 인 single-member (BUG-020) 도 cluster 로 분류 정상.

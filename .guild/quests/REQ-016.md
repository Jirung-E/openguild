## 요청

도서관의 검색 입력란과 검색 옵션이 **한 줄에 다 있어 입력란이 너무 좁다.**
입력란만 한 줄을 차지하고, 나머지(첨부 이름 포함 체크박스 · 정렬 셀렉터 ·
정렬 방향 버튼)는 **아래 줄로** 내린다. 총 2줄.

## 현황

`routes/library/+page.svelte` 의 `.search-row` 한 줄에 네 요소가 들어 있다.

```
[ 제목/본문 검색 ] [☐ 첨부 이름 포함] [이름 ▾] [↑]
```

`.search-input` 이 `flex: 1` 이라 남는 폭만 가져가는데, 나머지 셋이
차지하는 폭이 커서 입력란이 눌린다. UI 배율을 올리면 더 심해진다
([[BUG-254]] 스크린샷에서 그 상태가 보인다).

## 기대 형태

```
[ 제목/본문 검색                                  ]
[☐ 첨부 이름 포함]              [이름 ▾] [↑]
```

## 정할 것

- 둘째 줄의 정렬 — 체크박스는 왼쪽, 정렬 컨트롤은 오른쪽으로 밀지
  (`justify-content: space-between`) 아니면 전부 왼쪽에 붙일지.
- 규칙 페이지도 검색 입력이 있는데([[REQ-013]]) 거긴 옵션이 없어 한 줄로
  충분하다 — 같이 바꿀 필요는 없어 보이나 확인 필요.

## 수정

CSS 만 고쳤다. 마크업은 그대로다.

```css
.search-row            { flex-wrap: wrap; }
.search-row .search-input { flex: 1 1 100%; }   /* 자기 줄을 독차지 */
.search-row .sort-group   { margin-left: auto; } /* 둘째 줄 오른쪽 끝 */
```

`flex-basis: 100%` 면 입력란이 줄을 꽉 채우고 뒤 요소를 다음 줄로 밀어낸다 —
개수·순서에 무관하게 항상 2줄이 된다.

마크업의 `.search-row` 는 **두 곳**(트리 보기 사이드바 / 아이콘 보기 헤더)인데
CSS 규칙은 하나를 공유하므로 한 번에 고쳐진다.

## 검증 (브라우저 실측, 1400×900)

**트리 보기 사이드바** — 여기가 문제의 핵심이었다.

| | 줄 높이 | 입력란 폭 | 체크박스 | 정렬 |
|---|---|---|---|---|
| 수정 전 | 45.4 | **51.6** | 89.0 | 91.2 |
| 수정 후 | 78.2 | **243.0** | 89.0 | 91.2 |

243px 짜리 줄에서 입력란이 51.6px 였다 — 나머지 180px 를 체크박스와 정렬이
가져가고 있었다. 이제 입력란이 줄 전체(243px)를 쓴다. **4.7배**.

**아이콘 보기 헤더**: 입력란이 첫 줄 단독(1004px), 둘째 줄에 체크박스(왼쪽) +
정렬(오른쪽 끝). 정렬 그룹의 오른쪽 모서리가 줄의 오른쪽 모서리와 일치하는
것을 좌표로 확인했다(오차 <1.5px).

**배율 200%** 에서도 같은 2줄 배치가 유지된다.

## 테스트 방법

1. 도서관을 연다.
2. 검색 입력란이 **한 줄을 통째로** 쓰는지 본다.
3. 그 아래 줄에 '첨부 이름 포함' 이 왼쪽, 정렬 셀렉터·방향 버튼이 오른쪽 끝에
   붙어 있는지 본다.
4. 좌측 상단의 보기 토글(☰ / ▦)로 두 뷰를 오가며 둘 다 같은지 본다.
5. 설정에서 UI 배율을 200% 로 올려도 2줄이 유지되는지 본다.

## 무엇

`/campaigns/new` 페이지를 없애고, 퀘스트처럼 **모달**로 만든다.

## 왜

admin: *"왜 '새 퀘스트'는 팝업이면서 캠페인은 별도 페이지임? 통일할 필요 없을지?"*

[[DEV-011]] 이 캠페인 화면 묶음을 만들 때 `/campaigns/new` 로 잡았고, 퀘스트 생성 모달은
나중에 따로 생겼다. **둘을 다르게 하기로 한 기록은 없다** — 시기가 달랐을 뿐이다.

캠페인 입력은 제목·기간·본문 셋뿐이라 페이지 한 장을 쓸 이유가 없고, 만들다 그만두면 목록으로
되돌아가는 것도 모달이 더 자연스럽다.

## 할 것

- `NewCampaignModal` — 퀘스트 모달(`NewQuestModal`)의 구조·버튼 관용구를 따른다.
- 부르는 곳: 홈의 캠페인 추가 버튼, `/campaigns` 목록.
- `/campaigns/new` 라우트는 남길지 정한다 — 북마크·에이전트 링크가 있으면 목록으로 보내고 모달을 연다.
- 만든 뒤 이동: 지금은 상세로 간다. 모달에서도 같게.

## 구현

- `NewCampaignModal` — 새 퀘스트 모달과 같은 껍데기(오버레이 위 정렬·배경 스크롤 잠금·Esc 닫기).
  입력은 그대로 제목·기간·본문. `create` 가 본문을 안 받아 본문이 있으면 생성 뒤 한 번 더 저장하는
  동작도 그대로 옮겼다.
- 부르는 곳: 홈의 캠페인 추가, `/campaigns` 목록.
- `/campaigns/new` 는 **남겼다** — 북마크·에이전트 링크가 가리킬 수 있다. 목록(`?new=1`)으로
  보내고 모달을 열어 준다.
- 페이지 시절 한국어로 박혀 있던 문구를 옮기며 **i18n** 으로 바꿨다(`ncm.*`).
- 좁은 화면에서는 시작·종료일이 한 칸씩 내려간다 — 나란히 두면 날짜 입력기가 눌린다.

## 확인한 것

- 화면 시험 4개: 제목이 비면 못 만든다 / 만들면 닫고 만들어진 캠페인을 넘긴다 / 본문이 있으면
  생성 뒤 한 번 더 저장 / 실패하면 안 닫히고 이유가 남는다.
- 실제 브라우저(테스트 길드 웹): 목록에서 모달이 뜨고 Esc 로 닫히며 목록에 그대로 남는다 /
  옛 `/campaigns/new` 로 들어가면 `/campaigns?new=1` 로 바뀌며 모달이 열린다 / 제목만 넣고
  만들면 상세(C-014)로 이동. 콘솔 오류 없음. 확인용 캠페인은 지웠다.

## 테스트 방법

- 홈·목록 양쪽에서 모달이 뜨고, 만들면 상세로 간다.
- Esc·바깥 클릭으로 닫히고 입력이 날아가도 목록이 그대로 남는다.
- 좁은 화면(400px)에서 모달이 잘리지 않는다.

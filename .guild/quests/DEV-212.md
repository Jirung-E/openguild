사용자 피드백(DEV-022 테스트): restore --at 이 journal 을 truncate 해서 복원 전 상태가 손실될 수 있음. 대화형 확인 대신, 파괴적 restore 직전에 **현재 상태를 새 백업(스냅샷)으로 자동 생성**하고 진행. 그러면 확인 프롬프트 없이도 복원 전 상태를 항상 되돌릴 수 있음.

동작:
- journal 이 non-empty(= 마지막 스냅샷 이후 미저장 변경 존재)인 상태에서 truncate 를 유발하는 restore(--at) 실행 시: 먼저 현재 상태를 스냅샷으로 떠서 백업 목록에 남긴 뒤 restore 진행.
- journal 이 비어있으면(현재 = 최신 스냅샷) 새 백업 불필요 → 그냥 진행.
- 비대화형/멱등이라 --yes 같은 확인 플래그 불필요.

참고: restore_snapshot 은 이미 .pre-restore/ 롤백 슬롯을 만들지만, 그건 단일 임시 슬롯이고 백업 목록에 안 남음. 이 quest 는 정식 backup 목록에 남는 스냅샷을 만들어 restore --to 로 복귀 가능하게 함. create_snapshot 자체가 journal 을 truncate 하므로 순서(현재 스냅샷 → restore)만 지키면 정합.
관련: DEV-022, DEV-210.

## 증상

admin: *"퀘스트 추가하면 자동정렬되는데 이거 뭐임"* / *"보드에서, 새 노드가
가장 앞으로 오는 느낌임."*

퀘스트를 하나 만들면 보드의 다른 노드들이 한 칸씩 밀린다. 새 노드는 레인
맨 앞(좌상단)을 차지한다.

## 원인 — 자동 배치가 **배열 순서**에 달려 있다

보드는 `questsApi.list(true)` 로 퀘스트를 받는다. 그 기본 정렬은 **`id DESC`**
(생성 역순, `services/quests.rs` 의 `vec![("id", false)]`)다. 즉 **방금 만든
퀘스트가 배열의 0번**이다.

`QuestBoard.svelte` 의 초기 적재는 저장된 위치가 없는 노드를 `autoCount` 로
3열 격자에 채우는데, 그 카운터가 `quests.forEach` 순서를 그대로 따른다.

```js
quests.forEach((q) => {
  let pos = posMap.get(q.id);
  if (!pos) {
    const n = autoCount.get(q.status_id) ?? 0;   // ← 배열 순서
    const col = n % 3, row = Math.floor(n / 3);
    ...
```

그래서 새 퀘스트가 **0번 칸**(레인 좌상단)을 가져가고, 같은 레인의 위치
없는 노드가 전부 한 칸씩 뒤로 밀린다. 사용자 눈에는 "정렬이 다시 됐다".

위치가 저장된 노드는 안 움직이므로, **손으로 옮긴 적 없는 노드만** 밀린다 —
그래서 더 종잡을 수 없어 보인다.

## 두 번째 어긋남 — 살아 있는 보드에 추가할 때의 x 좌표

보드를 켜 둔 채 퀘스트를 만들면 `handleFlash` 가 노드를 직접 꽂는데, x 를
**레인 한가운데**로 잡는다.

```js
const absX = li * LANE_STRIDE + LANE_W / 2;
```

초기 적재는 `COL_OFFSETS` 의 3열 중 하나에 놓는다. 두 경로가 서로 다른 배치
규칙을 쓰므로, 살아 있는 보드에 추가한 노드만 **열이 안 맞는 자리**에 선다.

## 할 것

- 자동 배치를 **안정된 키**(quest id 오름차순)로 돌린다. 새 퀘스트는 항상
  마지막 칸에 붙고 기존 노드는 자기 칸을 지킨다. 받은 배열의 정렬은 목록
  화면이 쓰는 것이므로 건드리지 않는다 — 보드가 자기 순서를 정한다.
- `handleFlash` 의 x 를 초기 적재와 **같은 규칙**으로 맞춘다.

## 테스트 방법

- 위치 없는 노드가 여럿인 레인에 퀘스트를 추가하면 **기존 노드의 칸이 안
  바뀐다**(추가 전후 좌표 비교).
- 새 노드가 초기 적재와 같은 열 좌표에 선다.

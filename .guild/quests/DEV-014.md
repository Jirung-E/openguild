현재 하드코딩 → 길드마스터가 prefix/color/name 편집 가능. 기본값 복원 버튼.

## 현재 상태

### Type
- 정의: `.guild/types/<PREFIX>.toml`
  ```toml
  prefix = "DEV"
  color = "#4A90D9"
  description = "일반 개발 작업"

  [counter]
  last_number = 50
  ```
- CLI: `openguild types` — **list 만** (prefix, color, description).
- GUI: meta API `list_quest_types` — board column header / quest 카드
  prefix 표시. 관리 UI 없음.
- 추가/변경/삭제 방법: `.toml` 파일 직접 편집 → reindex (GUI Admin 또는
  CLI).

### Status
- 정의: `.guild/statuses/<sort_order>-<slug>.toml`
  ```toml
  sort_order = 1
  name_en = "Open"
  name_ko = "게시됨"
  color = "#8B95A1"
  ```
- CLI: `openguild statuses` — list 만.
- GUI: meta API `list_quest_statuses` — board column 정의 / status badge
  색. 관리 UI 없음.
- 추가/변경/삭제: 파일 직접 편집 + reindex.

## 요구사항

Admin 페이지 (`/admin`) 에 두 섹션 추가:

1. **Quest Types**
   - 표: prefix / color (swatch + hex) / description / 사용 중 quest 수.
   - 액션: 추가 / 수정 (color / description) / 삭제.
   - 삭제 가드: 해당 prefix 를 쓰는 quest 가 있으면 차단.
   - prefix rename 은 quest slug cascade 라 **이 quest 범위 외** (별도).
   - 추가 시 prefix validation: 대문자 + 숫자, 3~6자 + 중복 거부.
   - "기본값 복원" 버튼 — DEV/BUG/REQ 시드 다시.

2. **Quest Statuses**
   - 표: sort_order / name_en / name_ko / color swatch / 사용 중 quest 수.
   - 액션: 추가 / 수정 (이름 / 색 / sort_order) / 삭제. sort_order 는
     직접 입력 또는 drag reorder.
   - 삭제 가드: 그 status 의 alive quest 가 있으면 차단.
   - **slug** (name_en 기반) 는 DEV-049 의 history / positions 의 참조
     키. rename 시 slug 도 바뀌면 history 깨질 위험:
     - 우선 추가 / 삭제 + name_ko / name_en display rename 만, slug 는
       frozen.
     - 또는 rename + history.status_slug migrate (별도 quest 후보).

## 구현 스케치

### Backend (core + gui)
- **`repo::types`** (현재 read 만) 에 write API:
  - `create_type(store, prefix, color, description?)` — 파일 write +
    types row insert.
  - `update_type(store, prefix, color?, description?)` — 파일 rewrite +
    types row update.
  - `delete_type(store, prefix)` — 사용 quest count > 0 면 `Err`. 파일
    삭제 + types row delete.
- **`repo::statuses`** 동일 패턴: `create_status` / `update_status` /
  `delete_status`. sort_order 변경 시 파일명 (`<sort_order>-<slug>.toml`)
  rename.
- Tauri admin commands: `admin_create_type` / `admin_update_type` /
  `admin_delete_type` + status 3개 + `admin_count_quests_by_{type,status}`.

### Frontend
- `/admin/+page.svelte` 에 `<section class="types">` /
  `<section class="statuses">`.
- 각 row inline 수정 (color picker + text) + 삭제 버튼.
- "+ 새 type / status" 모달 (NewQuestModal 패턴).
- 색은 `<input type="color">` + hex text 양방향.

### Migration / 호환성
- DB schema 변경 없음 — 파일 + 기존 reindex 흐름.
- mutation 후 자동 reindex 또는 in-place update.

## UX

- 삭제 가드 에러: 모달 / 알림 ("이 type 을 쓰는 quest N개가 있어 삭제할
  수 없습니다. 먼저 다른 type 으로 이동시키세요.").
- 색 변경 즉시 board / card 반영.
- 추가한 type 이 NewQuestModal dropdown 에 자동 노출 (meta API cache
  안 함).

- 사용 안 하는 type 삭제 → 파일 + DB 둘 다 제거.

- status 색 변경 → 카드 badge 색 즉시 변경.

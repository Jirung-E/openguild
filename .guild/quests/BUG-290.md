## 증상

admin: *"정의 만들기 버튼이 없는건 뭐임"*

태그 목록에서 **한글 태그에는 색·설명을 달 버튼이 없다.** 테스트 길드는 `리팩터링`,
`백엔드`, `보안` 처럼 태그 대부분이 한글이라, 대부분의 태그에 색을 달 방법이 없다.

## 원인 — 두 입구의 규칙이 다르다

| 입구 | 받는 이름 |
|---|---|
| 태그 붙이기(퀘스트·도서관·규칙 frontmatter) | 아무 문자열(공백으로 나눌 뿐) |
| 태그 색·설명(`.guild/tags/{이름}.toml`, `validate_tag_slug`) | **영문 소문자·숫자·`-`·`_`, 32바이트** |

색·설명은 이름이 **태그와 똑같아야** 붙는데, 붙일 수 있는 이름의 대부분을 거절한다. 이름이
그대로 파일명이 되기 때문으로 보이지만, 제한 이유를 적은 기록은 퀘스트([[DEV-068]])에도
코드에도 없다. [[DEV-392]] 의 화면은 이 제한에 맞춰 버튼을 숨겼을 뿐이라 이유도 안 보였다.

## 수정 — 막아야 하는 것만 막는다

이름이 파일명이 되므로 **파일명으로 위험한 것**만 거절한다.

- 빈 이름, 앞뒤 공백, 공백 문자 포함(태그는 공백으로 나뉘므로 애초에 못 붙인다)
- 경로·예약 문자 `/ \ : * ? " < > |`, 제어 문자
- `.` 으로 시작하거나 끝나는 이름(`.`, `..`, 숨김 파일, Windows 가 끝 점을 버림)
- Windows 예약 이름 `CON` `PRN` `AUX` `NUL` `COM1-9` `LPT1-9` (대소문자 무시)
- 길이는 **글자 수** 64자까지(파일명 255바이트 안에 한글 64자 + `.toml` 이 들어간다)
- **대소문자만 다른 정의가 이미 있으면** 거절 — macOS·Windows 기본 파일시스템에서 같은
  파일이다(`API.toml` 을 쓰면 `api.toml` 을 덮는다).

## 할 것

- core `validate_tag_slug` 교체 + 대소문자 충돌 검사(갱신은 같은 이름이면 허용).
- 화면(태그 목록)의 이름 검사를 같은 규칙으로.
- CLI `tag add` 도움말 문구.

## 확인한 것

- 코어 시험 4개: 붙일 수 있는 이름(한글·일본어·`v1.2`·`C++`·64자) 통과 / 파일명 위험 이름
  (공백·탭·경로·예약 문자·제어 문자·`.` `..` 숨김·끝 점·`CON` 류·65자) 거절 / 한글 정의가
  reindex 뒤에도 남고 삭제되면 파일도 지워짐 / `api` 가 있을 때 `API` 새로 만들기 거절, `api`
  갱신은 됨. 옛 규칙에서 4개 모두 실패, 대소문자 검사를 빼면 마지막 것이 실패.
- 화면 시험: 한글 태그에 버튼이 있고 그 이름으로 저장 / `a/b` 에는 버튼 없음.
- 실제 CLI(임시 길드): `tag add 리팩터링` 성공, `API` 는 "대소문자만 다른 태그 정의 'api'"
  로 거절, `a/b` 거절, reindex 뒤 목록에 남음, 삭제하면 파일 사라짐.
- 실제 브라우저(테스트 길드 웹): `리팩터링` 에 색·설명 저장 → 새로고침 뒤에도 색 유지 →
  삭제하면 다시 [정의 만들기]. 콘솔 오류 없음. 만든 정의는 지웠다.
- `just test` 전체 통과.

덧: `openguild tag list --table` 은 한글 이름에서 열이 어긋난다(글자 수로 폭을 잰다). 이
퀘스트 전에도 같았다 — 한글 이름을 받게 되며 더 자주 보일 것.

## 테스트 방법

- 한글 태그 `리팩터링` 에 색·설명을 달고, reindex 뒤에도 남는다.
- 위의 거절 대상이 전부 거절된다.
- `api` 정의가 있을 때 `API` 를 새로 만들면 거절, `api` 갱신은 된다.
- 한글 이름 정의를 삭제하면 파일이 지워진다.
- 화면: 한글 태그에 버튼이 보이고 저장된다.

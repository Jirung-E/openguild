방향 확정 + 구현 완료: 3안 중 "제거"(file-truth §1 충돌)와 "현행 유지+수동 버튼" 대신, **원칙대로 mutation 이 파일도 함께 갱신**하는 정공법 채택.

- create_quest / change_type(새 번호 부여 지점)이 sync_type_counter_file() 로 `.guild/types/{P}.toml` 의 last_number 를 즉시 갱신 — 파일 값이 더 크면 보존(단조 증가). 실패는 경고만(정합성은 DB counter+self-heal 이 담당, 파일은 백업/표시 값).
- reindex 에 counter 양방향 self-heal 추가: DB counter 를 max(number) 로 끌어올린 뒤 낡은 type 파일에 write-back — git pull/외부 편집 경로 커버. GUI reindex 버튼도 이 경로라 "GUI 로는 절대 갱신 안 됨" 문제 해소.
- `check counters --fix` 는 유지(수동 정비 수단) — 다만 정상 사용에선 더 이상 고칠 게 없음.
- 기존 테스트 1건은 "create 후 파일이 낡아 --fix 가 1건 잡음" 기대였는데 새 동작(0건)으로 갱신. 신규 테스트: create 가 파일 counter 갱신 + 더 큰 파일 값 보존.

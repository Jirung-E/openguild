## 왜

"기록이 퀘스트 본문에만 있고 자기 퀘스트가 없는 것" 을 훑어 나온 것들. 반박됐던
것도 **코드 상태는 그대로**라 남겨두면 안 된다.

- **`run` 시한이 손자를 안 거둔다.** 훅이 백그라운드로 던진 프로그램은
  `child.kill()` 로 안 죽는다. "시한이 지나 중단했습니다" 라고 보고해 놓고 실제로는
  계속 도는 것이 제일 나쁘다.
- **동의 파일을 잃을 수 있다.** `~/.openguild/plugin-consent.json` 에는 이 기계의
  **모든** 동의가 들어 있는데, 파싱 실패를 빈 상태로 갈음하고 그대로 덮어썼다 —
  한 번 깨지면 곧 "동의 전부 소멸" 이고 사용자는 왜 다시 물어보는지 모른다.
  쓰기도 `fs::write` 직접이라 중간에 죽으면 파일이 반쯤 남는다.
- **`PluginStatus.notes` 가 죽은 필드다.** [[DEV-383]] 이 `no_guild` 로 갈아탄 뒤
  아무도 안 채우고 아무도 안 그리는데 Rust·TS 양쪽 타입에 남아 있다. 다음 사람에겐
  "여기 한국어 문장을 실으면 되는 자리" 로 보인다.

함께: 버전을 0.6.0-beta 로 올리고, 이번에 밟은 지뢰 둘을 규칙으로 옮긴다.

## 테스트 방법

- 손자를 백그라운드로 띄우는 훅이 시한에 걸리면 손자도 멈춘다.
- 깨진 동의 파일은 덮어쓰지 않고 오류로 알린다. 읽기는 여전히 빈 상태(안전).
- 동의 쓰기 뒤 임시 파일이 안 남는다.

## 결과

**손자까지 거둔다.** 자식을 자기 프로세스 그룹의 리더로 띄우고(`process_group(0)`),
시한이 지나면 `kill -KILL -pgid` 로 그룹째 죽인다. `libc` 를 새로 들이지 않으려고
`kill(1)` 을 쓴다 — POSIX 에서 음수 PID 는 프로세스 그룹을 뜻한다. Windows 는
프로세스 그룹이 없어 job object 가 필요한데 그건 별개 작업이라 기존 동작을 둔다.

시험은 셸이 손자를 백그라운드로 띄우고 자기는 자게 해 놓고, 돌아온 **뒤로** 손자가
쓰던 파일이 더 안 커지는지 본다. 시간만 재면 "포기하고 돌아왔다" 까지만 보인다.

**동의 파일 둘.** 못 읽는 파일은 **덮어쓰지 않는다**(오류로 알린다 — 사용자가 파일을
보고 판단할 기회를 준다). 쓰기는 임시 파일 + `rename` 이라 중간에 죽어도 예전 파일이
남는다. 읽기 전용 경로는 여전히 빈 상태로 떨어진다 — 그쪽은 "아무것도 안 돈다" 라
안전한 방향이다.

**`notes` 제거.** Rust·TS 양쪽에서 없앴다. 프런트 시험이 `'notes' in got === false`
를 확인한다 — 필드가 다시 생기면 걸린다.

### 되돌림 시험 4건 물었다

프로세스 그룹 제거(손자가 계속 돎) · 깨진 파일을 빈 상태로 갈음 · tmp+rename 없이
직접 쓰기 · (예제·body_env 는 [[DEV-384]] 에서 확인).

## 함께 한 것

**버전 0.6.0-beta.** 다섯 곳 — core/cli/server/gui 의 Cargo.toml,
`gui/frontend/package.json`, `skills/.../plugin.json`([[BUG-261]] 의 검사가 강제).

**규칙 둘을 `AGENTS.md` 로 옮겼다.** 퀘스트 본문에만 적어 두면 그 퀘스트가 닫히는
순간 사라진다.

- `just test` 는 **커밋 직전**에 돌린다 — 앞에서 통과한 것은 커밋되는 상태의
  증거가 아니다([[DEV-383]] 이 그래서 깨진 채 머지됐다).
- 되돌림 시험의 원복은 **백업 파일에서** 한다 — `git checkout --` 은 아직 커밋 안
  된 작업까지 지운다.

## 증상

확인 대화상자가 떠도 **포커스가 뒤 페이지에 남는다.**

- 대화상자를 열어도 아무것도 포커스되지 않는다.
- Tab 을 누르면 대화상자 안이 아니라 **뒤에 깔린 페이지**를 돌아다닌다.
- 키 처리가 `<svelte:window {onkeydown} />` 이라 포커스가 어디 있든 Enter/Esc 가
  먹는다 — 뒤 페이지의 다른 버튼에 포커스가 있어도 **Enter 가 "확인"으로 간다.**
- 닫은 뒤 원래 있던 버튼으로 포커스가 안 돌아온다.

## 왜 중요한가

`ConfirmDialog` 는 앱 전체의 되돌리기 어려운 동작에 쓰인다 — 퀘스트 삭제, 프리셋
삭제, 그리고 [[DEV-379]] 의 "이 길드를 전부 허용"(임의 코드 실행 동의). 그중
어느 것도 **스쳐 지나가는 Enter 로 눌려서는 안 되는** 것들이다.

`gui/frontend/src/lib/components/ConfirmDialog.svelte` 에 `focus` 호출이 하나도
없다(확인함). 플러그인 화면에서 발견했지만 플러그인 문제가 아니다.

## 고칠 방향

- 열릴 때 대화상자(또는 취소 버튼)에 포커스.
- Tab 을 대화상자 안에 가둔다.
- 키 처리를 window 가 아니라 대화상자 노드로 옮긴다.
- 닫을 때 열기 전 요소로 포커스 복귀.

`<dialog>` 요소의 `showModal()` 이 이 넷을 대부분 공짜로 준다 — 다만 앱의 기존
오버레이 스타일과 어떻게 맞출지 확인이 필요하다.

## 고침 (2026-10-07)

- 새 부품 `modalFocus`(`lib/actions/modal-focus.ts`) — 대화상자 노드에 건다.
  - 열릴 때 `[data-autofocus]` → 첫 버튼 → 대화상자 순으로 포커스.
  - Tab / Shift+Tab 은 대화상자 안에서만 돈다. 클릭 등으로 밖에 간 포커스도 다시 안으로.
  - 닫힐 때 열기 전 요소로 포커스를 돌려준다.
- `ConfirmDialog` 에 붙였다.
  - 키를 window 가 아니라 대화상자에서만 받는다 — Esc 만 직접(밑에 깔린 모달까지 닫히지 않게 올려 보내지 않음),
    Enter 는 포커스된 버튼이 스스로 누른다.
  - **위험한 동작(`danger`)은 '취소'에서 시작**한다 — Enter 를 한 번 더 쳐도 지우지 않는다. 그 밖은 '확인'에서.
  - 제목 · 문구를 화면 읽기 프로그램에 잇는다(`aria-labelledby` · `aria-describedby`).
- `<dialog>` 의 `showModal()` 은 쓰지 않았다 — 기존 오버레이 · 스크롤 잠금 · 배율 스타일을 그대로 두려고.

## 시험

- `ConfirmDialog.test.ts` 5개: 시작 버튼, 뒤 페이지 Enter 무시, Tab 가둠, 밖으로 나간 포커스 복귀, Esc 와 닫은 뒤 복귀.
  고치기 전 대화상자로 돌리면 4개가 실패하는 것을 확인했다.

다시 안고치냐" 로 짚었다.

**원인**

1. 처음 고침은 공통 확인 창(`ConfirmDialog`) **하나에만** 들어갔다. 퀘스트 삭제 · 타입 변경 · 연관 고르기, 캠페인
   연결, 보드의 "변경" 확인 · 보드 설정, 관리 상태 · 타입 추가 · 삭제, 환영 화면 확인, 새 퀘스트 · 새 캠페인, 편집 충돌,
   명령 팔레트는 각자 만든 창이라 포커스 관리가 없었다.
2. Tab 을 끝에서만 직접 옮기고 나머지는 브라우저에 맡겼다. **맥 앱(WKWebView)은 기본 설정에서 Tab 이 버튼을
   건너뛴다** — 버튼만 있는 확인 창에서 Tab 이 뒤 페이지 입력칸으로 나갔다.
3. 모달 위에 모달이 뜨면 둘이 서로 포커스를 끌어갔다.

**고침**

- `modalFocus` — Tab 을 **언제나** 직접 옮긴다(안쪽에서 이미 쓴 Tab 은 그대로). **맨 위 모달만** 포커스를 지킨다.
  `onEscape` 를 주면 Esc 로 닫고 밖으로 안 올려 보낸다.
- 모달 19곳 모두에 건다. 되돌리기 어려운 창(퀘스트 삭제 · 타입 변경 · 관리 삭제 · 환영 화면 지우기)은 **취소에서
  시작**한다. 새 퀘스트 · 새 캠페인 · 명령 팔레트는 입력칸에서.
- 보드의 떠 있는 퀘스트 카드는 모달이 아니라 뺐다.

**시험** `modal-focus.test.ts` 5개 — 버튼만 있는 창에서 Tab 을 직접 옮김, 안쪽에서 쓴 Tab 은 그대로, 모달 위 모달,
Esc, 닫으면 제자리. 예전 구현으로 돌리면 3개가 실패한다. `ConfirmDialog.test.ts` 5개 그대로 통과.

확인(헤드리스 WebKit): 퀘스트 삭제 창이 "취소" 에서 시작, Tab 이 창 안에서만 돈다(삭제 → × → 취소 → 삭제), Esc 로
닫힌다. 새 퀘스트 창은 제목 칸에서 시작. 보드 설정에서 Tab 30번 뒤에도 창 안. 페이지 오류 없음.

## 테스트 방법

**맥 앱에서**(WKWebView — 이번 원인이 있던 곳) 아래 창마다:
퀘스트 상세 [삭제] · 타입 변경, 보드 [보드 설정] · 레인 이동 확인, 관리 → 상태 / 타입 [추가] · 삭제, 도서관 삭제 확인.

1. 창이 열리면 포커스가 창 안에 있다(위험한 동작은 "취소" 에).
2. Tab · Shift+Tab 을 여러 번 — 창 밖(뒤 페이지)으로 나가지 않는다.
3. Enter 는 포커스된 버튼만 누른다 — 위험한 창을 열자마자 Enter 를 쳐도 지워지지 않는다.
4. Esc 로 닫힌다. 모달 위 확인 창에서 Esc 는 확인 창만 닫는다.

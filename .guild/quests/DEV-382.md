## 왜

admin 지적: **"버튼 모양이 다른 ui들과 현저히 다름."**

플러그인 설정 화면에 `class="ghost"` / `class="primary"` 라고 썼는데 이 저장소에는
그런 클래스가 **없다.** 그래서 브라우저 기본 버튼이 그대로 나왔고, 회색 덩어리
하나만 다른 UI 와 따로 놀았다.

## 왜 아무도 못 잡았나

Svelte 컴파일러는 **반대 방향만** 경고한다 — 정의했는데 안 쓰는 selector 는
알려주지만, 쓰는데 정의가 없는 쪽은 아무 말이 없다. 타입 검사도, 기존 가드 8종도
이 방향을 안 본다. 결국 **눈으로 볼 때까지 아무도 모른다.**

앞선 리뷰가 6개 관점으로 32건을 냈지만 전부 core/cli/server 였다 — 프런트엔드는
관점 자체가 없었다.

## 할 것

- 버튼을 앱의 관용구에 맞춘다. 같은 페이지의 `.btn-check-upd` 와 전역 `--btn-*`
  토큰을 쓴다. 길드 통째 허용은 되돌리기 어려우니 경고색으로 구분한다.
- **가드를 만든다** — `check:classes`. 습관을 검사로 바꾼다(이 저장소의 방식).
  도입 시점의 16건은 ALLOW 에 두되 "줄이되 늘리지 말 것" 으로 못 박는다.
- 가드 등록 3곳(package.json / justfile / check.yml) — `check:guards` 가 강제한다.

## 테스트 방법

- 없는 클래스를 쓰면 `check:classes` 가 걸린다(되돌림 시험).
- `check:guards` 가 새 가드의 3곳 등록을 확인한다.

## 결과

버튼을 `.btn-plain` / `.btn-go` 로 바꾸고 같은 페이지의 `.btn-check-upd` 관용구와
전역 `--btn-primary-*` / `--btn-warning-*` 토큰에 맞췄다. 길드 통째 허용은
되돌리기 어려우므로 경고색 테두리로 구분한다 — 평범한 버튼처럼 보이면 안 된다.

**가드 `check:classes` 를 신설했다.** 전수 조사에서 이미 있던 것은 9개 파일
16건뿐이라(대부분 진짜 죽은 클래스 — 예: `QuestBoard` 의 `.resolved` 는 아무 데도
규칙이 없다) ALLOW 에 두고 "줄이되 늘리지 말 것" 으로 못 박았다.

`check:guards`(DEV-372)가 **바로 일했다** — package.json 과 justfile 에만 넣고
CI 를 빠뜨리자 그 자리에서 걸렸다. 가드를 만드는 가드가 값을 한 셈이다.

되돌림 시험: `class="btn-go"` 를 `class="primary"` 로 되돌리자 `check:classes` 가
그 줄을 집어냈다.

## 남은 것

이 지적이 드러낸 더 큰 문제는 **리뷰에 프런트엔드 관점이 아예 없었다**는 것이다.
6개 관점 32건이 전부 core/cli/server 였다. UI 리뷰를 따로 돌렸고 결과는 별도
퀘스트로 정리한다.

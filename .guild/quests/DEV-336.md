admin 요청: 마크다운 에디터에서 bullet·들여쓰기가 자동 입력되는 걸 끄는 설정.
구현 가능한지 먼저 조사.

## 결론: 가능하다. 세 가지가 각각 다른 출처라 나눠서 꺼야 한다

### 1. 목록/인용 이어쓰기 (`- ` 다음 줄에 `- ` 자동)

`@codemirror/lang-markdown` 의 `markdownKeymap` 이 원인:

```js
const markdownKeymap = [
  { key: "Enter",     run: insertNewlineContinueMarkup },
  { key: "Backspace", run: deleteMarkupBackward }
];
```

`markdown({ addKeymap: false })` 로 통째로 끌 수 있다(소스에서 확인 —
`addKeymap = true` 가 기본 인자). 단 Backspace 의 마크업 정리도 같이 꺼진다.
따로 살리려면 keymap 을 직접 구성.

### 2. 새 줄 자동 들여쓰기 (앞 줄 공백 따라가기)

`basicSetup` 의 defaultKeymap 이 Enter 에 `insertNewlineAndIndent` 를 건다.
`@codemirror/commands` 의 `insertNewline` 으로 더 높은 precedence 의 keymap 을
얹으면 순수 개행이 된다.

### 3. 타이핑 중 재들여쓰기

`indentOnInput()` — basicSetup 구성 요소. BUG-215 로 이미 setup 을 우리가
조립하는 구조가 됐으니(`editor-setup.ts`) 여기서 빼면 된다.

## 적용 방식

테마 전환에 이미 쓰는 `Compartment` 패턴을 그대로 쓰면 **편집기 재생성 없이**
설정을 즉시 반영할 수 있다(`editorThemeCompartment` 참고). editorSettings 스토어
(들여쓰기 폭/탭 설정이 이미 있음)에 항목을 추가하는 게 자연스럽다.

## 결정 필요

- 스위치를 몇 개로 둘지: 하나로 묶기(자동 서식 끄기) vs 위 3개를 따로.
  개인적으로는 **하나**를 권한다 — 사용자가 "자동으로 뭐가 입력되는 게 싫다" 는
  단일 의도로 켜고 끄는 성격이고, 3개로 나누면 설정만 늘어난다.
- 기본값은 현재 동작 유지(자동 서식 켜짐).

## 구현 완료 (2026-08-05)

권장대로 스위치 하나("자동 서식")로 통합. `editorSettings` 스토어에
`autoFormat`(기본 true=기존 동작) 추가. `editor-setup.ts` 에
`markdownEditorExtensions({ touch, autoFormat })` 신설 — 꺼지면
`markdown({ addKeymap: false })`(목록 이어쓰기 + Backspace 마크업 정리 제거) +
Enter 를 높은 우선순위 keymap 으로 평범한 `insertNewline` 에 바인딩(자동
들여쓰기 제거) + `indentOnInput()` 자체를 기본 확장에서 제외(desktopSetup /
touchSetup 재구성, autoFormat 켜짐인 흔한 경로는 여전히 basicSetup 원본 사용
— 동작 변화 없음). 설정 페이지 '편집기' 탭에 사용/끄기 토글 추가.

실제 Enter 키 입력을 jsdom 에 KeyboardEvent 로 dispatch 해 "- item" 다음
Enter 시 "- " 가 이어지는지/안 이어지는지 end-to-end 로 검증하는 테스트 포함
(editorSetup.test.ts) — 전부 통과.

## 테스트 방법

1. 설정 → 편집기 탭에서 "자동 서식" 을 끄기로 변경.
2. 아무 퀘스트/캠페인 본문 편집기에서 "- item" 입력 후 Enter — 다음 줄에
   "- " 가 안 붙는지.
3. 들여쓰기된 줄(예: 앞에 스페이스 4칸)에서 Enter — 다음 줄이 들여쓰기
   안 따라오고 그냥 새 줄로 시작하는지.
4. 다시 켜기로 바꾸고 위 두 동작이 원래대로(자동 이어짐/들여쓰기) 돌아오는지.

## 무엇

모든 이벤트에 대상(`subject`) — 퀘스트·캠페인·도서관 문서·규칙 중 하나 — 를 같은 모양으로 싣는다([[BOOK-004]] "받을 데이터 with").

## 왜

`with` 를 "대상과 연결된 것" 하나의 규칙으로 만들기 위해서다. 그래야 플러그인 작성자가 이벤트 55개마다 받을 수 있는 것을 외우지 않는다. 댓글·첨부처럼 여러 문서에 달리는 이벤트(`target: {kind, id}`)도 여기에 맞춘다.

## 확인

- 이벤트 목록 검사(실제 페이로드로 모든 이벤트 확인)가 모든 이벤트에 `subject` 가 있음을 본다.

## 구현 / 확인한 것

- `Event::subject()` — 대상 `{ kind, id }` 를 **한 곳에서** 뽑는다. 댓글·첨부는 달린 문서(`target`), 나머지는 이벤트 이름의
  앞부분이 가리키는 본문(`quest.id`, `campaign.id`, `book.id`, `rule.slug`, `folder.path`, `type.prefix`, `status.slug`,
  `tag.slug`), 노트는 `date`, 백업은 `timestamp`. 종류는 `SUBJECT_KINDS` 10가지 — 앞의 넷(quest·campaign·book·rule)이 문서다.
- 플러그인이 받는 JSON 에 `subject` 로 실린다(스크립트에서 `e.subject.kind` / `e.subject.id`). 이벤트를 내는 곳(ops)은
  고치지 않았다 — 새 이벤트를 추가해도 규칙이 한 곳이라 빠뜨리기 어렵고, 빠뜨리면 아래 시험이 잡는다.
- 시험: 실제 ops 로 낸 이벤트 **전부**에 대상이 있고 JSON 과 일치하는지, 대상 10종류를 모두 밟는지, 댓글의 대상이 퀘스트인지,
  실패한 변경(`ok: false`)에도 대상이 실리는지. 규칙 하나(tag)를 빼면 `tag.defined 에 대상이 없다` 로 실패함을 확인.

# [cli] comments / quest comment 옵션셋 통일 + 기본 전체출력 분리

사용자 보고 묶음 — `openguild comments` 와 `openguild quest comment` 의
옵션셋/기본 동작 통일.

## 보고된 문제

1. `openguild comments` 를 옵션 없이 실행하면 길드의 **모든** 댓글을 출력 —
   기본값으로는 과함. 전체 출력은 명시 옵션(예: `--all`)으로 분리하고 기본은
   제한(최신 N개 등)으로.
2. `quest comment show` 도 마찬가지 — 옵션 없이 그 퀘스트의 전체 댓글 출력.
   동일하게 기본 제한 + `--all` 분리.
3. `quest comment` 에도 `comments` 가 가진 필터 옵션(--author/--since/
   --until/--grep/--discussion/--unresolved/--limit/--summary)이 필요.
4. 반대로 `comments` 에는 `quest comment show` 가 가진 tree 출력(--tree,
   --depth, --with-parents 계열)이 없음.

## 구현

- **`comments_search`(Backend 메서드)**: SQL 레벨 `LIMIT`/`ORDER BY DESC`
  제거 — `quest comment list` 와 동일하게 필터만 SQL, 정렬/limit 은 Rust
  쪽에서(top_only/reply_to 필터가 limit 보다 먼저 걸리게). 기본 정렬을
  오래된순(대화 흐름)으로 통일, `--reverse` 로 최신순 전환.
- **`Command::Comments`(전역)**: `--top-only`/`--reply-to`/`--reverse`/
  `--tree` 추가. `--tree` 는 여러 slug 가 섞여 있어 slug 별로 먼저 묶은 뒤
  그 안에서 부모/자식 들여쓰기 트리를 그림(그룹 헤더 `== SLUG ==`).
- **`CommentCmd::List`(quest/campaign comment list)**: `--until`/
  `--discussion`/`--unresolved`/`--summary` 추가. 기본 출력을 본문 전체로
  변경(`--summary` 시 기존처럼 60자 요약 1줄) — 이미 전역 `comments` 가
  DEV-230 에서 이렇게 바뀌었는데 `list` 만 항상 요약이었던 것 통일.
- **`CommentCmd::Show`(quest/campaign comment show)**: `--all` 추가.
  `--id` 없이 실행 시 기본 최근 20개만(전체는 `--all` 로 해제), `--id`
  와는 상호배타.

## 의도적으로 제외한 범위

전역 `comments` 에 `--depth`/`--with-parents` 같은 "특정 entry 하나 골라
그 스레드만 보기" 기능은 이번엔 추가하지 않음 — 전역 명령은 여러 quest/
campaign 이 섞여 있어 "entry id 하나"만으론 대상을 특정할 수 없고
(slug + id 쌍이 필요), 지금의 플랫 플래그 구조를 서브커맨드(`comments
show <slug> <id>` 식)로 바꿔야 해서 범위가 커진다. 필요해지면 별도
후속으로.

   `cli_parse_global_comments_dev262_added_options`) 전부 통과.
   `comments_search_union_filters_and_order` 도 새 정렬/시그니처에 맞게
   갱신.
2. `cargo test --workspace` 526건 통과, `cargo clippy --workspace
   --all-targets -- -D warnings` 클린.
3. 스크래치 길드에서 실기 확인 — comment add(+parent-id 답글) 후
   `list`(기본 전체 본문 vs `--summary`), `show`(기본 vs 없이), 전역
   `comments`/`comments --tree` 모두 기대한 형태로 출력되는지 확인.
4. CHANGELOG(Unreleased) + 배포용 스킬 `reference/comments.md` 갱신 —
   후자는 겸사겸사 이미 부정확했던 플래그 표기(`--reply-to` on add →
   실제는 `--parent-id`, discussion/resolved 가 토글이 아니라 플래그를
   받는 것처럼 표기됐던 것)도 같이 바로잡음.

## 원인 (도입 시점: DEV-074 최초 커밋, 590e45b)
`QuestBoard.svelte` 의 `refreshNodeBgForTheme()` 가 테마 전환 시 모든 노드의
`urgencyBg` data 를 새 테마 색으로 갱신하려 하는데, 정작 그 값을 계산하는
`urgencyBgFor(urgency, eff)` 에 넘길 `urgency` 를 `n.data('urgency')` 로
읽고 있었다 — 그런데 Cytoscape 노드 생성부(같은 파일 2곳)는 파생값
`urgencyColor`/`urgencyBg` 만 data 로 저장하고 원본 `urgency` 자체는 애초에
저장한 적이 없다. 즉 `n.data('urgency')` 는 항상 `undefined` 였고, 그 결과
`urgencyBg` 는 테마가 바뀌어도 절대 갱신되지 않았다(리팩터 시리즈
"DEV-074 fix1~fix20" 전부 이 부분은 건드리지 않음 — 최초 커밋부터 있던
잠복 버그).

이 값은 노드가 `active`(클릭으로 확장 카드가 열린 상태) 일 때만
`node[questId][?active]` 셀렉터가 `background-color: data(urgencyBg)` 로
덮어써 화면에 노출된다 — 평소엔 안 보이다가 클릭해야 "새로고침 시점 테마의
낡은 urgencyBg" 가 드러난 것. dark 테마의 urgencyBg 값(#181c22~#2d0f0f)은
거무튀튀하고 light 테마 값(#eef0f3~#fdecec)은 희끄무레해 "까맣게/하얗게
변한다"로 보였음.

## 수정
`refreshNodeBgForTheme()` 에서 `n.data('urgency')` 대신, 바로 아래
`nodeBg`(SVG) 재생성에 이미 쓰던 것과 동일하게 `allQuests` 에서 `questId`
로 원본 quest 를 찾아 `quest.urgency` 를 사용하도록 수정.

## 예방책
- 이 파일(QuestBoard.svelte)엔 Cytoscape/DOM 의존 로직이라 컴포넌트
  테스트가 전혀 없음(기존에도 없었음) — 이번 수정도 별도 회귀 테스트는
  추가하지 못함(순수 로직으로 분리돼 있지 않아 vitest 로 검증하기 어려움).
  실기 확인으로만 검증.
- 같은 클래스의 버그(“node.data() 에 저장 안 한 필드를 읽어 항상
  undefined”)를 막으려면, 노드 생성부와 갱신부가 같은 필드 목록을
  공유하는 헬퍼로 묶는 리팩터가 근본적이나 이번 범위 밖 — 최소한
  refreshNodeBgForTheme 자체는 이제 nodeBg/urgencyBg 둘 다 "quest 원본에서
  재계산" 패턴으로 통일해 drift 재발 가능성을 줄임.

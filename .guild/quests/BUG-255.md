## 증상

원격/브라우저 모드에서 캠페인 배너를 **설정도 제거도 못 한다.** 버튼 자체가
안 보인다.

```svelte
{#if isTauri}
    <button class="btn-edit" onclick={pickBanner}>배너</button>
    {#if detail.image_path}
        <button class="btn-edit" onclick={removeBanner}>…×</button>
    {/if}
{/if}
```

보는 것은 된다 — 서버에 `get_banner_image` 라우트가 있다. 쓰기만 없다.

## 원인 — 배너를 **로컬 파일 경로**로만 다룬다

```ts
// lib/api/campaigns.ts:72
setBanner: async (slug, sourcePath) => {
    const { invoke } = await import('@tauri-apps/api/core');
    return await invoke('set_campaign_banner', { slug, sourcePath });
}
```

`transport.ts` 를 안 거치고 곧장 `invoke` 다. Rust 쪽
(`gui/src/commands.rs:2058`)도 `source_path: String` 을 받아 `.guild/assets/`
로 **복사**하므로 넘길 값이 실제 파일시스템 경로여야 한다. 브라우저에는 경로가
없으니 애초에 부를 수가 없어서 버튼을 숨긴 것이다.

서버에는 배너를 **쓰는** 라우트가 아예 없다 — `get_banner_image` 하나뿐.

## 불가피한 제약이 아니다 — 첨부는 이미 두 경로를 다 갖췄다

```ts
// lib/utils/editor-attach.ts:243 — BUG-168
async function pickUploads() {
    if (isLocalTauri()) { /* 네이티브 다이얼로그 → 경로 기반, 크기 무관 */ }
    return (await pickFilesViaInput()).map(uploadFromFile);   // 숨은 file input → bytes
}
```

같은 파일 주석에 `no-native-dialogs` 규칙은 확인/경고 다이얼로그 한정이고
**파일 선택은 예외**라고 명시돼 있다. DEV-087 이 경로 방식만 만들었고,
[[BUG-168]] 이 나중에 첨부에 대해서만 그 격차를 메웠다 — 배너는 남았다.

## 함께 드러난 것 — 원격 모드에서 잘못된 길드에 쓴다

캠페인 페이지의 판별이 첨부와 다르다.

| 곳 | 판별 |
|----|------|
| `AttachmentSection.svelte:38` | `detectEnvironment() === 'tauri' && !getRemoteServerUrl()` |
| `campaigns/[slug]/+page.svelte:262` | `detectEnvironment() === 'tauri'` ← **원격 제외가 없다** |

그래서 데스크톱 앱이 **원격 서버에 접속한 상태**에서는 버튼이 보이는데,
누르면 `invoke` 가 원격이 아니라 **로컬 Store** 를 건드린다. 보고 있는 길드와
쓰는 대상이 다르다.

## 수정 방향

첨부와 같은 모양으로 맞춘다.

1. **core** — `set_banner_image` 을 둘로 쪼개 경로/바이트 두 경로가 검증·
   journal·옛 배너 제거·DB/frontmatter 커밋을 **공유**하게 한다. 확장자 검증이
   두 벌이 되면 곧 어긋난다.
2. **server** — `POST /api/campaigns/{slug}/banner?ext=png` (raw body 스트리밍,
   `save_attachment_stream` 과 같은 방식: 중단 시 조각 파일 삭제) +
   `DELETE /api/campaigns/{slug}/banner`.
3. **frontend** — `setBanner` / `clearBanner` 를 환경별로 분기. 로컬 Tauri 는
   지금처럼 경로, 그 외는 숨은 file input 으로 받은 `File` 을 그대로 POST.
   버튼의 `{#if isTauri}` 를 걷는다.
4. 판별을 `isLocalTauri` 로 통일한다.

크기 상한은 두지 않는다 — 경로 방식이 이미 무제한이라(`std::fs::copy`),
모드에 따라 되고 안 되고가 갈리면 그게 더 나쁘다.

## 테스트 방법

1. `openguild-server host` 로 서버를 띄우고 브라우저로 접속.
2. 캠페인 상세에서 '배너' 버튼이 **보이는지**.
3. 눌러서 이미지를 고르면 배너가 뜨는지. 새로고침 후에도 남아 있는지.
4. '× ' 버튼으로 제거되는지.
5. png/jpg/gif/webp/bmp 가 되고 그 외(예: `.txt`)는 거부되는지.
6. 데스크톱 앱(로컬)에서 **기존 동작이 그대로인지** — 네이티브 다이얼로그.
7. 데스크톱 앱을 **원격 서버에 연결**한 상태에서 배너를 바꾸면 그 원격 길드에
   반영되는지(로컬 길드가 아니라).

## 수정

### core — 경로/바이트가 검증과 커밋을 공유

`set_banner_image` 을 셋으로 나눴다.

| | 하는 일 |
|---|---|
| `check_banner_ext` | 확장자 화이트리스트 (`BANNER_EXTS` 단일 출처) |
| `begin_banner_image` | 검증 · journal · **옛 배너 제거** · 대상 경로 확보 |
| `commit_banner_image` | DB `image_path` + frontmatter 갱신 |

갈라지는 것은 **파일을 어떻게 놓느냐** 뿐이다 — 데스크톱은 `std::fs::copy`,
서버는 body 스트리밍. `set_banner_image` 은 이제 begin → copy → commit 이라
바깥 시그니처가 그대로다(Tauri 커맨드 무수정).

옛 배너 제거가 공유 구간에 있는 게 중요하다. 확장자가 바뀌면 파일 이름이 달라
**덮이지 않으므로**, 안 지우면 `assets/` 에 고아가 쌓인다.

### server — 쓰기 라우트 신설

```
POST   /api/campaigns/{slug}/banner?ext=png    (raw body 스트리밍)
DELETE /api/campaigns/{slug}/banner
```

`save_attachment_stream`(BUG-168)과 같은 방식이다 — body 가 파일 원문이라
확장자는 쿼리로 받고, 도중에 끊기면 **조각 파일을 지운다**(아무도 참조하지
않는 쓰레기가 reindex/스냅샷에 끌려다니지 않도록).

`DefaultBodyLimit::disable()` — 데스크톱 경로가 이미 무제한(`std::fs::copy`)
이라 모드에 따라 되고 안 되고가 갈리면 그게 더 나쁘다.

### frontend

`setBanner` 를 `setBannerFromPath` / `setBannerFromFile` 로 나누고 `pickBanner`
가 환경에 따라 고른다. 브라우저는 `editor-attach.ts` 와 같은 숨은 file input
패턴(`accept` 는 지원 확장자, `oncancel` 처리 포함). `clearBanner` 는 로컬이면
invoke, 아니면 `DELETE`.

버튼의 `{#if isTauri}` 를 걷었다.

### 판별 통일 — `isLocalTauri`

`editor-attach.ts` 에 private 으로 있던 것을 `transport.ts` 로 올려 단일
출처로 만들었다. 캠페인 페이지가 쓰던 `detectEnvironment() === 'tauri'` 는
**원격 제외가 빠져** 있어, 데스크톱이 원격 길드에 접속한 상태에서 배너를
바꾸면 `invoke` 가 로컬 Store 를 건드렸다 — 보는 길드와 쓰는 대상이 갈렸다.

## 검증

### HTTP 실측 (test-guild, 서버 3100)

| 요청 | 결과 |
|------|------|
| 배너 없음 `GET /image` | `404` |
| `POST /banner?ext=png` | `200`, `image_path: assets/C-001-banner.png` |
| `GET /image` | `200`, `image/png`, **원본과 바이트 동일** |
| `POST /banner?ext=txt` | `400` `지원하지 않는 이미지 확장자: .txt (png/jpg/…)` |
| `POST /banner?ext=gif` (png 위에) | `200`, assets 에 **파일 1개**(gif 만) |
| `DELETE /banner` | `200`, `image_path: null`, assets **0개**, `GET` → `404` |

파일 진리원도 확인했다 — `.guild/campaigns/C-001.md` frontmatter 의
`image = "assets/…"` 가 함께 바뀌고, 제거 후에는 그 줄이 사라진다.
`check drift` 이상 없음.

### 실제 UI 경로 (브라우저, 1400×900)

- 캠페인 상세의 top-actions: `배너` 버튼이 **HTTP 모드에서 보인다**(수정 전에는
  없었다).
- 숨은 input 의 `click` 을 가로채 파일을 주입해 `pickBanner` →
  `setBannerFromFile` → POST 전체 경로를 태웠다. input 속성이
  `accept=".png,.jpg,.jpeg,.gif,.webp,.bmp"`, `multiple=false` 로 확인됐고,
  업로드 후 제거(`×`) 버튼이 나타났다.
- 홈 카드의 `img.banner-img` 가 `/api/campaigns/C-001/image` 를 **60×20** 으로
  로드 — 올린 이미지의 실제 치수와 일치.
- `×` 버튼을 눌러 제거 → 버튼이 사라지고 assets 0개.

### 테스트 8건 추가 + 되돌려 실패 확인

server 4건(왕복 / 확장자 거부 / 확장자 교체 / DELETE),
core 4건(경로 복사 · 기록 / 옛 파일 제거 / 확장자 거부 / 대소문자·점 정규화).
`banner` 로 필터하면 5건이 잡히는데 그중 `get_banner_image_404_when_none` 은
원래 있던 것이다. 워크스페이스 합계 779 → **787**.

되돌려 확인한 것:

| 되돌린 것 | 깨진 테스트 |
|---|---|
| `check_banner_ext` 무력화 | core 2건 + **server 1건** — 화이트리스트가 실제로 공유됨 |
| 옛 배너 제거 삭제 | core 1건 |

## 남는 것

**데스크톱 앱 실행 확인은 못 했다.** 경로 경로는 core 단위 테스트로 고정했고
Tauri 커맨드 시그니처는 안 건드렸지만, 앱을 띄워 네이티브 다이얼로그로
골라본 것은 아니다. 원격 접속 상태의 동작(판별 통일 효과)도 마찬가지다.

## 테스트 방법

1. `openguild-server host` 로 서버를 띄우고 **브라우저**로 접속.
2. 캠페인 상세에서 '배너' 버튼이 보이는지. 눌러 이미지를 고르면 홈 카드에
   배너가 뜨는지. 새로고침 후에도 남아 있는지.
3. '×' 로 제거되는지.
4. `.txt` 같은 파일을 고르면 거부 메시지가 나오는지.
5. **데스크톱 앱(로컬)** 에서 기존처럼 네이티브 다이얼로그가 뜨고 동작하는지.

**퀘스트 타입을 바꾸면(DEV-001 → BUG-001) 댓글 · 메모 · 첨부 목록이 옛 이름에 남는다**(2026-10-01, DEV-433 을
하다 시험으로 확인 — 댓글을 단 퀘스트의 타입을 바꾸면 새 이름으로 댓글을 읽을 때 0개).

- 타입 바꾸기는 본문 파일과 변경 이력(`history/`)만 새 이름으로 옮긴다. `DEV-001.comments.md`,
  `DEV-001.memo.md`, `DEV-001.attachments.json` 은 그대로 남아 **아무 퀘스트에도 안 붙는다** — 화면에서 댓글과
  첨부가 사라진 것처럼 보인다(파일은 있어 지워지진 않았다).
- 캐시(DB)의 댓글 행은 퀘스트 행 id 에 붙어 있어 다시 색인하기 전까지는 보일 수 있다 — 다시 색인하면 사라진다.
- 태그가 사라지던 것은 DEV-433 에서 같이 고쳐졌다(본문 파일을 옮긴 뒤 쓰게 바꿔서).

## 고칠 것

- 타입 바꾸기에서 댓글 · 메모 · 첨부 목록 파일도 새 이름으로 옮긴다(`history::rename` 처럼). 새 이름에 이미
  파일이 있으면 덮지 않고 멈춘다.
- 이미 옛 이름에 남은 파일 — `check` 가 "주인 없는 사이드카" 로 알려 준다(자동으로 붙이지는 않는다: 옛
  이름이 다른 퀘스트에 다시 쓰였을 수 있다).

## 시험

- 댓글 · 메모 · 첨부가 있는 퀘스트의 타입을 바꾸면 새 이름으로 셋 다 읽힌다. 댓글 번호(DEV-433)도 이어진다.

## 고침 (2026-10-01)

- 타입 바꾸기가 본문 · 변경 이력에 이어 **댓글 · 메모 · 첨부 목록 파일**도 새 이름으로 옮긴다(`move_sidecars`).
  파일째 옮기므로 댓글 번호(DEV-433)도 이어진다.
- 새 이름에 이미 파일이 있으면 덮지 않고 옛 파일을 그대로 두며 이유를 남긴다 — 이름은 이미 DB 에서 바뀌어
  여기서 전체를 실패시키지 않는다(번호를 다시 주지 않으니 보통은 안 일어난다).
- **하지 않은 것**: 이미 옛 이름에 남은 파일을 `check` 가 알려 주는 것 — 따로 정한다.

## 시험

- 댓글 · 메모 · 첨부가 있는 퀘스트의 타입을 바꾸면 새 이름으로 셋 다 읽히고, 옛 이름 파일이 없고, 다음 댓글
  번호가 2 다(고치기 전: 댓글 0개로 실패).

## 테스트 방법

1. 앱에서 댓글 · 메모 · 첨부가 있는 퀘스트의 타입을 바꾼다(예: DEV → BUG).
2. 바뀐 퀘스트를 열었을 때 댓글 · 메모 · 첨부가 그대로 보이면 정상.

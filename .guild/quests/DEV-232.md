두 가지 요청.

## 1. rule create alias 완전 제거
DEV-231 에서 rules(복수형) alias 는 제거했으나 create(동사 alias)는
남겨뒀음 — 사용자가 이것도 지우라고 지시. RulesCmd::Create 의
`#[command(name = "new", alias = "create")]` 에서 alias 제거,
`openguild rule create ...` 는 이제 unknown subcommand 에러.

## 2. echo 로 한글 넣으면 rule show 에서 깨짐 — 기존 유사 문제 확인
`echo "한글" | openguild rule new <slug>` 처럼 stdin 파이프로 한글을
넣으면 `rule show` 로 봤을 때 깨져 보임.

**기존에 동일 문제가 이미 있었음 — DEV-222** ("PowerShell 한글 인코딩
깨짐"): quest 본문도 인라인 인자/stdin 으로 넣으면 PowerShell 파이프
인코딩 문제로 깨져서, `--description-file <PATH>` (UTF-8 파일 직접
지정)를 해법으로 도입했음 — stdin 디코딩 자체를 고치는 대신 "파일로
넘기게 유도"하는 게 이 프로젝트의 확립된 대응 패턴.

`rule new`/`rule set`(과 comment add/edit, memo set, template new)은
전부 공용 `read_content()` 헬퍼를 쓰는데, 이미 `--file` 옵션을
지원함 — 즉 해법 자체는 이미 존재. 문제는 이 사실이 사용자에게
`--help` 시점에 안 보였다는 것.

## 수정
- read_content 를 사용하는 모든 `--file` 인자의 `///` doc 에 "한글 등
  비ASCII 는 --file 권장 — PowerShell 파이프는 인코딩이 안 맞아 깨질
  수 있음" 힌트 추가 (comment add/edit, memo set, rules set/new,
  template new). `--help` 로 미리 보이게 해 시행착오 전에 안내.
- stdin 디코딩 자체를 고치는 시도는 안 함(DEV-222 의 기존 결정 유지 —
  PowerShell 파이프 인코딩은 버전/설정에 따라 달라 범용 해결이 어려움).

## 테스트 방법
- `openguild rule new --help` → 한글 인코딩 안내 문구 확인.
- `openguild rule create foo` → 에러(unknown subcommand).
- `echo "한글" | openguild rule new test --file` 대신
  `openguild rule new test --file <utf8파일>` 로 넣으면 `rule show`
  로 정상 확인.
- `cargo test -p openguild-cli` 통과 (help leak 가드 포함).

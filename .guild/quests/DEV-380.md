## 왜

[[DEV-374]]~[[DEV-379]] 를 머지한 뒤 배선을 6개 관점(환경 매트릭스 · 동의 우회 ·
전달 런타임 · 이벤트 발행 · 비밀값 · CLI/서버 배선)으로 다시 훑었다. 반박 검증을
통과한 지적 5건과, admin 요청인 **웹 읽기 전용 조회**를 함께 처리한다.

## 웹 읽기 전용 조회 (admin 요청)

플러그인 설정은 어차피 길드 파일이라 그 서버에 닿는 사람은 이미 읽을 수 있다.
"이 공유 서버에 어떤 훅이 걸려 있나" 를 보는 것은 오히려 필요한 투명성이다.
**조회만 열고 허용/철회는 계속 막는다** — 팀이 공유하는 주소로 동의를 받으면
"누구의 동의인가" 가 흐려지고 `run` 을 여는 원격 구멍이 된다.

`GET /api/plugins` 하나. 프런트는 기존 transport 추상화를 그대로 타므로
브라우저·데스크톱·데스크톱+원격이 각각 **자기가 보고 있는 길드**를 읽는다.

## 지적 5건

**1 (HIGH) — BUG-255 재발.** `pluginsSupported()` 가 `detectEnvironment()` 만
본다. 데스크톱 앱으로 원격 길드에 접속한 상태에서는 `invoke` 가 여전히 로컬
Store 를 보므로, **원격 길드를 띄워놓고 로컬 길드의 플러그인을 보고 허용**하게
된다. 저장소가 이미 `isLocalTauri()` 로 이름 붙여둔 함정이다.

**2 (HIGH) — welcome placeholder 를 신뢰해 버린다.** 길드 없이 띄우면 관리
Store 가 in-memory placeholder 이고 `guild_root` 가
`$TMPDIR/openguild-welcome-placeholder` 다. 그 상태에서 "이 길드를 전부 허용" 을
누르면 **임시 디렉터리가 영구히 신뢰 목록에 들어간다.** 리눅스에서 그 부모는
누구나 쓸 수 있는 `/tmp` 라, 다른 프로세스가 거기에 정의를 심으면 묻지 않고 돈다.

**3 (MEDIUM) — 신뢰를 되돌릴 방법이 없다.** `is_granted` 가 `trusted` 에서
단락되는데 `revoke` 는 개별 항목만 지운다. 길드를 신뢰한 뒤에는 철회 버튼이
아무 일도 안 하고, `trusted_guilds` 에서 빼는 수단이 어디에도 없다.

**4 (MEDIUM) — `task-` 가 API 키로 걸린다.** `looks_like_known_key` 가
`starts_with` 가 아니라 `contains` 를 쓴다. `sk-` 는 영어 단어 꼬리에 흔해서
`task-runner`, `desk-notify`, `risk-eval` 이 전부 "비밀값" 으로 적재 거부된다.
실측으로 확인함.

**5 (MEDIUM) — `run` 은 `${VAR}` 를 안 푼다.** `expand_env` 가 post 의 url/헤더에만
걸려 있다. 그런데 비밀값 검사는 run 의 command/args 도 훑으므로 사용자는 반드시
`${VAR}` 로 적어야 하고, 그러면 자식이 리터럴 `${MY_API_KEY}` 를 받는다.
문서(USAGE.md)도 그렇게 쓰라고 안내한다.

## 테스트 방법

- 브라우저에서 목록이 보이고 허용/철회 버튼은 **없다**.
- 데스크톱+원격에서 목록이 **원격 길드** 것이고, 관리 버튼은 없다.
- 길드 없이 띄운 상태에서 허용/신뢰가 거부된다.
- `plugin untrust` 뒤 개별 동의만 남는다.
- `task-runner` 가 든 URL 이 적재된다. `sk-abcdef...` 는 여전히 거부된다.
- `run` 의 args 에 쓴 `${VAR}` 가 자식에게 풀려서 간다.

## 결과

### 웹 읽기 전용 조회

`GET /api/plugins` 하나 열었다. 프런트는 **기존 transport 추상화를 그대로 탄다** —
그게 핵심이다. 브라우저는 서버에게, 데스크톱은 로컬 Store 에게, 데스크톱+원격은
원격 서버에게 묻으므로 **화면이 보고 있는 길드와 목록이 항상 같은 길드**가 된다.
지적 1 이 저절로 닫히는 구조다.

허용/철회는 transport 를 안 탄다. `api/plugins.ts` 가 invoke 를 직접 부르고
`isLocalTauri()` 로 막는다. 프런트만 믿지 않고 **서버가 답한 `manageable`** 과
AND 로 묶었다 — 한쪽이 틀려도 버튼이 안 나온다.

모양은 `core/src/plugins/view.rs` 로 옮겼다. 프런트는 하나뿐인데 GUI 와 서버가
각자 만들면 필드가 갈린다.

### 지적 5건 전부 수정

1. **BUG-255 재발** — `pluginsManageable()` 이 `isLocalTauri()` 를 본다.
2. **welcome placeholder** — 가드를 커맨드에만 넣었더니 **시동 경로가 안 막혔다.**
   시험이 그걸 잡았다(`install_plugins_for_gui` 자체가 placeholder 면 sink 를
   비우고 돌아온다). 커맨드 넷에도 같은 거부를 뒀다.
3. **신뢰 해제** — `consent::untrust_guild`, `openguild plugin untrust`, 설정
   화면의 해제 버튼. 신뢰 중 개별 철회는 **아무 효과가 없다고 말한다**(예전엔
   성공했다고만 했다).
4. **`task-` 오탐** — 접두사를 토큰 시작에서만 본다. `sk-abcdef…` 는 여전히 막힌다.
5. **`run` 의 `${VAR}`** — 띄우기 직전에 푼다. 오류 메시지에는 원문을 쓴다(푼
   값에는 비밀이 들어 있다).

### 되돌림 시험 6건 전부 물었다

관리 게이트를 `detectEnvironment` 로(2건 실패) · placeholder 가드 제거(1) ·
untrust 를 no-op 으로(1) · 접두사 판정을 `contains` 로(1) · run 의 env 확장
제거(1) · 서버가 `manageable: true` 로 답함(1).

### 아직 검증 못 한 지적

리뷰에서 나온 27건 중 6건만 반박 검증을 통과했고, **12건은 세션 한도로 검증이
중단**됐으며 15건은 관점당 상한(3건)에 잘렸다. 눈에 띄는 것만 적어 둔다 —
확인 후 별도 퀘스트로:

- `emit_post_failed` 호출 지점이 0곳 — `ok` 가 false 인 이벤트가 실제로는 안 나간다.
- 누락 검사가 journal 없는 mutation 12개를 못 본다.
- `problems`(전달 실패)가 GUI 로 안 올라온다 — 지금은 항상 빈 배열.
- `run` 타임아웃이 손자 프로세스를 못 거둔다.
- rhai 스크립트는 git 으로 오는데 비밀값 검사를 안 받는다.

## 원인

`QuestList.svelte` 의 두 플래그가 **영속 계층에 배선돼 있지 않았다.**

목록의 나머지 필터는 전부 `QuestFilterState` 를 거친다 —
`snapshotFilter()` → `questFilters` store(뷰 전환) + `serializeFilter` →
길드별 localStorage(전체 리로드). REQ-010 이 플래그 2개를 추가하면서 이
경로에 넣지 않아, 컴포넌트가 다시 마운트되는 순간 `$state(false)` 초기값으로
돌아갔다.

## 수정

- `quest-filter.ts` — `QuestFilterState` / `EMPTY_FILTER` /
  `serializeFilter` / `deserializeFilter` 에 두 필드 추가.
  구버전 저장값은 `=== true` 검사로 자연히 false 가 된다.
- `QuestList.svelte` — `snapshotFilter` / `applyFilter` 에 추가.
- `QuestBoard.svelte` — `boardFilterSnapshot()` 이 store 의 값을 그대로
  유지하도록. **여기가 두 번째 누수였다** — 보드는 이 플래그를 편집하지
  않는데 스냅샷에는 넣어야 하므로, tags 와 같은 방식(`get(questFilters)`)
  으로 보존한다. 안 그러면 보드에 들렀다 오는 것만으로 풀린다.

## URL 동기화도 같이

`?search_comments=` / `?search_attachments=` 를 붙였다. `search` /
`titleOnly` 는 이미 URL 에 실리는데 범위만 빠져 있어, 링크를 공유하면
검색어는 같은데 결과가 다른 상태였다.

`isFilterActive` 에는 **넣지 않았다.** 검색어가 비면 이 플래그만으로 결과가
달라지지 않아, 포함하면 보이는 변화 없이 '필터 활성' 표시만 켜진다.
`titleOnly` 가 이미 같은 이유로 빠져 있다.

## 테스트

`quest-filter.ts` 에 테스트가 하나도 없었다. 12건 신설:

- **직렬화 왕복에서 모든 필드가 살아남는지** — 키 집합까지 비교해서, 앞으로
  인터페이스에 필드를 추가하고 직렬화에서 빠뜨리면 여기서 깨진다.
  (이번 버그의 재발 방지 지점)
- 구버전 저장값 호환 / Set↔배열 / 깨진 JSON / 알 수 없는 TriState
- `isFilterActive` — 검색어 없이 범위 플래그만 켠 경우 비활성, titleOnly
  단독 비활성, 각 필터 종류 단독 활성

수정 전 코드(직렬화에서 필드 제거)로 되돌려 **2건이 실패**하는 것을 확인했다.

## 참고 — 서버 정적 자산 함정

테스트 중에 `npm run build` 를 했는데도 옛 화면이 나왔다. 서버를 길드
폴더에서 띄우면 `static` 이 `target/debug/gui/frontend/build`(gui 크레이트
build.rs 가 만든 복사본)로 잡힌다. 최신 프론트엔드로 확인하려면
`FRONTEND_DIST=<repo>/gui/frontend/build` 를 주거나 gui 크레이트를 다시
빌드해야 한다.

길드 열기가 가끔 오래 걸리는 근본 원인 해소.

## 현황
`incremental::sync_changed_quest_files` 는 "기존 파일의 수정(mtime 변화)"만 cheap 하게 처리하고, **신규/삭제 파일을 하나라도 발견하면 needs_full_reindex → drift::auto_resync → 전체 reindex** 로 빠진다. 전체 reindex 는 quests/댓글/캠페인/도서관/히스토리/positions/첨부 blob 전 테이블 재구축 — 이 길드 기준 warm 1.3s / **cold 10.2s** (OS 캐시 미스 + Defender 실시간 검사가 작은 파일 수천 개에 파일당 수 ms 씩 누적).

트리거가 잦음: git pull / branch 전환 / 외부 편집기 파일 추가·삭제 — 파일 1개 추가됐다고 전체 rebuild 하는 구조.

## 작업
incremental 동기화가 신규/삭제도 직접 처리하게 확장:
- 신규 quest 파일: parse → INSERT (+ counter self-heal, tags/positions 등 연관 캐시).
- 삭제된 파일: 해당 row 및 연관 캐시 DELETE.
- sibling(.comments/.memo/.attachments)과 campaigns/library 파일도 동일 원리 적용 범위 검토 — 1차는 quests 본문만이라도 full fallback 빈도를 크게 줄임.
- full reindex fallback 은 남기되(안전망), 트리거 조건을 "incremental 로 표현 불가능한 변화(타입/상태 정의 변경 등)"로 축소.

## 참고
체감 악화 요인(길드 열기 UI 블로킹/진행표시 없음)은 별도 항목 — admin 이 이번엔 2번(본 퀘스트)만 등록 지시.

## 검증
- 신규/삭제/수정 혼합 시나리오 단위 테스트 (full fallback 안 타는지 report 로 확인).
- git branch 전환 시뮬레이션(파일 추가+삭제 동시) 후 open 시간 측정.

## 한 것 (2026-10-24)

- `Store::open` — index.db 를 열거나 마이그레이션할 때 SQLite 가 **망가짐**(`CORRUPT` 11 · `NOTADB` 26, 확장 코드 포함)이라고 답하면: 풀을 닫고 → `index.db`(+`-wal` · `-shm`)를 `backups/index.db.corrupt` 로 옮기고(앞서 옮긴 것은 덮음) → 새로 만들고 → **그 자리에서 파일로 다시 채운다**(`reindex`). CLI 는 매번 재색인하지 않으므로 빈 캐시로 두면 퀘스트가 안 보인다.
- 망가짐이 아닌 실패(잠김 · 권한 · 없는 테이블)는 전처럼 오류 — 캐시를 함부로 버리지 않는다.
- 옮기지 못하면(윈도우에서 앱 · 서버가 쥐고 있을 때) "닫고 다시 하세요" + 처음 오류.
- `journal.db` 가 망가졌으면 버리지 않고, 무엇인지 · 어떻게 하면 되는지 알린다(옛 기록만 잃음).
- 알림: CLI · 서버는 stderr 한 줄 `⚠ index.db(캐시)가 망가져 있어 파일에서 새로 만들었습니다 — 옛 파일: …`. 앱은 알림 없이 그냥 열린다.
- USAGE 문제 해결 표에 한 줄.

## 확인

- 시험 3: 망가진 두 모양(데이터베이스가 아닌 글 · 첫 페이지가 깨진 것) 각각 — 고치지 않은 열기는 정말 망가짐 오류, `Store::open` 은 열리고 퀘스트가 다시 있고 옛 파일이 바이트 그대로 남고, 다시 열면 또 새로 만들지 않는다 / 멀쩡한 길드는 그대로 / 망가짐 코드만 고른다. 고침을 끄면 실패하는 것 확인.
- 이 길드 사본의 index.db 첫 페이지를 깨뜨려서: 설치본 0.5.1 은 `failed to migrate index db … (code: 11) database disk image is malformed`(사용자가 본 것과 같음), 새 빌드는 경고 한 줄 뒤 퀘스트 846 · 캠페인 · 도서관 · 규칙 수가 원본과 같고 `check drift` 깨끗.

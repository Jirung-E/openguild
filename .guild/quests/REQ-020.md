## 왜

admin: *"플러그인 설정창에서 해당 플러그인의 설명이 보이면 좋겠는데."*

지금 설정 화면이 보여주는 것은 **이름 · 이벤트 패턴 · scope · 목적지**뿐이다.
전부 기계가 읽는 값이라, 처음 보는 플러그인 앞에서 "이게 무슨 일을 하는가" 를
사람 말로 알려주는 것이 하나도 없다.

```
telegram-quest-status
post → https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage
quest.status_changed  scope: cli, gui
```

이 화면의 존재 이유가 **"무엇에 동의하는지 보여주는 것"** 인데(DEV-383),
정작 "무엇을" 에 해당하는 사람 말이 없다. 스크립트 원문은 펼쳐 볼 수 있지만
그건 읽을 수 있는 사람에게만 답이다.

## 할 것

`plugin.json` 에 **선택 필드 `description`** 을 만들고, 정의를 보여주는 곳
전부에 흘린다 — 설정 화면(요청받은 곳), `PluginView`, `openguild plugin list`.
`plugin allow` 는 정의 전체를 이미 출력하므로 자동으로 따라온다.

## 정할 것

**선택 필드다.** 없다고 적재를 막지 않는다 — 기존 정의가 전부 깨진다.

**길이 상한을 둔다.** 설명은 화면에 그대로 그려지고 동의 지문에도 들어간다.
상한이 없으면 한 줄짜리 목록에 문단이 들어오고, 지문 파일이 정의 하나로
부풀 수 있다. 긴 설명은 플러그인 폴더의 README 자리다.

**비밀값 검사를 태운다.** git 에 커밋되는 파일의 자유 텍스트다 — 다른 필드는
막으면서 여기만 열어 두면 토큰을 적을 자리를 하나 만들어 주는 셈이다.

**빈 문자열은 없는 것으로 정규화한다.** `"description": ""` 가 지문에서는
"없음" 과 다른 값이라, 빈 값을 넣었다 뺐다 하는 것만으로 동의를 다시 묻게
된다. 화면에서는 어차피 똑같이 아무것도 안 보인다.

**지문에서 빼지 않는다.** 설명을 고치면 동의를 다시 묻는다 — 오타 하나
고쳤을 때는 성가시다. 그래도 뺄 만한 이유가 못 된다:
`skip_serializing_if` 로 없을 때는 직렬화에 아예 안 나타나므로 **기존 동의는
그대로 살아 있고**, "정의가 바뀌면 다시 묻는다" 라는 규칙 하나를 지키는 값이
필드마다 예외를 만드는 비용보다 싸다. 설명은 사용자가 읽고 판단하는 문장이라
"바뀌었으면 다시 본다" 가 어색하지도 않다.

## 테스트 방법

- 설명이 있는 정의가 적재되고 `PluginView` 까지 값이 간다.
- 설명이 **없는** 기존 정의도 그대로 적재된다.
- 설명 없는 정의의 동의 지문이 이 변경 **전과 같다** — 업그레이드했다고
  모든 동의가 무효가 되면 안 된다.
- 상한을 넘긴 설명은 적재에서 걸린다.
- 설명에 `sk-` 로 시작하는 리터럴이 있으면 걸린다.
- `"description": "   "` 는 없는 것으로 읽힌다.
- `plugin list --json` 에 설명이 실린다.
- 배포하는 예제 넷이 전부 설명을 갖고, 그대로 적재된다.
- 프런트: 설명이 없는 플러그인은 그 자리에 아무것도 안 그린다.

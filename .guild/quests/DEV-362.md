## 요청

검색 팔레트에 표시되는 **SLUG 를 PILL(알약 뱃지) 형태로** 표시한다.

## 기대 동작

- **접혀 있을 때**: PILL 들이 **가로로 나란히** 표시
- **펼쳐졌을 때**: PILL 들이 **세로로 나란히** 표시

이 변경으로 인해 **기존에 1줄로 표시되던 항목도 펼쳐지게 될 것**이다(요청자가
이 부작용을 인지하고 요청한 것 — 의도된 동작).

## 대상

`gui/frontend/src/lib/components/SearchPalette.svelte`

## 참고

PILL 스타일은 기존 태그/상태 뱃지와 시각적으로 통일할 것.
색상 토큰은 `frontend-theme-tokens` 규칙을 따른다
(`openguild rule show frontend-theme-tokens`).

## 수정 내용 (2026-08-20)

`SearchPalette.svelte` 한 파일.

- 기존엔 `displayName()` 이 `"{slug} {제목}"` 을 **한 문자열로 합쳐** `.ptitle`
  에 넣고 있었다. slug 를 별도 `.pslug` 칩으로 분리했다.
- 종류 칩(`.ptype`)과 slug 칩을 `.pills` 묶음으로 감쌌다.
  - 접힘: `flex-direction: row` — 가로로 나란히
  - 펼침(`.expanded`) / 접히는 중(`.collapsing`): `column` — 세로로 나란히
- `.collapsing` 에도 같은 규칙을 건 이유: DEV-359 가 정한 대로 접힘
  애니메이션 동안에는 **펼친 글자 배치를 유지한 채 높이만 줄어야** 접히는 게
  보인다. 여기서 방향을 되돌리면 마지막 프레임에 칩이 튄다.
- 제목이 없는 항목(규칙 — slug 가 곧 식별자)에서도 `.ptitle` 을 계속 렌더한다.
  `flex: 1` 스페이서 역할을 겸하고 있어서, 빼면 태그가 왼쪽으로 붙는다.

`displayName()` 은 창 제목(`openInWindow`)과 미리보기 헤더에서 계속 쓰이므로
남겨뒀다.

## 검증 (브라우저 실측, 614행)

- 접힌 행: `flex-direction: row`, 높이 **정확히 36px**
- 펼친 행: `column`, 높이 61px — 1줄짜리 항목도 펼치면 2줄이 된다
  (요청자가 인지한 의도된 부작용)
- 방향키 이동 시 펼침/접힘이 정상적으로 따라옴, 고착 행 0건
- 다크모드 정상 — slug 칩은 `color-mix(--text-muted 12%)` 라 테마를 따라간다

**36px 이 중요하다**: DEV-359 가 성능을 위해 `contain-intrinsic-size: 36px`
로 접힌 행 높이를 고정해 뒀다. 접힘 레이아웃을 바꾸지 않았으므로 그 가정이
그대로 유지되고, 화면 밖 행 예상 높이가 어긋나 스크롤이 흔들리는 회귀가 없다.

## 앞선 "별건 발견" 은 오판이었다 (정정)

이 본문에는 한때 "접힘 애니메이션이 끊기면 `.collapsing` 이 영구히 남는
기존 결함" 을 발견했다고 적혀 있었다. **틀렸다 — 그런 결함은 없다.**

원인은 검증 환경이었다. Claude 의 브라우저 패널이 hidden 상태면 문서가
`visibilityState: hidden` 이라 `requestAnimationFrame` 이 돌지 않고, 그래서
rAF/transition 에 걸린 정리 경로가 실행되지 않는다. 그 상태로 관찰하니 클래스가
남아 있는 것처럼 보였을 뿐이다(같은 이유로 CSS transition 이 `playState:
"running"` 인 채 영원히 안 끝나는 것도 확인했다).

정리 경로 자체는 정상이다. 리사이즈 없이 방향키만으로 5회 이동했을 때 고착
행은 0건이었다.

**교훈**: hidden 패널에서 애니메이션 종료에 의존하는 상태를 관찰하면 안 된다.
최종 상태를 확인하려면 `*{transition:none;animation:none}` 을 주입해 전이를
끄고 측정한다.

## 테스트 방법

검색 팔레트(상단 검색창)를 열고:

1. 접힌 행들에서 종류 칩과 slug 칩이 가로로 나란한지
2. 방향키/마우스 호버로 행을 선택하면 두 칩이 세로로 쌓이는지
3. 제목이 짧아 원래 1줄이던 항목도 펼치면 2줄이 되는지 (의도된 동작)
4. 규칙(rule) 항목처럼 제목이 없는 행에서 태그가 오른쪽에 정렬되는지

## 후속 — slug 칩이 종류 색을 따르도록 (2026-08-20, 사용자 요청)

처음엔 slug 칩을 중립색(`--text-muted`)으로 뒀는데, 종류에 맞는 색을 갖도록
바꿨다.

색은 `.pills` 래퍼에 `--kind-c` 로 **한 번만** 정하고 칩들이 그걸 참조한다.
`.ptype.{kind}` 규칙을 건드리지 않은 이유가 있다 — `.ptype` 은 행뿐 아니라
**미리보기 헤더(544행)에서 `.pills` 없이 단독으로도** 쓰이므로, 색 정의를
래퍼로 옮기면 그쪽이 색을 잃는다.

```
.pills.quest    { --kind-c: var(--accent);  }
.pills.campaign { --kind-c: var(--hl-pre);  }
.pills.rule     { --kind-c: var(--success); }
.pills.book     { --kind-c: var(--warning); }
.pslug { color: var(--kind-c, var(--text-muted));
         background: color-mix(in srgb, var(--kind-c, var(--text-muted)) 8%, transparent); }
```

배경은 종류 칩(14%)보다 옅은 **8%** 로 뒀다. 같은 색 계열이되 종류 칩이 먼저
읽히도록 위계를 남기기 위함이다. `--kind-c` 미정의 시 중립색 fallback.

### 검증 (브라우저 실측, 4종 전부)

| 종류 | slug | 종류 칩 색 | slug 칩 색 | 일치 |
|------|------|-----------|-----------|------|
| quest | DEV-362 | rgb(9,105,218) | rgb(9,105,218) | ✓ |
| campaign | C-006 | rgb(130,80,223) | rgb(130,80,223) | ✓ |
| rule | cli-command-naming | rgb(26,127,55) | rgb(26,127,55) | ✓ |
| book | BOOK-001 | rgb(154,103,0) | rgb(154,103,0) | ✓ |

slug 칩 배경은 모두 해당 색의 alpha 0.08. 라이트/다크 모두 확인.

### 검증 중 실수 기록

리빌드 후 브라우저에 옛 DOM 이 남아 "변경이 반영 안 됨" 으로 오인했다.
원인은 캐시가 아니라 **탭이 리빌드 이전에 로드된 SPA 를 그대로 띄우고 있던
것**이다(HTML 은 `no-cache`, 청크는 해시 기반이라 캐시 설정은 정상).
프론트엔드를 다시 빌드했으면 **페이지를 새로고침**해야 한다.

### 재수정 — 종류 색이 아니라 **퀘스트 타입 색** (사용자 지적)

처음엔 slug 칩을 kind 색(퀘스트=파랑 하나)으로 칠했는데, 그러면 팔레트의 모든
퀘스트가 같은 파랑이 된다. 사용자 지적대로 **퀘스트 타입 색**(DEV/BUG/REQ 별로
다름)이어야 한다.

근거가 분명하다 — `QuestListItem`(:57), `QuestBoard`(:3291, :3359),
`QuestCombobox`(:106)가 이미 `quest_id` 뱃지에 `type_color` 를 쓴다. 팔레트만
다르면 **같은 ID 가 화면마다 다른 색**으로 보인다.

- `Item` 에 `color?: string` 추가, 퀘스트는 `color: q.type_color`.
- 마크업: `<span class="pills {it.kind}" style:--kind-c={it.color}>`
  인라인 `--kind-c` 가 `.pills.{kind}` 클래스 값을 덮는다.
- 타입 개념이 없는 캠페인/규칙/도서관은 `color` 가 undefined → 인라인 변수가
  안 붙어 기존 종류 색으로 자연스럽게 fallback.

**종류 칩(`.ptype`)은 영향받지 않는다.** `.ptype.{kind}` 는 `--accent` 등을
직접 참조하고 `--kind-c` 를 쓰지 않기 때문이다. 그래서 "퀘스트" 칩은 파랑
그대로, slug 칩만 타입 색이 된다 — 두 정보가 동시에 읽힌다.

#### 검증 (브라우저 실측)

홈 목록의 `quest_id` 뱃지 색을 기준으로 대조:

| 타입 | 팔레트 slug | 홈 뱃지 | 일치 |
|------|-------------|---------|------|
| DEV | rgb(74,144,217) | rgb(74,144,217) | ✓ |
| BUG | rgb(233,79,79) | rgb(233,79,79) | ✓ |
| REQ | rgb(123,184,127) | rgb(123,184,127) | ✓ |

fallback 확인: campaign `C-002` / rule `file-truth-db-cache` / book `BOOK-001`
모두 인라인 `--kind-c` 없이 종류 색 유지.

### 후속 2 — 규칙은 칩 대신 이름으로 (2026-08-21, 사용자 지적)

slug 칩은 **짧은 식별자**(`DEV-362` / `C-006` / `BOOK-001`)를 담으라고 만든
것이다. 그런데 규칙은 slug 가 곧 이름이라(`title: ''`) 긴 kebab-case
(`cli-command-naming`)가 칩에 들어가고 제목 자리는 비어, 다른 항목들과 리듬이
깨져 어색했다.

`it.title` 이 없는 항목은 칩을 만들지 않고 이름을 제목 자리에 그대로 둔다.
종류 칩("규칙")이 이미 무엇인지 알려주므로 정보 손실도 없다.

```svelte
{#if it.title}
  <span class="pslug">{it.label}</span>
{/if}
...
<span class="ptitle">{it.title || it.label}</span>
```

특정 종류를 하드코딩하지 않고 "제목이 따로 있는가" 로 판정했다 — 나중에
slug 가 곧 이름인 종류가 더 생겨도 그대로 동작한다.

#### 검증 (브라우저 실측)

| 종류 | slug 칩 | 제목 자리 |
|------|---------|-----------|
| quest | `DEV-362` | 검색 팔레트 SLUG 를 PILL 로 표시… |
| campaign | `C-006` | 베타 0.6.0 |
| book | `BOOK-001` | index.db 는 파일의 일방향·폐기가능 투영이다… |
| **rule** | **없음** | **cli-command-naming** |

`rules:` 범위 검색으로 규칙 9건이 "규칙 칩 + 이름" 한 줄로 정렬돼 보이는 것을
육안 확인했다.

### 후속 3 — 타원형 칩 + 펼침 시 세로 가운데 정렬 (2026-08-21)

- **slug 칩을 타원형으로** (`border-radius: 4px → 20px`). 다른 화면
  (`QuestListItem` / `QuestBoard` / `QuestCombobox`)의 `quest_id` 뱃지와 같은
  모양이다. 좌우 여백도 `0.35rem → 0.5rem` 으로 넓혔다 — 각진 칩의 여백 그대로
  두면 글자가 곡면에 붙어 보인다.
- **펼친 행은 칩·제목·우측 버튼을 위아래 가운데로.** `.row.expanded` 와
  `.collapsing` 에 `align-items: center`, 행 내부(`.row-main`)도 함께.

#### DEV-359 회귀를 특히 조심했다

`align-items: flex-start` 는 [[DEV-359]] 가 **의도적으로** 넣은 것이다 — 제목이
1줄일 때와 2줄일 때 정렬 기준이 달라져 상자 높이가 4px 튀고, 칩과 우측 버튼이
미세하게 흔들렸다. 게다가 **접힌 행 높이 36px 는 `contain-intrinsic-size: 36px`
의 전제**라 어긋나면 화면 밖 행의 예상 높이가 틀려 스크롤이 흔들린다.

그래서 가운데 정렬을 **펼친 행에만** 걸었다. 접힌 행은 그대로 `flex-start` 다.

실측:

| 확인 | 결과 |
|------|------|
| 접힌 행 높이 | **36px** (방향키로 4회 이동한 뒤에도 동일) |
| 펼친 행에서 칩/제목/버튼 세로 중심 | **75px / 75px / 75px** — 일치 |
| 선택 이동 후 다른 행에서도 | **219 / 219 / 219** — 일치 |
| slug 칩 `border-radius` | `20px` |

### 후속 4 — 기존 뱃지 공식과 통일 + 쌓인 칩 가로 중앙 (2026-08-21)

앞선 후속 3 에서 타원형으로 바꾸긴 했지만 **기존 스타일과 미묘하게 달랐다**
(사용자 지적). 전수 조사해 공통 공식을 찾았다:

| | QuestListItem | QuestBoard | QuestCombobox | 내 것(수정 전) |
|---|---|---|---|---|
| radius | 20px | 20px | 12px | 20px |
| background | `--c` 18% | `--c` 18% | `--c` 16% | **8%** |
| **border** | **40%** | **40%** | **40%** | **없음** |
| weight | 500 | 500 | — | **600** |
| padding | .15/.55rem | .15/.5rem | .1/.45rem | **.1/.5rem** |

**테두리가 이 공식의 핵심**이었다 — 빼면 같은 색이어도 다른 칩처럼 보인다.
팔레트 행은 조밀하므로 셋 중 작은 `QuestBoard` 쪽 크기(0.7rem /
`0.15rem 0.5rem`)에 맞췄다.

`.ptype`(종류 칩)은 그대로 뒀다 — 그건 quest_id 뱃지가 아니라 분류 라벨이라,
같은 모양이면 식별자와 구분이 안 된다.

**세로로 쌓인 칩은 가로 가운데로.** `flex-direction: column` 이면 교차축이
가로가 되는데 `align-items: flex-start` 라 폭이 다른 두 칩이 왼쪽에 들쭉날쭉
붙어 있었다.

#### 검증

- slug 칩 계산값 `20px / weight 500 / 1px solid / bg 0.18` — 홈 목록 뱃지와 일치
- 쌓인 상태에서 종류 칩과 slug 칩의 **가로 중심이 408px 로 동일**

### 후속 5 — 칩 두께 / 접힘 정렬 / 폰트 통일 (2026-08-21)

- **칩 세로만 얇게** — `0.15rem → 0.02rem`. 가로 여백(0.5rem)과 곡률(20px)은
  전역 뱃지 공식 그대로 둔다. 팔레트 행이 36px 로 조밀해 세로 두께가 그대로면
  행을 꽉 채워 답답했다.
- **접힌 행도 세로 가운데.** `.row-main` 이 `flex-start` 라 접힌 상태에서 요소가
  위로 붙어 있었다. `center` 로 바꿨다.

  DEV-359 가 여기를 `flex-start` 로 둔 이유는 **당시엔 접힘/펼침이 이 한 규칙을
  공유**해서, `center` 면 제목이 1줄→2줄이 될 때 정렬 기준이 바뀌며 칩과 버튼이
  튀었기 때문이다. 지금은 펼친 행이 `.row.expanded .row-main` 에서 따로 `center`
  를 받으므로 **두 상태가 모두 center** 이고, 기준이 바뀌지 않아 그 문제가 없다.
- **두 칩의 글자 크기를 맞췄다** — `.pslug` 를 0.7rem 으로 올렸던 것을 다시
  `.ptype` 과 같은 0.68rem 으로. 나란히 놓이는 칩이라 크기가 다르면 한쪽이
  잘못된 것처럼 보인다.
- **칩 높이도 맞췄다** — slug 칩에만 테두리가 있어 2px 낮았다(18 vs 20).
  `.ptype` 에 투명 테두리를 줘 상자 높이만 맞춘다.

모양(각진 4px vs 타원 20px)은 **일부러 다르게** 유지한다 — `.ptype` 은 식별자가
아니라 분류 라벨이다.

#### 검증

| 확인 | 결과 |
|------|------|
| 접힌 행 높이 | **36px** (DEV-359 의 `contain-intrinsic-size` 전제 유지) |
| 칩 높이 | ptype 20px = pslug 20px |
| 글자 크기 | 둘 다 10.88px |
| 접힌 행 세로 중심 | 칩/제목/버튼/행 **122.7 로 모두 일치** |
| 펼친 행 세로 중심 | **74.6 으로 모두 일치** |

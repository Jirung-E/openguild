사용자가 .exe / .dmg / .AppImage 받아서 자기 PC 에 설치할 수 있도록 — server
호스팅 없이 desktop 단독 동작.

## 범위

### Windows
- `cargo tauri build --target x86_64-pc-windows-msvc`
- 결과물: `target/release/bundle/{msi,nsis}/*.msi` / `*.exe`
- WiX (MSI) 또는 NSIS — `tauri.conf.json::bundle.windows` 설정.
- 코드 사이닝 (초기엔 self-signed OK / 정식 인증서는 v1 진입 시).

### macOS
- `cargo tauri build --target {x86_64,aarch64}-apple-darwin`
- 결과물: `*.dmg` (intel/arm 각각).
- Apple notarization 은 초기엔 skip (사용자가 우클릭 → 열기).

### Linux
- `cargo tauri build`
- 결과물: `*.AppImage` + `*.deb` + `*.rpm`.

## CI 구성 (GitHub Actions)

`.github/workflows/release.yml`:
- 트리거: tag `v*` push.
- matrix: ubuntu / macos / windows.
- 각 job:
  1. checkout
  2. node + rust setup
  3. `cd gui/frontend && npm ci && npm run build`
  4. `cargo tauri build`
  5. artifact upload (installer 파일).
- `softprops/action-gh-release` 로 GitHub Release 에 첨부.

## 구현 (2026-05-25)

### 결정 — Windows NSIS only (지금 cycle 한정)
- MSI 도 한 번 빌드해서 작동 확인했지만 (multi-component 도 OK),
  사용자가 NSIS 만 유지 결정. tauri.conf.json `bundle.targets = ["nsis"]`.
- macOS / Linux 는 사용자 요청 시. (matrix CI 는 DEV-071 에서.)

### `gui/tauri.conf.json`
- `bundle.targets = ["nsis"]`.
- `bundle.windows.nsis`:
  - `template = "nsis/installer.nsi"` — custom template (아래).
  - `installerIcon = "icons/icon.ico"` / `uninstallerIcon = "icons/icon.ico"`
    — 안 지정하면 setup.exe / uninstall.exe 의 .exe 리소스 아이콘이
    NSIS 기본 (다운로드 화살표) 으로 남음. `MUI_ICON` 만으로는 wizard
    페이지 내부만 바뀜.
- `fileAssociations[].description`, `shortDescription`, `longDescription`
  영어로 — WiX codepage 1252 제약 잔재. NSIS 는 사실 한글도 가능하지만
  나중에 MSI 재활성화해도 일관되게 통과되도록.
- `beforeBuildCommand` 도 `npm --prefix ./frontend run build` →
  `npm run build` (Tauri 2 는 frontendDist 의 부모, 즉 `gui/frontend/`
  에서 실행 — `--prefix ./frontend` 가 `gui/frontend/frontend/` 가 됨).

### `gui/nsis/installer.nsi`
Tauri bundler 2.9 의 default NSIS template 을 base 로 다음 추가:
- 페이지 추가: `MUI_PAGE_COMPONENTS` (Directory 와 Start menu 사이).
- `Section Install` 하나를 6개로 분리:
  - `-Core` (hidden, always) — `SetOutPath`, run-check, uninstaller,
    Add-Remove Programs registry, resources, tauri externalBin.
  - `Desktop App (GUI)` — main exe + file associations + deep links +
    start menu / desktop shortcut. 기본 체크.
  - `Command-Line Tool (openguild)` — `..\..\openguild.exe` 복사. 기본
    체크.
  - `/o HTTP Server (openguild-server)` — 기본 **uncheck** (`/o`).
  - `Add to PATH` — PowerShell 로 HKLM `Environment\PATH` 에 `$INSTDIR`
    append (중복 방지 검사 포함). 기본 체크. Uninstaller 도 같은 방식
    으로 정리.
  - `-PostInstall` (hidden) — passive mode auto-close, NSIS_HOOK_POSTINSTALL.
- `MUI_FUNCTION_DESCRIPTION_BEGIN/END` 로 각 section description 표시.
- Uninstall section 에 `Delete openguild.exe` / `openguild-server.exe`
  추가 + PathEnvSet registry marker 보고 PATH 제거.
- `Icon "${INSTALLERICON}"` / `UninstallIcon "${UNINSTALLERICON}"` 명시
  (위의 installer icon 설명).

### 빌드 절차
```bash
# 1) CLI / Server 를 target/release/ 에 미리 빌드 (NSIS template 이
#    ..\..\openguild.exe / ..\..\openguild-server.exe 상대경로 참조)
cargo build --release -p openguild-cli -p openguild-server

# 2) icon / build-script 캐시 회피 (icon.ico 교체 후 1회)
cargo clean -p openguild-gui
rm -rf target/debug/build/openguild-gui-* target/release/build/openguild-gui-*

# 3) NSIS 빌드
cd gui && cargo tauri build
#   → target/release/bundle/nsis/OpenGuild_0.1.0_x64-setup.exe (~9.2 MB)
```

### 검증 (사용자, 2026-05-25)
- setup.exe 더블클릭 → 마법사 진입 → Components 페이지에서 GUI/CLI/
  Server/PATH 선택 가능. Server 만 기본 unchecked.
- 설치 후:
  - 시작 메뉴 → OpenGuild 실행 (GUI 동작).
  - `.guild` 파일 더블클릭 → OpenGuild 가 그 길드 열기 (DEV-005).
  - 새 터미널 → `openguild --version` (PATH OK, CLI 동작).
  - Server 체크했다면 `openguild-server --help`.
- 제거 시 PATH 에서 INSTALLDIR 사라짐.
- setup.exe 의 파일 탐색기 아이콘도 OpenGuild 아이콘 (256×256 추출 확인).

릴리즈/호스팅 환경에서 단일 링크(서버 하나가 SPA+API 동일 origin 서빙)로 웹 접근이 되도록. 현재 단일 origin 모드를 막는 갭: (1) FRONTEND_DIST 기본값 dist 가 실제 빌드 build 와 불일치 (2) SPA fallback 없어 딥링크 404 (3) 127.0.0.1 고정 바인드라 원격 접근 불가 (4) 릴리즈가 server+frontend 번들을 안 만듦. 접근안/결정은 토론 댓글 참조.

## 후속 수정 (2026-06-28, 테스트 중 발견)

(1) 의 잔여 버그: `FRONTEND_DIST` 기본값(`gui/frontend/build`)이 **cwd 기준
상대경로**였다. repo root 에서 실행하면 우연히 맞았지만, 사용자가 자연스럽게
실행할 위치인 `target/release/`(exe 가 있는 곳)에서 실행하면 cwd 가 달라
정적 서빙이 항상 비활성화되어 `http://127.0.0.1:3000/` 접속이 404 —
`/api/*`, `/health` 는 cwd 무관하게 정상 동작해 혼란스러웠음.

수정(`server/src/main.rs` `run_host()`): cwd 기준 상대경로가 없으면 exe 의
조상 디렉토리들(`exe.ancestors()` — `target/release` → `target` → repo
root)을 차례로 따라가며 `gui/frontend/build` 를 찾는다. cargo build 산출물
레이아웃(`target/{debug,release}/<exe>`)을 그대로 따라가므로 추가 설정 없이
repo root 실행과 `target/release` 실행 둘 다 정적 서빙이 동작.

## 후속 수정 2 (2026-06-28, 설치본에서 재현 — (4) 의 본 버그)

위 수정으로 개발 환경(repo root / `target/release`)에서는 해결됐지만,
**NSIS 설치본**에서는 여전히 `/` 접속이 404 였다. 원인은 (4) 그대로: 설치본
번들에 `gui/frontend/build` 자체가 들어있지 않았다 — `tauri.conf.json` 의
`bundle.resources` 가 LICENSE/README/USAGE/CHANGELOG 문서만 복사하고
frontend 정적 자산은 빠져 있었음(exe 의 조상 경로 탐색이 아무리 잘 동작해도
파일 자체가 없으면 무의미). `openguild-server.exe` 가 설치되는 위치
(`$INSTDIR`, `openguild.exe`/`openguild-gui.exe` 와 같은 디렉토리)에
`gui/frontend/build` 가 통째로 없었던 것.

수정(`gui/tauri.conf.json` `bundle.resources`): `"./frontend/build":
"gui/frontend/build"` 항목 추가 — 빌드 시 SvelteKit 정적 출력 전체를
`$INSTDIR\gui\frontend\build` 로 복사. exe 의 첫 조상(= `$INSTDIR`)에서
바로 찾아지므로 위 exe-relative 탐색 로직과 정확히 맞물린다.

검증: `cargo tauri build` 로 0.3.0-beta NSIS installer 생성 →
`/S /D=<temp>` 로 무인 설치 → `$INSTDIR\gui\frontend\build\index.html`
존재 확인 → `openguild-server.exe` 를 그 디렉토리에 두고(서버 컴포넌트
체크 시 실제 설치되는 위치와 동일) 다른 cwd 에서 실행 → `GET /` 200,
`GET /health` 200 둘 다 확인. (HTTP Server 컴포넌트는 기본 비활성(`/o`)이라
무인 설치 시 따로 복사해 시뮬레이션.)

## (3) 바인드 호스트 opt-in — `--bind` 구현 (토론 댓글 #2 반영)

토론에서 admin 이 지적한 대로 `--host` 플래그는 `host` 서브커맨드와 이름이
겹쳐 `openguild-server host --host` 가 어색함 — **`--bind`** 로 명명.
`local`(기본, =127.0.0.1)/`public`(=0.0.0.0) 별칭 + IP 리터럴 지원
(env: `BIND`). loopback 밖으로 바인드하면 시작 로그에 경고 1줄
("인증 없음, 신뢰된 네트워크에서만") — 기존 결정(C) 그대로: 기본은
보수적으로 유지, 노출은 명시적 opt-in.

`server/src/main.rs`: `resolve_bind_ip()` 헬퍼 + CLI 테스트(별칭/리터럴/
잘못된 값 거부) 추가.

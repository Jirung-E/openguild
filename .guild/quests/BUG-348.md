**윈도우에서 플러그인 `run` 훅이 시한을 넘겨도 손자 프로세스가 계속 돈다**(2026-10-03, CI 윈도우 잡 실패를 윈도우 세션이 추적).

- 윈도우의 `kill_group` 이 빈 함수다(`delivery.rs` `#[cfg(not(unix))]`). 시한이 지나면 `child.kill()` 이 **직접 띄운 것만** 죽이고,
  그 아래 손자는 남는다. Git 의 `Git\bin\sh.exe` 는 46KB 런처라 진짜 bash 가 손자가 된다 — CI 러너는 이쪽이라 시한 시험이
  결정적으로 실패했다(`left: 8 / right: 20`). 훅이 백그라운드로 던진 프로그램도 같다.
- 손자까지 죽는다는 시험(`a_timeout_kills_grandchildren_too`)이 `#[cfg(unix)]` 라 윈도우에는 그 보장 자체가 없었다.
- 지난번 윈도우 확인이 못 잡은 이유: 기본 환경에는 `sh` 가 없어 시험이 건너뛰어지며 **통과로 집계**됐고(`have_sh`),
  sh 를 넣을 때 `Git\usr\bin`(bash 본체)을 앞에 둬 런처를 안 거쳤다.

## 고칠 것

- 윈도우에서 훅 자식을 **Job Object** 에 넣고 시한 때 job 째로 거둔다(`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`).
- 손자 시험을 윈도우에서도 돌린다.
- 확인: 윈도우에서 `Git\bin` 먼저 / `Git\usr\bin` 먼저 두 경우, 디버그(`cargo test -p …`, CI 와 같게).

윈도우 세션이 만든다(사용자 지시) — 맥 세션은 그동안 `delivery.rs` 를 안 건드린다.

## 고침 (2026-10-03, 윈도우 세션이 만들고 맥에서 적용)

- 윈도우에서 훅 자식을 `CREATE_NO_WINDOW | CREATE_SUSPENDED` 로 띄워 **job object 에 넣은 뒤** 깨운다(`Job::holding` → `resume`).
  순서가 핵심 — 띄운 뒤 넣으면 그 사이 태어난 손자가 묶음 밖에 남는다. `Command` 가 주 스레드 손잡이를 안 줘서 ToolHelp 로 그
  프로세스의 스레드를 훑어 깨운다.
- 시한 때 유닉스 `kill_group` 옆에서 `job.terminate()`. `KILL_ON_JOB_CLOSE` 는 **일부러 안 건다** — 걸면 정상 종료에서도 훅이
  남긴 백그라운드 프로그램이 죽어 유닉스와 갈린다.
- 묶기 실패 → 예전처럼 직계만(전달은 막지 않음). 깨우기 실패 → 바로 죽이고 오류.
- `windows-sys 0.61`(Cargo.lock 에 이미 있던 판) — `[target.'cfg(windows)'.dependencies]`.
- 손자 시험의 `#[cfg(unix)]` 를 풀었다. 윈도우는 `sh` 없이 PowerShell 로 손자를 만든다 — Git Bash 없는 기본 환경에서도 돈다.

## 시험

- 윈도우(디버그, CI 와 같게): `Git\bin` 먼저(런처) / `Git\usr\bin` 먼저 / Git Bash 없음 — 셋 다 1106 통과 / 0 실패. 두 시한 시험 × 세 조건 × 3회 18/18.
- `job.terminate()` 한 줄을 빼면 런처 조건에서 두 시험이, Git Bash 없는 조건에서도 손자 시험이 실패한다 — 시험이 문다.
- 맥: `just test` 통과, 손자 시험 sh 갈래 그대로 통과.

## 테스트 방법

사람이 볼 것은 없다 — CI 윈도우 잡이 초록이면 된다.

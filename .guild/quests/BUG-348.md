**윈도우에서 플러그인 `run` 훅이 시한을 넘겨도 손자 프로세스가 계속 돈다**(2026-10-03, CI 윈도우 잡 실패를 윈도우 세션이 추적).

- 윈도우의 `kill_group` 이 빈 함수다(`delivery.rs` `#[cfg(not(unix))]`). 시한이 지나면 `child.kill()` 이 **직접 띄운 것만** 죽이고,
  그 아래 손자는 남는다. Git 의 `Git\bin\sh.exe` 는 46KB 런처라 진짜 bash 가 손자가 된다 — CI 러너는 이쪽이라 시한 시험이
  결정적으로 실패했다(`left: 8 / right: 20`). 훅이 백그라운드로 던진 프로그램도 같다.
- 손자까지 죽는다는 시험(`a_timeout_kills_grandchildren_too`)이 `#[cfg(unix)]` 라 윈도우에는 그 보장 자체가 없었다.
- 지난번 윈도우 확인이 못 잡은 이유: 기본 환경에는 `sh` 가 없어 시험이 건너뛰어지며 **통과로 집계**됐고(`have_sh`),
  sh 를 넣을 때 `Git\usr\bin`(bash 본체)을 앞에 둬 런처를 안 거쳤다.

## 고칠 것

- 윈도우에서 훅 자식을 **Job Object** 에 넣고 시한 때 job 째로 거둔다(`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`).
- 손자 시험을 윈도우에서도 돌린다.
- 확인: 윈도우에서 `Git\bin` 먼저 / `Git\usr\bin` 먼저 두 경우, 디버그(`cargo test -p …`, CI 와 같게).

윈도우 세션이 만든다(사용자 지시) — 맥 세션은 그동안 `delivery.rs` 를 안 건드린다.

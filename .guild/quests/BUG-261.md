## 증상

openguild 를 쓰던 codex 가 "원격 서버 첨부 업로드는 지원하지 않으며, 바이너리
첨부는 길드 라이브러리에 복사하는 방식" 이라고 답했다(admin 보고). **둘 다
사실이 아니다** — 원격 첨부는 [[BUG-231]] 에서 스트리밍 업로드로 동작하고,
첨부는 라이브러리가 아니라 `.guild/attachments/` 로 간다.

codex 잘못이 아니다. 자기 설치본 문서를 정확히 옮긴 것이다:

```
~/.codex/plugins/cache/openguild/openguild-plugin/0.5.0/
  skills/openguild/reference/library.md:32
    Attachments are local-mode only (no remote-server support). Files are
    copied into `.guild/attachments/`;
```

## 원인 — plugin.json 버전이 5주째 멈춰 있다

저장소의 `library.md` 는 BUG-231(8/13)에서 이미 고쳐졌다. 그런데 설치본은
갱신 판단을 **`plugin.json` 의 version** 으로만 하고, 그 값이 8/2 이후 안
움직였다.

| 위치 | version | library.md |
|------|---------|-----------|
| 저장소 `skills/openguild-plugin/` | 0.5.0 | 최신 (8/23) |
| `~/.openguild/skill-marketplace/` | 0.5.0 | 최신 (8/23) |
| `~/.codex/plugins/cache/.../0.5.0/` | 0.5.0 | **7/31** |
| `~/.claude/plugins/cache/.../0.4.1/` | 0.4.1 | 더 옛날 |

세 곳이 같은 `0.5.0` 을 말하는데 내용이 다르다. 그 사이 스킬은 **9번**
바뀌었고(파일 10개 전부 다르다 — SKILL.md 포함), codex 는 `quest new
--prereq`([[DEV-365]])도 `comment add --discussion`([[DEV-361]])도
`remove` 표기 수정([[BUG-229]])도 모른다. 이번 첨부 건은 그중 하나가 터진
것뿐이다.

### 왜 멈췄나 — 규칙이 아니라 습관이었다

`.guild/rules/release-process.md` 의 "버전 동기화" 목록은 6개다:

```
core/Cargo.toml · cli/Cargo.toml · server/Cargo.toml
gui/Cargo.toml · gui/tauri.conf.json · gui/frontend/package.json
```

**plugin.json 이 없다.** 그런데도 실제로는 매 릴리즈 같이 올라가고 있었다:

| 릴리즈 | 앱 | plugin.json |
|--------|-----|-------------|
| 07-19 | 0.4.0-beta | 0.4.0 ✅ |
| 07-22 | 0.4.1-beta | 0.4.1 ✅ |
| 08-02 | 0.5.0-beta | 0.5.0 ✅ |
| 08-23 | 0.5.1-beta | — ❌ |
| 08-27 | 0.5.2-beta | — ❌ |

습관이 8/23 에 끊겼다. 하필 **그날이 마지막 스킬 커밋(DEV-365)이 들어간
날**이다. 스킬을 고친 당일 릴리즈를 내면서 플러그인 버전만 빼먹었고, 8/27 에
한 번 더 놓쳤다.

## 배포는 필요 없다

마켓플레이스 소스가 저장소를 직접 가리킨다:

```json
"openguild": { "source": "directory", "path": ".../openguild/skills" }
```

저장소 파일은 이미 최신이므로 재배포도 앱 재빌드도 필요 없다. 설치본이
"이미 0.5.0" 이라 받을 이유가 없다고 판단할 뿐이다. **버전 숫자 하나가 9개
커밋을 막고 있다.**

[[DEV-264]] 의 `~/.openguild/skill-marketplace` 동기화는 정상이다(8/23 최신).
이번 건과 무관하므로 건드리지 않는다.

## 할 것

1. `plugin.json` → `0.5.2` (`-beta` 는 뗀다 — 0.4.0 / 0.4.1 / 0.5.0 관례).
2. **자동 검사** — plugin.json 의 version 이 크레이트 버전에서 `-beta` 를 뗀
   값과 다르면 실패하는 테스트. `cargo test --workspace` 에 이미 물려 있어
   CI 와 릴리즈 체크리스트 양쪽에서 걸린다.
3. `release-process.md` 의 버전 동기화 목록에 plugin.json 추가.

검사는 **과거 이력으로 검증한다** — 8/23 · 8/27 커밋 둘 다 이 검사에서
실패했어야 한다.

### 이 검사의 한계 (의도적)

릴리즈 사이의 스킬 수정은 다음 릴리즈까지 안 나간다. 더 조이려면 "skills/ 가
바뀐 커밋인데 version 이 그대로면 실패" 를 붙일 수 있지만 diff 기준
(merge-base)이 필요해 rebase/squash 에 취약하다. 이번 사고는 **릴리즈 때
놓친 것**이므로 위 검사로 충분하다.

## 테스트 방법

1. `cargo test -p openguild-cli` — 새 검사 통과.
2. plugin.json 의 version 을 되돌리면 그 검사가 **실패**한다(검사가 무는지 확인).
3. `/plugin update` 후 설치본 `library.md` 에
   `work in local and remote (--remote) mode` 가 보인다.

## 원인

**정렬 어긋남은 펼친 행에서만** 생긴다. DEV-362 가 펼친 행의 칩 묶음을 세로로
쌓게 했는데(`flex-direction: column`), `.row-main` 은 여전히 `align-items: center`
라 제목이 **상자 전체 기준으로** 가운데 정렬됐다. 그래서 제목 줄이 종류 칩과
slug 칩 **사이**에 떠 보였다.

실측(수정 전, 펼친 행): 종류 칩 글자 중앙 59.4 / 제목 70.8 / slug 82.9 — 세 개가
전부 다른 높이. 접힌 행은 세 개 모두 중앙 116.6 으로 이미 맞아 있었다.

**칩 글자 크기**는 다른 화면들과 공유하던 0.68rem(=10.88px)/slug 10px 로, 제목
0.85rem(13.6px) 옆에서 너무 작았다.

## 수정

- 종류 칩 `0.68rem → 0.78rem`, slug 칩 `10px → 11.5px`.
- 두 칩 상자 높이 `17px → 20px` — 제목 한 줄(line-height 21.76px)과 가운데가
  거의 일치하게 만든다.
- 펼친 행의 `.row-main` 을 `align-items: flex-start` 로 — 종류 칩과 제목 첫 줄이
  같은 선에 온다. (규칙이 두 곳에 중복돼 있어 뒤쪽 하나로 합쳤다.)

## 칩 안에서 글자가 위로 뜨던 것 — 광학 보정

`align-items: center` 는 **줄 상자**를 가운데 두는데, 실측해 보니 그 결과
**baseline 이 상자 정중앙**에 놓였다(칩 상자 중앙 61.8 = baseline 61.8).
한글·대문자 라틴은 글자 덩어리가 baseline 위에 몰려 있어서(종류 칩 ascent 11px /
descent 2px, slug 칩 8px / 0px) 덩어리 중심이 상자 중심보다 **4.5px 위**에 온다 —
"글자가 위로 치우쳤다"는 그 느낌이다.

측정 방법: 높이 0 인 inline-block 을 칩에 잠깐 넣어 baseline 위치를 얻고,
canvas `measureText` 의 `actualBoundingBoxAscent/Descent` 로 잉크 범위를 구해
덩어리 중심과 상자 중심의 차이를 쟀다.

## 수정

위쪽 여백으로 글자를 내려 **덩어리 기준**으로 가운데를 맞춘다. 고정 높이
(20px, border-box)라 상자 크기는 그대로다. 여백은 `em` 이라 글자 크기(UI 배율)를
따라간다.

여백 값은 실측 스윕으로 골랐다(칩 14개 평균, 이탈 = 상자중앙 − 덩어리중앙):

| padding-top | 종류 칩 | slug 칩 | 최대 이탈 |
|---|---|---|---|
| 0 (수정 전) | +4.50 | +3.42 | 4.50 |
| 0.60em | +0.77 | +0.06 | 0.77 |
| **0.64em** | **+0.52** | **−0.17** | **0.67** |
| 0.68em | +0.27 | −0.41 | 0.91 |
| 0.72em | +0.02 | −0.63 | 1.13 |

주의로 남길 것: `padding-top` 을 넣어도 **뒤에 오는 `padding` 단축 속성이
덮어써서** 처음엔 아무 변화가 없었다(빌드까지 하고 실측에서 4.5 그대로 나와
발견). 단축 속성에 직접 값을 넣었다.

## 확인

정렬(BUG-244 본체 수정)도 접힘 0.9px / 펼침 0.0px 로 유지.

연관 섹션(서브퀘스트/선행/후속)이 비어 있어도 항상 렌더돼 "없음" 문구가 세 줄
자리를 차지했다. 대부분의 퀘스트는 연관이 없거나 한 종류만 있어, 정작 봐야 할
내용(캠페인·태그·댓글)이 아래로 밀렸다.

## 구현 (2026-07-29)

- **빈 연관 섹션은 렌더하지 않는다** — 서브퀘스트/선행/후속 각각 항목이 있을
  때만 표시(부모는 이전부터 조건부였다).
- 대신 **'+ 연관 추가' 진입점**을 하나 둔다. 누르면 드롭다운에서 종류를 고르고,
  종류마다 **'기존 연결' / '새로 만들기'** 두 갈래([[DEV-278]]).
  - 바깥 클릭으로 닫힘(BUG-160 과 같은 규칙).
  - 편집 모드에서는 숨김(기존 섹션 버튼들과 동일 규칙).
- 항목이 있는 섹션은 기존의 섹션별 추가 버튼을 그대로 유지 — 그 자리에서
  바로 더하는 흐름이 더 짧다.

부모(parent) 지정은 이 메뉴에 넣지 않았다. 부모는 기존대로 편집 모드에서
지정하며, 여기에 넣으면 "부모는 하나뿐"이라는 제약을 메뉴에서 다시 설명해야
해 범위를 넘어선다.

## 검증

- 브라우저: 연관이 하나도 없는 퀘스트(DEV-296)에서 **빈 섹션 3개가 사라지고**
  '연관 추가' 버튼만 남는 것 확인. 남은 "없음" 문구는 태그/댓글/메모 것뿐.
- 메뉴를 열면 3종류 × 2동작(기존 연결/새로 만들기)이 정확히 렌더됨(폭 320px).
- 연관이 생기면 해당 섹션이 다시 나타남(DEV-278 검증에서 확인).
- `svelte-check` 0 errors / 0 warnings.

## Test plan

1. 연관이 없는 퀘스트: 빈 섹션이 안 보이고 '연관 추가'만 있는지.
2. 연관이 있는 퀘스트: 해당 섹션만 보이고 섹션별 추가 버튼도 그대로인지.
3. 메뉴 바깥 클릭/Esc 로 닫히는지.
4. 편집 모드에서는 '연관 추가'가 숨는지.
5. 마지막 연관을 제거하면 섹션이 사라지는지.
6. 다크/라이트 양쪽에서 드롭다운 대비가 충분한지.

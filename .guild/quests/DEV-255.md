검색 팔레트(SearchPalette.svelte)에서 결과를 열 때 항상 인라인 미리보기로만
여는 현재 동작을 개선 — 미리보기/자식윈도우/페이지이동 중 선택 가능하게.

## 요구사항 (사용자 원문)

1. 검색팔레트에서 상세 페이지 확인할 때, 무조건 팝업(미리보기)으로 띄우는게
   아니라 미리보기팝업/자식윈도우/페이지이동 등을 선택 가능하도록.
2. 미리보기 팝업으로 연 경우에도, 그 안에서 다시 자식윈도우/페이지이동을
   선택해서 해당 방식으로 전환 가능하도록.
3. (향후) 모바일 UI 도입 시 "모바일 UI로 열기" 같은 모드도 추가 가능하도록
   확장 가능한 구조로.

## UI 결정 (AskUserQuestion, 2026-07-14)

- 선택 UI: 각 검색 결과 행에 아이콘 버튼 3개 (미리보기/자식윈도우/페이지이동)
  상시 노출. 클릭 한 번으로 해당 방식으로 바로 열림 (추가 클릭 없음).
- 자식윈도우: 항목별로 새 Tauri 창을 띄움 (보조 창 재사용 아님). 여러 개
  동시에 띄우고 비교 가능. 창 개수 관리는 OS 작업표시줄에 맡김.

## 현재 구현 (조사 결과)

- `SearchPalette.svelte` — 결과 행 클릭 시 무조건 `openPreview(it)` →
  인라인 미리보기 pane. 거기서 "페이지로 이동 →" 버튼만 `goItem(it)` →
  `goto(it.href)` 로 페이지 이동. 자식윈도우 경로는 아예 없음.
- 자식윈도우(멀티 Tauri window)는 이 프로젝트에 전례 없음 — `tauri.conf.json`
  이 단일 window만 정의, `capabilities/default.json` 도 `"windows": ["main"]`
  으로 create 권한 없음. 신규로 capability 추가 + `WebviewWindowBuilder`
  (Rust) 또는 `@tauri-apps/api/webviewWindow` (frontend) 필요.
- 상세 페이지 라우트는 이미 존재: `/quests/[id]`, `/campaigns/[slug]`
  (rules/library 는 쿼리 파라미터 라우트).

## 설계 방향 (향후 구현 시)

- 열기 모드 타입을 확장 가능한 union/enum 으로 정의 (`preview | window |
  page | mobile(추후)`) — 나중에 mobile 모드 추가가 케이스 추가만으로
  가능하게.
- 미리보기 팝업 내부에도 동일 아이콘 버튼(자식윈도우/페이지이동)을 배치해
  "전환" 가능하게 — 전환 시 미리보기는 닫힘.
- Tauri 미지원 환경(브라우저/HTTP 모드)에서는 자식윈도우 버튼을 숨기거나
  비활성화 — `detectEnvironment()` 로 분기 (기존 SchemaAheadBanner 등에서
  쓰는 패턴과 동일).

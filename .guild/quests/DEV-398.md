## 무엇

**백업이 만들어지면 알린다**(`backup.created`), 그리고 그걸 써서 **백업을 다른 폴더로 복사해
쌓아 두는 예제 플러그인**을 만든다.

admin: *"지금은 백업이 7개밖에 유지되지 않는걸로 아는데, 백업이 생성되면 별도 폴더에 복사해둬서
갯수 제한 없이 계속 저장할 수 있도록 하는 플러그인"*

## 왜

`.guild/backups/snapshots/` 는 **7개만 남기고 오래된 것을 지운다**(`prune_old_snapshots`).
자동 백업은 ops 50개 또는 24시간마다 도니, 바쁜 날에는 며칠 전 상태가 이미 없다. 길드 밖으로
복사해 두면 그 한계가 사라진다 — 그리고 이건 코어가 정책을 더 만들 일이 아니라 **플러그인이
할 일**이다(어디에 얼마나 둘지는 사람마다 다르다).

그런데 지금은 **백업 관련 이벤트가 하나도 없다.** 스냅샷 생성은 `ops` 가 아니라
`core/src/snapshot.rs` 라 카탈로그 검사에도 안 걸렸다. 훅을 걸 자리가 없어서 이 플러그인을
쓸 수 없다.

## 할 것

- 이벤트 `backup.created` — `snapshot::create_snapshot` 에서. **자동 백업도 같은 함수**를
  거치므로 수동·자동 둘 다 알린다. 페이로드: 경로(절대), 시각, 크기, 자동인지.
- 예제 플러그인 `backup-archive` — `run` 으로 스냅샷 파일을 `ARCHIVE_DIR` 로 복사.
  - 대상 폴더는 설정 입력(`inputs`)으로 받는다. 값이 없으면 안 돈다.
  - 스크립트는 rhai `payload` 가 경로만 내보내고, 셸이 그걸 복사한다.
- README·문서에 한 줄.

## 구현

- **이벤트 `backup.created`** — `snapshot::create_snapshot` 에서, **오래된 것을 지운 뒤에**
  낸다(그 전에 내면 구독자가 복사하는 사이에 지워질 수 있다). 페이로드: 절대 경로 · 시각 ·
  크기 · `automatic`. 자동 백업은 같은 함수의 다른 갈래(`create_snapshot_tagged`)로 구분한다.
- **이벤트 검사가 백업까지 본다** — 카탈로그 검사가 `core/src/ops/` 만 훑어서, 길드 파일을
  통째로 만들고 되돌리는 스냅샷 쪽은 사각지대였다. `snapshot.rs` 를 훑는 목록에 넣고
  `create_snapshot`(Emitted) · `maybe_auto_snapshot`(Excluded) · `restore_snapshot`(Excluded,
  이유: 복원은 수백 건을 한 번에 되돌려 개별 변경으로 표현할 수 없다)을 분류했다.
  훑을 때 **시험 모듈을 뺀다** — 시험이 쓰는 가짜 op 이름("t")이 잡혀 오탐이 났다.
- **예제 `backup-archive`** — `run` 으로 스냅샷을 `ARCHIVE_DIR` 로 복사. 설정값 둘
  (`ARCHIVE_DIR`, `ONLY_MANUAL`). rhai 가 복사 여부를 정하고 **경로 한 줄만** 내보내
  셸이 `jq` 없이 처리한다. 같은 이름은 안 덮고, `.part` 로 받아 옮겨 반쪽 파일을 안 남긴다.

### 코어를 하나 고쳐야 했다 — 설정값이 `run` 훅에 안 왔다

설정값은 `${...}` 치환에만 쓰였다. `post` 는 url·헤더·`body_env` 로 값을 쓰지만 `run` 에는
그런 자리가 없어서, **사용자가 넣은 값을 훅이 읽을 방법이 사실상 없었다**(`args` 로 넘기면
토큰이 `ps` 에 보인다). 이제 자식 프로세스의 환경변수로 넣는다. 코어가 주는 경로
(`OPENGUILD_PLUGIN_DIR` 등)는 뒤에 두어 설정값이 못 덮는다.

실환경에서 먼저 밟았다 — 예제를 걸고 백업을 만들었더니 훅이 `exit 1` 로 끝났고, 원인이
`$ARCHIVE_DIR` 가 비어 있던 것이었다. (같이 밟은 것 하나 더: 셸에서 `[ -e "$f" ] && exit 0` 는
`set -e` 아래에서 파일이 **없을 때** 스크립트를 죽인다 — `if` 로 고쳤다.)

## 확인한 것

- 코어 시험 2개(설정값이 자식 환경에 온다 / 코어 경로는 못 덮는다), 이벤트 카탈로그 검사 통과.
- 실제 CLI(임시 길드): 예제를 걸고 백업 → 사본 생성. **백업 10번** 만들어
  `.guild/backups/snapshots/` 는 7개로 유지되는 동안 보관 폴더에는 10개가 남았고, 길드에서
  지워진 가장 오래된 것도 보관 폴더에 그대로 있었다.
- 자동 백업(`OPENGUILD_AUTO_BACKUP_OPS=1`)에서도 이벤트가 나온다 — `ONLY_MANUAL` 을 켜면
  건너뛰고(10 → 10), 끄면 복사한다(10 → 11).
- `just test` 전체 통과.

## 시험 보강

- `snapshot::tests::creating_a_backup_announces_it_with_a_real_path` — 백업 8번(7개 한도를 넘겨)
  모두 `automatic: false`·절대 경로이고, **방금 것의 파일이 실제로 있다**(지운 뒤에 알리는지).
  자동 백업은 `automatic: true`. 자동 여부를 늘 false 로 되돌리면 실패한다.
- 이벤트 전수 시험에 백업을 넣었다 — 그래서 예제 `backup-archive` 의 스크립트가 **실제
  `backup.created` 페이로드**로 돈다. 스크립트가 없는 필드를 읽게 바꾸면 "배포 예제가 죽는다" 로
  실패한다(이전에는 이 예제가 아무 이벤트도 못 받아 검사 밖이었다).

## 테스트 방법

- 수동 백업(`openguild backup new`)과 자동 백업 둘 다에서 이벤트가 나온다.
- 페이로드의 경로로 **실제 파일이 그 자리에 있다**.
- 예제 플러그인을 걸고 백업을 만들면 대상 폴더에 사본이 생긴다. 8번째 백업을 만들어
  `.guild/backups/snapshots/` 에서 가장 오래된 것이 지워져도 **사본은 남아 있다**.

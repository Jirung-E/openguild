## 요청

도서관 화면의 검색에서도 [[REQ-009]] 의 강화된 검색을 쓸 수 있는 옵션을 추가한다.

## 배경

[[REQ-010]] 이 퀘스트 목록에 A 방식(대상을 그 화면의 문서 종류로 한정)을
적용하는데, 같은 논리로 도서관에도 필요하다. 도서관 문서(BOOK)에도 **댓글과
첨부**가 달리므로 본문만 검색해서는 놓치는 게 생긴다.

## 범위

- 도서관 목록/사이드바 검색에 영역 옵션(`댓글 포함` / `첨부 이름 포함`).
- 대상은 **도서관 문서로 한정** — 결과 형태는 지금과 동일하게 유지한다.
- 메모는 도서관에 없으므로 해당 없음.

## 확인 필요

도서관 검색이 현재 어떻게 동작하는지 먼저 확인할 것 — 클라이언트 필터인지
서버 쿼리인지에 따라 붙이는 지점이 달라진다. (퀘스트 목록은 서버 `?search=`
를 탄다.)

## 테스트 방법

1. BOOK 댓글에만 있는 단어로 검색 → 옵션을 켰을 때만 나오는지.
2. 첨부 이름으로 검색 → 마찬가지.
3. **회귀** — 옵션을 끄면 기존 결과와 동일한지.

---

## 수정 내용 (2026-08-21)

### 범위 정정 — 도서관 문서에는 **댓글이 없다**

퀘스트 본문에 "댓글 포함 / 첨부 이름 포함" 을 적었지만, 확인해 보니 도서관
문서는 **첨부만 있고 댓글 기능이 없다**(`openguild library --help` 에 `attach`
만 있고 `comment` 가 없다). 그래서 실제 범위는 **첨부 이름뿐**이다 — 본문과
제목은 이미 클라이언트에서 검색된다.

### 구현

도서관 검색도 [[REQ-010]] 의 목록과 같은 구조 — 전체를 받아 클라이언트에서
필터하는데(`searchBooks`), 첨부 이름은 목록 응답(`list()`)에 없다
(`attachments` 는 `get()` 에서만 채워진다).

그래서 **옵션이 켜졌을 때만** 서버에 판정을 맡긴다:

- [[REQ-009]] 의 `/api/search?q=…&in=attachment` 를 **그대로 재사용**하고
  `kind === 'book'` 만 추려 `book_id` 집합을 만든다. 새 서버 코드가 필요 없다.
- `searchBooks(books, query, attachIds)` — 제목/본문 매치와 **OR** 로 합친다.
  (제목 매치는 상단, 본문·첨부 매치는 그 아래 — 기존 정렬 규칙 유지.)
- 디바운스 250ms + stale-async 가드, 실패 시 기존 동작으로 폴백.
- 검색줄이 **두 곳**(트리 뷰 / 사이드바)이라 양쪽 모두에 체크박스를 넣었다.

`lib/api/search.ts` 를 새로 만들어 REQ-009 엔드포인트의 프론트 클라이언트를
정리했다 — [[REQ-012]](팔레트)에서도 그대로 쓴다.

## 검증

BOOK-001 에 `bookdoc.md` 첨부를 임시로 달고 확인 후 제거했다.

| 확인 | 결과 |
|------|------|
| 서버 `/api/search?q=bookdoc&in=attachment` | `('book','BOOK-001',['attachment'])` |
| 도서관 화면, 옵션 끔 | 안 나옴 — **회귀 없음** |
| 옵션 켬 | `설계 결정 기록 (개정)` 표시 |

프론트 418 passed, `svelte-check` 0 errors.

### 검증 중 실수

결과 확인 마커로 실 길드 BOOK-001 의 제목(`일방향…`)을 썼는데 **테스트 길드의
BOOK-001 은 제목이 다르다**(`설계 결정 기록 (개정)`). 잠깐 "동작 안 함" 으로
오판했다 — 검증 마커는 그 길드의 실제 데이터에서 가져와야 한다.

## 테스트 방법

1. BOOK 에 첨부를 달고 그 **파일 이름**으로 도서관 검색 → 옵션을 켰을 때만 나오는지.
2. **회귀** — 옵션을 끄면 제목/본문 검색 결과가 이전과 동일한지.
3. 트리 뷰와 탐색기(사이드바) 양쪽 검색줄에서 모두 되는지.

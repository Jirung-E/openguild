## 증상

본문에 첨부한 이미지의 **파일명에 띄어쓰기가 있으면** 이미지로 안 나오고
마크다운 원문이 글자 그대로 보인다(admin 보고).

## 원인 — 마크다운 링크 목적지에 공백이 못 들어간다

저장 파일명은 원본 이름을 살린다([[DEV-324]]) — 목록에서 알아보라고. 그리고
`sanitize_stem`(`core/src/ops/attachments.rs`)은 **공백을 일부러 남긴다**
(제어문자와 예약문자 `/\:*?"<>|` 만 `_` 로 바꾼다). 그래서 rel 경로에 공백이
그대로 들어간다:

```
attachments/스크린샷 2026-09-04-1a2b3c4d00000001.png
```

`editor-attach.ts` 의 `markdownFor` 는 이걸 그대로 감쌌다:

```js
if (IMAGE_EXTS.has(ext)) return `![${name}](${rel})`;
```

CommonMark 에서 **꺾쇠 없는 링크 목적지에는 공백이 올 수 없다.** 실측:

```
IN : ![스크린샷 2026.png](attachments/스크린샷 2026-abc.png)
OUT: <p>![스크린샷 2026.png](attachments/스크린샷 2026-abc.png)</p>   ← 글자 그대로

IN : ![스크린샷 2026.png](<attachments/스크린샷 2026-abc.png>)
OUT: <p><img src="attachments/%EC%8A%A4...%202026-abc.png" alt="..."></p>
```

### 범위는 이미지뿐이다

동영상은 `<video src="...">` — HTML 속성이라 공백에 안전하다.

**비미디어(PDF 등)는 애초에 본문에 안 들어간다.** `attachmentExtension` 이
셋으로 갈린다(`editor-attach.ts`):

```js
if (opts.mediaOnly && !isMedia(up.ext)) { onError(...); return 0; }   // 메모·규칙: 차단
if (onAttach && !isMedia(up.ext)) { uploadToSection(...); return 0; } // 퀘/캠/도서관: 첨부 섹션
return uploadAndInsert(...);                                          // 미디어만 본문
```

실제 호출부가 전부 `mediaOnly` 아니면 `onAttach` 라서 `markdownFor` 의 링크
분기는 도달하지 않는다(`MarkdownEditor.svelte` 주석도 "미지정 + mediaOnly=false
조합은 없음" 이라고 못박고 있다). 링크 분기도 같은 규칙으로 고쳐 두지만
**동작 변화는 없다** — fallback 이 열릴 때를 대비한 것이다.

## 꺾쇠로 감싸면 뒤가 둘 더 있다

**(1) 디코드가 필요하다.** `<...>` 로 감싸면 marked 가 파싱은 하지만 src 를
퍼센트 인코딩해서 낸다. `MarkdownView.rewriteLocalMedia()` 는 그 값을
`guildFileUrl(rel)` 에 넘기고, Tauri 분기는
`convertFileSrc(`${root}/.guild/${rel}`)` 라 **실제 파일 경로**여야 한다.

**(2) 그 디코드가 던진다.** marked 는 `encodeURI` 계열이라 `%` 를 인코딩하지
않는다. `100%.png` 이면 `%.p` 가 잘못된 이스케이프가 되어 `decodeURI` 가
`URIError` 를 던진다(실측). 그대로 두면 공백 버그를 `%` 버그로 바꾸는 것뿐이라
실패 시 원문을 쓰게 감싼다.

**(3) HTTP 경로는 반대로 인코딩이 없다.** `guildFileUrl` 의 브라우저/원격
분기는 `/api/guild-files/${rel}` 로 rel 을 날것으로 넣는다. 공백도 문제지만
`#` 는 조각 구분자라 **거기서 잘린 채** 전혀 다른 경로를 요청한다.

## 고르지 않은 선택지

파일명에서 공백을 `_` 로 바꾸는 방법도 있지만 택하지 않는다 — **이미 저장된
첨부는 안 고쳐지고**, DEV-324 가 원본 이름을 남긴 이유(목록에서 알아보기)를
깎는다. 생성부(마크다운)와 소비부(재작성)를 고치면 기존 첨부도 같이 낫는다.

## 구현

1. `markdownFor` — 목적지를 `<...>` 로. `sanitize_stem` 이 `<`/`>` 를 `_` 로
   바꾸므로 우리가 만드는 경로에서 꺾쇠가 조기 종료되지 않는다.
2. `banner.ts` 의 `decodeRelPath` — `decodeURI` + try/catch, 실패 시 원문.
3. `banner.ts` 의 `encodeRelPath` — 세그먼트별 `encodeURIComponent`(`/` 보존).
   HTTP 분기에만 적용하고 Tauri 분기는 파일 경로 그대로 둔다.
4. `MarkdownView.rewriteLocalMedia` — `guildFileUrl` 호출 전에 디코드.

## 검증

`attachment-markdown.test.ts` 29건 — 삽입부터 로드까지 **한 줄로 이어서**
고정한다(셋 중 하나만 검증하면 통과하는데도 화면은 깨진다):

```
markdownFor  →  marked 파싱  →  decodeRelPath  →  파일 경로
```

파일명 10종(공백/한글/`(`/`#`/`&`/`'`/`[`/`%`/평범)에 대해 이미지로 파싱되는지,
디코드가 원래 경로로 왕복하는지, 인코딩이 URL 로 안전한지.

**되돌려서 무는 것까지 확인했다:**

| 되돌린 것 | 결과 |
|-----------|------|
| `markdownFor` 의 꺾쇠 제거 | 8 failed |
| `decodeRelPath` 의 try/catch 제거 | 2 failed |
| `encodeRelPath` 를 항등으로 | 6 failed |

전체: frontend 639 pass, `npm run check` 0 errors, 스타일 가드 5종 통과.

## 테스트 방법

1. 공백이 든 이름의 이미지를 본문에 붙여넣기/드래그 → 이미지로 보인다.
2. 한글+공백 조합도 동일.
3. 공백 없는 기존 첨부가 그대로 보인다(회귀 없음).
4. 데스크톱과 브라우저(원격) 양쪽에서 확인 — 인코딩 분기가 다르다.

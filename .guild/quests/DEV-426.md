도서관 문서가 폴더 없이 나란히 있고, 기본 아키텍처 문서(BOOK-003)에 플러그인이 없다(admin).

## 정한 것

- **시제로 나눈다.** `아키텍처/` 는 지금 모습(코드가 바뀌면 같이 고친다), `설계 기록/` 은 그때 왜
  그렇게 정했나(고치지 않는다), `조사 기록/` 은 조사 과정. 같은 층에 있으면 "지금도 맞는 얘기인가" 를
  매번 따져야 한다.
- **아키텍처는 개괄 / 상세로 나눈다.** 개괄은 모듈끼리의 관계, 상세는 모듈 하나씩. 한 문서에 다
  넣으면 비대해진다.
- **AGENTS.md 는 안 건드린다.** 이미 "아키텍처 → `openguild library list`" 로 번호 없이 가리킨다.
  exe 사용자에게 필요한 플러그인 구조는 배포되는 스킬(`reference/plugins.md` ·
  `openguild-plugins`)에 이미 다 있다 — 항목별로 대조해 확인했다.

## 할 일

1. 폴더 — `아키텍처/`, `아키텍처/상세/`, `설계 기록/`, `조사 기록/`
2. BOOK-003 을 쪼갠다 — 개괄(전체 구조·원칙·크레이트 관계) / 상세-저장소(데이터 모델·안전장치) /
   설계 기록(변경 이력). 09-06 이후 낡은 곳은 지금 코드에 맞춘다(잠금이 프로세스 사이도 막는 것 등)
3. 상세-플러그인·이벤트를 새로 쓴다 — 코드 주석에만 흩어진 것(실행 모델, 컴포넌트별 차이, 동의,
   폴더, 체인)과 파일 지도
4. BOOK-001 → 아키텍처, BOOK-002 → 조사 기록, BOOK-004 → 설계 기록

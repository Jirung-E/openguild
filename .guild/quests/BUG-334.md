## 무엇이 잘못됐나

CLI 로 댓글을 달면 이 경고가 뜬다(admin, 윈도우에서 `claude` 로).

```
⚠ plugin delivery did not finish within 2000ms and was cut short
```

**두 가지가 문제다.**

**1. 말이 사실과 다르다.** "중단했습니다 / cut short" 는 **일을 죽였다**는 뜻으로 읽힌다.
실제로는 아니다 — 재 봤다.

```
02:04:27  ⚠ 플러그인 전달이 2000ms 안에 안 끝나 중단했습니다
02:04:35  늦게 끝남          ← 8초 뒤 멀쩡히 끝남
02:04:35  명령  …            ← 영수증도 남음
```

CLI 가 **기다리기를 그만둔 것**이지 훅은 계속 돈다. 그런데 사용자는 실패로 읽고 답글을
기다리지 않는다.

**2. 문서에 안 적혀 있다.** AI 를 부르는 예제는 본질적으로 5~15초가 걸린다. 기본 드레인
2초로는 **반드시** 이 경고가 뜬다. 그런데 README 의 예시에는 `OPENGUILD_PLUGIN_DRAIN_MS`
이야기가 한 줄도 없다 — **내가 시험할 때마다 그 값을 올려 놓고 적지를 않았다.** 그래서
"내 환경에서는 됐다" 가 됐다.

앱·서버는 계속 살아 있으므로 이 문제가 없다. **CLI 로 시험할 때만** 걸린다.

## 고칠 방향

- 경고 문구를 사실대로 — 기다리기를 그만뒀을 뿐이고 훅은 계속 돌 수 있다는 것,
  그리고 기다리려면 무엇을 올리면 되는지.
- README 의 AI 예시에 **드레인 이야기를 같이** 적는다. 시한(60초)만 적고 드레인을 빼면
  반쪽이다.

## 테스트 방법

- 느린 훅을 CLI 로 돌리면 경고가 뜨되, 그 말이 "죽었다" 로 안 읽힌다.
- README 대로 따라 하면 CLI 에서도 답글을 끝까지 본다.

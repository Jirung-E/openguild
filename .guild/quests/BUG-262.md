## 증상

퀘스트 상세에서 상태를 바꾸면 반영까지 눈에 띄게 걸린다(admin 보고,
"아직도 느리다").

## 원인 — 백엔드가 아니라 화면이 왕복을 세 번 한다

먼저 백엔드를 쟀다. **거의 공짜다:**

```
$ time openguild quest move DEV-001 in_progress
real 0.01 / 0.00 / 0.00  (6회, 테스트 길드)
```

느린 쪽은 `routes/quests/[id]/+page.svelte` 의 `changeStatus()` 였다:

```js
changingStatus = true;                              // ← 버튼 잠금 시작
await questsApi.changeStatus(detail.id, {...});     // ① PATCH
detail = await questsApi.getBySlug(slug);           // ② 퀘스트 전체 재조회
historyVersion += 1;                                // ③ 블록 재마운트
```

- ②는 **방금 바꾼 필드 하나 때문에** 본문·관계·태그·첨부를 통째로 다시 받는다.
  응답이 오기 전까지 화면은 옛 상태 그대로다. 게다가 PATCH 응답을 **버린다** —
  서버 `change_status` 는 이미 갱신된 `Quest` 를 돌려준다.
- ③은 `{#key `${detail.id}:${historyVersion}`}` 이라 블록을 파괴 후 재생성한다.
  그 key 안에는 이력과 **무관한** `BacklinkSection` 도 들어 있어 같이 다시
  읽었고, 펼쳐 둔 이력이 매번 도로 접혔다.
- 셋이 직렬이고 그동안 버튼이 잠겨 있다. 체감 지연은 셋의 합이다.

## 보드는 처음부터 제대로 하고 있었다

`QuestBoard.svelte` 는 성공 응답이 오면 아는 값으로 로컬만 갱신한다
(`applyStatusChange`) — 재조회가 없다. 설계가 갈린 게 아니라 상세만
안 맞춰져 있었다.

## 구현

1. **재조회 제거.** PATCH 응답을 그대로 쓴다:
   `detail = { ...detail, ...updated }`. `QuestDetail` 은 `Quest` 를 확장한
   것이라 응답이 가진 기본 필드(status_*, updated_at ...)만 새 값으로 바뀌고
   관계·태그·첨부처럼 상태와 무관한 것은 그대로 남는다. 필드를 손으로 골라
   덮는 것보다 안전하다 — 서버가 필드를 늘려도 자동으로 따라온다.
2. **이력은 제자리에서.** `QuestHistory` 에 `reloadToken` prop 을 두고 key 에서
   `historyVersion` 을 뺐다. 재마운트가 없어지니 `BacklinkSection` 의 불필요한
   재조회도 사라지고, 펼쳐 둔 접힘 상태도 유지된다.

낙관적 갱신(응답 전 미리 반영)은 넣지 않았다. PATCH 가 10ms 대라 왕복 하나면
체감이 없을 것으로 보고, 실패 시 되돌리는 복잡도를 지금 들일 이유가 없다.
그래도 느리면 그때 넣는다.

## 검증에서 걸린 것 — 테스트가 안 물었다

처음 테스트는 `@testing-library/svelte` 의 `rerender` 로 `reloadToken` 을
바꿔 재조회를 확인했다. **그 테스트는 아무것도 지키지 못한다** — `rerender` 는
props 를 통째로 무효화해서 값이 하나도 안 바뀌어도(같은 배열 참조를 넘겨도)
이펙트가 다시 돈다. `void reloadToken` 의존성을 지워도 **그대로 통과**했다
(되돌리기 시험에서 발각).

부모가 `$state` 로 토큰을 들고 바꾸는 래퍼(`QuestHistoryHarness.svelte`)를
거쳐 Svelte 자신의 반응성을 타게 고쳤다. 이제 의존성을 지우면 2건이 실패한다.

"토큰이 그대로면 다시 읽지 않는다" 는 **검증하지 않는다** — 위 이유로 이
하니스에서는 표현할 수 없다. 억지로 단언하면 거짓을 고정하게 되므로 테스트
파일에 이유를 적어 두었다.

## 검증

- QuestHistory 12건(신규 3건). 되돌리기 시험 통과 — `reloadToken` 의존성 제거
  시 2 fail.
- frontend 648 pass, `npm run check` 0 errors, 가드 7종 통과.
- `QuestHistory.svelte` 는 원래 prettier-clean 이 아니었다(마크업 들여쓰기).
  무관한 재포맷은 하지 않고 이번 변경 부분만 남겼다.

## 테스트 방법 (실기)

1. 상세에서 상태 버튼을 누르면 뱃지/버튼이 곧바로 바뀐다.
2. 이력 섹션에 새 행이 뜨는데, 그것 때문에 상태 반영이 늦지 않는다.
3. 이력을 펼쳐 둔 채 상태를 바꿔도 **펼침이 유지된다**(예전엔 접혔다).
4. 서버를 내린 뒤 상태 변경 → 토스트가 뜨고 상태는 원래대로 남는다.
5. 보드에서의 상태 변경은 기존과 동일(회귀 없음).

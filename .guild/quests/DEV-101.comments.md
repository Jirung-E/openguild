## 기능
Settings 페이지의 "표시" 섹션에 UI 크기 슬라이더.

## 사용
1. 상단 Nav 의 ⚙ 아이콘으로 Settings 진입.
2. "표시" 섹션의 슬라이더 (50% ~ 200%, 10% 단위) 드래그 또는 키보드 좌우.
3. 즉시 반영. localStorage 자동 저장 → 다음 실행 시 복원.
4. "초기화" 버튼으로 100% 로 reset (현재 100% 면 비활성화).

## 구현
- `lib/stores/uiScale.ts` — writable<number> + localStorage 영속 (key `openguild.uiScale`). 0.5 ~ 2.0 clamp.
- `applyUiScaleToDocument(s)` 가 `<html>` 의 font-size 갱신 (base 16px × scale).
- rem 기반 layout 전체가 비례 확대/축소.
- HTTP / Tauri 양쪽 동작 (옵션 A — root font-size). Tauri webview `setZoom` (옵션 C) 는 별도.

## 테스트
1. 슬라이더 50% / 100% / 150% / 200% 로 → UI 크기 변하는지.
2. 새로고침 / 앱 재시작 후 마지막 값 유지되는지.
3. "초기화" 버튼 → 100% / 슬라이더도 100% 위치.
4. localStorage 직접 ("openguild.uiScale" = "99") 변경 후 새로고침 → MAX 로 clamp.
5. QuestBoard 의 cy node 크기 / Home 의 px 직접 사용 영역에서 layout 깨짐 확인 (있으면 후속 fix 대상).

## 자동 검증
- `npm test uiScale` — 9 vitest (default / 영속 / clamp / garbage / set / reset / applyToDocument).

## 향후 (이 quest 범위 외)
- Tauri webview setZoom (옵션 C) — px 직접 사용 영역까지 자동 확대.
- Nav 우상단 ⚙ 옆 +/- 즉시 변경 버튼.
- 다크 / 라이트 모드 (DEV-074) 와의 통합.

## 원인
oninput 마다 setUiScale → `<html>` 의 font-size 갱신 → rem 기반 슬라이더 자체 위치 / 크기 변동 → 사용자 마우스가 thumb 보다 빨리/늦게 → 손 놓침 + 진동.

## 수정
oninput 과 onchange 분리:
- oninput (drag 중): previewScale state 만 갱신 → % 표시만 변화. 실 font-size 변경 X → 슬라이더 자체 stable.
- onchange (mouseup): setUiScale 호출. previewScale = null 로 reset.

displayScale() 헬퍼가 previewScale ?? $uiScale 반환.

scale-hint 도 "drag 중엔 미리보기, 손 떼면 적용" 으로 갱신.

## 테스트
1. 슬라이더 잡고 50% → 200% 끝까지 drag.
2. drag 중 thumb 이 마우스에서 안 벗어남.
3. % 표시는 실시간 변화.
4. 손 놓으면 그 시점에 font-size 일괄 적용.

## fix2~5 (2026-06-07): 슬라이더 + 컨텐츠 폭 + Nav rem

### fix2 — CustomSlider 도입 + 컨텐츠 폭 슬라이더 (73111fa)
native `<input type="range">` 의 두 문제 회피:
1. value 가 store 와 양방향 바인딩 안 되면 drag 중 thumb 가 reactive cascade 로 튕김.
2. UI scale 슬라이더처럼 자기 자신 변형 → 절대 위치 매핑이 깨짐.

`CustomSlider.svelte`:
- 트랙 click → thumb 점프 (즉시 commit).
- thumb 잡고 drag → `movementX` 델타 누적 — 페이지 변형 무관.
- pointer capture / 키보드 ← → Home End PageUp/Down 지원.

`contentWidth` store (`gui/frontend/src/lib/stores/contentWidth.ts`):
- 600~1800px, 기본 1100px. `--content-max-width` 토큰으로 `<html>` 에 반영.
- Home / Campaigns 목록·상세 / Rules / Quest 상세 / Admin / Settings 의 `.page max-width` 가 `var(--content-max-width, <기존값>)` 사용.

### fix3 — 즉시 적용 + 설정 페이지 폭 (afe10c6)
- `onInput` / `onChange` 두 콜백 + preview 상태 제거 → 단일 `onChange`.
- drag 중 매 step 마다 onChange 호출 — 손 떼기 안 기다림.
- `dragAcc` (drag 시작 시점 값) 을 movementX 누적 베이스로 → 외부 value commit 이 즉시 갱신돼도 튐 없음.
- `pixelsPerUnit` 을 pointerdown 시 한 번 측정 → drag 중 layout 변화에도 일관.
- `.settings { max-width: 900px }` → `var(--content-max-width, 900px)` — 설정 페이지 본인부터 즉시 반영.

### fix4 — step 세분화 + 직접 숫자 입력 (3fbc32a)
- UI 크기 step `0.05 → 0.01` (1%).
- 컨텐츠 폭 step `20 → 5` (5px).

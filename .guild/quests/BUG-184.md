macOS 실기(2026-08-01, just test-rust): gui/src/lib.rs 의 resolve_env_used_when_argv_empty 테스트가 assert_eq!(p, dir) 로 canonicalize 없이 직접 비교 — absolutize() 가 내부적으로 std::fs::canonicalize() 를 호출해 macOS 의 /var -> /private/var 심링크를 해소하므로 실제 값(p)과 원본 임시경로(dir)가 문자열로 안 맞음. 같은 파일의 다른 유사 테스트들(resolve_argv_dir_no_marker_uninit / resolve_argv_guild_file_wins 등)은 이미 양쪽을 canonicalize 해서 비교하는 패턴 — 이 테스트만 빠져 있었음. 앱 로직(resolve_launch_mode/absolutize) 자체엔 버그 없음, 테스트 어서션만 수정.

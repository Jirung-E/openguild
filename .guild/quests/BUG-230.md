## 배경

[[DEV-166]]에서 CLI 명령 개편에 따른 문서 갱신을 수행했고, [[BUG-229]]에서 구 `rm` 표기 6곳을 `remove`로 수정했다. 이후 현행 에이전트 지침·배포 스킬 레퍼런스·설계 문서·CLI 자체 도움말을 `cli/src/main.rs`의 clap 정의 및 기존 `target/release/openguild --help`와 다시 대조한 결과, `rm` 외에도 실제 호출이 실패하거나 동작 의미를 잘못 설명하는 불일치가 남아 있음을 확인했다.

현재 검증 수준은 다음과 같다.

- **확인 완료:** clap 정의, 실행 분기, 기존 release 바이너리의 `--help`, 존재하지 않는 서브커맨드의 거부 여부.
- **미확인:** 테스트 길드에서 실제 데이터 mutation 결과, 정렬 결과, restore/delete 안전장치의 전체 런타임 동작.
- 따라서 아래 항목은 문법·도움말 불일치로는 확인됐지만, 수정 전 테스트 길드에서 현재 동작을 한 번 더 재현해야 한다.

관련 영구 규칙: [[cli-command-naming]], [[restore-behavior]], [[test-data-script]].

## 구현 원칙

- 현행 CLI 동작을 제품 의도로 볼 수 있는 항목은 문서·도움말을 구현에 맞춘다. CLI 자체를 문서에 맞게 바꾸려면 별도 제품 결정이 필요한지 먼저 판단한다.
- `rm`, `quest template`, `--emoji`처럼 존재하지 않는 별칭을 편의를 이유로 새로 추가하지 않는다. canonical 명령을 문서에 정확히 기록한다.
- comment의 작성자 기록 정책은 유지하되, author를 지원하지 않는 memo와 분리한다. 필요하면 memo attribution 기능은 별도 퀘스트로 다룬다.
- CHANGELOG와 과거 퀘스트/댓글처럼 당시 명령을 기록한 역사 자료는 수정하지 않는다. 현행 사용 문서·스킬·도움말만 수정한다.
- 설치된 plugin cache가 아니라 저장소의 정식 스킬 소스를 수정한다.

## 테스트 방법

1. 빈 임시 디렉터리에 `scripts/seed-test-data.mjs`와 현재 바이너리로 테스트 길드를 생성한다. 기존 길드에서는 destructive 명령을 실행하지 않는다.
2. 테스트 길드에서 `tag add/update`, `worklog note show/set/clear`, `template list/show`, comment react, memo set의 문서상 수정된 명령이 성공하는지 확인한다. 기존 잘못된 `quest template`, `--emoji`, memo `--author`, worklog `--date`는 명확히 거부되는지 확인한다.
3. 테스트용 quest에서 `quest status <slug> <STATUS>`가 실제 mutation임을 확인한 뒤 `quest move`로 원복한다. 문서에는 deprecated mutation임을 명확히 남긴다.
4. 댓글을 시간순으로 여러 개 넣어 전역 `comments`와 `quest comment list`의 기본 순서·`--reverse`·`--summary` 출력을 확인한다. 전역 comments가 다른 길드까지 검색하지 않으며 Local 전용인지도 확인한다.
5. 캠페인 체크리스트를 추가한 뒤 1-based index로 check/uncheck/remove가 동작하고 항목 삭제 후 index가 재배치되는지 확인한다.
6. 별도의 폐기 가능한 테스트 길드 복사본에서 `backup new/list/remove`, `restore`, `restore --to <timestamp>`, `restore --at <ISO8601 UTC>`, `restore --at latest`를 [[restore-behavior]] 표대로 확인한다. `restore --list` 대신 `backup list`를 사용한다.
7. quest/campaign/library/rule/comment/tag/backup 삭제 명령의 확인 옵션과 dry-run 지원 여부를 각각 `--help` 및 폐기 가능한 데이터로 확인한다.
8. 수정 후 현행 문서에서 잘못된 명령 패턴을 재검색하고, CLI help의 기본 정렬·본문 출력 설명이 실행 결과와 일치하는지 확인한다.

검증 중 발견(2026-10-12, DEV-433 · DEV-435 3단계를 웹으로 확인하다가). **퀘스트 타입 바꾸기(DEV → BUG)가 서버에 없다.**

## 증상

- 데스크톱 앱(로컬 길드)은 타입 변경을 앱 내부 호출(`change_quest_type`)로 처리해서 된다.
- 서버에는 같은 HTTP 경로(`PATCH /api/quests/{id}/type`)가 없다 → **웹 화면과, 원격 길드에 붙은 앱**에서 타입을 바꾸면
  "그런 API 가 없습니다: /api/quests/833/type".
- DEV-193 의 교훈("GUI 가 쓰는 모든 내부 호출에 대응 HTTP 필수")에서 빠진 하나.

## 다른 빈 곳은 없나

앱의 API 파일(`gui/frontend/src/lib/api/*.ts`)이 부르는 101개 경로와 앱 쪽 시험의 57개 경로를 길드 사본 서버에 하나씩 보내
봤다 — 실제로 빠진 것은 이것 하나다.

## 고칠 것

서버에 `PATCH /api/quests/{id}/type` — 코어 `ops::change_quest_type` 을 그대로 부르는 얇은 어댑터. 서버 시험.

## 고침 (2026-10-12)

서버에 `PATCH /api/quests/{id}/type` — 코어 `ops::change_quest_type` 을 그대로 부르는 얇은 어댑터(앱의 내부 호출과 같은 함수).

**시험** `test_change_quest_type_endpoint_renames_and_keeps_tags` — 새 번호로 열리고 태그가 남고 옛 번호는 404. 경로를 빼면
실패하는 것을 확인했다.

확인(길드 사본 서버): 웹과 같은 경로로 타입을 바꾸니 새 번호 파일로 옮겨지고 번호(version)가 하나 오르고 태그 · 댓글이
그대로였다([[DEV-433]] 3단계). 웹에서 편집하는 사이 타입이 바뀌면 "번호가 바뀌었습니다" 와 "새 번호로 열기" 가 뜨고 내 글이
남았다([[DEV-435]] 3단계). `just test` 통과.

## 테스트 방법

1. 웹 화면(또는 원격 길드에 붙은 앱)에서 퀘스트 상세 → 타입을 바꾼다(DEV → BUG) → 번호가 바뀌고 새 번호로 열린다.
2. 파일 이름이 새 번호로 바뀌고, 태그 · 댓글이 그대로다.

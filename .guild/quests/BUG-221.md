최근 본 문서(검색 팔레트 recent 모드, `SearchPalette.svelte`)에서 항목을 클릭해도 해당 문서가 안 열림 — 미리보기/새창/페이지이동 3가지 방식 전부 안 됨.

## 재현 조건 (사용자 확인, 2026-08-08)

- **Tauri 데스크톱 앱에서만 재현. 웹(브라우저)에서는 정상.**
- 버튼 클릭 자체는 반응(눌리는 건 보임)하지만 그 이후 화면이 안 바뀜.

## 원인 (확정 — 코드 비교로 확인)

Tauri 데스크톱에서만 렌더되는 `TitleBar.svelte`(`usesCustomTitlebar()` —
웹은 대신 `Nav.svelte`)의 바깥 클릭 감지에 **DEV-294 리팩터 이후 정리 안 된
죽은 코드**가 있었다:

```js
function onWindowMouseDown(e: MouseEvent) {
    if (!menuOpen && !recentOpen) return;
    const t = e.target as HTMLElement;
    if (menuOpen && !t.closest('.tb-menu-wrap')) menuOpen = false;
    // DEV-276: 최근 문서 드롭다운도 같은 경로로 바깥 클릭 닫기.
    if (recentOpen && !t.closest('.tb-recent-wrap')) recentOpen = false;
}
```

`recentOpen` 을 닫는 이 줄은 **DEV-276 시절**(최근 문서가 전용 드롭다운이라
`.tb-recent-wrap` 안에 실제로 렌더됐던 때) 코드다. **DEV-294** 에서 전용
드롭다운을 없애고 `<SearchPalette mode="recent">` 로 교체했는데(팔레트는
`.tb-recent-wrap` **밖에** 별도로 렌더됨), 이 mousedown 핸들러는 안
지워졌다. 그 결과 팔레트 안(row-act 버튼 등)에서 클릭해도
`t.closest('.tb-recent-wrap')` 가 항상 실패해 **click 이벤트가 버튼에
도달하기 전에(mousedown, capture 단계) `recentOpen = false` 로 팔레트가
먼저 닫혀버림** — "클릭은 되는데 화면이 안 바뀜"과 정확히 일치.

`SearchPalette.svelte` 자기 자신도 이미 올바르게 스코프된(`.palette` 기준)
바깥 클릭 감지를 갖고 있어서(Nav.svelte 는 이 문제가 없음 — `recentOpen` 을
별도로 안 건드림), TitleBar 의 이 중복+잘못된 스코프 체크만 없애면 된다.

**왜 웹에선 안 터졌는지**: 웹은 `usesCustomTitlebar()` 가 false 라
`TitleBar.svelte` 자체가 안 렌더되고 `Nav.svelte` 가 쓰이는데,
`Nav.svelte` 의 mousedown 핸들러는 `moreOpen` 만 관리하고 `recentOpen` 은
안 건드림(SearchPalette 자체 로직에 위임) — 그래서 정상 동작했음.

## 수정

`TitleBar.svelte` 의 `onWindowMouseDown` 에서 `recentOpen` 관련 죽은 코드
제거 — `menuOpen` 만 관리하도록. `recentOpen` 닫기는 `SearchPalette` 자체
(`onclose` 콜백)에 위임(이미 Nav.svelte 와 동일한 정상 패턴).

## 테스트 방법

Tauri 데스크톱 앱에서: 최근 본 문서 열고 항목의 이동/새창/미리보기 버튼
클릭 시 정상 동작(화면 전환/새 창/미리보기 패널)하는지 확인.

(이 세션은 Tauri 데스크톱 앱을 직접 빌드/구동할 수 없어 — `usesCustomTitlebar()`
가 Tauri 환경 감지에 의존하고, 그 감지 플래그를 브라우저에서 가짜로 켜면
API 전송 계층 전체가 Tauri invoke 경로로 바뀌어 페이지가 통째로 깨짐 —
정적 코드 비교로 원인을 확정했을 뿐 실기기 검증은 못 했음. 실제 앱에서
확인 부탁드립니다.)

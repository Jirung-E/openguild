최근 본 문서(검색 팔레트 recent 모드, `SearchPalette.svelte`)에서 항목을 클릭해도 해당 문서가 안 열림 — 미리보기/새창/페이지이동 3가지 방식 전부 안 됨.

## 재현 조건 (사용자 확인, 2026-08-08)

- **Tauri 데스크톱 앱에서만 재현. 웹(브라우저)에서는 정상.**
- 버튼 클릭 자체는 반응(눌리는 건 보임)하지만 그 이후 화면이 안 바뀜.

## 조사 — 유력 가설

`SearchPalette.svelte` 의 바깥 클릭 감지 로직(DEV-255 4차 수정)이 원인일
가능성이 높다:

```js
// mousedown, capture:true 로 window 에 등록
function onWindowMouseDown(e: MouseEvent) {
    const target = e.target as HTMLElement;
    if (!target.closest('.palette')) onclose();
}
```

이 핸들러는 애초에 **Tauri 가 주입하는 drag-region 스크립트**(타이틀바
`data-tauri-drag-region` 위 mousedown 에서 `stopImmediatePropagation()`
호출)를 우회하려고 capture 단계로 옮겨진 전례가 있다(주석 참조). 클릭은
"mousedown → mouseup → click" 순서로 일어나는데, `row-act` 버튼(이동/
새창/미리보기)의 `onclick` 은 마지막 `click` 이벤트에서 실행된다. 만약
Tauri 웹뷰에서 `mousedown` 시점의 `e.target` 이 (drag-region 스크립트나
다른 웹뷰 특이 동작으로) `.palette` 조상 체인을 못 찾는 경우가 있다면,
`onclose()` 가 **click 이 실행되기 전에** 팔레트를 먼저 unmount 시켜버려
버튼의 `onclick` 이 아예 실행되지 못한다 — "클릭은 되는데(눌림 표시) 화면은
안 바뀜"과 정확히 일치하는 증상.

**미검증** — 이 저장소를 다루는 이 세션에서 Tauri 데스크톱 앱을 직접
빌드/구동해 재현할 수 없어(GUI 상호작용 환경 없음) 가설 단계. 코드
변경으로 넘어가기 전에 사용자에게 아래 진단을 부탁함:

## 확인 요청

1. **키보드로 항목 선택**(↑/↓ 로 이동 후 Enter)도 똑같이 안 되는지 —
   되면(정상 이동) mousedown 경쟁 가설이 맞다는 강한 근거, 안 되면 다른
   원인.
2. 가능하면 Tauri 앱에서 개발자 도구(우클릭 → 검사, 활성화돼 있다면)로
   클릭 시 콘솔 에러가 있는지.

## 1. spawn 태스크의 패닉 → 스트림을 에러로 끝낸다

`stream_attachments_zip` 의 `tokio::spawn` 을 `JoinHandle` 로 잡고, 본문을 다
흘린 **뒤** join 결과를 확인해 비정상 종료면 스트림을 에러로 끝낸다.

```rust
let tail = futures_util::stream::once(async move {
    match writer.await {
        Ok(()) => Ok(Bytes::new()),
        Err(e) if e.is_panic() => Err(io::Error::other("zip writer panicked")),
        Err(e) => Err(io::Error::other("zip writer aborted")),
    }
});
Body::from_stream(ReaderStream::new(r).chain(tail))
```

스트림이 에러로 끝나면 hyper 가 chunked 를 정상 종료자 없이 끊어, 클라이언트가
전송 실패를 감지한다.

### 실측

| | 정상 | 패닉 (수정 전) | 패닉 (수정 후) |
|---|------|---------------|---------------|
| HTTP | 200 | 200 | 200 |
| 크기 | 9,601 | 6,180 | 6,180 |
| **curl 종료 코드** | 0 | **0** (성공으로 봄) | **18** (PARTIAL_FILE) |
| 서버 로그 | — | 없음 | `첨부 zip 쓰기 태스크 패닉 —` |

상태 코드는 못 바꾼다(헤더가 이미 나갔다). 바꿀 수 있는 건 **전송이 끝났는지**
여부이고, 그것만으로 "성공으로 오해" 는 사라진다. 정상 다운로드는 그대로
exit 0 / 2 files 다.

## 2. Tauri 커맨드 패닉 → 두 겹

근본 대책은 커맨드 실행부에서 unwind 를 잡는 것인데 커맨드가 100개에 가까워
범위가 크다. 대신 **증상을 없애는 것**과 **원인을 남기는 것** 둘로 나눴다.

### (a) invoke 타임아웃 — 화면이 굳지 않게

`TauriTransport.call` 이 60초 안에 응답 없으면 실패로 바꾼다. 호출부의 기존
에러 처리에 그대로 태워진다.

오래 걸리는 게 **정상**인 커맨드는 제외했다 — 대용량 첨부 복사·재색인·
백업/복원·길드 열기. 잘라내면 그게 새 버그다.

### (b) 패닉 훅 — 원인이 사라지지 않게

`~/.openguild/panic.log` 에 시각·위치·메시지를 남긴다. 기본 훅을 **대체하지
않고 덧붙여서** 개발 중 콘솔 출력은 그대로 둔다. `OPENGUILD_HOME` 을
존중하므로 테스트가 실 홈을 건드리지 않는다.

`.app` 으로 실행하면 stderr 가 사실상 사라져, 지금까지는 "가끔 멈춘다" 는
신고만 남고 단서가 없었다.

### 실측 (실제 앱 실행)

임시 패닉 커맨드를 만들어 `transport.call` 로 호출(타임아웃 3초로 임시 단축):

```

rejected after 3095ms: Error: 'dev368_panic' 가 3초 동안 응답하지
않았습니다. (커맨드가 패닉했을 수 있습니다 — 앱 로그를 확인해 주세요.)
--- probe 끝 ---
```

```
~/.openguild/panic.log
[2026-08-26T14:37:51+09:00] gui/src/commands.rs:108 — DEV-368 검증용 패닉
```

수정 전에는 5초 타임아웃을 **내가 직접 걸어야** 빠져나왔고 로그도 없었다.

## 테스트 5건

통과 / 거부 전달 / **영영 응답 없으면 실패로 전환** / **제외 목록은 타임아웃
안 함** / 제외 목록 구성.

`just test` 504건 통과(499 + 5). 임시 코드는 전부 제거하고 grep 으로 확인했다.

## 남는 한계

커맨드가 패닉하면 여전히 그 작업은 실패다 — 타임아웃은 **화면이 굳는 것**만
막는다. 60초를 기다려야 한다는 점도 그대로다. 커맨드 단위 unwind 처리는
별도 범위로 남는다.

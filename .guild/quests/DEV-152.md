DEV-069 후속(admin #8, #9): 현재 첨부 업로드는 Tauri save_attachment invoke 전용이라 remote(서버) 모드에선 미동작(editor-attach 가 detectEnvironment!=='tauri' 면 무시). 서버 측 업로드 엔드포인트(POST /api/attachments) + HTTP transport 분기 + 파일 진리원/blob 동기화 정책을 remote 에 맞게 설계 필요.

## 구현 (완료, 전체 범위)

core::ops::attachments 의 함수들(save_attachment/add_*_attachment/remove_*_attachment)
이 원래 Tauri 와 무관해 그대로 재사용 — 별도 storage 정책 설계 불필요했음.

- **server**: `server/src/routes/attachments.rs` 신설.
  `POST /api/attachments`(bytes 저장, Tauri invoke 와 동일 응답 shape 맞추려
  `Json<String>` 그대로 반환 — object 로 안 감쌈) +
  `POST/DELETE /api/quests/by/{slug}/attachments`,
  `/api/campaigns/{slug}/attachments`(sidecar 등록/제거). quest/campaign
  detail 핸들러(get_quest, get_quest_by_slug, get_campaign)에 GUI Tauri 커맨드와
  동일하게 attachments 채우기 추가.
- **frontend**: `editor-attach.ts` 의 업로드 호출 4곳을 `saveAttachmentBytes()`
  단일 헬퍼(`api.post('/api/attachments', ...)`)로 통합 — `transport.ts` 가
  Tauri 면 invoke, 브라우저면 HTTP 로 자동 분기해 호출부가 환경 무지.
  4개의 `detectEnvironment()!=='tauri'` 차단 게이트 제거(paste/drop/버튼 모두
  브라우저에서도 동작). `AttachmentSection.svelte` 의 추가/제거도 동일 패턴
  (`api.post`/`api.delete`) 로 교체, "데스크탑 전용" 에러 제거. 다운로드/OS
  기본앱 열기는 그대로 Tauri 전용 유지(브라우저는 기존 새 탭/`<a download>`
  분기 — 이미 있던 경로, 변경 없음).
- **transport.ts**: `routeToInvoke` 에 `/api/attachments`,
  `quests/by/{slug}/attachments`, `campaigns/{slug}/attachments` 매핑 추가.
  HTTP body 는 프로젝트 컨벤션대로 snake_case(`data_base64`), invoke args 는
  Tauri 컨벤션대로 camelCase(`dataBase64`) — 매핑 함수가 변환.

## 테스트

- server: 신규 라우트 단위 동작 확인(빌드+clippy clean), 기존 166개 회귀 없음.
- frontend: `transport.test.ts` 에 5개 라우트 매핑 테스트 추가, vitest 202개 전체 green. svelte-check/no-hex 통과.
- **실제 E2E**(격리 temp 길드 + 실제 서버 바이너리 + curl): bytes 업로드 →
  quest/campaign 에 등록 → detail 응답에 표시 → 제거 까지 전부 확인.
  과정에서 **camelCase/snake_case 불일치 버그**(HTTP body `dataBase64` vs
  server 가 기대하는 `data_base64`) 를 실제로 잡아 수정 — 단위테스트만으론
  못 잡았을 통합 이슈.

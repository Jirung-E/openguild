질문(admin): '토론 해결(resolved)' 전환도 worklog 에 기록되어야 하는데
그렇게 설계되어 있는지? — **확인 결과: 안 됨 (설계 공백).**

## 현재 구조
- worklog 활동 소스(DEV-167): quest_history(상태/타입 변경) +
  quest/campaign 댓글의 **작성 시각(ts)** + quests.created_at.
- `toggle_comment_discussion` / `toggle_comment_resolved`(core
  ops/comments.rs)는 journal 에만 기록(감사용) — quest_history 에 안
  남고, 댓글 ts 도 안 바뀌므로 worklog 타임라인 어디에도 안 나타남.
  journal 은 snapshot 시 truncate 라 worklog 소스로 못 씀(기존 결정).

## 개선안 (설계 결정 필요)
(a) **quest_history 에 이벤트 추가**: op='discussion_resolved'/
    'discussion_reopened'/'discussion_marked' 로 INSERT + DEV-180
    사이드카 append — worklog 는 quest_history 를 이미 소스로 쓰므로
    kind 매핑만 추가하면 자동 표출. 권장.
(b) worklog 쿼리에서 comments 의 discussion/resolved 컬럼을 별도
    스캔 — 전환 "시각"이 저장 안 돼 있어 불가능(현재 스키마).
→ (a)로 가야 함. quest_history 스키마는 op 가 TEXT 라 확장 무변경.

## 함께 검토
- 같은 논리로 댓글 수정/삭제, due 변경, 태그 변경 등도 worklog 대상으로
  넣을지 범위 결정 (과기록은 노이즈 — 우선 resolve 전환만).

현재 보드는 상태(status) 레인이 **세로 열**로만 배치된다(LANE_W 948px 고정,
X축으로 LANE_STRIDE 만큼 나열). 레인을 **가로 행**으로 눕히는 모드를 추가해
사용자가 전환할 수 있게 한다.

## 왜
- 상태 수가 많으면 가로로 계속 길어져 좌우 스크롤이 심하다.
- 와이드 모니터에서는 세로 열보다 가로 행이 화면을 더 잘 쓴다(퀘스트가
  가로로 여러 개 늘어서고 상태끼리는 위아래로 비교).

## 구현 결정

- `quest_positions.x/y`는 기존 세로 열 좌표를 단일 정본으로 유지한다. 모드별
  좌표를 별도로 저장하지 않는다.
- 가로 행 모드에서는 화면 렌더링 시 기존 lane-local X(열)를 행 내부 Y로,
  기존 Y(아래 방향)를 X(오른쪽 방향)로 변환한다. 드래그·스냅·정렬·상태 변경
  저장 시에는 정확한 역변환을 적용한다.
- 기존 1/2/3열 설정은 가로 모드에서 1/2/3행 의미로 사용한다. 같은 status slug
  설정을 공유하므로 모드를 전환해도 밀도가 일관된다.
- orientation과 viewport는 길드별 localStorage에 저장한다. 기존
  `boardViewport`는 세로 열용으로 호환 유지하고 가로 행 viewport는 별도 키로
  보존한다.
- 접힌 레인은 세로 열에서 폭, 가로 행에서 높이를 40px로 줄인다. 숨김·접힘·순서
  변경은 현재 orientation의 교차축에서 빈 공간을 회수한다.

## 테스트 방법

1. 보드 도구바의 `세로 열` 버튼을 눌러 `가로 행`으로 전환한다. 상태 레인이
   위아래 행으로 배치되고 카드·관계선·레인 배경이 같은 위치 관계를 유지하는지
   확인한다.
2. 가로 행 상태에서 새로고침하거나 앱을 재시작해 orientation과 viewport가
   복원되는지 확인한다. 다시 세로 열로 전환했을 때 기존 viewport도 별도로
   복원되는지 확인한다.
3. 스냅을 켜고 레인별 1/2/3행을 각각 선택한다. 카드를 행 내부에서 드래그한 뒤
   점 위에 정렬되는지, 세로 열로 전환하면 같은 카드가 대응하는 기존 격자 위치에
   나타나는지 확인한다.
4. 카드를 다른 상태 행으로 드래그해 취소와 확정을 각각 시험한다. 확정 시 status와
   위치가 함께 저장되고 undo/redo가 같은 orientation에서 복원되는지 확인한다.
5. 전체 정렬과 레인별 정렬을 `그룹`/`전체` 모드로 실행한다. 가로 행에서는
   퀘스트가 오른쪽으로 진행하며 설정한 행 수 안에서 배치되는지 확인한다.
6. 보드 설정에서 레인 숨김, 접기/펼치기, ▲/▼ 순서 변경을 확인한다. 숨긴/접힌
   레인의 배경과 스냅 점이 남지 않고 뒤 레인이 위로 압축되는지 확인한다.
7. 가로 행에서 pan/zoom, 화면 맞추기, 노드 클릭·팝업 버튼, 새 퀘스트 버튼,
   다중 선택, 다크/라이트 및 한국어/영어 표시를 확인한다.
8. 세로 열 모드로 돌아와 기존 드래그·스냅·정렬·접기·숨김 동작에 회귀가 없는지
   확인한다.

사용자 보고: "이미지 첨부한게 표시가 안된다."

## 원인

`lib/utils/banner.ts` 의 `guildFileUrl()`/`campaignBannerUrl()` 가
`detectEnvironment() === 'tauri'` 만 보고 분기 — Tauri + 원격 연결
상태에서도 무조건 "로컬" 경로로 처리했다: `invoke('current_guild_path')`
로 Rust 의 **로컬** Store 경로를 얻어 `convertFileSrc` 로 asset:// URL 을
만드는데, 원격 모드에선 그 로컬 Store 가 실제로 보고 있는 길드와 무관
(보통 미연결/placeholder)하므로 존재하지 않는 로컬 파일을 가리켜
이미지가 깨졌다. Nav 길드 이름(DEV-113 후속) / board bounce
guard(BUG-095) 와 정확히 같은 패턴의 버그.

`AttachmentSection.svelte` 의 클릭 미리보기/다운로드(`openFile`/
`downloadOne`/`downloadAll`, BUG-081)도 같은 `isTauri` 플래그로 분기해
같은 문제가 있었음 — `open_guild_file`/`copy_guild_file` invoke 가 모두
로컬 파일 시스템 기준.

검증: 격리된 temp 길드 + 실제 서버 바이너리로 브라우저(HTTP) 경로는
업로드→연결→fetch 전부 정상(PNG bytes 정확히 반환)임을 먼저 확인 —
버그가 Tauri+원격 조합에만 있다는 걸 격리해서 확인.

## 수정

- `banner.ts`: `isTauriLocal()`(Tauri && !getRemoteServerUrl()) 헬퍼로
  교체. Tauri+원격이면 `httpBase()`(=getRemoteServerUrl())를 절대 URL
  prefix 로 붙여 `/api/guild-files/...` / `/api/campaigns/.../image` 를
  호출 — 브라우저는 base='' (같은 origin, 기존 동작 그대로).
- 부수 수정: `guildPathPromise` 의 "길드 경로는 세션 동안 불변" 메모
  이제 틀림(DEV-113 후속으로 같은 프로세스 안에서 다른 로컬 길드로
  전환 가능) — 캐싱 제거, 매번 새로 invoke(가벼운 로컬 호출).
- `AttachmentSection.svelte`: `isTauri` 플래그도 동일하게 원격 인지하도록
  수정 — Tauri+원격이면 URL 기반(새 탭 열기/다운로드 링크)으로 떨어지게.

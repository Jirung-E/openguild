[[BUG-135]] 의 근본 해결 후속. BUG-135 는 debug 빌드 stack overflow 를 8MB 스레드로 격리했지만, 원인 자체(clap derive 가 타입당 한 함수로 빌더 코드를 생성 → opt-level=0 에서 임시값 스택 슬롯 미병합 → 단일 생성 함수 프레임 1MB+)는 남아 있음. CLI 가 커질수록 프레임도 자람.

## 작업
1. **CLI 정의 구조 재편**: 인라인 인자가 많은 variant 의 인자 뭉치를 `#[command(flatten)]` struct 로 추출 — flatten struct 는 별도 `augment_args` 생성 함수 = 별도 프레임. 1순위 후보는 QuestCmd (인라인 인자 variant 25개, 특히 List 의 필터 ~20개 → `ListFilterArgs`). 핸들러 패턴 매칭이 `field` → `args.field` 로 바뀌는 기계적 리팩토링.
   - 서브커맨드로 위임된 enum(CommentCmd 등)은 이미 별도 생성 함수라 대상 아님.
2. **카나리 테스트**: 1MB 스택 스레드에서 `Cli::command()` 를 호출하는 테스트 추가 — 어떤 타입의 생성 프레임이 다시 1MB 선을 넘으면 debug 테스트가 즉시 실패(재발 감시). 현재는 테스트 스레드 기본 2MB 에 아슬아슬하게 의존 중.
3. BUG-135 의 8MB 스레드는 안전망으로 유지(비용 0, 제거하지 않음).

## 선택 항목 (착수 시 판단)
`[profile.dev.package.openguild-cli] opt-level = 1` — lifetime 마커로 stack coloring 활성화. 한 줄이지만 CLI 크레이트 디버거 스텝핑이 약간 뭉개짐 + 구조 문제를 옵티마이저로 가리는 것이라 1/2번의 대체가 아닌 보조.

## 검증
- 카나리 테스트(1MB)가 debug 에서 통과할 때까지 flatten 분리.
- 기존 CLI 파싱 테스트 전수 + --help 스냅샷 무변화(사용자 가시 동작 불변).

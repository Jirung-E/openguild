## 다중 파일 확장 (2026-06-03 — 같은 quest 후속)

사용자: "현재 길드 룰은 하나밖에 생성을 못하는거같은데 여러개를 생성할 수
있으면 좋겠음". `.guild/rules/{slug}.md` 디렉토리 구조로 확장.

### 설계
- 새 경로 `.guild/rules/{slug}.md` — 한 주제 = 한 파일. 자유 markdown.
- slug 규약: 빈/`/`/`\`/`..`/NUL/`.`-prefix 거부 (path traversal / 숨김 방지).
  kebab-case 권장, 한글 / ASCII 허용.
- **Backward compat**: 기존 단일 `.guild/rules.md` 가 있고 `general.md` 가 없으면
  첫 `list_rules` 호출 시 자동으로 `.guild/rules/general.md` 로 rename. 한 번만.

### Backend
- `core::repo::GuildPaths::{rules_dir, rule_path(slug)}` 추가.
- `core::repo::rules` 재작성:
  - `RuleEntry { slug, content }`.
  - `list_rules` / `read_rule` / `write_rule` / `create_rule` / `delete_rule` /
    `rename_rule` / `validate_slug` / `migrate_legacy_single_file`.
  - 기존 `read` / `write` 는 `general` slug 로 위임 (deprecated, backward compat).
- `core::ops::rules` 의 5개 신규 함수 + journal append.
- `server/routes/rules.rs`:
  - `GET /api/rules` → 목록. `POST /api/rules` body `{ slug, content? }` → 신규.
  - `GET/PUT/DELETE /api/rules/{slug}`. `PATCH /api/rules/{slug}` body
    `{ new_slug }` → 이름 변경.
  - `GET/PUT /api/rules-single` → legacy 단일 backward compat.

### Tauri
- `list_rules / get_rule / set_rule / create_rule / delete_rule / rename_rule`
  commands. transport.ts 매핑.

### Frontend
- `lib/api/rules.ts` 의 `rulesApi` 가 `list / get / set / create / delete /
  rename` (+ legacy `getSingle / setSingle`).
- `routes/rules/+page.svelte` 재작성 — 2-column layout:
  - 좌측 sidebar: slug 목록 + "+ 신규" 버튼.
  - 우측 panel: 선택 slug 의 markdown view + CodeMirror 편집 + "이름 변경" /
    "삭제" 버튼.
  - 신규 / 이름 변경은 inline modal. 편집 중 다른 slug 선택 시 확인 prompt.

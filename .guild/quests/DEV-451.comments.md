## 한 것 (2026-10-24)

- 코어 `query` — 대상 `Target`(퀘스트 · 캠페인 · 도서관). 해석기는 하나이고 **키 묶음과 SQL 만** 대상마다 다르다. `parse` 는 그대로 퀘스트용, `parse_for(대상, 글)` 이 새로 생겼다. 다른 대상의 키는 모르는 키로 처리하고, 오류 안내에 **그 대상의** 키만 나온다(`쓸 수 있는 키: status, start, end, quest`).
- 캠페인: `status`(active · done만 받음 — 캠페인 상태는 길드가 정하지 않는다), `start` · `end`(날짜 · 비교 · none), `end:overdue`(끝 날이 지났는데 진행 중 — 퀘스트의 `due:overdue` 와 같은 뜻), `quest:DEV-012`, 낱말 = 제목 · 설명 · 번호.
- 도서관: `tag`, `folder`(하위 폴더까지 — `--folder` 와 같은 규칙, `_` · `%` 는 글자 그대로; `none` = 최상위만), `updated`(고친 날), 낱말 = 제목 · 본문 · 번호.
- `services::campaigns::list_matching(status, q)` · `ops::library::list_books_query(folder, tags, q)` — 기존 옵션과 **그리고**.
- CLI `campaign list -q` · `library list -q`(`-` 로 시작해도 옵션으로 안 읽음). 원격은 `?q=` 로 실어 서버가 거른다.
- 서버 `GET /api/campaigns?q=` · `GET /api/library?q=`, 앱 `list_campaigns(q)` · `list_books(q)` — 화면은 [[DEV-452]].
- 문서: USAGE, 스킬(SKILL.md 명령 줄, reference/campaign.md "Filtering with a query", reference/library.md).

## 확인

- 시험 5: 해석기(대상마다 키 · 오류 안내 · 캠페인 status 값 · 폴더 LIKE 이스케이프 · 빼기 SQL), 캠페인 목록(키마다 · 빼기 · `--status` 와 함께 · 틀리면 BadRequest 4가지), 도서관 목록(태그 · 빼기 · 폴더 하위 · none · 여러 폴더 · 고친 날 · 낱말 · 번호 · 옵션과 함께 · 틀리면 BadRequest), 서버(거르기 · 400 + 키 안내), CLI(`-q '-status:done …'` 해석).
- 이 길드 사본으로 로컬과 원격(개발 서버)이 11가지 모두 같은 결과: `campaign list -q status:done` 5 · `quest:DEV-430` → C-007 · `베타` 5 · `library list -q 잠금` 4 · `updated:>=2026-10-01` 4 · `-folder:none` 8 …. `--folder 아키텍처` 와 `-q 'folder:"아키텍처"'` 가 같은 4개, `-folder:` 는 나머지 4개.
- 틀리면: `campaign list -q urgency:2` → "모르는 키 'urgency' — 쓸 수 있는 키: status, start, end, quest", 원격 `library list -q stauts:x` → 400 + "tag, folder, updated".

## 테스트 방법

```
openguild campaign list -q 'end:overdue'
openguild campaign list -q 'quest:DEV-430'
openguild library list -q 'folder:"아키텍처" -tag:초안 updated:>=2026-10-01'
openguild campaign list -q 'urgency:2'      # → 쓸 수 있는 키 안내
```

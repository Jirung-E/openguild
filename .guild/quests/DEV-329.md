﻿캠페인 목록에도 진행도 표시(admin 요청).

## 왜 서버 작업이 필요했나
목록은 `GET /api/campaigns`(원본 행)를 쓰는데 여기엔 진행도 필드가 없다. 진행도는 `summarize()` 가 체크리스트/연결 퀘스트를 집계해 `CampaignSummary` 로 내주는데, 기존 summary 엔드포인트는 **active 전용**(홈 카드용)이라 done 캠페인이 빠진다.

## 변경
- core `list_all_summaries()` — alive 전체를 `summarize()` 로. 진행도 계산 규칙이 카드/상세와 갈라지지 않도록 같은 함수를 재사용.
- server `GET /api/campaigns/summaries`, Tauri `list_campaign_all_summaries`, transport 매핑까지 3경로 동시 추가(로컬·서버·원격 동일 동작).
- 프론트: 목록이 `listSummaries()` 를 쓰고, 제목 아래에 얇은 바 + `완료/전체`.

## 표시 규칙
체크리스트와 연결 퀘스트를 **항목 수로 합산**해 하나의 바로 보여준다(카드는 둘을 따로 두 줄로 보여주지만 목록은 한 줄이라). 둘 다 없으면 바를 그리지 않는다. 완료 색(초록)은 `isCampaignDone()` — 카드/상세와 같은 판정.

## 비용
캠페인 하나당 3 쿼리(체크리스트·퀘스트 집계·상태별 카운트). 목록 규모(수십 개)에서는 문제가 없다고 판단해 계산 일관성을 택했다. 캠페인이 수백 개가 되면 상태별 카운트는 목록에서 빼는 게 맞다.

## 검증
- `GET /api/campaigns/summaries` 응답 확인, 13개 행 모두 바 렌더.
- C-013 체크리스트 1개 체크 → 목록이 `1/5`, 바 20%(273px 중 55px)로 갱신.
- 375px 가로 스크롤 0, 행 높이 100px.

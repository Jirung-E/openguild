## 할 것

플러그인을 어디에 두고, 어떻게 읽고, **어디서 돌릴지**.

```
.guild/plugins/{name}/plugin.json    ← 정의 (git 공유)
.guild/plugins/{name}/*.rhai         ← 스크립트 (DEV-375)
```

```json
{
  "name": "ai-notify",
  "on": ["quest.created", "comment.added"],
  "scope": ["gui", "cli"],
  "action": { "post": "https://…" }
}
```

## scope — admin 요구

CLI 에서도 돌아야 하지만 **사용자가 고를 수 있어야 한다**(GUI 에서만 돌리고
싶을 수 있다). `scope` 가 없으면 기본값을 정해야 하는데, **명시 필수**로
두는 편이 낫다 — 기본값이 무엇이든 놀라는 사람이 생긴다.

`server` 를 넣으면 그 서버를 쓰는 모든 사람에게 적용된다. 즉 **공유 범위는
scope 가 정한다** — 파일 위치가 아니다.

## 실행은 인라인 + 비동기

mutation 직후 그 프로세스가 띄우되 **기다리지 않는다**(fire-and-forget).
AI 호출이 몇 초 걸려도 `openguild comment add` 가 그만큼 멈추면 안 된다.

CLI 는 곧 끝나는 프로세스라 **종료 전에 전송이 끊길 수 있다.** 짧은 유예를
두고 못 끝내면 포기한다 — 여기서 재시도 큐까지 만들면 범위가 터진다.
필요해지면 그때 journal 커서 방식을 얹는다(구조상 가능).

## 동의 — 정의는 git 으로 따라온다

`.guild/plugins/` 는 커밋되므로 **동료가 만든 정의가 내 기계로 온다.**
`scope` 에 `cli`/`gui` 가 있으면 내 기계에서 도는 것이다. 특히 `run`
(DEV-376)이 열리면 임의 실행이다.

처음 보는 플러그인은 **한 번 물어보고**, 답을 `~/.openguild/` 에 남긴다
(git 아님 — 기계마다 따로). 정의가 바뀌면 다시 묻는다(내용 해시 비교).

혼자 쓰는 길드에서 매번 묻는 건 성가시므로, 길드 단위로 "이 길드는 다
허용" 도 둔다.

**비대화형에서는 실행하지 않는다**(admin 기본값 승인). CLI 가 스크립트나 CI
에서 돌면 물을 수가 없다 — 그때 조용히 남의 코드를 돌리는 것보다 안 돌리는
쪽이 낫다. 안내 메시지는 남겨 왜 안 돌았는지 알 수 있게 한다.

## 구독자가 없으면 이벤트를 만들지 않는다

적재 결과가 **emit 의 게이트**가 된다([[DEV-374]]). 이 길드에 플러그인 설정이
없거나 아무도 그 이벤트를 구독하지 않으면 `ops` 는 이벤트를 만들지도 않는다.

그래야 기존 ops 테스트 429건이 부수효과를 안 갖고, 플러그인을 안 쓰는 사용자가
비용을 치르지 않는다. 적재는 길드를 열 때 한 번 하고 결과를 들고 있는다.

## 실패

플러그인 하나가 죽어도 **다른 플러그인과 길드 동작은 멀쩡해야 한다.**
정의가 깨져 있으면 그 플러그인만 끄고 나머지는 돈다. 실패는 조용히 삼키지
말고 어딘가 남긴다 — 어디에 남길지는 구현하며 정한다(GUI 토스트는 CLI 에
없다).

## 테스트 방법

- `scope` 가 `["gui"]` 인 플러그인은 CLI 실행에서 **안 돈다**.
- 정의가 깨진 플러그인이 있어도 나머지가 돈다.
- 동의하지 않은 플러그인은 안 돈다. 정의가 바뀌면 다시 묻는다.
- mutation 이 플러그인 완료를 **기다리지 않는다**(응답 시간이 안 늘어난다).
- 이벤트를 구독하지 않는 플러그인은 호출되지 않는다.

## 결과

`core/src/plugins/` — `mod`(정의·검증·적재) · `consent` · `runtime`(전달) ·
`tests`. 진입점은 `Store::install_plugins(scope, delivery)` 하나이고,
**돌 게 하나도 없으면 sink 를 꽂지 않는다** — 그래야 [[DEV-374]] 의 게이트가
살아 페이로드를 만들지도 않는다. [[DEV-377]] 이 여기에 진짜 `Delivery` 를
끼운다(지금은 `DropDelivery`).

계획과 달라진 것 셋:

**동의는 해시가 아니라 정의 원문을 저장한다.** 해시를 쓰려면 의존성이 하나
늘고(BUG-267 에서 `filetime` 을 안 들인 것과 같은 판단), 무엇보다 사용자가
`~/.openguild/plugin-consent.json` 을 열어 **자기가 뭘 허락했는지 볼 수 있어야**
한다. 해시는 못 읽는다. 비교는 정규화된 JSON 동등성으로 한다.

**비밀값은 리터럴을 거부한다**(admin 확정). `plugin.json` 은 git 으로 가므로
API 키가 적히면 그대로 공유된다. `${OPENAI_API_KEY}` 같은 환경변수 참조만
받고, 없으면 적재 때 시끄럽게 실패한다 — 조용히 빈 문자열로 보내면 인증 실패
원인을 못 찾는다.

**"기다리지 않는다" 를 전용 스레드로 구현했다.** `dispatch` 는 일감을 넘기고
바로 돌아온다. 곧 끝나는 프로세스는 `Store::drain_events(budget)` 로 짧은
유예를 주고, 못 끝내면 포기한다. 스레드 하나면 충분하다 — 전달은 대부분
대기(HTTP 응답)이고, 순서가 보존되면 플러그인 쪽에서 순서를 다시 맞출 필요가
없다.

되돌림 시험 8건이 전부 물었다: 동의 검사 제거(3건 실패) · 이름만 지문(1) ·
scope 필터 제거(1) · 비밀값 검사 제거(2) · 패닉 격리 제거(2) · 전달을 동기로(1)
· 유예 예산 무시(1) · 빈 적재에도 sink 꽂기(1).

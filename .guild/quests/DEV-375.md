## 할 것

플러그인을 어디에 두고, 어떻게 읽고, **어디서 돌릴지**.

```
.guild/plugins/{name}/plugin.json    ← 정의 (git 공유)
.guild/plugins/{name}/*.rhai         ← 스크립트 (DEV-375)
```

```json
{
  "name": "ai-notify",
  "on": ["quest.created", "comment.added"],
  "scope": ["gui", "cli"],
  "action": { "post": "https://…" }
}
```

## scope — admin 요구

CLI 에서도 돌아야 하지만 **사용자가 고를 수 있어야 한다**(GUI 에서만 돌리고
싶을 수 있다). `scope` 가 없으면 기본값을 정해야 하는데, **명시 필수**로
두는 편이 낫다 — 기본값이 무엇이든 놀라는 사람이 생긴다.

`server` 를 넣으면 그 서버를 쓰는 모든 사람에게 적용된다. 즉 **공유 범위는
scope 가 정한다** — 파일 위치가 아니다.

## 실행은 인라인 + 비동기

mutation 직후 그 프로세스가 띄우되 **기다리지 않는다**(fire-and-forget).
AI 호출이 몇 초 걸려도 `openguild comment add` 가 그만큼 멈추면 안 된다.

CLI 는 곧 끝나는 프로세스라 **종료 전에 전송이 끊길 수 있다.** 짧은 유예를
두고 못 끝내면 포기한다 — 여기서 재시도 큐까지 만들면 범위가 터진다.
필요해지면 그때 journal 커서 방식을 얹는다(구조상 가능).

## 동의 — 정의는 git 으로 따라온다

`.guild/plugins/` 는 커밋되므로 **동료가 만든 정의가 내 기계로 온다.**
`scope` 에 `cli`/`gui` 가 있으면 내 기계에서 도는 것이다. 특히 `run`
(DEV-376)이 열리면 임의 실행이다.

처음 보는 플러그인은 **한 번 물어보고**, 답을 `~/.openguild/` 에 남긴다
(git 아님 — 기계마다 따로). 정의가 바뀌면 다시 묻는다(내용 해시 비교).

혼자 쓰는 길드에서 매번 묻는 건 성가시므로, 길드 단위로 "이 길드는 다
허용" 도 둔다.

## 실패

플러그인 하나가 죽어도 **다른 플러그인과 길드 동작은 멀쩡해야 한다.**
정의가 깨져 있으면 그 플러그인만 끄고 나머지는 돈다. 실패는 조용히 삼키지
말고 어딘가 남긴다 — 어디에 남길지는 구현하며 정한다(GUI 토스트는 CLI 에
없다).

## 테스트 방법

- `scope` 가 `["gui"]` 인 플러그인은 CLI 실행에서 **안 돈다**.
- 정의가 깨진 플러그인이 있어도 나머지가 돈다.
- 동의하지 않은 플러그인은 안 돈다. 정의가 바뀌면 다시 묻는다.
- mutation 이 플러그인 완료를 **기다리지 않는다**(응답 시간이 안 늘어난다).
- 이벤트를 구독하지 않는 플러그인은 호출되지 않는다.

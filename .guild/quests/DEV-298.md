용량이 큰 파일을 첨부할 때 진행이 되고 있는지 아닌지 구분이 안 간다.
버튼 라벨이 '처리 중…' 으로만 바뀌고, 어떤 파일이 몇 번째로 처리되는지도
알 수 없어 멈춘 것처럼 보인다.

## 수정 내용

- `pickAndUploadAttachments` 가 파일을 시작할 때마다 `onProgress` 로
  `{ name, index, total }` 을 알리고, 전부 끝나면 `null`(표시 해제)을 준다.
- 첨부 섹션에 진행 표시 줄 추가 — 현재 파일명 + `n / N`(여러 개일 때) +
  진행 바. `role="status"` + `aria-live="polite"` 로 스크린리더에도 알린다.
- 편집기 인라인 placeholder(`![업로드 중… 파일명 #N]()`)의 한글 하드코딩을
  i18n 키(`attach.uploading`)로 교체.

## 진행률(%)이 아니라 불확정 바인 이유

세 전송 경로 모두 진행률을 관측할 수 없다 —
경로 기반(Tauri)은 Rust 의 단일 `fs::read`+`write`, base64 경로는 IPC/`fetch`
한 번에 끝난다. 실제 %를 내려면 청크 단위 업로드 API(init/append/finish)가
필요하고, 그건 [[BUG-168]] 의 한도 문제까지 함께 걷어내는 별도 작업이다.
지금 목적("돌고 있는지 아닌지")에는 불확정 바로 충분하다고 판단.

## Test plan

1. 데스크탑에서 100 MB 이상 파일을 `+ 첨부` 로 선택 — 저장되는 동안 파일명과
   진행 바가 보이고, 끝나면 사라지면서 목록에 추가되는지.
2. 여러 개(3개 이상) 동시 선택 — `1 / 3`, `2 / 3` … 로 순번이 올라가는지.
3. 파일 선택 다이얼로그에서 취소 — 진행 표시가 뜨지 않고 버튼이 원래대로
   돌아오는지(멈춘 상태로 남지 않는지).
4. 중간에 실패하는 파일(64 MB 초과 등)이 섞여도 진행 표시가 끝까지 진행되고
   마지막에 사라지는지, 에러 메시지도 함께 보이는지.
5. 다크/라이트 양쪽에서 진행 바 색이 배경에 묻히지 않는지.
6. 언어를 영어로 바꾸면 편집기 placeholder 가 `Uploading…` 으로 나오는지.

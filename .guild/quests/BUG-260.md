## 증상 (admin 보고)

메인 창을 닫아도 자식 창(검색 팔레트의 "새 창으로 열기")은 그대로 남는다.
같이 닫혀야 한다.

## 배경

자식 창은 `lib/utils/open-item.ts` 가 `item-{ts}-{seq}` 라벨로 만든다
([[DEV-255]]). 지금 Tauri 쪽에는 창 이벤트 처리가 **아예 없다** —
`tauri::Builder` 에 `on_window_event` 가 걸려 있지 않다.

그래서 메인 창이 닫혀도 자식 창은 자기 생명주기대로 남고, 창이 하나라도
살아 있으면 앱 프로세스도 계속 산다. 사용자가 보기엔 "껐는데 안 꺼진" 상태다.

## 할 일

`on_window_event` 를 붙여, 라벨이 `main` 인 창의 닫힘 요청에서 `item-` 으로
시작하는 창을 전부 닫는다.

## 정할 것 / 주의

- **어느 이벤트인가.** `CloseRequested` 는 닫히기 전이라 자식을 먼저 정리할
  수 있다. `Destroyed` 는 이미 닫힌 뒤라 늦다.
- **역방향은 아니다.** 자식 창을 닫는 것이 다른 창에 영향을 주면 안 된다 —
  라벨이 `main` 일 때만 동작해야 한다.
- 자식 창에 저장 안 된 편집이 있으면? 지금 이탈 가드(`unsaved`)는 라우팅
  단위라 창 닫힘까지는 안 본다. 이 퀘스트에서 거기까지 갈지 판단할 것.
- macOS 는 마지막 창을 닫아도 앱이 남는 관례가 있다 — 지금 동작이 무엇인지
  확인하고, 이 변경이 그것을 바꾸지 않는지 볼 것.

## 테스트 방법

1. 검색 팔레트에서 문서 두 개를 "새 창으로 열기".
2. 메인 창을 닫는다 → 자식 창 둘 다 닫히고 앱이 종료돼야 한다.
3. 자식 창 하나만 닫는다 → 나머지 자식 창과 메인 창은 그대로여야 한다.

## 고친 것

`tauri::Builder` 에 `on_window_event` 를 붙였다. 라벨이 `main` 인 창의
`CloseRequested` 에서 `item-` 으로 시작하는 창을 전부 닫는다.

- `Destroyed` 가 아니라 **`CloseRequested`** — 이미 닫힌 뒤면 늦다. 그 사이
  자식만 남은 순간이 생긴다.
- 자식 하나가 닫히기를 실패해도 나머지는 계속 닫고, **메인의 닫힘을 막지
  않는다.** 막으면 앱이 안 꺼지는 더 나쁜 상태가 된다.
- `webview_windows()` 가 복제본을 주므로 순회 중 닫아도 안전하다.

## 판정을 두 함수로 뺐다 — 테스트하려고

창 이벤트 자체는 GUI 없이 못 돌린다. 대신 판정만 `is_child_window_label` /
`closes_children` 로 빼서 고정했다. 되돌려서 무는 것까지 확인했다:

- 접두사를 `item-` → `doc-` 로 어긋내면 → `child_window_label_matches_frontend_contract` 실패.
- `closes_children` 을 헐겁게(`!label.is_empty()`) 하면 →
  `main_and_child_predicates_are_disjoint` 실패. 이게 중요한 이유는, 두 판정이
  겹치면 **자식 창 하나를 닫을 때 형제 창이 전부 딸려 닫히기** 때문이다.

## 접두사는 세 곳이 공유하는 계약

`item-` 은 frontend 의 `open-item.ts`(생성) / `stores/windowKind.ts`(자식 판정,
타이틀바가 본다) / Rust 의 `is_child_window_label`(함께 닫을 대상) 셋이 공유한다.
하나만 바꾸면 메인을 닫아도 자식이 남는다. 세 곳에 서로를 가리키는 주석을 뒀고,
Rust 쪽에 형태를 고정하는 테스트가 있다.

## 저장 안 된 편집은 묻지 않는다 — 의도한 것

[[BUG-075]]: Tauri 에서 `beforeunload` 가드를 켰더니 **창 X 가 안 닫혔다**
(심각도 1). 그래서 그 가드를 통째로 걷어냈고 다시 켜면 같은 회귀 위험이 있다
(`reload-shortcut.ts` 주석). 지금도 메인 창을 닫으면 미저장 편집은 그냥
사라지고, 자식 창을 직접 닫을 때도 마찬가지다 — 이 변경이 **새로 만든 구멍이
아니라** 기존 동작의 범위를 넓힌 것이다. 확인 모달이 필요하다면 BUG-075 를
다시 열어 창 닫힘 경로를 따로 설계해야 한다.

## 검증

`cargo test -p openguild-gui` 24건 통과, clippy `-D warnings` 통과, 전체
`just test` 통과.

**실기 확인 못 했다.** 창 이벤트는 데스크톱 앱을 띄워야 보이는데 앱 빌드는
허락받고 하기로 했다. 확인할 것:

1. 문서 두 개를 "새 창으로 열기" → 메인 창 닫기 → 자식 둘 다 닫히고 앱 종료.
2. 자식 창 하나만 닫기 → 나머지 자식과 메인은 그대로.
3. macOS 에서 마지막 창을 닫았을 때 앱이 완전히 종료되는지(기존 동작과 같은지).

## 증상

admin: *"cli에서 도서관 문서를 만들때 바로 폴더 지정을 못하고 있는데 (…)
그럼 왜 에이전트가 폴더 지정을 제대로 못하는지? `--folder` 로 시도하려고 한다."*

기능은 **있다**. `openguild library new --title X --path "아키텍처/결정"` 이
정확히 그 일을 하고, 실제로 도는 것을 확인했다. 그런데 사람도 에이전트도
`--folder` 를 먼저 시도하고, 실패하면 "안 되는 기능" 으로 판단한다.

## 원인 — 개념 이름은 `folder` 인데 플래그만 `--path` 다

같은 명령군 안에서 표기가 갈린다.

```
openguild library folder list|new|delete     ← 하위 명령 이름이 "folder"
openguild library new    --path <PATH>       ← 그 folder 를 지정하는 플래그
openguild library update --path <PATH>       ← "새 폴더 경로로 이동"
```

도움말 문구도 전부 **한국어로 "폴더"** 라고 말한다 — `update` 의 설명이
"폴더 이동", `folder` 그룹이 "폴더(계층) 관리". 즉 **이 도메인의 이름은
folder 다.** `--path` 만 혼자 다른 말을 쓴다.

에이전트는 `library folder` 라는 하위 명령과 "폴더" 라는 도움말을 읽고
`--folder` 를 시도한다. **그게 자연스러운 추론이고, 틀린 쪽은 우리다.**

여기에 두 번째 혼동이 겹친다: 최상위에 이미 `--guild <PATH>` 가 있어서
`--path <PATH>` 를 보면 "길드 경로 비슷한 것" 으로도 읽힌다.

## 고려한 것

**문서만 고치기** — 스킬과 USAGE 에 `--path` 를 적는다. 싸지만, 이름이
어긋난 채로 두면 다음 에이전트도 같은 추론을 한다. 문서는 추론을 못 이긴다.

**`--folder` 를 alias 로 추가** — clap 의 `alias`/`visible_alias`. 기존
스크립트가 안 깨지고 자연스러운 이름이 통한다. 어느 쪽을 canonical 로
보여줄지는 정해야 한다.

**`--folder` 로 이름을 바꾸고 `--path` 를 alias 로** — 도메인 용어와
일치하는 쪽이 canonical 이 된다. 하위호환은 alias 가 지킨다.
[[BOOK-CLI 최상위 명령 네이밍]] 이 `types`/`statuses` 에서 쓴 방식과 같다 —
canonical 을 바꾸고 옛 이름을 alias 로 남겼다.

셋째가 맞아 보인다. 이 저장소는 이미 "이름이 어긋나면 canonical 을 고치고
alias 로 호환을 지킨다" 는 선례를 갖고 있다.

## 할 것

- `library new` / `library update` 의 `--path` 를 `--folder` 로, `--path` 는
  alias 로 남긴다.
- `library list` 에 **폴더로 거르는** 옵션이 아예 없다 — 문서를 폴더에 넣을 수
  있는데 그 폴더로 못 찾는다. 같이 볼 것.
- 스킬(`openguild`)과 `docs/USAGE.md` 에 폴더 지정 예시를 넣는다. 이름을
  고쳐도 **예시가 없으면 여전히 안 보인다.**

## 테스트 방법

- `--folder` 와 `--path` 둘 다 같은 결과를 낸다(옛 스크립트가 안 깨진다).
- 도움말에 canonical 이 `--folder` 로 보인다.

[[DEV-430]] 의 1단계 — **잠금 틀만** 바꾼다. 변경 함수들의 동작은 그대로다.

## 할 것

- 길드 잠금을 **RW** 로 — 프로세스 사이는 `.guild/.lock` 에 `File::lock_shared` / `File::lock`, 프로세스
  안은 tokio `RwLock`.
- **문서 잠금** — `.guild/.locks/{종류}/{id}` 파일(비어 있음, gitignored, 만들고 지우지 않는다) + 프로세스
  안은 문서별 async mutex.
- 잠금 함수는 둘뿐:
  - `store.lock_guild()` — 길드 **독점**(지금의 `mutation_guard` 와 같은 뜻)
  - `store.lock_docs(&[DocKey])` — 길드 **공유** + 목록의 문서들을 **이름 순**으로 독점
- **쥔 채 또 잠그면 오류**(같은 작업 안에서). 목록이 늘면 다 풀고 처음부터.
- `mutation_guard()` 는 당분간 `lock_guild()` 로 둔다 — 그래서 이 단계에서는 동작이 안 바뀐다.
- BUG-339 의 "잠금이 풀린 뒤 할 일"(`after_unlock`)은 두 잠금 모두에 그대로.

## 시험

- 공유끼리는 안 막고, 독점은 공유를 막고, 공유는 독점을 막는다(프로세스 사이 = 파일 잠금 기준).
- 다른 문서끼리는 동시에, 같은 문서는 줄 선다.
- 목록을 어떤 순서로 넘겨도 같은 순서로 잠근다 — 엇갈린 두 작업이 서로 기다리다 멈추지 않는다.
- 쥔 채 또 잠그면 오류.

## 한 것 (2026-10-01)

- `lock.rs` — `GuildMode`(공유/독점), `DocKey`, `Locks`(프로세스 안: 길드 `RwLock` + 문서별 mutex + 잠금을 쥔
  작업 목록), `acquire(locks, .guild, mode, docs)`. 문서 목록은 **정렬 · 중복 제거한 뒤** 그 순서로 잡는다.
- `Store::lock_guild()` / `Store::lock_docs(&[DocKey])`. `mutation_guard()` 는 `lock_guild()` 그대로 — 동작 변화 없음.
- 문서 잠금 파일은 `.guild/.locks/{종류}~{id}`. 폴더 안에 `*` 한 줄짜리 `.gitignore` 를 둬 폴더째 git 에서 빠진다
  (이미 있는 길드의 `.gitignore` 를 안 고쳐도 된다). 새 길드의 표준 `.gitignore` 에도 `.locks/` 를 더했다.
- 쥔 채 또 잠그면 오류 — tokio 작업 안에서 알아본다. `block_on` 으로 바로 도는 CLI 는 `lock_coverage` 시험이
  정적으로 막는다(잠그는 진입점끼리 서로 부르지 않는다).
- `Locks` 는 포인터 하나로 감쌌다 — `Store` 크기가 그대로다(CLI 의 `Backend` 가 `Store` 를 품는다).

## 시험

공유끼리 함께 · 독점과 서로 막음(파일 잠금 기준) / 다른 문서는 동시에 · 같은 문서는 줄 섬 / 독점은 공유를
기다리고 공유는 독점을 기다림 / 반대 순서로 넘긴 40개 작업이 멈추지 않음 / 쥔 채 또 잠그면 오류, 풀면 다시
됨 / 잠금 폴더가 스스로 git 에서 빠짐.

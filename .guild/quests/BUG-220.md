사용자 보고: 고정(pin)된 댓글을 편집할 때, 편집창이 "마크다운 모드"(리치
편집기, CodeMirror 기반)이면 배경색이 파란색으로 보임.

## 원인 (조사 완료)

`QuestCommentsSection.svelte` 의 `.entry-card.pinned` 가 고정된 댓글 카드
전체에 accent(파란색) 틴트 배경을 준다(DEV-234):

```css
.entry-card.pinned {
	border-color: color-mix(in srgb, var(--accent) 55%, transparent);
	background: color-mix(in srgb, var(--accent) 6%,
		color-mix(in srgb, var(--bg-elevated) 65%, var(--bg)));
}
```

편집 모드 진입 시 두 가지 입력 UI 중 하나가 뜬다(`editRich` 토글, "M↓" 버튼):
- **일반 모드**(`editRich=false`): `<textarea class="body-input">` —
  `background: var(--bg)` 로 **불투명** — pinned 틴트가 안 비침.
- **마크다운 모드**(`editRich=true`, 사용자가 말한 그 모드): `<MarkdownEditor>`
  (CodeMirror) — `MarkdownEditor.svelte` 의 `.editor-wrap` 에 **background
  선언이 아예 없다**(border/border-radius 만). 라이트 테마는
  `editorThemeExtension()` 이 빈 확장(`[]`)이라 CodeMirror 자체 배경도 딱히
  안 얹혀서, 결국 부모의 `.entry-card.pinned` 파란 틴트가 편집기 영역까지
  그대로 비쳐 보인다.

## 수정 방향 (조사만, 미확정)

`MarkdownEditor.svelte` 의 `.editor-wrap` 에 `background: var(--bg)` (또는
`--bg-elevated`) 를 명시해 불투명하게 — `.body-input` 과 동일한 배경을
써서 두 모드 간 시각적 일관성도 확보. quest/campaign 상세 등 다른 곳에서
쓰는 `MarkdownEditor` 도 같은 컴포넌트 공유라 이 수정이 거기도 적용됨
(부작용 여부 확인 필요 — 대부분 pinned 배경처럼 특이한 틴트 부모가 없어
보이는 변화는 없을 것으로 추정되지만 실제 화면에서 확인 필요).

## 수정 완료 (2026-08-07)

`MarkdownEditor.svelte` 의 `.editor-wrap` 에 `background: var(--bg)` 한 줄
추가 — `.body-input`(일반 텍스트 모드)과 동일한 불투명 배경.

## 검증

헤드리스 브라우저로 실제 재현 + 수정 전/후 computed style 대조:
- 수정 전: `.editor-wrap` 의 `background-color` = `rgba(0,0,0,0)`(완전 투명) —
  부모 `.entry-card.pinned` 의 파란 틴트가 그대로 비침.
- 수정 후: `rgb(255,255,255)`(라이트 테마 `--bg`) — 불투명, 틴트 안 비침.
- 다크 테마는 CodeMirror 자체(`oneDark`)가 이미 불투명 배경(`rgb(40,44,52)`)을
  줘서 원래도 문제없었고, 이번 수정으로도 변화 없음(회귀 없음) 확인.
- `just test` 전체 통과(이 수정 자체는 CSS 라 별도 유닛 테스트 대상 아님 —
  시각적 확인이 맞는 검증 방법이라 판단).

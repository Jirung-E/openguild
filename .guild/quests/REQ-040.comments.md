## 한 일 — 문서 검색 페이지 `/search`

- **검색**: 서버 강화 검색(`/api/search`)을 그대로 쓴다. 한 번 받아 탭으로 나눈다 — 전체 · 퀘스트 · 캠페인 · 도서관 · 규칙, 탭마다 개수.
  - 줄: 종류 · 번호 · 제목 · 맞은 곳(제목/본문/댓글/첨부/메모) · 발췌(맞은 말 강조).
  - 누르면 열고, 미리보기 · 새 창 · 이동 단추는 다른 목록과 같다(DocLink).
  - 본문 · 댓글 등에서만 맞은 문서는 찾기 바를 그 검색어로 띄운 채 연다(DEV-467 과 같다).
- **쿼리**: 퀘스트 · 캠페인 · 도서관 탭에서 그 목록 화면의 쿼리를 쓴다(쓰는 법 · 오류도 같은 것). 키 목록은 `utils/query-keys.ts` 로 모아 세 목록 화면과 같이 쓴다.
- **팔레트**: 검색어가 있으면 맨 아래 "'…' 모든 결과 보기 — 검색 페이지" 줄.
- **상단바**: 설정의 상단바 메뉴에서 '검색' 을 켤 수 있다. 기본은 ☰ 메뉴 맨 뒤.
- 주소에 `q` · `kind` · `mode` · `memo` 가 실린다.

## 정할 것 — 이렇게 정했다

1. '전체' 탭의 쿼리 — **막는다.** 종류마다 키가 달라 공통 키만 받으면 헷갈린다. "쿼리는 퀘스트 · 캠페인 · 도서관 탭에서 씁니다" 안내. 규칙은 쿼리가 없어 같은 안내.
2. 메모 — **'메모 포함' 을 켤 때만**(서버 기본 · CLI `--in memo` 와 같다). 검색 모드에서만 보인다.
3. 정렬 — **제목 · 번호에서 맞은 것 먼저**, 그 안은 종류 · 번호 순. 정렬 선택은 두지 않았다.

- 웹 빌드 + 임시 서버(WebKit), 임시 길드에 '코끼리' 를 제목(캠페인) · 본문(퀘스트 · 도서관) · 댓글(퀘스트)에:

  - 퀘스트 탭 → 2개, 주소 `kind=quest`.
  - 쿼리 `status:open` → 퀘스트 2개. `nokey:x` → 코어의 오류 문장. 전체 탭으로 옮기면 막는 안내.
  - 둘째 문서(본문 맨 아래에서 맞음)를 누르면 `/quests/DEV-002` + 찾기 바 '코끼리' 1/1.

  - '메모 포함' → 주소 `memo=1`. 상단바에 '검색' 을 올리면 홈 · 퀘스트 · 검색, 누르면 이 페이지.
  - 페이지 오류 0.

## 테스트 방법

1. 상단 길드 이름(팔레트)에서 아무 말이나 친다 → 맨 아래 "모든 결과 보기" → 검색 페이지.
2. 탭을 옮겨 본다(개수). 본문에서만 맞은 문서를 누르면 찾기 바가 떠 있다.
3. 퀘스트 탭에서 [쿼리] 로 `status:open` 같은 것을 넣는다. 전체 탭으로 가면 막는 안내.
4. 설정 → 상단바 메뉴에서 '검색' 을 켠다.

## 고침 — 쿼리를 못 쓰는 탭의 단추

admin: "입력박스 옆의 ? 버튼도 해당 탭에서는 비활성화해줘야하는거 아니냐"

- `전체` · `규칙` 탭에서는 [쿼리] 단추와 쓰는 법(`?`) 단추를 끈다(흐리게, 마우스를 올리면 "퀘스트 · 캠페인 · 도서관 탭에서 씁니다"). 쿼리 모드인 채 그 탭으로 오면 [쿼리] 는 켜진 채로 두고(검색으로 돌아갈 수 있게) `?` 만 끄며, 펼쳐 둔 쓰는 법도 닫는다.
- `SearchField` 에 `queryDisabled` 를 두었다 — 다른 화면은 그대로.

확인: 시험(전체 탭 `?` 꺼짐 → 캠페인 탭 켜짐) · 웹 빌드(WebKit): 전체 탭 [쿼리] 꺼짐, 퀘스트 탭에서 쿼리 + `?` 연 뒤 전체 탭 → `?` 꺼지고 쓰는 법 닫힘, 규칙 탭 `?` 꺼짐.

정규식: 지원하지 않는다(검색은 부분일치 · 낱말마다 그리고, 쿼리는 `키:값` · 쉼표=또는 · `-`=아님 · 따옴표).

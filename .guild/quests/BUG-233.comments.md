수정 — 응답 경로를 `/` 로 정규화하는 `rel_posix()` 를 두고 `save_template` 이
그걸 쓰게 했다. `PathBuf::to_string_lossy()` 직접 사용을 없앴다.

## 왜 지금 발견됐나

릴리스 전 **Windows 로컬**에서 워크스페이스 전체 테스트를 돌리다 걸렸다.
`check.yml` 의 테스트 잡은 ubuntu 에서만 돌고 macOS 잡은 build 만 한다 —
`/` 가 나오는 환경이라 통과했다. BUG-231(원격 파리티 복구)로 이 라우트가
추가될 때 들어온 것이다.

## 영향 범위 확인

`to_string_lossy()` 로 API 응답 경로를 만드는 다른 지점이 있는지 훑었다.
남은 한 곳은 `admin.rs:187` 인데 이건 응답이 아니라 **길드 파일 로드용 인자**라
플랫폼 경로 그대로가 맞다. 첨부는 애초에 `attachments/{name}` 문자열을 직접
만들어 영향 없음.

## 검증

- `test_template_create_list_show` 통과(원래 실패하던 것).
- 회귀 테스트 `test_template_path_uses_forward_slash` 추가 — 역슬래시 포함
  여부를 직접 확인하므로 **어느 플랫폼에서 돌려도 성립**한다. ubuntu 전용
  CI 가 못 잡던 종류를 잡기 위한 것.
- 워크스페이스 736 passed, clippy 통과.

## 남는 위험

CI 가 Windows 에서 테스트를 돌리지 않는 구조 자체는 그대로다. 같은 계열
(경로·개행·대소문자)의 문제가 또 나올 수 있다. CI 에 Windows 테스트 잡을
추가할지는 별도 판단이 필요하다.

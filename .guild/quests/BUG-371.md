앱 · 웹의 퀘스트 목록 검색칸은 "검색 (제목 / 본문)" 인데 **본문을 찾지 않는다** — 제목 · 번호만 본다(2026-10-21, DEV-447 확인 중 발견). 보드의 검색도 같다.

- 재현(시험용 길드 사본 + develop 서버): 목록 검색 `render_table` → **1개**, CLI `quest list --search render_table` → 3개(나머지 둘은 본문에만 있다).
- 원인: [[BUG-210]](2026-08-04)이 목록 · 보드가 받는 퀘스트에서 본문을 뺐다(`?slim=true`). 그런데 화면의 검색은 여전히 받은 퀘스트 안에서 찾는다 — 본문은 늘 비어 있다. BUG-210 은 "필터 · 검색은 서버에서 하므로" 라고 적었지만 실제로는 '댓글 · 첨부 포함' 을 켰을 때만 서버에 물었다.

## 고칠 것

- 검색어가 있고 '제목만' 이 꺼져 있으면 서버(앱은 코어)에 맞는 퀘스트를 묻는다 — 댓글 · 첨부 포함과 같은 길. 본문을 다시 받지는 않는다(BUG-210 의 수신량 이득 유지).
- 보드도 같은 판정으로 흐린다. 보드는 지금 '댓글 · 첨부 포함' 도 무시한다 — 같이 고친다.

## 고침 (2026-10-21)

- `needsServerSearch` 한 곳 — 검색어가 있고 '제목만' 이 아니거나 댓글 · 첨부를 넓혔으면 서버(앱은 코어)에 맞는 퀘스트를 묻는다. 본문은 여전히 받지 않는다(BUG-210 이득 유지).
- 목록: 넓힌 검색 갈래를 이 판정으로. '제목만' 도 서버에 싣는다 — 예전엔 빠져서 '제목만 + 댓글 포함' 이 본문까지 찾았다.
- 보드: 같은 판정으로 흐린다(늦게 온 답은 번호로 버림). 보드가 '댓글 · 첨부 포함' 을 무시하던 것도 같이 고쳐졌다.
- 답이 오기 전 0.25초는 예전처럼 제목 · 번호로 거른다.

## 확인 (웹 빌드 + develop 서버, WebKit, 시험용 길드 사본)

| `render_table` | 목록 | 보드 | CLI |
|---|---|---|---|
| 기본(제목 · 본문) | 1 → **3** | **3**/836 | 3 |
| 제목만 | 1 | — | 1 |
| 제목만 + 댓글 | 3 | — | 3 |

- 시험 `search-match.test.ts` 4. `just test` 통과.

## 테스트 방법

1. 퀘스트 목록 검색칸에 어떤 퀘스트의 **본문에만** 있는 낱말을 적는다 → 그 퀘스트가 나오면 정상.
2. '제목만' 을 켜면 사라진다.
3. 보드로 가면 같은 퀘스트만 선명하다.

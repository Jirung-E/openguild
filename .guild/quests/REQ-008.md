## 요청

문서 하단에 **'이 문서를 참조하는 문서'** 섹션을 추가한다.
해당 문서로 cross-link(`[[...]]`)를 건 문서들을 역방향으로 표시한다.

## 배경

현재 cross-link 는 **단방향**이다 — A 가 `[[B]]` 를 걸면 A 에서 B 로는 갈 수
있지만, B 를 보고 있을 때 "누가 나를 참조하는가" 를 알 수 없다. 설계 결정이
여러 퀘스트에 흩어져 있을 때 역방향 추적이 안 되면 맥락을 놓친다.

## 기대 동작

- 문서(퀘스트/캠페인/규칙/도서관) 상세 하단에 backlink 섹션
- 그 문서를 `[[...]]` 로 참조하는 모든 문서를 나열(제목 + 링크)
- 참조가 없으면 섹션 자체를 숨기거나 "없음" 표시

## 구현 고려사항

- **역인덱스가 필요하다.** 전체 문서 본문을 매번 스캔하는 것은 문서 수가 늘면
  비용이 크다. index.db 에 backlink 테이블을 두는 방식이 유력하나,
  [[BOOK-001]] 불변식상 **index.db 는 파일의 폐기가능 투영**이므로 반드시
  reindex 로 100% 재구축 가능해야 한다(DB→파일 역류 금지).
- cross-link 문법의 접두 별칭(`quest`/`q`, `campaign`/`c`, `rule`/`rules`/`r`,
  `book`/`library`/`lib`)과 접두 생략형을 모두 파싱해야 한다.
- 규칙 slug 는 공백을 포함할 수 있다(BUG-156, 예: `[[코딩 규칙]]`).
- 존재하지 않는 대상을 가리키는 깨진 링크는 backlink 집계에서 제외.

## 수정 내용 (2026-08-20)

결정대로 **index.db 역인덱스**.

### 색인 (파일 → DB 단방향)

- `core/migrations/0030_doc_links.sql` — `doc_links(src_kind, src_id,
  dst_kind, dst_id)`, `(dst_kind, dst_id)` 인덱스.
- `core/src/repo/crosslink.rs` — `[[...]]` 토큰 추출. **프론트 문법 미러**
  (`questIndex.ts` + `MarkdownView.svelte`): 대괄호/개행 제외 1~64자,
  `kind:` 별칭(quest/q, campaign/c, rule/rules/r, book/library/lib),
  BUG-156 의 공백 포함 규칙 slug 허용.
- `core/src/reindex.rs` **6e 단계** — 모든 문서 적재가 끝난 뒤에 돈다.
  링크를 **색인 시점에 해석**해 확정된 것만 담는다(깨진 링크 제외).
  그래서 조회 측이 우선순위(quest > campaign > book > rule)를 다시 구현하지
  않아도 되고, DEV-219 의 네임스페이스 충돌도 여기서 한 번만 정리된다.
  자기 자신 참조는 제외. 1단계 wipe 에 `DELETE FROM doc_links` 추가 —
  [[BOOK-001]] 대로 언제 지워도 reindex 로 100% 재구축된다.

### 조회

- `core/src/ops/backlinks.rs` — 읽기 전용. 제목은 각 캐시 테이블에서
  `COALESCE` 로 끌어오고, index.db 캐시가 없는 규칙은 slug 를 제목으로 쓴다.
- `server`: `GET /api/backlinks/{kind}/{id}`. 알 수 없는 kind 는 400 —
  조용히 빈 목록을 주면 "backlink 가 없는 문서" 와 구분이 안 된다.
- `gui`: Tauri `list_backlinks` 커맨드 + `transport.ts` 매핑. **데스크톱은
  HTTP 가 아니라 invoke 를 타므로 이걸 빠뜨리면 런타임에 throw 한다**
  (transport 가 그렇게 알려준다).

### UI

`BacklinkSection.svelte` — 퀘스트 / 캠페인 / 규칙 / 도서관 상세 4곳의 변경이력
바로 위에 배치. **참조가 없으면 섹션 자체를 렌더하지 않는다** — 대부분 문서엔
backlink 가 없고 빈 섹션이 쌓이면 소음이다.

[[REQ-004]] 에서 지적된 stale-async 문제를 처음부터 막았다 — 결과를 반영하기
전에 `wantKind/wantId` 가 아직 현재 대상인지 재확인한다. reindex 후에는
`reindexBump` 로 다시 읽는다.

## 부수 수정 — REQ-007 이 깨뜨린 테스트

전체 스위트를 돌리다 `QuestHistory.test.ts` 8건 실패를 발견했다. [[REQ-007]]
로 변경이력이 **기본 접힘**이 되면서 목록이 DOM 에 없어진 탓인데, 그 퀘스트를
머지할 때 컴포넌트 테스트를 돌리지 않아 놓쳤다.

테스트가 내용을 검증하기 전에 펼치도록 `renderExpanded()` 헬퍼를 넣었고,
**기본 접힘 계약 자체를 검증하는 테스트를 새로 추가**했다(접힌 동안 항목 0개
+ `aria-expanded=false` → 클릭 후 1개 + `true`).

## 테스트 방법

1. `openguild reindex` 후 BOOK-001 도서관 문서를 연다 — 하단에 "이 문서를
   참조하는 문서" 8건이 보이는지.
2. 목록의 규칙/퀘스트 링크가 각각 올바른 화면으로 가는지.
3. 아무도 참조하지 않는 문서에서는 섹션이 **아예 없는지**.
4. 퀘스트 본문에 `[[BOOK-001]]` 을 새로 추가 → `reindex` → 그 퀘스트가
   BOOK-001 의 목록에 나타나는지.
5. 데스크톱(Tauri) 앱에서도 동일하게 뜨는지 — HTTP 가 아니라 invoke 경로.

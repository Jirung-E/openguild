릴리스 전 전체 테스트에서 발견. `test_template_create_list_show` 가 Windows 에서
실패한다:

```
left:  ".guild\templates\remote-bug.md"
right: ".guild/templates/remote-bug.md"
```

## 테스트만의 문제가 아니다

`POST /api/templates` 응답의 `path` 를 `PathBuf::to_string_lossy()` 로 만든다
(`server/src/routes/templates.rs:52-57`). 그래서 **서버가 도는 OS 에 따라 응답이
달라진다**:

- Windows 호스팅: `.guild\templates\remote-bug.md`
- Linux/macOS 호스팅: `.guild/templates/remote-bug.md`

이 프로젝트의 상대 경로 관례는 `/` 다(첨부는 `attachments/{name}` 형태로
직접 문자열을 만든다). 클라이언트가 이 값을 그대로 표시하거나 다시 경로로
조립하면 Windows 서버에서만 어긋난다.

## 왜 CI 가 못 잡았나

`check.yml` 의 테스트 잡은 **ubuntu** 에서만 돈다(macOS 잡은 build 만). 거기선
`/` 가 나오므로 통과한다. BUG-231(원격 파리티 복구)로 이 라우트가 추가되면서
들어왔고, 로컬 Windows 전체 테스트에서 처음 드러났다.

## 방향

응답을 만들 때 구분자를 `/` 로 정규화한다. 같은 실수가 다른 라우트에 재발하지
않도록 정규화 지점을 한 곳으로 두고, Windows 에서도 성립하는 테스트를 남긴다.

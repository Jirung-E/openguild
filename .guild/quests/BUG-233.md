## 현상

1. 이미지 첨부 수가 많아지면 상세 화면의 미리보기가 반복해서 나타났다 사라지며 깜빡인다.
2. 첨부파일을 개별 다운로드하면 원본 확장자 없이 저장되는 경우가 있다.

## 확인된 원인

### 미리보기

AttachmentSection이 미디어마다 guildFileUrl을 비동기로 해석한 뒤 urls 객체를 갱신한다. 여러 요청이 동시에 진행될 때 각 요청이 오래된 urls 상태를 기준으로 객체를 다시 만들 수 있어, 늦게 완료된 요청이 이미 저장된 다른 URL을 덮어쓴다. effect에는 진행 중 요청을 구분하는 장치도 없어 누락된 경로를 반복 요청한다.

### 다운로드 파일명

개별 다운로드는 첨부 메타데이터의 name을 그대로 저장 파일명으로 사용한다. 길드의 실제 데이터 중에는 저장 path는 .html 확장자를 가지지만 표시 name에는 확장자가 없는 사례가 있다. 이 경우 macOS 저장 대화상자와 copy_guild_file 모두 확장자를 보완하지 않아 결과 파일도 확장자 없이 생성된다.

## 구현

- 미디어 URL 해석 중인 경로를 별도로 추적해 중복 요청을 막는다.
- 비동기 URL 해석이 끝난 시점의 최신 urls 상태에 결과를 병합해 다른 미리보기 URL을 지우지 않도록 한다.
- 다운로드용 파일명은 표시 name을 우선하되 확장자가 없으면 저장 path의 확장자를 붙인다.
- 내부 저장용 .bin은 실제 확장자가 아니므로 다운로드 이름에 붙이지 않는다.
- macOS 저장 대화상자에도 해당 확장자 필터를 전달하고, 반환 경로에 확장자가 전혀 없으면 보완한다.
- 전체 다운로드와 브라우저 다운로드에도 같은 파일명 정규화를 적용한다.
- URL 완료 순서 및 다운로드명 회귀 테스트를 추가한다.

## 완료 조건

- 여러 이미지 URL이 역순으로 완료돼도 모든 미리보기가 안정적으로 유지된다.
- 동일 경로의 URL 해석이 동시에 중복 실행되지 않는다.
- name에 확장자가 없어도 path에 확장자가 있으면 개별 및 전체 다운로드 결과가 해당 확장자를 가진다.
- 이미 확장자가 있는 이름은 변경하지 않는다.

## 수동 테스트

1. 이미지가 여러 장 첨부된 퀘스트를 열고, 첨부를 추가하거나 상세 화면을 다시 열어 모든 미리보기가 깜빡임 없이 유지되는지 확인한다.
2. 확장자가 표시 이름에 없는 첨부를 개별 다운로드해 실제 파일명이 저장 path의 확장자를 가지는지 확인한다.
3. 다운로드 전체를 실행해 같은 확장자 보완이 적용되는지 확인한다.
4. 원래 이름에 확장자가 있는 파일은 파일명이 바뀌지 않는지 확인한다.

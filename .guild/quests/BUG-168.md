대용량 파일을 첨부하면 실패한다. IPC 한도/타임아웃 의심.

원인 조사 결과와 실측 수치는 댓글 #1 참조 — 요약하면 **서버(브라우저) 모드는
axum 기본 body limit 2 MiB**(base64 팽창까지 감안하면 원본 약 1.5 MB)가
원인이고, 데스크탑은 base64-over-IPC 설계 자체가 파일 크기의 5~6배 메모리를
잡는 구조였다.

## 수정 내용

- server: `/api/attachments` 에만 `DefaultBodyLimit` 을 64 MB 원본 기준으로
  상향(다른 라우트는 기본 2 MiB 유지). 초과 시 크기를 밝힌 메시지 반환.
- gui(Rust): `save_attachment_from_path` 커맨드 추가 — 경로만 받아 Rust 에서
  읽고 저장. IPC payload 가 파일 크기와 무관하게 상수.
- gui(프론트): 파일 선택을 환경별로 분기(`pickUploads`) — 로컬 Tauri 는
  네이티브 다이얼로그로 경로, 그 외는 file input 으로 bytes. 첨부 섹션·본문
  편집기·댓글 편집기 3곳의 첨부 버튼이 모두 이 경로를 쓴다.
- bytes 경로에는 업로드 전 크기 검사 + 한도를 밝힌 안내(`attach.tooLarge`).

## Test plan

1. **데스크탑 · 첨부 섹션**: 퀘스트 상세에서 `+ 첨부` → 100 MB 이상 파일
   선택. 저장되고 목록에 뜨는지(기존엔 실패). 여러 개 동시 선택 시 하나씩
   목록에 추가되는지.
2. **데스크탑 · 본문 편집기**: 본문 편집 중 첨부 버튼으로 대용량 파일 선택 —
   첨부 섹션으로 들어가는지(비미디어) / 인라인 삽입되는지(미디어).
3. **데스크탑 · 붙여넣기·드래그&드랍**: 이미지 붙여넣기가 여전히 되는지.
   64 MB 초과 파일을 드랍하면 "첨부 파일이 너무 큽니다 (…MB / max 64 MB)"
   안내가 뜨는지(무반응/원문 노출 아님).
4. **브라우저(서버) 모드**: `openguild-server host` 로 접속해 5~50 MB 파일
   첨부 — 성공하는지. 64 MB 초과는 안내 메시지가 뜨는지.
5. **원격 연결된 데스크탑**: Tauri + 원격 서버 설정 상태에서 첨부 —
   경로 기반이 아니라 bytes 경로를 타야 한다(원격 서버엔 그 경로가 없으므로).
6. 언어를 영어로 바꿔도 안내 문구가 영어로 나오는지.

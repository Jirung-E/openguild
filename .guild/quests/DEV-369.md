## 배경

[[BUG-253]] 에서 레이아웃 px 를 정리하며 전수 조사를 했는데, **곡률 331건 /
테두리 331건**이 리터럴 px 로 남아 있었다. 그건 "깨지지는 않는" 부류라
범위 밖으로 뒀는데, admin 이 지적했다 —

> 설정팝업 / 보드툴바 / 노드클릭시팝업 / 대부분의 pill / cross-link 팝업 /
> cross-link 자동완성팝업 / 대부분의 버튼 등이 전부 곡률이 고정임.
> 모양이 같은데 재활용을 한 게 아니라 복붙을 한 거냐?

지목한 곳들은 전부 조사에 포함돼 있었다. 아래가 그 전수 결과다.

## 결론부터 — 복붙이 맞다

| | 건수 |
|---|---|
| 토큰(`var(--r-*)`) 사용 | **17** |
| 리터럴 px | **331** |
| 서로 다른 값 | **18종** |

토큰은 [[BUG-244]] 가 검색 팔레트·Nav 만 손대서 거기에만 있다. 나머지는 전부
값을 직접 적었다.

## 값 분포 — 표류의 증거

```
130  6px      ← --r-md 와 동일
 65  4px      ← --r-sm 과 동일
 24  10px
 22  8px      ← --r-lg 와 동일
 21  20px
 13  50%
 12  3px  ┐
 11  5px  ├─ 서로 1~2px 차이. 의도된 구분으로 보기 어렵다
  9  2px  │   ← --r-xs 와 동일
  9  12px ┘
  5  999px    ← --r-pill 과 동일
  4  9px
```

`3 / 4 / 5px` 이 따로 있고 `8 / 9 / 10 / 12px` 이 따로 있다. 같은 "작은 곡률" ·
"중간 곡률" 을 각각 세 가지로 적고 있는 셈이다.

## 용도별 — 같은 물건이 제각각이다

| 용도 | 건수 | 값 종류 | 분포 |
|------|------|--------|------|
| 버튼 | 91 | 7종 | `6px×53`, `4px×25`, 토큰×4, `20px×3`, `5px×3`, `999px×2` |
| pill/칩/뱃지 | 33 | **10종** | `20px×14`, `10px×4`, `6px×4`, `999px×2`, `12px×2`, `5px×2` |
| 카드/패널/행 | 28 | 10종 | `8px×8`, `6px×7`, `4px×4`, `50%×2`, `10px×2` |
| 입력 | 27 | 5종 | `4px×15`, `6px×9`, `12px×1`, `8px×1` |
| 모달 | 16 | 4종 | `10px×9`, `6px×4`, `4px×2`, `12px×1` |
| 팝업/드롭다운 | 12 | 6종 | `8px×3`, `6px×3`, 토큰×2, `50%×2`, `4px×1`, `5px×1` |
| 바/스크롤 | 11 | 8종 | `2px×4` 외 |
| 분류 안 됨 | 128 | 16종 | `code`, `.swatch`, `.status`, `.sort-sel` 등 소품 |

**pill 이 10종**이라는 게 핵심이다 — 같은 알약 모양을 `20 / 10 / 6 / 999 /
12 / 5px` 로 제각각 적었다. [[DEV-364]](pill 모양 통일)가 이미 등록돼 있는
이유이기도 하다.

**버튼도 `6px` 과 `4px` 이 반반**(53 : 25)이다. 어느 쪽이 "맞는" 값인지
코드만 봐서는 알 수 없다.

## admin 이 지목한 곳들 — 실제 값

| 화면 | 리터럴 px | 값 | 토큰 |
|------|----------|-----|------|
| 설정 팝업 | 10 | `6px×8`, `4px×2` | 0 |
| **보드 툴바 / 노드 팝업** | 27 | `6px×7`, `4px×6`, `10px×3`, `5px×3`, `9px×2` | 0 |
| cross-link 팝업 | 3 | `8px`, `4px`, `5px` | 0 |
| cross-link 자동완성 | 2 | `8px`, `5px` | 0 |
| 전역 버튼/pill(global.css) | 2 | `8px`, `3px` | 0 |
| 퀘스트 목록 항목 | 3 | `20px×3` | 0 |
| 검색 팔레트 | 0 | — | **11** |

보드가 가장 심하다 — **한 파일 안에서 다섯 종류**를 쓴다.

## 테두리도 같은 상태

| | 건수 |
|---|---|
| 토큰(`var(--bw)`) | **13** |
| 리터럴 | **331** (`1px×314`, `3px×9`, `2px×6`, `1.5px×1`, `5px×1`) |

1px 이 314건으로 거의 전부라 **치환 자체는 곡률보다 단순**하다. 다만
`--bw` 는 `0.0625rem` 이라 배율에 반응하므로, 200% 에서 테두리가 2px 로
두꺼워진다 — 그게 의도인지 확인이 필요하다.

## 정리 방안 (판단 필요)

### A. 값 그대로 치환 — 231건, 회귀 위험 0

```
6px  → var(--r-md)   130건
4px  → var(--r-sm)    65건
8px  → var(--r-lg)    22건
2px  → var(--r-xs)     9건
999px→ var(--r-pill)   5건
```

**모양이 전혀 바뀌지 않는다.** 나머지 100건(`3/5/9/10/12/20px`, `50%`)은
그대로 둔다.

### B. 전부 통일 — 331건, 모양이 1~2px 바뀜

표류한 값을 가까운 토큰으로 스냅한다(`3→xs`, `5→sm`, `9/10/12→lg`,
`20→pill`). 진짜 통일되지만 보드 노드·카드·pill 의 모양이 미세하게 달라져
눈으로 확인할 면이 넓다.

### C. 용도별로 결정하고 나서 치환

`버튼 = ?`, `pill = --r-pill`, `모달 = ?` 처럼 **용도별 정답을 먼저 정하고**
거기에 맞춘다. 가장 옳지만 디자인 결정이 선행돼야 한다.

## 남은 위험

- `50%` (13건, 원형 버튼)과 `999px`(5건)은 성격이 다르다 — 전자는 정원,
  후자는 알약. 토큰 하나로 묶으면 안 된다.
- 보드 노드는 `BOARD_NODE_WIDTH` JS 상수와 짝이라([[BUG-253]] 참고) 곡률은
  무관하지만 **크기는 절대 건드리면 안 된다.**
- `check:no-hex` 같은 자동 검사가 곡률에는 없다. 통일 후 재발을 막으려면
  `check:no-raw-radius` 류의 검사가 함께 필요하다 — 없으면 다음 커밋부터
  다시 리터럴이 섞인다.

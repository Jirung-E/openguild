
## 테두리도 같은 상태

| | 건수 |
|---|---|
| 토큰(`var(--bw)`) | **13** |
| 리터럴 | **331** (`1px×314`, `3px×9`, `2px×6`, `1.5px×1`, `5px×1`) |

1px 이 314건으로 거의 전부라 **치환 자체는 곡률보다 단순**하다. 다만
`--bw` 는 `0.0625rem` 이라 배율에 반응하므로, 200% 에서 테두리가 2px 로
두꺼워진다 — 그게 의도인지 확인이 필요하다.

## 정리 방안 (판단 필요)

### A. 값 그대로 치환 — 231건, 회귀 위험 0

```
6px  → var(--r-md)   130건
4px  → var(--r-sm)    65건
8px  → var(--r-lg)    22건
2px  → var(--r-xs)     9건
999px→ var(--r-pill)   5건
```

**모양이 전혀 바뀌지 않는다.** 나머지 100건(`3/5/9/10/12/20px`, `50%`)은
그대로 둔다.

### B. 전부 통일 — 331건, 모양이 1~2px 바뀜

표류한 값을 가까운 토큰으로 스냅한다(`3→xs`, `5→sm`, `9/10/12→lg`,
`20→pill`). 진짜 통일되지만 보드 노드·카드·pill 의 모양이 미세하게 달라져
눈으로 확인할 면이 넓다.

### C. 용도별로 결정하고 나서 치환

`버튼 = ?`, `pill = --r-pill`, `모달 = ?` 처럼 **용도별 정답을 먼저 정하고**
거기에 맞춘다. 가장 옳지만 디자인 결정이 선행돼야 한다.

## 남은 위험

- `50%` (13건, 원형 버튼)과 `999px`(5건)은 성격이 다르다 — 전자는 정원,
  후자는 알약. 토큰 하나로 묶으면 안 된다.
- 보드 노드는 `BOARD_NODE_WIDTH` JS 상수와 짝이라([[BUG-253]] 참고) 곡률은
  무관하지만 **크기는 절대 건드리면 안 된다.**
- `check:no-hex` 같은 자동 검사가 곡률에는 없다. 통일 후 재발을 막으려면
  `check:no-raw-radius` 류의 검사가 함께 필요하다 — 없으면 다음 커밋부터
  다시 리터럴이 섞인다.

### 조사 본문의 A안 설명을 정정한다

A안을 "모양이 전혀 바뀌지 않는다 / 회귀 위험 0" 이라고 적었는데 **정확하지
않다.** 토큰은 rem 이다(`--r-md: 0.375rem`). 기본 배율에서만 6px 과 같고,
UI 배율 200% 에서는 곡률도 12px 로 함께 커진다.

그게 [[BUG-244]]·[[BUG-254]] 가 의도한 동작이므로 문제는 아니지만, "안 바뀐다"
가 아니라 **"기본 배율에서 같고 그 위에서 비례한다"** 가 맞는 설명이다.

## 토큰 신설 — `--r-xl`

`10px` 이 24곳에 몰려 있는데 전부 **모달·다이얼로그·큰 카드**다
(`.modal` ×7, `.dialog`, `.node-card`, `.card`, `.qm`, `.modal-sm` ×2 …).

가장 가까운 `--r-lg`(8px)로 스냅하면 24곳의 모양이 전부 바뀐다 — 그건 통일이
아니라 임의 변경이다. **실제로 쓰이던 값을 토큰으로 승격**했다.

```
--r-xl: 0.625rem;  /* 10px — 모달 / 다이얼로그 / 큰 카드 */
```

덕분에 B안에서 모양이 바뀌는 곳이 조사 당시 추정(≈100건)보다 훨씬 적다.

## 실측에서 잡은 것 — 검색 팔레트 칩 높이

`.pslug`(19.58px)와 옆의 `.ptype`(22px)이 2.4px 어긋나 있었다.

**내 회귀는 아니다.** [[BUG-244]] 가 `.ptype` 을 제목 한 줄에 맞춰 1.375rem
으로 키우면서 `.pslug` 를 안 따라온 것이고, 값 자체는 이번 변경 전후가 같다
(git 으로 대조 확인). 다만 [[DEV-364]] 에서 내가 단 주석이 "나란히 놓이는
`.ptype` 과 같아야 한다" 였으므로 맞추는 게 맞다.

`.pill.xs` 의 높이를 `--pill-h` 손잡이로 노출하고 팔레트가 `1.375rem` 을
준다. 모양(비율)은 여전히 정본이 정하고, 화면 사정은 변수로 흡수한다.

**고치는 과정에서 CSS 우선순위 함정을 하나 만났다.** 처음엔 `.pslug` 로
적었는데 안 먹었다 — `.pill.xs`(0,2,0)와 `.pslug`+스코프 클래스(0,2,0)가
**같은 specificity** 라 순서로 갈리고, global.css 가 뒤에 와서 기본값
`1.7em` 이 이겼다. 실측이 19.58px 그대로인 것을 보고 알았다.
`.pill.pslug`(0,3,0)로 올려 해결했고, 이유를 코드 주석에 남겼다.

**수정 후**: `.pslug` 22px = `.ptype` 22px. 접힌 행 높이는 **36.4px** 로
그대로 — [[DEV-359]] 의 `contain-intrinsic-size` 전제가 유지된다.

## 남는 위험

- **Windows / Linux 는 실측하지 못했다** — 개발 환경이 macOS 다. rem 기반
  이라 엔진 차이는 적을 것으로 보이지만 확인한 것은 아니다.
- 보드의 자체 확대/축소와 rem 곡률이 겹치는 극단 배율(50% / 200%)에서 노드
  안 여백이 어색한지는 눈으로 훑는 수준까지만 봤다.

## 테스트 방법

1. 전 화면을 훑으며 모서리가 어색한 곳이 없는지 — 특히 위 5개.
2. 설정에서 UI 배율을 50% / 100% / 200% 로 바꿔가며 곡률·테두리가 함께
   비례하는지.
3. 스크롤바 모서리가 배율과 무관하게 그대로인지(의도된 예외).
4. 원형 요소(홈 캐러셀 점, 슬라이더 thumb, 원형 버튼)가 여전히 **정원**인지 —
   알약으로 바뀌었으면 잘못된 것이다.

## 정정 — 보드 노드는 px 섬이다 (admin 지적)

> 보드에 표시되는 노드는 크기가 변하면 안된다.

**맞다. 이 퀘스트 본문에 내가 직접 적어 둔 주의사항을 내가 어겼다** —
"보드 노드는 `BOARD_NODE_WIDTH` JS 상수와 짝이라 크기는 절대 건드리면 안 된다."

`.board-node` 는 `width: 284px / height: 80px` 이고 그 숫자가
`quest-board-model.ts` 의 `BOARD_NODE_WIDTH` / `BOARD_NODE_HEIGHT` 와 같다.
Cytoscape 레이아웃과 히트테스트가 같은 값을 쓰므로 **상자는 UI 배율을 안
따라간다.** 노드 안도 전부 px 다(`top: 7px`, `left: 8px`, `gap: 5px`,
`height: 18px`, `font-size: 12px`).

그런데 [[DEV-364]] 가 노드 pill 을 `.pill.xs`(em 기반)로 바꾸고 이 퀘스트의
일괄 치환이 노드 곡률을 `--r-xl`(rem)로 바꿨다. 상자는 그대로인데 안쪽만
커지므로 **배율을 올리면 내용이 넘친다.**

### 값까지 바뀐 것도 있었다

`.board-wrap.lod-overview .board-node` 는 원래 **14px** 인데 일괄 치환이
`--r-xl`(10px)로 보내 **기본 배율에서도 4px 줄어 있었다.** 표에 "14px →
`--r-xl`" 로 적어 두고도 값이 다르다는 것을 놓쳤다.

### 수정 — 모양 공식은 두고 치수 토큰만 px 로

노드 서브트리에서만 토큰을 px 로 덮는다. `.pill` 의 공식(곡률·배경비·
테두리비)은 그대로 쓰므로 정본은 여전히 하나다.

```css
.node-topline :global(.pill.xs) {
    --pill-fs: 10px;  --pill-h: 17px;  --pill-px: 7px;  --bw: 1px;
}
.board-node                        { --r-xl: 10px; }
.board-wrap.lod-overview .board-node { --r-xl: 14px; }
```

`.pill.xs` 가 `--pill-*` 를 **자기 요소에** 얹으므로 상속으로는 못 덮는다 —
같은 요소에 더 높은 specificity(0,3,0)로 얹어야 한다.

리터럴을 안 쓰고 토큰을 덮었으므로 `check:radius` 는 그대로 통과한다.

### 실측 — 배율 100% / 200% 대조

| | 100% | 200% |
|---|---|---|
| 노드 상자 | 284 × 80, 곡률 10px | **284 × 80, 곡률 10px** |
| slug pill | 10px / 17px / `0 7px` / 테두리 1px | **전부 동일** |
| 긴급도 pill | 10px / 17px / `0 7px` / 1px | **전부 동일** |

노드와 그 안 전부가 배율에 **완전히 불변**이고, 값은 DEV-364 이전과 같다.

### 다른 px 섬은 없는지 확인했다

`width/height` 가 px 로 고정된 상자를 전부 훑었다. JS 상수와 짝인 것은 보드
노드뿐이고, 나머지(스크롤바·슬라이더 thumb·캐러셀 점·타이틀바 창 버튼)는
곡률이 `50%` / `none` / `2px` 라 이번 치환이 건드리지 않았다.

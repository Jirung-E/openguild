프론트엔드 디자인 언어를 정한다(admin). **지금은 정의만 — 화면 적용은 [[DEV-428]] 이하.**

## 지금 (2026-09-23 측정)

| | 상태 |
|---|---|
| 색 | 토큰 60개 + 규칙 `frontend-theme-tokens` — 다크·라이트 둘 다 |
| 모서리 | 토큰 6단계(`--r-xs` ~ `--r-pill`), 거의 다 지켜짐 |
| UI 배율 | 규칙 `frontend-ui-scale` (rem) |
| 글자 크기 | 토큰 없음 — **39가지**. `0.8 / 0.82 / 0.825 / 0.85 / 0.875rem` 처럼 눈으로 구별 안 되는 값이 여럿 |
| 간격 | 토큰 없음 — `gap` 48가지, `padding` 177가지 |
| 그림자 | 36가지 |
| 버튼 | 공통 부품 없음 — 클래스 20종 넘음, `.btn-cancel` 이 8개 파일에 따로 정의 |

"버튼이 텍스트 링크처럼 보인다", "버튼과 입력칸이 붙어 보인다", "버튼이 띄엄띄엄 놓인다" 같은 보고는
대부분 아래 네 줄에서 나왔다 — 화면마다 따로 정하니 조금씩 어긋난다.

## 정한 것 (admin)

- **세 층으로 담는다.**
  - 토큰 — 있는 색·모서리에 **글자 크기 · 간격 · 그림자 · 움직임**을 더한다
  - 부품 — 버튼 · 입력칸 · 팝업 · 알약처럼 여러 화면에 나오는 것은 하나씩만
  - 원칙 — 밀도, 아이콘 스타일, 강조를 언제 쓰는지
- **성격은 지금 것을 유지**한다(GitHub 다크 계열). 새 방향을 잡지 않는다 — 지금 쓰이는 값에서 뽑아
  단계를 정한다.
- **어디에 적나** — 도서관 `디자인/` 폴더에 상세(왜 · 예시 · 단계표). 규칙에는 "디자인할 때는 이
  도서관 문서에서 정한 대로 한다" 한 줄과 가리키는 곳만. 규칙과 설명이 두 곳에 있으면 어긋난다.
- **적용은 따로** — 토큰과 규칙을 먼저, 그다음 버튼만 공통 부품으로([[DEV-428]]), 나머지는 그 화면을
  고칠 때 같이 옮긴다.

## 할 일

1. 지금 쓰이는 값을 모아 단계를 정한다 — 글자 크기 · 간격 · 그림자 · 움직임. 가까운 값끼리 묶는다
2. `global.css` 에 토큰 추가(다크·라이트 둘 다가 필요한 것은 둘 다)
3. 도서관 `디자인/` — 토큰 표 · 부품 목록 · 원칙
4. 규칙 — 도서관 문서를 가리키는 짧은 것. 기존 `frontend-theme-tokens` · `frontend-ui-scale` 와 어떻게 묶을지

프론트엔드 디자인 언어를 정한다(admin). **지금은 정의만 — 화면 적용은 [[DEV-428]] 이하.**

## 지금 (2026-09-23 측정)

| | 상태 |
|---|---|
| 색 | 토큰 60개 + 규칙 `frontend-theme-tokens` — 다크·라이트 둘 다 |
| 모서리 | 토큰 6단계(`--r-xs` ~ `--r-pill`), 거의 다 지켜짐 |
| UI 배율 | 규칙 `frontend-ui-scale` (rem) |
| 글자 크기 | 토큰 없음 — **39가지**. `0.8 / 0.82 / 0.825 / 0.85 / 0.875rem` 처럼 눈으로 구별 안 되는 값이 여럿 |
| 간격 | 토큰 없음 — `gap` 48가지, `padding` 177가지 |
| 그림자 | 36가지 |
| 버튼 | 공통 부품 없음 — 클래스 20종 넘음, `.btn-cancel` 이 8개 파일에 따로 정의 |

"버튼이 텍스트 링크처럼 보인다", "버튼과 입력칸이 붙어 보인다", "버튼이 띄엄띄엄 놓인다" 같은 보고는
대부분 아래 네 줄에서 나왔다 — 화면마다 따로 정하니 조금씩 어긋난다.

## 정한 것 (admin)

- **세 층으로 담는다.**
  - 토큰 — 있는 색·모서리에 **글자 크기 · 간격 · 그림자 · 움직임**을 더한다
  - 부품 — 버튼 · 입력칸 · 팝업 · 알약처럼 여러 화면에 나오는 것은 하나씩만
  - 원칙 — 밀도, 아이콘 스타일, 강조를 언제 쓰는지
- **성격은 지금 것을 유지**한다(GitHub 다크 계열). 새 방향을 잡지 않는다 — 지금 쓰이는 값에서 뽑아
  단계를 정한다.
- **어디에 적나** — 도서관 `디자인/` 폴더에 상세(왜 · 예시 · 단계표). 규칙에는 "디자인할 때는 이
  도서관 문서에서 정한 대로 한다" 한 줄과 가리키는 곳만. 규칙과 설명이 두 곳에 있으면 어긋난다.
- **적용은 따로** — 토큰과 규칙을 먼저, 그다음 버튼만 공통 부품으로([[DEV-428]]), 나머지는 그 화면을
  고칠 때 같이 옮긴다.

## 할 일

1. 지금 쓰이는 값을 모아 단계를 정한다 — 글자 크기 · 간격 · 그림자 · 움직임. 가까운 값끼리 묶는다
2. `global.css` 에 토큰 추가(다크·라이트 둘 다가 필요한 것은 둘 다)
3. 도서관 `디자인/` — 토큰 표 · 부품 목록 · 원칙
4. 규칙 — 도서관 문서를 가리키는 짧은 것. 기존 `frontend-theme-tokens` · `frontend-ui-scale` 와 어떻게 묶을지

## 한 것 (2026-10-11)

admin: "토큰을 최소화하는 방향으로 가 보고 이상한 곳을 고쳐 나가는 게 맞지 않을까" — **정의만 하고
나중에 적용**하던 계획을 바꿔, 단계를 줄인 토큰을 **바로 전체에 적용**하고 전후 화면을 비교해 어색한
곳을 고쳤다. 새 값은 만들지 않고 많이 쓰이던 값을 단계로 삼았다.

| | 전 | 후 |
|---|---|---|
| 글자 크기 | 42가지 | `--fs-xs/sm/md/lg/xl` 5단계 (11.5 / 12.8 / 14 / 16 / 20px) |
| 간격 (gap · padding · margin) | 56가지 | `--sp-2 ~ --sp-32` 8단계 |
| 그림자 | 38가지 | `--shadow-sm/md/lg` + `--ring`, 다크 · 라이트 진하기 따로 |
| 움직임 | 0.1 ~ 0.4s 여러 가지 | `--dur-fast/mid/slow`, 동작 줄이기면 0 |
| 굵기 · 줄 간격 | 6 · 11가지 | 4 · 3단계 |

- **고친 곳**: 아이콘 · × 글리프 20곳은 그림 크기라 원래 값으로 되돌림. 화면 제목 7곳(17.6 ~ 20px 섞임)을
  `--fs-xl` 하나로. 도서관 문서 제목은 xl 로 올리면 버튼 줄에서 두 줄로 넘쳐 lg 로.
- **검사** `check:tokens` (`just test` · CI) — 위 여섯 가지를 리터럴로 적으면 실패. 토큰이 맞지 않는
  자리는 그 줄에 `/* token-ok: 이유 */` (지금 26곳, 모두 아이콘 · × 글리프 · 환영 화면 큰 제목).
- **문서** 도서관 `디자인/` [[BOOK-009]] — 토큰 표 · 부품 · 원칙 · 새 값이 필요할 때.
- **규칙** `frontend-design-language` — [[BOOK-009]] 를 가리키는 짧은 것. `frontend-theme-tokens` ·
  `frontend-ui-scale` 은 그대로 두고 서로 가리키게만.
- 윈도우에서 글자가 작아 보이는 문제: 측정해 보니 크기 차이는 없다(윈도우가 오히려 5% 큼). 획 굵기 ·
  렌더링 쪽으로 보이며 admin 결정으로 놔둔다.

확인: 13개 화면(홈 · 보드 · 보드 카드 · 보드 설정 · 퀘스트 목록 · 상세 · 새 캠페인 · 도서관 · 규칙 ·
설정 · 캠페인 · 작업 기록 · 태그) × 다크 · 라이트, 바꾸기 전 빌드와 나란히 비교 — 깨지거나 잘린 곳 없음.
평균 글자 크기는 그대로(+0.1%). `just test` 851 통과.

## 테스트 방법

1. 앱 전체를 둘러본다 — 글자 · 여백이 전보다 고르고, 넘치거나 잘린 곳이 없다. 특히 모달 · 메뉴 ·
   보드 카드 · 퀘스트 목록 · 도서관.
2. 라이트 테마에서 모달 · 메뉴 그림자가 예전보다 옅고 자연스럽다.
3. 설정 → UI 크기를 바꿔도 글자 · 여백 · 그림자가 함께 커지고 작아진다.
4. 도서관 `디자인/` 에 "디자인 언어" 문서, 규칙에 `frontend-design-language` 가 있다.

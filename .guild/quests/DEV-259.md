사용자 지적: 어드민 페이지에서 Reindex 를 누르면 뜨는 알림이 업데이트 확인
알림(UpdateBanner)과 모양/위치가 다름. 과거에도 통일 요청이 있었으나 재발 —
이번엔 코드베이스 전수조사 후 등록.

## 전수조사 결과 (2026-07-14)

### (a) 알림 메커니즘이 최소 3갈래로 분산됨

1. **`ToastHost.svelte`** — 앱 공용 toast. `$lib/stores/toast` 의
   `showToast()` 로 발행. **우상단** fixed, `top: 1rem; right: 1rem;
   z-index: 2000`. "alert() 대체" 로 설계된 진짜 표준 컴포넌트
   (`+layout.svelte` 주석: "앱 공용 toast — alert() 대체, 어디서든 동일 UI").

2. **`UpdateBanner.svelte`** (업데이트 확인 알림) — `showToast()` 를 전혀 안
   쓰는 독자 구현. **우하단** fixed, `right: 1.5rem; bottom: 1.5rem;
   z-index: 60`. 자체 CSS/자동닫힘 타이머(5초, uptodate/error 만).

3. **`admin/+page.svelte`** — Reindex 를 포함한 어드민 페이지의 **모든**
   액션(snapshot 생성/복원/삭제, drift 체크, vacuum, journal 로드,
   `AdminTypesSection`/`AdminStatusesSection`/`AdminTagDefsSection` 의
   `onSectionMessage` 경유 메시지까지)이 로컬 `showSuccess`/`showError`/
   `showInfo` (86~97행, `showToast()` 아님) 를 거쳐 페이지 자체 인라인 마크업
   (234~238행 `.toast-wrap`) 으로 렌더. **우상단** — `ToastHost` 와 같은
   코너를 쓰지만 **완전히 별도 구현** (다른 z-index, 다른 자동닫힘 시간
   4초/6초, CSS/애니메이션을 `ToastHost` 것과 거의 동일하게 복붙).
   → `ToastHost.svelte` 를 고쳐도 admin 페이지엔 반영 안 됨 — 이게 바로
   "저번에 통일하라고 했는데" 가 재발한 근본 원인으로 추정.

### (b) `alert()` 로 완전히 새는 곳 (toast 시스템 자체를 안 탐)

`+layout.svelte`/`library/+page.svelte`/`quests/[id]/+page.svelte` 주석에
"alert() 대체" 컨벤션이 명시돼 있음에도, 실제로는 네이티브 `alert()` 가 아직
많이 남아있음:
- `QuestCommentsSection.svelte` — 446, 457, 468, 477, 798행 (반응/고정/토론/
  해결/삭제 실패 시 `alert()`).
- `campaigns/[slug]/+page.svelte` — 228, 241, 265, 278, 295, 314, 337, 371,
  384, 399행 (10곳).
- `campaigns/+page.svelte` — 58행.
- `rules/+page.svelte` — 298행.

## 방향 (착수 시 결정 필요 — 등록만, 미착수)

- 기본 방향: **`ToastHost`/`showToast()` 를 유일한 표준으로 통일** —
  UpdateBanner 의 우하단 배치는 "여러 상태(진행중/완료/에러)를 유지해서
  보여줘야 한다"는 특수 요구가 있어 완전 통합이 애매할 수 있음(ToastHost 는
  단발성 toast 큐 형태인지 확인 필요) — 착수 시 ToastHost 의 실제 API/동작
  방식부터 파악.
- admin 페이지의 `showSuccess`/`showError`/`showInfo` → `showToast()` 로
  교체가 가장 명확한 저비용 개선.
- `alert()` 잔재 목록(위 4개 파일, 총 15곳)도 같은 퀘스트 범위에 포함할지,
  분리할지는 착수 시 판단(스코프가 꽤 커서 별도 퀘스트로 쪼갤 수도 있음).

## 구현

퀘스트 본문의 작업 방향 그대로.

### 1. `--titlebar-h` 를 rem 으로

```
'32px' → '2rem'          (Windows / macOS)
'40px' → 'max(2.5rem, 30px)'  (Linux)
```

이 값을 쓰는 곳(Nav 의 `top`, QuestList / QuestBoard / SearchPalette 의 `calc`)은
전부 `var()` 라 함께 따라간다 — 손댈 게 없었다.

**Linux 만 px 하한을 뒀다.** 그쪽 창 컨트롤은 이전 수정이 **의도적으로 px 로
고정**해 둔 것이고(`.tb-controls.linux` 주석: "rem 이면 UI 스케일 시 버튼이
좌측으로 밀림") 지름이 24px 이라, 바가 그보다 낮아지면 버튼이 넘친다.
배율 50% 면 `2.5rem` = 20px 다.

### 2. `TitleBar.svelte` 앱 UI 를 rem 으로

앱 아이콘 · 아이콘 버튼 · 검색 pill · 드롭다운 메뉴 · 간격 · 폰트.
곡률·테두리는 BUG-244 의 토큰(`--r-sm` / `--r-md` / `--r-lg` / `--bw`)으로.

### 3. px 로 남긴 것 — **전부 네이티브 관례**

| 위치 | 값 | 이유 |
|------|-----|------|
| `.titlebar.mac-overlay` padding-left | 78px | traffic light 는 네이티브 위젯이라 앱 배율을 안 따른다. rem 이면 배율마다 여백이 버튼과 어긋난다 |
| `.tb-btn` width | 46px | Windows 캡션 버튼 표준. 높이는 `100%` 라 바를 따라간다 |
| `.tb-controls.linux` 일체 | 10/5/24px | 이전 수정의 의도적 결정 — 되돌리지 않았다 |

## 지적: 버튼은 커지는데 아이콘은 그대로

맞다. 앞 커밋이 CSS 만 rem 으로 옮겼는데, 아이콘 크기는 CSS 가 아니라 **SVG 의
`width` / `height` 속성**에 박혀 있었다.

```html
<svg width="15" height="15" viewBox="0 0 16 16">
```

속성값은 px 단위라 root font-size 배율을 따라가지 않는다. 그래서 버튼(rem)만
커지고 안의 아이콘은 15px 로 고정이었다.

## 수정

속성은 **그대로 두고** CSS 로 덮는다 — SVG 의 width/height 는 presentation
attribute 라 CSS 보다 우선순위가 낮다. 속성을 남겨두면 viewBox 비율과 CSS
미적용 시 폴백이 유지된다.

크기별 클래스 3종(`.tb-ico` 0.9375rem / `-sm` 0.8125rem / `-xs` 0.6875rem)을
붙였다 — 각각 15 / 13 / 11px 에 대응.

- `TitleBar.svelte` 12개
- `Nav.svelte` 2개 (`-xs` 는 안 쓰여 제거 — svelte-check 가 잡아줬다)

**Linux 창 컨트롤의 fallback 아이콘 4개(`width="10"`)는 건드리지 않았다** —
그 영역은 이전 수정이 의도적으로 px 로 고정한 곳이다.

## 실측 (앱 실행, 배율별 폭)

| 배율 | 아이콘 버튼 | 타이틀바 아이콘 |
|------|------------|----------------|
| 0.5 | 15.0 | **7.5** |
| 1.0 | 30.0 | **15.0** |
| 2.0 | 60.0 | **30.0** |

버튼과 같은 비율로 함께 커진다. 앞 커밋에서는 이 값이 15.0 으로 고정이었다.

## 확인하지 못한 것

- `.tb-appicon`(창 좌상단 앱 아이콘)은 macOS 에서 `{#if !isMac}` 이라 렌더되지
  않아 실측 불가. CSS 는 rem 으로 바꿔 뒀다.
- Nav 의 아이콘 2개는 닫힌 드롭다운 / 원격 접속 시에만 그려져 DOM 에 없었다.
  같은 CSS 규칙이고 svelte-check 가 셀렉터 사용을 확인했다.
- Windows / Linux 타이틀바는 이 기기가 macOS 라 여전히 실측 불가.

## 보고: Windows 에서 창 버튼 크기가 바뀜

내 회귀였다. 타이틀바의 px 를 일괄로 rem 화하면서 **`.tb-winicon` 의
`font-size: 10px` 까지 쓸어 담았다** — Windows 캡션 버튼의 글리프다.

macOS 는 네이티브 traffic light 라 `.tb-btn` 자체가 렌더되지 않아 앞선 실측에
안 걸렸다. "Windows / Linux 는 실측 못 했다" 고 남겼던 바로 그 사각지대다.

## 확인 방법 — macOS 에서 Windows 레이아웃 강제

`platform.ts` 의 `isMacOverlay()` 와 `usesCustomTitlebar()` 를 임시로 고정해
Windows 분기를 렌더시키고 배율별로 쟀다(검증 후 원복).

`usesCustomTitlebar()` 가 `isMacOverlay()` 를 참조해서, 처음엔 바 자체가
사라졌다 — 둘 다 강제해야 했다.

## 수정

1. **글리프** `0.625rem` → `10px` 복원.
2. **버튼 높이** `100%` → `32px` 고정(admin 결정). 예전 `height: 100%` 는
   타이틀바가 px 상수이던 시절엔 결과가 같았지만, 바가 rem 이 되면서 배율을
   따라가 버렸다(실측 200%: 46×64).
3. `.tb-controls` 에 `align-items: center` — 바가 더 높을 때 위아래 여백이
   대칭이 되도록. (Linux 쪽은 이미 있었다.)

창 컨트롤 영역에 rem 이 하나도 안 남은 것을 스크립트로 전수 확인했다.

## 실측 (Windows 레이아웃)

| 배율 | 바 | 창버튼 | 상/하 여백 | 글리프 |
|------|-----|--------|-----------|--------|
| 1.0 | 32 | **46×32** | 0 / 0 | **10px** |
| 1.5 | 48 | **46×32** | 8 / 8 | **10px** |
| 2.0 | 64 | **46×32** | 16 / 16 | **10px** |

수정 전에는 200% 에서 46×**64**, 글리프 20px 이었다.

## 여전히 확인 못 한 것

실제 Windows / Linux 실행은 이 기기(macOS)에서 불가능하다. 위 실측은 macOS
WKWebView 에서 **레이아웃만** 강제한 것이라, 폰트(Segoe Fluent Icons)가 없어
글리프의 시각적 결과는 확인할 수 없다. 치수는 맞다.

`just test` 515건, `check:no-hex` 통과.

## admin: Windows 는 세로 가운데정렬 말고 우측 **상단**에 붙는 게 낫다

앞 커밋에서 버튼 높이를 32px 로 고정하며 `.tb-controls` 에
`align-items: center` 를 넣었는데(바가 더 높을 때 위아래를 대칭으로),
네이티브 Windows 캡션 버튼은 항상 창 **우측 상단 모서리**에 붙어 있다.
가운데로 두면 모서리에서 떨어져 떠 보인다.

`flex-start` 로 바꿨다. **Linux 는 그대로 center** —
`.tb-controls.linux` 가 자기 규칙을 갖고 있고, GNOME 은 원형 버튼이 바 중앙에
오는 게 네이티브 모양이다.

## 실측 (Windows 레이아웃 강제)

| 배율 | 바 | 버튼 | 위 여백 | 아래 여백 |
|------|-----|------|--------|----------|
| 1.0 | 32 | 46×32 | **0** | 0 |
| 1.5 | 48 | 46×32 | **0** | 16 |
| 2.0 | 64 | 46×32 | **0** | 32 |

배율과 무관하게 위여백 0 — 상단에 붙고 남는 공간은 전부 아래로 간다.
오른쪽 여백도 92px 로 고정(창 버튼 2개 폭)이라 우측 모서리 기준이 유지된다.

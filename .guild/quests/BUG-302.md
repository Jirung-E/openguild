## 무엇이 잘못됐나

문서가 들어 있는 폴더인데 `openguild library folder list` 와 `/api/library/folders` 에는
**안 나온다.** 앱의 트리에는 보인다.

```
$ openguild library list --json | ... → '등록안된폴더/하위' 에 문서가 있다
$ openguild library folder list      → 그 폴더가 없다
$ curl /api/library/folders          → 역시 없다
```

## 왜

폴더는 두 갈래로 존재한다 — 레지스트리(`folders.toml`, 빈 폴더도 보이게 하려고 만든 것)와
**문서가 적어 둔 경로**. 트리는 둘을 합쳐 그리는데, 목록 API 는 레지스트리만 본다.

[[BUG-293]](옮기기) · [[BUG-300]](지우기)과 같은 계열이다 — 그 둘은 고쳤고 여기만 남았다.

## 왜 중요한가

에이전트·스크립트는 목록으로 폴더를 찾는다. 안 보이면 있는 폴더를 "없다" 고 판단하고,
`folder move` 로 옮길 대상도 찾지 못한다. 화면과 CLI 가 다른 세계를 보는 셈이다.

## 정할 것

- 목록에 합쳐 내되 **어디서 온 것인지**(레지스트리 / 문서 경로) 표시할지.
- 빈 폴더만 레지스트리에 남기는 지금 구조를 유지할지, 아니면 폴더를 만들 때 늘 기록할지.

## 정함 (2026-10-04, admin)

- 폴더를 만들 때마다 목록에 적는다(b).
- 어디서 왔는지 표시(a)는 **하지 않는다**(2026-10-05). 목록이 문서 경로의 폴더를 합쳐 내므로 예전 길드의 폴더도 보이고,
  새 폴더는 늘 적히니 두 종류가 새로 생기지 않는다. 길드를 열 때 한 번에 채워 넣는 것도 하지 않는다 — 필요가 없다.
  남는 차이: 예전 길드의 문서 경로에만 있는 폴더는 안의 문서를 다 옮기면 목록에서 사라진다(새 폴더는 빈 채로 남는다).

## 고침

- **늘 적기**: 문서를 새 폴더에 만들 때, 문서를 새 폴더로 옮길 때, 하위 폴더를 만들 때 — 그 폴더와 위 폴더들 중
  목록(`folders.toml` · 캐시)에 없는 것을 적고 `folder.created` 를 낸다. 목록 잠금(`library-folders`)을 쥐고 한다.
- **예전 길드**: 목록이 문서 경로의 폴더와 등록된 폴더의 위 폴더를 합쳐 낸다 — 트리와 같은 모양, 한 번씩만.
  합쳐 낸 것은 `id` 가 0 이다(목록 파일에는 아직 없다는 뜻).

## 시험

- `every_new_folder_is_registered` — 만들기 · 옮기기 · 하위 폴더 만들기마다 파일과 캐시에 적히고, 겹쳐 적지 않는다.
- `folder_list_includes_folders_only_documents_know` — 목록이 빈 길드에서 문서 경로의 폴더가 위 폴더까지 한 번씩 나온다.
- BUG-293 · BUG-299 시험은 예전 길드를 흉내 내도록(목록 비우기) 고쳐 같은 것을 계속 본다.

## 테스트 방법

1. 앱에서 문서를 새 폴더 경로(예: `시험/하위`)로 만든다.
2. 터미널에서 `openguild library folder list` → `시험`, `시험/하위` 가 나오면 정상.
3. 그 문서를 다른 새 폴더로 옮긴 뒤 다시 목록 → 새 폴더도 나오면 정상. 같은 폴더가 두 번 나오면 안 된다.

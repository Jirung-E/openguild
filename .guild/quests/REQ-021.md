## 왜

admin: *"텔레그램 플러그인 같이 사용자가 초기값을 넣어줘야하는건 해당 플러그인
설명 아래에 입력란이 나오면 좋겠음."*

지금 `telegram-quest-status` 를 허용해도 **안 돈다.** `TELEGRAM_BOT_TOKEN` 과
`TELEGRAM_CHAT_ID` 를 환경변수로 넣어야 하는데, 그걸 화면 어디서도 안 알려주고
넣을 자리도 없다. 데스크톱 앱은 셸에서 뜨지도 않으므로 사용자가
`export` 를 할 데가 없다 — GUI scope 플러그인은 사실상 못 쓴다.

## 무엇이 필요한지는 이미 정의에 있다

새 필드를 만들 필요가 없다. 정의의 `${VAR}` 참조를 훑으면 나온다.

```
url        https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage
body_env   { "chat_id": "TELEGRAM_CHAT_ID" }
headers    Authorization: Bearer ${DISCUSSION_WEBHOOK_TOKEN}
command/args (run)  ${...}
```

`body_env` 는 **값이 곧 변수 이름**이라는 점이 다르다(참조 문법이 아니다).

## 저장 (admin 확정: 기계별 평문 JSON)

`~/.openguild/plugin-secrets.json`, 파일 권한 0600. `${VAR}` 를 풀 때
**이 파일을 먼저 보고, 없으면 프로세스 환경변수**로 떨어진다 — 기존에
`export` 로 쓰던 사람이 안 깨진다.

git 에는 절대 안 올라간다. 길드 파일이 아니라 동의 파일과 같은 자리다 —
"정의는 git 으로 오고 비밀은 기계에 남는다" 는 [[DEV-375]] 의 결정을 그대로
잇는다.

**평문이라는 것을 화면에 밝힌다.** OS 키체인이 더 안전하지만 3개 OS 백엔드와
의존성이 붙고 Linux 는 데스크톱 환경마다 실패 경로가 다르다 — 베타에서는
평문 + 0600 + 명시가 낫다는 admin 판단.

## 할 것

- 정의에서 필요한 변수 이름을 뽑는다(모든 `${VAR}` + `body_env` 의 값).
- 설정 → 플러그인 의 **설명 아래**에 변수마다 입력란. 이미 값이 있으면
  마스킹해 보여주고, 프로세스 환경변수에서 온 값이면 그렇게 표시한다
  (덮어쓸지 사용자가 안다).
- 저장/삭제. 저장은 로컬 데스크톱에서만 — 동의와 같은 이유다(HTTP 로 열면
  남의 기계 비밀을 원격에서 넣는 구멍이 된다).
- 값이 하나라도 비어 있으면 그 플러그인이 **왜 안 도는지** 화면에서 알린다.

## 정할 것

**값은 지문에 안 들어간다.** 지문은 "무엇이 도는가" 이고 값은 "누구로서
도는가" 다. 값을 바꿨다고 동의를 다시 물으면 토큰 교체 때마다 재동의다.

## 테스트 방법

- 정의에서 변수 이름이 정확히 뽑힌다 — url·headers·body_env·command·args
  전부, 그리고 `${A}${B}` 처럼 둘 붙은 것도.
- 저장한 값이 `${VAR}` 해석에 쓰이고, 없으면 프로세스 환경변수로 떨어진다.
- 파일 권한이 0600 이다.
- 값을 바꿔도 동의가 안 풀린다.
- 원격 길드에 접속 중이면 저장이 막힌다.

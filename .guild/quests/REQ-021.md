## 무엇을 만드나

admin: *"gui에서 저런식으로 여러 종류의 입력 방법을 지원할 수 있게 하고,
gui에서 선택된대로 설정파일을 저장하고, 스크립트가 실행될때 그 설정파일을
읽어서 설정값들을 변수로써 사용하게 하라는 말이잖아."*

세 조각이다.

```
① 정의가 "이런 값이 필요하다" 를 선언  →  ② GUI 가 위젯을 그리고 저장
                                              ↓
                              ③ 스크립트·치환이 그 값을 변수로 쓴다
```

## 왜 지금

`telegram-quest-status` 를 허용해도 **안 돈다.** 토큰을 넣을 자리가 없다.
데스크톱 앱은 셸에서 뜨지 않으니 `export` 할 데조차 없다 — GUI scope
플러그인은 사실상 못 쓰는 상태다.

## admin 이 든 예시 — 텔레그램 알림 봇

| 필요한 것 | 위젯 |
|---|---|
| 봇 토큰 | 텍스트(가림) |
| 퀘스트 생성 알림 여부 | 체크박스 |
| 퀘스트 상태 변경 알림 여부 | 체크박스 |
| 댓글 알림 여부 | 체크박스 |
| 전송 주기 (즉시/5분/10분/30분/1시간) | 선택상자 |

**전송 주기만 성격이 다르다.** 나머지 넷은 값을 받아 쓰면 끝인데, 이것은
이벤트를 모아 뒀다 한 번에 보내는 **기계**가 있어야 한다(큐·타이머·여러 이벤트를
한 메시지로 만드는 payload). 게다가 CLI 는 명령이 끝나면 죽으므로 5분 버퍼가
영영 안 비워진다. 그래서 [[REQ-022]] 로 뺀다 — 이 퀘스트는 **입력란과 그 값**
까지다. 선택상자 위젯 자체는 여기서 만든다.

## ① 정의가 선언한다

```json
"inputs": [
  { "key": "BOT_TOKEN",  "label": "봇 토큰",       "type": "text",
    "secret": true, "help": "@BotFather 에서 받습니다." },
  { "key": "CHAT_ID",    "label": "받을 채팅 ID",  "type": "text" },
  { "key": "ON_CREATED", "label": "퀘스트 생성 알림", "type": "checkbox", "default": true },
  { "key": "ON_STATUS",  "label": "상태 변경 알림",   "type": "checkbox", "default": true },
  { "key": "ON_COMMENT", "label": "댓글 알림",       "type": "checkbox", "default": false },
  { "key": "INTERVAL",   "label": "전송 주기",       "type": "select",
    "default": "now",
    "options": [ { "value": "now",  "label": "즉시" },
                 { "value": "5m",   "label": "5분" },
                 { "value": "1h",   "label": "1시간" } ] }
]
```

| 필드 | |
|---|---|
| `key` | 필수. 스크립트와 `${...}` 에서 이 이름으로 쓴다 |
| `label` | 화면에 뜨는 이름. 없으면 `key` |
| `type` | `text` / `checkbox` / `select` / `number`. 기본 `text` |
| `secret` | 화면에서 가린다(`text` 전용) |
| `default` | 사용자가 아직 안 정했을 때의 값 |
| `options` | `select` 전용. `value` 는 실제 값, `label` 은 보이는 말 |
| `help` | 위젯 아래 한 줄 — 토큰을 어디서 받는지 같은 것 |

**이름·설명·선택지는 플러그인 작성자만 안다.** 코어가 변수 이름에서 추측할 수
있는 게 아니라서 정의가 선언한다.

## ② GUI 가 저장한다

설정 → 플러그인 의 **설명 아래**에 위젯을 그린다.

저장 위치는 `~/.openguild/plugin-values.json`, 권한 0600, 원자적 쓰기
([[DEV-385]] 가 동의 파일에서 겪은 그대로). 키는
**`{길드}/{플러그인}/{key}`** — 같은 플러그인이라도 길드마다 다른 값을 쓴다
(알릴 방이 프로젝트마다 다르다).

git 에 안 올라간다. 길드 파일이 아니라 동의 파일 옆이다 — "정의는 git 으로
오고 값은 기계에 남는다"([[DEV-375]]).

**평문임을 화면에 밝힌다.** OS 키체인은 3개 OS 백엔드가 붙고 Linux 는 데스크톱
환경마다 실패 경로가 달라, 베타에서는 평문 + 0600 + 명시가 낫다는 admin 판단.

저장·삭제는 **로컬 데스크톱에서만.** HTTP 로 열면 남의 기계 값을 원격에서
넣는 구멍이 된다(동의와 같은 이유).

## ③ 스크립트가 변수로 쓴다

rhai 에 `config("KEY")` 를 준다. **형이 살아 있다** — 체크박스는 bool,
`number` 는 숫자, 나머지는 문자열. 그래야 이렇게 쓴다:

```rhai
fn should_send(e) {
    if !e.ok { return false; }
    if e.event == "quest.created"        { return config("ON_CREATED"); }
    if e.event == "quest.status_changed" { return config("ON_STATUS"); }
    if e.event == "comment.added"        { return config("ON_COMMENT"); }
    false
}
```

이게 체크박스가 실제로 **동작을 바꾸는** 경로다. 값을 못 읽으면 체크박스는
url 에 박히는 것 말고는 할 일이 없다.

`config` 는 I/O 가 아니다 — 코어가 미리 읽어 넘겨주는 값이라 [[DEV-376]] 의
샌드박스(파일·네트워크 없음)는 그대로다.

**`secret` 값도 스크립트가 읽는다.** 두 층으로 가르는 것을 검토했다가 접었다:
스크립트가 만든 payload 는 어차피 **정의가 적은 그 주소로만** 나가고 사용자는
그 주소에 동의했다. 못 읽게 해도 막는 것이 없으면서 "왜 이 값만 안 읽히지" 를
만든다. `secret` 은 **화면에서 가린다**는 뜻이다.

## 치환도 같은 값을 본다

`${KEY}` 해석 순서는 **저장값 → 프로세스 환경변수**. 이 순서에서 성질 하나가
떨어진다: **진짜 환경변수가 "모든 길드 공통" 자리 노릇을 한다.** 토큰 하나를
여러 길드에서 쓰려면 예전처럼 `export`, 특정 길드만 다르게 하려면 화면에서
덮어쓴다. 층을 새로 만들 필요가 없다.

치환에는 **문자열**로 들어간다 — 체크박스는 `true`/`false`. url·헤더·
`body_env`·`command`·`args` 전부 같은 규칙.

## 정할 것

- **값은 동의 지문에 안 들어간다.** 지문은 "무엇이 도는가", 값은 "누구로서
  도는가" 다. 값을 바꿀 때마다 재동의면 토큰 교체가 지옥이 된다.
- **`inputs` 선언은 지문에 들어간다.** 요구하는 값이 바뀌는 것은 사용자가 다시
  볼 변화다.
- **비밀값 검사를 `inputs` 에도 건다.** `help` 에 예시랍시고 진짜 토큰을 적는
  사고가 제일 흔하다.
- 선언 안 된 `${X}` 참조도 입력란을 만든다(안 그러면 그 플러그인은 못 돈다).
  대신 적재 때 알린다. 선언했는데 안 쓰이는 키도 알린다 — 오타다.

## 할 것

- `PluginDef.inputs` + 검증(개수·길이 상한, `select` 는 `options` 필수,
  `default` 가 `options` 안에 있는지).
- 값 저장소 `plugin-values.json` — 읽기·쓰기·삭제, 0600, 원자적 쓰기.
- `${...}` 해석이 저장소를 먼저 본다.
- rhai `config(key)` — 형을 살려서.
- 설정 화면 위젯 4종 + 저장/되돌리기, 값이 비어 못 도는 플러그인 표시.
- CLI: `openguild plugin set <name> <key>`(값은 stdin — 셸 히스토리에 안 남긴다),
  `plugin unset`, `plugin config <name>`(현재 값, 비밀은 가림).
- 예제 `telegram-quest-status` 를 이 방식으로 다시 쓴다.

## 테스트 방법

- 위젯 4종이 선언대로 그려지고, `secret` 은 값이 DOM 에 안 남는다.
- 저장한 값이 `${...}` 와 `config()` 양쪽에 쓰인다.
- `config()` 의 형 — 체크박스가 bool, `number` 가 숫자로 온다.
- 같은 플러그인이 **길드마다 다른 값**을 갖는다.
- 저장값이 없으면 `default`, 그것도 없으면 프로세스 환경변수.
- 파일 권한 0600, 쓰다 죽어도 예전 값이 남는다.
- 값을 바꿔도 **동의가 안 풀린다.** `inputs` 를 바꾸면 풀린다.
- `help` 에 토큰처럼 보이는 리터럴이 있으면 적재에서 걸린다.
- `select` 의 `default` 가 `options` 에 없으면 적재에서 걸린다.
- 원격 길드에 접속 중이면 저장이 막힌다.

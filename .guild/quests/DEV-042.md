`quest_history.{old_value,new_value}` 가 status_id 숫자라서 status 추가 /
순서 변경 시 옛 history 가 다른 status 를 가리킴. **stable identifier 인
slug 로 저장하도록 변경** + 기존 데이터 마이그레이션.

## 원인

- `quest_statuses.id` 는 파일 정렬 순으로 결정되는 positional identifier.
- `quest_history.{old_value,new_value}` 는 변경 당시의 numeric id 문자열.
- 사용자가 status 를 추가/삭제/순서 변경하면 id 가 재배치되면서 옛
  history 가 다른 status 를 가리킴.

`quests.status_id` 는 reindex 가 .md 의 slug 로 매핑하므로 안전했지만,
quest_history 는 reindex 가 건드리지 않아서 깨질 위험이 컸음.

## 설계 (옵션 A 채택)

| 옵션 | 형식 | 안정성 | 선택 |
|---|---|---|---|
| A. slug | `"cancelled"` | ★★★★ | ✓ |
| B. UUID | `"550e8400..."` | ★★★★★ — 큰 schema 변경 | |
| C. name | `"Cancelled"` | ★★★ — rename 시 외부 무효 | |
| D. snapshot JSON | `{"slug":"...","name_en":"...","id":N}` | ★★★★★ — 형식 무겁 | |

slug 는 이미 `.md` frontmatter (`status = "open"`) 와 파일명 prefix
(`1-open.toml`) 에서 자연스러운 식별자로 사용 중 — 일관성 ↑.

## 구현 (2026-05-22)

### Schema
- `quest_statuses.slug TEXT` 추가 (nullable; reindex 가 채움).
- Migration `0006_status_slug_in_history.sql`:
  1. `ALTER TABLE quest_statuses ADD COLUMN slug TEXT`.
  2. `UPDATE ... SET slug = LOWER(REPLACE(REPLACE(name_en, ' ', '_'), '-', '_'))
     WHERE slug IS NULL` — name_en 에서 파생 (어떤 id 매핑이든 안전).
  3. `UPDATE quest_history SET old_value/new_value = (SELECT slug FROM ...)`
     WHERE op='change_status' AND value GLOB '[0-9]*' — 숫자 형태만 변환
     (idempotent — slug 형식은 skip).

### Reindex
- `quest_statuses` INSERT 시 slug 컬럼도 함께 INSERT (파일명에서 추출).

### change_status
- `core::ops::quests::change_status`:
  - 변경 전 status 의 slug 를 `quests JOIN quest_statuses` 로 미리 조회.
  - 변경 후 status 의 slug 도 조회.
  - `INSERT INTO quest_history (..., old_value, new_value)` 에 slug bind.

### Model / API
- `core::models::QuestStatus` 에 `pub slug: String` 추가.
- `/api/quest-statuses` 응답에 자동 포함 (sqlx::FromRow + serde).
- frontend `QuestStatus` 타입에 `slug: string` 추가.

### CLI 표시 변경
- `quest history <slug>` 출력이 숫자 → name_en 으로:
  - 이전: `change_status  3 → 4`
  - 현재: `change_status  Testing → Done` (각 status name 에 status.color
    ANSI 24-bit truecolor 적용 — 기존 `colorize()` 재사용).
- 비-TTY / `NO_COLOR` 시 평문 폴백 (기존 정책 동일).
- 숫자가 들어오면 (legacy DEV-042 이전 행) `Testing (legacy id)` 표시 →
  fallback (color 적용).
- 라이브: `openguild quest history DEV-028` → `change_status  Testing → In Progress`
  (TTY 에선 각 status 의 색 입혀짐).

### Frontend (QuestHistory.svelte)
- `statusBySlug` 추가. slug → name_en 으로 표시.
- legacy 숫자 들어오면 `Open (legacy)` 표시 (id 매핑 fallback).
- 양쪽 호환 — 미마이그레이션 데이터도 안전 표시.

### AGENTS.md 갱신
- "status / type slug 는 stable identifier" 절 추가. 정책 명시:
  - 추가 / 순서 변경 안전.
  - slug rename 은 위험 — quest_history 와 .md 동시 갱신 필요.

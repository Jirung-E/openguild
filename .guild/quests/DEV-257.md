# 모바일 UI

모바일 UI 도입 — 현재 GUI(Svelte 5 + SvelteKit, Tauri v2 데스크탑 셸)를
모바일 화면/입력(터치)에 맞춰 쓸 수 있게.

## 범위 결정 (2026-07-19, 사용자 확인)

**1차: 반응형 웹부터** — 같은 코드베이스에 CSS breakpoint 기반 반응형
레이아웃. 원격 서버를 폰 브라우저로 쓰는 경우를 우선 커버. Tauri
모바일(iOS/Android) 네이티브 빌드는 후속 별도 퀘스트로.

## 1차 구현 (2026-07-19)

375px(iPhone 급) 뷰포트에서 전 페이지를 실기 스캔(가로 오버플로 요소
전수 측정)한 결과, 대부분의 페이지는 기존 작업(BUG-039 overflow-wrap,
BUG-143 좁은 폭 wrap 정리, DEV-260 메뉴바 overflow 메뉴) 덕에 이미
깨지지 않았고, 실제 문제 3건만 발견·수정:

1. **홈 — 작업기록 카드 `.today` 줄** 이 화면 밖으로 밀림 → flex-wrap.
2. **작업기록 페이지 `.controls`**(단위 토글+기간 이동, 426px)가 페이지
   가로 스크롤 유발 → flex-wrap.
3. **검색 팔레트 폭** `min(560px, 62vw)` 가 모바일에선 232px 로 너무
   좁음 → `@media (max-width: 640px)` 에서 `calc(100vw - 16px)`.

스캔에서 정상 확인된 페이지: 홈/리스트/퀘스트 상세/캠페인 목록·상세/
규칙/도서관/작업기록/관리(넓은 표는 자체 스크롤 컨테이너)/태그/보드
(레인 내부 스크롤). viewport meta 는 이미 있음.

## 후속 범위 (이 퀘스트에 남김 — 재오픈 또는 서브퀘스트)

- 터치 인터랙션 전환: 보드 드래그/grid snap, SearchPalette 미리보기
  세로 리사이즈 핸들, 크로스링크 호버 미리보기(DEV-256 — 터치에선 탭 시
  즉시 이동으로 폴백 중) 등 마우스 전용 UI 목록화·전환.
- Tauri 모바일(iOS/Android) 빌드 파이프라인.
- `open-item.ts` OpenMode 'mobile' 확장.

## 테스트 방법

1. (실기 확인 완료) vite dev + server 를 375×812 로 열어 위 페이지 전부
   가로 스크롤 0 확인, 팔레트 폭 359px 확인.
2. `npx svelte-check` / `npm run test`(281) / `npm run build` 클린.
3. (사용자 확인) 실제 폰 브라우저(또는 데스크탑 브라우저 반응형 모드)로
   원격 서버 접속해 홈/리스트/상세/작업기록/검색 팔레트 사용감 확인.

## Test plan (2차 — 좌측 탭 페이지)

폰 브라우저(또는 데스크탑 브라우저를 375px 폭으로) 에서:

1. **도서관** — 폴더/문서 목록이 위, 문서 내용이 아래로 쌓이는지. 목록이
   길어도 자체 스크롤(화면 높이의 45%)로 제한돼 내용이 화면 밖으로 안
   밀리는지. **좌우 스크롤이 생기지 않고 메뉴바가 잘리지 않는지.**
2. **규칙** — 위와 동일(목록 40%).
3. **설정** — 탭('정보'/'표시'/'편집기' 등)이 위쪽 가로 한 줄로 뜨는지, 탭이
   많아 넘치면 그 줄만 좌우로 스크롤되는지(페이지 전체가 아니라).
4. 640px 이상(태블릿/데스크탑)에서는 기존 좌우 2열 그대로인지 — 회귀 확인.
5. 세로/가로 회전 시 전환이 자연스러운지.

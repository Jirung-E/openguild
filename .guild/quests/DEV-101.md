사용자: "ui 크기를 조절할 수 있으면 좋을거같다".

## 설계

### 옵션 A — CSS root font-size scale
Settings 페이지 또는 Nav 우상단 (⚙ 옆) 에 슬라이더 / +/- 버튼:
- `document.documentElement.style.fontSize = "${px}px"` (default 16px → 12~24).
- `rem` 기반 layout 이므로 전체 UI 가 비례 확대/축소.
- localStorage 영속 — 사용자별 (key: `openguild.uiScale`).

장점: 가장 단순. 거의 모든 컴포넌트에 자동 적용.
단점: `px` 직접 쓴 곳 (예: QuestBoard 의 cy node 크기) 는 따로 처리 필요.

### 옵션 B — CSS zoom 또는 transform: scale
- `document.body.style.zoom = scale` (Chromium 만 — Tauri webview 는 Chromium
  계열).
- 또는 `transform: scale(...)` (블러리 가능, hit-test 어긋날 수 있음).

장점: rem 안 쓴 px 값도 자동 확대.
단점: zoom 비표준 (Firefox X), transform 은 hit-test 부작용.

### 옵션 C — Tauri webview zoom
- `window.setZoom(level)` (Tauri 2).
- OS / Tauri 레벨에서 처리 — 전 페이지 일괄.

장점: 가장 정합. dev tools 의 zoom 처럼 동작.
단점: Tauri-only (HTTP 모드 안 됨), 영속화 별도.

### 권장
**A + C 혼합**:
- Tauri 환경 → C (`setZoom`).
- HTTP 환경 → A (root font-size).
- 같은 UX prop (Settings 의 슬라이더) → 환경 감지해서 적용.

## UI 위치

- **Settings 페이지** 의 "표시" 섹션 (없으면 신설):
  - 슬라이더 50%~200% (10% 단위) + reset 버튼.
  - 미리보기 — 슬라이더 옆 sample text.
- 또는 **Nav 우상단** 의 ⚙ 옆 +/- 버튼 (즉시 변경 — 작업 흐름 안 끊김).

## 구현 후보

### Frontend
- `lib/stores/uiScale.ts` — writable<number> + localStorage persist.
- `routes/+layout.svelte` 의 onMount 에 store subscribe → `document.
  documentElement.style.fontSize` (또는 `setZoom`) 적용.
- `routes/settings/+page.svelte` 에 슬라이더.

### 검증
- 50% / 100% / 150% / 200% 에서 layout 깨짐 확인 (특히 QuestBoard / Home).
- Tauri 환경 vs HTTP 환경 둘 다 적용.
- 재시작 후 영속 확인.
- BUG-016 의 `help_output_has_no_quest_id_leaks` 통과.

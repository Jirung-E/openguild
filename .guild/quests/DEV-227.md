DEV-209 는 "types/statuses/rules 복수형 유지, 리네임 안 함"으로 결정했었으나,
사용자가 재검토 후 단수로 통일하는 게 낫겠다고 판단 — 결정 번복.

## 방침
다른 top-level 명사 그룹(quest/campaign/template/backup/check/index/
journal)과 동일하게 단수형을 canonical 이름으로 하되, 기존 사용자
스크립트/습관 호환을 위해 복수형은 clap alias 로 유지 (rules 의
create/new alias 와 같은 패턴).

- `openguild type`   (alias: types)
- `openguild status` (alias: statuses)
- `openguild rule`   (alias: rules)

## 범위
- cli/src/main.rs: Command::Types/Statuses/Rules 에 #[command(name=...,
  alias=...)] 추가.
- docs/AGENTS_OPENGUILD_USAGE.md, docs/USAGE.md 의 예시 명령을 단수형
  canonical 로 갱신(복수형 alias 언급 추가).
- 길드 규칙 cli-command-naming 갱신 — "과거 결정으로 유지되는 예외"
  문구를 "단수로 통일됨, 복수형은 alias" 로 정정.
- 기존 테스트는 "types"/"statuses" 리터럴을 그대로 써도 alias 로 통과
  하지만, 신규 단수형 파싱 테스트도 추가.

## 추가 수정 (2026-07-05, 사용자 지적)
처음 구현은 `sub: Option<TypesCmd>`/`Option<StatusesCmd>` 를 유지해
bare `openguild type`(서브커맨드 없이) 가 여전히 조용히 list 로 떨어졌음
(DEV-062 부터의 관행) — 그런데 quest/campaign/template/backup/check/
index/journal/rule 은 전부 sub 가 **필수**라 bare 호출이 에러난다.
"단수형으로 통일했으면 다른 그룹처럼 `list` 를 명시해야 하는 거
아니냐"는 지적을 받아 TypesCmd/StatusesCmd 도 sub 를 필수로 변경 —
`type list` / `status list` 명시 필요, bare 호출은 이제 에러.

## 테스트 방법
- `openguild type` (서브커맨드 없이) → 에러 (다른 그룹과 일관).
- `openguild type list` / `openguild types list` 둘 다 목록 출력.
- `openguild status list` / `openguild statuses list` 둘 다 목록 출력.
- `openguild rule list` / `openguild rules list` 둘 다 동일 출력.
- `cargo test -p openguild-cli` 통과 (기존 + 신규 파싱 테스트).

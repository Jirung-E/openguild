admin 보고: 보드에서 테마 변경시 노드들은 테마 변경이 안됨.

## 원인
`theme` 스토어는 사용자가 고른 선택(`'dark' | 'light' | 'system'`)을 담는데,
'system' 모드에서 OS 가 실제 테마를 바꿔도 `theme` 스토어 **값 자체**는
여전히 'system' 그대로다. Svelte writable 은 `set()` 시 새 값이 이전 값과
같으면(safe_not_equal 실패) 구독자에게 전혀 통지하지 않는다.

`<html data-theme>`(CSS variable) 쪽은 +layout.svelte 가 `watchSystemPreference`
로 OS 변경을 별도 감지해 `applyThemeToDocument('system')` 을 직접 호출하므로
문제없이 갱신됐지만, Cytoscape/SVG data URL 처럼 CSS `var()` 를 못 쓰고 JS 가
색을 직접 계산해야 하는 곳들(`QuestBoard.svelte`, `QuestNodeConveyor.svelte`,
`MarkdownView.svelte` 의 mermaid)은 전부 `theme` 스토어를 직접 구독/파생하고
있어서, 이 신호를 못 받아 OS 테마 전환 시 갱신되지 않았다.

## 수정
- `lib/stores/theme.ts`: 실제 렌더에 쓰이는 `effectiveTheme`('dark'|'light')
  전용 스토어 신설. `theme` 변경 시 + (`theme==='system'`일 때) OS
  preference 변경 시 둘 다 반영해 `effectiveTheme.set()` — 실제로 값이
  바뀔 때만 set 되므로 safe_not_equal 을 자연히 통과해 구독자에게 통지된다.
- `QuestBoard.svelte`: 노드 재생성 트리거를 `theme.subscribe` → `effectiveTheme.subscribe` 로 변경.
- `QuestNodeConveyor.svelte`: `$derived(resolveTheme($theme))` → `$derived($effectiveTheme)`.
- `MarkdownView.svelte`: mermaid 렌더 테마 계산 + 재렌더 트리거 `$theme` → `$effectiveTheme`.

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`
  (프론트만 변경, Rust 쪽 변경 없음).
- 실기: 설정에서 테마를 "시스템 설정 따르기"로 두고 OS(Windows) 다크/라이트
  모드를 전환 → Quest Board 노드 배경색, Home 화면 conveyor 카드, 규칙/퀘스트
  본문의 mermaid 다이어그램이 즉시 따라 바뀌는지 확인. 명시적으로 다크/라이트
  선택 시에는 기존처럼(회귀 없이) 즉시 반영되는지도 확인.

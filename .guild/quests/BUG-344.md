**윈도우 앱에서 저장 · 댓글이 몇 초씩 "저장 중" 으로 멈춘다 — 자동 백업이 파일을 읽는 동안 길드를 잠가서**
(2026-10-01, admin 이 윈도우에서 겪음 — 최신 develop 앱, 짧은 퀘스트도. 윈도우 세션이 측정).

- BUG-340 이 백업을 두 단계로 바꾸며 **파일 내용 읽기를 길드 독점 잠금 안**에 넣었다. 맥에서는 이 읽기가 0.02초라
  문제가 안 됐다.
- 윈도우에서는 처음 읽기가 **약 6초**다(이 길드 1,877개 파일 · 3.1MB, Defender 실시간 검사 — 파일마다 검사).
  두 번째부터 0.36초.
- 앱을 열고 첫 저장 → 자동 백업이 뜬다(24시간 지났으면) → 백업이 6초 동안 길드를 독점 → 그동안의 저장 · 댓글이
  전부 기다린다. 예전(잠금 없는 백업)에는 뒤에서 돌아 아무도 안 기다렸다.
- 측정(윈도우, 한 프로세스): 평소 저장 33ms, 자동 백업 끄면 스파이크 사라짐.

## 고칠 것

- 내용 읽기는 **잠그지 않고** 하고, 파일마다 크기 · 수정 시각을 적어 둔다. 그다음 **잠깐** 잠그고 목록과 크기 · 시각만
  다시 본다(파일을 열지 않는다) — 바뀐 것 · 새것만 다시 읽고, 없어진 것은 뺀다. 결과는 잠근 순간의 모습 그대로다.
- journal 위치도 그 잠금 안에서 적는다(BUG-340 의 "읽은 뒤 변경은 journal 에 남는다" 유지).

## 시험

- 읽기와 확인 사이에 고친 파일 · 새 파일 · 지운 파일이 결과에 맞게 들어간다.
- BUG-340 시험(잠금 중 쓰다 만 파일을 찍지 않는다)이 그대로 통과한다.
- 윈도우에서 잠금을 쥐는 시간을 다시 잰다.

## 고침 (2026-10-02)

- 내용은 잠그지 않고 먼저 읽는다(`prefetch_guild_source`, 작업 스레드를 안 붙잡게 `spawn_blocking`) — 파일마다
  크기 · 수정 시각을 함께 적는다.
- 잠근 뒤에는 목록과 크기 · 시각만 다시 보고(`read_guild_for_backup_from`), 같으면 미리 읽은 내용을, 다르거나 새것이면
  지금 읽는다. 없어진 파일은 목록에 없으니 빠진다. journal 위치도 이 잠금 안에서 적는다.
- `collect_guild_source_files` → `walk_guild_source`(콜백) 로 바꿔 두 단계가 같은 순회를 쓴다.

## 시험

- 맥: 읽기와 확인 사이에 고친 것 · 새것 · 지운 것이 맞게 들어간다. BUG-340 시험(잠금 중 쓰다 만 파일을 찍지
  않는다, 읽은 뒤 변경은 journal 에 남는다) 그대로 통과. `just test` 통과.
- 윈도우(윈도우 세션, 실제 앱처럼 멀티스레드 · 식은 캐시 · 1,863개 파일): 백업 도는 동안 저장 지연 최대

  | | 잠금 개편 전 | develop(BUG-340) | 고친 것 |
  |---|---|---|---|
  | 길드 독점을 쥔 시간 | 0 (잠금 없음) | 5,783ms | 219ms |
  | 저장 지연 최대 | 66ms | 5,784ms | 188ms |

  백업 전체는 6.4초로 조금 늘었지만 뒤에서 돌아 체감은 없다.

## 테스트 방법

1. 윈도우에서 새로 빌드한 앱으로 길드를 열고, 퀘스트 본문을 고쳐 저장한다.
2. 곧바로 다른 퀘스트에 댓글을 단다.
- 이러면 정상: 저장 버튼이 몇 초씩 "저장 중" 으로 멈추지 않는다.

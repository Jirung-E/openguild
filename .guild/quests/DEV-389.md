## 왜

`run` 은 단위 시험과 임시 길드에서만 돌려 봤다. admin 이 실환경 확인이 가능한지
물었고, 셋 중 둘이 가능했다:

| | |
|---|---|
| 서버 scope `run` — HTTP mutation 에서 | 가능. **한 번도 안 해본 경로** |
| 배포하는 `desktop-notify/notify.sh` 실제 실행 | 가능. **실행된 적 없는 예제** |
| GUI scope `run` — 데스크톱 앱에서 | 불가. 앱 교체가 필요하고 허락 없이 안 한다 |

## 확인한 것

**서버 경로.** 임시 길드 + 전용 `OPENGUILD_HOME` 으로 서버를 띄우고 `POST
/api/quests` 와 `PATCH .../status` 를 쳤다. 시동 로그에 `plugin : 1 active —
server-hook` 이 뜨고, 진짜 파이썬 프로그램이 stdin 으로 이벤트를 받아 두 건을
기록했다. CLI 가 아닌 경로에서 `run` 이 도는 것을 처음 확인했다.

**`notify.sh`.** 배포하면서 한 번도 실행해 본 적이 없었다. scope 만 cli 로 바꿔
실제 CLI 경로로 태웠고 exit 0, `osascript` 도 정상. 흔적을 남기게 고쳐 재실행해
**진짜 이벤트 JSON 을 받았다**는 것까지 봤다.

## 찾은 결함 — 이벤트의 `guild` 가 디렉터리명이었다

훅이 받은 것: `"guild": "g"`. 그런데 그 길드의 이름은 **`runlab`** 이다
(`openguild init --name runlab` 을 `/tmp/runlab/g` 에서 했다).

`guild_label()` 이 `guild_root.file_name()` 을 썼다 — "마커 파일을 매번 읽지
않으려고" 였고, 주석은 "더 정확한 이름이 필요하면 길드를 직접 읽으면 된다" 고
적어 뒀다. 그런데 **읽을 수가 없다**: rhai 에는 I/O 가 없고 `post` 대상은 파일에
손이 닿지 않는다. `run` 만 겨우 가능하다.

화면 어디에도 없는 이름이 플러그인에게만 간다. 텔레그램 알림이 "어느
프로젝트인가" 를 이 값으로 말한다.

## 테스트 방법

- 디렉터리명과 길드 이름이 **다른** 길드를 만들고 이벤트의 `guild` 를 본다.
  같으면 시험이 아무것도 안 보는 것과 같다.

## 결과

**고쳤다.** 길드 이름을 열 때 한 번 읽어 `Store::guild_name` 으로 들고 있는다.
`recents::guess_name` 을 쓰므로 GUI 의 `current_guild_name` · CLI 의
`guild list` 와 **같은 규칙**이다 — 사용자가 보는 이름과 이벤트가 어긋나지
않는다. 매 이벤트마다 읽던 것도 아니고 열 때 한 번이라 비용도 없다.

실환경에서 다시 확인: 훅이 받은 값이 `runlab` 으로 바뀌었다.

되돌림 시험 1건: 다시 디렉터리명으로 돌리면 시험이 문다. 시험은 디렉터리명과
길드 이름을 **일부러 다르게** 만든다 — 같으면 아무것도 안 보는 것과 같다.

## GUI scope 는 여전히 미확인

앱 교체가 필요해 안 했다. 다만 CLI·서버 두 경로가 같은 `Outbound::run` 을
지나므로, GUI 만 다르게 동작할 여지는 배선(`install_plugins_for_gui`)뿐이고
그건 [[DEV-379]] 의 단위 시험이 덮는다.

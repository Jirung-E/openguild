사용자 보고(DEV-022 테스트 중): restore 이후 statuses 목록이 바뀜 — 기존엔 testing 이 없었는데 restore 후 생김.

## 원인 (스크래치 길드 재현으로 확정, 2026-07-03)

**restore 는 무죄 — init 이 만든 첫날부터의 파일↔DB drift 를 restore 의 reindex 가 뒤늦게 고친 것.**

- `openguild init` = 마커 + 파일 시드만 수행 (statuses 파일 7개: testing/returned 포함). Store/DB 는 안 건드림.
- 이후 첫 `Store::open` 의 migration 0001 이 **구식 기본 statuses 5개**(testing/returned 없음)를 fresh index.db 에 INSERT.
- `statuses` 명령은 DB 를 읽음 → 파일은 7개인데 목록은 5개 (drift). CLI 는 plain Store::open 이라 자동 보정 없음.
- restore → reindex → DB 가 파일 기준으로 재구축 → 7개 표시 = 'restore 가 statuses 를 바꿨다' 로 보인 증상.
- GUI 는 init_and_open_guild 가 sync_on_open(BUG-049/DEV-121)을 해서 이 구멍이 없음 — CLI init 만 문제.

## 수정

`cli/src/main.rs` init_guild_at: 시드 직후 Store::open + reindex 실행 — index.db 를 파일 기준으로 즉시 재구축해 첫날부터 정합. (migration 0001 자체는 sqlx 체크섬 때문에 수정 불가 — 기존 길드 전부 깨짐.)

회귀 테스트 추가: `init_syncs_index_db_statuses_with_seed_files` — init 직후 DB quest_statuses 수 == 파일 시드 수(default_statuses).

**기존에 CLI init 으로 만든 길드**는 이미 drift 상태일 수 있음 — `openguild reindex` 1회로 치유(또는 GUI 로 한 번 열기 / restore 시점에 자동 치유).

## 테스트 방법

- `cargo test -p openguild-cli` — 신규 회귀 테스트 포함 통과.
- 수동: 빈 폴더에서 `openguild init` → `openguild statuses` 가 **처음부터 7개**(Testing/Returned 포함) 표시. `backup new` → `restore` 후에도 목록 동일(변화 없음 = 증상 소멸).

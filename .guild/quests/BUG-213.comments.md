수정 — `OverlayScrollbar.svelte`:

1. **`input` 이벤트로 재측정.** textarea/input 의 값 변경은 자식 노드 변경이
   아니라서 MutationObserver 에 안 잡힌다. target 에 `input` 리스너를 걸어
   재측정한다(버블링되므로 컨테이너 target 에도 유효).
2. **`onScroll` 이 항상 `measure()`.** 예전엔 `scrollTop` 만 갱신해서, 한 번
   잘못 잰 `contentH` 가 스크롤 중에도 복구되지 않았다. rect 1회 읽기라 저렴.

## 검증 (실측)

브라우저 pane 이 숨겨져 있으면 `scheduleRemeasure` 의 rAF 가 발화하지 않아
측정이 왜곡된다(BUG-212 에서 얻은 교훈). rAF 를 setTimeout 으로 갈아끼운 뒤
측정:

| 상태 | scrollHeight / clientHeight | 이 textarea 소유 thumb |
|---|---|---|
| 빈 입력 | 78 / 78 | **0개** (정상 — 스크롤 불필요) |
| 60줄 입력 | 1282 / 78 | **1개** (h=32px) |

- 스크롤 시 `visible` 클래스가 붙고 1.2초 후 자동으로 사라진다.
- thumb 좌표가 textarea 박스 안에 들어온다(rect top 1939~2019, thumb top 1955).

수정 전에는 마운트 시점(빈 입력)의 `contentH == clientHeight` 가 그대로 남아
`needed` 가 계속 false → thumb 자체가 렌더되지 않았고, native 스크롤바는
`.body-input` 에서 CSS 로 숨겨져 있어(BUG-157) 아무 표시도 없었다.

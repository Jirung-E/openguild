## 증상

`just test` 가 통과했는데 CI 가 실패했다.

```
Command list: Argument or group 'json' specified in 'conflicts_with*' for 'table'
does not exist
```

## 원인 두 겹

### 1. REQ-005 의 clap 변경이 애초에 틀렸다

`--table` 에 `conflicts_with = "json"` 을 달았는데, `json` 은 **전역 인자**라
서브커맨드 스코프에서 clap 이 못 찾는다. clap 은 이걸 **debug assertion** 으로
잡는다.

이 자리에는 원래 정확히 그 내용의 주석이 있었다:

> "`json` 은 전역 인자라 clap 의 conflicts_with 대상이 못 됨(debug assert 가
> subcommand 스코프에서 못 찾음) — 핸들러에서 수동 검증."

**나는 그 주석을 "오래된 정보" 라고 단정하고 지웠다.** 근거는 로컬 실측
(`openguild rule list --table --json` 이 정상 거부)이었는데, 그게 바로 아래 2번
때문에 성립하지 않는 검증이었다.

### 2. `just test` 가 CI 와 두 군데 어긋나 있었다

| | justfile | check.yml |
|---|---|---|
| rust 테스트 | `cargo test --workspace **--release**` | `cargo test --workspace` (debug) |
| frontend | check / no-hex / vitest | check / no-hex / **no-emoji** / vitest |

릴리즈 빌드는 `debug_assertions` 가 꺼져 **clap 의 인자 정의 검증이 통째로
사라진다.** 그래서 로컬은 조용히 통과하고 CI(debug)에서만 터졌다.
`check:no-emoji`(BUG-169 재발 방지)는 그냥 빠져 있었다.

justfile 주석은 "check.yml 과 동일 게이트" 라고 적혀 있었지만 실제로는
아니었다.

## 수정

**clap 되돌리고 수동 검사로 통일.** `ensure_table_json_exclusive(table, json)`
헬퍼를 만들어 `--table` 을 가진 **8개 명령 전부**에 걸었다. 지운 주석도
되살려 이유를 남겼다.

그 과정에서 `quest deleted` 가 **세 번째 동작**을 하고 있던 것을 발견했다 —
에러도 무시도 아니고 `table && !json` 이라 조용히 json 을 우선했다.

**justfile 을 CI 에 맞췄다.** `--release` → debug, `check:no-emoji` 추가.

디스크 근거는 역전돼 있었다 — `target/debug` 39G(개발 중 이미 존재) vs
`target/release` 4.1G(테스트 전용 추가분). debug 로 맞추면 오히려 4.1G 를
아낀다.

## 검증

**8개 명령 전수 실측** — quest list / quest deleted / rule / status / campaign /
library / type / tag, 전부 같은 에러. 단독 사용(`--table` 만, `--json` 만)은
회귀 없음.

**게이트가 실제로 잡는지**: 버그를 한 곳에 다시 심고 비교했다.

| | 종료코드 |
|---|---------|
| 새 게이트(debug) | **101** — `Command deleted: ... does not exist` |
| 예전 게이트(`--release`) | **0** (조용히 통과) |

`just test` 종료코드 0.

## 남는 교훈

"주석이 틀렸다" 고 판단할 때, **그 주석이 경고하는 조건에서 검증했는지**를
먼저 확인해야 한다. 이번엔 debug assert 를 없애는 빌드로 debug assert 의
존재를 부정했다.

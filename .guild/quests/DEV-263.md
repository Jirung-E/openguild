사용자 보고: docs 에 있는 문서가 퀘스트 번호를 언급하는데, 이 문서가
`openguild docs` 로 출력되면 문제가 될 수 있다.

## 배경

- BUG-016/DEV-248: `--help` 출력에 이 repo 의 퀘스트 ID(DEV-NNN 등)가 새면
  다른 길드에서 CLI 를 쓰는 에이전트가 그 ID 를 자기 길드의 퀘스트로
  오인함 — clap doc 주석에 ID 금지 + help-leak 회귀 테스트로 차단됨.
- 그런데 `openguild docs <name>` 는 리포의 md 문서를 컴파일 타임 embed 해
  그대로 stdout 출력(DEV-248) — 같은 누출 경로가 문서 본문에 열려 있음.

## 조사 결과 (2026-07-17, 퀘스트 ID 언급 줄 수)

- docs/AGENTS_OPENGUILD_USAGE.md: 34줄 (docs agents 로 출력)
- docs/USAGE.md: 8줄 (docs usage)
- README.md: 16줄 (docs readme)
- CHANGELOG.md: 50줄 (docs changelog)

## 방향 (착수 시 결정)

- CHANGELOG 는 성격상 퀘스트 ID 가 본문의 핵심 — 제거 불가. 선택지:
  (a) docs 출력에서 changelog 제외, (b) 출력 시 ID 마스킹/치환,
  (c) CHANGELOG 는 예외로 두고 나머지 3개 문서만 ID-free 로 재작성.
- AGENTS_OPENGUILD_USAGE.md 가 가장 중요(에이전트가 직접 읽는 문서) —
  "예: DEV-001" 식 예시는 가상의 접두(EX-001 등)나 플레이스홀더로 교체.
- 회귀 방지: help-leak 테스트와 동일한 find_quest_id 스캔을 embed 문서에도
  적용하는 테스트 추가(예외 문서 allow-list 지원).

## 진행 내역

DEV-264 작업으로 docs/AGENTS_OPENGUILD_USAGE.md 자체가 이미 삭제돼(34줄
누출의 대부분을 차지하던 문서), 남은 범위는 USAGE.md/README.md/
CHANGELOG.md 였습니다.

- USAGE.md/README.md 재조사 결과, 실제 "이 repo 고유 서사" 인용은
  README의 "복구" 절 제목에 붙어있던 `(BUG-041)` 하나뿐이었고 제거했습니다.
  나머지(DEV-001/BUG-003/BUG-045/C-001)는 전부 "어떤 길드든 그 길드의
  첫 quest/campaign은 실제로 이 번호가 된다"는 범용 예시라 leak이 아니라고
  판단해 유지했습니다.
- CHANGELOG.md는 방향 (c) 채택 — 성격상 quest ID 인용이 본문 핵심(여느
  오픈소스 프로젝트 CHANGELOG의 이슈/PR 번호 표기 관례와 동일)이라 그대로
  둡니다.
- 회귀 방지 테스트 추가: `embedded_docs_have_no_quest_id_leaks` — USAGE.md/
  README.md에 등장하는 quest-ID 형식 문자열을 스캔해 allowlist
  (DEV-001/BUG-003/BUG-045/C-001) 밖의 새 ID가 나타나면 테스트 실패.

## 테스트 방법

- `cargo test -p openguild-cli embedded_docs_have_no_quest_id_leaks` 통과.
- `cargo test -p openguild-cli` 전체(102 tests) 통과.
- `cargo clippy -p openguild-cli --all-targets -- -D warnings` 통과.
- `grep -noE "DEV-[0-9]+|BUG-[0-9]+|REQ-[0-9]+|C-[0-9]+" README.md docs/USAGE.md`
  결과가 allowlist 4개 값뿐인지 육안 확인.

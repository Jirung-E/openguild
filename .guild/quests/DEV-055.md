퀘스트 종류(BUG-DEV 등..)를 바꾸는 기능 필요.

종류를 바꾸면 퀘스트 식별자가 바뀔텐데, 다음과 같은 문제가 있다.
- 연관관계에 있는 퀘스트들에 적혀있는 식별자도 변경해줘야한다.
- 이후 캠페인 기능이 추가되면 캠페인에도 위와같은 작업을 해줘야한다.

어떻게 해결할지?
1. 위 문제를 신경쓰면서 구현한다.
    - 구현방법은 2가지:
        1. 기존 퀘스트의 식별자 변경
        2. 기존 퀘스트 내용을 가지고 새로운 퀘스트 생성 후 기존 퀘스트 삭제
2. 별도 관리 번호를 사용한다.
    - 별도 부가정보가 늘어나는셈.
    - 바꿀곳이 많을거같다.

## 구현 (2026-05-24)

3 phase 분할 커밋.

### Phase 1 — core (commit 1)
- Models: `ChangeTypeRequest { new_type_prefix }`.
- `services::quests::change_type` → `(QuestRow, old_slug, new_slug)`.
  같은 type 이면 NoOp. transaction:
  - counter self-heal (BUG-counter-self-heal 패턴).
  - target type counter +1 → new number.
  - quests UPDATE: quest_type_id, number, updated_at.
  - quest_history.quest_slug cascade (DEV-049).
  - quest_positions.quest_slug cascade.
- `ops::quests::change_quest_type`:
  - journal + sql + history INSERT (op='change_type').
  - 파일: <new_slug>.md 새로 쓰고 <old_slug>.md 삭제.
  - 관련 quest (parent / sub / prereq / dependent) 파일들 auto-block
    재생성 — 본인 mention 새 slug 반영.
- 테스트 +4 (core 158 → 162): rename + history cascade / NoOp /
  unknown type 거부 / related files 갱신.

### Phase 2 — Tauri + frontend API (commit 2)
- gui/src/commands.rs: `change_quest_type` Tauri command.
- transport.ts: `PATCH /api/quests/<id>/type` 매핑 + transport.test +1.
- quests.ts: `changeType(id, body)`.
- types/index.ts: `ChangeTypeRequest` interface.

### Phase 3 — Quest Detail UI (commit 2 합침)
- routes/quests/[id]/+page.svelte:
  - 기존 `_types` placeholder → 실제 사용 (`types`).
  - "타입 변경" row — 상태 변경과 동일 디자인. type prefix 버튼들.
    현재 type 은 active + disabled.
  - 클릭 → confirm 모달: 현재 slug → 새 type 안내 + 본문 mention 사용자
    책임 안내 + 변경 / 취소.
  - 변경 성공 → `goto('/quests/<new_slug>', { replaceState: true })`.

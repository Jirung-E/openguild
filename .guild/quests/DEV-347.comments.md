## 1. 기본 출력을 요약으로, 전체는 `--full`

```
$ openguild quest show DEV-002
DEV-002  데이터베이스 스키마 변경
  status   : Open (게시됨)
  urgency  : 3
  relations: parent REQ-002
```

관계 요약(있는 것만: `parent <slug>` / `sub N` / `prereq N` / `succ N`)을 남긴
이유는, 관계가 있는지조차 안 보이면 결국 `--full` 을 다시 치게 되기 때문이다.
관계가 하나도 없으면 그 줄도 없다.

`--full` 은 예전 기본 출력 그대로(본문·관계 목록·태그·기한).

## 2. `--field` 다중 지원

```
$ openguild quest show DEV-002 --field title status urgency
title: 데이터베이스 스키마 변경
status: Open
urgency: 3

$ openguild quest show DEV-002 --field title        # 하나면 값만 (기존 동작)
데이터베이스 스키마 변경

$ openguild quest show DEV-002 --field title status --json
{ "status": "Open", "title": "데이터베이스 스키마 변경" }
```

여러 줄 값(description, 관계 목록)은 라벨 아래로 들여쓴다.

## 3. 관계 필드는 원래 있었다 — help 가 빠져 있었을 뿐

`prerequisites` / `successors` 가 이미 구현돼 있었다**(DEV-291). 다만 `--help`

## 수정

관계 라벨 색을 상수로 뽑아 **요약과 `--full` 이 같은 것을 쓰게** 했다:

```
REL_COLOR_PARENT  #7ee787 (초록)
REL_COLOR_SUB     #3dc9b0 (청록)
REL_COLOR_PREREQ  #a371f7 (보라)
REL_COLOR_SUCC    #f0883e (주황)
```

예전에는 `--full` 쪽에만 hex 리터럴이 박혀 있었다. 요약에 색을 넣으며 값을
복사하면 나중에 한쪽만 바뀌어 같은 관계가 화면마다 다른 색이 된다 — 상수
공유로 갈라질 수 없게 했다. GUI QuestBoard 의 다중-선택 하이라이트 팔레트와도
같은 값이다.

부모 slug 는 기존처럼 타입 색을 유지한다(관계 라벨 색과 별개 정보).

## 검증

**색은 파이프로 확인할 수 없다** — `use_color()` 가 `stdout().is_terminal()` 을
보므로 파이프에서는 ANSI 가 아예 안 나온다(`cat -v` 로 확인). 그래서 대신
불변식을 테스트로 고정했다:

- 네 상수가 모두 유효한 hex 인지 — `colorize` 는 파싱 실패 시 원문을 그대로
  돌려주므로, 오타가 나면 **조용히 무색**이 된다. 이 테스트가 그걸 잡는다.
- 네 색이 서로 겹치지 않는지.

터미널에서의 실제 색감은 admin 확인 필요(테스트가 보장하는 건 "색 코드가
정상적으로 만들어지고 요약/전체가 동일하다" 까지다).

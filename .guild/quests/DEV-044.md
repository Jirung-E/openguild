`status` 단어는 자연어상 **현재 상태를 묻는다** (git status 등). 그런데
기존 CLI 는 `quest status <slug> <status>` 로 **변경** 명령이었음 → 의도
모호. 변경은 별도 `quest move <slug> <status>` 로 분리. 기존 호출은
deprecation alias 로 유지하여 호환성 유지.

## 구현 (2026-05-22)

### CLI 변경
- `QuestCmd::Status` 의 `status` 인자를 `Option<String>` 으로:
  - 미지정 → 현재 상태 출력 (slug + name_en + name_ko, status.color 입힌).
  - 지정 → 변경 수행 + stderr 에 deprecation 경고:
    `warning: 'quest status <slug> <status>' 는 deprecated. ... 'quest move' 사용`
- 새 `QuestCmd::Move { slug, status }` 추가 — 두 인자 모두 필수.
  내부적으로 기존 `change_status_with_noop_notice` 위임 (BUG-011 도입).

### 출력 형식
- 평문: `DEV-044  Testing (테스트 중)` — name_en 에 status.color (TTY).
- JSON: `{ quest_id, status_id, status_name_en, status_name_ko }`.

### 영향 범위
- 사용자 docs / AGENTS.md 의 status 예시는 `quest move` 로 이행 권장 — 추후 정리 (별도 chore).
- `quest start/done/reopen` alias 는 그대로 유지 — 간결성 우선.

## 자동 테스트 +4 (cli)
- `quest status DEV-001` → status: None (출력 모드).
- `quest status DEV-001 testing` → status: Some("testing") (변경 alias).
- `quest move DEV-001 testing` 파싱.
- `quest move DEV-001` (status 누락) → clap 에러.

```
DEV-044    [In Progress] ... (urgency 3)
```

## 증상

`openguild --help` 또는 subcommand `--help` 결과에 `DEV-044` 같은 내부
quest 번호가 그대로 보임. 사용자 입장에서 무슨 번호인지 알 수 없고 내부
메모가 외부 인터페이스로 leak.

## 원인

`cli/src/main.rs` 의 `Command` / `QuestCmd` enum variant doc comment
(`/// ...`) — clap derive 가 그것을 `about` / `long_about` 으로 사용 →
help 출력에 그대로 노출. 일반 `//` 주석은 leak 안 됨.

## 구현 (2026-05-24)

진단: 5건.

| line | 위치 | 이전 | 이후 |
|---|---|---|---|
| 135 | `quest list --title-only` | `... (DEV-037). description 제외.` | `... description 제외.` |
| 178 | `quest show` | `퀘스트 상세 (슬러그: DEV-001)` | `퀘스트 상세 (슬러그로 조회).` |
| 188 | `quest history` | `... (DEV-013) — 최신 → 과거 순.` | `... — 최신 → 과거 순.` |
| 236 | `quest status` | `... (DEV-044). status 인자 ...` | `... status 인자 ...` |
| 244 | `quest move` | `상태 변경 (DEV-044). ...` | `상태 변경. ...` |

본문 안 (#1679, #1709, #2731) 의 `// DEV-044:` 일반 코멘트는 leak 안 됨
(clap derive 가 `///` 만 본다) → 유지.

회귀 방지 테스트 +2 (cli 66 → 68):
- `find_quest_id_detects_patterns` — substring matcher 단위 검증.
- `help_output_has_no_quest_id_leaks` — `Cli::command()` 부터 모든
  subcommand 의 `render_long_help()` 재귀 traverse + `<PREFIX>-<숫자>`
  패턴 0건 보장 (prefix 2~5 ASCII 대문자).

## 검증
- `cargo test --workspace -- --test-threads=1` → **383 passed** (cli 66 → 68).
- `cargo clippy -p openguild-cli --all-targets -- -D warnings` → clean.
- `openguild quest list --help` / `quest show --help` / `quest history --help`
  / `quest status --help` / `quest move --help` grep → 0 매칭.

## 후속 fix (2026-06-03)

사용자 보고: "--help 에서 퀘스트 번호 나오는 경우가 다시 발견되었다".

DEV-016-cli / DEV-099 작업 시 doc comment 에 quest_id prefix 를 넣어서 5 곳
회귀 (회귀 테스트는 잘 잡았지만 본 세션에 cargo test 안 돌려서 못 봄):

```
[openguild]              'DEV-016' in help  (Command::Rules 의 doc)
[openguild quest]        'DEV-099' in help  (QuestCmd::Comment 의 doc)
[openguild quest comment] 'DEV-099' in help
[openguild quest memo]   'DEV-099' in help  (QuestCmd::Memo 의 doc)
[openguild rules]        'DEV-016' in help
```

수정 — 5 doc comment 에서 quest_id prefix 제거. `BUG-016` 주석으로 정책
재명시 (다음에 추가하는 사람이 보고 잊지 않도록):

```rust
// BUG-016: doc comment 의 quest id 가 clap help 로 leak — 외부 사용자에게
// internal quest 번호 노출 금지. 기능 설명만 plain `///` 으로.
/// 길드 규칙 — `.guild/rules/{slug}.md` 다중 파일 CRUD.
Rules { ... }
```

회귀 테스트 (`help_output_has_no_quest_id_leaks`) 재실행 → 통과.

### 정책 (재명시)
- clap 의 `#[arg(...)]` 또는 `#[command(...)]` / `enum variant doc comment`
  (`///`) 에 **`<PREFIX>-<숫자>` 패턴 금지**. 기능 설명만.
- 일반 `//` comment (clap 이 안 보는 것) 는 quest_id 자유.
- 회귀 보호: `cargo test -p openguild-cli help_output_has_no_quest_id_leaks`.
  새 subcommand 추가 시 반드시 cargo test 한 번.

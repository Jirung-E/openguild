## 증상

`openguild --help` 또는 subcommand help 결과에 `DEV-044` 같은 내부 quest
번호가 그대로 보임. 사용자 입장에서 이게 무슨 번호인지 알 수 없고 (그
quest 본 적 없음), 내부 메모가 외부 인터페이스로 leak.

## 원인 추정

`clap` 의 `#[command(about = "...", long_about = "...")]` 또는 enum variant
의 doc comment (`/// ...`) 에 적힌 quest mention 이 그대로 help 출력에 들어감.

예 (가설):
```rust
/// `quest status <slug> <status>` 는 deprecated (DEV-044). 'quest move' 사용.
#[clap(...)]
Status { ... }
```
이런 doc comment 가 clap derive 매크로에 의해 long_about 으로 변환됨.

## 진단 (실행 전)

```bash
openguild --help > /tmp/h1.txt
openguild quest --help > /tmp/h2.txt
openguild quest status --help > /tmp/h3.txt
grep -E "DEV-[0-9]+|BUG-[0-9]+" /tmp/h*.txt
```

## 수정

- 노출되는 quest mention 들을 doc comment 에서 제거하거나 ASCII 코멘트
  (`//`) 로 옮김 (사용자에겐 보이지 않게).
- 사용자 친화 문장으로 rewrite — 예 "deprecated (DEV-044)" →
  "deprecated — 'quest move' 를 사용하세요."

## 검증

- `openguild --help` + 각 subcommand `--help` 출력 grep — `DEV-` /
  `BUG-` 패턴 0건.
- 자동 테스트 (cli) — help 출력에 quest 패턴 없는지 정규식 assert.

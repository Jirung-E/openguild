작업기록에서 댓글 활동을 눌러도 **문서까지만** 이동하고 끝나, 긴 문서에서
그 댓글을 다시 찾아야 했다. 해당 댓글로 바로 스크롤되게 한다.

## 구현 (2026-07-28)

**core** — `ActivityRow` 에 `ref_id: Option<i64>` 추가. `activities()` 의 여섯
UNION 분기에 열을 맞췄다:
- 퀘스트/캠페인 댓글: 댓글 번호
- 토론 해결/재개(`discussion_resolved`/`reopened`): `new_value` 가 곧 댓글 번호
- 그 외(created/status/rule/book): `NULL`

**주의해서 고른 값** — UI 앵커(`#comment-N`)는 **퀘스트별 번호(`entry_id`)** 를
쓴다. 처음엔 전역 rowid(`c.id`)를 실었는데, 실기에서 앵커가 `comment-1..6`
인데 링크는 `comment=1254` 라 아무 데도 안 걸렸다. `entry_id` 로 교체.
(진리원은 사이드카 파일이고 그 안의 번호가 곧 표시 번호다.)

**frontend**
- `activityHref()`: `ref_id` 가 있으면 `?comment=N` 을 붙인다.
- `QuestCommentsSection`: 댓글이 로드된 뒤 `?comment=N` 대상 앵커로 스크롤 +
  2.2초 강조(`jump-target`). 접혀 있으면 펼친다. 같은 id 에는 한 번만 —
  댓글 추가/새로고침마다 다시 튀지 않도록.
- 앵커가 그려질 때까지 **rAF 재시도(최대 3초)** — `entries` 가 채워진 직후
  단발 `tick()` 만으로는 놓친다(groups 파생 → 중첩 snippet 순서). 실기에서
  단발 tick 은 스크롤이 아예 안 걸렸다.
- `prefers-reduced-motion` 이면 smooth 대신 즉시 이동.

## 검증

- 실제 길드 worklog JSON: 댓글 활동 19건 전부 `ref_id` 가 실리고, 값이
  `quest comment list` 의 표시 번호(#1..#6)와 일치. created/status 등은 `null`.
- 브라우저: `/quests/BUG-153?comment=4` 로 진입 → 효과가 대상(4)을 찾아
  스크롤 호출까지 도달하는 것을 콘솔 진단으로 확인.
- 프론트 308건 / core worklog 4건 통과, `svelte-check` 0 errors/0 warnings.

**환경 한계**: 검증에 쓴 브라우저 패널이 숨김 상태라 프레임 루프가 멈춰
`behavior:'smooth'` 스크롤이 진행되지 않았다(같은 요소를 `behavior:'auto'` 로
부르면 1767px 즉시 이동함을 확인 — 로직이 아니라 환경 문제). 실제 브라우저에서
부드러운 스크롤이 끝까지 도달하는지는 실기 확인이 필요하다.

## Test plan

1. 작업기록에서 **댓글** 활동을 클릭 → 해당 퀘스트로 이동 + 그 댓글이 화면
   중앙에 오고 잠깐 강조되는지.
2. **캠페인 댓글** 활동도 동일한지.
3. **토론 해결/재개** 활동을 클릭하면 그 댓글로 가는지.
4. 상태변경/생성/규칙/BOOK 활동은 기존처럼 문서까지만 가고 쿼리가 안 붙는지.
5. 댓글 섹션이 접힌 상태로 들어가도 펼쳐지며 이동하는지.
6. 같은 페이지에서 댓글을 새로 달아도 다시 튀지 않는지(1회만).
7. 답글(중첩 2단)로도 이동되는지.

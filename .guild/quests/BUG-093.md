사용자 보고: "127.0.0.1 로 접속시 reindex 가 안됨" — server 로그:
```
ERROR openguild_server::error: internal error: error returned from database: (code: 787) FOREIGN KEY constraint failed
```

## 원인

`core::reindex::reindex()` 의 quest insert 루프가 unknown type prefix /
잘못된 number / unknown status slug 인 quest 를 skip(continue — DB INSERT
안 함)한다. 그런데 그 skip 직전에 만들어진 `slug_to_id` map 은 **파싱에
성공한 모든 quest 파일의 slug**를 넣어두고 있었다(실제 INSERT 여부와
무관). 다른 quest 가 그 skip 된 quest 를 `parent` 또는 `prerequisites` 로
참조하면, `slug_to_id.get(slug)` 가 "존재하지 않는 quest id"를 돌려주고
`quest_dependencies.prerequisite_id` / `quests.parent_quest_id` 가 그 id 를
가리키게 된다. `PRAGMA defer_foreign_keys=1` 로 FK 검증이 commit 시점까지
미뤄지지만, commit 시점에도 그 id 가 실재하지 않으므로 FK 위반(code 787)으로
**reindex 전체가 실패**한다.

재현 (CLI):
```
DEV-001: status = "bogus_status_xyz" (정의되지 않은 status)
DEV-002: parent = "DEV-001", prerequisites = ["DEV-001"]
openguild reindex  → FOREIGN KEY constraint failed
```

## 수정

`core/src/reindex.rs` — `slug_to_id` 를 **실제로 INSERT 될 quest 만** 매핑하도록
변경. validity(type prefix / number / status 모두 해당 파일 자체 데이터로만
결정되어 순서 무관)를 quest insert 루프보다 먼저 한 번에 계산해 map 을 채운다.
이후 parent_id 해석 / prerequisites 해석 / position 복원 / campaign
linked_quests 해석이 모두 같은 map 을 쓰므로, skip 된 quest 를 참조하던 링크는
(별도 처리 없이) 자동으로 조용히 drop 된다 — FK 위반 없이.

회귀 테스트 추가: `reindex_drops_dangling_refs_to_skipped_quest_without_fk_error`
(core/src/reindex.rs).

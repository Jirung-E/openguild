## 문제

`openguild --remote <URL>`에서 서버 HTTP API가 이미 제공하는 기능까지 CLI의 `Backend::Http` 분기가 `unsupported`를 반환해 사용할 수 없다. 대표적으로 quest/campaign 댓글과 메모는 GUI와 서버에서는 정상 동작하지만 CLI 원격 모드만 차단된다.

여러 기능이 공용 `http_unsupported_meta()`를 재사용해 댓글·메모·태그·템플릿 명령도 `type/status 관리 미지원`이라는 잘못된 오류를 출력한다.

실제 재현:

```text
openguild --remote <URL> quest comment list DEV-349
error: remote 모드에서는 type/status 관리 미지원 ...
```

같은 서버의 `GET /api/quests/by/DEV-349/comments`는 정상 응답하며 댓글 1건을 반환했다. Campaign 댓글·Quest/Campaign 메모도 동일하게 서버 API는 정상이고 CLI만 거부한다.

## 범위 A — 기존 서버 API 연결

1. Quest 댓글: `list/show/add/edit/remove/react/discussion/resolved/pinned`
2. Campaign 댓글: `list/show/add/edit/remove/react/pinned`
3. Quest/Campaign 메모: `show/set/clear`
4. Quest 태그: `list/add/remove/set`
5. Quest/Campaign/Library 첨부: 각각 `list/add/remove`
   - 원격 업로드는 `/api/attachments/stream`에 파일 body를 직접 흘려 대용량 파일을 메모리에 통째로 올리거나 base64로 복제하지 않는다.
6. Type/Status 관리: `add/update/delete`
7. 서버 정비: `reindex`/`index rebuild`, `check drift [--resync]`, `index vacuum`, `journal tail`

관련 선행 사례: [[BUG-166]], [[DEV-193]], [[DEV-152]], [[DEV-199]], [[DEV-333]].

## 범위 B — 추가한 서버 API

1. `GET /api/comments`: 최상위 `comments` 횡단 검색
2. `GET/POST /api/templates`, `GET /api/templates/{name}`: `template list/show/new` 및 원격 `quest new --template`
3. `GET /api/tags/used`: `tag list --used`
4. `POST /api/admin/counters`: `check counters [--fix]`
5. `GET /api/admin/info`: `info`

`migrate-to-files`는 일회성 오프라인 이전 명령이므로 로컬 전용을 유지한다.

## 구현 원칙 및 결과

- 기능과 무관한 공용 `http_unsupported_meta()`를 제거했다.
- 읽기·쓰기·필터·확인 플래그는 로컬 코어 로직 또는 같은 서버 어댑터를 사용한다.
- reindex 응답에 로컬 보고서의 전체 카운트를 포함하되 기존 GUI가 쓰는 `skipped` 객체 형식은 유지한다.
- 원격 DTO 역직렬화를 위해 core 보고서 형식에 `Deserialize`만 추가했다.
- 템플릿 HTTP 저장은 단일 안전한 파일명만 허용해 `.guild/templates` 경로 탈출을 차단한다.
- CLI 스킬 문서의 첨부/템플릿/댓글/정비 원격 지원 설명을 현재 동작과 맞췄다.

## 테스트 방법

자동 검증(실행은 사용자 승인 필요):

```bash
cargo test -p openguild-core
cargo test -p openguild-server
cargo test -p openguild-cli
```

실제 로컬/원격 대조:

1. 같은 테스트 길드를 대상으로 서버를 띄운다.
   `cargo run --bin openguild-server -- host --bind local --port 3000`
2. 아래 각 명령을 로컬(`--guild <PATH>`)과 원격(`--remote http://127.0.0.1:3000`)에서 실행하고 JSON 결과/파일 변경을 대조한다.
3. 댓글은 답글·반응·discussion/resolved·pin까지, 메모는 빈 값/clear까지 확인한다.
4. Quest/Campaign/Library 첨부는 각각 추가·목록·제거한다. 큰 파일 업로드 중 CLI 메모리가 파일 크기에 비례해 증가하지 않는지도 확인한다.
5. 임시 Type/Status를 생성→rename/update→삭제하고, 사용 중 삭제 거부와 slug cascade를 확인한다.
6. `reindex`, `check drift --resync`, `index vacuum`, `journal tail`, `check counters`, `info`의 출력 의미를 대조한다.
7. `template new/list/show` 후 `quest new --template`으로 기본 제목/type/urgency/tags/body 적용을 확인한다.
8. `comments` 필터와 `tag list --used`가 로컬/원격에서 같은 행을 반환하는지 확인한다.
9. `migrate-to-files --remote ...`만 해당 기능과 오프라인 실행 대안을 정확히 안내하며 거부되는지 확인한다.

## 구현 (간단)

`URGENCY_LABEL[urgency]` / `URGENCY_COLOR[urgency]` bare access 가 invalid urgency (예: 5) 에서 undefined → 직후 `.length` 폭발 → 보드 mount 실패.

`types/index.ts` 에 `urgencyLabel(u)` / `urgencyColor(u)` 헬퍼 추가 (범위 밖이면 4 fallback). QuestBoard 4곳 + QuestListItem + quest detail 의 bare access 를 헬퍼로 교체. `{#each [1,2,3,4]}` 같은 fixed array iteration 은 안전이라 그대로.

## 테스트 방법

### A. 기본 (정상 데이터)

1. Board / List / Quest Detail 진입 → 평소처럼 urgency 뱃지 (Critical / High / Medium / Low) 가 색과 함께 표시.
2. 라이트 / 다크 둘 다 색 정확.

### B. 방어 (invalid 데이터)

수동으로 invalid urgency 주입 — 테스트용 quest 가 필요.

1. `.guild/quests/TEST-001.md` 신규 작성 (frontmatter `urgency = 99`). (또는 SQL 직접 `UPDATE quests SET urgency = 99 WHERE quest_id = 'XXX-NNN'` 후 reindex 우회).
2. GUI 재시작 (또는 admin reindex).
3. **Board 가 폭발 안 하고** TEST-001 이 표시되어야. urgency 뱃지는 "Low" 로 fallback.
4. Quest Detail / List 동일.
5. 테스트 후 파일 제거 + reindex.

(invalid 데이터 만들기 번거로우면 (B) skip. (A) 정상 동작만 확인해도 OK — 본 fix 는 데이터 정정 + 방어가 둘 다 들어가서 기본 사용에선 차이 없음.)

## 처리 내역 + #2(clamp) 미반영 상태 정리

**원래 fix(댓글 #1)가 한 것 — 보드 폭발 방어:**
- GUI: `urgencyLabel(u)` / `urgencyColor(u)` 헬퍼로 bare map access 제거. 범위 밖이면 `?? URGENCY_LABEL[4]`로 fallback → `undefined.length` 폭발 차단. (QuestBoard / QuestListItem / quest 상세 사용처 교체)
- core reindex: 파일 urgency가 1..=4 밖이면 4로 적재 + skipped 경고, quest 자체는 잃지 않음. (`reindex_clamps_out_of_range_urgency` 테스트 존재)

**#2 지적(clamp) — 아직 미반영:**
현재는 양쪽 다 "범위 밖 → 무조건 4(Low)"라 진짜 clamp가 아님. **하한이 틀림:**
- `0`, `-3` → 지금은 4(Low). clamp라면 1(Critical)이어야 함.
- `5`, `99` → 지금도 4(Low), clamp도 4(Low) (상한은 결과 동일).

진짜 clamp = `min(max(u, 1), 4)`. 고칠 곳 2군데:
- `core/src/reindex.rs` urgency 분기 (현재 else 가지 → 4 고정)
- `gui/frontend/src/lib/types/index.ts` `urgencyLabel` / `urgencyColor` (현재 `?? [4]`)

(용어 참고: 시스템은 1=Critical … 4=Low. #2의 "low(1)" 표기는 값이 반대로 보임 — clamp 기준은 1=Critical / 4=Low로 잡으면 됨.)

→ 위 2군데를 clamp로 바꾸면 #2 반영됨. 반려 사유가 이 부분이면 바로 진행 가능.

## 처리 완료 (clamp + 경고)

방향대로 구현 — DB 는 raw urgency 보존, GUI 는 clamp 표시 + 범위 밖이면 경고.

- **clamp(#2 반영)**: `urgencyLabel`/`urgencyColor` 를 `min(max(u,1),4)` 진짜 clamp 로. 이제 0/-3 → 1(Critical), 5/99 → 4(Low). (이전 '무조건 4' 는 하한이 틀렸음.)
- **reindex**: 범위 밖 urgency 를 4 로 덮어쓰지 않고 raw 그대로 적재 + skipped 경고. (incremental sync 는 이미 raw 저장이라 reindex 만 불일치였음 — 이제 일치. GUI 가 원본 범위 밖 여부를 알아야 경고 가능.)
- **경고 표시**: 원본이 1..4 밖이면 ⚠ — quest 상세 헤더 / 보드 노드 SVG / 홈 conveyor 노드 SVG / 리스트 행. 표시 값 자체는 clamp 된 값. tooltip 에 원본값 + "파일 정정" 안내.
- 보드 폭발은 BUG-060 본 fix 의 안전 헬퍼가 계속 방어.

test: `reindex_keeps_raw_out_of_range_urgency_with_warning` (raw 적재 검증). 전체 cargo test / npm check 통과.

참고: 현재 .guild 파일엔 범위 밖 urgency 가 없음(DEV-120 은 이미 4 로 정정됨) — 경고를 눈으로 확인하려면 파일 하나의 urgency 를 임시로 5 등으로 바꾸고 reindex 하면 됨.

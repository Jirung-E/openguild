## 증상

GUI 의 "최근 guild(recent guild)" 목록에 `%TMPDIR%/openguild-welcome-placeholder`
같은 임시 경로가 정식 항목으로 계속 등록됨.

## 원인

`openguild-welcome-placeholder` 는 guild 를 안 연 Welcome/Uninit 상태에서
쓰는 in-memory DB 용 고정 tmp 경로(`gui/src/lib.rs`). BUG-041 당시 "in-memory
라 디스크에 아무 흔적도 안 남긴다"는 의도로 설계됐는데, `core/src/store.rs`
의 `Store::open_in_memory` 가 여전히 `.guild/`(+`backups/`) 마커 디렉터리를
실제 디스크에 만들고 있었다.

여기에 최근 추가된 "뒤로가기로 guild 히스토리 복원"(DEV-355) 기능이 겹치며:
1. Welcome 상태에서 페이지를 돌아다니면 브라우저 히스토리에 이 placeholder
   경로가 찍히고,
2. 나중에 실제 guild 를 연 뒤 뒤로가기(트랙패드 스와이프 포함)로 그 히스토리
   지점에 도달하면 `open_guild_in_current_window` 가 이 경로로 호출되는데,
3. `.guild/` 마커가 디스크에 없어야 정상 거부(`has_guild_marker`)되어야
   하는데 1번 버그 때문에 마커가 실제로 존재해 체크를 통과해버리고,
4. 진짜 디스크 DB 가 만들어지며 `recents.json` 에 정식 등록됨.

## 수정

`Store::open_in_memory` 에서 `.guild/`(+`backups/`) 디렉터리 생성 코드를
제거 — index/journal 모두 sqlite in-memory(`mode=memory&cache=shared`)라
디렉터리 자체가 애초에 불필요. 이제 이 경로엔 디스크 흔적이 전혀 안 남아
`has_guild_marker` 체크가 정상 작동하고, 히스토리 복원 경로를 타도 recents
에 등록될 수 없다.

## 참고 (이번엔 손 안 댐)

`current_guild_path` Tauri 커맨드(`gui/src/commands.rs`)가 launch mode 를
체크 안 하고 항상 placeholder 경로를 반환하는 지점도 있음 — `current_guild_name`
처럼(BUG-136) launch mode 가드를 추가하는 방어책도 가능하나, 프론트엔드
호출부 5곳(guildIdentity.ts / banner.ts / guild-storage.ts / QuestBoard.svelte
/ settings +page.svelte)의 동작을 다 검토해야 해서 별도 후속 과제로 남김.

## 테스트 방법

`cargo test -p openguild-core --lib store::` 통과 확인(자동). 다만 실제
회귀 경로(Welcome 에서 페이지 이동 → 뒤로가기로 stale 히스토리 진입 →
recents 오염 여부)는 GUI 조작이 필요해 자동화 범위 밖 — 수동 확인 필요:
1. GUI 를 guild 없이 시작(Welcome).
2. 설정 등 다른 화면으로 몇 번 이동.
3. 실제 guild 를 하나 연다.
4. 트랙패드 뒤로가기 스와이프(또는 뒤로가기)로 여러 번 되돌아가 Welcome
   시점 히스토리까지 진입.
5. recent guild 목록에 `openguild-welcome-placeholder` 항목이 새로 안
   생기는지 확인.

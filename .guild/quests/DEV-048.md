`CreateQuestRequest` / `ChangeStatusRequest` body 에서 `status_id` 제거,
`status_slug` 전용 받음. positional id 가 status 추가/순서 변경 시 silent
corruption 일으키는 hazard 제거 (DEV-042 의 quest_history slug 화와 동일
원리, API 표면에서).

## 구현 (2026-05-23)

### 모델 (Breaking change)
- `core::models::CreateQuestRequest`: `status_id: i64` → `status_slug: String`.
- `core::models::ChangeStatusRequest`: `status_id: i64` → `status_slug: String`.

### Backend 내부 resolve
- `core::services::quests::create`: 트랜잭션 시작 후 `SELECT id FROM
  quest_statuses WHERE slug = ?` 로 id resolve. 모르는 slug → 400 BadRequest.
- `core::services::quests::change_status`: 동일 resolve.
- `core::ops::quests::change_status`: BUG-011 의 no-op 비교를 **slug 기준** 으로
  변경 (이전엔 numeric id 비교). 더 간결.

### CLI
- `HttpClient::change_status(id, status_slug: &str)` — body 에 slug 전송.
- `Backend::change_status(id, &str)` — Http / Local 둘 다 slug 받음.
- `Backend::resolve_status_slug(input)` 신설 — name_en / slug / id 모두 받아
  slug 반환. fallback chain. 기존 `resolve_status_id` 는 제거 (production 경로
  에선 미사용).
- `change_status_with_noop_notice` 가 slug 기반으로 no-op 비교 +
  HTTP body 에 slug 전송.
- `quest new` 시 default open status 의 slug 사용.

### Frontend
- `ChangeStatusRequest.status_slug: string` / `CreateQuestRequest.status_slug: string`.
- `QuestBoard.svelte`:
  - 모듈 level helper `slugOf(statusId: number): string` 추가 (sorted 리스트
    조회). lane 내부 표현은 status_id 그대로 유지 (Cytoscape filter `[statusId = N]`).
  - `changeStatus` 호출 3곳 (undo/redo single, undo/redo multi, drag-to-lane)
    이 `slugOf(target.statusId)` 전송.
- `NewQuestModal.svelte`: `openStatusId` → `openStatusSlug`. POST body 에 slug.
- `Quest Detail (+page.svelte)`: `changeStatus(statusId, statusSlug)` 시그니처
  변경. 버튼 클릭 시 `(s.id, s.slug)` 전달.

### Tauri / 기타
- Tauri commands 는 serde Deserialize 가 struct 정의를 따르므로 자동 적용.
- 테스트 fixture 일괄 교체 (`status_id: N` → `status_slug: "open|in_progress|..."`).

## 자동 테스트

- 기존 모든 backend 테스트 (server / core / cli) 가 새 slug-only body 로 갱신.
- frontend transport / client 모킹 fixture 도 slug 사용.
- `CreateQuestRequest` deserialize 테스트: `status_slug` 필드 검증 추가.

## 회귀

- 기존 클라이언트가 status_id 를 보내면 deserialize 실패 (의도적 — silent
  corruption 회피).
- 모든 내부 컴포넌트가 동시 갱신 — production 경로에서 status_id 사용 0.
- QuestRow.status_id 응답 필드는 유지 (호환 + 표시용).

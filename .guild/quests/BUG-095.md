사용자 보고: "gui를 처음 열때 이전 원격 길드의 홈으로 열리는 현상이
있는거 같은데 확인좀".

## 원인

`remoteServerUrl` 은 localStorage(디스크) 영속이라 앱을 완전히 새로 켜도
(이전 프로세스와 무관) 남아있다. local 길드는 DEV-052 설계상 인자 없이
실행하면 항상 Welcome 으로 진입(이전 길드 자동 재오픈 안 함) — `open_*`
Tauri command 가 성공 시 `LaunchInfo.mode` 를 "guild" 로 Rust 쪽에서
직접 갱신해주기 때문에 board 의 bounce guard 가 정확히 "지금 진짜로 길드가
열려있는지"를 판단할 수 있다.

원격은 이 메커니즘이 없다 — DEV-113 직전 수정에서 board 의 bounce
guard 를 "`remoteServerUrl` 이 설정돼 있으면 무조건 건너뛴다"로 고쳤는데,
이게 *이전 세션*의 잔존 값과 *이번 세션에 실제로 연결함*을 구분하지
못해, 콜드 스타트에도 항상 직전 원격 길드로 자동 재진입되는 local 과의
비대칭 버그가 생겼다.

## 수정

`lib/stores/remoteServer.ts` 에 `markRemoteSessionActive()` /
`isRemoteSessionActive()` 추가 — sessionStorage 기반(OS 프로세스 재시작
=새 WebView 세션마다 항상 빈 상태로 시작, localStorage 와의 핵심 차이).
Welcome 의 `openRemoteEntry()`(목록 클릭 + 신규 연결 공용)가 연결 시점에
이 플래그를 세팅. board(`/`) 의 bounce guard 는 `remoteServerUrl` 단독이
아니라 **`remoteServerUrl` && `isRemoteSessionActive()`** 일 때만
bounce 를 건너뛴다 — 콜드 스타트엔 세션 플래그가 없어 정상적으로
launch_mode 체크 → Welcome 으로 bounce, 같은 세션 내 Welcome 에서
실제로 클릭해 연결한 경우만 bounce 를 건너뜀.

검증: `openguild-gui.exe` 재빌드 후 새 프로세스로 콜드 스타트(이전 세션의
원격 연결이 localStorage 에 남아있는 상태) → Welcome 화면에 정상 진입
확인(이전이면 바로 원격 길드 보드로 들어갔을 상황). DEV-206 의 원격 항목
비활성화 표시도 함께 정상 동작.

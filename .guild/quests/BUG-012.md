DB에만 저장하고있는건 아닌지 확인 필요.

## 원인

`core/src/ops/quests.rs::write_quest_file` 의 description 보존 fallback:
```rust
let existing_description = QuestFile::read(&path).ok().map(|f| f.description).unwrap_or_default();
...
description: if existing_description.is_empty() {
    quest.description.clone().unwrap_or_default()
} else {
    existing_description  // ← DB 의 새 값 무시
},
```

GUI 의 description 수정 흐름:
- `update_quest` → SQL UPDATE OK → `write_quest_file` 호출.
- `write_quest_file` 가 "파일에 description 이 비어있지 않으면 그것을 그대로
  유지" → DB 의 새 description 이 파일에 안 쓰임.
- 사용자가 GUI 새로고침 시 DB 에서 fetch → 새 값 보이긴 함.
- 하지만 다음 `reindex` 가 돌면 파일 → DB 로 옛 description 복원되어 손실.

이 fallback 은 `f6a5bc5` ("chore: quest 상태 + 문서 + 코드 정리") 에서
들어왔는데, 의도는 추측건대 "외부 편집으로 풍부해진 description 을 mutation
이 덮어쓰지 않도록" 보호. 하지만 실제로는 GUI 수정 자체를 막는 회귀.

## 수정

- `write_quest_file` 의 fallback 제거 → 항상 `quest.description` (DB 의
  최신 truth) 사용.
- `write_quest_file_as_deleted` 도 같이 정리 (동일 패턴, 의도 동일).
- 회귀 테스트 `update_quest_description_writes_to_file` 추가:
  1차 → 2차 수정 → 파일에 새 값 반영. 3차 (description 안 건드림) →
  description 보존.

## Trade-off (수용)

외부 편집 시나리오 — `.md` 를 직접 편집 후 reindex 없이 GUI 에서 다른
필드 수정 → 외부 편집한 description 잃음. AGENTS.md 정책상 외부 편집
후 reindex 는 사용자 책임 (실제로 이 quest 본문 작성 중 동일 시나리오로
한 번 잃음 → reindex 후 재작성).

## 요청

worklog(작업 기록) 뷰가 현재는 **모든 조작을 개별 항목으로** 나열한다.
같은 문서에 대한 조작은 **문서 단위로 묶어서(compact)** 보여줄 수 있어야 한다.

## 배경

한 퀘스트를 작업하면 상태변경·댓글·수정이 연달아 쌓이는데, 지금은 그게 전부
평면 목록으로 풀려서 나온다. 활동이 많은 날은 실제로 몇 개의 문서를 건드렸는지
파악하기 어렵다.

## 기대 동작

- 같은 문서(퀘스트/캠페인/도서관 등)에 대한 조작을 하나의 그룹으로 묶어 표시
- 그룹 헤더에 문서 ID/제목, 그 안에 해당 문서에 가해진 조작들
- compact 뷰와 기존 전체 뷰를 토글할 수 있으면 좋음(기본값은 논의 필요)

## 참고

묶음 단위/정렬 기준(최근 조작 시각 기준 정렬 등)과 기본 뷰를 무엇으로 할지는
구현 전에 확정할 것.

## 수정 내용 (2026-08-20)

결정대로 **compact 기본 + 전체 보기 토글**.

`routes/worklog/+page.svelte` 한 파일 + i18n 키.

- `groupByDoc(rows)` — 하루치 활동을 slug 단위로 묶는다. **문서의 첫 등장
  순서를 유지**해 시간 흐름이 뒤집히지 않게 했다.
- 묶음 헤더에 표시하는 것: 시각(범위면 `01:34–21:22`), slug 링크, 조작 종류
  뱃지(중복 제거), 건수, 첫 조작 요약.
- 그룹을 펼치면 개별 조작이 들여쓰기로 나온다. 기본은 전부 접힘.
- 뷰 모드는 `localStorage`(`openguild.worklogViewMode`) 영속 — 매번 다시
  고르게 하면 성가시다(QuestNoteSection 의 heightMode 와 같은 정책).

설계상 판단:

- **행 전체를 링크로 만들지 않았다.** 펼치기와 문서 이동이 충돌하기 때문이다.
  화살표 버튼 = 펼침/접힘, slug = 문서로 이동으로 나눴다.
- 그룹 링크는 그 문서의 **첫 활동**을 가리킨다 — 댓글 활동이면 DEV-296 의
  `?comment=N` 이 그대로 붙어 해당 댓글로 스크롤된다.
- `expandedDocs` 는 `Set` 을 직접 mutate 하지 않고 새 `Set` 으로 교체한다.
  Svelte 5 는 in-place mutation 을 감지하지 못한다.

## 검증 (브라우저 실측, 활동 21건)

| 항목 | 결과 |
|------|------|
| compact 묶음 | 21건 → **10개 문서 그룹** |
| 그룹 펼침 | 하위 4건 표시, `aria-expanded=true` |
| 그룹 접힘 | 하위 0건, `aria-expanded=false` |
| 전체 뷰 전환 | 그룹 0 / 행 21 |
| compact 복귀 | 그룹 10 |
| localStorage | `full` ↔ `compact` 정확히 저장 |

시각 컬럼은 기존 `.ts`(2.8rem)가 범위 표기(`01:22–01:26`)에 좁아 두 줄로
접혔다 — 묶음 헤더에 한해 5.4rem 으로 넓히고 `nowrap` 을 줬다. 실측 높이 19px
단일 행 확인.

육안 확인: DEV-362 그룹(4건)을 펼치면
`open→in_progress / in_progress→testing / testing→in_progress /
in_progress→testing` 이 들여쓰기되어 나온다.

## 테스트 방법

1. 작업 기록 화면에서 기본이 **문서별** 뷰인지 확인.
2. 여러 조작이 있는 문서 행의 화살표를 눌러 펼침/접힘 확인.
3. slug 를 클릭하면 그 문서로 이동하는지 (댓글 활동이면 해당 댓글로 스크롤).
4. **전체** 로 바꾼 뒤 새로고침 → 전체 뷰가 유지되는지(영속).
5. 주/월/구간 뷰에서도 날짜 구분선 아래로 묶음이 정상인지.

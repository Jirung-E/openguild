CLI 출력의 색 일관성 강화 + status_id 의 외부 노출을 slug 로 대체.

## 구현 (2026-05-22)

### 색 적용 위치
- `print_quest_detail` (`quest show`):
  - 헤더 quest_id → type.color.
  - status name_en → status.color.
  - urgency 숫자 → urgency_color().
  - sub-quests / prerequisites: `- {quest_id colored} [{status colored}] {title}`
    형태로 status 도 함께 표시 (정보 풍부 + 색).
  - created/updated 줄 / description / parent 줄은 색 제외 (정보 자체).
- `Command::Types`: prefix 에 type.color (좌측 패딩 포함 colorize).
- `Command::Statuses`: name_en 에 status.color (좌측 패딩 포함).
- `Command::Quest::Status` (출력 모드): quest_id 에 type.color (이전엔 status 만).
- `Update --dry-run` urgency 변경 줄: `{from colored} → {to colored}` 양쪽.

비-TTY / `NO_COLOR` 시 평문 폴백은 기존 `colorize()` 정책 그대로.

### `quest status --json` 출력 변경
- 이전: `{ quest_id, status_id, status_name_en, status_name_ko }`.
- 현재: `{ quest_id, status_slug, status_name_en, status_name_ko }`.
- `status_id` 는 positional id (status 추가/순서 변경 시 의미 깨짐) — 외부
  클라이언트가 참조하기에 부적합. DEV-042 이후 stable identifier 인 slug 로
  대체.

### QuestRow / 모델
- `core::models::QuestRow.status_slug: String` 추가.
- `core::services::quests::QUEST_SELECT` 의 JOIN 절에 `qs.slug AS status_slug` 추가.
- frontend `Quest` 타입에도 `status_slug: string` 추가.
- 기존 `status_id` 필드는 유지 (DB FK / 기존 코드 path 호환). 새 코드는
  status_slug 사용 권장.

### 영향 / 호환
- `quest show --json` / `quest list --json` 등 모든 QuestRow JSON 출력에 status_slug 가 함께 노출.
- 기존 frontend / API consumer 는 status_id 그대로 사용 가능.
- backend 변경: 모델 필드 1개 + SELECT 1줄 추가 — 다른 코드 path 영향 없음.

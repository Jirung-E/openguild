## MVP (1.0 범위, 완료)

전체 범위(GUI 전역 + core/cli/server 문자열 전부 스윕)는 다중 세션급 리팩터라
1.0 마감엔 과함. 1.0 은 **인프라 + 대표 적용**까지:

- `lib/stores/locale.ts` — `theme.ts` 와 동일 패턴. `Locale = 'ko'|'en'`,
  localStorage 영속(`openguild.locale`), 기본 `ko`(기존 사용자 경험 무변화),
  `t(key, locale)` 사전 기반 번역 + 누락 키는 ko 원문 fallback.
- `SettingsQuickMenu.svelte` — 설정 퀵메뉴 자체의 라벨(테마/UI 크기/컨텐츠 폭/
  전체 설정 + 새 "언어" 토글 행)을 `t()` 로 전환 + 한국어/English 세그먼트
  버튼으로 즉시 전환 확인 가능. (`$derived` 로 `$locale` 변경 시 라벨 재계산.)
- Nav 의 주요 라벨(Home/Quest Board/Quest List/Admin/Rules)은 이미 영어라
  별도 적용 불필요 — 확인만.
- (후속 피드백) `/settings` 페이지의 '표시' 탭에도 언어 토글 노출 — 테마/UI
  크기/컨텐츠 폭과 같은 자리에 한국어/English 세그먼트 버튼 추가. SettingsQuickMenu
  의 기존 토글은 유지(테마처럼 둘 다 노출, 일관 패턴).

**남은 전체 스윕(GUI 나머지 컴포넌트 + core/cli println!/에러 메시지 +
server 응답)은 [DEV-205](DEV-205.md) 로 분리** — 화면/모듈 단위 점진 진행 권장.

## 버그 수정 (returned, 2026-06-28) — 언어 선택 버튼 라벨이 번역되던 문제

admin 보고: 영어로 전환하면 언어 선택 버튼 자체의 라벨("한국어")이
"Korean"으로 번역되어, 선택 중인 항목이 한국어 옵션인지 헷갈림. 언어 이름은
그 언어를 가리키는 고유명사라 항상 같은 표기("한국어"/"English")로 보여야
한다 — 현재 locale 기준으로 번역하면 안 됨.

수정: `lib/stores/locale.ts` 의 `settings.language.ko`/`settings.language.en`
사전 항목 제거(애초에 "번역"할 대상이 아니었음), `SettingsQuickMenu.svelte`
+ `settings/+page.svelte` 양쪽의 언어 토글 라벨을 `t()` 호출 없이 고정
문자열 `'한국어'` / `'English'` 로 직접 지정.

## 메모 — Status name 입력 UX (DEV-014 후속, 2026-05-24)

DEV-014 의 Admin Quest Statuses 섹션에서 현재 `name_en` 만 필수, `name_ko`
는 선택. 이 기본 언어 선택 기능이 만들어지면:
- **기본 언어 = 영어**: `name_ko` 입력 필드 자체를 숨김 (또는 "+ 다른 언어
  추가" 아코디언). 영어권 사용자에겐 한국어 input 이 시각 잡음.
- **기본 언어 = 한국어**: `name_ko` 노출 (현재 동작). 단 여전히 선택 — 한국어
  사용자라도 짧은 status 는 영어 그대로 두고 싶을 수 있음.
- 적용 위치:
  - `lib/components/admin/AdminStatusesSection.svelte` 의 추가 모달 + inline
    수정 input.
  - `name_ko` 비어있을 때의 표 표시 "—" 도 기본 언어 = 영어면 column 자체
    숨김 검토.
- 표시 사이트 (board / detail / list / combobox status badge) 가 현재
  `name_en` 고정 — 기본 언어 정책에 따라 `name_ko` 우선 fallback 도입 필요.
  fallback 순서: 사용자 기본 언어 → name_en (영원한 fallback).
- DB schema 변경 없음 — UI 정책만 바뀜.

## 증상

사용자 보고 (다른 길드에서 테스트 중): "퀘스트 삭제하고 Quest Board 보니까
에러나고, reindex 하려니까:

```
reindex 실패: Error: internal error: error returned from database:
  (code: 1299) NOT NULL constraint failed: quest_history.quest_id
```

## 원인

`core/src/reindex.rs` 의 5c 단계 `UPDATE quest_history` 가 subselect 로 새
quest_id 를 채우는데:

```sql
UPDATE quest_history
  SET quest_id = (
    SELECT q.id FROM quests q JOIN quest_types qt ON q.quest_type_id = qt.id
    WHERE qt.prefix || '-' || printf('%03d', q.number) = quest_history.quest_slug
  )
  WHERE quest_slug IS NOT NULL
```

사용자가 quest 파일을 **hard-delete** (또는 외부 편집으로 .md 제거) 하면 그
slug 에 해당하는 row 가 reindex 후 quests 테이블에 없음 → subselect 가 NULL
→ `NOT NULL` 컬럼인 quest_history.quest_id 에 NULL UPDATE → sqlite 1299
panic. **전체 reindex transaction rollback** → 캐시 정합 깨짐.

Quest Board 의 후속 에러도 같은 chain — reindex 가 실패해서 DB 가 stale →
board UI 가 inconsistent 데이터로 렌더 → 에러.

## 수정

WHERE 절에 `EXISTS` 조건 추가 — 매칭되는 quest 가 있는 history 행만 UPDATE.
매칭 안 되는 행은 기존 quest_id 유지 (stale 가능하지만 NULL 안 됨; FK constraint
없는 history 테이블이라 dangling reference 도 무해 — read-only 표시용).

```sql
UPDATE quest_history SET quest_id = (...)
  WHERE quest_slug IS NOT NULL
    AND EXISTS (SELECT 1 FROM quests q JOIN quest_types qt ON q.quest_type_id = qt.id
                WHERE qt.prefix || '-' || printf('%03d', q.number) = quest_history.quest_slug)
```

## 검증

다른 길드 DB (사용자가 quest 파일 삭제한 상태) → reindex 다시 시도 → 통과
예상. 같은 working tree 에서 cargo test -p openguild-core 전체 통과 확인.

## 향후 (이 quest 범위 외)

- `quest_history.quest_id` 의 nullable 화 — soft / hard 양쪽 모두 history 보존 측면.
- hard-delete 시 history 정리 정책 (cascade? orphan keep?).

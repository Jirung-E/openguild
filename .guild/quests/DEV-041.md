DB / 파일 양쪽에 ts 를 `2026-05-22T13:41:10+09:00` 형식으로 저장. 기존
UTC w/o-marker 데이터는 frontend 에서 UTC 가정으로 호환.

## 원인 (개선 전)

- SQLite `datetime('now')` 는 UTC 시각을 TZ 마커 없이 저장 (`2026-05-22 04:41:10`).
- JS `new Date("2026-05-22 04:41:10")` 는 로컬로 해석 → KST 환경에서 9 시간 어긋남.
- `formatRelative` (방금 / X시간 전) 가 어긋난 차이를 그대로 노출.

## 구현 (2026-05-22)

### 신규 모듈
- `core::time::now_local_iso8601()` — `chrono::Local::now().to_rfc3339_opts(Secs, false)`
  → `2026-05-22T13:41:10+09:00` (작성자 TZ 보존).
- `core::time::normalize_legacy_ts(s)` — legacy `"YYYY-MM-DD HH:MM:SS"` →
  `"YYYY-MM-DDTHH:MM:SSZ"`. 이미 ISO 형식이면 그대로.

### Migration `0005_timestamps_iso8601.sql`
- 기존 행의 `quests.{created_at,updated_at,deleted_at}` 와 `quest_history.ts`
  중 legacy 형식만 UTC ISO 로 정규화 (length=19 + 11번째가 공백 검출).
- Idempotent — 이미 변환된 행은 SKIP.

### SQL 바인딩 변경
- `core::services::quests`:
  - `create`: `INSERT ... (created_at, updated_at) VALUES (?, ?)` — `now_local_iso8601()`.
  - `update / change_parent / change_status / delete / restore`: 모두 `updated_at = ?` 로 변경 + bind.
- `core::ops::quests::change_status`: `INSERT INTO quest_history (..., ts, ...)` 명시 bind.
- `core::reindex::reindex`: `.md` 의 legacy ts 를 `normalize_legacy_ts` 통과 후 db 에 기록 — 한 번 정규화한 db 가 reindex 로 되돌아가지 않도록.

### SQL 컬럼 DEFAULT
- `DEFAULT (datetime('now'))` 유지 (safety net). 새 코드 경로는 항상 명시 bind.

### Frontend (gui)
- `gui/frontend/src/lib/utils/datetime.ts::normalize(s)`:
  - TZ 마커 (`Z` / `±HH:MM` / `±HHMM`) 있으면 그대로.
  - 없으면 → 공백을 `T` 로, 끝에 `Z` 추가 (UTC 가정).
- `formatTs` / `formatRelative` 가 모든 입력 (legacy / Z / offset) 을 동일하게 처리.

### 자동 테스트 +9
- core time module +4: now 패턴 / legacy 변환 / Z 통과 / offset 통과.
- server +3: create/update timestamps + history.ts 가 TZ 마커 포함.
- frontend +2: ISO offset 입력 / 절대 시각 일치 (KST vs UTC).
- 기존 테스트들: 환경 TZ 영향 제거를 위해 fixture 를 명시적 UTC (Z) 로 변경.

## 회귀

- 기존 데이터: legacy 형식 자동 정규화. 표시상 변화 없음 (UTC → 로컬 변환 결과 동일).
- 새 데이터: 작성자 TZ 보존 (Git 식). 다른 TZ 의 사용자가 봐도 절대 시각 + 원본 TZ 둘 다 명확.
- ORDER BY ts DESC: 정규화로 모든 행이 일관 형식 → 정렬 안정.

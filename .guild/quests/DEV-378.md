## 왜 별도 퀘스트인가

[[DEV-374]]~[[DEV-377]] 로 코어는 다 됐지만 **어느 바이너리도 부르지 않는다.**
`Store::install_plugins` 를 아무도 안 부르니 링커가 rhai 와 reqwest 를 통째로
걷어내고, 사용자 입장에서는 기능이 없는 것과 같다. 우산([[DEV-373]])의 서브
퀘스트 넷은 전부 코어 안쪽이었고 배선이 빠져 있었다.

## 할 것

### `openguild plugin` 명령

동의를 남길 방법이 없으면 플러그인은 영원히 안 돈다. 코어는 **묻지 않는다** —
묻는 것은 컴포넌트 몫이고, CLI 에서는 이 명령들이 그 자리다.

```
openguild plugin list              적재 상태 — 도는 것 / 동의 대기 / scope 밖 / 깨진 것
openguild plugin allow <name>      이 플러그인 하나를 허용 (정의+스크립트 원문을 보여준 뒤)
openguild plugin revoke <name>     동의 철회
openguild plugin trust             이 길드는 다 허용
openguild plugin events            구독 가능한 이벤트 이름 목록
```

`plugin events` 는 이미 검증 오류 메시지가 가리키고 있다(“`openguild plugin
events` 로 이름을 확인하세요”) — 없으면 그 안내가 거짓말이 된다.

### CLI 실행 배선

- 길드를 연 뒤 `install_plugins(Scope::Cli, Outbound)` 를 **한 번** 부른다.
- **비대화형에서는 동의를 못 물으므로 안 돈다**(admin 기본값). 동의 대기가
  있으면 어떻게 허용하는지 한 줄 안내를 남긴다 — 왜 안 돌았는지는 알아야 한다.
- 명령이 끝나기 전에 `drain_events` 로 짧은 유예. CLI 는 곧 끝나는 프로세스라
  이걸 안 하면 전송이 도중에 끊긴다.
- 깨진 정의·전달 실패는 stderr 로. **stdout 은 오염시키지 않는다** — 파이프로
  쓰는 사람이 있다.

### 크기 실측

rhai + reqwest 가 이제 실제로 링크된다. [[DEV-376]] 에서 잰 rhai 단독
+3.0MB 위에 reqwest 가 얼마나 더 붙는지 재서 기록한다.

## 테스트 방법

- 동의 없는 플러그인이 있는 길드에서 CLI 명령이 **정상 동작**하고, 안내만 남는다.
- `plugin allow` 뒤에는 실제로 돈다(대역 서버로 수신 확인).
- `plugin list` 가 네 갈래(active / 동의 대기 / scope 밖 / 오류)를 다 보여준다.
- 플러그인이 없는 길드에서 **아무 비용도 안 는다**(sink 가 안 꽂힌다).
- 명령 종료 전에 전송이 끝난다(drain).

## 결과

이제 실제로 돈다. 정의 → 동의 → 이벤트 → rhai 가공 → HTTP POST 까지 한 줄로
이어지는 것을 테스트 길드에서 확인했다:

```
$ openguild plugin allow ai-notify --yes
✓ 허용: ai-notify
$ openguild quest new --type DEV --title "전달확인"     # 0.018s
DEV-002    [Open] 전달확인
# 대역 서버: RECEIVED: openguild {"text":"[DEV-002] 전달확인"}
```

명령이 0.018초에 끝났다 — 전달은 기다리지 않고 떠났고, 종료 직전 유예에서
나갔다.

### 크기 실측 (0.6.0 착수 전 대비)

| | 착수 전 | 지금 | |
|---|---|---|---|
| CLI (`openguild`) | 16.37 MB | 19.70 MB | **+3.33 MB (+20.3%)** |
| 서버 (`openguild-server`) | 13.47 MB | 13.52 MB | +59 KB (+0.4%) |

CLI 증가분은 rhai 가 대부분(+3.0MB — [[DEV-376]] 단독 실측)이고 reqwest 는
이미 CLI 에 있어 한계비용이 작았다. 서버가 거의 그대로인 이유는 **아직
배선되지 않아 링커가 걷어내기 때문**이다 — [[DEV-379]] 에서 다시 잰다.

### 판단 몇 가지

**`allow` 는 두 단계다.** 인자 없이 부르면 정의 JSON 과 스크립트 원문을
보여주기만 하고, `--yes` 를 붙여야 실제로 허용한다. 보지 않은 것에 동의할 수는
없다. `delete --yes` 와 같은 관례를 따랐다.

**관리 명령은 scope 를 가리지 않는다**(`load_all`). GUI 전용 플러그인의 허용도
CLI 에서 할 수 있어야 한다 — GUI 동의 UI 는 아직 없고([[DEV-379]]), scope 로
걸러 버리면 목록에도 안 나와 허용할 방법이 사라진다.

**유예는 `Drop` 에 걸었다.** `run()` 의 모든 종료 경로(에러 `?` 포함)를
지나가야 하기 때문이다. 기본 2초, `OPENGUILD_PLUGIN_DRAIN_MS` 로 조절.
시간 안에 못 끝내면 조용히 버리지 않고 stderr 에 한 줄 남긴다.

**안내는 전부 stderr.** stdout 은 파이프로 쓰는 사람이 있다. `--json` 이면
아예 안 찍는다.

### 테스트 6건 추가(CLI 124건), 되돌림 시험 4건 전부 물었다

`--yes` 게이트 제거(1건 실패) · 관리에서 scope 필터링(1) · trust 확인 제거(1) ·
종료 유예 제거(1).

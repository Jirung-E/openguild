`scripts/seed-test-data.ps1` 를 Node 스크립트로 재작성 — pwsh 는 로컬 개발
환경(mac/linux)에 기본 설치돼 있지 않아 실행 자체가 안 되고, 스크립트
자체에도 실제 이식성 버그가 있음.

## 조사 결과 (2026-08-02)
- `.ps1` = Windows 전용이라는 전제는 틀림 — `scripts/extract-release-notes.ps1`
  은 CI(`check.yml`/`release.yml`)에서 `shell: pwsh` 로 실행되는데, GitHub
  Actions 의 ubuntu/macos/windows 러너 전부 pwsh 7 이 기본 설치돼 있어 이미
  3 OS 모두 정상 동작 중(스크립트 자체 주석에도 명시). **이건 그대로 둔다** —
  CI 전용이라 로컬 개발자가 직접 돌릴 일이 없음.
- 진짜 문제는 `scripts/seed-test-data.ps1`(로컬 개발자가 GUI 수동 테스트용
  으로 직접 실행하는 스크립트, `.guild/rules/test-data-script.md` 참조):
  1. 로컬 mac/linux 엔 pwsh 자체가 기본 설치 안 됨(이 세션 중 Mac 에서
     `pwsh not found` 확인). 별도 설치(`brew install --cask powershell` 등)
     필요 — 미문서화 상태.
  2. `Resolve-OpenguildBin` 이 `-BinDir` 지정 시 무조건 `openguild.exe` 로
     찾음 — mac/linux 바이너리는 확장자 없어 실패.
  3. 임시파일 경로에 `$env:TEMP` 사용(Windows 전용 환경변수, mac/linux 엔
     비어있음) — 같은 파일 안 다른 곳은 이미 크로스플랫폼인
     `[System.IO.Path]::GetTempPath()` 를 써서 일관성도 없음.

## 결정 (사용자 확인 완료)
Rust 서브커맨드로 옮기는 대신 Node 로 재작성하기로 함 — 이 스크립트는
신규 기능마다 갱신해야 하는(운영 규칙에 명시) 자주 손대는 스크립트라
"고칠 때마다 cargo build 재컴파일"이 반복 비용이 큼. Node 는 컴파일 스텝이
없고, `gui/frontend` 빌드 때문에 이미 필수 의존성이라 새 설치도 불필요.

## 구현 방향
- `scripts/seed-test-data.mjs` (또는 `.js`) 로 재작성. 순수 Node 내장
  모듈(`child_process`, `fs`, `path`)만 사용해 `npm install` 조차 불필요하게.
- 기존과 동일하게 이미 빌드된 `openguild` 바이너리를 서브프로세스로 호출하는
  구조 유지(child_process.spawnSync 등) — core 라이브러리 직접 호출 아님.
- 위 이식성 버그 2개(`.exe` 하드코딩, `$env:TEMP`) 자연히 해소.
- `.guild/rules/test-data-script.md` 의 실행 방법(`pwsh -File ...`)도
  `node scripts/seed-test-data.mjs ...` 로 갱신 필요.
- 기존 11 단계 시딩 로직(quest/campaign/댓글/메모/첨부/규칙/도서관/worklog/
  백업 등)은 그대로 포팅 — 신규 기능 추가 없음, 순수 언어 이식.
- `scripts/extract-release-notes.ps1` 은 건드리지 않음(CI 전용, 이미 정상).

## 구현 완료 (2026-08-06)

`scripts/seed-test-data.mjs` 신설(순수 Node 내장 모듈만, npm install 불필요),
`scripts/seed-test-data.ps1` 삭제. 이식성 버그 2개(`.exe` 하드코딩, `$env:TEMP`)
는 애초에 Node 로 옮기면서 자연히 없어짐 — mac/linux/윈도우를
`process.platform`/`os.tmpdir()` 로 정상 분기. `.guild/rules/test-data-script.md`
의 실행법도 갱신 — 겸사겸사 이전부터 실제 스크립트와 어긋나 있던 문서
오류 2개도 같이 고쳤다(문서에만 있고 구현된 적 없는 `OPENGUILD_BIN` env
override 설명 제거, 단계 수 10→11 표기 정정 — 백업 스냅샷 단계가 표에서
누락돼 있었음). `docs/architecture.md` 의 파일 트리 참조도 갱신.

기존 11단계 로직은 전부 그대로 포팅(신규 기능 추가 없음) — quest 생성 12개
+ cross-link 데모, 캠페인 13개(active 5 + upcoming 7 + future 1) + 체크리스트,
캠페인↔퀘스트 연결, 관계/태그/soft-delete/템플릿, 댓글/메모/첨부 3종,
규칙 3개+변경이력 데모, 도서관 3개+폴더+cross-link, worklog 노트 2개,
백업 스냅샷 1개.

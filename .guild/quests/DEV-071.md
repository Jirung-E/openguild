DEV-034 가 로컬 빌드 (cargo tauri build) 까지. 자동 배포 (tag v* 푸시 → CI 가 windows-latest runner 에서 NSIS 빌드 → GitHub Release 자동 생성 + setup.exe 첨부) 는 별도. .github/workflows/release.yml 작성 + Swatinem/rust-cache 적용 + softprops/action-gh-release 사용. 첫 tag 전에 workflow_dispatch 로 빈 release 만들어 dry-run 권장. 코드 사이닝 / multi-arch / macOS-Linux matrix 는 후속.

## 구현 (2026-05-25)

### `.github/workflows/release.yml`
- 트리거 2개:
  - `push: tags: ['v*']` — 전체 파이프라인 (빌드 + Release 생성).
  - `workflow_dispatch` — 수동 trigger. 빌드만, Release 생성 안 함.
    Artifact 로 setup.exe 업로드 (7일 보관) — dry-run 검증.
- `permissions: contents: write` — softprops/action-gh-release 가 Release
  생성하려면 필수.
- Single job `windows` on `windows-latest`. 단계:
  1. checkout v5.
  2. setup-node v5 (Node 20, npm cache).
  3. dtolnay/rust-toolchain@stable.
  4. **Swatinem/rust-cache@v2 with `cache-bin: true`** — `target/` +
     `~/.cargo/{registry,git,bin}` 캐시. `cache-bin` 이 핵심 — tauri-cli
     (~5분 install) 도 캐싱 대상이라 첫 run 후 빨라짐.
  5. `npm ci` (gui/frontend).
  6. `cargo build --release -p openguild-cli -p openguild-server` —
     NSIS template 이 `..\..\openguild{,-server}.exe` 참조하므로
     `cargo tauri build` 보다 먼저 두 binary 가 `target/release/` 에 있어야 함.
  7. `cargo install tauri-cli --version '^2' --locked` — cache hit 시 skip.
  8. `cd gui && cargo tauri build` — beforeBuildCommand 가 frontend dist 생성.
  9. `actions/upload-artifact@v4` — 항상 upload (dry-run 도 검증 가능).
  10. `softprops/action-gh-release@v2` — `if: startsWith(github.ref, 'refs/tags/')`
      조건. tag push 일 때만 Release 생성, `generate_release_notes: true`
      로 commit log → notes 자동 생성.

### 릴리즈 절차 (사용자)
```bash
# 1) 버전 bump (두 파일 같이)
#    - gui/tauri.conf.json::version
#    - gui/Cargo.toml::version  (sync)
# 2) commit
git add -A && git commit -m "chore: bump v0.1.1"
# 3) tag + push
git tag v0.1.1
git push origin develop --tags
# 4) GitHub Actions 가 빌드 (첫 run ~10분 / 캐시 hit 후 ~3-5분).
#    Release 페이지에 OpenGuild_0.1.1_x64-setup.exe 첨부됨.
```

### dry-run (첫 tag 전 검증)
- GitHub → Actions → release workflow → "Run workflow" → branch 선택 → 실행.
- 빌드 완료 후 workflow run 의 Artifacts 섹션에서 setup.exe 다운로드해서
  로컬 검증. Release 는 생성 안 됨.

### 한계 / 후속 (이 quest 범위 외)
- **코드 사이닝**: setup.exe / 설치된 exe 모두 unsigned. Windows
  SmartScreen 의 "알 수 없는 게시자" 경고. 정식 release 시 EV 인증서
  필요 (별도 quest).
- **multi-arch**: 현재 x64 만. arm64 는 matrix 확장.
- **macOS / Linux**: matrix 확장 + 각 OS 별 캐시 / 빌드 단계.
- **auto-updater (DEV-063)**: Release 첨부에 `latest.json` 추가 필요.

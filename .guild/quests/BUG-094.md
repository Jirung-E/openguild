사용자 보고: "서버 --help에서 퀘스트 추적번호가 설명으로 나오고있다. 근데
테스트는 통과했다. 이걸 막는 테스트는 cli에만 있는건지?"

## 원인

`server/src/main.rs` 의 `Command::Host::bind` 필드 `///` doc comment 에
DEV-195 quest id 가 그대로 들어가 있었음(이번 세션에서 `--bind` 옵션
추가 시 실수). clap 은 `///` doc comment 를 그대로 `--help` 텍스트로
렌더링하므로 `openguild-server host --help` 가 "DEV-195 후속(admin
피드백): ..." 를 그대로 노출.

BUG-016 이 동일한 문제(quest id 가 CLI help 로 leak)에 대한 회귀
가드(`help_output_has_no_quest_id_leaks`)를 이미 만들어뒀지만, **그
테스트는 `cli/src/main.rs` 의 `Cli::command()` 만 스캔** — `openguild`
(CLI) 바이너리 전용이고 `openguild-server` 바이너리의 `Cli`는 완전히
다른 struct(별도 crate) 라 전혀 검사 대상이 아니었음. 그래서 사용자가
지적한 그대로: "테스트는 통과했다"(CLI 쪽 테스트는 CLI 만 봤으니 당연히
통과) — server 쪽엔 동등한 가드 자체가 없었음.

## 수정

- `server/src/main.rs` 의 `bind` 필드 doc comment 에서 quest id 제거,
  일반 `//` 주석으로 분리(BUG-016 의 기존 패턴과 동일).
- `server/src/main.rs::cli_tests` 에 `help_output_has_no_quest_id_leaks`
  + 헬퍼(`check_help_recursive`/`find_quest_id`) 를 **새로 추가** —
  `cli/src/main.rs` 의 동명 테스트와 동일 로직(별도 crate 라 공유 X,
  복붙 후 server 의 `Cli`로 교체). 이제 두 바이너리 모두 같은 회귀
  가드를 가짐.

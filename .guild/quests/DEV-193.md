출처: DEV-161 결정 필요 항목. server=host 전용(DEV-163/165) 이후 HTTP admin 라우트가 CLI/core 일부 기능과 갭. 핵심: frontend 가 호출하는 types/statuses 조회 라우트가 HTTP(server)에 없어 브라우저/원격 모드가 깨짐. 결정+조치 필요: (a) 데스크탑(Tauri) 전용으로 확정하고 브라우저 모드에서 admin/해당 호출 비활성화 + 문서화, 또는 (b) HTTP 파리티 — 누락 라우트(types/statuses 등) 추가. 최소 types/statuses 갭은 둘 중 하나로 해소해야 함.

## 해소 — (b) HTTP 파리티로 결정

사용자 보고로 정확한 증상 확인: 127.0.0.1 admin 페이지 접속 시
`status 목록 조회 실패: SyntaxError: Unexpected token '<', "<!doctype "...`.
원인: frontend 의 `adminApi.listStatuses()`/`listTypes()` 가 `GET
/api/admin/statuses` / `GET /api/admin/types` 를 호출하는데, server 에는
**읽기 전용** `/api/quest-types` / `/api/quest-statuses` 만 있고
`/api/admin/types` / `/api/admin/statuses` (CRUD, Tauri invoke
`admin_list_types` 등과 1:1 대응되어야 할 경로) 자체가 라우터에 없었음 —
매칭 안 되는 요청이 SPA fallback(index.html, 200)으로 떨어져 JSON.parse 가
HTML 을 받아 깨짐.

수정 — `server/src/routes/meta.rs` + `mod.rs`: gui/src/commands.rs 의
`admin_list_types` / `admin_create_type` / `admin_update_type` /
`admin_delete_type` / `admin_list_statuses` / `admin_create_status` /
`admin_update_status` / `admin_delete_status` 와 1:1 대응하는 HTTP 핸들러
추가(같은 `openguild_core::ops::meta` 함수 재사용, 로직 중복 없음).
라우트: `GET/POST /api/admin/types`, `PATCH/DELETE
/api/admin/types/{prefix}`, `GET/POST /api/admin/statuses`,
`PATCH/DELETE /api/admin/statuses/{slug}` — transport.ts 의
`routeToInvoke` 매핑 그대로.

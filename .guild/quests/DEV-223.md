사용자 피드백(2026-07-04) 2건 — [[ 컨텍스트 자동완성 UX.

## 구현 (2026-07-04)
1. **빈 [[ 트리거**: editor-links(CM)의 'explicit 호출만' 가드와 textarea-wikilink 의 'partial<1 → null' 가드 제거 — [[ 입력 즉시 전체 후보(id 정렬) 표시.
2. **auto-close ]] 중복 방지**:
   - CM: 문자열 apply(`insert]]`) → 함수형 apply — 커서 뒤가 이미 `]]` 면 재사용(삽입 생략)하고 커서만 닫힘 뒤로 이동. closeBrackets 의 [[→]] 자동삽입과 공존.
   - textarea(applyWikiLink): 치환 범위 바로 뒤 `]]` 면 함께 삼켜 치환 — 닫힌 링크 안 재완성도 중복 없음.
3. 테스트: 빈 [[ = 전체 후보(기대값 반전, 치환 범위 [[ 포함 확인).

## 테스트 방법
1. 본문 편집기(CM)에서 `[[` 입력 → **즉시 팝업**(전체 후보) + auto-close 로 `]]` 가 이미 있는 상태에서 후보 선택 → **`[[DEV-001]]` 정확히**(`]]]]` 없음) + 커서가 닫힘 뒤.
2. auto-close 없이(붙여넣기 등으로 `[[abc` 만 있는 상태) 후보 선택 → `]]` 정상 삽입.
3. 댓글 textarea 에서 `[[` → 팝업, 선택 삽입 정상 + Ctrl+Z 로 되돌리기 동작(undo 보존 회귀).
4. 규칙 편집기/메모에서도 1 동일(공통 확장).
5. cd gui/frontend && npm run check && npm test -- --run.

## 추가 재현/관찰 (2026-07-18, BUG-146 작업 중)

원래 이 퀘스트는 "GUI 시동 sync" 로 좁혀 적었으나, 이번 세션에 **CLI
명령만으로도 동일 오염이 재현**됨을 확인. 즉 GUI 전용이 아니라 리포
길드를 여는 **모든 openguild 경로(CLI 포함)의 sync** 가 원인.

관찰:
- `git restore` 로 17개(BUG-137, DEV-015/205/211/228/229/241/247/248/
  249/250/252/254/255/258/259, REQ-001)를 깨끗이 되돌린 직후,
- 리포 디렉토리에서 `openguild quest start / new / update / move` 를
  실행하자 **같은 17개의 `updated_at` 이 다시 일괄 변조**(내용 변경 0,
  순수 타임스탬프)됨.
- 이번 세션에서만 이 restore→CLI 실행→재오염 사이클을 2회 겪음.

시사점:
- BUG-103 의 내용 비교 게이트(`is_content_identical_to_db`)가 실제
  CLI/GUI 가 타는 sync 경로에서 **실질적으로 안 먹히는 것으로 보임**.
  게이트가 호출되긴 하는지, 아니면 restore 후 파일 mtime < DB cached_mtime
  상황에서 다른 분기로 write-back 되는지 확인 필요.
- 특히 `git restore` 로 파일을 과거 상태로 되돌리면 파일 mtime 이 DB
  cached_mtime 보다 **뒤처지는데**, 이 "파일이 캐시보다 과거" 케이스의
  처리(refresh_quest_if_stale 의 else 경로에서 cached_mtime 을
  max(file,cached) 로 둔다던 로직 포함)를 재점검할 것.

재현 절차:
1. `git status` 클린 상태(또는 위 17개를 restore).
2. 리포에서 `openguild quest list` 등 아무 명령 1회 실행.
3. `git status` 에 무관한 quest `.md` 대량 diff(순수 updated_at) 확인.

[[DEV-430]] 의 3단계 — 변경 함수를 길드 독점에서 **문서 잠금**(`lock_docs`)으로 옮긴다.

## 문서 단위

"문서" 는 사람이 보는 한 덩이다 — 퀘스트 DEV-1 은 본문 · 댓글 · 메모 · 이력 파일을 한 문서로 본다. 열쇠:
`quest:DEV-1` · `campaign:C-1` · `book:BOOK-1` · `rule:{slug}` · `template:{이름}` · `worklog:{날짜}`, 그리고
길드에 하나뿐인 것(`positions` · `library-folders` · 타입별 번호 `counter:DEV`).

## 순서

1. **한 문서만** 건드리는 것부터 — 댓글 · 메모 · 태그 · 본문 · 제목 · 규칙 · 도서관 문서.
2. **여럿** — 퀘스트 만들기(번호 + 새 문서 + 부모의 자동 블록), 삭제(하위 · 선행 퀘스트의 자동 블록),
   부모 · 선행 바꾸기. 잠근 뒤 "건드릴 목록이 그새 바뀌지 않았나" 를 다시 보고, 바뀌었으면 다 풀고 다시.
3. **길드 전체** — 타입 · 상태 이름 바꾸기처럼 모든 퀘스트를 고치는 것은 **독점 그대로**.

`lock_coverage` 시험의 표에 함수마다 무엇을 잠그는지 적고, 시험이 그것을 강제한다.

## 시험 · 측정

- 서로 다른 퀘스트에 동시에 댓글 → 둘 다 기다리지 않고 된다. 같은 퀘스트면 줄 선다(둘 다 남는다 — BUG-287
  이 막은 유실이 안 돌아온다).
- 바꾸기 전후로 변경 한 번의 시간, 동시 변경이 기다리는 시간을 잰다.

## 한 것 (2026-10-01)

- **변경 함수 전부**를 옮겼다 — `lock_coverage` 표에 함수마다 **길드 독점(Guild) / 문서 잠금(Docs)** 을 적고,
  시험이 적은 대로 잠그는지 본다(틀리게 적으면 실패하는 것 확인). `Store::mutation_guard` 는 없앴다.
  - 문서 잠금: 퀘스트 댓글 · 메모 · 본문 · 기한 · 태그 · 상태 · 부모 · 선행 · 지우기 · 되살리기 · 만들기,
    캠페인과 그 댓글 · 체크리스트 · 배너 · 연결, 도서관 문서 · 태그 · 만들기, 폴더 만들기, 규칙, 보드 위치,
    일지, 첨부.
  - 길드 독점: 타입 · 상태 · 태그 정의(meta 전부), 타입 바꾸기, 규칙 이름 바꾸기, 도서관 폴더 옮기기 · 지우기,
    번호 맞추기.
- 번호(행 id)만 받는 변경은 `ops::lock_resolved` — 고칠 문서를 알아내 잠그고, 잠근 뒤 다시 알아내 같은지 본다.
  다르면 다시, 네 번 넘으면 길드 독점.
- 부모 · 선행을 바꾸는 변경(부모 바꾸기, 선행 더하기, 지우기, 되살리기)은 `quest-tree` 를 함께 잡는다 — 각자
  제 문서만 잠그면 따로는 괜찮은 두 변경이 합쳐 고리를 만든다.
- 새로 번호를 받는 것은 번호 열쇠(`counter:DEV`, `counter:campaign`, `counter:book`)를 잡는다.
- **캐시 DB 쓰기 트랜잭션을 `BEGIN IMMEDIATE` 로**(`db::begin_write`, 19곳) — 보통 `BEGIN` 은 동시에 쓰면
  기다리지 않고 바로 실패한다(시험으로 보임).
- **플러그인의 기다리는 줄을 작업별로** — 한 줄에 모으면 먼저 끝난 변경이 아직 잠금을 쥔 남의 줄을 돌린다
  (고치기 전 코드에서 실패하는 시험).
- BOOK-006 잠금 부분을 지금 모습으로 새로 썼다. BOOK-003 · 007 의 `mutation_guard` 언급도 고쳤다.

## 시험

- 다른 퀘스트를 쥔 동안 댓글이 기다리지 않는다 / 같은 퀘스트면 기다리고 둘 다 남는다(BUG-287 유실 없음).
- 옛 부모 · 새 부모 어느 쪽을 쥐어도 부모 바꾸기가 기다린다.
- 잠근 뒤 목록이 바뀌면 다시 잡고, 계속 바뀌면 길드 독점으로 간다.
- 겹치는 쓰기 트랜잭션이 기다렸다 둘 다 된다.

## 측정 (릴리스 빌드, 각 3번)

| | 전(develop) | 후 |
|---|---|---|
| 댓글 하나 | 1.2~1.7ms | 1.3~1.4ms |
| 서로 다른 퀘스트 16개에 댓글 64개 동시 | 132~143ms | 96~106ms |

동시 변경은 30% 남짓 줄었다 — 캐시 DB 와 journal 이 한 번에 한 쓰기만 받는 것이 남은 병목이다. 큰 이득은
**한 문서를 오래 쥔 변경이 다른 문서를 막지 않는 것**이다.

## 테스트 방법

평소처럼 앱과 CLI 를 함께 써 본다 — 앱에서 한 퀘스트에 댓글을 다는 동안 CLI 로 다른 퀘스트를 고치는 식.
멈추거나 "바쁨" 오류가 나거나 댓글 · 태그가 사라지지 않으면 정상.

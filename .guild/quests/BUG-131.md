admin 보고 (BUG-125 후속): 이모지 팝업이 스크롤을 이동해도 따라오지 않는다.
"자동완성 팝업이랑 같은 방식"이라고 했는데 실제로는 그 부분이 빠져있었음.

## 원인
BUG-125 에서 `.reaction-picker` 를 `position:fixed` + 버튼의
`getBoundingClientRect()` 로 위치를 계산하도록 바꿨지만, 그 계산을 팝업을
"여는 시점"에 딱 한 번만 했다. 자동완성 팝업(wiki 팝업)은 `repositionWiki`
가 window 의 scroll(capture)/resize 이벤트마다 트리거 위치를 다시 계산해
따라오는데, 이모지 팝업엔 그 부분을 안 만들고 resize 시 팝업을 그냥
닫아버리기만 했음 — "같은 방식" 이라는 설명과 실제 구현이 달랐음(내 실수).

## 수정
트리거 버튼 엘리먼트를 `reactionPickerBtn` 으로 기억해두고, 팝업이 열려
있는 동안 window 의 scroll(capture:true — 조상 스크롤 컨테이너 포착)/resize
이벤트마다 그 버튼의 최신 `getBoundingClientRect()` 로 위치를 재계산 —
wiki 팝업의 `repositionWiki` 와 동일 패턴.

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`.
- 실기: 댓글이 많아 목록이 스크롤되는 상황에서 이모지 팝업을 연 채로
  목록을 스크롤 → 팝업이 버튼을 따라 같이 움직이는지(자동완성 팝업과
  동일하게).

`run` 훅이 실패하면 앱의 '문제' 칸에는 이것만 뜬다.

```
플러그인 'discussion-to-ai' 토론 전달 — powershell 가 exit status: 1 로 끝났습니다
```

**자식이 한 말은 버린다.** `delivery::run` 이 `stdout`/`stderr` 를 둘 다 `Stdio::null()` 로
꽂기 때문이다(CLI 표준출력에 섞이면 파이프로 쓰는 사람이 깨진다는 이유였다).

그래서 같은 곳에서 두 번 막혔다(admin).

- BUG-332 — 실제 원인은 claude 로그인이었는데 그 안내가 안 보이고 `exit code: 1` 만 보였다.
- BUG-335 — 실제 원인은 명령이 답을 아무 데도 안 넘기는 것이었는데 역시 안 보였다.
  재현에서 `delivered.log` 에는 `no .guild file at ...` 이 그대로 있었다.

예제는 스스로 `delivered.log` 에 남기지만 그건 **예제가 친절해서**다. 코어가 안 해 주면
플러그인마다 다시 만들어야 하고, 영수증을 안 남기는 플러그인은 영영 이유를 못 본다.

## 하려는 것

자식의 출력 끝부분(몇 줄)을 모아서 실패 메시지에 붙인다. `Stdio::null()` 대신 파이프로
받되 **CLI 표준출력으로는 안 흘린다** — 문제 목록에만 넣는다. 길이는 잘라야 한다(빌드
로그 통째로는 아무에게도 도움이 안 된다).

시한 초과로 죽일 때도 그때까지 나온 것을 같이 남기는 편이 낫다 — 지금은 "안 끝나 중단했습니다"
뿐이라 무엇을 하다 멈췄는지 알 수 없다.

## 고침 (2026-10-04)

- 자식의 stdout · stderr 를 버리지 않고 **받아 둔다**(CLI 표준출력으로는 여전히 안 흘린다). 각각 마지막 4KB 만 쥐고, 계속 읽어
  출력이 많은 훅이 통로가 가득 차 멈추지 않게 한다.
- 실패하면(0 아닌 종료 · 시한 초과) 메시지 끝에 **마지막 8줄**을 붙인다 — stderr 가 있으면 그것, 없으면 stdout.
  예: `powershell 가 exit status: 1 로 끝났습니다 — 마지막 출력(stderr):\n  로그인이 필요합니다`.
- 끝난 뒤 출력은 0.2초만 더 기다린다 — 훅이 남긴 백그라운드 프로그램이 통로를 붙잡아도 전달이 멈추지 않게.

## 시험

- 실패한 훅의 stderr 끝줄이 보이고, 앞부분 · stdout 은 안 붙는다 / stderr 가 비면 stdout 을 붙인다 / 2만 줄 찍는 훅이 멈추지도
  실패하지도 않는다 / 시한 초과 때 그때까지의 말이 붙는다. 앞의 셋은 고치기 전 코드에서 실패.

## 테스트 방법

1. 플러그인 하나의 `run` 명령을 일부러 틀리게 한다(예: discussion-to-ai 의 AI_COMMAND 를 없는 명령으로).
2. 그 훅이 도는 일을 한다(토론 댓글).
3. 앱의 관리 → 플러그인 문제 칸에 "… 로 끝났습니다 — 마지막 출력(stderr):" 과 그 명령이 한 말(예: 찾을 수 없다는 오류)이 보이면 정상.

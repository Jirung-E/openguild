## 배경

admin 이 설정의 '업데이트 자동 확인' 토글이 **다른 컴포넌트와 다른 속도로**
커진다고 보고했다. 원인은 `font-size` 는 rem 인데 `padding`·`gap` 만 px 인
것이었다 — 글자만 커지고 여백은 그대로라 비율이 어긋난다.

그 토글과 쌍둥이인 퀘스트 목록 보기 토글은 [[BUG-254]] 에서 함께 고쳤다.
**같은 부류가 더 남아 있어** 여기 정리한다.

## 전수 조사

`padding` / `gap` / `margin` 계열이 px 인 곳 — 총 **75건**.

| 구분 | 건수 | 처리 |
|------|------|------|
| `QuestBoard` 노드 내부 | 44 | **건드리면 안 됨** — px 섬([[DEV-369]]). `NODE_W/NODE_H` JS 상수와 짝 |
| `TitleBar` 창 크롬 | 4 | **일부러 px** — OS 가 정한 치수([[BUG-246]]) |
| 나머지 | **27** | 이 퀘스트 대상 |

## 눈여겨볼 것 — 서로 짝인 값이 있다

`QuestList` 의 떠 있는 '새 퀘스트' 버튼(`top: 10px; right: 14px`)과
`QuestListFilter` 의 `padding: … 130px …`(DEV-086 이 그 버튼 자리를
예약해 둔 것)은 **한 쌍**이다. 한쪽만 rem 으로 바꾸면 배율에서 버튼이
필터 위로 올라타거나 자리가 과하게 남는다. 같이 바꾸거나 같이 둬야 한다.

`QuestListFilter` 의 `margin: -1px` 은 테두리 겹침 보정으로 보인다 —
`calc(-1 * var(--bw))` 가 맞는지 확인이 필요하다.

## 검사가 없다

`check:radius` 가 곡률·테두리를 막지만 **간격은 안 본다.** [[DEV-369]] 가
겪은 대로, 검사 없이 치환만 하면 다음 커밋부터 다시 섞인다. 치환과 함께
`check:spacing` 류를 붙이고 예외(보드 노드 / 타이틀바)를 ALLOW 에
등록해야 한다.

## 정할 것

1. 27건 전부 바꿀지, 눈에 띄는 것만 할지. 대부분 1~4px 짜리 미세 여백이라
   기본 배율에서는 차이가 안 보이고 200% 에서만 드러난다.
2. 위 '짝인 값' 두 건을 어떻게 다룰지.

## 테스트 방법

설정에서 UI 배율을 50% / 100% / 200% 로 바꿔가며, 여백이 있는 컴포넌트가
**주변과 같은 비율로** 커지는지 본다. 특히 세그먼트 토글, 날짜 선택,
캠페인 카드, 퀘스트 목록의 떠 있는 버튼.

## 범위 확대 — 여백만이 아니라 **치수**도 (admin 보고 2건째)

> 캠페인 진행도 표시의 굵기가 안변함

같은 뿌리다. 진행도 바의 **두께**가 px 이라 배율을 안 따라갔다. 곡률
(`--r-xs`)은 rem 이라 함께 커지는데 두께만 그대로여서, 배율을 올리면 바가
과하게 둥근 실선처럼 보였다.

진행도 바는 네 곳에 같은 패턴으로 있어([[BUG-254]] 에서 함께 수정) —
홈/목록 카드 `.progress-bar`(4px), 캠페인 목록 `.prog-bar`(4px), 캠페인 상세
`.quest-progress-bar`(6px), 첨부 업로드 `.up-bar`(3px).

**남은 얇은 px 치수** (이 퀘스트 대상에 추가):

| 위치 | 값 | 성격 |
|------|-----|------|
| `CustomSlider` `.track` | `height: 4px` | 설정의 슬라이더 — **UI 배율 슬라이더 자신이 여기 해당** |
| `CustomSlider` `.thumb` | `14px` 정사각 | 위와 한 쌍 |
| `CampaignCarousel` `.dot` | `8px` 정원 | 홈 캐러셀 페이지 점 |

**계속 px 로 둘 것**: 스크롤바(`global.css`, 폭이 네이티브 위젯 치수),
`QuestListFilter` 의 `1px` 정사각(스크린리더 전용 숨김 요소).

즉 이 퀘스트는 "여백" 이 아니라 **"배율을 안 따라가는 px 치수 전반"** 이다.

## 정한 것 — 전부 바꿨다

"눈에 띄는 것만" 이 아니라 **전부**로 갔다. 1~4px 짜리는 기본 배율에서 안
보이지만, 이 퀘스트가 존재하는 이유가 "배율을 올렸을 때 비율이 어긋난다" 이므로
남겨 두면 같은 보고가 다시 온다. [[BUG-254]] / [[DEV-369]] 와 같은 판단.

짝인 값 두 건도 **같이** 바꿨다(아래 참조).

## 조사가 틀렸던 곳 — 보드의 px 가 전부 '노드 섬'은 아니었다

앞선 조사는 `QuestBoard` 의 px 44건을 통째로 "건드리면 안 됨" 으로 묶었다.
실제로 열어 보니 셋이 섞여 있었다:

| 구분 | 성격 | 처리 |
|------|------|------|
| `.board-node` / `.node-*` | `NODE_W`/`NODE_H`(JS 상수)로 좌표를 계산 | px 유지 |
| `:global(.lane-*)` | 헤더 높이가 JS 의 `LANE_TOP=52` 와 정렬 | px 유지 |
| 노드 상세 카드 `.card-*` / `.hl-*` | px 캔버스 위에 노드 좌표 기준으로 뜸 | px 유지 |
| **툴바 / 필터칩 / HUD** | **순수 화면 UI, 기하와 무관** | **rem 으로 변경** |

마지막 칸이 중요하다. 보드 툴바의 '새 퀘스트' 버튼은 목록 뷰의 같은 버튼과
**치수가 같아야 한다**([[DEV-086]] — 보드↔목록 전환 시 안 흔들리게). 목록 쪽만
rem 으로 바꿨다면 배율에서 짝이 깨졌을 것이다. `QuestListFilter` 의 우측 예약
폭(130px → 8.125rem)까지 같은 한 벌이라 셋을 함께 옮겼다.

## 토큰이 맞는 곳 둘 — rem 이 아니라

- `QuestListFilter` 의 `margin: -1px` → `calc(-1 * var(--bw))`. 상쇄해야 할
  대상이 테두리 두께이므로 그 토큰을 그대로 써야 한다.
- `QuestBoard` 의 `.tb-sep { width: 1px }` → `var(--bw)`. 세로 헤어라인이다.

## 검사 — 파일 통째 예외 대신 **구간 표시**

`check:spacing`(`scripts/check-raw-spacing.mjs`)을 붙였다.
`check:radius` 와 달리 예외를 ALLOW 목록에 몰아넣지 않고, 소스에 직접 표시한다:

```css
/* check-spacing:off — 왜 px 인지 */
…
/* check-spacing:on */
```

이유가 **그 자리에** 남고, 표시를 지우면 곧바로 검사 대상이 되므로 섬이
조용히 넓어지지 않는다. 실제로 그렇게 되는지 확인했다 — 노드 섬의 off 표시
하나를 무력화하면 그 안의 15건이 즉시 드러난다.

검사가 안 보는 것: `@media` 조건절(중단점은 px 가 맞다), `0px`,
`var()`/`calc()` 안의 px(값은 토큰이 정한다).

## 검증 — 실측

루트 font-size 를 16 → 32(200%) / 8(50%) 로 바꿔가며 쟀다.

| 대상 | 50% | 100% | 200% |
|------|-----|------|------|
| 목록 '새 퀘스트' 버튼 | 42×15 | 83×30 | 166×61 |
| 그 padding | 2px 5px | 4px 10px | 8px 20px |
| 필터 우측 예약 | 65px | 130px | 260px |
| **보드 노드** | **112×32** | **112×32** | **112×32** |
| **레인 헤더 높이** | **38** | **38** | **38** |

- 정확히 비례한다(100% 값은 변경 전과 **동일**하다 — 환산이 정확했다는 뜻).
- 보드 툴바 버튼도 166×61 로 목록 쪽과 **숫자가 같다**(DEV-086 유지).
- 노드·레인은 배율과 무관하게 그대로다 — admin 의 "노드는 크기가 변하면
  안된다" 가 지켜진다.

`just test` 전부 통과(Rust 789 / 프론트 530 / 가드 4종).

**미리보기로 못 본 것**: 설정의 `CustomSlider`(track 4px→0.25rem, thumb
14px→0.875rem)와 `CampaignCarousel` 의 점(8px→0.5rem). 각각 데스크톱 전용
화면과 캠페인이 있어야 그려지는 것이라 이 환경에서 렌더되지 않았다. 리터럴
치환이라 값 자체는 확실하지만 눈으로는 확인이 필요하다.

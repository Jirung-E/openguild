## 코드 재검토 + 로직 격리 테스트 (설치 없이)

설치 프로그램을 실제로 돌리지 않고 검증할 방법이 있었다. `installer.nsi` 의
`SetSectionSelected` 매크로와 `RestoreComponentSelection` 함수를 **그대로 옮긴**
NSIS 하네스를 makensis(Tauri 동봉본)로 컴파일해, 섹션이 파일을 설치하는 대신
자기 이름만 로그에 남기게 했다. 스크래치 HKCU 키 + 임시 폴더만 사용하고 끝나면
지운다.

| 시나리오 | 실행된 섹션 |
|---|---|
| 업데이트 · 마커 CompCli/CompServer=1, 파일 없음 | GUI CLI **SERVER** |
| 업데이트 · 마커 없음 · 파일 CLI+SERVER 존재 (구버전 fallback) | GUI CLI **SERVER** |
| 업데이트 · 마커 없음 · 파일 없음 (서버 미선택 사용자) | GUI |
| 업데이트 · 마커 없음 · CLI 파일만 | GUI CLI |
| 일반 설치(/UPDATE 없음) | GUI CLI (기본값 — 서버 미선택) |

의도대로다. 레지스트리 마커 우선, 없으면 파일 존재 fallback, 둘 다 없으면 미설치
유지. 역방향(CLI 를 뺀 사용자에게 업데이트가 CLI 를 몰래 추가하던 것)도 막힌다.

## 코드 리뷰에서 확인한 것

- `.onInit` 순서: `/UPDATE` 파싱(495) → `SetContext`(504) → `$INSTDIR` 확정
  (`RestorePreviousInstallLocation`) → **그 뒤** `RestoreComponentSelection`(538).
  파일 존재 fallback 이 올바른 `$INSTDIR` 를 본다. `INSTALLMODE` 는 currentUser
  (tauri.conf 에 installMode 미지정 → 기본값)라 SHCTX=HKCU 로 고정, MultiUser 초기화
  순서 문제 없음.
- `/UPDATE` 경로는 언인스톨러를 돌리지 않으므로(PageLeaveReinstall, 322) 마커가
  담긴 UNINSTKEY 가 지워지지 않는다. 언인스톨러가 도는 경로에서는 키를 통째로
  지우지만(998), 그때는 `.onInit` 에서 이미 선택을 복원한 뒤라 섹션이 다시 기록한다.
- 언인스톨러는 `openguild.exe` / `openguild-server.exe` 를 항상 삭제 시도(929) —
  컴포넌트 잔여물 없음.

## 남은 흠 (릴리즈 블로커 아님)

마커는 **1 만 기록하고 0 은 안 쓴다**. 언인스톨 없이 덮어쓰는 경로에서 사용자가
서버를 해제하면 `CompServer=1` 이 남아 다음 업데이트에 서버가 다시 깔린다.
정확히 하려면 섹션 비선택 시 0 기록/값 삭제가 맞다. 방향이 "있던 걸 유지" 쪽의
과설치라 무해한 편이고, 일반 재설치는 언인스톨이 키를 지워 정상 동작한다.

## 이 테스트가 커버하지 못하는 것

하네스는 로직 복사본이다. 실제 `setup.exe /UPDATE /P` 로 배포본을 덮어쓰는 경로
(Tauri 업데이터가 넘기는 인자, 파일 잠금, 서명)는 확인하지 않았다.

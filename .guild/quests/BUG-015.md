## 증상

Quest List (`/?view=list`) 에서 quest 항목 클릭 → `/quests/<id>` Detail 진입.
Detail 의 ← back 누르면 항상 `/` (Board) 로 이동. 사용자가 List 에서 들어
왔어도 Board 로 가서 다시 List 로 전환해야 하는 두 단계.

## 원인

`gui/frontend/src/routes/quests/[id]/+page.svelte` 의 back 핸들러가
하드코딩으로 `goto('/')` 또는 `goto('/?view=board')` 호출 (추정 — 코드
확인 필요).

## 수정 방향

옵션 A — **`history.back()` 사용** (가장 간단):
- 사용자가 List 에서 왔으면 history stack 의 직전 entry 가 List.
- 단점: 외부에서 직접 link 로 진입한 경우 (다른 길드 / 새 탭) 뒤로갈 곳
  없음 → fallback 필요.

옵션 B — **`referrer` / 의도 인자 추적**:
- 진입 시 `?from=list` 또는 sessionStorage 에 origin 기록 → back 시 그쪽으로.
- referrer 가 같은 origin 일 때만 신뢰.

권장: **A + fallback**.
```ts
function goBack() {
    if (window.history.length > 1) {
        history.back();
    } else {
        goto('/');
    }
}
```

## 검증

- Board → quest 클릭 → back → Board ✓.
- List → quest 클릭 → back → List ✓.
- 외부 link 로 직접 Detail 진입 → back → Board (fallback) ✓.
- 같은 quest 안에서 다른 quest 클릭 (parent / sub) → back → 직전 quest.

## 구현 (2026-05-25)

### `gui/frontend/src/routes/quests/[id]/+page.svelte`
- 권장 옵션 A + fallback 채택.
- `<a href="/" class="back">← Back</a>` → `<button class="back" onclick={goBack}>` 로 변경.
- `goBack()`:
  ```ts
  function goBack() {
      if (typeof window !== 'undefined' && window.history.length > 1) {
          window.history.back();
      } else {
          goto('/');
      }
  }
  ```
- CSS `.back` 도 button 기본 스타일 제거 (background/border/padding none).

### 검증
- `npm run check` → 0 errors (1 pre-existing warning).
- `npm test` → 116 passed.
- 라이브: Board → Detail → back = Board / List → Detail → back = List /
  외부 link → back = Board (fallback) — 사용자 검증.

## 반려 (사용자, 2026-05-25)

> 리포트한 버그가 안고쳐졌다.

즉 빌드 후 테스트해도 여전히 List → Detail → back 이 Board 로 감.

## fix1 (2026-05-25)

### 원인 (재분석)
`window.history.back()` 만으로는 SvelteKit + Tauri WebView 의 history
stack 동작이 신뢰되지 않음. 가능 원인:
- QuestList 의 view 전환 `goto(next, { replaceState: true })` (line 66)
  으로 `?view=list` 가 push 가 아닌 replace 라 history entry 동작이
  intuition 과 다름.
- WebView 의 `window.history.length` / `history.back()` 가 SvelteKit
  의 client-side router state 와 일치하지 않을 가능성.

→ history API 신뢰 포기, **query parameter `?from=list|board` 로 명시
origin 추적**.

### 변경
1. `QuestListItem.svelte` — `goto('/quests/${id}')` → `goto('/quests/${id}?from=list')`.
2. `QuestBoard.svelte::card-goto button` — `goto('/quests/${id}')` →
   `goto('/quests/${id}?from=board')`.
3. `routes/quests/[id]/+page.svelte`:
   - `goBack()` 가 history.back() 대신 `?from` query 보고 `/?view=list`
     또는 `/?view=board` 로 명시 navigate. from 없으면 `/` fallback.
   - `fromSuffix = $derived(...)` 헬퍼 추가. parent / sub / prereq link
     세 곳의 `href="/quests/{id}"` 에 `{fromSuffix}` 붙여 같은 quest
     안에서 다른 quest 클릭 후 back 도 원래 origin (list/board) 로 감.
   - rename navigate (`changeType` 후) 도 fromSuffix 보존.

### 검증
- `npm run check` → 0 errors.
- `npm test` → 116 passed.
- 라이브: Board → quest → back = Board ✓ / List → quest → back = List ✓ /
  Quest 안에서 parent 클릭 → 그 parent 의 back = 원래 origin ✓ — 사용자 검증.

## 배경

BUG-012 (write_quest_file 의 'description 보존 fallback' 제거) 의 의도된
trade-off — `.md` 파일을 외부 편집 (사용자 에디터 / CLI 가 아닌 git pull
/ AI agent 등) 후 reindex 없이 mutation 호출 시 외부 편집된 description
이 DB 의 옛 값으로 덮어쓰여짐.

실제 시나리오 (2026-05-24 발생):
1. BUG-016.md 본문을 손으로 풍부하게 채움 (외부 편집).
2. `openguild quest move BUG-016 testing` (= change_status 호출).
3. ops::change_status → write_quest_file → DB 의 옛 한 줄짜리 description
   으로 파일 덮어씀.

## 원인

`core/src/ops/quests.rs::write_quest_file` 는 항상
`quest.description.clone().unwrap_or_default()` 사용. 호출하는 mutation 이
description 을 의도적으로 바꿨는지 여부 알 수 없음. 모든 mutation 이
"DB → file 일방향 덮어쓰기".

## 수정 방향

`write_quest_file` 가 호출자로부터 "description 이 이 mutation 의 명시적
대상인지" flag 받음:

```rust
async fn write_quest_file(
    store: &Store,
    quest: &QuestRow,
    description_was_explicitly_updated: bool,
) -> AppResult<()> { ... }
```

분기:
- `true` (`update_quest({description: Some(...)})`): DB 값을 그대로 사용
  (현재 동작) — GUI 가 description 수정 → 파일 반영 (BUG-012 의 의도).
- `false` (다른 mutation — `change_status` / `change_parent` /
  `add_prerequisite` 등): 파일의 description 이 비어있지 않으면
  파일을 truth 로 사용 + DB 도 그것으로 sync (서서히 정합).
  파일이 없거나 비어있으면 DB 값.

### 호출자 수정
- `update_quest` — `body.description.is_some()` 그대로 전달.
- 다른 mutation 들 — 항상 `false`.

### DB sync
- 파일 값을 truth 로 쓸 때 `UPDATE quests SET description = ?` 도 같이 실행.
- 이렇게 하면 외부 편집한 description 이 점진적으로 DB 에도 반영 →
  명시적 reindex 안 해도 일관성.

## 회귀 방지 + 테스트

새 테스트 (`core/src/ops/quests.rs::tests`):
- `change_status_preserves_external_description` — 파일을 직접 편집해
  description 갱신 → change_status → 파일 본문 보존 + DB 도 sync 됨.
- `update_quest_description_still_overrides_file` (기존 BUG-012
  테스트 유지 보강) — 명시적 update 는 파일 덮어쓰기 그대로.

## 구현 (2026-05-25)

### `core/src/ops/quests.rs::write_quest_file`
시그니처 변경:
```rust
pub(crate) async fn write_quest_file(
    store: &Store,
    quest: &QuestRow,
    description_explicit: bool,
) -> AppResult<()>
```

분기:
- `description_explicit = true` → DB 의 `quest.description` 그대로 사용
  (`update_quest` 가 `body.description = Some(...)` 받았을 때, 또는
  create / rename 처럼 description 이 의도된 갱신 대상).
- `false` → 기존 파일 읽기:
  - 파일 description 본문이 비어있지 않으면 **그것을 파일에 다시 씀**
    + DB 와 다르면 `UPDATE quests SET description = ?` 로 sync.
  - 파일이 없거나 본문 비어있으면 DB 값 사용 (기존 동작).

### 호출자 분기
| 호출자 | flag | 이유 |
|---|---|---|
| `create_quest` 본인 | `true` | create body 가 description 명시 |
| `create_quest` 부모 (auto-block 갱신) | `false` | 부모 description 안 건드림 |
| `update_quest` | `body.description.is_some()` | **핵심 분기점** |
| `change_status` / `change_parent` / `add/remove_prerequisite` / `restore` | `false` | description 안 건드림 → 외부 편집 보존 |
| `change_quest_type` (rename) | 옛 파일에서 description 미리 sync 후 `true` | path 변경이라 새 path 에선 file→DB sync 안 통함, 옛 경로 직접 처리 |
| `meta::rename_type_prefix` cascade | 옛 파일에서 description 미리 sync 후 `true` | 같은 이유 |
| `meta::rename_status` | `false` | 같은 path 라 자동 보존 작동 |
| `meta` 의 부모/관련 갱신 | `false` | description 안 건드림 |

### 테스트 (`core/src/ops/quests.rs::tests`)
- 신규 `change_status_preserves_external_description_and_syncs_db`:
  1. quest 생성 (`description: "initial body"`).
  2. 파일을 직접 편집 (`"initial body"` → `"EXTERNALLY EDITED BODY"`).
     reindex 호출 X.
  3. `change_status` 호출.
  4. 파일에 `EXTERNALLY EDITED BODY` 보존 + `initial body` 사라짐 +
     status 변경 정상 + **DB description 도 `EXTERNALLY EDITED BODY` 로 sync**.
- 기존 `update_quest_description_writes_to_file` (BUG-012): description
  명시 update 는 여전히 DB 값으로 파일 덮어쓰기. 회귀 없음.

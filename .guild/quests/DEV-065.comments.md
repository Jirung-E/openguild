## 기능
Quest List 뷰 모드 토글 — Tree (기본, 부모 들여쓰기) / List (모든 quest 평면).

## 사용
- Quest List 페이지 (`/?view=list`) 상단 필터 바로 아래 [Tree | List] 세그멘티드 토글.
- 클릭으로 즉시 전환.
- URL `?mode=list` 동기화 (Tree 는 기본이라 생략).
- localStorage (`openguild.questListMode`) 영속.

## 차이

| Tree | List |
|------|------|
| 부모 아래로 자식 들여쓰기 | 모든 quest 평면 |
| 검색 결과의 조상 자동 포함 + 펼침 | 매칭된 quest 만 |
| 폴드/펼치기 chevron | 단일 row |

## 테스트
1. `/?view=list` → Tree 모드 (기본).
2. List 클릭 → 모든 quest 평면. 부모/자식 구분 없음.
3. URL 에 `?mode=list` 추가됨.
4. 새로고침 → List 유지 (URL + localStorage).
5. `?view=list&mode=tree` 직접 입력 → Tree.
6. 검색 입력 → List 모드는 매칭된 것만, Tree 모드는 조상 자동.

## 한계 (향후)
- List 모드의 부모 표시 컬럼 (현재는 부모 정보 안 보임 — depth=0 으로 단순화).
- 정렬 옵션 (DEV-033 의 sort UI 와 합쳐지면 더 자연스러움).

## 답
### 기본 = flat list (모든 quest)
- `openguild quest list` → 자식 quest 도 모두 포함 (parent 무관).
- agent / 스크립트 친화: 직선 출력 → xargs / pipe 쉬움.

### 기본 의도 그대로 보존 + `--tree` 옵션 추가
- agent / 사용자가 부모-자식 관계 시각화하고 싶을 때 `--tree` 플래그.
- 부모 (root) → 자식 (`└─ ` prefix + indent) → 손자 (`   └─ `) ...
- 같은 결과 set 안에 부모가 없는 자식은 root 로 표시 (필터 등으로 부모가 빠진 경우).
- `--id-only` / `--count` / `--json` 과 함께 쓰면 무시 (구조화 출력 우선) — agent 호환성.

## 사용 예
```
$ openguild quest list --tree --type DEV --status Open,Testing
DEV-031    [Open] Saved view ...
DEV-032    [Open] openguild query ...
DEV-033    [Open] frontend QuestList ...
└─ DEV-065    [Testing] Quest List 뷰 모드 토글 ...
...
DEV-089    [Open] [gui] UI 완성도 ...
└─ DEV-112    [Open] [gui] Quest Board 노드 배경 투명도 ...
```

## 구현
- `cli::QuestCmd::List` 에 `tree: bool` 추가.
- `print_quest_tree(&[Quest])` — HashMap 으로 id→quest / parent→자식 빌드, BFS / DFS 로 들여쓰기 출력.
- BUG-016: doc 에 quest_id prefix 안 씀.

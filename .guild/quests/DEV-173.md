DEV-140 cross-link 을 길드 규칙(.guild/rules/{slug}.md)으로 확장. 규칙 slug 은 XXX-NNN 형식이 아니라 bare 텍스트 자동인식 불가 → 무조건 [[slug]] 로 감싼 경우에만 링크.

## 구현 (2026-07-03)

- `questIndex.ts`: rules 도 인덱스 적재 (kind='rule', 원본 대소문자 slug 보존, 제목=본문 첫 # 헤딩). rules fetch 실패해도 quest/campaign 은 유지. `refHref` 규칙 → `/rules?slug=<원본slug>`.
- `MarkdownView.svelte`: 위키링크 정규식을 임의 slug 형태(`[[release-process]]`)까지 확장 — 규칙은 명시 [[..]] 만 링크(+미존재 빨강), bare 인식은 기존대로 quest/campaign 전용. 규칙 링크는 원문 대소문자로 표시.
- `editor-links.ts`(CodeMirror — 본문/메모/규칙 편집기 공통): `[[` 컨텍스트 자동완성 신설 — 규칙 포함 전체 인덱스 prefix 매칭, 규칙은 원본 slug 로 삽입. bare 토큰 제안은 quest/campaign 만 유지.
- `textarea-wikilink.ts`(댓글): 동일한 `[[` 컨텍스트 매칭 추가(치환 범위가 [[ 포함). WikiItem 에 kind='rule'/insert. 팝업에 '규칙 ·' 라벨.
- `/rules?slug=` 딥링크: rules 페이지 onMount 에서 query param 읽어 해당 규칙 선택.
- 테스트: questIndex.test.ts(refHref rule), textarea-wikilink.test.ts 신설(bare 규칙 제외 / [[ 컨텍스트 규칙 제안 / 빈 [[ 무시 등 5케이스).

## 테스트 방법

- `cd gui/frontend && npm run check && npm test -- --run` — 신규 테스트 포함 통과.
- 수동 (GUI 또는 브라우저 모드):
  1. 퀘스트 본문 편집기에서 `[[rel` 타이핑 → 자동완성에 '🔗 release-process (규칙 · 릴리즈 패키지 절차)' 후보 → 선택 시 `[[release-process]]` 삽입.
  2. 저장 후 본문 렌더에서 `release-process` 가 파랑 링크 → 클릭 시 규칙 페이지의 해당 규칙으로 이동.
  3. `[[no-such-rule]]` → 빨강(미존재) 표시.
  4. 댓글 textarea 에서 `[[rel` → 동일 팝업/삽입 동작.
  5. bare 텍스트 `release-process` (대괄호 없이) → 링크 안 됨(일반 텍스트) 확인.
  6. 기존 `[[DEV-033]]`/bare `DEV-033` 링크 회귀 확인.

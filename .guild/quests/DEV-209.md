## 전수조사 결과 (2026-07-03, 댓글 #1 상세)

목록 명령 네이밍은 이미 일관 — `types list`/`statuses list` 가 서브커맨드로 존재(bare 호출=list 기본동작). top-level 복수형 명사는 하위호환 대비 이득이 작아 현행 유지 결정.

## 구현 (2026-07-04) — 축소된 실작업 2건

1. **statuses list 에 slug 표시** (BUG-018 정책 갱신): `Open           (open)         게시됨` — quest move 등 명령 인자와 frontmatter 의 정규 식별자가 slug 인데 목록에서 안 보였음. 에러 메시지의 'Open (open)' 표기와 통일. --json 은 기존부터 slug 포함(변경 없음). types 는 prefix 자체가 식별자라 현행 유지.
2. **`rules new` alias**: rules create 가 생성 관례(new — DEV-176)와 어긋남 → clap alias 추가(create 유지).
3. USAGE 문서 반영.

## 테스트 방법
- `openguild statuses` → 각 행에 (slug) 컬럼 표시.
- `openguild statuses --json` → 기존과 동일(회귀).
- `openguild rules new test-alias --empty` → 생성됨 (create 와 동일), `rules delete test-alias --force` 로 정리.
- `cargo test -p openguild-cli` 통과.

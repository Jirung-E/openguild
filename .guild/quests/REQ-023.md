## 증상 — 본문을 누가 어떻게 바꿨는지 알 수 없다

admin: *"현재 이력을 보는 방법은 없지 않냐?"*

이력 화면(CLI `openguild quest history`, 퀘스트 상세의 이력)은 **있다.** 그런데
보여줄 게 상태 변경뿐이다. 이 저장소 길드의 실제 이력 파일 전수:

```
change_status        2012
update                 29   ← 전부 도서관 문서·규칙. 퀘스트는 0건
create                  5
discussion_resolved     1
```

- **퀘스트 본문·제목 수정은 이력에 아무것도 안 남는다.** `ops::quests::update_quest`
  가 이력을 안 쓴다.
- 도서관·규칙 수정은 남기는 하는데 `{"ts":"…","op":"update"}` 가 전부다 —
  **수정됐다는 사실만 있고 무엇이 어떻게 바뀌었는지는 없다.**

그래서 본문을 실수로 지웠거나, 다른 사람(에이전트)이 덮어썼을 때 **되돌릴 방법이
없다.** git 이력으로 파일을 뒤지는 게 유일한 길인데, 그건 앱 사용자가 할 일이 아니다.

## 참고 — 지라가 유일하게 잘하는 부분

지라는 동시 편집을 조용히 덮어쓰지만([JRACLOUD-37142](https://jira.atlassian.com/browse/JRACLOUD-37142),
2014년부터 미해결), **모든 필드 변경의 옛 값·새 값을 이슈 이력에 남긴다.** 덮어써진
설명을 복구하는 공식 경로가 "이력 탭에서 옛 설명을 복사해 붙여넣기" 다
([커뮤니티 답변](https://community.atlassian.com/forums/Jira-questions/Previous-Content-Lost-Due-to-Jira-Description-Conflict/qaq-p/2860113)).
불편하지만 **잃지는 않는다.** openguild 에는 그 바닥조차 없다.

## 할 것

- 퀘스트 본문·제목·긴급도·기한 수정을 이력에 **옛 값과 함께** 남긴다.
- 도서관·규칙의 `update` 도 무엇이 바뀌었는지 남긴다.
- 이력 화면에서 옛 버전을 보고, 지금과의 차이를 볼 수 있게 한다.
- (정할 것) 되돌리기 버튼까지 둘지.

## 정할 것 — 이력 파일은 git 에 올라간다

`.guild/history/*.jsonl` 은 git 추적 파일이다([[BOOK-001]] 의 tracked 진리). 본문을
고칠 때마다 **옛 본문 전체**를 쌓으면 저장소가 그만큼 커진다. 긴 설계 문서를 여러 번
고치면 금방 커진다.

- **변경분(diff)만 저장** — 작다. 옛 버전을 보려면 거꾸로 적용해 재구성한다.
- **전체 저장 + 크기 상한** — 단순하다. 상한을 넘으면 변경분으로 떨어진다.

## 테스트 방법

- 본문을 고치면 이력에 옛 값이 남고, 이력 화면에서 옛 본문이 보인다.
- 도서관·규칙 수정도 같다.
- 여러 번 고친 뒤 임의의 옛 버전을 정확히 재구성한다(변경분 방식이면 특히).
- 이력 파일 크기가 본문 크기 × 수정 횟수로 불어나지 않는다.

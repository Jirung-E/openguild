# [gui] `openguild-gui --version` 출력이 프롬프트 뒤에 나옴

```
PS> openguild-gui --version
PS> openguild-gui 0.5.0-beta      ← 프롬프트가 먼저 돌아오고 그 뒤에 출력
```

CLI/서버는 정상. GUI 만 이렇게 보인다.

## 원인 (코드 확인)

`gui/src/main.rs:2` 의 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
때문이다. release 빌드는 **GUI 서브시스템** 실행 파일이라 셸이 종료를 기다리지
않는다 — PowerShell 은 프로세스를 띄우자마자 프롬프트를 돌려준다. 그 다음
프로세스가 `attach_parent_console()`(`gui/src/lib.rs:166`)로 부모 콘솔에 붙어
`println!` 하므로, 글자가 **이미 출력된 프롬프트 뒤에** 찍힌다.

출력 내용·종료 코드는 정상이고 순서만 어긋난다. `attach_parent_console` 의
`AttachConsole` + `CONOUT$` `SetStdHandle` 은 의도대로 동작 중이다(BUG-041 후속
작업). 남은 것은 "셸이 기다리지 않는다"는 서브시스템 자체의 성질이라 콘솔
attach 로는 못 고친다.

`openguild-gui --version | cat` 처럼 파이프하면 stdout 이 valid 라 attach 를
건너뛰지만, 셸이 안 기다리는 건 마찬가지다.

## 영향

- 릴리스 사후 점검에 `openguild-gui --version` 확인 항목이 있다(release-process
  규칙). 지금은 출력이 프롬프트 뒤에 섞여 나와 스크립트로 잡기 어렵다.
- `--help` 도 같은 증상.

## 수정안 (택1 — 결정 필요)

1. **콘솔 서브시스템으로 빌드하고 GUI 시동 시 `FreeConsole()`** — `--version`/
   `--help` 가 동기적으로 정상 출력된다. 대신 GUI 를 더블클릭/런처로 띄울 때
   콘솔 창이 잠깐 번쩍일 수 있다(FreeConsole 타이밍).
2. **콘솔 서브시스템 shim 을 따로 배포** — `openguild-gui.com`(또는 `-cli.exe`)
   을 같이 깔고, 그쪽이 인자를 받아 처리/중계. PATHEXT 상 `.com` 이 `.exe` 보다
   먼저 잡힌다. GUI 시동 경험은 그대로. 설치 구성이 하나 늘어난다.
3. **안 고치고 문서화** — 버전 확인은 `openguild --version`(CLI) 로 안내하고,
   릴리스 점검 항목도 그쪽으로 바꾼다. 비용 0.

DEV-351(CLI·Server 자체 갱신)에서 버전 질의 경로를 손보게 되면 1/2 와 함께
정리하는 편이 낫다.

구현 — `routes::compression_layer()` (tower-http `compression-gzip`).

- 레이어는 `main.rs` 의 **가장 바깥**에 건다. axum 의 `layer` 는 그 시점까지
  등록된 라우트만 감싸므로, 정적 fallback(`ServeDir`)이 붙은 뒤에 걸어야
  `_app/*.js` 까지 압축된다.
- 판정은 `compression_predicate()` 로 분리해 테스트에서 직접 검사한다.
  `DefaultPredicate`(32바이트 미만 / gRPC / `image/*` / SSE 제외)에
  `application/octet-stream`, `application/zip`, `video/`, `audio/` 를 추가.
  `/api/guild-files/{*rel}` 가 확장자를 못 알아보면 octet-stream 으로 주므로
  zip·동영상 첨부가 이 경로로 나간다 — BUG-188 의 1.5GB 첨부를 통째로
  압축하는 일은 반드시 피해야 한다.

## 측정 (실제 길드, 퀘스트 531건)

| 응답 | 무압축 | gzip | 배율 |
|---|---|---|---|
| `/api/quests?slim=true` | 259,974 B | **33,987 B** | 7.6x |
| `/api/quests` (본문 포함) | 1,162,192 B | 373,478 B | 3.1x |
| `/api/rules` | 36,870 B | 15,830 B | 2.3x |
| `/api/library` | 16,489 B | 7,565 B | 2.2x |
| `index.html` | 3,909 B | 930 B | 4.2x |
| 최대 JS 청크 | 963,303 B | 317,109 B | 3.0x |

한글 JSON 인 slim 목록이 7.6배로 가장 잘 줄었다. BUG-210 과 합치면
cross-link 인덱스 적재가 **1,156,414 B → 33,987 B (약 34배)** 가 된다.

## 테스트 (3건)

- `test_gzip_applied_to_json` — Accept-Encoding: gzip 이면 gzip 으로 나감.
- `test_no_gzip_without_accept_encoding` — 요청 안 하면 무압축(협상 결과).
- `test_compression_predicate_skips_already_compressed_types` —
  octet-stream/zip/video/audio/image 는 제외, json/html/markdown 은 압축.
  (`SizeAbove` 는 헤더가 아니라 body size hint 를 본다 — 처음에 빈 body 로
  테스트해서 json 까지 "압축 안 함" 으로 나왔다.)

빈 목록(`[]`, 2바이트)처럼 32바이트 미만은 압축하지 않는다 — 정상 동작이라
픽스처를 퀘스트가 있는 것으로 바꿔 검증했다.

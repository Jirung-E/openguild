전체 코드베이스 리뷰(프론트엔드 lib/routes)에서 발견. 코드 확인으로 검증 완료.

## 공통 근본 원인

비동기 결과를 커밋하기 전에 **"내가 아직 현재 요청/대상인가"** 를 확인하지
않는다. 이미 저장소 안에 올바른 패턴이 있다 —
`routes/quests/[id]/+page.svelte` 의 slug effect 는 결과 적용 전에
`slug === currentSlug` 를 재확인한다. 이걸 복사하면 되는 건들.

## 1. history 컴포넌트 3종 — 다른 문서의 이력이 보임

- `lib/components/QuestHistory.svelte:30` (questId 키)
- `lib/components/CampaignHistory.svelte:19` (campaignSlug 키)
- `lib/components/SidecarHistory.svelte:20` (kind/id 키)

셋 다 `$effect` 에서 id 를 캡처하고 `.then((list) => { entries = list; })` 로
**무조건** 대입한다. in-flight 취소도, 해소 시점 id 재확인도 없다.

재현: A 퀘스트 상세 → B 퀘스트 상세로 A 요청이 끝나기 전에 이동. A 응답이
나중에 도착하면 **페이지 나머지는 B 인데 이력 패널만 A** 를 보여준다.

## 2. title-popup 싱글턴 하이재킹

`lib/actions/title-popup.ts:18` 의 `current` 는 모듈 레벨 싱글턴인데,
`update()` 가 `if (current)` 만 검사한다 — **그 current 가 이 노드의 것인지
확인하지 않는다.** 이후 `createPopup(label, node)` 가 `current` 를 새 요소로
재대입(:47).

재현: 툴팁이 떠 있는 상태에서 **무관한** 노드의 reactive label 이 바뀌면
(예: 목록 새로고침 후 타일 재렌더) 떠 있던 툴팁이 엉뚱한 앵커로 끌려가며
내용도 바뀐다.

## 3. LinkPreviewPopup — 다른 문서 본문이 표시됨

`lib/components/LinkPreviewPopup.svelte:75` 의 kind/id effect 에 취소 가드
없음. `MarkdownView.svelte:358` 이 `PopupComp` 를 key 없이 렌더하고
`hoverTarget` 을 직접 재대입하므로 인접 링크로 마우스를 옮기면 같은 인스턴스가
effect 를 재실행한다. A 응답이 B 보다 늦으면 **헤더는 B, 본문은 A.**

## 4. scroll-restore 루프 경합

`lib/utils/scroll-restore.ts:9` `restoreScroll()` 은 취소 핸들을 반환하지 않고
호출마다 rAF 루프 + wheel/touchstart/keydown 리스너를 독립 설치한다.
빠른 back/forward 시 이전 페이지 y 를 겨냥한 루프와 새 루프가 매 프레임 서로
다른 `window.scrollTo` 를 호출 → 지터/엉뚱한 최종 위치.

## 5. tags 페이지 퀘스트 링크가 깨져 있음 (별개, 단순)

`routes/tags/+page.svelte:70` 이 `href: /quests/${q.id}` 로 **숫자 PK** 를
쓴다. 그런데 `/quests/[id]` 라우트는 param 을 slug 로 취급해
`getBySlug` 를 호출한다(`+page.svelte:63`).

앱 내 유일한 예외다 — `Home.svelte:355`, `SearchPalette.svelte:220`,
`campaigns/[slug]/+page.svelte:696`, 퀘스트 상세의 prereq/subquest 링크
(:941/:987/:1026/:1070) 전부 `q.quest_id` 를 쓴다.

재현: `/tags` → 태그 펼침 → 퀘스트 행 클릭 → `/quests/123` 으로 가서 에러 상태.
수정은 `q.id` → `q.quest_id` 한 곳.

## 6. worklog CodeMirror 인스턴스 누수

`routes/worklog/+page.svelte:219` 의 `onDestroy` 가 `setUnsaved` 만 정리하고
`editorView?.destroy()` 를 호출하지 않는다(destroy 는 :232 재생성 직전과
:256 cancelEdit 에만 존재).

재현: 노트 편집 모드 진입 → editMode 인 채로 이탈(전역 unsaved 모달의
"버리고 진행" 이 정확히 이 경로 — clearUnsaved + goto 만 하고 이 페이지 상태는
안 건드림) → CodeMirror 인스턴스가 DOM/이벤트 바인딩과 함께 살아남는다.

`lib/components/MarkdownEditor.svelte:335` 는 `$effect` cleanup 으로 올바르게
처리하고 있으므로 그 패턴에 맞추면 된다.

## 공통 도구 — `lib/utils/latest-only.ts`

퀘스트가 짚은 대로 저장소에 이미 올바른 패턴이 있다(`quests/[id]` 의 slug
effect 가 `slug === currentSlug` 재확인). 그걸 세대 토큰으로 일반화했다.

```ts
const gen = new Generation();
$effect(() => {
  const mine = gen.next();
  api.load(id).then((v) => { if (gen.isCurrent(mine)) value = v; });
});
```

`enhanced-search.ts` 의 `LatestQuery` 와 목적이 겹치지만 그쪽은 **디바운스가
함께 있는 검색 전용**이다. 이쪽은 가드만 필요한 경우를 위한 것이라 나눴다.

## 1. history 3종 — 다른 문서의 이력이 보이던 문제

`QuestHistory` / `CampaignHistory` / `SidecarHistory` 전부 `.then` · `.catch` ·
`.finally` 세 곳 모두에 가드를 넣었다. `finally` 까지 막아야 늦게 온 응답이
`loading` 을 꺼서 **아직 로딩 중인 최신 요청을 완료로 보이게** 하는 것도
막힌다.

## 2. title-popup 싱글턴 하이재킹

`current` 만 보고 다시 그리던 것을 **소유 노드**(`currentOwner`)를 함께 들고
자기 것일 때만 갱신하도록 바꿨다.

테스트 3건. 수정 전 코드로 되돌려 `expected 'B 바뀜' to be 'A 툴팁'` 으로
실패 — 무관한 노드의 label 변경이 남의 툴팁을 실제로 끌어왔다.

## 3. LinkPreviewPopup — 헤더는 B, 본문은 A

`MarkdownView` 가 key 없이 렌더하고 `hoverTarget` 만 재대입해 **같은
인스턴스**가 effect 를 다시 돈다. 같은 세대 가드를 적용했다.

## 4. scroll-restore 루프 경합

`activeCancel` 모듈 핸들을 두고, 새 복원이 시작되면 앞선 루프를 끊는다.
`cancelRestoreScroll()` 도 노출해 페이지 이탈에서 쓸 수 있게 했다.

테스트 4건. 수정 전에는 `expected Set{ 300, 900 } to deeply equal Set{ 900 }`
— 두 루프가 매 프레임 서로 다른 목표로 되돌리는 것이 그대로 잡혔다.

rAF 와 `performance.now` 를 스텁해 프레임을 수동으로 돌려 결정적으로 관찰한다
(jsdom 은 `scrollTo` 를 구현하지 않아 그것도 스텁).

## 5. tags 페이지 링크

`/quests/${q.id}`(숫자 PK) → `/quests/${q.quest_id}`. 라우트가 param 을 slug 로
받아 `getBySlug` 를 호출하므로 숫자로는 조회가 실패한다. 앱에서 유일한
예외였다.

**브라우저 실측**: `/tags` 에서 태그를 펼쳐 링크를 뽑으니 `/quests/BUG-057`
(숫자 PK 링크 0건), 그 주소로 이동하니 제목이 정상 표시되고 에러 없음.

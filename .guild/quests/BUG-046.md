## 증상

Campaign Detail 페이지 (`/campaigns/{slug}`) 에서 체크리스트 항목의 체크박스
를 클릭하면:
- 항목의 체크 상태는 정상 토글 (DB / 파일 반영 OK).
- 페이지 스크롤이 **최상단으로 점프**.

긴 체크리스트의 중간/하단 항목 작업 시 매번 스크롤 복원 필요해서 UX 거슬림.

## 원인 추정

`gui/frontend/src/routes/campaigns/[slug]/+page.svelte:206` 의 `toggleChecklist`:

```ts
async function toggleChecklist(idx: number, currentlyChecked: boolean) {
    if (!detail) return;
    try {
        await campaignsApi.setChecklist(detail.campaign_slug, idx + 1, !currentlyChecked);
        await load();              // ← detail 전체 객체 reload
    } catch (e) { ... }
}
```

`load()` 가 `detail` state 를 새 객체로 교체 → `{#each detail.checklists as
item, idx (item.id)}` 의 모든 item 이 새 객체 참조 → Svelte 가 list 의 DOM
을 재생성 → 체크박스 / 주변 DOM 재구성 도중 focus / scroll anchor 손실 →
브라우저가 페이지 최상단으로 fallback.

`removeChecklist` 도 동일 패턴 — 같은 증상 추정.

## 작업 (옵션)

### A. Optimistic update (권장)
체크박스 토글 시 즉시 UI 만 갱신 + API 호출. 성공 시 reload 안 함, 실패 시
revert:

```ts
async function toggleChecklist(idx: number, currentlyChecked: boolean) {
    if (!detail) return;
    const next = !currentlyChecked;
    detail.checklists[idx].checked = next;
    detail = detail; // Svelte 5 reactivity
    try {
        await campaignsApi.setChecklist(detail.campaign_slug, idx + 1, next);
    } catch (e) {
        detail.checklists[idx].checked = currentlyChecked;
        detail = detail;
        alert(e instanceof Error ? e.message : 'failed');
    }
}
```

- 장점: 체감 즉시 반응 + scroll 점프 X (전체 list re-render 안 함).
- 단점: 서버가 다른 값으로 응답할 가능성 무시 (campaign 진행률 등 derived
  값은 reactive 라 자동 갱신).

### B. Partial reload — 체크리스트만
`load()` 전체 reload 대신 좁은 API 만 호출 (`getChecklist` 같은). 기존 detail
의 다른 필드는 보존 → key=item.id 가 stable 이라 DOM 재사용.
- 장점: 데이터 정합성 보장.
- 단점: 새 API 필요 (현재 없음). 한 round-trip 추가.

### C. Scroll position 보존 (workaround)
`load()` 직전 `window.scrollY` 저장 → `await load()` 후 `tick()` +
`window.scrollTo(0, savedY)`.
- 장점: 즉시 적용 가능, 작은 변경.
- 단점: 근본 원인 안 잡음, 다른 케이스 (linked_quests 변경 등) 도 따로 처리.

## 권장 순서

1. **A** (체크박스 / × 삭제 양쪽 적용 — 가장 큰 효과).

# [gui] 일부 아이콘이 타 OS 에서 컬러 이모지로 렌더

사용자 보고: "일부 아이콘이 다른 운영체제에서는 컬러로 보임 (홈 정지 아이콘 등)".

## 원인

`⏸`(U+23F8) `📁` `📄` `💬` `📝` `🗑` `🖼` `🌐` `📌` `⬆` 등은 **기본 emoji
presentation** 코드포인트라 OS/폰트 폴백에 따라 컬러 이모지로 그려진다.
모양·크기·색·기준선이 환경마다 달라 버튼 정렬까지 흔들린다.

전수 스캔 결과 47종의 이모지 계열 글리프가 있었고, 그중 **기본 컬러 표현**인
것만 골라내면 48개 지점(주석 포함)이었다. 텍스트 기본 표현 기호
(✓ ✗ ▶ ◀ ● ★ ✎ ☰ ⚙ ⚠ ✕)는 흑백으로 렌더되므로 대상에서 제외했다.

## 수정

- **`PlayPauseIcon.svelte` 신설** — 사용자가 지목한 홈의 정지/재생 아이콘.
  같은 마크업이 CampaignCarousel / CampaignConveyor / QuestNodeConveyor 세 곳에
  중복돼 있어 컴포넌트로 뽑았다.
- **`Icon.svelte` 신설** — folder/doc/comment/memo/trash/image/globe/pin/up/
  clock/link/tag 12종, `currentColor` + viewBox 16 통일.
- 마크업 **21개 지점** 교체: 도서관 타일(📁📄)·폴더트리·상단 이동(⬆)·문서
  경로, 첨부 파일 칩(📄), 퀘스트 목록 댓글 수(💬), 퀘스트/캠페인 상세의
  점프 버튼(💬📝)·삭제(🗑)·배너(🖼), welcome 원격 항목(🌐), 댓글 섹션의
  토론 토글(💬)·고정(📌), 크로스링크 자동완성 라벨(🏷️🔗).
- **재발 방지 가드**: `scripts/check-no-emoji-icons.mjs` +
  `npm run check:no-emoji` + CI(check.yml) 스텝. DEV-131 의 `check:no-hex` 와
  같은 방식으로 의존성 없이 `.svelte` **마크업만**(script/style/주석 제외)
  스캔한다. 실제로 이 가드가 내가 놓친 1곳(자동완성 라벨)을 잡아냈다.

## 유지 / 후속

- 댓글 반응(`REACTION_SET = ['👍','✅','❓','❌']`)은 **반응 자체가 이모지**라
  유지 — 가드의 대상이 아니다(마크업이 아닌 script 안 상수).
- JS 가 문자열로 조립하는 SVG(`quest-node-svg.ts`, `QuestBoard.svelte` 의
  `⛺ ⏱ 💬`)와 i18n 라벨(`locale.ts` 의 `📁 🕘 🔘 📝`)은 성질이 달라
  [[DEV-302]] 로 분리했다 — 전자는 `<text>` 안 문자라 path 화 + 노드 폭 계산
  변경이 필요하고, 후자는 라벨 문자열에서 아이콘을 떼는 리팩터가 맞다.

## 검증

`svelte-check` 0 errors / 0 warnings, 프론트 테스트 301건 통과,
`check:no-emoji` 통과(마크업 잔여 0).

## Test plan

1. **macOS / Linux 에서** 홈 화면 컨베이어의 정지/재생 버튼이 흑백 SVG 로
   보이는지(이전엔 컬러 이모지).
2. 도서관 아이콘 보기의 폴더/문서 타일, 상단 '위로' 버튼.
3. 퀘스트 상세의 삭제 버튼, 댓글/메모 점프 버튼, 캠페인 배너 버튼.
4. 퀘스트 목록의 댓글 수 아이콘, 첨부 파일 칩.
5. 댓글 반응 이모지는 **여전히 컬러**여야 한다(의도).
6. 다크/라이트 양쪽에서 아이콘 색이 텍스트와 같은 색으로 따라오는지
   (currentColor).
7. 아이콘+텍스트 정렬(기준선)이 어긋나지 않는지.

# 작업 기록(Worklog) 설계안

## 한 줄 정의
"누가 / 언제 / 무슨 작업을 했나"를 날짜·기간별로 모아 보는 화면.
기록 = ① 자동(시스템이 캡처한 활동) + ② 수동(그날 한 일 메모).

## ① 자동 활동 — 데이터원: quest_history (채택) vs journal.db (탈락)
- **journal.db (AOF)**: snapshot 생성 시 **truncate(절단)** 됨 → 과거가 사라져
  누적 기록용으로 부적합. 디버그/감사 전용으로 유지.
- **quest_history (채택)**: 영구 보존 + `actor`(누가) 보유. 상태 변경/부모 변경 등
  구조화된 활동에 적합.
- 보강: 댓글 = `quest_comments`/`campaign_comments`(author+ts), 생성 = history 의
  create op.
- 결론: **quest_history 주축 + comments 보강**.

## ② 수동 메모 — 저장 위치
- 파일=진리원 + git 추적(공유/어드민 가시) → `.guild/worklog/{user}/{YYYY-MM-DD}.md`
- 사용자별 폴더 격리 · 날짜별 1파일. index.db 에 캐시(빠른 조회), 파일이 진리.

## 유저별 기록 + 어드민 전체 보기
- 모든 활동은 `actor`/`author`/`user_id` 로 사용자에 귀속 → "내 기록" = 현재 사용자 필터.
- **개인 화면**: 본인 활동 + 본인 메모만.
- **어드민 페이지**: 모든 사용자, 사용자별 필터/그룹으로 확인.

### ⚠ 선행 의존성 (중요)
현재 openguild 는 인증/유저 모델이 MVP 스텁(server admin.rs: "인증 없음 — 멀티유저
단계 진입 시 토큰/role 가드"). "현재 사용자" 식별과 "어드민 role" 은 **유저 식별/role
기능이 선행**되어야 한다. (quest_memos 의 `user_id` 컬럼은 그 준비.)
→ 권장: 유저 식별/role 을 **선행 quest** 로 분리. 작업 기록은 처음부터 `user_id`
키로 설계해 단일 사용자(=local)에서 동작시키고, 멀티유저가 붙으면 어드민 전체보기가
자연히 활성화되도록 forward-compatible 하게 구현.

## 범위 분해(제안)
1. (선행) 유저 식별 + role(admin) 모델.
2. worklog 코어: quest_history+comments 집계 쿼리(기간/유저 필터) + 메모 파일 CRUD.
3. GUI: 개인 작업 기록 화면(목업 참조: 기간 세그먼트·주간 요약·날짜별 활동+메모).
4. GUI: 어드민 페이지 '전체 사용자 작업 기록' 뷰.

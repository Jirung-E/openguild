사용자 보고: 리눅스에서 설정 화면의 UI 크기(스케일) 슬라이더를 조절할 때
버벅거림.

## 기존 조치 (이전 세션)

`gui/frontend/src/lib/stores/uiScale.ts` 의 `applyUiScaleToDocument`
와 `gui/frontend/src/routes/+layout.svelte` 의 content-width 슬라이더
핸들러에 rAF 병합 적용 — 슬라이더를 빠르게 움직여도 실제
`document.documentElement.style` 쓰기(폰트 크기/CSS 변수)는
`requestAnimationFrame` 콜백에서 프레임당 1회로 상한(마지막 값만 반영).
이전 재오픈 코멘트에서 "프레임당 DOM 쓰기 1회 상한까지가 이 퀘스트의
역할, 전반적으로 느린 근본 원인은 BUG-144(WebKitGTK DMABUF 완화)로 별도
커밋"이라고 정리된 바 있음.

## 2026-07-18 재확인

코드 재확인 결과 위 rAF 병합은 그대로 유효하게 남아있음 — 이번 세션에서
이 퀘스트 자체에 추가 코드 변경은 하지 않음.

다만 BUG-144 에서 실기(NVIDIA 리눅스 데스크톱) 검증 중 "리눅스 전반
버벅임"의 실제 원인 하나를 추가로 찾아 고쳤음 — Quest Board 의 wheel
핸들러가 매 wheel 이벤트마다 동기적으로 캔버스를 다시 그리던 문제
(BUG-144 참조). UI 크기 슬라이더 자체와는 다른 지점이지만, "리눅스에서
전반적으로 버벅인다"는 인접 증상이라 함께 재검증 요청.

## 테스트 방법

1. 리눅스 빌드(이번 세션 BUG-144 수정 포함) 실행 후 설정 화면에서 UI 크기
   슬라이더를 빠르게 드래그.
2. 이전 빌드 대비 버벅임이 나아졌는지 확인. 여전히 느리면:
   - 보드가 아닌 다른 화면(설정 페이지 자체)에서도 슬라이더만 움직일 때
     느린지
   - GPU(NVIDIA 여부)/Wayland·X11 여부
   를 알려주면 다음 단계로 파겠음.

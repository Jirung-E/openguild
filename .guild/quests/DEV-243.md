admin 요청: 도서관 문서와 길드 규칙에 태그를 달 수 있으면 좋을듯.

## 설계 (admin 확인: 규칙 파일 frontmatter 도입 감수하고 진행)

- 도서관: 이미 frontmatter(+++ TOML +++) + DB 캐시(library_docs) 구조가
  있어 quest 의 DEV-068 태그 패턴(frontmatter tags + library_tags 캐시
  테이블)을 그대로 적용. 색/설명 정의는 quest 와 동일한
  `.guild/tags/{slug}.toml` registry 공유(엔티티 무관 단일 registry라
  새 정의 테이블 불필요).
- 규칙: 지금까지 frontmatter 가 아예 없는 순수 markdown 이었음 — 이번에
  **선택적** `+++ TOML +++` frontmatter 를 처음 도입. 태그가 하나도
  없으면 frontmatter 자체를 생략해(파일 그대로) 기존 규칙 파일과의 diff
  최소화. DB 캐시는 안 둠(rules 는 원래부터 "파일 직독" 정책 —
  file-truth-db-cache 규칙 §4 유지).

## 구현
- **core**: `BookFrontmatter.tags` + `library_tags` 캐시 테이블(migration
  0024) + `set_book_tags`/`attach_tags`(N+1 방지 일괄조회) — quest의
  `set_quest_tags` 와 동일 패턴. reindex 도 tags 재구축하도록 확장.
  `RuleFile`(선택적 frontmatter parse/serialize) + `RuleFrontmatter.tags`
  + `set_rule_tags` — 본문만 저장하는 mutation(`write_rule`)은 기존
  태그를 보존.
- **server/Tauri**: `PATCH /api/library/{id}/tags`, `PUT /api/rules/{slug}/tags`
  + 대응 Tauri command(`set_book_tags`/`set_rule_tags`) — quest 의
  set_tags 라우트와 동일 body 포맷(`{"tags":[...]}`).
- **frontend**: `TagPills.svelte` 공용 컴포넌트 신설(quest 상세 페이지의
  기존 인라인 태그 UI와 동일 UX — pill 표시/추가/삭제, 태그 정의 색상
  적용) — 도서관/규칙 페이지에 부착. quest 자체는 기존 인라인 구현 그대로
  유지(리스크 최소화, 이번 범위 밖).

## 테스트 방법
- `cargo test --workspace` (core: frontmatter parse/serialize/보존/정규화,
  server: HTTP 태그 설정 + 본문 저장 시 보존 회귀 테스트) + `cargo clippy
  --workspace --all-targets -- -D warnings`.
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`.
- 실기: 도서관 문서 상세에서 태그 추가/삭제, 본문 편집 저장 후에도 태그
  유지되는지. 길드 규칙에서도 동일. 태그 정의(색)를 설정에서 만들면
  pill 색이 반영되는지(quest 와 동일 registry 공유 확인).

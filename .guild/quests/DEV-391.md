## 증상

**"이 퀘스트만 알림" 이 댓글에는 안 걸린다.**

[[REQ-021]] 의 텔레그램 예제를 실환경에서 돌리다 나왔다. 퀘스트 상태 변경은
`notify` 태그로 거를 수 있는데, 같은 퀘스트에 달린 **댓글은 못 거른다.**

## 원인

`comment.added` 의 페이로드는 이렇다.

```json
{ "target": { "kind": "quest", "id": "DEV-001" },
  "comment": { "id": 3, "author": "…", "body": "…" } }
```

어느 문서에 달렸는지는 `target` 으로 알리지만 **그 문서의 태그·제목·상태는
안 싣는다.** `target: {kind, id}` 는 캠페인 댓글과 이름을 나누지 않으려고
[[DEV-388]] 이 고른 모양이고, 그 판단 자체는 옳다 — 구독 하나로 두 종류를
덮는다.

문제는 그 대가로 **구독자가 대상에 대해 아는 것이 id 뿐**이라는 것이다.
스크립트에는 I/O 가 없으므로([[DEV-376]]) 그 id 로 퀘스트를 조회할 방법도
없다. `post` 로 보내는 쪽도 마찬가지다.

그래서 "알림 설정한 퀘스트의 댓글만" 이라는, 제일 흔할 요구를 못 쓴다.

## 고려한 것

**대상 문서를 통째로 싣기** — `quest` 를 comment 이벤트에도 넣는다. 간단하지만
캠페인 댓글에는 `campaign` 이 들어가야 하므로, 결국 구독자가 `target.kind` 로
분기해야 한다. 이름을 안 나눈 이득이 반쯤 사라진다.

**대상의 요약만 싣기** — `target: { kind, id, title, tags, status }`. 종류가
달라도 모양이 같아서 분기가 안 생기고, 필터에 필요한 것은 대부분 이 넷이다.
`payload::target` 한 곳만 고치면 되고 첨부 이벤트도 같이 좋아진다.

지금은 두 번째가 맞아 보이지만, `tags` 를 채우려면 이벤트마다 조회가 하나
붙는다 — `events_wanted` 로 게이트해서 구독자가 없으면 조회도 안 하게 해야
한다([[DEV-386]] 에서 `*_changed` 의 이전 값을 그렇게 처리했다).

## 테스트 방법

- `notify` 태그가 붙은 퀘스트와 안 붙은 퀘스트에 각각 댓글을 달고, 태그로
  거르는 스크립트가 하나만 통과시킨다.
- 캠페인 댓글도 같은 모양의 `target` 을 받는다(분기가 안 생기는지).
- 구독자가 없으면 조회가 아예 안 일어난다.

## 증상

사용자 보고: reindex 시도 후 보드 화면 중앙에 "Cannot read properties of undefined (reading 'length')" 에러가 표시되어 board mount 실패.

## 원인

직접 원인: 내가 DEV-120.md 등록 시 `urgency = 5` 로 잘못 작성. core 의 validation 은 1..=4 만 허용하지만 reindex 는 파일 → DB 직접 INSERT 라 validation 우회. DB 에 urgency=5 row 가 들어감.

GUI 측 원인: `QuestBoard.svelte:128` 의 `URGENCY_LABEL[quest.urgency]` 가 bare access — 5 면 undefined. 직후 line 138 `ul.length` 에서 폭발. 같은 패턴이 여러 곳에 산재.

DEV-120.md 의 urgency 는 별도 fix 커밋 (`c201dc7`) 으로 4 로 정정. 본 BUG 은 GUI 가 다시는 이런 데이터로 폭발하지 않도록 방어 코드.

## 수정

### `gui/frontend/src/lib/types/index.ts`
헬퍼 함수 추가:
```ts
export function urgencyLabel(u: number): string {
    return URGENCY_LABEL[u] ?? URGENCY_LABEL[4];
}
export function urgencyColor(u: number): string {
    return URGENCY_COLOR[u] ?? URGENCY_COLOR[4];
}
```
범위 밖이면 4 (Low) 로 fallback — 시각적 노이즈 최소 + 데이터 정정 유도.

### bare access → 헬퍼 교체
- `QuestBoard.svelte` 4 곳: `makeSvgUrl` 의 `uc/ul`, theme 갱신 시 `urgencyColor`, init 의 `urgencyColor`, expand 카드의 badge.
- `QuestListItem.svelte` urgency badge.
- `routes/quests/[id]/+page.svelte` urgency badge.

`NewQuestModal.svelte` / quest detail 의 select dropdown 의 `{#each [1,2,3,4] as u}` 는 fixed array 라 안전 — 그대로.

`quest-node-svg.ts` 는 이미 `?? '?'` / `?? '#666'` fallback 보유 (DEV-074 fix 추정).

## 후속 가능 (미진행)

core 측에서도 reindex 시 invalid urgency 를 skipped report 에 추가하면 사용자가 알아챌 수 있음. 현재는 silent DB INSERT — 다음 라운드 검토.

admin 지적: BUG-119(도서관 뒤로가기 버그) 수정 과정에서 원인이 BUG-104 때
도입된 `replaceState: true` 패턴이었음을 확인 — 그런데 이 패턴은 도서관뿐
아니라 rules/worklog 페이지에도 동일하게 복사돼 있었음(DEV-217, DEV-167).
admin 확인 결과 이 replaceState 정책 자체가 애초에 요청받은 설계가 아니라
BUG-104 수정 중에 임의로 도입된 것이었고, 따라서 rules/worklog 도 같은
문제(문서/항목을 여러 번 선택하며 탐색하다 뒤로가기를 하면 선택 이력이
아니라 페이지를 그냥 나가버림)를 안고 있을 가능성이 높음 — 실제로 동일한
패턴이 그대로 있음을 확인.

## 원인 (공통)
BUG-104(커밋 2662a9d, rules/+page.svelte)가 "규칙 선택마다 history entry 를
쌓지 않는다"는 이유로 `syncUrl()` 에 `replaceState: true` 를 도입 —
DEV-217(library, 이후 BUG-119로 수정 완료)과 DEV-167(worklog) 이 동일
패턴을 그대로 복사해 확산.

이 정책은 "항목을 선택해서 탐색"하는 곳에는 맞지 않음 — 그런 곳은
pushState 로 매 선택이 history entry 가 되어야 뒤로가기로 이전 선택으로
돌아갈 수 있음. (반대로 QuestList/QuestBoard의 검색어/필터/정렬 미러링이나
quest 타입변경 후 리다이렉트, `/` → `/welcome` 리다이렉트처럼 "상태를
URL에 미러링"하거나 "이전 URL이 무효화"되는 곳은 replaceState 가 맞고
이번 수정 대상이 아님.)

## 수정
- `rules/+page.svelte`: `syncUrl(slug)` 에서 `replaceState: true` 제거 —
  규칙 선택마다 새 history entry.
- `worklog/+page.svelte`: 날짜/단위 이동 `goto()` 에서 `replaceState: true`
  제거 — 날짜/단위 변경마다 새 history entry.
- QuestList/QuestBoard 필터·정렬 미러링, quest 타입변경 리다이렉트,
  `/` → `/welcome` 리다이렉트는 그대로 유지(무관 — replaceState 가 정답).

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`
  (프론트만 변경, Rust 쪽 변경 없음).
- 실기: rules 페이지에서 규칙 여러 개 선택 후 뒤로가기 → 이전에 본 규칙으로
  한 단계씩 복귀하는지. worklog 페이지에서 날짜/단위 여러 번 바꾼 뒤
  뒤로가기 → 이전 날짜/단위로 복귀하는지.

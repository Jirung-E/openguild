## 증상

사용자 보고:
```
> .\openguild.exe statuses update open --name-ko 게시 --color "#888"
internal error: failed to read: .../.guild/statuses/0-open.toml: 지정된 파일을 찾을 수 없습니다.
```
실제 길드의 파일은 `1-open.toml` 같은 형식인데, DB 의 `sort_order=0` (외부
편집 / 마이그레이션 / 옛 길드 등으로 drift) 라서 코드가 `0-open.toml` 을 찾음.

또 다른 시나리오 — `rename open backlog` 성공 메시지 후 `statuses` 로 list 출력
했더니 여전히 `Open` 표시. slug 가 list 에 안 보여서 사용자가 변경 확인 불가
(name_en 은 그대로 'Open', slug 만 'backlog' 가 됐을 가능성).

## 원인

`ops::meta::update_status` / `rename_status_slug` / `delete_status` 가
파일 경로를 `StatusFile::filename(row.sort_order, slug)` 로 추정. DB 의
sort_order 와 실제 파일명 prefix 가 drift 한 길드에서 항상 실패.

## 수정

### Backend (`core/src/ops/meta.rs`)
- `find_status_file_by_slug(paths, slug)` 헬퍼 — 디렉토리에서 `*-<slug>.toml`
  패턴 search. DB sort_order 추정 없이 정확한 파일 찾음.
- `update_status` / `delete_status` / `rename_status_slug` 모두 이것 사용.
- `update_status` 가 file 의 sort_order 도 DB 와 sync (drift 자동 보정).

### CLI (`cli/src/main.rs`)
- `statuses` list 출력에 slug 도 표시: `Open (open) 게시됨` 같은 형식.
- 이전엔 `Open 게시됨` 만 — rename 후 사용자가 결과 확인 불가.

## 테스트

`status_mutations_work_when_file_prefix_drifts` — 파일을 `99-open.toml` 로
강제 rename (drift 시뮬레이션) → update / rename / delete 모두 성공 검증.

## 후속 fix (사용자 추가 지적, 2026-05-24)

> slug만 바꾸면 무슨소용임? 결국 사용자에게 보여지는건 이름일거아니야

정확한 지적. `rename` 명령이 slug 만 바꾸는 건 사용자 시각에서 무의미.
실제 사용자 의도는 "정체성 (slug + 표시명) 통째로 변경". 사용자 결정에
따라 **C 옵션** 채택:

- `rename` 명령 제거 — CLI / GUI / Tauri 모두.
- `update` 가 모든 필드 (`new_slug` / `new_prefix` 포함) 통합 처리.

### Backend (core)
- `ops::meta::update_type(store, prefix, new_prefix, color, description)`:
  `new_prefix` 가 다르면 내부에서 `rename_type` 호출 후 다른 필드 update.
- `ops::meta::update_status(store, slug, new_slug, name_en, name_ko, color, sort_order)`:
  동일 패턴.
- `rename_type` / `rename_status_slug` 는 내부 helper 로 유지 (외부 호출
  제거하면 dead — pub 그대로 두되 외부에서 호출 안 함).

### Tauri commands
- `admin_rename_type` / `admin_rename_status_slug` 제거.
- `UpdateTypeBody.new_prefix` / `UpdateStatusBody.new_slug` 추가.

### CLI
- `TypesCmd::Rename` / `StatusesCmd::Rename` 제거.
- `Update` 에 `--prefix` (types) / `--slug` (statuses) 옵션 — 다르면 rename
  트리거.

### GUI (Admin)
- "이름" 버튼 + rename 모달 제거.
- inline 수정 모드에 prefix / slug input 노출 (변경 가능).
- 저장 시 prefix/slug 가 바뀌었으면 `window.confirm` 으로 cascade 경고.

### 검증
- `cargo test --workspace -- --test-threads=1` → **401 passed** 유지.
- `npm test` → 116 (transport rename test → update with new_prefix 로 갱신).

### 변경
- `openguild statuses` (human): `Open 게시됨` 형식. slug 노출 X.
- `openguild statuses --json`: agent/script 용 — `slug` 필드 그대로 유지.
- `openguild statuses update <ident>` / `delete <ident>`: `<ident>` 가
  slug / id / name_en / name_ko 모두 매칭. backend `resolve_status_slug`
  helper 에 name_ko fallback 추가.
- update 출력도 slug 표시 제거 — `Open 갱신됨` 형식. rename 했을 때만
  명시 ("slug rename: ... → ...").

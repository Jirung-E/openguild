## 증상

`npm run dev` (Vite dev) 후 브라우저 콘솔에 'CSP blocks eval' 류 경고. 기능 영향 없음. 조사(2026-05-17) 결과 우리 코드/의존성에 eval 사용 없음, CSP 미설정 상태의 브라우저 advisory 경고로 판정.

## 수정 (2026-07-03) — production CSP 도입

경고의 근본 해소 = 명시적 CSP 도입(퀘스트의 원래 수정 방향). eval 을 실제로 금지(unsafe-eval 미포함)하는 CSP 를 두 배포 경로에 각각 설정:

1. **openguild-server** (`server/src/main.rs`): 모든 응답에 Content-Security-Policy 헤더 — default/connect 'self'(DEV-195 단일 origin), script 'self'+'unsafe-inline'(SvelteKit inline hydration 부트스트랩, 빌드마다 바뀌어 hash 불가), style 'unsafe-inline'(Svelte/cytoscape inline style), img/media 에 data:/blob:(첨부 미리보기), object-src 'none', frame-ancestors 'self'. tower-http set-header feature 추가.
2. **Tauri GUI** (`gui/tauri.conf.json` security.csp): script-src 'self'(Tauri 가 번들 자산 inline script 에 hash 자동 주입), connect-src 에 ipc:/http://ipc.localhost(IPC invoke) + http:/https:(원격 서버 모드 — 임의 LAN URL), img/media 에 asset:/http://asset.localhost(첨부 asset protocol) + http(s)(원격 첨부).

Vite dev(5173)는 CSP 미적용(dev 서버는 이 헤더 경로를 안 탐) — dev HMR 영향 없음.

## 테스트 방법

**브라우저 모드** (openguild-server 재빌드 후):
- 접속 → DevTools Network 에서 응답에 Content-Security-Policy 헤더 확인
- 보드/리스트/상세/admin 정상 렌더, 콘솔에 CSP violation 에러 없는지
- 첨부 이미지/동영상 표시 + 클립보드 붙여넣기 미리보기
- Firefox 에서 기존 eval 경고 소멸(또는 잔존 여부) 확인

**Tauri GUI** (재빌드 후) — CSP 로 깨질 수 있는 지점 전수:
- 앱 시동 + 보드 렌더 (inline script hash 주입 정상 여부)
- invoke 동작 (퀘스트 목록 등 — connect-src ipc: 검증)
- 로컬 길드 첨부 이미지/동영상 표시 (asset protocol)
- 원격 서버 연결 + 원격 데이터/첨부 표시 (connect/img http:)
- 다크/라이트 전환, 코드블록 하이라이팅 (style 관련)

## 회귀 주의
CSP 는 화이트리스트라 빠뜨린 리소스 출처가 있으면 그 기능만 조용히 깨짐 — 콘솔의 'Refused to ...' 에러가 단서.

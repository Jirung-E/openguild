## 증상

`npm run dev` (Vite dev) 후 http://localhost:5173 접속 시 브라우저 콘솔에:

> Content Security Policy of your site blocks the use of 'eval' in JavaScript

기능 자체는 정상 (quest list / detail 등 모두 동작). 사용자도 dogfood 검증
중 보고: "기능은 잘 동작하는거 같다" (2026-05-17).

## 조사 (2026-05-17)

- 우리 `src/` 에 `eval` / `new Function` 호출 **없음**.
- `vite/dist/client/client.mjs` — eval 안 씀.
- `cytoscape/dist/cytoscape.esm.mjs` / `marked/lib/` / `@codemirror/*` —
  모두 0 매치.
- `svelte/src/internal/client/` (브라우저 측 runtime) — 0 매치.
- `@sveltejs/kit/src/runtime/server/...` 만 `new Function` 사용
  (SSR 전용, 브라우저에서 실행 안 됨).
- `svelte.config.js`, `vite.config.ts`, `app.html`, server static 응답 모두
  CSP 헤더 / meta 설정 없음.

→ Firefox **자체의 advisory warning** (실제 CSP 가 set 되지 않았음에도 dev tools
  가 "CSP 가 있었다면 eval 차단됐을 것" 류로 표시) 가능성이 가장 큼.

대안 가설:
1. Firefox 확장 (NoScript / uBlock / etc.) 이 CSP 주입.
2. `about:config` 의 `security.csp.*` 설정.
3. 우리가 못 찾은 어떤 transitive dep 가 eval 사용.

## 우선순위

`urgency = 4`. 기능 영향 없음. 단순 콘솔 경고. production CSP 도입 시점
(보안 강화 quest) 에 동시 처리 권장.

## 수정 방향 (production CSP 시점)

```
# app.html 에 meta 또는 server 응답 헤더
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'wasm-unsafe-eval';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  connect-src 'self' http://localhost:3000;
```

dev 모드에서 Vite HMR 가 필요로 하면 dev 전용으로 `'unsafe-eval'` 추가.
Tauri 측은 `tauri.conf.json` 의 `app.security.csp` 별도 설정.

## 임시 우회

콘솔 경고 무시. 기능 영향 없음 확인됨.

## 증상

- Quest description / 댓글 / 메모 안의 `https://...` 링크를 클릭하면
  openguild Tauri 윈도우 안의 webview 가 그 URL 로 navigate → 앱이
  "다른 사이트" 가 되어버림 (SPA 가 사라짐).
- 정상 동작: 시스템 기본 브라우저에서 새 탭으로 열려야 함.

## 원인

- MarkdownView 의 `<a href="...">` 가 plain anchor — Tauri webview 가
  내부 navigation 으로 처리.
- Tauri 의 link intercept 핸들러 미설정.

## 작업

### A. Tauri 의 `WindowEvent` 또는 navigation hook
- `tauri.conf.json` 의 `app.windows[].url` 외부 URL 차단.
- `tauri::Builder` 에 `on_page_load` / `on_navigation` 핸들러 — 외부 URL
  감지 시 `tauri::api::shell::open(...)` 으로 시스템 브라우저 호출 + 차단.

### B. Frontend 차원에서 `a[href^="http"]` click intercept
- MarkdownView 의 marked renderer 커스터마이즈 — `target="_blank"` +
  `rel="noopener noreferrer"`.
- Tauri 명령 `open_external(url)` 를 만들고, click handler 에서 호출.
- A 와 병행 — A 는 안전망, B 는 의도 명확.

## 권장
- 우선 B (frontend) — 즉시 완화.
- A (Tauri 핸들러) — 안전망. 잘못된 link 라도 시스템 브라우저로.

## 적용 (2026-06-03)

`tauri-plugin-opener` 도입 + frontend 의 document-level click intercept 로
일괄 처리.

### Rust
- `gui/Cargo.toml`: `tauri-plugin-opener = "2"`.
- `gui/src/lib.rs`: `.plugin(tauri_plugin_opener::init())`.
- `gui/capabilities/default.json`: `opener:default`, `opener:allow-open-url`.

### Frontend
- `gui/frontend/package.json`: `@tauri-apps/plugin-opener` install.
- `gui/frontend/src/routes/+layout.svelte`: `onMount` 에 document-level click
  intercept (capture phase) — `composedPath` 로 anchor 찾고 `href` 가
  `http(s)://` 로 시작하면 `e.preventDefault()` + `openUrl(href)`.
  - 내부 anchor (`/quests/...`) / hash / javascript: / mailto 는 그대로 통과.
  - `openUrl` 실패 시 `window.open` fallback (마지막 안전망).
- `SchemaAheadBanner.svelte` 의 "최신 버전 받기" 버튼도 `openUrl` 로 변경
  (button 은 자동 intercept 대상 아님 — 명시 호출).

### 검증
- `cargo build -p openguild-gui`: 통과 (opener plugin embed).
- `npm run check`: 0 errors.
- `cargo test help_output_has_no_quest_id_leaks`: 통과 (BUG-016 정책).

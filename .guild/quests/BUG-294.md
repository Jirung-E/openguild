## 현상

Windows 에서 예제 플러그인 `backup-archive` 가 실패한다(admin 보고). `run` 의 명령이 `sh` 로 고정인데 Windows 에는 `sh` 가 없다.
`desktop-notify` 도 같은 이유로 Windows 에서 못 돈다.

## 원인

`run` 동작에 명령이 하나뿐이라 **운영체제마다 다른 명령을 적을 방법이 없다.** 예제만의 문제가 아니라, `run` 플러그인을
세 OS 에서 돌게 만들 수단 자체가 없다. `scope` 가 cli/gui/server 를 고르게 하면서 OS 는 가정하지 않은 셈이다.
CI 에도 Windows 잡이 없어 예제가 Windows 에서 도는지 아무도 보지 않았다.

## 구현 / 확인한 것

- 코어: `run` 에 운영체제별 명령 `windows` / `macos` / `linux` (`RunByOs`, `#[serde(flatten)]`). 그 OS 에서는 기본
  `command`/`args` 대신 띄운다(`Action::run_command`). 전달·동의 화면(`view`)은 이 기계에서 띄울 것을 쓰고, 키 리터럴 검사와
  입력란(`${…}` 참조)은 **모든 OS 것**을 본다. 셋 다 비면 직렬화에 안 나타나 **기존 동의가 그대로다**(시험으로 고정).
- Windows: 훅 프로세스를 `CREATE_NO_WINDOW` 로 띄운다 — 데스크톱 앱(콘솔 없음)에서 powershell 을 띄우면 이벤트마다 콘솔 창이
  떴을 것이다. 소스 경로는 `\\?\` 를 떼고 저장(길드 경로와 같은 규칙) — 그대로면 `${OPENGUILD_PLUGIN_DIR}` 로 넘어간다.
- 예제: `backup-archive/archive.ps1`, `desktop-notify/notify.ps1` + 각 `plugin.json` 의 `windows`. `.ps1` 은 ASCII(5.1 은 BOM 없는
  스크립트를 시스템 코드페이지로 읽는다), stdin 은 UTF-8 로 직접 읽는다, JSON 문자열은 배열로 감싸 파싱(5.1).
  `desktop-notify` 는 powershell 기동 + 풍선 4초를 위해 시한 5초 → 10초.
- 시험: `run_picks_the_command_for_this_os`, `a_run_without_os_commands_serializes_as_before`,
  `os_specific_commands_are_validated_everywhere`, `run_uses_the_command_written_for_this_os`(선택을 빼면 실패함을 확인).
- 스크립트(휴대용 PowerShell 7.4 를 스크래치에 풀어서 — 설치 안 함): `archive.ps1` 한글·공백 경로 복사 / 이미 있으면 안 덮음 /
  ARCHIVE_DIR 없음·원본 없음 → 1 / 빈 stdin → 0 / Windows 경로 JSON(`C:\\Users\\…`) 해제. `notify.ps1` 파싱부(한글 제목,
  빈 본문 대체, 200자 자르기).
- 실제 바이너리: 한글 경로 스크래치 길드에 예제를 넣고 `macos` 에 `windows` 와 같은 PowerShell 명령을 적어 `backup new` →
  한글 이름 폴더에 사본 생김(OS 선택 + 설정값 환경변수 + UTF-8 stdin 을 한 번에).
- **Windows 에서는 직접 확인하지 못했다** — 이 환경에 Windows 도, Windows 교차 빌드도, CI 의 Windows 잡도 없다. Windows
  PowerShell 5.1 에서의 동작, 풍선 알림, `CREATE_NO_WINDOW` 컴파일은 Windows 에서 확인이 필요하다(릴리스 워크플로의 Windows
  빌드가 컴파일은 본다).

## 추가 — admin 실사용: `powershell` 로는 0xFFFD0000, `pwsh` 로는 성공

0xFFFD0000(-196608)은 Windows PowerShell 5.1 이 `-File` 인자를 파일로 받아들이지 못할 때 내는 종료 코드다 — 스크립트가
시작도 안 했다. 5.1 은 `-File` 경로를 와일드카드로 해석해 `\\?\C:\…` 의 `?` 에서 걸리고, 7(`pwsh`)은 문자 그대로 받는다
(추정 — Windows 에서 경로 문자열로 확인 필요).
그 경로의 출처: **이전 빌드가 `plugin-sources.json` 에 `\\?\` 를 붙여 적었다.** 위 수정은 새로 등록할 때만 뗐으므로 이미 등록된
소스는 계속 그 형태로 `${OPENGUILD_PLUGIN_DIR}` 에 들어갔다.

- `SourcesFile` 을 읽을 때마다(`load`, `update`) 접두사를 뗀다 — 옛 기록도 그대로 동작하고, 다음 쓰기에서 파일도 고쳐진다.
  같은 폴더 재등록 판정도 뗀 형태끼리 비교한다.
- 훅에 넘기는 `OPENGUILD_PLUGIN_DIR` / `OPENGUILD_PLUGIN_DATA_DIR`(치환·환경변수 둘 다)에서도 뗀다 — 출처와 무관하게.
- 시험 `a_source_recorded_with_a_verbatim_prefix_still_works`(옛 형식 파일 → 적재·재등록 판정·재기록). 정규화를 빼면 실패함을 확인.
- Windows 에서 재확인 필요.

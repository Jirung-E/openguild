# [cli] library attach 서브커맨드 누락

## 배경

`openguild` 배포용 스킬(SKILL.md)에 첨부파일 관련 사용법을 문서화하려고
CLI를 확인하던 중 발견. 도서관(`library`)을 만든 목적 중 하나가 큰
첨부파일(기획 문서 원본 PDF, zip 등)을 저장하는 것이었는데, 실제로
CLI엔 `library attach` 명령이 없었다.

`quest attach`/`campaign attach`(DEV-170)는 list/add/remove 서브커맨드가
다 있는데, 도서관(book) 첨부는:
- core: `ops::attachments::{list,add,remove}_book_attachment` 이미 구현 +
  테스트(`spec.pdf`, `f.zip` 케이스) 있음.
- server: `server/src/routes/library.rs` 에 라우트 있음.
- GUI: `AttachmentSection.svelte` 가 library 페이지에도 연결돼 있음.
- **CLI만 빠져 있었음** — `LibraryCmd` enum에 `Attach` variant 자체가 없었다.

## 수정

`quest`/`campaign` 첨부와 동일한 `AttachCmd`(List/Add/Rm) 를 재사용해
`LibraryCmd::Attach { sub: AttachCmd }` 추가. 대상이 book 하나뿐이라
quest/campaign 처럼 `CommentScope` 로 분기할 필요 없어, book 전용
`Backend::book_attachments_{list,add,remove}` 메서드 + `run_book_attach_cmd`
핸들러를 새로 추가(기존 comment/memo 의 `CommentScope` enum은 건드리지
않음 — 그쪽까지 book 케이스를 추가하면 불필요한 ripple).

원격 모드는 quest/campaign 첨부와 동일하게 미지원(로컬 전용) — 기존
패턴 그대로.

```bash
openguild library attach list <book-id>
openguild library attach add <book-id> <file> [--name "표시 이름"]
openguild library attach remove <book-id> <path>
```

## 테스트 방법 (로컬에서 이미 확인함)

1. `cargo build -p openguild-cli` — 통과.
2. `cargo test -p openguild-cli` — 102 passed (회귀 없음).
3. `cargo clippy -p openguild-cli --all-targets -- -D warnings` — 클린.
4. 스크래치 길드에서 실기 확인:
   - `library new` → book id 획득
   - `library attach add <id> <file> --name spec.pdf` → 첨부됨
   - `library attach list <id>` → 목록에 표시
   - `library attach remove <id> <path>` → 제거되고, 참조가 없어지면
     sidecar json 도 자동 삭제됨(quest/campaign 첨부와 동일한 orphan
     정리 동작).

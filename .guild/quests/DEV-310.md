DEV-246 로 **퀘스트 본문** 파일의 추가/삭제/수정은 증분 반영되지만, 나머지 파일은 아직 하나만 바뀌어도 전체 재색인으로 넘어간다. 댓글 하나를 외부에서 고치거나 git pull 로 캠페인·도서관 파일이 들어오면 DEV-246 이 없앤 4초가 그대로 돌아온다.

## 현황
`incremental::sync_on_open` 이 다루는 범위는 `.guild/quests/{slug}.md` 뿐이다. 나머지는 `drift::detect_drift` 가 변화를 감지하면 `auto_resync` → `reindex::reindex_all`:
- sibling: `{slug}.comments.md` / `.memo.md` / `.attachments.json`
- `.guild/campaigns/*.md`
- `.guild/library/**/*.md`, `.guild/rules/**`
- `.guild/worklog/*.md`

## 작업
1. sibling 파일부터 — 파일 → 해당 quest 의 댓글/메모/첨부 캐시만 재적재(퀘스트 행은 건드리지 않음). 빈도가 가장 높다(댓글이 제일 자주 바뀐다).
2. campaigns — 파일 1개 → 캠페인 행 + `campaign_quests` 링크만 재동기화.
3. library/rules — 문서 행 + `doc_history` 사이드카.
4. worklog — 노트/활동 집계 캐시.
5. 각 단계마다 "표현 불가능한 변화" 는 full reindex 안전망 유지.

## 검증
- 각 종류별로 파일 1개 추가/수정/삭제 후 `needs_full_reindex == false` 확인하는 단위 테스트.
- 퀘스트 651개 길드에서 댓글 1건 외부 수정 후 `bench_open` 측정 — 현재 약 4초에서 100ms 미만 목표.
- `check drift` / `check counters` clean 유지.

## 증상

admin: *"지워진 도서관 문서를 참조하는 cross-link를 클릭하면 도서관 페이지로
넘어간다."*

없는 문서를 가리키는 `[[BOOK-005]]` 는 **빨갛게 칠해지고** 툴팁도 "존재하지
않는 도서관 문서" 라고 뜬다. 거기까지는 맞다. 그런데 **누르면 실제로 이동한다** —
`/library?id=BOOK-005` 로 가서 도서관 페이지가 열린다. 사용자는 "링크가 살아
있었나?" 하고 잠시 헷갈리고, 보던 문서에서 튕겨 나온다.

도서관만이 아니다. 없는 퀘스트를 가리키면 `/quests/DEV-999` 로 간다.

## 원인

`MarkdownView.svelte` 의 `applyRefToAnchor` 가 `href` 를 **존재 여부와
무관하게** 붙인다.

```js
const ref = resolved.ref;              // 없으면 null
a.href = refHref(id, kind, ...);       // ← null 이어도 그대로 붙인다
a.className = ref ? 'xlink' : 'xlink missing';
```

`missing` 은 **색과 툴팁에만** 반영된다(`.md a.xlink.missing` 이 danger 색을
칠한다). 링크로서의 동작은 실재하는 것과 똑같다. 호버 미리보기는 `missing` 을
제대로 빼고 있어서(DEV-256), **클릭만 빠진 셈**이다.

## 고칠 방향

`missing` 이면 `href` 를 안 붙인다. `<a>` 에 `href` 가 없으면 브라우저가
링크로 취급하지 않으므로 클릭도 포커스도 안 간다.

갱신 경로는 그대로 돈다 — `rewriteCrossLinks` 가 `a.dataset.xtoken` 으로
다시 resolve 하고, [[BUG-173]] 의 "인덱스 늦은 적재" 경로가 채워지면
`applyRefToAnchor` 가 다시 불려 그때 `href` 가 붙는다. `querySelectorAll`
셀렉터가 `a.xlink` / `a.xlink.missing` 이라 href 유무와 무관하다.

**커서도 같이 본다.** `.xlink` 가 링크 모양이라 `missing` 이면 손가락 커서가
"눌리는 것" 처럼 보인다.

## 테스트 방법

- 없는 `[[BOOK-999]]` 가 그려진 뒤 `href` 속성이 **없다**.
- 실재하는 `[[BOOK-001]]` 은 여전히 `href` 를 갖는다.
- 없던 것이 인덱스에 채워지면 다시 `href` 가 붙는다(BUG-173 경로 회귀 방지).

**저장 결정 제안**: `.guild/theme.toml` (길드 데이터 — git tracked, 팀 공유) 보다 **localStorage 우선 권장** — 테마는 개인 취향(같은 길드를 다크로 보는 사람/커스텀으로 보는 사람 공존)이라 길드 파일에 넣으면 멀티유저에서 충돌. 프리셋 export/import(JSON)가 공유 요구를 커버. 착수 시 사용자 확인 1회.

## 단계
1. **토큰 카탈로그**: `frontend-theme-tokens` 길드 규칙 + `themePalette`(DEV-074 fix20 단일 source)에서 사용자 노출 토큰 목록 확정 — 전부 노출하면 압도적이라 1차는 핵심 ~12개(--bg/--bg-elev/--text/--text-muted/--accent/--success/--warn/--danger/--btn-primary-* 등), 고급 토글로 전체.
2. **store**: `lib/stores/customThemes.ts` — {name, base: 'dark'|'light', overrides: Record<token, hex>}[] + activeTheme(기존 theme store 확장: 'dark'|'light'|'system'|`custom:<name>`).
3. **적용 경로**: `<html>` style.setProperty 로 override 주입(기존 theme 적용 지점에 합류). ⚠️ Quest Board 는 CSS 변수를 못 쓰고 themePalette hex 를 직접 쓰므로(DEV-074) — themePalette 가 override 반영하도록 함께 수정 + cy.style() 재적용 훅 확인. **이게 최대 함정.**
4. **설정 UI**: 테마 편집기 섹션 — 토큰별 color picker(native input type=color) + live preview + reset + 프리셋 저장/선택/삭제 + export/import.
5. no-hex 규칙과 충돌 없음(사용자 입력 hex 는 데이터, CSS 소스 아님).

예상 규모: 중~대형. 함정: Board palette 연동(3), 프리셋과 system 자동전환의 상호작용 정의.

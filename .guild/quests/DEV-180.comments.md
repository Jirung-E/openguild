**(A) `{slug}.history.jsonl`** 추천 근거 재확인: append-only(매 변경 전체 재작성 없음), 사이드카 패턴(comments/memo/attachments) 일관, git diff 도 줄 단위로 깨끗. (B) frontmatter 배열은 상태 변경마다 파일 전체 재작성 + frontmatter 비대화 — 기각 권장.

## 단계
1. **포맷**: 한 줄 = `{"op":"change_status","old":"open","new":"testing","ts":"..."}` (quest_history 컬럼 그대로). slug 는 파일명이 담당.
2. **이중 기록**: quest_history INSERT 하는 모든 지점(ops::quests — change_status/change_type 등)에서 사이드카 append 동시 수행. 파일=진리원, DB=캐시로 지위 정상화.
3. **reindex**: `.guild/quests/*.history.jsonl` → quest_history 재구축(기존 행 삭제 후 재삽입, slug→현재 id 매핑 — DEV-022 재매핑 패턴).
4. **스냅샷**: quests 서브디렉토리에 있으므로 SOURCE_SUBDIRS 로 자동 포함 — 확인만.
5. **일회성 마이그레이션**: 기존 index.db quest_history → 사이드카 파일로 export (reindex 시 사이드카 없고 DB 에 행 있으면 write-back — drift 보정과 유사, 또는 명시 명령 `openguild check history --export`). 이게 없으면 첫 reindex 에서 기존 이력 소실 ⚠️ — 설계 시 핵심 주의점.
6. **gitignore 여부**: history 는 감사 기록이므로 **tracked 권장**(comments 와 동일). memo 처럼 개인 데이터 아님.
7. 테스트: append→reindex 왕복, 마이그레이션(DB-only 이력 보존), 스냅샷 복원 후 이력 생존.

## 페이지 전환 / 다른 명령 시 reindex 검토 (2026-06-07)

### 비용 분석
`drift::auto_resync` 호출 비용:
1. `drift::detect_drift` — `.guild/` 의 모든 파일 mtime 스캔 + DB updated_at 비교. **모든 파일 stat 호출** — n_files × syscall.
2. drift 있으면 `reindex` — 전체 파일 재파싱 + DB rewrite. **수십~수백 ms** (길드 크기 비례).

### 페이지 전환 시 매번 호출?

#### 단점
- 사용자가 quest list ↔ board ↔ detail 빠르게 이동하면 매 클릭마다 file stat 수십~수백 회 + 필요시 reindex. UI 지연 (특히 detail 진입).
- detail 페이지가 좀 느려진다는 사용자 피드백 가능성.

#### 장점
- CLI / 외부 편집기로 동시 작업 시 즉시 반영.

### 절충안 제안

**A. 드물게 + 조건부**
- 페이지 전환 시 매번 X. **`detect_drift` 만 background tick** (예: 30 초 인터벌).
- drift 발견 시에만 reindex 호출 + UI toast `'외부 변경 감지 — 새로고침됨'`.
- 사용자 액션 (페이지 전환) 과 비동기 — UI block 없음.

**B. mutation 후만 invalidate**
- 자기 GUI 의 mutation (create / update / status change) 후엔 캐시 이미 정합 (ops 가 file+DB 양쪽 갱신).
- 페이지 전환 자체에 reindex 필요 없음 — A 의 background tick 만 의존.

**C. file watcher**
- Tauri 의 `notify` crate 로 `.guild/` 감시. file 변경 이벤트 → drift 즉시.
- 가장 정확하지만 구현 복잡 + 본인 GUI 의 write 도 이벤트 발생 → debounce 필요.

### 권장
B + A 조합 — mutation 은 자체 해결, **외부 변경은 30~60s background drift check** 로 잡음. UI 지연 0 + 자연스러운 갱신. C 는 별도 quest (예: DEV-095 후속) 로 단계적 도입.

## 한 것 (2026-10-24)

- **`QueryField` 부품** — 쿼리 칸(입력 · 지우기 × · 틀리면 빨간 칸과 이유 · `?` 쓰는 법)을 퀘스트 목록에서 떼어 냈다. 대상마다 다른 것은 쓰는 법에 보일 키 · 안내 글 · 예시 글뿐. 퀘스트 목록은 이 부품을 쓰도록 바꿨고 **모양은 그대로**(아래 확인).
- **보드** — 보드 설정의 필터에 쿼리 칸이 **보이기만 하고 어디에도 이어지지 않았다**(DEV-447 이 목록만 이었다). 이제 편집하면 목록과 같은 값이 되고, 보드는 코어 판정(`?q=`)으로 흐린다. 틀린 동안은 쿼리만 빼고 흐린다. 새로 불러오면 다시 묻는다. `isFilterActive` 에 쿼리가 들어가 '필터 적용 중 N/M' 이 뜬다.
- **캠페인 목록** — 상태 · 정렬 줄 아래 쿼리 칸. 코어(`GET /api/campaigns?q=`, 앱 `list_campaigns(q)`)가 고른 번호와 상태 선택을 그리고로. 주소 `?q=` 에 실린다.
- **도서관** — 탐색기 · 트리 두 보기 모두 태그 줄 아래 쿼리 칸. 코어(`GET /api/library?q=`, 앱 `list_books(q)`)가 고른 문서와 태그 줄 · 검색을 그리고로. 주소 `?q=` 에 실리고, 폴더 · 문서를 옮겨도 남는다.
- 앱(Tauri) 전달: `/api/library?q=` · `/api/campaigns?…q=` 를 명령 인자로.
- 쿼리 칸은 캠페인 · 도서관에서는 **늘 보인다**(퀘스트 목록처럼 '고급' 안에 넣을 자리가 없다). 거슬리면 접는 토글을 따로 한다.

## 확인 (develop 서버 + 웹 빌드, WebKit, 이 길드 사본)

- 퀘스트 목록 쿼리 칸 — 바꾸기 전 빌드(develop)와 후 빌드를 같은 화면(틀린 쿼리 + 쓰는 법 열림)으로 찍어 **PNG 가 바이트까지 같다**(라이트 · 다크), 버튼 · × · 입력칸의 계산된 스타일도 같다.
- 캠페인: 전체 7 → `status:done` 5 · `quest:DEV-430` 1 · `베타 -status:done` 1 · `end:overdue` 0(CLI 와 같음), 주소에 `q=`. `urgency:2` → 빨간 칸 + "쓸 수 있는 키: status, start, end, quest", 목록 7 그대로. 새로고침 뒤 그대로 1.
- 도서관(탐색기, 아키텍처 폴더, 사본에 태그 결정 · 초안을 달고): `tag:결정` → BOOK-001, `-tag:결정` → BOOK-003, `잠금` → BOOK-003, `status:open` → 오류 + "tag, folder, updated". 주소 `?q=` 로 `아키텍처/상세` 에 들어가면 BOOK-006 만, 칸에 쿼리 그대로. 트리 보기 폭 400px 가로 넘침 없음.
- 보드: `status:testing` → '필터 적용 중 — 13/846', `type:BUG status:open` → 1/846(둘 다 CLI 와 같은 수), `stauts:x` → 오류 + 846/846(쿼리만 빼고). 보드에서 건 쿼리가 목록에도 걸려 있다.
- 시험: `isFilterActive` 가 쿼리를 센다(공백만은 아님), 앱 전달이 `q` 를 넘긴다. 페이지 오류 0.

## 테스트 방법

1. 캠페인 → 쿼리 칸에 `status:done` → 끝난 것만. `?` 를 누르면 캠페인 키가 나온다.
2. 도서관 → `tag:<있는 태그>` 또는 `-folder:<폴더>` → 맞는 문서만. 폴더를 옮겨도 칸이 남는다.
3. 보드 → 보드 설정 → 고급 → 쿼리에 `status:open` → 나머지가 흐려지고 '필터 적용 중' 이 뜬다. 목록에 가도 같은 쿼리.
4. 퀘스트 목록의 쿼리 칸 모양이 예전과 같다.

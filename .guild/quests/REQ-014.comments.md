## 요청

검색 발췌에서 **걸린 부분을 하이라이팅**한다.

발췌만 보여주면 "이 문서가 왜 나왔는지" 는 알아도 "어느 글자가 맞았는지" 는
여전히 눈으로 찾아야 한다. 토큰이 여러 개면 더 그렇다.

## 구현

`lib/utils/highlight.ts` 신설.

- `searchTokens(query)` — core 의 `search()` 와 같은 규칙(공백 분리).
- `highlightSegments(text, query)` — 걸린 조각과 아닌 조각의 **배열**을 돌려준다.

적용: 검색 팔레트(`.pwhy-x`, [[REQ-012]]) + 규칙 목록(`.rule-excerpt`,
[[REQ-013]]). 두 곳이 같은 표기를 쓴다.

## `{@html}` 을 쓰지 않은 이유

`<mark>` 를 문자열로 끼워 넣어 `{@html}` 로 렌더하는 게 가장 짧지만, **발췌는
문서 본문·댓글에서 온 값**이라 마크업이 섞여 있을 수 있다. 그대로 렌더하면
그게 곧 주입 경로다. 조각 배열을 돌려주고 컴포넌트가 각 조각을 텍스트로
그린다 — 텍스트 노드라 애초에 파싱되지 않는다.

테스트로도 못 박았다: `<script>alert(1)</script> 수달` 을 넣으면 스크립트
부분은 그냥 글자로 남고 '수달' 만 표시된다.

## 판단한 것들

- **토큰이 여러 개면 각각 전부 표시한다.** core 의 AND 는 "문서가 결과에
  나오는 조건" 이고, 표시는 눈에 보이는 모든 일치가 대상이다.
- **겹치는 일치는 하나로 합친다.** `가나` 와 `나다` 가 `가나다` 에 겹쳐 걸리면
  조각이 쪼개져 어색하다.
- **소문자화로 길이가 달라지는 입력은 표시를 포기한다.** 일부 문자는
  `toLowerCase()` 후 길이가 변해(예: `İ` → 2글자) 인덱스가 어긋난다. 잘못된
  위치를 칠하느니 원문 그대로 둔다.
- 정규식을 쓰지 않았다 — `indexOf` 로 찾으므로 `a.b`, `100%`, `c:\tmp` 같은
  검색어가 이스케이프 없이 그대로 동작한다.

## 표기

기본 `<mark>` 는 노란 배경 + 검정 글자라 다크 테마에서 튄다. 배경은
`color-mix(in srgb, var(--accent) 26%, transparent)`, 글자는 `var(--text)`.
`check:no-hex` 통과(토큰만 사용).

## 검증 (브라우저 실측)

**규칙 목록** — `setext` → `release-process` 의 발췌에서 `setext` 만 표시.

**검색 팔레트** —

| 검색어 | 결과 |
|--------|------|
| `근데` | 4행 모두 표시, 한 발췌에 두 번 나오면 **둘 다** |
| `서버 퀘스트` | 한 발췌에서 `서버` 와 `퀘스트` 를 각각 표시 |

**다크 테마** — 배경 `srgb(0.345 0.651 1 / 0.26)`, 글자 `rgb(201 209 217)` 로
테마 토큰을 따라간다. 라이트에서는 각각 다른 값. 스크린샷 육안 확인.

## 테스트 15건

단일/반복/다중 토큰, 대소문자, 겹침·맞닿음 병합, 빈 입력, 앞·뒤 경계,
마크업 문자열, 정규식 특수문자, 그리고 **조각을 이어 붙이면 항상 원문**
(하이라이트가 글자를 잃거나 더하지 않는다는 계약).

`just test` 499건 통과.

## 노란색으로 변경

accent(파랑) 계열이던 표시를 노랑으로 바꿨다.

`frontend-theme-tokens` 규칙대로 **전용 토큰을 다크/라이트 양쪽에 신설**했다
(`global.css`). 컴포넌트에는 hex 를 쓰지 않는다 — `check:no-hex` 통과.

```
:root                  --search-hit-bg: #6b4b00;  --search-hit-text: #ffdf5d;
[data-theme='light']   --search-hit-bg: #fff3c4;  --search-hit-text: #4a3800;
```

## `--warning` 을 재사용하지 않은 이유

이미 노란 계열 토큰(`--warning`: 다크 #f5a623 / 라이트 #9a6700)이 있지만
쓰지 않았다.

- **의미가 다르다.** 경고가 아니라 검색 일치다. 규칙 4("토큰은 용도에 맞게")
  가 `--nav-*` 를 Nav 전용으로 못 박은 것과 같은 이유다.
- 나중에 경고색을 조정하면 검색 표시까지 따라 바뀐다.
- `--warning` 은 **글자색**으로 쓰이는 값이라 배경으로 깔면 대비가 안 맞는다.

## 테마별로 밝기를 반대로 잡았다

브라우저 기본 `<mark>` 는 노란 배경 + 검정 글자 고정이라 다크에서 튄다.

- **다크**: 어두운 바탕이라 배경을 낮추고(#6b4b00) 글자를 밝은 노랑(#ffdf5d)으로.
- **라이트**: 흰 바탕이라 형광펜에 가까운 밝은 노랑(#fff3c4) + 진한 갈색 글자(#4a3800).

구분된다.

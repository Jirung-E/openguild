BUG-105 의 admin 댓글 후속 (놓쳤던 두 번째 줄): "frontend 위치를 지정해줄
config 파일을 따로 두는 등의 방안 생각해보기".

## 현재 상태 (server/src/main.rs)
frontend 정적 자산 위치는 두 가지로만 결정:
1. `FRONTEND_DIST` env — 실행할 때마다 지정해야 함.
2. 자동 탐색 — cwd 의 `gui/frontend/build`, 없으면 exe 조상 디렉토리들을
   차례로 시도 (cargo build 산출물 레이아웃 전제).

둘 다 "설치 없이 소스/바이너리만 가져다 쓰는" 환경에선 불편: env 는
휘발성이고, 자동 탐색은 repo 레이아웃을 벗어나면 (exe 만 복사 등) 실패.

## 제안
서버 설정 파일 도입 — 예: `openguild-server.toml` (exe 옆 또는 cwd,
또는 `--config <PATH>`):

```toml
[server]
frontend_dist = "C:/path/to/frontend/build"
# 향후 port / bind addr / guild_path 등도 이 파일로 통합 가능
```

우선순위: CLI 인자/env > config 파일 > 자동 탐색 (기존 동작 유지,
config 는 그 사이에 끼움).

## 함께 (BUG-105 조사 시 이미 확인된 개선점)
- 시동 로그에 static 서빙 상태 명확히 출력: 서빙 중이면 경로, 아니면
  "frontend 자산 없음 — API-only 모드. FRONTEND_DIST 또는 config 로
  지정 가능" 안내. 지금은 아무 표시가 없어 사용자가 왜 화면이 안 뜨는지
  알 수 없음 (BUG-105 의 실제 혼란 원인).

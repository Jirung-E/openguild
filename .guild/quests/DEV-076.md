퀘스트에 desired_due / required_due 날짜 필드 추가. Home 페이지에 마감 임박 퀘스트 carousel/conveyor (Quest Board 노드 모양) 표시.

## 명세 (2026-05-26, 사용자 확인 완료)

### 필드
- `desired_due` (희망 기한): 사용자가 원하는 마감. nullable. YYYY-MM-DD.
- `required_due` (필수 기한): 절대 마감. nullable. YYYY-MM-DD.

### Home 표시 — 임박 판단
**기준은 `required_due` 만.** desired_due 는 정보성 (Quest Detail 등에서 표시).

임박 임계값은 urgency 별로 다름:
- urgency 1 (Critical): 7일 이내
- urgency 2 (High):     4일 이내
- urgency 3 (Medium):   1일 이내
- urgency 4 (Low):      1일 이내

### Overdue 별도 섹션
- `required_due < today` 이고 status ∉ {done, cancelled} 인 퀘스트 → "마감 지남" 섹션.
- 임박 섹션과 분리. 1개라도 있으면 노출, 없으면 섹션 자체 숨김.

### Home 섹션 순서
1. 진행중 캠페인 (carousel)
2. 곧 시작되는 캠페인 (conveyor)
3. **마감 지난 퀘스트 (Overdue)** ← 신규, 있을 때만
4. **마감 임박 퀘스트 (Imminent)** ← 신규
5. 최근 추가된 퀘스트

### 카드 모양
Quest Board 의 cytoscape SVG 노드 (`makeSvgUrl`) 와 동일.
공유 utility 로 추출 → `lib/utils/quest-node-svg.ts`. Home 의 carousel/conveyor
는 이 SVG 를 inline `<img>` 로 표시.

### 구현 범위
한 번에 전체:

2. core: Quest struct + frontmatter parse/write.

4. server: REST 응답에 두 필드 포함.

6. GUI Quest Edit: 두 개 date input.

## 구현 (2026-05-27)

### 1) DB / core
- migration `0009_quest_due_dates.sql`: `quests` 에 `desired_due TEXT` /
  `required_due TEXT` (둘 다 NULL). `idx_quests_required_due` partial
  index (NULL 제외, alive only) — Home 임박 필터 가속.
- `QuestFrontmatter` / `QuestRow` 에 두 nullable 필드 추가.
  `skip_serializing_if = "Option::is_none"` — 미설정 시 frontmatter /
  JSON 에서 키 자체 누락.
- `reindex`: 파일 → DB sync 시 두 필드 propagate.
- `ops::quests::write_quest_file`: DB → 파일 sync 시 두 필드 propagate.

### 2) Service / Ops
`services::quests::set_due_dates(pool, id, desired, required)`:
- `Some(Some(d))` = 설정, `Some(None)` = 해제, `None` = 변경 없음.
- 빈 문자열은 자동으로 None 으로 정규화.
- YYYY-MM-DD 형식 검증 (10자 / 4-2-2 / 숫자 + 대시).

`ops::set_due_dates`: journal append → service 호출 → 파일 sync →
after_mutation (자동 백업 검토).

### 3) CLI
```
openguild quest due <slug>
  [--desired YYYY-MM-DD] [--required YYYY-MM-DD]
  [--clear-desired]      [--clear-required]
```
- 인자 없으면 현재 상태 출력 (`(없음)` / 날짜).
- `--desired` vs `--clear-desired` 는 clap `conflicts_with` 로 상호배타.

### 4) Server
`PATCH /api/quests/{id}/due`
- JSON body 의 키 존재 여부로 변경 의도 구분:
  - `{ "desired_due": "2026-06-15" }` → 설정
  - `{ "desired_due": null }`          → 해제
  - 키 없음                              → no-op
- 두 필드 동시 가능.

### 5) GUI
- `lib/types/index.ts`: `Quest.desired_due?` / `Quest.required_due?` 추가.
- `lib/api/quests.ts`: `questsApi.setDueDates(id, body)` 추가.
- `lib/utils/quest-node-svg.ts`: 신규 — Quest Board 의 노드 SVG 와 동일한
  모양을 다른 곳에서 재사용. `makeQuestNodeSvgUrl(quest, overlayColor?)`
  반환 = data URL. overlay 색 (overdue 빨강) 옵션.
- `lib/components/QuestNodeConveyor.svelte`: 신규 — `CampaignConveyor`
  패턴 (rAF marquee + 드래그 + 정지) 으로 quest 노드 카드 회전.
  카드 폭 = NODE_W (284px). overdue 모드는 빨간 stroke overlay.
- `lib/components/Home.svelte`:
  - 전체 quest list 로드 (RECENT_QUEST_LIMIT 은 slice 만, 임박/Overdue
    분류는 전체에서).
  - `imminentQuests` (`required_due` 가 urgency 별 임계값 이내,
    status ∉ done/cancelled).
  - `overdueQuests` (`required_due < now`, 동일 status 필터).
  - 섹션 순서: 진행중 / 곧 시작 / Overdue (조건부) / 임박 (조건부) / 최근.
  - Overdue 개수는 빨간색 강조.
- `routes/quests/[id]/+page.svelte`: 편집 모드에 두 개 `<input type="date">`
  (희망 / 필수). 빈 값 → null (해제). save 시 변경 있을 때만 PATCH.
  읽기 모드 헤더 메타에 두 기한 표시 (필수=주황, 희망=파랑).

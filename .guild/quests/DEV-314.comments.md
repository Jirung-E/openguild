구현 완료.

## 문제
updater 엔드포인트는 `releases/latest/download/latest.json` **파일 하나**다. 그런데 windows 잡이 자기 서명만 담은 latest.json 을 만들어 릴리스에 올리는 구조라, 플랫폼이 늘면 잡마다 같은 이름을 덮어써 **마지막 잡의 플랫폼만 남는다**. macOS 를 추가하는 순간 터질 자리였다.

## 변경
- windows 잡의 `Generate latest.json` 제거, 릴리스 첨부 목록에서도 latest.json 제거. 이제 빌드 잡은 설치 파일과 `.sig` 만 올린다.
- `updater-manifest` 잡 신설 (`needs: [windows, macos]`, 태그 push 에서만):
  `gh release download --pattern '*.sig'` 로 **실제 릴리스에 올라간 서명 자산**을 받아 하나의 latest.json 으로 합쳐 첨부한다.

조각 파일을 artifact 로 나르는 방식도 검토했는데, 릴리스 자산을 직접 읽는 편이 "artifact 엔 있는데 릴리스엔 없는" 어긋남이 원천적으로 없고 단계도 적다.

자산 이름 → 플랫폼 키는 `platform_of()` 한 곳:
- `*-setup.exe` → `windows-x86_64`
- `*.app.tar.gz` → `darwin-aarch64`
- 그 외(deb/rpm/AppImage) → updater 대상 아님, skip

## 검증 (실제 실행)
워크플로에서 이 스텝의 스크립트를 그대로 뽑아 로컬에서 돌렸다.
- 서명 3개(win/mac/deb)를 놓고 실행 → `windows-x86_64` + `darwin-aarch64` 두 항목의 latest.json 생성, deb 는 "skip(updater 대상 아님)", `has_manifest=true`.
- 서명이 하나도 없을 때 → 경고 출력 + `has_manifest=false` + exit 0 (첨부 스텝이 건너뛰어짐). 서명 시크릿 없는 환경에서 릴리스가 실패하지 않는다.

`gh` 가 없는 로컬에서도 다운로드 실패가 `|| true` 로 흡수되는 것까지 같이 확인됐다.

## 규칙 반영
`.guild/rules/release-process.md` 에 "latest.json 은 빌드 잡이 만들지 않는다" 와 사후 점검 항목(플랫폼이 전부 들어있는지) 추가.

## 미검증
실제 태그 릴리스에서의 동작(잡 순서·gh 권한). `needs` 로 두 빌드 잡 뒤에 도는 것은 보장되고, `github.token` 에 `contents: write` 가 이미 부여돼 있다.

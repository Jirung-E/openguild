사용자 보고: "처음 gui를 키면 welcome 페이지에 이전에 연결했던 원격 길드가
표시되는데, 해당 서버에 연결이 되어있지 않음에도 클릭이 가능함.
'경로를 찾을 수 없는 로컬 길드'랑 똑같이 회색으로 비활성화 표시가
되어야함. 즉, 처음 gui를 켜면 비활성화로 표시되는데 자동으로 연결
확인을 해서 연결이 되어있으면 다시 활성화로 표시해야함."

## 현재 상태

`welcome/+page.svelte` 의 `UnifiedEntry` — local 은 `missing: boolean`
필드가 있어 경로가 없으면 `class:missing`(회색, 클릭 비활성화, "⚠ 경로를
찾을 수 없습니다")으로 표시되지만, remote(`RemoteGuild`)에는 이런 필드가
없어 항상 활성 상태로 렌더된다. 서버가 죽어있어도 클릭해서 연결 시도
가능 — 클릭해야만 실패를 알게 됨.

## 요구사항

- Welcome 마운트 시 `remoteGuildList` 의 각 항목에 대해 백그라운드로
  `pingRemoteServer(url)`(이미 있는 헬퍼, `/health` 확인) 호출.
- 확인 전(또는 실패) 상태는 local 의 `missing` 과 동일한 스타일(회색,
  클릭 비활성화)로 렌더 — `UnifiedEntry` 의 remote variant 에 `reachable:
  boolean | null`(null = 확인 중) 같은 필드 추가 검토.
- 확인 성공하면 해당 항목만 활성화로 전환(전체 리렌더 없이).
- 여러 원격 항목이 있으면 병렬로 ping(순차 대기 시 목록이 느리게
  풀리는 느낌 방지).
- 로컬의 "⚠ 경로를 찾을 수 없습니다" 와 톤이 맞는 문구(예: "⚠ 서버에
  연결할 수 없습니다") 추가.

## 구현 완료

`welcome/+page.svelte`:
- `remoteReachable: Record<string, boolean>` (url → 확인 결과) 신설. 키
  없음 = 아직 확인 안 됨(local 의 missing 과 동일하게 처리 — 비활성화).
- `onMount` 에서 `remoteGuildList` 전체를 `Promise.then`/`catch` 로
  **병렬** ping(`pingRemoteServer`) — 응답 오는 항목부터 즉시
  `remoteReachable` 갱신, 전체 대기 없음.
- 목록 렌더 — `class:missing` 을 local 의 `entry.missing` 또는 remote 의
  `!remoteOk` 로 통일(완전히 같은 회색/비활성화 스타일 재사용). 버튼
  `disabled` 도 동일 조건. title/label 3 상태 분기: 확인 전 "연결 확인
  중…"(muted, `.checking-label`), 실패 "⚠ 서버에 연결할 수 없습니다"
  (`.missing-label` 재사용, warning 톤), 성공 시 평소처럼 클릭 가능.

검증: svelte-check/no-hex/vitest(205) 전부 통과, `openguild-gui.exe`
재빌드 후 정상 기동 확인(크래시 없음). **단, 이번 세션엔 computer-use
도구가 연결 끊긴 상태라 화면을 직접 보며 비활성화→활성화 전환을 눈으로
확인하지는 못했음** — 로직은 local 의 기존 missing 패턴을 그대로
재사용한 것이라 동작 신뢰도는 높지만, 실제 화면 확인은 권장.

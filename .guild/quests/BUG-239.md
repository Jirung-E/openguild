## 증상

다크모드 ↔ 라이트모드 전환 시 **모든 컴포넌트가 동시에 바뀌지 않고 시간차**가
있다. 일부는 즉시 바뀌고 일부는 뒤늦게 따라와, 전환이 끊겨 보인다.

## 원인 (조사 완료)

테마 전환 자체에 애니메이션이 걸려 있는 게 아니다. 컴포넌트들이 **hover 피드백
용으로** 선언해 둔 transition 이 테마 전환 때도 같이 발동하는 것이다.

`<html data-theme>` 가 바뀌면 CSS 변수(`--bg`, `--text`, `--border` …)의 값이
바뀌는데, `transition: background 0.15s` 같은 선언이 있으면 그 변화가
**애니메이션된다.** 그런데 지속시간이 컴포넌트마다 제각각이다:

| 지속시간 | 선언 수 |
|----------|---------|
| 0.15s | 10 |
| 0.12s | 10 |
| 0.1s | 8 |
| 0.2s | 1 |
| 0.4s | 1 |

transition 이 아예 없는 요소는 **즉시** 바뀌고, 0.4s 짜리는 가장 늦게 끝난다.
그 편차가 그대로 "시간차" 로 보인다.

관련 선언 위치(일부): `global.css:280`(checkbox),
`CampaignCarousel.svelte:203,243`, `CampaignConveyor.svelte:307`,
`QuestListFilter.svelte:276`(`all`), `QuestBoard.svelte:4556`(`all`),
`QuestListItem.svelte:115`, `QuestNodeConveyor.svelte:333`.

## 제안 — 전환 순간에만 transition 억제

각 컴포넌트의 transition 을 지우면 hover 피드백이 사라진다. 그러면 안 된다.
대신 **테마를 바꾸는 그 순간에만** 전역으로 transition 을 끈다.

1. 테마 적용 직전 `<html>` 에 `.theme-switching` 클래스를 붙인다.
2. 전역 CSS: `.theme-switching *, .theme-switching *::before,
   .theme-switching *::after { transition: none !important; }`
3. 다음 프레임(또는 짧은 타이머) 뒤 클래스를 제거한다.

이러면 테마는 한 프레임에 통째로 바뀌고, 이후 hover transition 은 그대로
살아 있다.

### 주의

- 클래스 제거를 `requestAnimationFrame` 에 걸면 **숨겨진 문서에서는 rAF 가
  발화하지 않아** 클래스가 영구히 남는다(BUG-238 에서 확인한 함정).
  타이머를 쓰거나 rAF + 타이머 fallback 을 함께 둘 것.
- 커스텀 테마(`customThemes.ts`)도 `setTheme` 을 거치므로 같은 경로를 탄다.

## 테스트 방법

1. 설정에서 다크 ↔ 라이트를 여러 번 전환하며 **모든 영역이 한 번에** 바뀌는지 본다
   (특히 홈의 캠페인 카드·작업기록 히트맵·퀘스트 목록 행·체크박스).
2. 전환 후 버튼/행에 마우스를 올려 **hover 전환 애니메이션이 여전히 살아 있는지**
   확인한다(억제가 전환 순간에만 걸려야 한다).
3. 퀘스트 보드에서도 확인 — `transition: all` 을 쓰는 곳이라 영향이 크다.

## 수정 내용 (2026-08-20)

처음엔 전환 순간 transition 을 **끄는**(즉시 전환) 방식으로 구현했다가,
"색이 부드럽게 바뀌게 할 수 없느냐" 는 요청으로 **균일 페이드**로 바꿨다.
시간차의 원인은 애니메이션이 있다는 것이 아니라 **속도가 제각각**이라는 것이므로,
없애는 대신 **하나로 통일**해도 문제는 똑같이 해결된다 — 그리고 더 보기 좋다.

- `stores/theme.ts` `applyThemeToDocument()` — 모든 테마 변경(설정 토글 / OS
  따라가기 / 커스텀 테마)이 이 함수 하나를 지나므로 여기만 고치면 된다.
  1. `<html>` 에 `.theme-switching` 을 **먼저** 붙이고
  2. 그 다음 `data-theme` 을 바꾸고 (순서 중요 — 값이 바뀔 때 이미 페이드가
     걸려 있어야 한다)
  3. `THEME_FADE_WINDOW_MS`(260ms) 뒤 클래스 제거
- `styles/global.css` — `.theme-switching` 하위 전체에 색 계열 속성만
  `var(--theme-fade)`(200ms) `ease` 로 **`!important` 통일**.

설계상 신경 쓴 점:

- **색 계열 속성만 전환한다.** `all` 로 두면 width/transform 까지 애니메이션되어
  레이아웃이 출렁인다. 대상은 background-color / border-color / color / fill /
  stroke / box-shadow / outline-color.
- **`animation` 은 건드리지 않는다** — 컨베이어 marquee 등이 멈추면 안 된다.
- **해제 타이머(260ms) > 페이드(200ms).** 페이드 도중 클래스가 빠지면 각 요소가
  원래의 제각각인 transition 으로 되돌아가 색이 튄다. 여유분 60ms.
- **`prefers-reduced-motion: reduce` 존중** — 그 경우엔 페이드 없이 즉시.
  즉시이되 **균일하게** 즉시라 시간차 문제는 그대로 해결된다.
- 연속 전환 시 앞선 해제 예약을 `clearTimeout` 으로 취소한다. 안 그러면 두 번째
  전환의 페이드가 첫 전환 타이머에 의해 중간에 끊긴다.

### 해제를 타이머로 한 이유

`requestAnimationFrame` 은 숨겨진 문서(`visibilityState: hidden`, 예: 배경
자식 창)에서 **발화하지 않는다.** rAF 로 풀면 그런 창에서 클래스가 영구히 남아
색 계열 transition 이 계속 덮어씌워진 상태가 된다. [[BUG-238]] 에서 같은
함정을 확인했다.

## 검증

`svelte-check` 0 errors. `theme.test.ts` **12 passed**(신규 2건): 전환 중 클래스가
붙고 `data-theme` 은 즉시 반영되며 이후 해제되는지 / 연속 전환에서 조기 해제되지
않는지(fake timers).

브라우저 실측 (설정 > 표시):

| | 평소 | 전환 중 |
|---|---|---|
| 지속시간 종류 | **5종** (`0.1s` / `0.1s,0.1s` / `0.15s,0.15s` / `0.15s,0.15s,0.2s` / `0.15s,0.15s,0.4s`) | **1종** (`0.2s` ×7) |
| 대상 속성 | 컴포넌트마다 다름(`all` 포함) | 색 계열 7개로 한정 |

대표 사례 — 헤더(`HEADER.svelte-1h32yp1`)는 평소 `transition-duration: 0s` 라
**혼자 즉시 튀던** 요소인데, 전환 중에는 `0.2s ease` 를 받아 나머지와 함께
움직인다. 전환 대상 요소는 이 화면에만 28개.

MutationObserver 로 순서도 확인: `class` 추가 → `data-theme` 변경 → `class` 제거.

### 확인하지 못한 것

**실제로 부드럽게 보이는지는 사람이 봐야 한다.** Claude 브라우저 패널이 hidden
이라 `visibilityState: hidden` 이고, 이 상태에서는 transition 이 진행되지 않으며
`setTimeout` 도 초 단위로 스로틀링돼 중간 프레임을 샘플링할 수 없다.
CSS 계산값과 클래스 수명(단위 테스트)까지가 이 환경에서 확인 가능한 범위다.

## 검증

전환 중 억제 클래스가 붙고 `data-theme` 은 즉시 반영되며 이후 해제되는지,

- 억제 중/후 계산값: 어떤 링크 요소가 `0.15s, 0.15s` → **`0s`** → `0.15s,

- 설정 화면 한 곳에만 transition 요소가 **28개**, 지속시간이 **5종**
  (`0.1s` / `0.1s,0.1s` / `0.15s,0.15s` / `0.15s,0.15s,0.2s` /
  `0.15s,0.15s,0.4s`)로 제각각이었다 — 이 편차가 시간차의 정체였다.
  억제 중에는 애니메이션되는 요소가 **0개**.

### 환경 주의

hidden 문서에서는 브라우저가 타이머를 스로틀링해 60ms 예약이 실측 891ms 에
풀렸다. 보이는 창에서는 60ms 다. 억제가 길어져도 hidden 창에서는 hover 가
일어나지 않으므로 무해하다.

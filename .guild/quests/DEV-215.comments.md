**변경 위치**: core 전용 — repo/(파일 IO), ops/(mutation), store(캐시), reindex, snapshot, migrations.

1. **파일 포맷** `.guild/library/{BOOK-NNN}.md`:
   `+++` TOML frontmatter — `book_id`("BOOK-001") / `title` / `created_at` / `updated_at` / `deleted`(soft delete, quest 와 동일) + markdown 본문. `repo/quest.rs` 의 파서/라이터 패턴 재사용(신규 `repo/book.rs`).
2. **카운터** `.guild/library/.counter.toml` — `[counter] last_number = N`. `counter.rs` 의 단조 증가 로직 재사용(번호 재사용 금지, check counters 진단에 포함).
3. **캐시**: migration `00XX_library.sql` — `library_docs(id, book_id UNIQUE, title, description, created_at, updated_at, deleted_at)`. (⚠️ BUG-102 교훈: migration 에 시드 데이터 넣지 말 것 — 빈 테이블만.)
4. **journal op**: `create_book` / `update_book` / `delete_book` / `restore_book` — replay dispatcher(replay.rs)에도 등록(DEV-022 의 id→slug 재매핑 패턴 동일 적용).
5. **reindex**: `.guild/library/*.md` 스캔 → library_docs 재구축. incremental sync(DEV-121) 대상에도 추가(file_mtime rel_key).
6. **snapshot**: `SOURCE_SUBDIRS` 에 "library" 추가 — 백업/복원 자동 포함.
7. **ops::library**: create(카운터 발번)/update/soft delete/restore/list/get — quest ops 시그니처 관례.
8. 테스트: ops CRUD + 카운터 단조 + reindex 왕복 + replay 재적용.

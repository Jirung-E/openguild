보드에서 노드를 다른 레인으로 끌어 놓으면, 격자에 맞춰지는 게 한참 뒤에야 일어난다(admin 보고, 2026-10-08).

## 원인
드롭 처리(`processPendingDrags`) 순서가 **확인 창 → 확인 → 상태 변경 API 를 노드마다 차례로 await → 그 다음에 격자 스냅**이었다.
놓은 자리에 그대로 떠 있다가 확인 창을 닫고, 서버 응답까지 다 받은 뒤에야 맞춰진다. 여러 개를 옮기면 응답을 하나씩 기다려 더 늦다.
(백엔드 상태 변경 자체는 CLI 기준 0.02초 — 느린 건 순서다.)

## 고칠 것
- 놓는 즉시 격자에 맞춘다(확인 창보다 먼저).
- 확인 후 상태 변경은 한꺼번에(병렬) 보낸다.
- 취소하거나 실패하면 원래 자리로 돌아간다(지금과 같음).

## 한 일
- `processPendingDrags`: 놓는 즉시 그 레인 안 최종 자리(스냅 + 레인 폭 안으로, `dropTarget`)로 옮긴 뒤 확인 창을 띄운다.
- 확인된 상태 변경은 `Promise.all` 로 한꺼번에 보낸다.
- 취소 · 실패면 원래 자리로 되돌린다(예전과 같음). `applyStatusChange` 가 absX/absY 로 자리를 다시 잡으므로 새 값을 먼저 넣는다.
- QuestBoard 는 컴포넌트 시험이 없어(마운트 비용) 자동 시험은 추가하지 않았다 — 아래 수동 확인.

## 테스트 방법
1. 보드에서 툴바 '스냅'을 켠다.
2. 노드 하나를 다른 레인으로 끌어 격자 칸 사이 애매한 곳에 놓는다 → **확인 창이 뜨기 전에** 이미 격자에 맞춰져 있으면 정상.
3. 확인을 누르면 그 자리에 그대로 남는다. 취소를 누르면 원래 레인 원래 자리로 돌아간다.
4. 여러 개를 골라(박스 선택) 한꺼번에 옮겨도 확인 직후 바로 끝난다.
5. 같은 레인 안에서 옮기기, Ctrl+Z / Ctrl+Shift+Z 도 예전처럼 된다.

보드에서 노드를 다른 레인으로 끌어 놓으면, 격자에 맞춰지고 상태가 바뀌는 게 한참 뒤에야 일어난다(admin 보고, 2026-10-08 — **윈도우 · 릴리스 GUI 앱**, 빈도는 모름. 확인을 누른 뒤에도 조금 있다가 바뀜).

## 원인
1. 드롭 처리(`processPendingDrags`) 순서가 **확인 창 → 확인 → 상태 변경 API 를 노드마다 차례로 await → 그 다음에야 스냅 · 화면 갱신**이었다. 화면이 저장 응답에 묶여 있었다.
2. 그 저장이 윈도우에서 가끔 늦는다 — 가장 유력한 건 자동 백업이 길드를 잡고 있는 동안 기다리는 것([[BUG-344]]: 고친 뒤 최대 약 0.2초, 그 전 빌드는 약 6초. 50번 변경마다 · 하루 한 번이라 "빈도를 모르겠다" 와 맞는다). 윈도우에서 직접 재지는 못했다.
- 맥에서 잰 것(실제 길드 복사본 811개 노드, 서버 + 헤드리스 WebKit): 저장 0.004~0.01초, 고치기 전 화면도 확인 후 0.03초 만에 제자리 — 맥에선 재현 안 됨.

## 한 일
- 놓는 즉시 그 레인 안 최종 자리(스냅 + 레인 폭 안으로, `dropTarget`)로 옮긴 뒤 확인 창을 띄운다.
- 확인하면 **화면(상태 · 자리)부터 바꾸고** 저장은 뒤에서 `Promise.all` 로 한꺼번에 보낸다.
- 저장이 실패하면 옛 상태 · 자리로 되돌리고 알림을 띄운다. 취소면 원래 자리로(예전과 같음).
- 확인(헤드리스 WebKit, 저장 응답을 일부러 2초 늦추거나 실패시킴): 2초 늦춰도 확인 0.1초 뒤 이미 새 자리, 실패시키면 원래 자리 + "시험용 실패" 알림.

## 테스트 방법 (윈도우 앱, 새로 빌드한 것)
1. 보드에서 노드를 다른 레인으로 끌어 놓는다 → 스냅이 켜져 있으면 확인 창이 뜨기 전에 이미 격자에 맞춰져 있다.
2. 확인을 누르면 **바로** 끝난다 — 여러 번 반복해도 늦게 바뀌는 순간이 없으면 정상.
3. 취소를 누르면 원래 레인 원래 자리로 돌아간다.
4. 여러 개를 골라 한꺼번에 옮겨도 확인 직후 바로 끝난다. Ctrl+Z / Ctrl+Shift+Z 도 예전처럼.

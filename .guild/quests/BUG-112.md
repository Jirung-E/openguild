증상: 길드 A 의 보드/리스트에서 필터를 걸어둔 채 그 길드를 나가서
길드 B 로 들어가면, 길드 B 의 quest 에 길드 A 의 필터가 그대로
적용되어 보임(엉뚱한 결과 또는 텅 빈 목록).

## 원인
`questFilters`(gui/frontend/src/lib/stores/quest-filter.ts) 가 모듈
전역 writable store — 길드를 오가도 in-memory 값이 리셋되지 않음.
localStorage 는 `gk()`(guildKeyPrefix)로 이미 길드별로 스코프돼 있는데,
QuestBoard/QuestList 둘 다 onMount 에서 "store 에 이미 뭔가 있으면
(다른 길드 값이라도) 손대지 않는다"는 조건부 가드를 써서, 다른 길드의
필터가 store 에 남아있으면 이 길드의 localStorage 값(또는 필터 없음
상태)으로 덮어쓰지 않았음.

- QuestBoard.svelte: `if (!isFilterActive(get(questFilters))) { ...
  hydrate ... }` — DEV-135 가 "새로고침 시 store 가 비어있으면
  hydrate"용으로 만든 가드인데, 길드 전환 시나리오(store 가 비어있지
  않고 다른 길드 값으로 차있음)를 놓침.
- QuestList.svelte: `const savedFilter = loadFilterFromStorage(); if
  (savedFilter) applyFilter(savedFilter);` — 이 길드에 저장된 필터가
  없으면(null) 그냥 아무것도 안 하고 넘어가, 방금 위에서 복원한 다른
  길드 값(`applyFilter(get(questFilters))`)이 그대로 남음.

## 수정
두 곳 다 "이 길드의 localStorage 값 (없으면 EMPTY_FILTER)"로 **무조건**
덮어쓰도록 변경 — 조건부 가드 제거.

## 테스트 방법
1. 길드 A 보드에서 필터(타입/상태/태그 등) 하나 걸기.
2. 길드 A 나가서 길드 B 로 진입(같은 세션 안에서, 앱 재시작 없이).
3. 길드 B 의 보드/리스트에 필터가 안 걸려있는지(또는 길드 B 자체에
   저장해둔 필터가 있으면 그게) 확인 — 길드 A 필터가 새지 않아야.
4. 길드 B 에도 필터를 걸고 A ↔ B 왕복하며 각자의 필터가 독립적으로
   유지되는지 확인.
5. `cd gui/frontend && npm run check && npm test -- --run` 통과.

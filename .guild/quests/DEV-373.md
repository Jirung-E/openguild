## 목표

길드의 동작에 사용자가 **자기 동작을 붙일 수 있게** 한다. 예: 새 퀘스트나
댓글이 생기면 그 내용을 AI 에 보낸다.

0.6.0 의 핵심 기능. admin 과의 설계 논의 결과를 여기 정리하고, 실제 작업은
서브퀘스트로 나눈다.

## 세 층으로 나눈다

```
① 배선 (JSON)      언제 / 어디서 / 무엇으로 내보낼지
                   on(이벤트) · scope(cli|gui|server) · action(post|run)

② 판단·가공 (rhai)  보낼 것인가, 어떤 모양으로 보낼 것인가
                   **I/O 없음** — 순수 함수. 입력 event, 출력 payload 또는 skip

③ 실제 동작 (외부)  사용자 프로그램 / 서비스. 무엇이든.
```

**코어가 소유하는 동작은 두 개뿐**이다 — `post`(HTTP)와 `run`(프로세스).
"밖으로 내보낸다"의 최소 완전집합이고, 나머지는 전부 사용자 몫이다. 통합
카탈로그(slack/discord/email…)를 코어에 쌓기 시작하면 끝없이 따라다녀야 한다.

## 정한 것 (admin)

| 질문 | 결정 |
|------|------|
| CLI 에서도 도나 | **돈다.** 단 `scope` 로 사용자가 고른다(gui 전용 등) |
| 실행 시점 | **인라인 + 비동기**(fire-and-forget). CLI 를 훅 속도에 묶지 않는다 |
| 스크립트 | **rhai** — 1단계에 포함. 동작을 결정하는 핵심이라 미루지 않는다 |
| `run` | 2단계로 미뤄도 됨. 되는지 확인해 한계를 정하는 게 목적 |
| 이벤트 이름 | **공개 이름 ↔ 내부 이름 매핑** + `리소스.동사` + 와일드카드 |
| 페이로드 | 내부 구조체를 그대로 흘리지 않고 **공개 모양으로 감싼다** |

## 왜 rhai 인가 (JS 를 접은 이유)

처음엔 JS 를 생각했지만 이 저장소에 JS 런타임이 없다. CLI 에서도 돌려면
런타임을 3개 바이너리에 새로 넣어야 하고, **AI 를 부르려면 스크립트에
네트워크를 줘야 하니 샌드박스가 무의미해진다** — 셸과 위험이 같아지면서
엔진 값만 치른다.

rhai 는 순수 Rust 인터프리터라 core 에 넣어도 이질적이지 않고, 무엇보다
**I/O 를 안 줘도 된다.** 네트워크는 코어의 `post`/`run` 이 태우고 rhai 는 그
앞에서 판단·가공만 한다. 그러면 샌드박스가 실제로 의미를 갖는다.

## 이벤트 이름 — 내부명을 그대로 쓰면 안 된다

지금 journal 의 `op` 는 내부 함수명 51종이고, 공개 계약으로 쓰기엔 문제가 많다:

```
add_attachment      vs  campaign_checklist_add    ← 동사 위치가 반대
add_comment_entry   vs  add_campaign_comment      ← 한쪽만 "entry"
save_attachment     vs  add_attachment            ← 다른 일인데 구분 안 됨
set_comments / set_rules                          ← 파일 일괄 쓰기(내부 사정)
toggle_comment_resolved                           ← 해결/해제를 못 가름
```

특히 `toggle_*` 6종. "댓글이 해결됨"을 구독하고 싶은데 **해제까지 잡힌다.**

그대로 노출하면 **함수 이름을 다시는 못 바꾼다** — 리팩터링이 곧 플러그인
파괴다. 공개 이름을 따로 두면 내부는 자유롭고, `toggle_*` 도 args 를 보고
`comment.resolved` / `comment.unresolved` 로 갈라서 낼 수 있다.

## journal 을 그대로 이벤트 버스로 쓰지 않는 이유

값싸 보이지만 세 가지가 걸린다:

1. **시점** — journal 은 `// 1. journal append (의도 기록)` 이다. 하기 **전에**
   쓴다. 뒤에서 실패해도 남는다. 구독하면 **시도했다 실패한 것까지** 나간다.
2. **결과가 없다** — `journal::append` 54곳 중 **53곳이 `result` 를 `None`**
   으로 넘긴다. 입력만 있다. `create_quest` 의 args 에는 새로 부여된
   `DEV-007` 이 없다(그건 결과다). 플러그인이 원하는 건 대개 결과다.
3. **목적이 다르다** — journal 은 AOF(복구 replay)다. 스냅샷 때 truncate 되고
   replay 중 억제 로직이 붙는다. 겸용하면 **복원 중에 과거 이벤트가 쏟아진다.**

그래서 성공 시점에 얇은 emit 을 두는 쪽으로 간다. 다만 51종 전부에 명시적
`emit` 을 다는 **완전한 형태(E안)는 0.6.0 범위가 아니다** — 공개 이름을
내부와 분리해 두면 나중에 조용히 갈아탈 수 있으므로, 그 문만 열어 둔다.

## 하지 않는 것

- **pre 훅(거부 가능)** — post(관찰)만. 훅이 죽으면 길드가 멈춘다. 로컬 우선
  도구에서 치명적이다. 넓히긴 쉽고 좁히긴 어렵다.
- **`openguild ai hello` 같은 사용자 정의 CLI 명령** — 완전히 다른 기능.
  섞으면 범위가 터진다.
- **통합 카탈로그**(slack/discord/email 액션) — 위 "두 개면 충분" 참고.

## 서브퀘스트

1. 이벤트 계약 — 공개 이름 매핑 · 페이로드 래핑 · 누락 검사
2. 플러그인 정의와 적재 — `.guild/plugins/`, scope, 동의
3. rhai 필터·가공
4. 전달 — `post`(1단계) / `run`(2단계)

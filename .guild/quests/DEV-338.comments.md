구현 — 취소 손잡이를 `{ cancelAll, cancelOne(id) }` 로 바꿨다.

- `AbortController` 를 **항목마다** 만든다(예전엔 전체가 하나를 공유해서 하나만
  끊을 방법이 없었다). 전체 취소는 그것들을 모두 abort.
- 대기 중 항목은 시작 자체를 막고, 진행 중 항목은 abort — 브라우저는
  `xhr.abort()`, 데스크톱은 이미 `upload_id` 단위 레지스트리라 그대로 성립한다
  (조각 파일 제거도 DEV-323 경로 그대로).
- 취소 버튼은 **아직 안 끝난 항목**(대기/진행)에만 보인다. 완료·실패·취소된
  줄에는 없다.
- 취소가 하나라도 있으면 목록을 걷지 않는다 — 무엇이 빠졌는지 남아야 한다.

## 실측 (파일 4개, 업로드를 1.5초씩 지연시켜 관찰)

```
  +406ms  1:진행 | 2:대기 | 3:대기   | 4:대기
 +1011ms  1:진행 | 2:대기 | 3:취소됨 | 4:대기     ← 3번만 취소
 +1962ms  1:✓    | 2:진행 | 3:취소됨 | 4:대기
 +3509ms  1:✓    | 2:✓    | 3:취소됨 | 4:진행
 +5034ms  1:✓    | 2:✓    | 3:취소됨 | 4:✓
```

3번만 빠지고 1·2·4 는 그대로 끝났다. 취소한 항목은 첨부 목록에 추가되지 않았고,
확인용으로 올라간 3건은 테스트 길드에서 삭제했다.

테스트 2건 추가 — 끝난 항목엔 취소 버튼이 없고(진행/대기 2개만 노출),
누르면 해당 id 로 `cancelOne` 이 호출되며 `cancelAll` 은 불리지 않는다.

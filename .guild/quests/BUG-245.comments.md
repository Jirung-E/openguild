## 원인 (코드 확인)

`welcome/+page.svelte` 의 정렬·갱신 두 곳:

1. **비일관 비교자** — `(a, b) => (a.last_opened < b.last_opened ? 1 : -1)` 는 같은
   값에도 `-1` 을 돌려준다. 같은 시각 항목이 있으면 정렬 결과가 구현 정의로
   흐트러진다.
2. **형식이 다른 두 소스를 문자열로 비교** — 로컬 recents 는 Rust `now_iso()` 의
   초 단위(`...:33Z`), 원격 길드는 JS `toISOString()` 의 밀리초(`...:33.123Z`).
   `'.'`(0x2E) < `'Z'`(0x5A) 이므로 **같은 초**의 원격 항목이 로컬보다 오래된
   것으로 밀린다.
3. **갱신 시점** — 목록을 `onMount` 에서만 읽었다. 길드를 열었다 뒤로 돌아오는
   경로에서 컴포넌트가 재사용되면 옛 순서가 그대로 남는다(보고: "뒤로가기 할 때").

Rust 쪽(`core::recents::add`)은 LRU 로 정상 동작하고 `days_to_ymd` 도 표준
알고리즘이라 문제 없었다.

## 수정

- 비교 규칙을 `utils/recent-sort.ts` 로 분리 — `Date.parse` 로 **시각 비교**,
  같으면 0, 파싱 불가한 값은 맨 뒤. 단위 테스트 4건(밀리초 혼재, 동률, 깨진 값).
- `afterNavigate` 로 이 페이지에 돌아올 때마다 목록을 다시 읽는다(`refreshGuildLists`).
  mount 시 첫 호출은 기존 `onMount` 가 처리.

## 확인 못 한 것

로컬 recents 는 **Tauri 데스크톱 앱에서만** 존재한다(HTTP 모드는 빈 배열). 그래서
브라우저로는 원격 길드 쪽만 확인 가능하고, "로컬 길드가 맨 위로 오는지"는
데스크톱 앱에서 봐주셔야 한다.

## 진짜 원인 — 프론트 정렬이 아니라 **타임스탬프가 덮어써지고 있었다**

`.guild` 밖 `recents.json` 자체가 이미 "틀린 순서"로 기록되고 있었다. 그래서
프론트 비교자를 고쳐도 증상이 그대로였다(1차 수정이 헛짚음).

경로: `routes/+layout.svelte` 의 history guard(DEV-355). 뒤로/앞으로 이동으로
**다른 길드의 히스토리 항목**에 도달하면 그 길드를 다시 열어야 화면이 맞으므로
`open_guild_in_current_window` 를 부른다. 그런데 그 커맨드는 `recents::add` 로
**최근 시각을 갱신**한다. 결과적으로 뒤로가기만 해도 옛 길드가 목록 맨 위로
올라오고, 방금까지 쓰던 길드가 아래로 밀린다 — 보고된 "뒤로가기 할 때"와 정확히
일치한다.

## 수정

`open_guild_in_current_window` 에 `touch_recents: Option<bool>`(기본 true) 추가.
히스토리 복원 경로만 `touchRecents: false` 로 부른다 — 길드는 열되 최근 순서는
건드리지 않는다. 사용자가 Welcome 목록/폴더 열기로 여는 경로는 그대로 갱신.

## 남는 것

1차 수정(비교자 `Date.parse` + `afterNavigate` 재조회)은 그대로 둔다 — 초/밀리초
형식이 섞이는 문제와 목록 갱신 시점 문제는 실재하고, 이번 원인과 독립이다.

데스크톱 앱에서만 재현·검증 가능하다(HTTP 모드는 로컬 recents 가 빈 배열).
확인하려면 `cargo tauri build` 로 다시 빌드해야 하고, 그러려면 실행 중인
`target\release\openguild-gui.exe` 를 닫아야 한다(파일 잠금).

# [core] GUI 시동 sync 가 무관한 quest updated_at 일괄 변조 (BUG-103 재발)

BUG-103(git checkout 후 updated_at 일괄 오탐)은 core/src/incremental.rs 에
내용 비교 게이트를 넣어 Done 처리됐으나, **동일 증상이 재발**한다.

## 재현 (2026-07-18, 이번 세션 실사고)

git checkout 을 하지 않았는데도, 개발 중 GUI(`openguild-gui`)를 이
저장소 자체 길드(`OPENGUILD_GUILD=<repo>`)에 대고 여러 번 실행하니
관련 없는 quest 17개(BUG-137, DEV-015/205/211/228/229/241/247/248/249/
250/252/254/255/258/259, REQ-001)의 `.md` frontmatter `updated_at` 이
일괄 변조됨. `git diff` 상 **내용 변경은 0, 오직 updated_at 만** 바뀜.
변조 타임스탬프가 14:34:02 / 14:36:28 로 뭉쳐 있어 시동 sync 계열의
일괄 rewrite 로 보임.

## 근본 원인 (이번에 확인)

`core/src/incremental.rs::is_content_identical_to_db` — BUG-103 이 추가한
"콘텐츠 동일하면 write-back 안 함" 게이트가, 비교 대상 필드에
**`updated_at` 자기 자신을 포함**시키고 있었다. 이게 자기강화 루프를
만든다:

1. 어떤 이유로든(레이스, 초기 마이그레이션 등) DB 의 cached `updated_at`
   이 파일의 committed 값과 한 번 어긋나면,
2. 다음 `Store::open`(→ `incremental::sync_on_open`, CLI/GUI/서버 전부
   호출)마다 `is_content_identical_to_db` 가 "updated_at 이 다르다"는
   이유만으로 "콘텐츠가 다르다"고 오판,
3. 진짜 콘텐츠(title/description/status/...)는 전혀 안 변했는데도
   `writeback_external_edit_ts` 가 파일 mtime 을 새 `updated_at` 으로
   frontmatter 에 다시 써버림 — 이러면 파일이 git 커밋된 값과 달라져
   `git status` 에 "M" 으로 잡히고, DB 의 cached `updated_at` 도 그
   새 값으로 갱신됨,
4. 다음 `git checkout`(어떤 브랜치로든)이 파일을 다시 커밋된 원래 값으로
   되돌리면, DB 의 cached 값(3번에서 새로 오염된 값)과 또 어긋나고
   mtime 도 checkout 때문에 다시 전진 → 1번으로 복귀.

즉 한 번이라도 오탐성 write-back 이 발생하면, 그 뒤로는 브랜치를 바꿀
때마다(또는 CLI/GUI 를 실행할 때마다) 영원히 재발한다 — 이번 세션 내내
관찰된 "무관한 quest .md 파일이 계속 M 으로 잡히는" 현상과 정확히 일치.

## 수정

`is_content_identical_to_db` 비교에서 `updated_at` 필드를 제외. 이
필드는 write-back 이 매번 다시 쓰는 대상(파생 값)이지, 사용자가 편집한
"콘텐츠"가 아니다. 진짜 콘텐츠(title/description/status/urgency/parent/
prereq/dates/deleted/tags)만 비교해 "동일"로 판단하도록 수정.
`refresh_quest_if_stale`(상세 페이지 lazy refresh) 도 같은 함수를
재사용하므로 함께 수정됨.

## 테스트 방법

1. `cargo test -p openguild-core incremental` — 기존 BUG-103 회귀 테스트
   전부 통과 + 신규 회귀 테스트
   `bug145_stale_cached_updated_at_does_not_perpetually_rewrite`(DB 의
   cached updated_at 이 이미 오염된 상태를 직접 시뮬레이션) 통과.
2. `cargo test --workspace` — 전체 526건 통과, `cargo clippy --workspace
   --all-targets -- -D warnings` 클린.
3. 실기 재현/검증 — 이 repo 자체를 길드로 CLI 를 반복 실행 + 실제
   `git checkout <quest-branch> && git checkout develop` 후 CLI 실행까지
   해서, 수정 전엔 즉시 재현되던 무관한 quest 파일 무더기 변조가 수정
   후엔 전혀 발생하지 않음을 확인.

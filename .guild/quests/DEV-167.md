날짜/기간(일·주·월)별 작업 기록을 '전역(모든 활동, 유저 구분 없음)'으로 표시 — 이번 범위. 자동 활동(quest_history 주축 + quest/campaign comments + quests.created_at 의 생성 이벤트; journal 은 snapshot 시 truncate 라 제외) + 날짜별 수동 노트(.guild/worklog/{date}.md, 파일=진리원+git tracked). 유저 구분이 없어 유저모델/인증 불필요. ※ 유저별 개인 뷰 + role 기반 접근은 후속으로 분리(이번 캠페인에서 구현 안 함).

## 확정 설계 (admin 승인, 2026-07-05)

### GUI — 첨부 목업 2개 참조
- **HOME 요약 카드** (worklog-home-card-mockup.html): GitHub 잔디 스타일
  히트맵(최근 12주, 하루 활동량 = 상태변경+댓글+생성 합산, 농도 5단계) +
  오늘 집계 한 줄 + 마지막 활동. 카드 클릭 → /worklog 상세, 히트맵 날짜
  칸 클릭 → 그 날짜 선택된 채 상세(?date=). worklog 는 자동 생성이라
  자주 찾는 페이지가 아님(admin) — **Nav 미노출, HOME 카드가 유일한 진입점**.
- **상세 페이지 /worklog** (worklog-detail-mockup.html): 일/주/월 토글 +
  ◀날짜▶/오늘 네비 + 노트(인라인 편집, CodeMirror + cross-link 재사용) +
  활동 타임라인(시각·종류 배지·quest ID 클릭 시 상세 이동, 기본 접힘 +
  더 보기) + 하단 종류별 집계. 주/월 뷰는 타임라인을 날짜 구분선으로
  그룹핑, 노트는 일별 나열(주/월 전용 노트 없음).

### 수동 기록 명칭 — "노트(note)"
quest memo(개인, gitignored)와 성격이 달라(전역 공유, git tracked)
혼동 방지 위해 note 로 명명 (admin 결정).

### Server (Tauri invoke 와 1:1 — DEV-193 교훈)
- `GET /api/worklog?from&to` — 기간 활동 타임라인 + 종류별 집계 (일/주/월 공용).
- `GET /api/worklog/summary?from&to` — 일별 count 만 (히트맵용 경량).
- `GET /api/worklog/note/{date}` / `PUT /api/worklog/note/{date}` —
  노트 조회/저장 (빈 본문 PUT = 파일 삭제).
- 활동 데이터는 index.db 기존 테이블 조회뿐 — 새 저장소는 노트 파일만.
  reindex/snapshot SOURCE_SUBDIRS 에 worklog 디렉토리 추가 필요.

### CLI (cli-command-naming 규칙: 단수형 + sub 필수)
```
openguild worklog show [--date D | --from D --to D]   # 타임라인+집계 (기본 오늘)
openguild worklog note show <DATE>
openguild worklog note set  <DATE> [--file <PATH>]     # 한글은 --file 관례
openguild worklog note clear <DATE>
```
`--json` 은 서버 응답과 동일 구조. 원격 모드는 HTTP 라우트 그대로 자동 지원.

## 구현 (2026-07-05, 확정 설계대로)
- **core** `ops/worklog.rs`: activities(from,to) — quest_history(상태/타입) +
  quest/campaign 댓글 + quests.created_at UNION, 날짜는 ts 앞 10자 비교.
  counts(상태변경/댓글/생성/done 전환) 동봉. daily_summary(히트맵용 경량).
  노트 get/set(빈 본문=파일 삭제)/list — rules 식 "파일 진리원, 캐시 없음".
  validate_date 로 traversal 방지. snapshot SOURCE_SUBDIRS + seed 에
  worklog 추가, set_worklog_note 는 replay fail-loud(len 만 기록).
- **server** `routes/worklog.rs`: GET /api/worklog, /summary, /notes,
  GET/PUT /note/{date}.
- **CLI**: `worklog show [--date|--from/--to]`(타임라인+노트+집계, --json),
  `worklog note show/set/clear`. 원격 모드 지원 (HttpClient 에 put 헬퍼 추가).
- **GUI**: Tauri commands 5개 + transport 매핑(+vitest), api/worklog.ts,
  `/worklog` 상세 페이지(일/주/월 토글, ◀▶/오늘, 노트 인라인 편집
  — CodeMirror+cross-link, 주/월은 일별 노트 나열 + 날짜 구분선 타임라인,
  하단 집계, ?date= 딥링크 URL 진리원), HOME 의 WorklogSummaryCard
  (12주 히트맵 — success 토큰 농도 4단계, 오늘 집계, 카드/날짜 칸 클릭 →
  상세). Nav 미노출 (admin 결정 — HOME 카드가 유일한 진입점).

## 테스트 방법
- 자동: `cargo test -p openguild-core --lib worklog` (활동 수집/집계/노트
  CRUD/날짜 검증), `cargo test -p openguild-server test_worklog`,
  `cargo test -p openguild-cli cli_worklog` (파싱),
  `cd gui/frontend && npm run check && npm test -- --run` (transport 매핑).
- 실기 (재빌드 후):
  1. HOME 하단에 작업 기록 카드(히트맵 + 오늘 집계) 표시 확인.
  2. 카드 클릭 → /worklog (오늘). 히트맵 특정 날짜 칸 클릭 → 그 날짜 선택.
  3. 일/주/월 토글 + ◀▶/오늘 이동, 주/월에서 날짜 구분선 그룹핑.
  4. 노트 작성/편집/저장 → `.guild/worklog/{날짜}.md` 생성, 빈 본문 저장 시
     파일 삭제. 주/월 뷰에서 일별 노트 나열 + 날짜 클릭 시 일 뷰 이동.
  5. 타임라인 항목 클릭 → quest/campaign 상세 이동.
  6. CLI: `openguild worklog show` / `note set <날짜> --file <utf8.md>` /
     `note show` 한글 무결. `--remote` 로도 동일.

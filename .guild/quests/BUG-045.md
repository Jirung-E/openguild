## 증상

사용자: "설정창에서 업데이트 확인 버튼을 눌렀는데 업데이트를 확인할 수 없는
이유는 뭐임?"

## 원인 (1순위)

`gui/tauri.conf.json` 의 updater endpoint:

```json
"updater": {
  "endpoints": [
    "https://github.com/Jirung-E/openguild/releases/latest/download/latest.json"
  ]
}
```

**첫 release 가 아직 안 만들어짐** → 그 URL 이 404 → Tauri updater plugin 의
`check()` 가 fetch 실패로 throw → frontend `updateState` 가 `error` 로 떨어지지만
사용자에게 보이는 메시지는 "업데이트를 확인할 수 없습니다" 정도로 모호.

확인: 본 quest 의 prerequisite **DEV-036** (릴리즈 패키지 절차) 가 처리되어 첫
release + `latest.json` 이 attach 되면 자연 해결.

## 원인 (2순위 — dev 빌드)

사용자가 `cargo run` / `cargo tauri dev` 로 실행 중이라면 updater plugin 이
production 빌드 검증 차이로 안 될 수 있음. `cargo tauri build --release` 후의
binary 만 정식 동작.

## 작업

### A. (즉시 가능) — 명확한 에러 표시

`gui/frontend/src/lib/api/updater.ts` 의 `catch` 에서 더 명확한 메시지:

- HTTP 404 → "릴리즈가 아직 없습니다 / endpoint 가 잘못되었습니다"
- 네트워크 에러 → "네트워크 연결 확인"
- signature 실패 → "release 의 signature 검증 실패"
- dev 빌드 → "dev 빌드에선 자동 업데이트 미지원"

`UpdateBanner.svelte` / 설정 페이지에서 에러 메시지 그대로 노출.

### B. (DEV-036 의존) — 첫 release 만들기

DEV-036 의 `.guild/rules/release-process.md` 절차대로 첫 release 진행. 그 안에:

- installer (DEV-034 의 workflow) 가 자동 attach.
- **`latest.json` 도 반드시 attach** — updater plugin 의 endpoint.

### C. (선택) — dev 빌드 시 명시적 안내

`detectEnvironment()` 외에 "dev 빌드인지" 도 감지 (예: `__TAURI_INTERNALS__`
의 build mode). dev 면 "업데이트 확인" 버튼을 disable + 안내.

## 권장 순서

1. **DEV-036 진행 → 첫 release** (가장 본질적 해결).
2. **A** (release 가 있어도 다른 이유로 실패 시 사용자에게 명확).
3. **C** (개발자 / 테스터에게 친절).

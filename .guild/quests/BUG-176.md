길드를 바꾼 뒤 **뒤로가기로 이전 길드로 돌아갈 수 없다.**

## 재현

1. A 길드에 들어간다.
2. (뒤로가기가 아니라) 웰컴 페이지를 **경유**해서 B 길드로 간다.
3. 뒤로가기를 누른다 → 기대: A(또는 최소한 웰컴). 실제: **B 로 돌아온다.**
   히스토리가 `B → Welcome → B` 처럼 되어 이전 길드로 갈 수 없다.

## 추정 원인 (조사 필요)

웰컴 페이지가 "이미 열린 길드가 있으면 그 길드로 이동" 하는 리다이렉트를
갖고 있다면, 뒤로가기로 웰컴에 도달하는 순간 즉시 현재 길드(B)로 다시 튕겨
나간다 — 사용자가 보는 `B → Welcome → B` 와 정확히 일치한다.

## 확인할 것

- 웰컴 진입 시 자동 리다이렉트 여부와 그 조건.
- 길드 전환이 SPA 라우팅인지, Store 를 갈아끼우는 것인지(뒤로가기로 이전
  길드에 가더라도 백엔드 Store 는 B 를 보고 있으면 데이터가 어긋난다).
- 애초에 "뒤로가기로 다른 길드로 이동" 이 성립하는 모델인지 —
  성립하지 않는다면 뒤로가기가 웰컴에서 멈추도록(리다이렉트 억제) 하는 것이
  올바른 동작일 수 있다.

## 수정 (B 안, 2026-07-29 — 사용자 선택)

"뒤로가기가 길드를 되돌린다"(A 안)가 아니라 **잘못된 화면을 보여주지 않는
것**까지만 한다. 다른 길드의 히스토리 항목에 도달하면 웰컴으로 보내 거기서
명시적으로 고르게 한다.

### 구현

- `stores/guildIdentity.ts` 신설 — 지금 열린 길드의 식별자.
  로컬은 `{kind:'local', path}`(Rust `current_guild_path`), 원격은
  `{kind:'remote', url}`. **원격은 `remoteServerUrl` 만 보지 않고
  `isRemoteSessionActive()` 까지 확인**한다(BUG-095/099 와 같은 기준 —
  이전 세션의 잔존값과 실제 연결을 구분해야 한다).
  경로 조회는 invoke 라 캐시하고, 길드를 열 때 `invalidateCurrentGuild()`.
- `app.d.ts` 의 `App.PageState` 에 `guild` 선언 — SvelteKit shallow routing
  state 에 실어 **히스토리 항목마다** 표식을 남긴다(URL 에는 길드 정보가 없다).
- `+layout.svelte` 의 `afterNavigate`:
  - 표식이 없는 항목이면 현재 길드로 `replaceState` (히스토리가 늘지 않는다).
  - 표식이 지금 길드와 다르고 **popstate 로 도달**했으면 `/welcome` 으로
    (replaceState — 뒤로가기 스택을 더 어지럽히지 않는다).
  - 브라우저 모드는 `currentGuildId()` 가 null 이라 가드 자체가 꺼진다
    (서버가 길드 하나에 바인딩돼 전환 개념이 없다).
- 웰컴의 길드 열기 4경로(최근 목록 / 직접 선택 / 초기화 / 원격 연결) 모두
  `goto('/', { state: { guild } })` 로 새 길드를 표식과 함께 남긴다.

### 왜 A 를 안 했는지 (기록)

뒤로가기 한 번이 길드 재오픈(DB 열기·마이그레이션·시동 sync)을 유발하고,
폴더 삭제/권한 실패를 **뒤로가기 도중에** 만나게 된다. 편집 중 뒤로가기 시
Store 가 바뀐 뒤 저장이 다른 길드로 가는 문제, 연타 시 직렬화, 로컬/원격 두
축의 조합까지 붙는다. 필요하면 별도 퀘스트로.

## 검증

- 단위 테스트 8건(`guildIdentity.test.ts`): 같은/다른 로컬 경로, 원격 URL,
  로컬↔원격 교차, 표식 없음, 브라우저 모드 null, **원격 잔존값 오인 방지**.
- 프론트 321건 전체 통과, `svelte-check` 0 errors / 0 warnings.
- 브라우저 모드 회귀: 정상 이동 후 뒤로가기가 그대로 동작하고 웰컴으로
  튕기지 않음을 실기 확인(가드 비활성이 의도대로).

**미검증**: 실제 길드 전환(A → 웰컴 → B → 뒤로가기)은 Tauri 앱 빌드가 필요해
확인하지 못했다. 아래 Test plan 대로 실기 확인 필요.

## Test plan

1. A 길드 → 로고 버튼으로 웰컴 → B 길드 열기 → **뒤로가기**:
   웰컴이 보이고, 한 번 더 누르면 **B 가 아니라 웰컴에 머무는지**
   (예전엔 B 가 A 인 것처럼 보였다).
2. 웰컴에서 A 를 다시 열면 정상 동작하는지.
3. **같은 길드 안에서의 뒤로가기는 그대로**인지 — 퀘스트 상세 ↔ 목록 ↔ 보드를
   오가며 뒤로/앞으로가 막히지 않는지(과잉 차단 회귀 확인).
4. 원격 길드: 원격 연결 → 로컬 길드 열기 → 뒤로가기에서도 동일한지.
5. 콜드 스타트(앱을 길드 인자로 바로 실행) 후 뒤로가기가 이상 동작하지 않는지.
6. 자식 창(단일 문서 보기)에서 회귀가 없는지.

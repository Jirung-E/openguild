## 전수조사 — 목록성 명령 현황

| 엔티티 | 목록 명령 | 비고 |
|---|---|---|
| quest | `quest list` (+search/deleted) | 기준 관례 |
| campaign | `campaign list` | 일치 |
| backup | `backup list` | 일치 |
| rules | `rules list` | 일치 |
| template | `template list` | 일치 |
| comment | `quest comment list` | 일치 |
| types | `types` (bare) = **`types list` 이미 존재** (기본 동작) | 사실상 일치 |
| statuses | `statuses` (bare) = **`statuses list` 이미 존재** | 사실상 일치 |
| journal | `journal tail` | 성격이 달라(최근 N개) tail 유지가 맞음 |

**결론 1**: 우려했던 네이밍 비일관은 이미 해소돼 있음 — `types list`/`statuses list` 가 서브커맨드로 존재하고 bare 호출이 그 기본동작. top-level 이 복수형 명사(types/statuses)인 것만 다른데, 바꾸면 하위호환 파손 대비 이득이 작아 **현행 유지 권장**.

**결론 2 (실제 작업)**: **slug 미표시** — `statuses list` 사람용 출력이 name_en/name_ko 만 표시. 명령 인자(quest move 등)는 slug 를 받으므로 표시 필요.

**부수 발견**: `rules create` 가 생성 관례(`new`, DEV-176)와 어긋남 — `rules new` alias 추가 검토(기존 create 유지).

## 구현 계획
1. `statuses list`: slug 컬럼 추가 — `Open  (open)  게시됨` 형태 (에러 메시지의 "available: Open (open), ..." 표기와 통일). types 는 prefix 자체가 식별자라 현행 유지.
2. (선택) `rules new` = create alias.
3. AGENTS_OPENGUILD_USAGE §2.1 갱신.

예상 규모: 소형(cli 출력부 ~20줄).

## 구현

생성 자체에 `discussion` 을 실어 **쓰기 1회 / HTTP 1회**로 끝내도록 바꿨다.

- `services::comments::add_entry` — `discussion: bool` 파라미터 추가.
  하드코딩 `discussion: false` 를 제거했다. 여기가 근본 원인이었다 — 생성
  시점에 지정할 방법이 없어서 상위가 토글로 우회할 수밖에 없었다.
- `ops::comments::add_comment_entry` — 같은 파라미터, journal 에도 기록.
- 서버 `AddCommentRequest.discussion` (`#[serde(default)]`) — 필드를 안 보내는
  **구버전 CLI 는 동작이 예전과 동일**하다.
- CLI `comments_add_scoped` 가 이 값을 싣는다. `CommentCmd::Add` 는 이제
  토글을 부르지 않는다.

## 구버전 서버 호환

새 CLI ↔ 구버전 서버 조합이 더 위험했다. 서버가 `discussion` 을 모르면
조용히 무시하고 평댓글을 만드는데, CLI 는 "· 토론" 이라고 출력한다 —
**거짓 성공**이다.

그래서 응답 entry 의 `discussion` 을 확인하고, 요청했는데 false 로 돌아온
경우에만 토글로 보정한다. 신버전 서버끼리는 왕복 1회, 구버전 상대로는
예전의 2단계로 자동 강등된다.

## campaign 방어

서버 `camp_add_comment` 가 `discussion` 을 받으면 400 으로 거부한다.
조용히 무시하면 호출측은 토론을 만들었다고 믿는데 평댓글이 생긴다 —
DEV-361 이 없애려던 바로 그 상태다. CLI 는 이미 클라이언트에서 막지만,
서버도 스스로 막아야 다른 클라이언트에서 같은 일이 안 생긴다.

## GUI

`gui/src/commands.rs` 는 `false` 를 넘겨 기존 흐름(생성 후 별도 토글) 유지.
로컬 IPC 라 원격 같은 부분 실패 위험이 없어 범위에 넣지 않았다.

## 검증

- core 단위 테스트 2건 추가 — 생성 즉시 토론(파일 + DB 캐시 양쪽),
  그리고 `discussion=false` 기본 경로 불변
- `cargo test --workspace` 762건 통과
- **원격 실측**: 서버를 띄워 `--discussion` 실행 → 서버 로그에 POST
  `/comments` **1건만**, `/discussion` 토글 호출 **0건**. 파일에
  `discussion="true"` 기록됨
- **구버전 서버 실측**: 요청 본문에서 `discussion` 을 제거해 전달하는 프록시를
  세워 흉내 → 폴백이 돌아 `/comments/2/discussion` 토글이 호출되고 최종
  결과는 `discussion="true"`. 폴백 분기가 실제로 동작함을 확인
- 구버전 CLI 흉내(필드 없이 POST) → `discussion` 없이 정상 생성
- campaign 에 `discussion:true` → `400 discussion is only available for quest comments`

사용자 요청: 알림 시스템 개선 — 여러 개의 알림이 동시에 오는 경우의 처리
설계. (DEV-259 '알림 UI 통일'과 연계 — 259는 구현/스타일 통일, 이 퀘스트는
동시 발생 시나리오의 동작 설계와 테스트 방법.)

## 현재 상태 — 동시 발생 시 무슨 일이 나나

알림 표면이 4곳으로 흩어져 있음(DEV-259 조사 참고):
- ToastHost(우상단): 유일하게 스택 지원 — 여러 개 세로로 쌓임. OK.
- UpdateBanner(우하단): 단일 카드. 상태가 바뀌면 내용 교체.
- SchemaAheadBanner(좌상단): 단일 카드, 자동닫힘 없음.
- admin 로컬 토스트(우상단): 단일 — 새 메시지가 이전 것을 '덮어씀'(유실).

즉 현재의 '동시 알림 전략'은 사실상 **코너 분산**: BUG-139 수정이 그 예 —
SchemaAheadBanner 가 레이아웃을 밀어내던 것을 floating 카드로 바꾸면서,
UpdateBanner(우하단)/ToastHost(우상단)와 겹치지 않도록 일부러 **좌상단**에
배치했다(겹침 회피를 위치 분리로 해결). 이 방식의 한계:
- 코너가 4개뿐 — 알림 종류가 늘면 파산.
- admin 토스트처럼 같은 코너를 쓰는 비스택 구현은 메시지 유실.
- 사용자 입장에선 알림이 사방에서 떠서 시선 분산.

## 설계 과제

1. 단일 알림 스택(큐)으로 수렴: 모든 단발 알림은 한 코너의 스택으로,
   상태 유지형(업데이트 진행/schema 경고)은 별도 '지속 알림' 영역으로.
   동시 N개 = 스택에 순서대로 + 최대 표시 개수/이상은 "+N개 더" 축약.
2. 우선순위/수명 정책: error > warning > info, 지속형은 수동 닫기.
3. 중복 억제: 같은 키의 알림 재발생 시 갱신(카운트 뱃지)인지 새 항목인지.

## 테스트 방법 (BUG-139 "테스트는 어떻게?" 질문에 대한 답 포함)

BUG-139 검증의 어려움: schema-ahead 는 '구버전 바이너리 + 신버전 DB'
조합에서만 뜨고, 업데이트 알림은 실제 릴리즈가 있어야 떠서 동시 재현이
번거로움. 그래서:
- (제안) dev 전용 트리거: 개발 모드에서만 노출되는 디버그 액션(설정 숨김
  메뉴 또는 콘솔 헬퍼)으로 각 알림 타입을 임의 발화 — 동시 발생 조합을
  수동/자동으로 재현 가능하게.
- vitest 컴포넌트 테스트: 스택 순서/최대 개수/우선순위/중복 억제 로직을
  스토어 단위로 검증(렌더 위치까지는 스냅샷).
- 수동 시나리오 표: (업데이트 있음 + reindex 성공 + schema 경고) 등 조합
  체크리스트를 퀘스트 댓글로 관리.

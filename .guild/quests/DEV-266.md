# [gui] 알림 시스템 개선 — 동시 다발 알림 처리 설계 + 테스트 방법

사용자 요청: 알림 시스템 개선 — 여러 개의 알림이 동시에 오는 경우의 처리
설계. (DEV-259 '알림 UI 통일'과 연계 — 259는 구현/스타일 통일, 이 퀘스트는
동시 발생 시나리오의 동작 설계와 테스트 방법.)

## 설계 결정 + 구현 (2026-07-19)

DEV-259 가 이미 단일 스택(우하단)으로 수렴시켰고, admin 로컬 토스트도
showToast() 로 흡수돼 유실 문제는 해소된 상태였다. 이번에 남은 정책을
구현:

1. **표시 상한 + 축약** — `MAX_VISIBLE_NOTIFS = 5`. 초과 시 우선순위 낮은
   것(오래된 info/success 토스트)부터 숨기고 스택 맨 위에 "+N개 더 보기"
   칩 표시, 클릭 시 전체 펼침(개수가 상한 아래로 내려가면 자동 복귀).
2. **우선순위 정책** — error 토스트와 지속형(update/schema)은 상한을
   넘어도 절대 숨기지 않음(error > persistent > info). 지속형은 항상
   코너쪽(맨 아래)에 정렬 고정 — 토스트 출입에 따라 오래 떠 있는 카드
   위치가 튀지 않게.
3. **중복 억제** — 같은 message+variant 토스트 재발생 시 새 카드 대신
   기존 카드의 count 를 올리고(×N 뱃지) 자동 소멸 수명을 리셋. 루프성
   에러가 같은 문구로 스택을 도배하는 것 방지.
4. **dev 전용 트리거** — schema-ahead 는 '구버전 binary+신버전 DB',
   업데이트 카드는 실제 릴리즈가 있어야만 떠서 동시 조합 재현이 어려움.
   dev 모드에서만 `window.__ogNotify`(toast/schema/update) 콘솔 헬퍼를
   노출해 임의 조합 수동 재현 가능. (update 카드는 dev 모드에 한해
   브라우저에서도 렌더 허용 — 트리거 검증용.)

핵심 로직(`computeVisible`)은 순수 함수로 스토어(toast.ts)에 둬서 렌더
없이 테스트 가능하게 함.

## 테스트 방법

1. **vitest 스토어 테스트** (`toast.test.ts`, 10건 — 통과 확인): 도착순
   적재 / 중복 억제(count 증가+수명 리셋+동일 id 반환) / variant 다르면
   별개 / durationMs=0 수동 닫기 / 상한 이하 전부 표시+persistent 후순위
   정렬 / 초과 시 오래된 non-error 부터 숨김+hidden 집계 / error·
   persistent 는 안 숨김 / expanded 전체 표시 / 전부 error 면 상한 초과
   유지 / upsert 제자리 교체.
2. `npm run test` 전체 281건 통과, `npx svelte-check`·`npm run build` 클린.
3. (사용자 확인) dev 모드 콘솔에서:
   `__ogNotify.toast('e','error',0); __ogNotify.schema(); __ogNotify.update('available');`
   `for (let i=0;i<8;i++) __ogNotify.toast('m'+i,'info',0);`
   → 5개 + "+N개 더 보기" 칩, error/지속형 유지, 칩 클릭 시 전체 펼침,
   `__ogNotify.toast('m1','info',0)` 재호출 시 ×2 뱃지 확인.

search 가 `quest_id` (slug, 예 `DEV-037`) 와 부분 number (`037`, `BUG-`) 도
매칭하도록 확장. `title_only` 와 무관 — slug 는 메타 정보지 본문이 아니므로
항상 매치.

## 구현 (2026-05-21)

### Backend
- `core::services::quests::list`:
  - `SLUG_EXPR = LOWER(qt.prefix || '-' || printf('%03d', q.number)) LIKE LOWER(?)`
  - 각 search 토큰의 OR 절에 slug 비교 추가.
  - title_only=true: 2개 bind (title + slug).
  - title_only=false: 3개 bind (title + description + slug).

### Frontend (gui)
- `quest-list.ts::filterQuests`:
  - 토큰 비교 시 `q.quest_id.toLowerCase().includes(t)` 도 OR.
  - `titleOnly=true` 여도 slug 는 항상 검사.

### 자동 테스트 +10
- server +4: 전체 slug / 부분 number / prefix / title_only 와 결합.
- frontend +6: 전체 / 부분 / prefix / 대소문자 / titleOnly / 다중 match.

## 후속 버그 수정 (2026-05-22)

테스트 중 발견: **sub-quest 가 매치되어도 화면에 안 보임**.

원인: `QuestList` 가 `filterQuests` 결과를 `buildTree(filtered, null)` 로
넘기는데, sub-quest 만 매치되고 부모가 매치 안 되면 부모가 결과에 없어서
`buildTree` 가 root 부터 트리를 만들 때 sub-quest 에 닿지 못함.

수정:
- `quest-list.ts::includeAncestors(matched, all)` — 매치 항목의 모든 조상을
  union 으로 포함. 트리 구조 유지하면서 sub-quest 노출.
- `quest-list.ts::ancestorIdsOf(matched, all)` — 조상 id 만 (자기 자신 제외).
- `QuestList.svelte`: `search.trim()` 가 있을 때만 `includeAncestors` 적용 +
  `ancestorIdsOf` 를 `expanded` 와 union 하여 자동 펼침.

자동 테스트 +6:
- includeAncestors: 잎 매치 / root 매치 / multi / 순서 유지 / orphan parent /
  ancestorIdsOf 셈 검증.
- 통합 회귀: "needle" 토큰으로 sub-quest 만 매치하는 시나리오 — buildTree
  단독으로는 비어있고 includeAncestors 후엔 정상 트리.

## 회귀

- 기존 search 동작 (title + description) 변경 없음 — slug OR 추가.
- title_only 의 동작 (description 제외) 유지 — slug 만 추가로 OR.
- 검색이 빈 상태 → includeAncestors 호출 안 함 → 기존 동작 동일.

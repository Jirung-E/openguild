현재 본문/규칙/메모(CodeMirror)는 CM 네이티브 autocomplete 팝업을, 댓글(textarea)은 DEV-171 커스텀 caret 팝업(스크롤 추종 / 화면밖 위로 flip / 현재 입력값 첫 항목 / ↑↓ Enter Esc 키보드 네비)을 쓴다. 본문도 댓글과 동일한 팝업을 쓰도록 통일. 접근: DEV-171 의 팝업(placeWiki + 후보 리스트 UI)을 공용 컴포넌트/유틸로 추출하고, CM 쪽은 네이티브 autocompletion 대신 view.coordsAtPos 로 caret 좌표를 얻어 같은 팝업을 띄워 구동(wikiMatch 로직 공유). 본문/규칙/메모 3곳 적용.

## 구현 요약

- `wiki-popup-place.ts`(신규): 댓글(QuestCommentsSection)의 배치 계산(`computeWikiPlace`/`clampWikiLeft`/`isWikiCaretVisible`)을 순수 함수로 추출 — textarea/CodeMirror 공용.
- `WikiAutocompletePopup.svelte`(신규): 댓글의 팝업 UI(마크업+CSS)를 그대로 추출한 공유 컴포넌트.
- `QuestCommentsSection.svelte`: 위 두 유틸/컴포넌트를 쓰도록 리팩터(동작 동일, 코드만 통합).
- `MarkdownEditor.svelte`(본문/규칙/메모 공용 편집기): CM 네이티브 `autocompletion()`/`tooltips()` 제거, `view.coordsAtPos()` 로 caret 좌표를 구해 같은 `WikiAutocompletePopup` 을 띄우는 커스텀 `keymap`(↑↓/Enter/Tab/Esc, `Prec.highest`)+`updateListener` 로 교체. 매칭 로직은 기존 `wikiMatch()`(textarea-wikilink.ts, 프레임워크 무관) 그대로 재사용, 삽입만 CM 전용 헬퍼(`editor-wikilink.ts`: `applyWikiLinkCM`/`applyWikiPrefixCM`)로 신규 작성.
- `worklog/+page.svelte` 는 범위 밖(퀘스트 설명이 "본문/규칙/메모 3곳"으로 한정) — 별도 CM 인스턴스라 기존 `crossLinkAutocomplete()`(editor-links.ts) 그대로 유지.

## 테스트 방법

1. 퀘스트 상세(본문) 편집 진입 → `[[` 타이핑 → 댓글과 동일한 팝업(아이콘 + ID + 제목)이 뜨는지.
2. ↑/↓ 로 후보 이동, 선택 항목이 제자리에서 펼쳐지는지(DEV-297 동작 유지).
3. Enter/Tab 으로 적용 시 `[[kind:ID]]` 로 정확히 삽입되고 팝업이 닫히는지. `[[q` 처럼 네임스페이스 접두만 골랐을 때는 `]]` 안 닫히고 그 종류로 필터된 후보로 바로 이어지는지.
4. Esc 로 닫히는지, 같은 토큰에서 재오픈 안 되는지(닫은 토큰 기억).
5. 화면 아래쪽(뷰포트 하단 근처)에서 입력 시 팝업이 위로 flip 되는지 — 화면 밖으로 안 나가는지.
6. 모바일 폭(좁은 화면)에서 팝업이 화면 밖으로 안 삐져나가는지, 좌우 clamp 정상인지.
7. 규칙(rules) / 메모(memo) 편집기에서도 동일하게 동작하는지.
8. 댓글 쪽(기존 DEV-171 동작)이 리팩터 후에도 회귀 없는지 — 위 1~6 을 댓글 입력창에서도 확인.

(Playwright 로 1~4, 8 은 자동 검증 완료 — 5~7 은 실제 화면/모바일에서 육안 확인 필요.)

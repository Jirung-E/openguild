## 할 것

[[DEV-378]] 이 CLI 를 배선한 뒤, 남은 두 컴포넌트.

### 서버 (`Scope::Server`)

`scope` 에 `server` 를 넣으면 **그 서버를 쓰는 모두**에게 적용된다 — 공유
범위는 파일 위치가 아니라 `scope` 가 정한다.

서버는 오래 사는 프로세스라 요청 때마다 물을 수 없다. 시작할 때 한 번 적재하고,
동의 대기가 있으면 로그에 남긴다. 허용은 서버를 띄우는 사람이 CLI(`openguild
plugin allow`)로 하거나 관리 API 로 한다 — 어느 쪽인지 정해야 한다.

`drain` 은 종료 신호를 받았을 때.

### GUI (`Scope::Gui`)

여기서만 **대화상자로 물을 수 있다.** 처음 보는 플러그인이 있으면 정의와
스크립트 원문을 보여 주고 허용/거부를 받는다 — 사용자가 무엇에 동의하는지
보지 못하면 동의가 아니다.

Tauri invoke 핸들러 + 프런트엔드 화면이 필요하므로 CLI/서버보다 크다.

### 사용자 문서

기능이 다 붙은 뒤에 한 번에 쓴다 — 반쯤 붙은 상태로 문서에 올리면 없는 기능을
광고하게 된다.

- `docs/USAGE.md` — 플러그인 절(정의 위치, 동의, `openguild plugin` 명령).
- `skills/openguild-plugin/skills/openguild/reference/` — 에이전트가 읽는
  레퍼런스. 새 명령 그룹이 여기 없으면 에이전트는 그 명령을 모른다
  ([[BUG-261]] 에서 겪은 것과 같은 계열).
- CHANGELOG — 0.6.0 의 핵심 기능이므로 맨 위.

## 정해야 할 것

- 서버의 허용 경로 — CLI 로만 할지, 관리 API 를 열지.
- GUI 에서 동의를 물어보는 시점 — 길드를 열 때인지, 설정 화면에서인지.
- 전달 실패를 GUI 어디에 보일지(토스트? 설정 화면의 목록?).

## 테스트 방법

- 서버: `scope: ["server"]` 플러그인이 서버 mutation 에서 돈다. `["cli"]` 는 안 돈다.
- GUI: 동의 전에는 안 돌고, 대화상자에서 허용하면 돈다.
- 어느 쪽이든 플러그인 하나가 죽어도 길드 동작은 멀쩡하다.

## 결과

세 컴포넌트가 전부 배선됐다. 0.6.0 플러그인 시스템 완성.

### 정해야 했던 것 — 내가 정한 기본값 (뒤집고 싶으면 한 줄이면 된다)

**서버의 허용 경로: CLI 전용. 관리 API 는 열지 않는다.** 서버는 팀이 공유하는
엔드포인트다. 거기로 동의를 받으면 "누구의 동의인가" 가 흐려지고, 무엇보다
**`run` 을 열어 주는 원격 구멍**이 된다. 서버를 띄우는 사람이 그 기계에서
`openguild plugin allow` 로 한다. 프런트에서도 이 경로는 아예 안 부른다
(브라우저에서 부르면 조용히 no-op 이 아니라 던진다 — 조용하면 "허용 눌렀는데
안 도네" 로 이어진다).

**GUI 의 동의 시점: 설정 화면.** 길드를 열자마자 대화상자로 막으면 플러그인을
안 쓰는 사람까지 방해한다. 대신 목록에서 동의 대기가 눈에 띄게 보이고,
허용하면 **즉시** 다시 꽂힌다 — 방금 허용해 놓고 앱을 다시 켜야 도는 것은
고장으로 보인다.

**전달 실패 표시: 설정 화면의 목록.** 토스트는 시끄럽고, 실패는 대개 설정
문제라 설정 옆에 있는 편이 낫다. CLI 는 stderr, 서버는 시작 로그.

### GUI 에서 무엇을 보여주는가

정의 JSON 만으로는 동의가 형식만 남는다. 목록에 **목적지**(`post` 의 URL 또는
`run` 의 명령)를 바로 띄우고, 스크립트가 있으면 **원문을 펼쳐 볼 수 있게**
했다. 사용자가 무엇에 동의하는지 보지 못하면 동의가 아니다.

### 배선 지점 셋 — swap 누락 패턴

GUI 는 Store 가 세 곳에서 만들어진다(시동 · `init_and_open_guild` ·
`open_guild_in_current_window`). 하나라도 빠뜨리면 **이전 길드의 플러그인이 새
길드의 이벤트를 받는다.** asset scope 에서 겪었던 것과 같은 패턴이라(BUG-223
계열) 그 옆에 나란히 뒀다.

### 서버는 graceful shutdown 이 생겼다

`drain` 을 걸 자리가 없었다 — Ctrl+C 가 프로세스를 즉시 끊어서 마지막
mutation 의 훅이 나가는 중이면 그대로 사라졌다. `with_graceful_shutdown` +
SIGTERM 처리를 넣었고, 덤으로 처리 중인 요청도 함께 마무리된다.

### 크기 실측 (0.6.0 착수 전 대비)

| | 착수 전 | 지금 | |
|---|---|---|---|
| CLI (`openguild`) | 16.37 MB | 19.70 MB | +3.33 MB (+20.3%) |
| 서버 (`openguild-server`) | 13.47 MB | **19.83 MB** | **+6.37 MB (+47.3%)** |

서버가 CLI 보다 두 배 는 이유는 **rhai 에 더해 reqwest/rustls 까지 새로
들어가기 때문**이다(실측: rhai 계열 +3.47MB, reqwest +3.06MB — 반반이다).
CLI 는 reqwest 를 이미 갖고 있었다. admin 이 "크기 무관하게 진행" 으로
확정했으므로 되돌리지 않는다.

여기 한때 "줄이고 싶으면 `plugins` 를 cargo feature 로 빼면 된다" 고 적어
뒀는데 **그건 하면 안 되는 일이다** — 어떤 액션을 쓸지는 `plugin.json` 을 쓰는
사람이 정하는 런타임 결정이라, 컴파일 시점에 가르면 그 결정권을 패키징하는
쪽으로 옮기게 된다. 자세한 이유는 [[DEV-373]] 의 "cargo feature 로 가르지
않는다" 참고.

잠금으로 바꿨다.

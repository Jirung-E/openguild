## 할 것

[[DEV-378]] 이 CLI 를 배선한 뒤, 남은 두 컴포넌트.

### 서버 (`Scope::Server`)

`scope` 에 `server` 를 넣으면 **그 서버를 쓰는 모두**에게 적용된다 — 공유
범위는 파일 위치가 아니라 `scope` 가 정한다.

서버는 오래 사는 프로세스라 요청 때마다 물을 수 없다. 시작할 때 한 번 적재하고,
동의 대기가 있으면 로그에 남긴다. 허용은 서버를 띄우는 사람이 CLI(`openguild
plugin allow`)로 하거나 관리 API 로 한다 — 어느 쪽인지 정해야 한다.

`drain` 은 종료 신호를 받았을 때.

### GUI (`Scope::Gui`)

여기서만 **대화상자로 물을 수 있다.** 처음 보는 플러그인이 있으면 정의와
스크립트 원문을 보여 주고 허용/거부를 받는다 — 사용자가 무엇에 동의하는지
보지 못하면 동의가 아니다.

Tauri invoke 핸들러 + 프런트엔드 화면이 필요하므로 CLI/서버보다 크다.

### 사용자 문서

기능이 다 붙은 뒤에 한 번에 쓴다 — 반쯤 붙은 상태로 문서에 올리면 없는 기능을
광고하게 된다.

- `docs/USAGE.md` — 플러그인 절(정의 위치, 동의, `openguild plugin` 명령).
- `skills/openguild-plugin/skills/openguild/reference/` — 에이전트가 읽는
  레퍼런스. 새 명령 그룹이 여기 없으면 에이전트는 그 명령을 모른다
  ([[BUG-261]] 에서 겪은 것과 같은 계열).
- CHANGELOG — 0.6.0 의 핵심 기능이므로 맨 위.

## 정해야 할 것

- 서버의 허용 경로 — CLI 로만 할지, 관리 API 를 열지.
- GUI 에서 동의를 물어보는 시점 — 길드를 열 때인지, 설정 화면에서인지.
- 전달 실패를 GUI 어디에 보일지(토스트? 설정 화면의 목록?).

## 테스트 방법

- 서버: `scope: ["server"]` 플러그인이 서버 mutation 에서 돈다. `["cli"]` 는 안 돈다.
- GUI: 동의 전에는 안 돌고, 대화상자에서 허용하면 돈다.
- 어느 쪽이든 플러그인 하나가 죽어도 길드 동작은 멀쩡하다.

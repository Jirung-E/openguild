tauri-plugin-updater 도입 + 시작 시 + 메뉴에서 수동 체크. 새 버전 있으면 다운로드 + 사용자 확인 후 재시작.

## 배경

DEV-034 가 installer 자체를 만든다면 본 quest 는 그 이후 — 사용자가 새
버전이 나왔을 때 알아채는 / 받는 메커니즘. installer 매번 새로 받기 불편.

## 구현 스케치

### Backend (gui)
- `tauri-plugin-updater = "2"` 추가.
- `lib.rs::run()` 에 `.plugin(tauri_plugin_updater::Builder::new().build())`.
- `tauri.conf.json::plugins.updater`:
  - `endpoints`: GitHub Release 의 `latest.json` URL (호스팅).
  - `pubkey`: 서명 검증용 (CI 가 signing key 로 release artifact 서명).
- capability 추가: `updater:default` (capabilities/default.json).

### Frontend
- 시작 시 자동 체크 (background, 비차단): onMount 에서
  `check()` → 새 버전이면 toast / 헤더 배지.
- 사용자 액션:
  - Welcome 또는 Admin 페이지 메뉴에 "업데이트 확인" 버튼.
  - 새 버전 있으면 release notes (latest.json 의 `notes`) 표시 + "다운로드 + 재시작" / "나중에" 선택.
- 진행 표시: 다운로드 % progress bar.

### 서명 (release 측, DEV-034 보완)
- Tauri 의 `tauri signer generate` 로 key pair 생성. private key 는
  GitHub secret, public key 는 tauri.conf.json.
- release CI 가 빌드 결과를 sign → latest.json 에 signature 포함.

## 검증
- 로컬 두 버전 빌드 → 한쪽에서 다른쪽으로 업데이트 확인.
- 서명 검증 실패 시 거부.
- "나중에" 누른 뒤 재시작해도 강제 안 됨.

## 구현 (2026-05-28)

### Backend (gui)
- `gui/Cargo.toml`: `tauri-plugin-updater = "2"` + `tauri-plugin-process = "2"`.
- `gui/src/lib.rs`: `.plugin(tauri_plugin_updater::Builder::new().build())`
  + `.plugin(tauri_plugin_process::init())`.
- `gui/capabilities/default.json`: `updater:default` + `process:default`.

### tauri.conf.json
- `bundle.createUpdaterArtifacts: true` — build 시 `*-setup.exe.sig` 생성.
- `plugins.updater`:
  - `endpoints`: `.../releases/latest/download/latest.json`
  - `pubkey`: minisign 공개키 (CI 가 private key 로 서명, 클라가 검증).

### Frontend
- 의존성: `@tauri-apps/plugin-updater` + `@tauri-apps/plugin-process`.
- `lib/api/updater.ts`: `checkForUpdate({silent})` / `downloadAndRelaunch()`
  / `dismissUpdate()` + `updateState` store. 브라우저 (http) 는 no-op.
  플러그인 모듈은 동적 import (브라우저 번들 강제 로드 방지).
- `lib/components/UpdateBanner.svelte`: 상태별 배너 (available / downloading
  +progress / ready / checking / uptodate / error). `+layout.svelte` 에
  mount → 시작 시 silent 체크.
- `Nav.svelte`: Tauri 에서만 "⟳ 업데이트" 버튼 (수동 체크).

### release.yml (DEV-034 보완)
- Tauri build step 에 `TAURI_SIGNING_PRIVATE_KEY` / `..._PASSWORD` env
  (GitHub secret). 없으면 signing skip.
- `Generate latest.json` step (tag push 때만): `.sig` 내용 + release asset
  URL 조합 → `latest.json`. secret 없으면 skip + warning.
- Release 첨부에 `*.sig` + `latest.json` 추가. `fail_on_unmatched_files:
  false` — secret 없는 환경에서도 release 성공.

### ⚠ 배포 측 1회 설정 필요 (사람)
1. GitHub repo Settings → Secrets and variables → Actions:
   - `TAURI_SIGNING_PRIVATE_KEY` = 생성된 private key 파일 내용
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` = 빈 문자열 (무패스워드 키)
2. 다음 release 부터 `latest.json` + `.sig` 자동 첨부.
3. **키 분실 시 업데이트 영구 불가** — 안전 보관 필수.

키 미설정 상태에서도 `cargo build` / `cargo tauri dev` 정상 — signing 은
`cargo tauri build` bundling 단계에서만 필요.

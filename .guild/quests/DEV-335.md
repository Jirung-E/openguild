admin 요청: 첨부 이미지가 HDR 로 보인다 — 이걸 제어하는 설정을 추가하고 싶다.
구현 가능한지 먼저 조사.

## 결론: 가능하다 (CSS 한 줄 + 설정 토글)

Chromium 에 `dynamic-range-limit` CSS 속성이 있다. 요소와 그 하위의 이미지가
디스플레이의 HDR 헤드룸을 얼마나 쓸지 제한한다.

**이 PC 의 Chrome 148 에서 실측한 지원 값:**

| 값 | 지원 |
|---|---|
| `standard` | ✅ (HDR 을 쓰지 않음 = SDR 로 톤매핑) |
| `constrained` | ✅ (제한적으로 사용) |
| `no-limit` | ✅ (기본 — HDR 전부 사용) |
| `high` | ❌ (이 키워드는 없음 — 문서 초안에만 있던 이름) |

즉 설정에서 "첨부 이미지 HDR: 사용 / 제한 / 끄기" 를 주고, 본문 이미지와
첨부 썸네일 컨테이너에 `dynamic-range-limit` 을 걸면 된다.

## 참고 사실

- HDR 표시 여부는 화면에 달렸다. 이 PC 는 `matchMedia('(dynamic-range: high)')`
  가 **false** — 여기선 애초에 HDR 로 안 보인다. admin 이 본 건 폰 화면일 것.
  같은 미디어 쿼리로 "HDR 화면일 때만 설정 노출" 같은 것도 가능하다.
- 데스크톱 앱(WebView2)의 Chromium 버전에 따라 미지원일 수 있다 —
  `CSS.supports('dynamic-range-limit','standard')` 로 확인해 미지원이면 설정을
  숨기거나 비활성 안내.
- 미지원 환경 대비 대체 수단은 마땅치 않다(`filter: brightness()` 는 HDR
  헤드룸을 건드리는 게 아니라 SDR 밝기만 낮춘다 — 오히려 어두워지기만 함).

## 범위 제안

1. 설정 페이지 '표시' 탭에 항목 추가 (기본값: 끄기? 제한? — admin 결정 필요)
2. 적용 대상: 마크다운 본문 이미지(`.md img`), 첨부 썸네일, 이미지 미리보기
3. 미지원 환경에서는 항목 자체를 숨김

## 구현 완료 (2026-08-05)

`gui/frontend/src/lib/stores/hdrSettings.ts` 신설 + `+layout.svelte` 에서
`<html>` 의 `--hdr-limit` custom property 로 반영. `.md :global(img)`
(MarkdownView, 본문 이미지) / `.thumb img`(AttachmentSection, 첨부 썸네일)
양쪽이 `dynamic-range-limit: var(--hdr-limit, no-limit)` 참조. 설정 페이지
'표시' 탭에 사용/제한/끄기 3단 토글 추가(기본값: 사용=no-limit, 기존 동작
유지) — `CSS.supports` 로 미지원 브라우저에서는 항목 자체 숨김.
store 단위 테스트(hdrSettings.test.ts) 통과.

## 테스트 방법

1. 설정 → 표시 탭에서 "첨부 이미지 HDR" 항목이 보이는지 (Chromium 계열
   최신 브라우저 필요 — 미지원이면 항목 자체가 안 보이는 게 정상).
2. HDR 로 촬영된 이미지를 퀘스트 본문 또는 첨부에 넣고, "제한"/"끄기"로
   바꿨을 때 실제로 덜 밝게(덜 HDR 하게) 보이는지 — 실제 HDR 디스플레이/
   이미지가 있어야 육안 확인 가능.

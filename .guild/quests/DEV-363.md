## 문제

`quest_id` 뱃지 스타일이 **공통 정의 없이 컴포넌트마다 중복**돼 있다.
`global.css` 에 공용 클래스가 없다.

같은 뱃지를 그리는데 값이 제각각이다:

| | QuestListItem | QuestBoard | QuestCombobox |
|---|---|---|---|
| radius | 20px | 20px | **12px** |
| background | `--c` 18% | `--c` 18% | **16%** |
| border | 40% | 40% | 40% |
| font-size | 0.75rem | 0.7rem | 0.7rem |
| padding | .15/.55rem | .15/.5rem | .1/.45rem |

## 실제로 사고가 났다

[[DEV-362]] 에서 검색 팔레트에 slug 칩을 추가할 때 **참고할 정본이 없어 눈으로
베끼다 테두리를 빠뜨렸다.** 사용자가 "기존과 약간 다르다" 고 지적해 전수 조사
후에야 공통 공식(타원 20px + 배경 18% + 테두리 40% + weight 500)을 찾았다.
정본이 있었으면 애초에 생기지 않았을 일이다.

## 범위 — `quest_id` 계열만

`border-radius: 20px|12px` 을 쓰는 컴포넌트는 12개지만 **전부 같은 뱃지는
아니다**. 태그 칩(`TagPills`)·필터 칩·이력 칩은 성격이 다르므로 건드리지 않는다.

통합 대상은 `--c`(타입/종류 색) 기반의 **식별자 뱃지**:

- `QuestListItem`
- `QuestBoard`
- `QuestCombobox` (12px/16% — 통합 시 20px/18% 로 수렴시킬지 판단 필요)
- `SearchPalette` (`.pslug`)

## 제안

`global.css` 에 `--c` 를 받는 공용 클래스를 두고 각 컴포넌트가 그것을 쓴다.
크기 차이는 modifier 나 CSS 변수로 흡수한다(팔레트 행은 조밀해 작은 크기가
필요하다 — 하나로 못 합치면 `--badge-size` 같은 변수로).

Svelte 의 스타일 스코핑 때문에 컴포넌트 안에서 전역 클래스를 쓰려면
`:global()` 이 필요하다 — 이 점을 확인하고 진행할 것.

## 주의

공용 UI 전반을 건드리므로 **시각 회귀 위험이 크다.** 각 화면(목록/보드/
콤보박스/팔레트)을 실제로 열어 크기·색·테두리를 대조 확인할 것.

## 테스트 방법

1. 퀘스트 목록 / 보드 / 퀘스트 선택 콤보박스 / 검색 팔레트를 차례로 열어
   `quest_id` 뱃지가 **변경 전과 같은 모양**인지 (의도한 수렴 외에는 회귀 없어야).
2. 라이트/다크 모두 확인.
3. 타입별 색(DEV/BUG/REQ)이 그대로 반영되는지.

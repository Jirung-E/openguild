`quest list --child-of <부모> --search <글>` 처럼 **부모 조건과 검색을 같이** 쓰면 맞는 것이 있어도 빈 목록이 나온다(2026-10-21, DEV-446 하며 발견).

- 재현(시험용 길드 사본): `--child-of DEV-089` 13개, 그중 제목에 gui 가 든 것 11개 → `--child-of DEV-089 --search gui` = **0개**.
- 원인: `services::quests::list_with_attachment_matches` 가 SQL 에는 검색 조건을 부모 조건 **앞에** 붙이는데, 값은 부모 id 를 검색어보다 **먼저** 끼운다. 그래서 부모 id 가 제목 LIKE 에, 검색어가 `parent_quest_id = ?` 에 들어간다.
- 같은 구조체를 쓰므로 서버 `GET /api/quests?child_of=…&search=…` 도 같다. 앱 목록 화면은 거르기를 화면에서 해서 영향 없다.

## 고칠 것

- 값을 끼우는 순서를 SQL 순서와 맞춘다.
- 시험: 부모 + 검색, 부모 + 검색 + 태그.

## 고침 (2026-10-21)

- 부모 id 를 검색어 **뒤에** 끼운다(SQL 순서 그대로).
- 시험 `child_of_and_search_together_bind_in_sql_order` — 부모 + 검색, 부모 + 검색 + 태그. 고치기 전 코드에서 빈 목록으로 실패. `just test` 통과.
- 시험용 길드 사본: `--child-of DEV-089 --search gui` 0 → 11.

## 테스트 방법

- `openguild quest list --child-of <자식이 있는 퀘스트> --search <그 자식 제목의 낱말>` → 그 자식이 나오면 정상.

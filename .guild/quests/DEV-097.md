## 아이디어

Quest 에 이미지 / 파일 첨부. 두 가지 범위:

- **글로벌 첨부파일** — 여러 quest 가 공유 가능. 예: 로고, 디자인 가이드, 공용
  스크린샷.
- **로컬 첨부파일** — 한 quest 전용. 다른 quest 에서 못 씀.

## 저장 설계 (초안)

### 디렉토리
```
.guild/
├── attachments/          ← 글로벌 (tracked? 또는 LFS?)
│   ├── images/
│   └── files/
└── quests/
    ├── DEV-001.md
    └── DEV-001.attachments/   ← 로컬 (이 quest 와 운명 공유)
        ├── screenshot.png
        └── reference.pdf
```

### Frontmatter 또는 inline reference
- markdown 안에 `![alt](attachments/foo.png)` (글로벌) 또는
  `![alt](DEV-001.attachments/foo.png)` (로컬).
- 또는 quest frontmatter 의 `attachments = ["foo.png", "bar.pdf"]` 배열.

### 삭제 정책
- Quest soft-delete → 로컬 첨부도 함께 archive (또는 유지).
- 글로벌은 reference count — 어떤 quest 도 안 쓰면 cleanup 후보.

## 작업

### 1. 저장 + reference
- `.guild/attachments/` (글로벌) / `.guild/quests/{slug}.attachments/` (로컬)
  디렉토리 생성.
- `core::repo::attachments` 모듈 — list / upload / delete / move (로컬 ↔ 글로벌
  승격).

### 2. HTTP / Tauri
- `POST /api/quests/{id}/attachments` (로컬, multipart).
- `POST /api/attachments` (글로벌).
- `GET /api/attachments` (글로벌 목록).
- `DELETE /api/attachments/{path}`.

### 3. Frontend
- Quest Detail 에 첨부 섹션 (썸네일 + 다운로드 + 삭제).
- Markdown 에디터에서 drag-drop → 자동 upload + 본문에 reference 삽입.
- 글로벌 vs 로컬 토글 (업로드 시 선택, 사후 승격 가능).

### 4. 검색
- 첨부 파일명 / 메타데이터 검색 — 추후.

## 향후 (이 quest 범위 외)
- 이미지 EXIF strip (보안).
- 첨부 사이즈 제한 / 알림.
- S3 / 클라우드 sync (AWS 백엔드 단계 이후).

사용자 보고: 연관 퀘스트 추가/제거·상태 변경이 ~1초 지연(퀘스트 많을수록
심함), 보드 snap 도 느림(snap 은 await changeStatus 뒤라 동일 원인).

## 원인 (실측으로 규명)
`after_mutation` → `maybe_auto_snapshot` → `latest_snapshot()` →
`list_snapshots()` 가 **모든 스냅샷 디렉토리에 `tree_size`(전체 파일 재귀
stat)** 를 수행. 스냅샷은 BUG-076 이후 길드 소스 전체 복사본(각 수백 파일)
이라 비용이 (스냅샷 수 × 길드 파일 수)에 비례 — 매 mutation 마다 발생.

실측(도그푸딩 길드 복사본, 스냅샷 7개/23MB):
- 상태변경/prereq: **~0.5s** ↔ 스냅샷 비우면 20ms (절제 실험으로 확정)
- 합성 600퀘스트(스냅샷 없음): 16ms — "퀘스트 수" 자체가 아니라 스냅샷 걸림

## 수정
age trigger 는 최신 스냅샷의 timestamp(디렉토리 이름)만 필요 —
`latest_snapshot_timestamp()`(이름 스캔만, tree_size 없음) 신설 후
`maybe_auto_snapshot` 이 그걸 사용. `list_snapshots`(size 포함)는 admin
목록 UI 용으로 유지.

## 실측 (수정 후, 스냅샷 7개 존재)
상태변경 14~24ms, prereq add/remove 14ms. (간헐 2s 는 임계치 도달로 실제
스냅샷 생성 — 별도 후속: 동기 블로킹을 백그라운드화)

## 테스트 방법
스냅샷 여러 개 있는 큰 길드에서 상태변경/연관 추가·제거/보드 드래그 snap
이 즉각 반응하는지. `cargo test -p openguild-core snapshot` 통과.

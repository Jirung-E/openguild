DEV-317 DOM/SVG 보드 전환 후 실제 사용에서 확인된 저배율 표시·성능 회귀를
한 범위로 수정한다.

## 증상

- 접힌 레인에도 grid snap 점이 계속 보인다.
- snap 점과 저배율 노드가 흐리고 지나치게 작다.
- snap 점이 일정 높이 위·아래에서는 그려지지 않는다.
- 보드를 깊게 축소하면 제스처가 버벅인다.
- 실제 Tauri/Safari에서 rAF/표시 주사율이 60Hz인지 120Hz인지 앱 안에서 확인할
  수단이 없다.
- 후속 실기에서 레인당 snap 열이 하나만 보이고 점이 너무 크게 보였다.
- macOS Tauri 앱의 성능 HUD가 ProMotion 화면에서도 30Hz로 고정됐다.

## 구현

- snap 시각 레이어를 거대한 world 배경에서 분리해 현재 viewport만 덮는 반복
  타일로 만들고, pan은 transform/phase만 갱신한다.
- collapsed/hidden lane에는 snap 시각 레이어를 표시하지 않는다.
- CSS 가로 반복에 기대지 않고 레인마다 최대 3개의 실제 세로 dot column을 만든다.
  laneCols가 1/2/3이면 동일한 수의 열만 노출한다.
- 점 반지름은 screen-space 0.55~1.35px로 줄이고 세로 범위는 viewport 전체에서
  반복되게 한다.
- 깊은 축소에서는 상세 카드 paint를 줄이는 저배율 LOD를 적용하되 hit-test와
  위치·edge 정합은 유지한다.
- 성능 HUD는 릴리스 UI에서 제거한다. Vite dev 또는 Rust debug 빌드에서만
  Cmd/Ctrl+Shift+H로 토글하며 rAF 간격, p95, 누락 프레임, board viewport
  transform 갱신 수와 page visibility/focus를 표시한다.
- 보드 코드에는 30fps 제한이 없다. 일반 브라우저에서는 120Hz가 측정됐고,
  macOS Tauri의 30Hz는 WKWebView rAF pacing 경로에서 발생한다. 공개 API로
  WKWebView 120Hz를 요청하는 방법은 현재 없으므로 별도 플랫폼 조사 대상으로 둔다.

관련 기록: [[DEV-317]], [[BUG-180]], [[BOOK-002]].

## 테스트 방법

1. snap on 상태에서 레인 접기/펼치기 시 해당 레인의 점이 함께 사라지고 복원된다.
2. 위·아래로 멀리 pan해도 현재 viewport 전체에 snap 점이 이어진다.
3. 레인 열 수를 1/2/3으로 바꿀 때 각 레인에 동일한 수의 세로 snap 열이 보인다.
4. 최소 zoom에서도 작은 점이 식별 가능하고, 노드는 가벼운 overview 표현으로 보인다.
5. 최소 zoom에서 연속 pan/zoom의 frame interval과 Layers/CPU를 기존 구현과 비교한다.
6. 디버그 빌드에서 Cmd/Ctrl+Shift+H로 HUD가 켜지고 다시 꺼진다.
7. 릴리스 빌드에는 성능 버튼이 없고 단축키도 동작하지 않는다.
8. macOS Tauri에서 HUD의 page가 visible/focus인지 확인한 뒤 30/60Hz 값을 기록한다.

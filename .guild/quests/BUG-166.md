# [cli] rules 명령이 --remote(HTTP) 미지원

서버에는 처음부터 `/api/rules*` 라우트가 전부 있는데 CLI 의
`Backend::Http` 가 6개 메서드 모두 `http_unsupported_meta()` 로 막고 있었다
(도서관·댓글·퀘스트는 원격을 지원해 비대칭).

## 구현

`rules_list/get/set/create/delete/rename` 을 서버 라우트에 배선:

| CLI | HTTP |
|---|---|
| `rule list` | `GET /api/rules` → `{entries:[...]}` |
| `rule show` | `GET /api/rules/{slug}` → `{content: null 가능}` |
| `rule set` | `PUT /api/rules/{slug}` `{content}` |
| `rule new` | `POST /api/rules` `{slug, content}` |
| `rule delete` | `DELETE /api/rules/{slug}` |
| `rule rename` | `PATCH /api/rules/{slug}` `{new_slug}` |

응답 DTO(`RulesListDto`/`RuleDto`)는 server `routes/rules.rs` 의
RulesListResponse/RuleResponse 와 1:1 — 필요한 필드만 받아 서버가 필드를
추가해도 안 깨지게 했다.

## 함께 고친 것 — 경로 인코딩

규칙 slug 는 **공백을 포함할 수 있다**(`코딩 규칙` 처럼 파일명이 곧 slug,
BUG-156). 그대로 경로에 끼우면 원격 요청이 깨진다. unreserved 문자만 남기고
%XX 로 바꾸는 `urlenc()` 를 추가하고(의존성 추가 없이 최소 구현), 이미 원격을
지원하던 `rule history` 의 미인코딩 경로도 같이 고쳤다.

## 검증 (임시 길드 + 실제 서버)

`--remote` 로 **공백·한글 slug**(`코딩 규칙`)에 대해 전 명령 실행:

- `rule new` → ✓ created, `rule list` → 표에 정상 표시
- `rule show` → 한글 본문 그대로
- `rule set` → 갱신 반영 확인
- `rule rename` → `코딩 규칙` → `코딩 스타일`
- `rule history` → `[rename] 코딩 규칙 → 코딩 스타일` / `[update]` / `[create]`
  3건 (DEV-290 기록이 원격으로도 조회됨)
- `rule delete --force` → 목록에서 사라짐
- 로컬 모드 회귀: 실제 길드에서 `rule list` / `show` / `history` 정상

주의(조사 중 겪은 함정): `rule history` 가 처음엔 HTML(SPA fallback)을 반환해
라우트 문제로 보였으나, **서버 바이너리가 DEV-290 이전 빌드**였던 것.
`cargo build -p openguild-server` 후 정상. 원격 기능을 검증할 때는 서버
바이너리가 최신인지 먼저 확인할 것.

## Test plan

1. 원격 서버를 띄우고 `--remote` 로 위 6개 명령 + history 반복.
2. 공백·한글·특수문자(`#`, `?`) 가 든 slug 로도 동작하는지.
3. 없는 slug 로 show/delete → 명확한 에러(HTML 아님).
4. 로컬 모드 회귀 — 같은 명령들이 그대로 동작.

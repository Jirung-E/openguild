## 사용자 피드백 (2026-07-17): locale en 인데 --help 가 한국어

원인: DEV-254 의 번역 범위는 println!/에러 메시지(tf! 매크로)였고, --help
텍스트는 clap 파생 매크로의 `///` doc 주석에서 오는 **컴파일 타임 정적
문자열** — locale 스위치가 아예 적용되지 않는 별개 경로다.

저장 위치(같은 질문에 대한 답): `~/.openguild/locale.json`
(Windows: C:\Users\<user>\.openguild\locale.json). 우선순위는
OPENGUILD_LOCALE 환경변수 > locale.json > 기본 ko. GUI 는 아직 자체
localStorage(openguild.locale)를 써서 CLI 설정과 동기화되지 않음 — 이것도
후속 범위 후보.

## --help 로케일화 구현 방향 (남은 범위)

- clap derive 는 `#[command(about = <expr>)]` / `#[arg(help = <expr>)]` 에
  런타임 표현식을 허용(Command 빌드 시 평가) — doc 주석 대신 tf!() 기반
  표현식으로 옮기면 언어 반응 가능.
- 단 help 는 `Cli::parse()` 중에 렌더되므로, LOCALE static 로드를 run()
  안이 아니라 **parse 이전(main 초입)** 으로 옮겨야 함.
- 전체 커맨드/인자 도움말 문자열 번역 = CLI 표면 전체 — 규모가 커서 별도
  일괄 작업 필요. BUG-016(help 에 퀘스트 ID 금지) 회귀 테스트가 en/ko 양쪽
  렌더를 다 스캔하도록 확장도 필요.

DEV-472 의 eslint 정리 중 발견(`svelte/no-at-html-tags`).

## 무엇
`MarkdownView.svelte` 가 마크다운을 `marked` 로 HTML 로 바꾼 뒤 `{@html html}` 로 **거르지 않고** 넣는다. `marked` 는 본문 속 HTML 을 그대로 통과시키므로, 퀘스트 · 캠페인 · 도서관 · 규칙 본문이나 댓글에 이런 것이 있으면 화면을 여는 순간 스크립트가 돈다:

```html
<img src=x onerror="…">
```

## 왜 문제인가
- 길드 내용은 git · 공유 서버로 **남이 쓴 것**이 들어온다.
- 데스크톱 앱에서는 그 웹뷰가 앱 기능(Tauri invoke — 파일 · 플러그인 허용 등)을 부를 수 있다. 서버 웹 화면에서도 같은 출처의 API 를 부를 수 있다.

## 고칠 방향(논의)
- HTML 소독(DOMPurify 같은 것)을 `{@html}` 앞에 — 허용 태그 · 속성 목록. 지금 마크다운에서 쓰는 것(코드 하이라이트 span, mermaid 자리, 표, 체크박스, cross-link)이 살아남는지 확인.
- 또는 `marked` 에서 원문 HTML 을 막고(글자로 보이게) 필요한 것만 허용.

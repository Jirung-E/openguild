# 크로스링크 호버 시 미리보기 팝업 (검색 팔레트와 동일)

본문(quest/campaign description·댓글·규칙·도서관 등)에 렌더된 크로스링크
(`[[DEV-033]]` / `[[C-001]]` / `[[kind:ID]]`)에 마우스 호버하면, 검색
팔레트에서 결과를 선택했을 때와 동일한 미리보기 팝업을 띄운다.

## 구현 (2026-07-19)

- **`LinkPreviewPopup.svelte` 신규** — 종류 칩 + 제목 헤더 + MarkdownView
  본문(최대 260px 스크롤) + "새 창으로 열기"/"페이지로 이동" 버튼.
  검색 팔레트 미리보기와 동일한 톤(칩 색/버튼 스타일)이지만 코드를 뜯어
  오진 않고 팝업 전용으로 새로 작성 — SearchPalette 의 미리보기는 팔레트
  내부 상태(목록 복귀/크기조절 핸들 등)와 강결합이라 추출 비용이 더 컸음.
- **MarkdownView 에 위임(delegation) 훅** — 동적 생성되는 `a.xlink` 에
  개별 리스너를 달 수 없어 컨테이너 mouseover/mouseout 위임. 실재 링크
  (missing 제외)에만 data 속성(xkind/xid/xslug/xtitle)을 실어 팝업이
  읽는다. 호버 intent 280ms 후 열림, 링크/팝업 모두 벗어나면 300ms 후
  닫힘(링크→팝업 이동 중엔 안 닫힘). 팝업 컴포넌트는 **동적 import** —
  LinkPreviewPopup ↔ MarkdownView 정적 순환 의존 회피 + 첫 호버 전 비용 0.
- **팝업 위치** — 앵커 rect 기준 아래(화면 60% 이하면 위), 가로 clamp.
  z-index 1300(검색 팔레트 1200 위) — 팔레트 미리보기 안 크로스링크에서도
  중첩으로 뜬다(위키피디아 프리뷰 식).
- **부수 버그 수정(작업 중 발견)** — 첫 렌더 시점에 인덱스가 아직 적재
  전이면 크로스링크가 missing(빨강)으로 만들어진 뒤, 인덱스 적재 후
  effect 재실행에도 원본 텍스트 노드가 이미 anchor 로 치환된 뒤라 영구
  고착되던 레이스. anchor 에 원본 토큰(data-xtoken)을 남기고 재실행 시
  기존 anchor 를 다시 resolve 해 갱신하도록 수정(존재→미존재 전환도 동일
  경로).

## 결정 사항

- DEV-255 의 열기 방식 3종 중 "미리보기" 버튼은 제외(팝업 자체가 이미
  미리보기), 새창/페이지이동 2개만 노출.

## 테스트 방법 (1·2는 실기 확인 완료)

1. 웹 모드(vite dev + openguild-server, 스크래치 길드)에서 `[[DEV-002]]`
   포함 본문 호버 → 팝업(칩/제목/본문/버튼) 표시 확인, 마우스 벗어나면
   닫힘 확인 — 접근성 트리 레벨로 검증 완료.
2. `npm run build` + `npx svelte-check` 클린.
3. (사용자 확인 필요) 데스크탑 앱에서 호버 딜레이 체감/팝업 위치/중첩
   팝업(팝업 안 링크 호버) 등 시각적 완성도 확인.

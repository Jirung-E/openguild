Admin 에서 type prefix / status slug 까지 rename 가능하도록.
현재 (DEV-014) 는 둘 다 frozen — 표시 이름 (name_en / name_ko / color /
description) 만 수정 가능. 본 quest 는 그 frozen 을 푸는 cascade 작업.

## 왜 frozen?

slug / prefix 가 다음 위치에서 stable identifier 로 참조됨:

### Type prefix
- `.guild/quests/<PREFIX>-NNN.md` — 파일명 자체.
- frontmatter `quest_id = "DEV-001"` — 본문 안 ID.
- `.guild/types/<PREFIX>.toml` — type 파일명.
- DB `quests.number` 는 prefix 별 카운터.
- 다른 quest 의 본문에서 mention (`DEV-001 참조`) — 본문 grep 필요.

### Status slug
- `.guild/statuses/<order>-<slug>.toml` — 파일명.
- `.guild/quests/*.md` frontmatter `status = "open"` — 모든 quest 의 본문.
- DB `quest_statuses.slug`.
- DB `quest_history.old_value / new_value` (DEV-042 — slug 저장).
- frontend 의 redirect (`/quests/by/<slug>` 같은 경로는 quest_slug 임 —
  status slug 와 다름. 그래도 admin 의 status 페이지 routing 등 검토).

## 구현 스케치

### Backend
- `core/src/ops/meta.rs`:
  - `rename_type(store, old_prefix, new_prefix)`:
    1. validate new_prefix (기존 create 규칙 재사용).
    2. `.guild/types/<old>.toml` → `.guild/types/<new>.toml` rename.
    3. 모든 `.guild/quests/<old>-NNN.md` 파일명 + frontmatter `quest_id`
       + 본문 내 self-mention 갱신.
    4. 다른 quest 본문의 mention (`<old>-001` 같은 패턴) 일괄 grep + replace
       — 사용자 확인 후 (dry-run 옵션).
    5. DB `quest_types.prefix` UPDATE — `quests.number` / `quest_counters`
       자동 정합 (FK).
    6. `quest_positions.quest_slug`, `quest_history.quest_slug` 도 cascade
       UPDATE (DEV-049 의 slug 컬럼).
  - `rename_status_slug(store, old_slug, new_slug)`:
    1. validate new_slug (a-z0-9_).
    2. `.guild/statuses/<order>-<old>.toml` → `<order>-<new>.toml` rename.
    3. 모든 `.guild/quests/*.md` frontmatter `status = "<old>"` → "<new>"
       일괄 rewrite.
    4. DB `quest_statuses.slug` UPDATE.
    5. DB `quest_history.old_value / new_value` 에서 매칭 slug UPDATE.
- 두 작업 모두 transaction + dry-run 모드 + 영향받는 파일 수 reporter.

### Tauri commands
- `admin_rename_type(old_prefix, new_prefix)` / `admin_rename_status_slug(
  old_slug, new_slug)`.
- Frontend Admin 의 inline 수정에 prefix / slug 도 편집 가능 input 추가
  (현재 frozen `<code>` 였음).

### 위험 + 가드
- 진행 중 cascade 실패 시 partial 상태. transaction + 파일 백업 (snapshot)
  자동 실행 권장.
- 본문 mention 검출 — false positive 위험 (`DEV-001` 이 다른 의미 가능).
  사용자에게 dry-run 결과 보여주고 확인.
- frontend redirect: `/quests/<id>` 는 number ID — slug 와 무관. 영향 X.
  단 다른 frontend 자리 검토 필요.

## 검증

- Type rename: `cargo test` + 라이브에서 DEV → CORE 같은 rename → 모든
  quest 파일 + frontmatter + 본문 mention 갱신 + index.db 정합.
- Status rename: open → in_review 같은 rename → frontmatter 일괄 변경 +
  history 보존 확인.
- dry-run 결과 + 사용자 확인 UI 검증.

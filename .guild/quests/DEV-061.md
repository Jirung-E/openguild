Admin 에서 type prefix / status slug 까지 rename 가능하도록. 현재는 둘 다 frozen — 표시 이름 (name_en / name_ko / color / description) 만 수정 가능.

## 정책 (DEV-055 와 동일)

- **본문 mention** (다른 quest 의 description 안 자유 텍스트 `DEV-001` 같은
  표기) 은 자동 갱신 X — 사용자 책임. false positive 방지 + 단순화.
- 자동 cascade 대상: 파일명 + frontmatter + DB 의 stable id 컬럼들.

## 구현 (2026-05-24)

3 phase 분할.

### Phase 1 — core ops (commit 1)

#### `ops::meta::rename_type(store, old_prefix, new_prefix)`
- validate + 중복 거부 + 같은 prefix NoOp.
- transaction:
  - `quest_types.prefix` UPDATE.
  - `quest_history.quest_slug` cascade — 그 type 의 모든 quest 의 새 slug
    (SQL 안에서 type prefix + zero-padded number compose).
  - `quest_positions.quest_slug` cascade.
- 파일 IO:
  - `.guild/types/<old>.toml` 의 prefix 필드 갱신 + `<new>.toml` write +
    옛 파일 삭제.
  - 그 type 의 모든 `<old>-NNN.md` → `<new>-NNN.md` rename + frontmatter
    `quest_id` 갱신 (write_quest_file 호출).
  - 관련 다른 quest (parent / sub / prereq / dependent) 의 auto-block
    재생성 — 본인 mention 새 slug 반영.

#### `ops::meta::rename_status_slug(store, old, new)`
- validate (`[a-z0-9_]` 1~32) + 중복 거부.
- transaction:
  - `quest_statuses.slug` UPDATE.
  - `quest_history.old_value / new_value` (op='change_status') UPDATE.
- 파일 IO:
  - `.guild/statuses/<order>-<old>.toml` → `<order>-<new>.toml` rename
    (파일 내용 unchanged).
  - 그 status 의 모든 quest .md frontmatter rewrite — write_quest_file 가
    자동으로 새 slug 반영.

#### 부수 fix
- `write_quest_file` 의 frontmatter.status 가 `status_name_to_slug` (name_en
  추정) 대신 `quest.status_slug` (DB truth, DEV-042 slug 컬럼) 직접 사용.
  status name_en 그대로 두고 slug 만 바꾸는 rename 시 필수.
- `status_name_to_slug` 헬퍼 제거.
- `write_quest_file` 가시성 `pub(crate)` — ops::meta 에서 호출.

#### 테스트 +7 (core 162 → 169)
- rename_type_empty / rename_type_with_quests_cascades /
  rename_type_rejects_duplicate / rename_type_rejects_invalid_prefix.
- rename_status_slug_renames_file_and_cascades /
  rename_status_slug_rejects_duplicate /
  rename_status_slug_rejects_invalid_slug.

### Phase 2 — Tauri commands + frontend API (commit 2)

- `gui/src/commands.rs`:
  - `admin_rename_type(prefix, body: { new_prefix })`.
  - `admin_rename_status_slug(slug, body: { new_slug })`.
- transport.ts: `POST /api/admin/{types,statuses}/<id>/rename` — rename 은
  별도 sub-resource (PATCH 의 partial-update 의미 충돌 회피).
- transport.test +2 (115 → 117).
- adminApi: `renameType(prefix, newPrefix)` /
  `renameStatusSlug(slug, newSlug)`.

### Phase 3 — Admin UI (commit 2 합침)

- AdminTypesSection / AdminStatusesSection 각 row 의 "수정" 옆에
  **"이름"** 버튼 추가.
- 클릭 → 별도 rename 모달:
  - 현재 prefix/slug 표시 + 새 값 input.
  - 영향 안내 ("이 type 의 모든 quest 의 slug 가 함께 변경됩니다", 본문
    mention 사용자 책임).
  - input 에 maxlength + pattern (HTML5 hint, 진리원은 backend).
  - "변경" / "취소".
- 성공 시 toast 메시지 + 목록 refresh.

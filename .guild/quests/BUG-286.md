## 증상

admin: *"BUG-284 - 애초에 저장을 안하는게 문제 아님?"*

맞다. 그리고 [[BUG-284]] 보다 한 층 깊다. **보드 위치가 영속적으로 저장되지 않는다.**

실측(서버로 위치를 저장한 뒤):

```
① 손으로 옮긴 위치:        x=777 y=888
② reindex 뒤:              x=777 y=888     ← 메모리 백업으로 살아남음
③ rm index.db + reindex:   []              ← 전부 사라짐
```

③은 예외 상황이 아니다. [[BOOK-001]] 이 **"회피책이 아니라 불변식의 일부"** 라고
하고, `release-process` 규칙이 **브랜치 전환·머지 후마다** 실행하라고 하는 명령이다.
즉 **브랜치를 바꿀 때마다 사용자의 보드 배치가 날아간다.** 새로 clone 한 기계에도
없다(index.db 는 gitignore).

## 원인 — 설계된 저장소가 구현되지 않았다

BOOK-001 은 저장 클래스를 **셋**으로 나누고 위치의 자리를 명시한다.

> - **tracked 진리**: `.guild/quests|…` — git 이 관리, 브랜치를 따라감.
> - **폐기가능 캐시**: `.guild/index.db` — 파생물, 반드시 파일에 종속.
> - **로컬 UI 상태**: `.guild/positions.json` — tracked 도 캐시도 아님. 보드 좌표 등
>   개인 로컬. gitignored.

코드는 이걸 따르지 않는다.

- 위치를 **폐기가능 캐시(`index.db` 의 `quest_positions`)에만** 둔다.
- `positions.json` 은 `GuildPaths::positions_json()` 으로 **경로만 선언**돼 있고
  **읽는 곳도 쓰는 곳도 없다.** `.gitignore` 에도 올라가 있다 — 만들 생각은 했다.
- `reindex` 가 지우기 전에 위치를 **메모리에** 백업했다 복원하는 우회로 ② 를
  살렸는데, db 파일 자체를 지우면(③) 백업할 원본이 없다. 코드 주석이 이미 자백한다:
  *"position 은 UI 상태라 파일에 저장 안 함 → reindex 가 wipe 하면 그대로 사라짐."*

## BUG-278 / BUG-284 와의 관계

둘 다 이 구멍 위에 서 있다.

- [[BUG-278]] · [[BUG-284]] 는 "자동 배치 노드를 저장하지 않아 다시 계산되며 밀린다"
  를 고쳤다. BUG-284 는 보드 적재 때 위치를 **고정**한다.
- 그런데 고정한 곳이 브랜치 전환마다 지워지는 곳이다. 지워지는 순간 **전부 다시
  자동 배치 대상**이 되고 278/284 의 증상이 되살아난다.

BUG-284 의 **시점**(보드가 노드를 볼 때 고정)은 맞다. 퀘스트를 만드는 쪽(CLI·API·
에이전트)은 보드 기하(노드 폭·레인 폭·열 위치 — 전부 프런트 상수)를 모르므로 생성
시점에 위치를 정할 수 없다. 틀린 것은 **저장 장소**다.

## 수정 방향 — BOOK-001 대로

`positions.json` 을 위치의 **진리원**으로 삼는다.

- 쓰기: 위치를 저장할 때 `positions.json` 에 쓴다(원자적 쓰기). index.db 의
  `quest_positions` 는 그 투영이다.
- 읽기/적재: `reindex` 가 `positions.json` 에서 `quest_positions` 를 채운다. 메모리
  백업 우회는 필요 없어진다.
- **키는 slug** — 정수 id 는 reindex 가 재배정한다(기존 백업이 slug 기준인 이유).
- 이동: 첫 실행 때 기존 `index.db` 위치를 `positions.json` 으로 옮긴다. 안 옮기면
  업그레이드한 사용자의 배치가 그 순간 날아간다.
- gitignore 는 그대로 — 사람마다 보드를 다르게 배치하는 개인 UI 상태다.

## 테스트 방법

- 위치를 저장한 뒤 **`rm index.db && reindex`** 해도 위치가 남는다(지금은 `[]`).
- 브랜치 전환 흉내(파일은 그대로, index.db 만 새로) 뒤에도 남는다.
- 퀘스트 타입이 바뀌어 slug 가 바뀌면 위치도 따라간다(`DEV-001` → `BUG-001`).
- 기존 index.db 에만 위치가 있는 길드를 열면 `positions.json` 으로 옮겨진다.
- 일괄 저장([[BUG-284]])도 파일에 한 번에 쓴다 — 건마다 파일을 다시 쓰지 않는다.

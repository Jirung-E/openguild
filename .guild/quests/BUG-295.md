## 무엇이 잘못됐나

첨부가 4개 있는 퀘스트를 CLI 로 보면 하나도 없다고 답한다.

```
$ openguild --json quest show DEV-007   →  "attachments": []
$ openguild quest show DEV-007 --full   →  첨부 이야기가 한 줄도 없음
```

파일(`.guild/quests/DEV-007.attachments.json`)에는 멀쩡히 4개가 있다. 도서관·캠페인도 같고,
`library attach add` 로 방금 붙인 직후에도 `library show` 는 `[]` 라고 한다.

## 왜

`core/src/services/quests.rs` 의 `get_by_slug`/`get_by_id` 가 `attachments: Vec::new()` 로
두고 넘긴다 — 첨부는 sidecar 파일이 진리원이라 `Store` 를 가진 호출 계층이 채우는 구조다
(DEV-156). 그런데 **GUI(`gui/src/commands.rs`)와 서버(`server/src/routes/quests.rs`)만 채우고
CLI 는 안 채운다.** 도서관·캠페인도 마찬가지다.

## 왜 중요한가

에이전트가 퀘스트를 읽는 주된 수단이 `quest show --json` 이다. 지금은 **첨부가 있다는 사실
자체를 알 수 없다** — 사람이 스펙 PDF 나 목업을 붙여 놔도 없는 것처럼 일한다. 조용히 틀린
답을 주는 쪽이라 더 나쁘다.

## 할 일

- CLI 의 `quest show` / `library show` / `campaign show` 가 첨부를 채우고, 사람이 보는
  출력에도 목록을 적는다(이름 · 경로). `--json` 도 같은 값을 낸다.
- 스킬 문서에 **"첨부를 확인한다"** 를 넣는다. cross-link 에는 "반드시 따라가라" 는 절이
  통째로 있는데, 첨부는 **만드는 법만** 있고 읽으라는 말이 없다.

## 테스트 방법

- 첨부가 있는 퀘스트·도서관 문서·캠페인을 `show` 로 보면 목록이 보인다(`--json` 도).
- 첨부가 없으면 그 자리가 아예 없다(빈 섹션을 만들지 않는다).
- 되돌려 확인: 채우는 코드를 지우면 이 시험이 깨진다.

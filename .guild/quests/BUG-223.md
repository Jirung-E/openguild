Tauri 데스크톱 앱(macOS)에서 첨부 이미지/동영상 썸네일 및 **본문에 붙여넣은 이미지/동영상**까지 전부 로드 실패(깨진 이미지 아이콘). 파일 칩으로 대체 표시되는 게 아니라 `<img>`/`<video>` 자체가 뜨는데 로드만 실패 — URL은 만들어지는데 실제 asset 로드가 막힘.

## 원인 (확정 — Tauri 소스 + 재현 테스트로 검증)

`gui/src/lib.rs` / `commands.rs` 세 군데에서 asset protocol scope 를
`asset_protocol_scope().allow_directory(guild_root, true)` 로,
**길드 루트**를 기준으로 재귀 허용해왔다. 그런데 실제 첨부/이미지 파일은
전부 `guild_root/.guild/...` 아래에 있고, `.guild` 는 **숨김(dot) 디렉터리**다.

Tauri(`tauri` crate 2.11.2, `scope/fs.rs`)의 asset scope 는 내부적으로
`glob` crate 패턴 매칭을 쓰는데, `require_literal_leading_dot` 옵션이
**Unix(macOS/Linux)에서 기본값 `true`**다(우리 `tauri.conf.json` 의
`assetProtocol.scope: []` 는 배열 형태라 `FsScope::AllowedPaths` 로
파싱되고, 이 값을 오버라이드할 수 있는 `FsScope::Scope{require_literal_
leading_dot,...}` 객체 형태가 아니므로 기본값 `true` 가 그대로 적용됨).
`require_literal_leading_dot=true` 면 `*`/`**` 같은 와일드카드는 `.` 로
시작하는 경로 컴포넌트에 **매칭되지 않는다** — 즉
`allow_directory(guild_root, true)` 가 만드는 패턴 `guild_root/**` 는
`guild_root/.guild/attachments/x.png` 를 매칭하지 못한다(`.guild` 부분을
와일드카드가 건너뛰지 못함).

**재현 테스트**(`glob` crate 로 Tauri 와 동일한 `MatchOptions` 로 직접
확인):
```
OLD scope (allow_directory(guild_root)) matches target? false
NEW scope (allow_directory(guild_root/.guild)) matches target? true
```

## 수정

`allow_directory(guild_root, true)` → `allow_directory(guild_root.join(".guild"), true)`
로 변경 — `.guild` 를 패턴에 **리터럴 텍스트**로 포함시키면(와일드카드가
아니라 실제 문자로 존재) `require_literal_leading_dot` 옵션과 무관하게
매칭된다. 3곳(`gui/src/lib.rs` 시동 시, `gui/src/commands.rs` 의
`init_and_open_guild`/`open_guild_in_current_window` 길드 전환 시) 전부 동일 수정.

## 테스트 방법

Tauri 데스크톱 앱에서: 퀘스트 상세의 첨부 섹션 이미지/동영상 썸네일, 그리고
본문에 붙여넣은 이미지/동영상 둘 다 정상 표시되는지 확인. (수학적으로/
glob 매칭 테스트로 검증했으나 실제 GUI 클릭 검증은 Accessibility 권한 문제로
이 세션에서 직접 못 함 — 실제 화면 확인 부탁드립니다.)

쓰기가 파일이 아니라 `index.db` 를 믿어서, DB 가 파일보다 뒤처지면 데이터가 조용히 사라진다.

재현(v0.5.3 에도 있음):
- `index.db` 가 없는 길드(git 으로 받은 길드)에서 `quest new` · `campaign new` → 기존 `DEV-001` · `C-001` 을 덮어쓴다. 목록은 0건.
- git pull 로 `DEV-002` · `C-002` 가 들어온 뒤 `quest new` · `campaign new` → 들어온 문서를 덮어쓴다.
- 밖에서 제목을 고친 뒤 CLI 로 다른 칸을 고치면 → 제목이 옛 값으로 되돌아간다.

할 것:
1. 번호는 파일에서 — `types/*.toml` 카운터와 실제 파일 최대 번호 중 큰 값 + 1(도서관과 같은 방식). 퀘스트 · 캠페인 · retype.
2. 새 문서는 기존 파일을 덮어쓰지 않는다.
3. 쓰기 전에 문서 잠금 안에서 그 문서 파일을 다시 읽어 DB 를 맞춘다.
4. 조회 전에 바뀐 파일을 반영한다 — 명령마다 reindex 는 안 한다. 앱 열기 시간도 함께 줄일 방법을 본다.

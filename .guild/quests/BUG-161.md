# [core] init 이 생성하는 .gitignore 에 이 repo 퀘스트 번호/한글 주석 leak

사용자 보고: init 할 때 자동생성되는 gitignore 에 한글과 퀘스트번호가
있는 것 같다.

## 원인

`GuildPaths::gitignore_content()` 가 이 repo 의 개발 맥락을 그대로 담고
있었다:

```
# openguild — 내부 캐시 / UI 상태 / 백업 (git 추적 X)
...
# DEV-012: 비공개 메모 (개인 노트)
quests/*.memo.md
# DEV-100: 캠페인 비공개 메모
campaigns/*.memo.md
```

이 파일은 **사용자 저장소에 생성되어 팀과 공유**된다. 두 가지가 문제:

1. **퀘스트 번호** — `DEV-012`/`DEV-100` 은 이 repo 의 이력이라 남의
   길드에서는 의미가 없고, 다른 길드 사용자가 자기 길드 얘기로 오인할 수
   있다(BUG-016 = CLI help leak, DEV-263 = docs leak 과 같은 유형).
2. **한국어** — `init` 을 누가 실행했는지에 따라 팀 공유 파일의 내용이
   달라지는 셈이라 이상하다. gitignore 는 관례상 영어.

## 수정

내용을 ASCII 영어로 교체하고 주석은 "무엇이 왜 제외되는지"만 남김.
메모 2줄은 같은 이유(비공개)라 주석 하나로 합침.

## 전수 확인

`init` 이 실제로 생성하는 파일 전부를 스캔:
`.gitignore` / `statuses/*.toml` 7개 / `types/*.toml` 3개 / index.db /
journal.db. **leak 은 `.gitignore` 하나뿐**이었고 나머지는 깨끗했다.
(소스 주석의 `DEV-xxx` 는 이 repo 에만 남으므로 대상 아님 — 프로젝트
규약상 오히려 권장.)

## 회귀 방지

`gitignore_content_has_no_quest_ids_or_non_ascii` 테스트 추가:
- `<PREFIX 2자+>-<숫자>` 패턴 스캔(정규식 크레이트 없이 수동).
- `is_ascii()` — 한국어뿐 아니라 em dash 같은 비ASCII 도 차단(실제로 이
  테스트가 처음에 내가 쓴 `—` 를 잡아냈다).

## 테스트 방법

1. `cargo test -p openguild-core` — 358건 통과(신규 1건 포함).
2. 실기: 빈 디렉토리에서 `openguild init` 후 `.guild/.gitignore` 확인 —
   퀘스트 번호/한글 없음 확인 완료.

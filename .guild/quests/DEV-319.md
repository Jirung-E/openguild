CLI 에서 매번 길드 "경로"를 넘겨야 하는 게 번거로움 — 길드 "이름"으로도
지정할 수 있게 하고 싶다.

## 배경 조사 (2026-08-01)
- 길드 = `.guild/{name}.guild` 마커(TOML, `GuildFile{name,...}`)를 가진
  디렉터리(`core/src/guild_file.rs`). `find_from`/`find_from_cwd` 로 상위
  디렉터리를 훑어 탐색.
- CLI 는 전역 `--guild <PATH>` 옵션(clap global) 하나로 모든 서브커맨드가
  공통 사용, 값 없으면 cwd 부터 자동 탐색(`cli/src/main.rs` `Backend::new`).
- "최근 접속 길드" 추적 모듈이 이미 있음: `core/src/recents.rs`
  (`~/.openguild/recents.json`, `{path, name, last_opened}` LRU, 최대 10개,
  `list()`/`add()`/`remove()`/`guess_name()` API).
  단, **지금은 GUI 만 이 목록을 채움** — CLI 실행은 recents 를 갱신하지
  않는다는 정책 주석이 `cli/src/main.rs` 에 명시돼 있음("recents는 GUI로
  직접 연 길드만 의미").

## 하고 싶은 것
1. `--guild <값>` 이 경로로 존재/`.guild` 마커 확인에 실패하면, recents
   목록에서 이름 매칭을 시도해 자동으로 경로를 resolve. 새 플래그 없이
   기존 `--guild myproject` 가 그대로 동작하게.
2. 이름이 여러 길드에 중복되면 "여러 개 매칭됨, 경로로 지정하세요" 식
   에러 — 이 경우는 기존처럼 경로를 넘기는 수밖에 없음(불가피).
3. CLI 에서 "최근 접속 길드 목록"을 출력하는 명령 추가 — 기존 컨벤션
   (`backup list`, `template list` 등 명사+동사)에 맞춰 `guild list` 가
   유력 후보. 출력 형식은 "길드이름  경로" 두 컬럼.

## 결정 필요한 것 (미정)
- 정확한 서브커맨드 이름/사용법(`guild list` vs `guild recent` 등).
- CLI 실행도 이제 recents.json 을 갱신하도록 정책을 바꿀지 — 안 바꾸면
  GUI로 한 번도 안 연 길드는 CLI 이름 조회로 못 찾는 모순이 생김.

## 구현 완료 (2026-08-06)

## 결정 (미정이던 것)
- 서브커맨드: `guild list` (제안대로 확정 — backup/template 등과 명사+동사 일관).
- **recents.json 을 CLI 도 갱신하도록 정책을 바꾸지 않았다.** DEV-117 이 "CLI
  활동이 GUI Welcome 의 최근 목록 순서를 흔든다"는 실사고를 고친 결정이라
  뒤집지 않는 게 안전하다고 판단 — 대신 이름 해석은 recents 를 **읽기만**
  한다(그 자체로는 DEV-117 이 막던 "쓰기로 순서가 흔들림" 문제와 무관).
  결과적으로 남는 한계: GUI 로 한 번도 안 연 길드는 CLI 이름으로 못 찾음 —
  경로로 지정하면 항상 동작하니 안내 메시지에 명시.

## 구현
- `core::guild_file::resolve_guild_ref(raw)` 신설 — 경로로 안 풀리면 recents
  에서 이름 매칭. 0개=기존 에러, 1개=경로 반환(단 지금도 유효한지 재확인),
  2개 이상=모호함 에러(매칭된 경로 전부 나열).
- `cli::Backend::new` 가 이 함수를 쓰도록 교체 — 새 플래그 없이 기존
  `--guild <값>` 그대로, 값이 이름이면 자동 resolve.
- `openguild guild list` 신설 — recents 목록을 "이름  경로" 로 출력(+ `--json`).
  Backend/Store 무관 — 특정 길드 없이도 동작(`init`/`docs`/`locale` 와 동일 취급).

## 테스트
- `core::guild_file` 단위 테스트 5건 (경로 직접 지정 / 이름 1건 매칭 / 모호함
  / 미발견 / recents 엔 있는데 파일이 사라진 경우).
  - 구현 중 실사고: 처음엔 `recents::tests` 의 BUG-048 env-lock(Mutex)을
    복제해 별도 인스턴스로 썼는데, 서로 다른 Mutex 라 두 모듈 테스트가 같은
    process-global `OPENGUILD_RECENTS_DIR` 를 동시에 건드려 간헐적 실패가
    남(recents.rs 자체 테스트가 파일 write 실패). `recents::tests::env_lock`/
    `with_env` 를 `pub(crate)` 로 공유하도록 고쳐 해결.
- CLI 파싱 테스트 1건(`guild list`).
- 실행 바이너리로 스크래치 길드 2개 + 손으로 만든 recents.json 으로 단일/
  모호/미존재 케이스 수동 확인.
- `cargo test -p openguild-core --lib` 395/395, `-p openguild-cli` 112/112.

## 테스트 방법
1. GUI 로 길드를 한 번 연 뒤, CLI 에서 `openguild guild list` — 이름+경로가 보이는지.
2. `openguild --guild <그 이름> quest list` — 경로 안 써도 동작하는지.
3. 이름이 같은 길드를 GUI 로 두 개 이상 연 적이 있으면, 그 이름으로 다시
   시도 — "모호함" 에러가 두 경로를 다 보여주는지.

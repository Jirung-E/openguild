윈도우 세션 보고(2026-10-27, BUG-375 · BUG-376 시험 중, 사용자가 연 PowerShell 로 실제 레지스트리 확인).

**증상:** 설정 앱에서 openguild 를 지운 뒤에도 `HKCU\Software\Classes\.guild` 가 남고, 기본값이 방금 지운 `openguild Guild File` 을 가리킨다 — 끊긴 연결. `openguild Guild File_backup` 값도 남는다.

    KEY PRESENT  HKCU\Software\Classes\.guild  [OpenGuild Guild File_backup=openguild Guild File; =openguild Guild File]
    KEY GONE     HKCU\Software\Classes\openguild Guild File

**원인:** 설치 스크립트가 Tauri 의 `FileAssociation.nsh` 를 그대로 쓴다.
- `APP_ASSOCIATE` 는 연결할 때마다 `.guild` 의 지금 기본값을 `<클래스>_backup` 에 적고 자기 것으로 바꾼다. 이미 openguild 가 깔린 위에 다시 깔면(업데이트 · 재설치) 지금 값이 이미 자기 클래스라 **백업이 자기 자신**이 된다.
- `APP_UNASSOCIATE` 는 그 백업을 기본값으로 되돌리고 클래스 키를 지운다 → `.guild` 가 없는 클래스를 가리킨다. `_backup` 값도 안 지운다.
- 값 이름의 대소문자(`OpenGuild …`)는 옛 버전의 철자 — 레지스트리 값 이름은 대소문자를 안 가려 같은 값이다.

**고칠 것:** 설치 스크립트에 자체 매크로를 둔다.
- 연결: 지금 값이 비었거나 자기 클래스면 백업하지 않는다.
- 풀기: `.guild` 가 지금 우리 클래스를 가리킬 때만 손댄다(그사이 다른 앱이 가져갔으면 그대로). 백업이 있고 자기 자신이 아니면 되돌리고, 아니면 기본값을 지운다. `_backup` 값은 지우고, 키가 비면 키도 지운다.

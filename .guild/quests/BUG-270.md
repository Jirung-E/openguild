## 증상

CI 의 **macOS 잡만** `cargo test` 에서 실패한다. 같은 커밋에서 ubuntu 는 통과.

```
---- tests::detects_welcome_placeholder_path stdout ----
panicked at gui/src/lib.rs:794:9: placeholder 자신을 못 알아봄
```

## 원인 — 존재 여부에 따라 답이 달라진다

`is_welcome_placeholder` 는 양쪽을 각각 `canonicalize` 한다:

```rust
let norm = |x| normalize_abs(&fs::canonicalize(x).unwrap_or_else(|_| x.to_path_buf()));
norm(p) == norm(&welcome_placeholder_path())
```

`canonicalize` 는 **경로가 없으면 실패**해서 원문을 그대로 쓴다. 그런데
placeholder 는 `temp_dir()/openguild-welcome-placeholder` — **고정 경로**다.
같은 테스트 바이너리의 `cleanup_removes_leftover_marker_dir` 가 그 디렉터리를
만들고 지운다. `cargo test` 는 병렬이라, 두 `canonicalize` **사이에** 존재
여부가 바뀌면 한쪽만 `/private/var/...` 로 풀리고 비교가 어긋난다.

macOS 만 실패하는 이유는 `/var` → `/private/var` 심볼릭 링크 때문이다.
리눅스의 `temp_dir()` 은 `/tmp` 라 링크가 아니고, 있든 없든 결과가 같다.

## 테스트만의 문제가 아니다

**실제 동작에도 같은 결함이 있다.** `cleanup_welcome_placeholder_leftovers`
는 recents 의 각 항목에 이 판정을 쓴다. recents 에는 경로가 **정규 표기**
(`/private/var/...`)로 저장되는데, 정리 시점에는 placeholder 디렉터리가 이미
없다. 그러면:

- `norm(저장된 항목)` → canonicalize 실패 → `/private/var/...` (저장된 그대로)
- `norm(welcome_placeholder_path())` → canonicalize 실패 → `/var/...`

**두 값이 달라 판정이 false 가 되고, 잔재 항목이 영영 안 지워진다.**
[[BUG-236]] 이 고치려던 바로 그 증상이다.

## 고치는 법

경로 자신이 아니라 **부모(temp_dir)를 정규화**하고 고정된 이름을 붙인다.
부모는 항상 존재하므로 결과가 존재 여부와 무관해진다 — 경합도 같이 사라진다.

## 테스트 방법

`cargo test -p openguild-gui`

새 테스트: `temp_dir()` 의 정규 표기로 만든 같은 경로도 알아보는지. 공유
경로를 만들거나 지우지 않으므로 이 테스트 자신은 경합을 만들지 않는다.
macOS 에서 **옛 코드로는 실패**하고 리눅스에서는 양쪽 다 통과한다(그 차이가
이 버그의 정체다).

재현(2026-07-03 실발생): 릴리즈 과정에서 git checkout master ↔ develop 브랜치 전환 → 모든 quest .md 의 파일 mtime 이 갱신됨 → 직후 첫 CLI 실행에서 drift auto-resync(BUG-080 의 '외부 편집 시 updated_at←mtime 보정')가 200여 개 quest 전부를 '외부 편집됨'으로 오인해 updated_at 을 현재 시각으로 일괄 rewrite. 실제 수정일 정보가 파괴되고 git 에 200+ 파일 노이즈 diff 발생.

이번엔 내용 변경이 없는 순수 오염(1줄 diff)임을 확인 후 git restore + reindex 로 복구했으나, 근본 원인이 남아있어 브랜치 전환/git pull 때마다 재발 가능.

## 원인 분석 방향
- git checkout/pull/restore 는 내용이 같아도 mtime 을 바꿈 — mtime 만으로는 '외부 편집' 판별 불가.
- 보정 조건을 'mtime 변경 AND 내용(해시 또는 파싱 결과) 변경'으로 강화해야 함. 내용이 DB 와 동일하면 updated_at 을 건드리지 말고 file_mtime 기록만 갱신.
- 대량(예: 전체의 절반 이상) 보정이 발생하는 경우는 의심 신호 — 일괄 적용 전 경고/스킵 정책 검토.

관련: BUG-080(보정 도입), BUG-049(auto_resync hook), DEV-121(incremental sync).

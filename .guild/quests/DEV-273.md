# 모바일 앱 (Tauri iOS/Android 네이티브 빌드)

[[DEV-257]](모바일 UI) 1차에서 "반응형 웹 우선, Tauri 모바일 빌드는
후속"으로 분리한 그 후속. 착수 전 조사 결과를 정리해둠 (2026-07-20).

## 아키텍처 결정 (가장 먼저 확정할 것)

**1차는 "원격 클라이언트 전용" 앱을 강력 권장.**
모바일 앱 = openguild-server 에 HTTP 로 붙는 셸. 근거:

- GUI 에 원격 모드가 이미 있음(DEV-113) + 반응형 1차 완료(DEV-257) —
  프론트 코드 재사용률이 매우 높고 스코프가 확 줄어든다.
- 반면 "로컬 길드 온디바이스"는 사실상 별도 프로젝트: 모바일 파일 접근
  모델(Android SAF / iOS 문서 피커·security-scoped bookmark)에선 "임의
  디렉토리의 `.guild` 마커" 개념 자체가 성립하기 어렵고, CLI/서버
  사이드카 동봉 불가, git 연동 부재, 기기↔데스크탑 동기화 스토리까지
  필요. → 장기 백로그로 분리.

## 필요한 것 (요구사항)

- **공통**: Tauri v2 는 iOS/Android 공식 지원. `cargo tauri android init`
  / `cargo tauri ios init` 으로 네이티브 프로젝트(Gradle/Xcode) 스캐폴딩.
- **Android**: Android Studio(SDK+NDK), JDK 17, Rust 타깃
  (`aarch64-linux-android` 등), `ANDROID_HOME`/`NDK_HOME` 환경변수.
  **현 개발환경(Windows)에서 개발/빌드 가능.** 배포 시 keystore 서명,
  Play Console 등록($25 1회) 또는 APK 직접 배포.
- **iOS**: **macOS + Xcode 필수 — Windows 에선 빌드 자체가 불가.**
  실기기 설치/배포엔 Apple Developer Program($99/년). 현 환경에선 CI
  (GitHub Actions macOS 러너) 경유로만 가능 → iOS 는 Android 검증 후
  별도 단계로.
- **CI**: release.yml 에 android job(ubuntu 러너로 가능) 추가.
  iOS 는 macos 러너 + 코드사이닝 시크릿 관리 필요.

## 제한사항 (Tauri 모바일 플랫폼 자체)

- **updater 플러그인 미지원** — 공식적으로 `cfg(not(android/ios))` 로만
  설치하게 안내됨. 모바일 업데이트는 스토어/APK 재배포 경유. DEV-063
  자동업데이트 경로는 전부 데스크탑 한정으로 게이트해야 함.
- **멀티윈도우 불가** — 단일 풀스크린 웹뷰. DEV-255 "자식창으로 열기"
  (`openInWindow`, WebviewWindow) 무의미 → 페이지 이동 폴백 필요.
- 커스텀 타이틀바/창 컨트롤/drag-region 개념 없음(전부 데스크탑 전용).
- WebView 엔진 매트릭스 증가: Android=시스템 WebView(크로미움),
  iOS=WKWebView — WebView2/WebKitGTK 와 또 다른 렌더링 차이 검증 필요.
- Android 네이티브 커맨드는 메인스레드 스케줄링 — 장시간 작업 시 UI
  프리즈/ANR 위험(무거운 invoke 는 spawn 필수).
- 사이드카 바이너리(CLI/서버 동봉) 불가. iOS 백그라운드 실행 제약.

## 기존 구현 영향 (코드 확인 결과)

게이팅만 정확하면 **데스크탑 동작엔 영향 없음** — 전부 "모바일에서 끄기"
방향의 추가 작업:

- `gui/src/lib.rs`: `#[cfg_attr(mobile, tauri::mobile_entry_point)]` 는
  이미 있음(스캐폴드 기본). 단 titlebar 훅(Windows WM_NCHITTEST/Linux
  GTK)·updater 플러그인 등록·번들 docs/skills sync 등 데스크탑 전용
  로직에 `#[cfg(desktop)]` 게이트 필요.
- **프론트 플랫폼 판별 함정(조사 중 발견)**: `platform.ts` 의
  `isMacOverlay()` 가 `ua().includes('Mac')` 인데 **iOS UA 에는 "like
  Mac OS X" 가 포함** → iOS 에서 mac-overlay 커스텀 타이틀바를 그리는
  오판 발생 예정. `usesCustomTitlebar()` 의 Android 제외는 이미 있음
  (`!includes('Android')`) — iOS 제외 추가 필요.
- `ToastHost` 업데이터 watcher: isTauri 면 checkForUpdate 호출 — 모바일
  에서 플러그인 부재. try/catch 는 있어 크래시는 아니지만 명시적 모바일
  게이트가 깔끔.
- `open-item.ts`: `openInWindow` 를 모바일에서 `openInPage` 로 폴백.
  DEV-255 때 예고한 `OpenMode 'mobile'` 확장 지점.
- 터치 인터랙션: DEV-257 에 남긴 후속 목록(보드 드래그/grid snap,
  미리보기 리사이즈 핸들, 크로스링크 호버 미리보기 → 탭 UX)과 합류.
- 설정: `tauri.android.conf.json`/`tauri.ios.conf.json` 플랫폼 conf,
  모바일 아이콘 세트, 딥링크(원격 서버 URL) 검토.

## 규모 추정

- **1차 (Android, 원격 전용)**: 중형 — ①빌드 환경/스캐폴딩 ②데스크탑
  전용 코드 cfg/런타임 게이팅 + platform.ts 판별 정리 ③터치 필수분
  ④서명/CI. 서브퀘스트 3~5개로 분할 권장(또는 캠페인화).
- **iOS 추가**: 소~중형이지만 macOS/계정/심사라는 외부 전제가 지배적.
- **로컬 길드 온디바이스**: 대형(파일 모델 재설계 + 동기화) — 이
  퀘스트 범위에서 명시 제외, 별도 장기 백로그.

## 착수 시 첫 단계

1. 위 아키텍처 결정(원격 전용 1차) 사용자 확정.

   원격 모드 접속 스모크.
3. 발견되는 게이팅 누락을 서브퀘스트로 등록하며 진행.

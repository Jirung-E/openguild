## 전수 조사

[[BUG-252]] 가 팔레트 하나였는데, 같은 부류가 더 있는지 프론트엔드 전체를
훑었다(`@media` 조건과 `var()` 폴백은 제외).

**고정 px 총 849건 / 51개 파일.** 속성별로는:

| 건수 | 속성 | 성격 |
|------|------|------|
| 315 | `border-radius` | 시각만 — 배율에서 살짝 각져 보이는 정도 |
| 281 | `border` | 1px 헤어라인 — 배율에서 얇아 보임 |
| **64** | `width` / `height` / `font-size` / `min-*` / `max-*` | **레이아웃 — 잘림·넘침을 만든다** |
| 나머지 | `padding` / `gap` / `top` / `margin` 등 | 중간 |

곡률·테두리 596건은 **깨지지 않는다** — 토큰(`--r-*`, `--bw`)이 이미 있으니
별도 정리 건으로 남긴다. 이번엔 **레이아웃 64건**만 다뤘다.

## 손대지 않은 것 — 근거

| 대상 | 이유 |
|------|------|
| `html { font-size: 16px }` | **배율의 기준점** — uiScale 이 이 값을 덮어쓴다 |
| 보드 노드 `284×80px` | `BOARD_NODE_WIDTH = 284` **JS 상수와 짝**이다. CSS 만 rem 으로 바꾸면 화살표 기하가 어긋난다([[BUG-242]] 의 그 계산) |
| 타이틀바 창 컨트롤 | 네이티브 크롬 — [[BUG-246]] 결정 |
| `calc(100vw - 16px)` (팔레트/자동완성) | 화면 가장자리 여백은 물리 치수 |
| 1px 구분선 / 스크롤바 폭 | 헤어라인·물리 치수 |

## 고친 것 (19곳)

**팔레트와 같은 부류 — 팝업/드롭다운**

- `LinkPreviewPopup` `min(400px, 90vw)` → `min(25rem, 90vw)`, `max-height 260px` → `16.25rem`
- `QuestCombobox` / `CampaignCombobox` `min(70vh, 600px)` → `min(70vh, 37.5rem)`

**편집기·카드·필터**

`MarkdownEditor` 200px, `QuestNoteSection` 120/2000px, `CampaignCard` 180px,
`NewQuestModal` 80px×2, `BacklinkSection` 17px/10px, `QuestListItem` 20px,
`QuestListFilter` 20px, `campaigns/new` 760/120px, `library` 92px,
`quests/[id]` 160/180px, `worklog` 220px.

`NewQuestModal` 의 `calc(... + 2px)` 는 테두리라 `var(--bw) * 2` 로.

전부 **기본 배율에서 같은 값**이 되도록 환산했다(100% 에서 변화 없음).

## 검증

`max-height` 가 배율을 따라가는 것을 실측했다 — 340 → 510 → 680px.

폭은 이번에 재지 못했다. 브라우저 창이 숨겨져 `innerWidth: 0` 이 되고,
`min(35rem, 62vw)` 의 vw 항이 0 이라 측정이 무효가 된다(이 환경의 알려진 제약).
BUG-252 에서 1920px 화면으로 이미 실측한 값(280/560/840/1120)이 그대로
적용된다 — 이번 변경은 같은 형태의 다른 컴포넌트들이다.

**팝업·콤보박스는 실제로 열어 보지 못했다** — 호버/포커스가 필요해 숨겨진
창에서는 띄울 수 없었다. CSS 는 팔레트와 동일한 형태다.

`just test` 515건, svelte-check 0 errors, `check:no-hex` 통과.

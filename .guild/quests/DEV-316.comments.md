## 방향 전환 (2026-08-01, 9차 — 사용자 지적: "유예시간 늘리는 건 느린 걸
숨기는 거지 고치는 게 아니다")

정확한 지적 — 지금까지(5~8차)의 "제스처 중 캔버스 안 건드리고 CSS
transform으로 흉내내다 끝나면 실제로 반영" 접근 전체가 "지연을 어떻게

빠르게** 만드는 것.

## 가설

노드 배경(makeSvgUrl 이 만드는 SVG data-URI, BUG-057 로 pixelRatio 2~3배
해상도)을 cytoscape 캔버스가 처음 그릴 때 브라우저가 그제서야

디코딩 비용이 몰려 눈에 띄게 느린 것으로 추정.

## 수정

- `makeSvgUrl()` 이 SVG data-URI 를 만드는 시점(퀘스트 로드/노드 생성/

  = url` 로 미리 디코드를 걸어 브라우저 캐시를 데워둠. 모든 노드가
  로드되는 시점에 다 도는 거라, 실제로 그 노드가 화면에 들어올 때는
  이미 디코드가 끝나 있을 것으로 기대.
- DEV-316(5~8차)에서 넣었던 CSS transform + cy.png() reveal 메커니즘
  전부 원복 — 다시 BUG-144 원안(rAF 배칭 + cy.zoom()/panBy() 직접 호출)
  으로. 한 손가락 드래그와 동일한 경로.

## 근본 재설계 (2026-08-01, 11차 — 사용자 제안: "유예시간 추측 대신 주기

Quest type / status 의 추가 · 수정 · 삭제를 GUI Admin 페이지에서 가능하게.

## 현재 상태

### Type
- 정의: `.guild/types/<PREFIX>.toml`
  ```toml
  prefix = "DEV"
  color = "#4A90D9"
  description = "일반 개발 작업"

  [counter]
  last_number = 50
  ```
- CLI: `openguild types` — **list 만** (`name_en/name_ko`, prefix, color).
- GUI: meta API `list_quest_types` — board 의 column header 색 / quest
  카드 prefix 표시에 사용. 관리 UI 없음.
- 추가/변경/삭제 방법: `.toml` 파일 직접 편집 → reindex 필요 (currently
  reindex 는 GUI Admin 에 있음).

### Status
- 정의: `.guild/statuses/<sort_order>-<slug>.toml`
  ```toml
  sort_order = 1
  name_en = "Open"
  name_ko = "게시됨"
  color = "#8B95A1"
  ```
- CLI: `openguild statuses` — list 만.
- GUI: meta API `list_quest_statuses` — board 의 column 정의 / status
  badge 색에 사용. 관리 UI 없음.
- 추가/변경/삭제: 파일 직접 편집 + reindex.

## 요구사항

Admin 페이지 (`/admin`) 에 두 섹션 추가:

1. **Quest Types**
   - 표: prefix / color (swatch + hex) / description / 사용 중인 quest 수
     (참고용, count from list_quests group by type).
   - 액션: 추가 / 수정 (color / description) / 삭제.
   - 삭제 가드: 해당 prefix 를 쓰는 quest 가 있으면 차단 (에러 메시지).
   - prefix 자체 rename 은 quest 들의 slug 가 다 바뀌므로 **이번 quest
     범위 외** — disabled / 별도 quest.
   - 추가 시 prefix validation: 대문자 + 숫자, 3~6자 (자기 컨벤션) +
     중복 거부.

2. **Quest Statuses**
   - 표: sort_order / name_en / name_ko / color swatch / 사용 중 quest 수.
   - 액션: 추가 / 수정 (이름 / 색 / sort_order) / 삭제 + drag-and-drop
     reorder (또는 sort_order 직접 입력으로 단순화).
   - 삭제 가드: 그 status 의 alive quest 가 있으면 차단.
   - **slug** (name_en 기반 normalized) 는 DEV-049 가 history /
     positions 의 참조 키로 사용 — rename 시 slug 도 바뀌면 history 가
     깨질 수 있으므로:
     - 추가/삭제만 우선, name 수정은 `name_ko` / `name_en` display only
       (slug 는 별도 column 으로 frozen).
     - 또는 rename 시 history 의 status_slug 도 migrate (별도 quest 후보).

## 구현 스케치

### Backend (core + gui)
- **`repo::types`** (현재 read 만) 에 write API:
  - `create_type(store, prefix, color, description?)` — 파일 write +
    types row insert.
  - `update_type(store, prefix, color?, description?)` — 파일 rewrite +
    types row update.
  - `delete_type(store, prefix)` — 사용 중 quest 있으면 `Err` (count > 0).
    파일 삭제 + types row delete.
- **`repo::statuses`** 동일 패턴: `create_status` / `update_status` /
  `delete_status`. sort_order 변경 시 파일 이름 (`<sort_order>-<slug>.toml`)
  도 rename.
- Tauri commands: `admin_*` prefix 로 8개 신설
  (`admin_create_type` / `admin_update_type` / `admin_delete_type` +
   `admin_create_status` / `admin_update_status` / `admin_delete_status` +
   `admin_count_quests_by_type` / `admin_count_quests_by_status`).

### Frontend
- `/admin/+page.svelte` 에 `<section class="types">`, `<section
  class="statuses">` 추가.
- 각 row: inline 수정 모드 (color picker / text input) + 삭제 버튼.
- "+ 새 type / status" 모달 (NewQuestModal 패턴 재사용).
- 색 입력은 `<input type="color">` + hex text 양방향.

### Migration / 호환성
- 기존 DB schema 변경 없음 — 파일 + 기존 reindex 흐름 그대로.
- mutation 후 자동 reindex 트리거 (또는 in-place update + 파일 rewrite).

## UX

- 삭제 가드 에러는 모달 / 알림 ("이 type 을 쓰는 quest 5개가 있어 삭제할
  수 없습니다. 먼저 다른 type 으로 이동시키세요.").
- 색 변경은 즉시 보드 / 카드에 반영 (Admin 떠나서 보드 가면).
- 추가한 type 이 NewQuestModal 의 dropdown 에 자동 노출 (이미 meta API
  cache 안 함, 매번 fetch).

## 검증

- 새 type 추가 → 보드에 column / NewQuestModal dropdown 에 노출.
- 사용 중 type 삭제 시도 → 에러 + 차단.
- 사용 안 하는 type 삭제 → 파일 + DB 둘 다 제거.
- status sort_order 변경 → 보드 column 순서 즉시 변경.
- status 색 변경 → 카드 badge 색 즉시 변경.

## 후속 (이 quest 범위 외)

- **Type prefix rename** — 모든 quest 의 slug + history / positions /
  파일명 cascade. 별도 quest.
- **Status slug rename + history migrate** — DEV-049 의 quest_history /
  positions 의 status_slug 컬럼 마이그레이션 동반.
- HTTP server 도 동일 mutation API (현재는 read-only types/statuses).

## 왜

지금 있는 `reference/plugins.md` 는 **사용법**이다 — 필드가 뭐고 명령이 뭔지.
"플러그인 만들어줘" 를 받은 에이전트에게 필요한 건 **제작 절차**다: 무엇을 먼저
물어야 하고, 어떤 순서로 결정하고, 무엇을 확인한 뒤에 건네주는가.

admin 확정: 별도 스킬로 신설(`skills/openguild-plugin/skills/openguild-plugins/`).
길드 작업만 하러 온 에이전트가 플러그인 제작 절차를 통째로 읽게 되면 안 된다.

## 스킬이 담아야 할 것

- **순서를 강제한다.** JSON 부터 쓰는 것이 흔한 실패다. 이벤트 → scope →
  post/run → 스크립트 필요 여부 → 비밀값 자리 순으로 각 단계가 "못 만드는
  플러그인" 을 하나씩 걸러낸다.
- **비밀값이 어디로 가는지** 세 자리(url / 헤더 / `body_env`)를 표로.
  `body_env` 가 왜 있는지도 — 스크립트에 I/O 가 없는 것은 구멍이 아니라 설계다.
- **건네주기 전에 반드시 검증.** 대역 서버 레시피를 스킬 안에 넣는다. 진짜
  서비스로 첫 시험을 하면 안 된다.
- **음성 케이스도 확인한다.** 한 번도 거르지 않는 필터는 필터가 아니다.
- **안 나갈 때 어디부터 보는지** 순서대로.

## 테스트 방법

- 스킬의 검증 레시피를 **그대로 따라** 플러그인을 하나 만들어 본다. 문서가
  틀렸으면 거기서 드러난다.
- 스킬이 발견 가능한지 검사로 고정 — `SKILL.md` 가 없거나 frontmatter 의
  `name` 이 폴더와 어긋나면 그 스킬은 **조용히 없는 것**이 된다.

## 결과

`skills/openguild-plugin/skills/openguild-plugins/SKILL.md`. 기존 `openguild`
스킬과 형제로 두었다 — 길드 작업만 하러 온 에이전트가 제작 절차를 통째로 읽을
이유가 없다.

### 스킬을 그 스킬대로 써서 검증했다

문서만 쓰고 넘기면 틀린 줄 모른다. 스킬의 "Verifying" 절을 **그대로 따라**
플러그인을 하나 만들었다 — 미해결 토론 댓글만 밖으로 보내는 것.

```
음성 케이스(평범한 댓글) → 0건
양성 케이스(미해결 토론) → POST /hook
  {"author":"kim","quest":"DEV-001","question":"이 방식 맞나요?"}
```

레시피가 그대로 통했다. 그 과정에서 만든 것을 **네 번째 예제**로 넣었다
(`examples/plugins/discussion-to-ai`) — 비밀값이 **헤더**로 가는 유일한 예이고,
텔레그램 예제(url + `body_env`)와 짝이 된다.

### 스킬이 사라지는 것을 검사로 막았다

스킬은 `skills/*/SKILL.md` 로 **발견**된다. 폴더 이름을 바꾸거나 frontmatter 의
`name` 이 폴더와 어긋나면 그 스킬은 **조용히 없는 것**이 된다 — 에이전트는
"그런 기능 없다" 고 답하고 아무도 오류를 못 본다. `shipped_skills_are_discoverable`
가 둘의 존재·frontmatter·설명 길이를 본다.

되돌림 시험 2건: 스킬 폴더 이름 어긋내기 · 예제 스크립트 깨뜨리기.

### 스킬이 강제하는 것

순서다. **JSON 부터 쓰는 것이 흔한 실패**라, 이벤트 → scope → post/run →
스크립트 필요 여부 → 비밀값 자리 순으로 각 단계가 "못 만드는 플러그인" 을
하나씩 걸러낸다. 그리고 **건네주기 전에 반드시 검증**하되 진짜 서비스가 아니라
대역 서버로 하고, **음성 케이스도 본다** — 한 번도 거르지 않는 필터는 필터가
아니다.

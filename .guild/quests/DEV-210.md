restore --at 최신 복원 시 9999-12-31T23:59:59Z 같은 먼 미래 시각을 넣어야 해서 불편 → `latest` 키워드. DEV-022(journal replay) 후속 UX.

## 구현 (2026-07-04)
- `resolve_at_keyword` (cli): `latest`(대소문자 무시) → 먼 미래 ISO 치환, 그 외 passthrough(검증은 core replay). 단위 테스트 5케이스.
- 출력 분기: latest 는 무손실(상태 동일)이라 '✓ 최신 상태로 복구: 최신 스냅샷 + journal op N 개 재적용' — 과거 시점 복원의 '이후 변경 폐기' 경고 미출력. --json 에 "latest": true 필드.
- --at help 문구 + restore-behavior 길드 규칙 + AGENTS_OPENGUILD_USAGE §2.8 에 latest 반영.
- HTTP admin 라우트는 미변경 — 키워드 해석은 CLI 책임(원격 CLI 도 CLI 단에서 치환돼 서버엔 ISO 로 전달됨).

## 테스트 방법
- `cargo test -p openguild-cli resolve_at_keyword` 통과.
- 실기(스크래치 길드): quest 생성 → backup new → quest 수정 → `restore --at latest` → '최신 상태로 복구' 문구 + 상태 유지(무손실) + journal 비워짐. `restore --at LATEST`(대문자) 동일. 일반 ISO 시점 복원 회귀(경고 문구 유지).

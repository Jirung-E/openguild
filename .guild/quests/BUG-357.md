admin: "다른창에 있다가 보드로 올때 접은 레인이 잠깐 보이는 문제가 있음" — 윈도우 앱, 앱 안의 다른 페이지에 갔다 올 때.
"접힌 레인이 펼쳐진 상태에서 내부 노드가 보였다가, 바로 정상화됨". 이후 "더이상 발생하지 않는다".

## 원인

상단 바 "다시 색인" 의 신호(`reindexBump` store)는 앱이 켜져 있는 동안 값이 남는다. 그런데 보드 · 퀘스트 목록 · 홈은
"마지막으로 본 값" 을 **0 에서 시작**한다(`let lastReindexBump = $state(0)`). 그래서 한 번이라도 다시 색인을 누른 뒤에는
그 화면에 들어올 때마다 "새로 색인됐다" 로 보고 데이터를 **한 번 더** 불러온다.

앱(Tauri)에서는 보드의 정식 적재가 길드 경로를 물어본 뒤(비동기) 접은 레인 등 길드별 설정을 읽는데, 이 추가 적재는
그보다 먼저 그려서 **접은 레인이 펼쳐지고 그 안 노드까지 보인다** → 곧 정식 적재가 다시 그려 정상화. 앱을 다시 켜면
신호가 0 이라 안 생긴다 — "더이상 발생하지 않는다" 와 맞는다.

재현(헤드리스 WebKit, 가짜 Tauri · 완료 · 취소됨 접힘): 다시 색인 안 누르면 첫 프레임부터 정상(노드 71). 다시 색인을
한 번 누른 뒤 목록 → 보드: 145ms 에 레인 전부 펼침 · 노드 822 → 206ms 에 정상.

## 고칠 것

세 화면이 "마지막으로 본 값" 을 들어올 때의 store 값으로 시작한다 — 들어온 뒤의 다시 색인에만 반응한다.

## 고침 (2026-10-11)

보드 · 퀘스트 목록 · 홈이 "마지막으로 본 값" 을 **들어올 때의 store 값**(`get(reindexBump)`)으로 시작한다 — 들어온 뒤에
일어난 다시 색인에만 반응한다. 목록 · 홈은 눈에 띄는 증상은 없었지만 같은 이유로 들어올 때마다 두 번 불러오고 있었다.

확인(헤드리스 WebKit, 가짜 Tauri): 다시 색인 → 목록 → 보드에서 첫 프레임부터 정상(노드 71, 펼쳐진 프레임 없음).
보드에 있을 때 다시 색인을 누르면 여전히 새로 불러온다(`/api/quests` 등 다시 요청). `just test` 통과.

## 테스트 방법

1. 앱에서 보드의 완료 레인을 접는다.
2. 상단 바 "다시 색인" 을 누른다.
3. 퀘스트 목록 → 보드를 여러 번 오간다 — 접힌 레인이 한 번도 펼쳐지지 않는다.
4. 보드에 있을 때 다시 색인을 누르면 보드가 새로 불러와진다(원래 기능).

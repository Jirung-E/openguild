DEV-012 에서 만든 댓글은 단일 markdown 파일 통째 편집 모델이라 "댓글 하나밖에 못
쓴다" 는 사용자 피드백이 있었음. GitHub 식으로 entry 단위 (작성 시각 / 작성자 /
개별 본문) 로 분리해서 추가 / 수정 / 삭제가 각각 가능하도록.

## 설계

### 저장 형식 (단일 파일 + 마커)
- 파일: `.guild/quests/{slug}.comments.md` (그대로 — git tracked).
- 각 entry 는 HTML 주석 마커로 시작:
  ```
  <!-- og-comment id="1" ts="2026-06-02T01:23:45+09:00" author="" -->
  본문 markdown — 여러 줄 가능.

  빈 줄도 가능.
  <!-- og-comment id="2" ts="2026-06-02T01:24:00+09:00" author="alice" -->
  다음 댓글.
  ```
- entry body = 자신의 마커 다음 줄부터 다음 마커 직전 (또는 EOF) 까지, 앞뒤 공백 trim.
- 마커 없는 기존 파일은 "legacy 단일 entry" 로 자동 인식 (id=1, ts=파일 mtime
  대신 현재 시각, author="", body=파일 본문 전체) — 첫 mutation 시 정식 마커
  포함으로 재serialize.

### Rust
- `core::repo::comments::CommentEntry { id, ts, author, body }`.
- `parse_entries(text) -> Vec<CommentEntry>` / `serialize_entries(&[CommentEntry]) -> String`.
- `read_entries(paths, slug) -> Vec<CommentEntry>` / `write_entries(paths, slug, &entries)`.
- 기존 raw 텍스트 API (`read_comments` / `write_comments`) 는 deprecate 가능 — 일단
  유지하고 새 API 와 공존. memo 는 그대로 raw text (개인 메모는 entry 단위 불필요).
- `core::services::comments::{list_entries, add_entry, update_entry, delete_entry}`:
  - `list_entries(store, slug) -> Vec<CommentEntry>` — file read + parse.
  - `add_entry(store, slug, author, body) -> CommentEntry` — id = max+1, ts = now.
  - `update_entry(store, slug, id, body) -> CommentEntry` — find by id, body 만 교체
    (ts/author 보존).
  - `delete_entry(store, slug, id)` — 해당 entry 제외 후 재기록.
- `core::ops::comments::*` — journal append 래퍼.

### HTTP / Tauri
- `GET /api/quests/by/{slug}/comments` 응답 변경:
  `{ "entries": [{id, ts, author, body}, ...] }` (구 `{ "content": ... }` 형식 폐기).
- `POST /api/quests/by/{slug}/comments` body `{ author?, body }` → 새 entry.
- `PATCH /api/quests/by/{slug}/comments/{id}` body `{ body }`.
- `DELETE /api/quests/by/{slug}/comments/{id}`.
- 메모 (`/memo`) 는 그대로 단일 텍스트 — 변경 없음.

### Frontend
- 새 컴포넌트 `QuestCommentsSection.svelte` — entry 목록 표시, 각 entry 마다
  편집/삭제 버튼, 하단에 "댓글 추가" 입력 + 저장.
- 기존 `QuestNoteSection mode="comments"` 사용 위치를 `QuestCommentsSection` 으로 교체.
- 메모는 `QuestNoteSection mode="memo"` 그대로.

## 답글 (DEV-094 후속 — 같은 working tree)

사용자 요구: "댓글에 답글도 달 수 있어야함" — 별도 quest 없이 즉시 통합.

### 데이터 모델
- `CommentEntry.parent_id: Option<u64>` — 답글의 경우 부모 entry id.
- 마커 attr 에 `reply_to="N"` 추가 (없으면 top-level). 파서가 추출, 직렬화기가 출력.
- 1-level threading — 답글의 답글도 동일 root 의 직접 자식으로 flatten (GitHub
  PR 댓글 모델).

### Rust
- `services::add_entry(slug, author, body, parent_id)` — `parent_id` 가 Some 인데
  현존 entry 셋에 없으면 `BadRequest`.
- `ops::add_comment_entry(slug, author, body, parent_id)` — journal 에 parent_id
  포함.

### HTTP / Tauri
- `POST /api/quests/by/{slug}/comments` body `{ author?, body, parent_id? }`.
- Tauri `add_comment(slug, author, body, parentId)`.

### Frontend
- `commentsApi.addComment(slug, body, author, parentId?)`.
- `QuestCommentsSection` 의 entry 마다 "↩ 답글" 버튼 → inline form (작성자 옵션
  + body + 저장 / 취소). parent_id 자동 채움.
- 표시: root + 자식 reply 들을 indent + 좌측 border 로 thread 형태.
- 부모 삭제 시 자식은 살아남되 "↩ 삭제된 댓글에 대한 답글" 섹션으로 분리 표시.

### 테스트
- `repo::comments`: parse `reply_to` 마커, top-level 은 None, serialize roundtrip
  (3개 entry 중 1개 reply).
- `services::comments`: `reply_links_parent_id_and_round_trips`,
  `reply_to_nonexistent_parent_rejected`.
- 전체 `cargo test -p openguild-core --lib comments`: 19 passed.

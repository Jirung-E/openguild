## 왜

[[DEV-382]] 가 "리뷰에 프런트엔드 관점이 아예 없었다" 는 걸 드러냈다. 시각 ·
상태 · i18n · 접근성 4개 관점으로 플러그인 설정 화면을 다시 봤고 23건이 나왔다.
중복을 합치면 15건쯤이다.

## 제일 큰 것 — 힌트 문단이 통째로 스타일이 안 먹었다

`.scale-hint` 의 규칙이 **`.ui-scale .scale-hint` 하나뿐**이다. 그 조상 클래스가
없는 플러그인 탭에서는 아무것도 안 먹어서, 안내문이 본문 크기(1rem) 그대로에
여백 없이 붙어 나온다 — admin 스크린샷에 그대로 찍혔다.

[[DEV-382]] 에서 만든 `check:classes` 도 이건 못 잡는다. **정의가 있긴 있기
때문**이다. "쓰였지만 그 요소에는 절대 안 맞는 selector" 는 다른 검사가 필요하다.

## 그 외

- **한국어만 나오는 문장**이 영어 UI 에 섞인다. `notes` 와 적재 오류가 Rust 에서
  한국어로 만들어져 그대로 렌더된다.
- **길드를 안 연 상태**에서 "플러그인이 없습니다. .guild/plugins/… 에 정의하세요"
  와 "조회만 가능합니다" 가 동시에 뜬다 — 둘 다 그 상황에서 틀린 말이다.
- **조회가 실패하면 목록이 통째로 사라지고** "다른 기계에서 하세요" 로 바뀐다.
  데스크톱 앱 안에서 데스크톱 앱을 쓰라고 한다. 다시 시도할 방법도 없다.
- **첫 진입에 안 불러온다** — 탭 버튼 onclick 에만 걸려 있어서, 다른 경로로
  들어오면 빈 화면이다.
- **이름이 겹치면 화면이 깨진다** — `{#each}` 키가 `p.name` 인데 중복을 아무도
  안 막는다. 폴더를 복사하고 이름을 안 고치는 건 흔한 실수다.
- 스크립트가 코드 글꼴을 안 따른다. 길면 상한 없이 늘어나 허용 버튼을 밀어낸다.
- 전달 실패 메시지에 URL 이 들어가면 잘려서 **정작 이유가 안 보인다**.
- 접근성: 스크립트 펼침 버튼에 `aria-expanded` 없음, 버튼 이름이 전부 같음,
  동작 후 포커스가 `<body>` 로 날아감.

## 테스트 방법

- 힌트가 다른 탭과 같은 크기·색으로 나온다.
- 길드를 안 연 상태에서 모순된 안내가 안 뜬다.
- 조회가 실패해도 직전 목록이 남고 다시 시도할 수 있다.
- 이름이 겹친 플러그인이 있어도 화면이 안 깨진다(적재에서 걸린다).

## 결과

UI 리뷰 23건 중 중복을 합쳐 **13건**을 고쳤다.

| | 무엇 |
|---|---|
| HIGH | `.scale-hint` 를 조건 없이 먹게 했다. 규칙이 `.ui-scale .scale-hint` 하나뿐이라 그 조상이 없는 플러그인 탭에서는 안내문이 본문 크기 그대로에 여백 없이 나왔다 — admin 스크린샷 그대로다 |
| HIGH | 길드를 안 연 상태를 **문장이 아니라 `no_guild` 플래그**로 넘긴다. Rust 가 만든 한국어가 영어 UI 한가운데 그대로 렌더됐다 |
| HIGH | 스크립트 펼침 버튼에 `aria-expanded` / `aria-controls`. 이 화면의 존재 이유가 "무엇에 동의하는지 보여주는 것" 인데 그게 스크린리더에 안 전달되면 동의가 형식만 남는다 |
| MED | 조회가 실패해도 **직전 목록을 안 지운다**. 예전엔 목록이 통째로 사라지고 "다른 기계에서 하세요" 로 바뀌어, 데스크톱 앱 안에서 데스크톱 앱을 쓰라는 화면이 됐다 |
| MED | 첫 진입에 `$effect` 로 불러온다(탭 버튼 onclick 에만 걸려 있었다) + 실패 시 "다시 시도" 버튼 |
| MED | **이름이 겹치면 적재에서 거른다.** 동의도 화면도 이름으로 구분하는데 둘이면 알 수 없고, `{#each}` 키가 이름이라 화면이 통째로 깨졌다 |
| MED | 길드 미개방 상태에서 "플러그인이 없습니다 … 정의하세요" 와 "조회만 가능합니다" 가 함께 뜨던 것 — 그 상황에서 둘 다 틀린 말이다 |
| MED | "조회만 가능합니다" 를 **답을 받은 뒤에만** 띄운다. 로컬 데스크톱에서도 잠깐 스쳐 지나갔다 |
| MED | 스크립트·목적지에 `--font-mono`. 코드 글꼴 설정을 앱의 모든 mono 표면이 따르는데 정작 "읽고 동의하라" 는 화면만 안 따랐다 |
| MED | 스크립트에 `max-height` — 길면 허용 버튼을 화면 밖으로 밀어냈다 |
| MED | 전달 실패 줄에 `flex-wrap` + `overflow-wrap` — URL 이 들어가면 잘려서 **정작 이유가 안 보였다** |
| MED | 버튼 이름에 플러그인 이름을 붙였다. 플러그인이 셋이면 "허용" 버튼 셋의 접근성 이름이 전부 같았다 |
| LOW | 목록 본문 0.875rem(다른 절과 맞춤) · `scope:` 하드코딩 제거 · `pluginBusy` 를 집합으로 · 신뢰 중 철회 불가 이유를 `title` 로 · 허용/철회 성공 토스트 |

## 이건 검사로 못 막는다

[[DEV-382]] 의 `check:classes` 는 **정의가 아예 없는** 클래스만 잡는다.
`.scale-hint` 는 정의가 있긴 있었다 — 그 요소에 안 맞았을 뿐이다.

"자손 selector 로만 정의된 클래스" 를 잡아 볼까 해서 전수 조사했더니 **239건**이
나왔다. 이 저장소에서 자손 selector 로만 칠하는 것은 **정상 관용구**다
(`.upd .btn-primary` 등). 검사로 만들면 소음만 남는다.

그래서 이 결함 종류는 여전히 눈으로 잡아야 한다. 되돌림 시험에서도 확인했다 —
`.scale-hint` 를 `.ui-scale` 밑으로 되돌려도 `svelte-check` 는 0 errors 다.

## 안 고친 것

- **적재 오류·전달 실패 문구가 Rust 에서 한국어로 온다.** `tf!` 로 감싸면
  되지만 core/cli/server 전반의 메시지 정책이라 여기서 건드릴 범위가 아니다.
- **`ConfirmDialog` 의 포커스 가둠** — 대화상자가 떠도 포커스가 뒤 페이지에
  남는다. 앱 전체가 쓰는 공용 컴포넌트라 별도로 다뤄야 한다.
- 동작 후 포커스 되돌리기(성공 토스트로 알림은 넣었다), 라이브 리전, 신뢰
  상태에서 안내문과 소개문이 서로 모순되는 문구.

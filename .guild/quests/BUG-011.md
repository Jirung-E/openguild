`openguild quest status DEV-XXX <same>` 를 이미 그 상태인 quest 에 실행하면
no-op 인데도 `quest_history` 에 `Testing → Testing` 같은 무의미 행이 남고
`updated_at` 도 바뀜.

## 원인

`core::ops::quests::change_status` 가 현재 상태와 요청 상태를 비교 안 함 →
journal append → SQL UPDATE (updated_at 갱신) → history INSERT 가 항상 수행.

## 수정 (2026-05-22)

### Backend
`change_status` 진입 직후, 현재 quest 의 `status_id` 를 `quest_statuses` 와
JOIN 으로 한 번에 조회 (`status_id`, `slug` 동시). 요청 `status_id` 와 같으면
즉시 `sql::fetch_by_id` 로 현재 quest 반환 — journal / SQL UPDATE / history
모두 skip.

부수 효과:
- old_status_slug 조회를 두 번 → 한 번으로 줄임 (current 조회 시 함께 fetch).
- quest 부재 시 (`fetch_optional` → None) 는 비교 false → 기존 코드 경로로
  진입 → `sql::change_status` 가 NotFound 반환 (회귀 없음).

### CLI 피드백 (testing 반려 후 추가)
backend 만 고치면 사용자 입장에선 "명령이 정상 수행된 것처럼" 보이는 문제 →
CLI 가 backend 호출 **전** 에 현재 상태를 조회하여 같으면 명시 출력:
```
$ openguild quest status BUG-011 in_progress
(이미 In Progress 상태입니다 — 변경 없음)
BUG-011    [In Progress] ...
```
`In Progress` 부분은 status.color 로 컬러 (TTY 시).

대상 명령 4 곳:
- `quest status <slug> <status>` (명시 변경)
- `quest start` / `quest done` / `quest reopen` (alias)

모두 새 helper `change_status_with_noop_notice` 로 집약.
JSON 모드 (`--json`) 에선 quest 본문은 stdout, no-op 마커는 stderr
(`{"noop":true,"reason":"already in status",...}`) — agent 파싱 친화.

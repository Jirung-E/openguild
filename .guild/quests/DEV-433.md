[[DEV-430]] 의 4단계 — **문서 번호**.

- 문서 파일(frontmatter)에 `version = N`. openguild 가 고칠 때마다 1 올린다. 없으면 0 으로 본다(옛 파일).
- 이벤트에 싣는다 — 훅이 "v8 을 이미 봤으니 늦게 온 v7 은 버린다" 를 판단한다. 프로세스가 다르면 도착 순서를
  보장할 수 없으므로(지금도 그렇다) 순서는 번호로 안다.
- **"바뀌었나" 판단에는 쓰지 않는다**([[REQ-036]] — 밖에서 파일을 고치거나 git 병합으로 번호가 안 맞을 수
  있다). 그건 변경 종류별로 한다(본문은 출발 원문 비교 — [[REQ-024]]).
- 사이드카(댓글 · 이력)는 본문과 같은 문서로 보고 번호를 하나로 쓸지, 따로 둘지 정한다.

## 정한 것 (2026-10-01, admin)

- 사이드카는 **따로** 센다 — 댓글을 달 때 본문 파일을 다시 쓰지 않는다(git 변경 · 병합 충돌을 줄인다).

## 한 것

- `repo/version.rs` — 번호를 **글자 수준에서만** 적고 읽는다. 퀘스트 · 캠페인 · 도서관 문서 · 규칙은 frontmatter 의
  `version = N`, 퀘스트 · 캠페인 댓글은 첫 줄 `<!-- og-comments version="N" -->`. 파일 모델 구조체는 번호를
  모른다 — TOML 은 모르는 키를 건너뛰고, 옛 댓글 파서는 첫 마커 앞을 무시하므로 **옛 openguild 도 새 파일을
  읽는다**(구조체 57곳을 안 고쳐도 됐다).
- 쓸 때 번호는 **파일이 정한다**: 지금 파일의 번호를 읽어, 내용이 그대로면 쓰지 않고(번호 · mtime 그대로),
  다르면 하나 올린다. 번호 없는 옛 파일은 0 — 내용이 그대로면 손대지 않는다.
- 이벤트에 `version` — 바뀐 뒤 · 성공한 이벤트만. `Store::emit` 이 대상으로 파일을 찾아 읽는다(잠금을 쥔 채
  내므로 방금 쓴 번호). `comment.*` 는 댓글 파일 번호.
- 번호가 없는 것: 첨부 목록(JSON 배열이라 자리를 만들려면 형식을 바꿔야 한다 — 옛 openguild 가 못 읽는다),
  비공개 메모, 일지 노트, 바뀌기 전 이벤트.
- **타입 바꾸기**(DEV-1 → BUG-1)가 파일을 새 이름으로 **옮긴 뒤** 쓴다 — 번호가 이어진다. 덤으로 **태그가
  사라지던 것**도 고쳐졌다(새 경로에 새로 써서 옛 파일의 태그를 못 읽었다 — develop 에서 확인: `tags=[]`).
  댓글 · 메모 · 첨부 파일이 옛 이름에 남는 것은 따로 — BUG-343.
- 문서: USAGE(플러그인 쪽 — 늦게 온 알림 거르기), BOOK-006(파일 형식), BOOK-007(이벤트).

## 시험

- 번호가 바뀔 때만 오르고, 같은 내용이면 파일을 안 쓴다 / 옛 파일은 0 이고 손대지 않는다 / 넘겨받은 내용의
  번호는 무시한다 / frontmatter 없는 규칙에도 붙는다 / 댓글 첫 줄 번호가 댓글로 읽히지 않는다.
- 이벤트: 만들기 1, 고치기 2, 댓글 1 · 2(본문 번호와 따로), 첨부 · pre 는 없음, 플러그인 JSON 에 `version`.
- 타입 바꾸기가 번호와 태그를 이어 간다(고치기 전: 번호 2 → 1, 태그 사라짐).
- 사본 길드 CLI: 본문 `version = 2`, 댓글 파일 `version="2"`, 다시 색인 뒤에도 댓글 그대로.

## 테스트 방법

1. 앱에서 퀘스트 하나를 만들고 제목을 한 번 고친다 → 파일 맨 위에 `version = 2` 가 보이면 정상.
2. 그 퀘스트에 댓글을 둘 단다 → 댓글 파일 첫 줄이 `version="2"` 이고, 본문 파일은 여전히 `version = 2` 면 정상.
3. 그 퀘스트의 타입을 바꾼다(DEV → BUG) → 새 이름 파일의 번호가 3 이고 태그가 그대로면 정상.

## 무엇

`plugin.json` 을 TOML 로 바꾸고, 정의를 `[[handlers]]` 줄 목록으로 만든다([[BOOK-004]] "줄 단위 핸들러").

## 할 것

- 줄마다 단계 `pre` / `post` 중 **하나**, 동작 `call`(스크립트 함수) / `action`(`post`·`run`) 중 **하나**, 이름 `id`.
- 한 플러그인에서 액션 줄과 스크립트 줄을 섞을 수 있다. `call` 이 없으면 `scripts` 는 필요 없다.
- 한 이벤트에 여러 줄이 걸리면 **적힌 순서대로** 실행.
- 불러올 때 검사 — 단계·동작 누락/중복, 스크립트에 없는 함수, `id` 중복.
- 허용 확인(지문)을 새 형식에 맞춘다. `plugin.json` 은 더 읽지 않는다(출시 전이라 호환 불필요).
- 기존 `should_send` / `payload` 방식은 없앤다.

## 확인

- 액션 줄·스크립트 줄이 섞인 플러그인이 이벤트마다 다른 일을 한다.
- 잘못된 정의가 이유와 함께 거절된다.

## 구현 / 확인한 것

- **정의 파일** — `plugin.toml`(`MANIFEST`). `PluginDef` = `name` · `description` · `scope` · `scripts` · `actions`(이름 붙인
  동작) · `handlers` · `inputs`. 모르는 칸은 거절(`deny_unknown_fields`) — 옛 `on`/`action`, 오타 칸이 조용히 무시되지 않는다.
  옛 `plugin.json` 만 있는 폴더는 "plugin.toml 로 옮기세요" 오류로 보인다.
- **줄** — `Handler { id, pre | post, call | action }`. `action` 은 `[actions]` 의 이름 또는 그 자리에 적은 동작.
  적재 검사: 단계·동작 누락/중복, 없는 동작 이름, 없는 함수(스크립트 컴파일 후 `fn 이름(e)` 확인), `id` 중복, 맞는
  이벤트가 없는 패턴, pre 를 안 내는 이벤트, `scripts` 없이 `call`.
- **스크립트 계약 변경** — `should_send`/`payload` 를 없앴다. 함수 이름은 자유이고, 함수 안에서 `send("이름", 본문)` /
  `run("이름", 입력)` 으로 **할 일을 적기만** 한다. 함수가 끝난 뒤 런타임이 적힌 순서대로 실행한다(던지면 적은 일도 버림,
  한 번에 32개까지). 없는 이름·종류가 안 맞는 명령(`send` 로 run 동작)은 그 일만 기록하고 건너뛴다.
  → [[DEV-406]] 의 "명령을 모았다가 실행" 뼈대가 여기서 먼저 들어갔다(보내기·실행 두 명령). 남은 것: 알림·백업 등 길드
  명령, 권한 선언, 잠금 밖 실행 확인.
- **여러 파일** — `scripts` 목록을 한 공간으로 합쳐 컴파일, 같은 함수가 두 파일에 있으면 거절. → [[DEV-408]] 은 폴더 밖
  `import` 가 남는다.
- **전달** — `Delivery::deliver` 가 동작을 인자로 받는다(한 플러그인이 여러 동작). 런타임은 플러그인마다 줄을 **적힌
  순서대로** 본다.
- **비밀값·입력란** — 이름 붙인 동작과 줄에 적은 동작 **모두**를 본다(오류 위치: `sync.headers.Authorization`,
  `handlers[0].action.args[0]`). 동작 이름에 token 이 들어가도 오탐하지 않는다.
- **화면·CLI** — `PluginView` 에 `handlers`(언제 → 무엇)와 `actions`(내보내는 곳). 관리 → 플러그인 이 줄 목록과 내보내는
  곳을 보여 준다. `plugin list --json` 은 `actions`/`handlers`/`scripts`, `plugin allow` 는 정의를 TOML 로 보여 준다.
- **예제 5개**를 새 형식으로(텔레그램은 이벤트마다 다른 함수, desktop-notify 는 스크립트 없는 동작 줄, deleted-audit 은
  pre 줄, 스크립트 파일 이름은 `main.rhai`).
- 시험: 코어 616(새 규칙 5건 — 섞인 줄 읽기, 줄 규칙 8가지, 모르는 칸, 없는 함수·옛 plugin.json, 비밀값 범위), 런타임
  (한 플러그인이 이벤트마다 다른 곳으로 적힌 순서대로, 없는/안 맞는 명령), 스크립트(명령 순서·본문, 던지면 버림, 상한,
  여러 파일), 예제를 실제 이벤트 페이로드에 태워 적은 일이 정의의 동작과 맞는지, 프런트 줄 목록 2건. 기존 시험은 옛 모양을
  새 모양으로 옮기는 시험용 변환기로 대부분 그대로 살렸다.
- 실제 바이너리(스크래치 길드, `OPENGUILD_HOME` 격리): 동작 줄(생성 → 기록) + 스크립트 줄(상태 변경 중 done 만 기록)이
  한 플러그인에서 각각 동작 — 생성 1줄, in_progress 는 기록 없음, done 1줄. backup-archive 새 형식으로 `backup new` → 사본
  생김. 옛 plugin.json 폴더는 안내 오류. `plugin allow` 미리보기가 TOML. 시드 스크립트가 예제 5개를 싣는다.
- **아직 옛 형식인 것** — 테스트 길드(`~/workspace/testbed/test-guild`)의 플러그인, USAGE·스킬·예제 README·CHANGELOG 의
  설명 → [[DEV-413]]. 그 전에 3100 서버를 새 바이너리로 다시 띄우면 테스트 길드 플러그인이 "옮기세요" 오류로 멈춘다.

DEV-067 한계 항목 실측 확인. 현재 localStorage key 들 (openguild.hideSettings, openguild.laneCols, openguild.globalCols, openguild.boardViewport, openguild.gridSnap) 이 단일 namespace — 길드 A 에서 설정한 hideSettings (status slug 기반) 가 길드 B 로 누수. slug 충돌 시 의도치 않은 hide 적용 + viewport / lane 폭 도 옮겨감. 길드별 namespace prefix (path hash 또는 abs path) 도입 필요.

## 구현 (2026-05-25)

### Backend
- `commands::current_guild_path(store)` → 활성 길드의 절대 경로 반환.
  `Store.paths.guild_root.display().to_string()`. `invoke_handler!` 등록.
- Welcome / Uninit 모드에선 placeholder 경로가 그대로 — frontend 는
  `launch_mode.mode === "guild"` 컨텍스트 (이미 board 진입 전제) 에서만
  의미 있게 사용.

### Frontend (`QuestBoard.svelte`)
- 모듈 상단:
  - `let guildKeyPrefix = ''`.
  - `fnv1a32(s)` — 32-bit FNV-1a → 8 hex (짧고 충돌 거의 없음).
  - `gk(suffix)` → `openguild.<prefix>.<suffix>` (prefix 비면 기존 `openguild.<suffix>` 폴백 = web GUI 경로).
- 영향받는 5개 key 모두 `gk(...)` 로 교체:
  - `laneCols`, `globalCols` (BUG-009).
  - `hideSettings` (DEV-056).
  - `boardViewport` (DEV-058).
  - `gridSnap` (구).
- 모듈 init 시 eager `loadHideSettings()` / `loadGlobalCols()` 제거 →
  기본값 (`{}`, `2`). prefix 가 비어 있을 때 read 가 의미 없으므로.
- 첫 onMount: listener 등록만. gridSnap load 도 이쪽에서 제거.
- 두 번째 onMount (data fetch):
  1. `detectEnvironment() === 'tauri'` 일 때만 `invoke('current_guild_path')` →
     `fnv1a32` → `guildKeyPrefix`.
  2. prefix 확정 직후 `hideSettings = loadHideSettings()`,
     `globalCols = loadGlobalCols()`, `gridSnap = ...` 로드.
  3. 이후 평소대로 `init(...)` 호출 (`laneCols` / `viewport` 도 init 안에서
     loaded — 이미 prefix 적용된 `gk()` 통과).

### 한계 / 의식적 결정
- `gui/frontend/src/routes/quests/[id]/+page.svelte` 의
  `openguild.questEditorHeight` 는 **글로벌 유지**. 길드와 무관한 사용자
  UI 선호 — 모든 길드에서 같은 편집기 높이가 자연스러움.
- 기존 단일 namespace 에 저장된 데이터는 마이그레이션 안 함. 비-prod
  상태이고 양도 적어 사용자가 다시 설정. 다음 진입부터 길드별 분리됨.
- web GUI (HTTP 모드) 는 prefix 빈 채로 동작 — `openguild.<suffix>` 기존
  키 그대로. 단일 길드 백엔드 가정.

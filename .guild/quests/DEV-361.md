## 증상

토론 댓글을 남기라고 지시했는데, 댓글의 **'토론(discussion)' 기능을 쓰지 않고**
본문 말머리에 그냥 `[토론]` 이라고 텍스트로 적는 경우가 발생한다.

말머리는 아무 기능도 하지 않는다 — 미해결 토론 차단(완료 전환 block), 미해결
필터(`openguild comments --unresolved`), GUI 토론 표시 어느 것도 동작하지 않아
사실상 토론을 남기지 않은 것과 같다.

## 추정 원인 (확인함)

`openguild quest comment add` 에 **`--discussion` 플래그가 없다.**
토론 댓글을 만들려면 반드시 2단계를 밟아야 한다:

```
openguild quest comment add {ID} --author me --file body.md   # 1) 추가
openguild quest comment discussion {ID} {댓글번호}             # 2) 토론 토글
```

한 번에 만드는 경로가 없으니, 작성자가 1단계만 하고 "토론임을 표시" 하려고
말머리를 붙이는 것으로 보인다.

## 제안

1. `comment add` 에 `--discussion` 플래그 추가 — 추가와 동시에 토론으로 생성.
   (가장 근본적. 2단계를 1단계로 만들면 말머리를 붙일 이유가 사라진다.)
2. 스킬/문서에 "토론은 말머리가 아니라 `discussion` 기능" 을 명시.
3. 선택 — 본문이 `[토론]` 등으로 시작하는데 discussion 플래그가 꺼져 있으면
   CLI 가 경고를 띄우는 방안.

1번만 해도 대부분 해소될 것으로 보인다.

## 수정 내용 (2026-08-20)

결정대로 **CLI `--discussion` 플래그만** 추가했다(서버 API 파리티·말머리 경고는 제외).

- `cli/src/main.rs` `CommentCmd::Add` 에 `--discussion` 플래그 추가.
  생성 직후 `comments_toggle_discussion` 을 호출한다 — 새 entry 는 항상
  `discussion=false` 로 만들어지므로 토글이 곧 설정이다.
- **scope 검증을 본문 읽기 앞에 뒀다.** 토론은 quest 전용인데, stdin 을 소비한
  뒤에 실패하면 사용자가 입력한 본문을 잃는다.
- 출력에도 반영 — 텍스트는 `· 토론`, JSON 은 `discussion` 필드.
- 문서 2곳 갱신: `.agents/skills/openguild-workflow/SKILL.md` (내부용),
  `skills/openguild-plugin/skills/openguild/reference/comments.md` (배포용).
  둘 다 "토론은 말머리가 아니라 기능" 을 명시했다 — 플래그만 추가하고 문서를
  안 고치면 같은 오용이 반복된다.

## 검증 (스크래치 길드에서 실행)

실 길드를 오염시키지 않도록 임시 길드를 만들어 확인했다.

- `--discussion` 생성 → `✓ 댓글 추가: #1 (... · 토론)`
- `comment list --unresolved` 에 잡힘 (`#1 ... ●미해결`)
- **미해결 상태에서 `quest done` 차단됨** — "미해결 토론(discussion) 댓글
  1개(#1)를 먼저 resolve 해야 완료 상태로 전환할 수 있습니다."
  ← 말머리로는 얻을 수 없던 바로 그 동작
- `resolved` 처리 후 `quest done` 통과
- JSON: `{"discussion":true,"id":3,...}`
- campaign 댓글에 `--discussion` → "quest 댓글 전용입니다" 로 거부
- `cargo test -p openguild-cli` 115 passed


업데이트 자동 확인을 켜고 끌 수 있어야 한다.

현재는 시동 시 무조건 updater endpoint(`latest.json`)를 확인한다. 오프라인
환경이나 사내망, 또는 버전을 고정해 쓰는 경우에 매번 외부 요청이 나가는 것을
막을 방법이 없다.

## 할 일

- 설정에 "업데이트 자동 확인" on/off (기본 on).
- 끄면 시동 시 확인을 건너뛴다. 수동 확인 경로는 남긴다("지금 확인").
- 설정 저장 위치는 다른 GUI 설정과 동일 규칙.

## 구현 (2026-07-29)

- `stores/updateSettings.ts` 신설 — localStorage 영속, **기본 on**(기존 동작 유지).
- 설정 > 정보 탭의 버전 행 아래에 켜기/끄기 토글 + 설명. Tauri 전용
  (브라우저 모드는 업데이트 개념이 없어 숨김).
- `ToastHost` 의 시동 확인과 주기 확인 양쪽에서 `isAutoUpdateCheckEnabled()`
  를 **매 호출 시점에 다시 읽는다** — 설정을 끄면 앱 재시작 없이 즉시 멈춘다.
- **수동 확인('업데이트 확인' 버튼)은 이 설정과 무관하게 항상 동작한다** —
  사용자가 명시적으로 누른 것이므로 막을 이유가 없다.

손상된 저장값은 "켜짐"으로 해석한다 — 확인을 조용히 멈추는 쪽이 더 위험하다.

## 검증

- 단위 테스트 5건(`updateSettings.test.ts`): 기본 on / 끄면 즉시 반영 /
  재시동 후 유지 / 다시 켜기 / 손상값 fallback.
- 프론트 313건 전체 통과, `svelte-check` 0 errors / 0 warnings.
- 브라우저 모드에서 설정 페이지에 이 행이 **숨겨지는 것**까지 확인(정상).

**미검증**: 데스크탑(Tauri)에서의 실제 토글 표시와 "끄면 시동 시 요청이 안
나가는지"는 앱 빌드가 필요해 확인하지 못했다.

## Test plan

1. 데스크탑에서 설정 > 정보에 "업데이트 자동 확인" 토글이 보이는지.
2. 끈 뒤 앱을 재시작 → 시동 시 업데이트 확인이 **안 일어나는지**(네트워크
   요청 없음, 알림 없음).
3. 끈 상태에서도 '업데이트 확인' 버튼은 동작하는지.
4. 다시 켜면 시동/주기 확인이 복구되는지.
5. 설정이 재시작 후에도 유지되는지.

## 무엇이 잘못됐나

`just test` 가 가끔 깨진다. 같은 코드인데 어떤 때는 되고 어떤 때는 안 된다.

```
test store::tests::ensure_schema_is_idempotent ... FAILED
```

혼자 돌리면 통과한다. 여럿이 같이 돌 때만 깨진다.

## 왜

`Store::open_in_memory` 는 메모리 DB 에 이름을 붙여 쓴다(`?mode=memory&cache=shared`).
**이름이 같으면 같은 DB** 다. 그런데 그 이름을 **시계로** 지었다.

```rust
let ns = SystemTime::now().duration_since(UNIX_EPOCH)...as_nanos();
format!("sqlite:file:og-mem-index-{ns}?mode=memory&cache=shared")
```

나노초라고 쓰여 있지만 이 시계는 그만큼 곱지 않다. 맥에서 재 봤더니 두 갈래로 16만 번
읽는 동안 **8만 번이 앞의 것과 같은 값**이었다. 즉 같은 순간에 열린 두 Store 가 남의 DB 를
그대로 들여다본다. 한쪽이 만들어 둔 표·자료가 다른 쪽에 보이고, 스키마를 두 번 깔게 되면서
엉뚱한 곳에서 실패한다.

테스트만의 문제가 아니다. `open_in_memory` 는 **길드를 아직 안 연 상태의 앱**도 쓴다. 창을
동시에 두 개 띄우면 같은 일이 난다.

## 고친 것

시계 대신 **한 번 쓰고 버리는 번호**로 이름을 짓는다(프로세스 id + 세는 수). 겹칠 수가 없다.

## 테스트 방법

- 한꺼번에 16개를 열어 각자 자기 표를 만들고 자기 것만 보이는지 보는 시험을 붙였다.
- 옛 코드로 되돌려 20번 돌려 보니 **17번 잡힌다**. 하나씩 여는 기존 시험은 한 번도 못 잡았다.

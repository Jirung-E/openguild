quest_history 가 index.db 전용 권위 데이터 — 'index.db=재생성 가능한 캐시' 원칙의 유일한 예외라 index.db 삭제(새 clone/캐시 초기화) 시 이력 영구 소실. (A)안(사이드카 jsonl) 채택.

## 구현 (2026-07-05)
- **신규 `repo/history.rs`**: `.guild/quests/{slug}.history.jsonl` — 한 줄=한 이벤트 JSON({ts,op,old,new}), append-only, git tracked(감사 기록). 깨진 줄 fail-soft.
- **이중 기록**: change_status/change_type(history INSERT 지점 전수)이 DB INSERT 와 동시에 사이드카 append. change_type 은 .md 처럼 사이드카도 rename cascade.
- **reindex 5d 동기화**: (a) 사이드카 없는 slug 의 DB 행 → 파일 export(DEV-180 이전 데이터 일회성 자가 치유 — 첫 reindex 에서 기존 이력 보존) (b) 사이드카 있는 slug 는 파일 기준으로 DB 재구축 — fresh index.db 에서도 이력 복원. dangling 사이드카(quest 없음)는 skip.
- 스냅샷: quests 서브디렉토리 통째 복사라 자동 포함(확인).
- ReindexReport 에 history_loaded/history_exported + summary/CLI 출력.
- 테스트: history.rs 왕복/rename/fail-soft + reindex 양방향 동기화(테이블 와이프→복원, 사이드카 삭제→export).

## 테스트 방법
- `cargo test -p openguild-core history` + `cargo test -p openguild-core reindex` 통과.
- 실기: 이 길드에서 `openguild reindex` → 출력에 'history: 0 복원 / N export' (기존 이력 전량 export, .guild/quests/*.history.jsonl 생성 확인) → `quest move` 한 번 → 사이드카에 줄 추가 확인 → index.db 백업해두고 삭제 → 아무 명령(Store 재생성) 후 reindex → `quest history <slug>` 에 이력 살아있는지.

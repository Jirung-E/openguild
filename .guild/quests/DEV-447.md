[[REQ-039]] — 퀘스트 목록 화면에서 쿼리로 거르기. 해석과 거르기는 코어(앞 퀘스트)가 하고, 화면은 글을 보내 맞는 퀘스트를 받는다.

## 할 것

- 목록 필터 줄에 쿼리 입력칸 — 지금 버튼 필터와 **그리고**로 합친다.
- 주소(`?q=`)에 실려 공유 · 새로고침에 남고, 길드별 필터 저장에도 들어간다.
- 문법 오류는 입력칸 아래에 한 줄로(어디가 틀렸는지). 오류인 동안은 목록을 거르지 않는다.
- 쓸 수 있는 키를 짧게 알려 주는 도움말.

## 나중 (이 퀘스트 밖)

- 버튼을 누르면 쿼리 글이 채워지는 것(쿼리가 진리원).
- 보드 · 캠페인 · 도서관.

## 한 것 (2026-10-21)

- 필터 줄 아래에 **쿼리** 입력칸(한 줄 전체, 고정폭 글꼴). 글을 멈추고 0.25초 뒤 코어에 맞는 퀘스트를 묻고(`GET /api/quests?q=…&slim=true`, 앱은 `list_quests` 의 `q`), 받은 id 를 지금 목록에 겹친다 — 버튼 · 검색과 **그리고**.
- 틀리면 입력칸이 빨개지고 아래에 코어의 말 그대로("쿼리 1번째 글자: 모르는 키 'stauts' — 쓸 수 있는 키: …"). 틀린 동안은 거르지 않는다.
- `?` — 규칙 한 줄 + 키 7개와 예.
- 주소 `?q=` 와 길드별 필터 저장에 실린다(새로고침 · 공유 링크). 보드에 들렀다 와도 남는다. 보드의 '필터 해제' 는 주소의 `q` 도 지운다.
- 넓힌 검색(댓글 · 첨부)과는 따로 건다 — 넓힌 검색은 검색어 매칭을 서버에 맡기지만, 쿼리는 검색어와 겹쳐 걸어야 해서 `queryMatchIds` 를 따로 두었다.
- 보드는 아직 쿼리로 흐리지 않는다 — 그래서 '필터 걸림'(isFilterActive)에 쿼리를 넣지 않았다.

## 확인 (웹 빌드 + develop 서버, WebKit, 시험용 길드 사본 836개)

- `status:open type:BUG` → 2(CLI 와 같음), 주소에 `q=` 실림. `due:overdue` → 6(CLI 와 같음). 새로고침 뒤에도 그대로 6. 지우면 836.
- `stauts:open` → 빨간 칸 + 오류 줄, 목록은 836 그대로.
- 라이트 · 다크 · 폭 400px(가로 넘침 없음) 스크린샷.
- 시험: 필터 왕복에 query, 쿼리만으로는 보드 기준 비활성, 쿼리 id 는 검색어와 함께 건다. `just test` 통과.

## 테스트 방법

1. 퀘스트 목록 → 쿼리 칸에 `status:open -tag:wip` → 맞는 것만 남는다. `?` 를 누르면 쓰는 법이 나온다.
2. `stauts:open` 처럼 틀리게 쓰면 칸이 빨개지고 이유가 나오며 목록은 그대로다.
3. 새로고침 · 보드에 갔다 오기 뒤에도 쿼리가 남는다.

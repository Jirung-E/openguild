구현했습니다. `notify(글, #{ seconds: 10, open: "DEV-001", comment: 3 })`

- `seconds`: 표시 시간(초). 0 은 닫을 때까지, 최대 3600, 없으면 기본 4초.
- `open`: 누르면 열 문서(퀘스트 · 캠페인 · 도서관). `comment`: 그 댓글까지 이동(`open` 필요, 도서관 제외).
- 틀린 옵션은 스크립트 오류. CLI · 서버는 글만 남깁니다. `notify(글)` 은 그대로입니다.
- 갈 곳이 있는 알림에는 "열기" 표시가 붙고, 글이 같아도 갈 곳이 다르면 합치지 않습니다.

검증: `just test` EXIT=0(Rust 1311, 프론트 977). 임시 길드에서 실제 CLI 로 옵션 있는 알림 · 틀린 옵션 오류 확인. 알림 누르기는 컴포넌트 시험으로 확인했습니다.

사용자 확인 필요: 데스크톱 앱에서 실제 알림이 뜨는 것, 표시 시간, 눌러서 댓글로 이동. (앱 이벤트 통로는 시험에서 직접 돌리지 못했습니다.)

맥 데스크톱 앱(debug, 격리 길드, `99b73e6c`)에서 직접 조작해 확인했습니다.

- `seconds: 10`: 9초 때 보이고 12초 때 사라짐. 
- `open` + `comment: 7`: 누르면 DEV-001 의 7번 댓글로 이동. 갈 곳 있는 알림에 "열기" 표시.
- 편집 중에 누르면 "버리고 이동할까요?" 를 묻는다.
- `seconds: 0`: 15초 넘게 남고, 빈 곳을 눌러도 남는다. **탭을 옮기면 사라진다** — 아래 참고.
- `open: "BOOK-001"` · `"C-001"` 알림이 뜨는 것까지 봤고, 눌러 이동은 안 봤다(주소는 단위 시험).

**확인 필요:** 합성 클릭으로 상단 탭을 옮기면 앱 페이지 전체가 다시 읽힌다(임시 표시로 횟수 증가 확인). 그래서 알림 저장소가 비워진다. 목록 행 · 보드/목록 전환은 안 그런다. `tauri://` 와 URL 의 origin 은 같아 그 가설은 아니다. 합성 클릭 탓일 수 있어 손으로 확인이 필요하다.

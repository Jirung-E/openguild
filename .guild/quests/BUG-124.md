admin 보고: 도서관에서 첨부파일(본문 첨부파일 말고 일반 첨부파일)이 있는
상태에서 본문 편집을 누르고 본문에 사진을 추가한 후 저장을 누르면 기존
첨부파일이 보이지 않음. 나갔다 들어오거나 새로고침해도 안 보이고 새로운
첨부파일을 추가할 때까지 안 보임.

## 원인
`server/routes/library.rs`(+ Tauri 대응 `gui/src/commands.rs`) 의
`update_book`(PATCH) 핸들러가 `list_books` 와 동일하게 응답의
`attachments` 를 항상 빈 배열로 뒀음 — "단건 조회(get_book)에서만 채우고
list 는 절약"이라는 원래 의도였는데, PATCH(단건 수정) 도 그 "list" 취급을
받고 있었음. quest/campaign 의 `update_quest`/`update_campaign` 은 이미
단건 응답에 attachments 를 채우는데(quests.rs 참고) 도서관만 이 패턴을
안 따르고 있었던 것.

클라이언트(`library/+page.svelte`)의 `save()`/`onRetitle()`/`onMove()` 는
PATCH 응답으로 book 객체 전체를 교체(`books = books.map(...)`)하는데, 그
응답의 attachments 가 항상 []라 실제 파일은 디스크에 안전하게 남아있어도
화면에서 첨부 목록이 사라짐. 새로고침해도 `list()` 역시 원래 빈 배열이라
복구가 안 되고, 첨부를 새로 추가하면 그 응답(`addAttachment`)은 최신 전체
목록을 돌려주므로 그제서야 우연히 복구됐던 것.

## 수정
- `server/routes/library.rs::update_book`, `gui/src/commands.rs::update_book`:
  `get_book` 과 동일하게 응답 조립 후 `list_book_attachments` 로 attachments
  채움.
- `list_books`/`create_book` 은 의도대로 유지(생성 직후엔 첨부가 없고,
  목록은 payload 절약 목적이 여전히 유효).

## 테스트 방법
- `cargo test -p openguild-server library` — 신규
  `test_library_update_preserves_attachments_in_response` 포함.
- `cargo clippy --workspace --all-targets -- -D warnings`.
- 실기: 문서에 일반 첨부파일 추가 → 본문 편집 진입 → 본문에 이미지 삽입 →
  저장 → 기존 첨부파일이 그대로 보이는지. 제목 변경/폴더 이동 후에도 동일.

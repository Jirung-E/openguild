## 구현

입력란 오른쪽에 **넓게** 토글. `localStorage`(`openguild.paletteWideSearch`)
영속.

- 켜면 `parsed.term` 으로 `/api/search` 조회 → 결과를 `kind` + `id` 로 키잉해
  `all` 의 항목과 맞춘다. `Item.label` 이 quest_id / campaign_slug / rule slug /
  BOOK-NNN 이고 `SearchHit.id` 도 같은 값이라 그대로 대응된다.
- 결과를 **대체가 아니라 합친다.** 로컬 매치(제목/slug/태그)는 즉시 보이고,
  서버 응답이 오면 댓글·첨부에서 맞은 것이 뒤이어 붙는다 — 켠 순간 목록이
  비었다가 채워지지 않는다.
- 제목/slug/태그로 **안** 맞는데 나온 행에만 `댓글`/`첨부`/`본문` 뱃지와
  발췌를 붙인다. 맞는 행에까지 붙이면 소음이다.
- 네임스페이스 범위(`quest:` 등)는 그대로 적용된다 — 실측에서 `book:젤리곰` 은 0건.

## 디바운스 · stale 가드는 utils 로

퀘스트 목록(REQ-010)·도서관(REQ-011)이 각자 구현해 두 벌이었고 여기가 세
벌째라 `lib/utils/enhanced-search.ts` 로 뺐다(REQ-013 커밋에 포함). 룬을 쓰지
않는 순수 TS 라 가짜 타이머로 테스트가 붙는다 — 8건 중 핵심은 "늦게 도착한
이전 응답이 최신 결과를 덮지 않는다" 와 "cancel 후 도착한 응답도 무시한다".

## 검증 중에 잡은 것 — 옛 검색어의 결과가 남아 있었다

처음 구현은 `wideHits` 를 그냥 Map 으로 들고 있었다. 그러면 검색어를 바꾼 뒤
새 응답이 오기 전까지 **이전 검색어의 결과가 화면에 그대로 남는다.** 기다리는
중이 아니라 틀린 답을 낸 것처럼 보인다. (stale-async 가드는 '늦게 온 응답' 을
막을 뿐, '아직 안 온 응답' 동안의 표시를 정하지 않는다.)

`{ term, hits }` 로 **어느 검색어의 결과인지 함께** 들고, 검색어가 어긋나면
로컬 매치만 쓰도록 고쳤다. 조회 중임은 진행 표시로 알린다.

## 증상 (사용자 보고, 모바일)

팔레트에서 넓게 켜고 검색하면 **펼쳐진 행의 글자가 한 글자씩 세로로** 늘어서고
칩·제목·버튼이 화면에서 사라진다. 행 하나가 목록 전체를 덮는다.

## 원인

세로로 늘어선 건 발췌가 아니라 **제목**이었다.

`DEV-297` 이 펼친 행에서 제목 전체를 보여주려고 이렇게 둔다:

```css
.row.expanded .ptitle {
    overflow: visible;
    white-space: normal;
    overflow-wrap: anywhere;
}
```

`overflow: visible` 이 되는 순간 flex 의 `min-width: auto` 가 되살아나고,
`overflow-wrap: anywhere` 때문에 그 **최소 폭이 한 글자**가 된다. 접힌 행은
`overflow: hidden` 이라 `min-width: auto` 가 0 으로 계산되어 말줄임으로
정상 동작한다 — 펼친 행에서만 성립하는 함정이다.

거기에 REQ-012 가 발췌(`.pwhy`)를 같은 줄에 폭 제한 없이 넣었다. 375px 실측:

| | 폭 |
|---|---|
| 행 전체 | 279.8px |
| 발췌 | 156.6px (56%) |
| **제목** | **11.8px** ← 한 글자 |
| 행 높이 | **1211px** |

BUG-237(mermaid 라벨이 단어 중간에서 끊겨 상자를 넘침)과 같은 뿌리다 —
`overflow-wrap: anywhere` 가 최소 폭을 1글자로 만든다.

## 수정

폭만 조절하면 화면 폭에 따라 다시 깨진다. **줄을 나눠 원인을 없앴다.**

- 펼친 행: `.row-main { flex-wrap: wrap }` + `.pwhy { flex-basis: 100% }`
  → 발췌가 아래 줄로. 펼친 행은 원래 높이가 늘어나는 상태라 자연스럽다.
- 접힌 행: `.pwhy { flex: 0 1 auto; max-width: 40% }` — 태그(`.ptags`)가
  쓰던 방식과 동일하게 제한.

## 검증

| 폭 | 상태 | 제목 | 발췌 | 행 높이 |
|----|------|------|------|---------|
| 375 | 수정 전 | 11.8 × 1196.7 | 126.6 | **1211.1** |
| 375 | 수정 후 | 177.9 × 65.3 | 224.3 × 17.4 | **106.7** |
| 1280 | 켬 | 378.9 × 43.5 | 425.3 × 17.4 | 88.6 |
| 1280 | 끔(회귀) | 378.9 × 21.8 | `.pwhy` 없음 | 61.6 |

토글을 끄면 `.pwhy` 가 아예 렌더되지 않아 행 높이가 예전과 같다.
스크린샷으로 375px 렌더 육안 확인. `just test` 475건 통과.

## 요청

토글을 켠 상태에서는 **접힌 행에서도** 제목과 매칭 부분을 한 줄씩 보여준다.
매칭 이유가 없는 행은 한 줄 그대로(사용자 결정).

## 구현

앞선 수정은 발췌를 **펼친 행에서만** 아래 줄로 내렸다. 그 규칙을 없애고
`.pwhy` 를 접힘·펼침 공통으로 항상 아래 줄에 둔다.

- `.row-main { flex-wrap: wrap; row-gap: 0.2rem }`
- `.pwhy { flex-basis: 100%; max-width: 100% }` — 폭 40% 제한은 뺐다.
  줄이 나뉘었으니 제목과 다툴 일이 없다.

제목은 접힌 행에서 원래대로 한 줄 말줄임(`overflow: hidden`), 발췌도
`white-space: nowrap` + 말줄임이라 **각각 정확히 한 줄**이다.

## 접힌 높이 추정치를 함께 고쳐야 했다

`.row` 는 `content-visibility: auto` + `contain-intrinsic-size: 2.275rem`
이다. 화면 밖 행의 예상 높이를 접힌 한 줄 높이로 고정해 스크롤 흔들림을 막는
장치인데(BUG-244), 두 줄이 되는 행에 그대로 두면 **행이 36.4px 로 고정돼
둘째 줄이 잘린다.** 실제로 처음 구현에서 발췌가 행 밖으로 삐져나갔다 —
`.pwhy` 는 y=155.4 인데 행 아래끝은 159.4 였다.

BUG-244 와 같은 방식으로 정확히 계산해 별도 값을 줬다:

```
첫 줄 2.275rem + row-gap 0.2rem + 발췌 줄(0.68rem × line-height 1.25
= 0.85rem) = 3.325rem
```

`.pwhy` 에 `line-height: 1.25` 를 명시해 이 계산이 성립하게 고정했다.

## 검증 (실 길드)

`3.325rem × 16 = 53.2px` — 실측과 **정확히 일치**(오차 0). BUG-244 가
0.38px 어긋남으로도 튐을 잡아낸 자리라 값이 정확해야 한다.

| 행 | 높이 | 비고 |
|----|------|------|
| 이유 있음 · 접힘 | **53.2px** (3.3247rem) | 추정치와 일치, 발췌가 행 안에 |
| 이유 없음 · 접힘 | **36.4px** | 기존 그대로 (사용자 결정) |
| 이유 있음 · 펼침 | 78.36px | 제목 전체 + 발췌 |

'보드' 검색 8행 중 7행 두 줄 / 1행(BUG-242, 제목으로 맞음) 한 줄 — 섞여도
정상.

375px 스크린샷 육안 확인: 제목이 한 줄 말줄임, 그 아래 `댓글`/`본문` 뱃지와
발췌가 한 줄. 앞서 보고된 세로 늘어짐은 재현되지 않는다.

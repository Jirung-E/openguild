## 증상

- `cargo build -p openguild-gui` (또는 `cargo run`) 만 실행하면 Tauri 가 embed
  하는 frontend (`gui/frontend/build/`) 가 **이전 빌드 결과** 그대로.
- frontend `.svelte` / `.ts` 를 수정한 뒤 `cargo build` 만 하면 변경 반영 안 됨.
- 사용자가 매번 수동으로 `cd gui/frontend && npm run build` 를 먼저 실행해야 함.

## 원인

- Tauri 의 `tauri.conf.json` 의 `build.beforeBuildCommand` 설정으로
  pre-build 명령을 줄 수 있음 — 현재 미설정 (또는 dev 모드 전용으로만).
- release 빌드도 동일 — `cargo build --release` 시에도 stale embed 가능.

## 작업

### A. `tauri.conf.json` 의 `beforeBuildCommand` 설정
```jsonc
{
  "build": {
    "beforeBuildCommand": "npm --prefix frontend run build",
    "frontendDist": "../gui/frontend/build"
  }
}
```
- `cargo tauri build` 가 자동으로 npm build 먼저 실행 → embed.
- `cargo build -p openguild-gui` 는 Tauri CLI 를 거치지 않으므로 여전히 stale
  가능 — 그래서 다음 B 추가.

### B. `build.rs` 에서 npm 빌드 트리거 (선택)
- `gui/build.rs` 에 frontend 파일 변경 감지 → `npm run build` 실행.
- 단 CI / docker 에서 npm 없는 환경 고려 — env 로 skip 옵션.

### C. 문서화
- README / AGENTS_OPENGUILD_USAGE 에 "frontend 변경 시 `npm run build` 필수" 명시.
- 가장 적은 코드로 즉시 해결.

server 테스트 `load_server_config_none_when_not_found_and_not_explicit`
(`server/src/main.rs` cli_tests)이 **실제 `~/.openguild` 를 격리하지 않아**,
개발자 머신에 real `~/.openguild/openguild-server.toml` 이 있으면 실패한다.

## 재현 (2026-07-19, DEV-254 작업 중 발견)

- `~/.openguild/openguild-server.toml` 이 존재하는 환경에서
  `cargo test -p openguild-server` → 위 테스트 1개 실패
  (`assert!(load_server_config(None).unwrap().is_none())` — 실제 파일을
  찾아 Some 반환).
- 그 파일을 잠시 옮기면 통과(190 passed) — 확인함.

## 원인

`load_server_config(None)` 은 explicit 미지정 시 exe 옆 → cwd →
`~/.openguild` 순으로 탐색(DEV-229/247, 정상 동작). 그런데 "없을 때 None"
을 단언하는 이 테스트가 `~/.openguild` 를 temp 로 격리하지 않아 실제 홈에
의존한다. 즉 코드가 아니라 **테스트 격리 결함**.

## 수정 방향

- 이 테스트(및 config 탐색 관련 테스트들)를 `OPENGUILD_HOME` 을 빈 temp
  디렉토리로 설정한 상태에서 실행하도록 격리(`user_dirs::openguild_home()`
  이 `OPENGUILD_HOME` 을 존중함 — core/locale.rs 주석 참조).
- 단, env 는 프로세스 전역이라 parallel 테스트와 레이스 주의 — serial
  실행(`serial_test` 또는 단일 테스트 내 set/remove) 또는 cwd/exe 격리와
  함께 설계. locale 테스트가 OPENGUILD_LOCALE 을 set/remove 하는 기존
  패턴 참고.

## 테스트 방법

`~/.openguild/openguild-server.toml` 이 있는 상태에서도
`cargo test -p openguild-server` 가 전부 통과하는지.

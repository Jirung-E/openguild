사용자 지적(2026-07-03): 퀘스트 타입 prefix 는 커스텀 가능(types add)한데, 캠페인(C-NNN)/길드규칙 slug/도서관(BOOK-NNN, DEV-184) ID 와 겹칠 수 있음.

## 충돌 시나리오
1. `types add --prefix C` → 퀘스트 C-001 이 캠페인 C-001 과 충돌 (cross-link/조회 모호).
2. (DEV-184 후) `types add --prefix BOOK` → 도서관 문서와 충돌.
3. 규칙 slug 를 `dev-001` 처럼 XXX-NNN 형태로 생성 → cross-link 인덱스(questIndex, 대문자 키)에서 퀘스트 DEV-001 과 **키 충돌 — 나중에 적재된 규칙이 퀘스트를 덮어씀** (DEV-173 구현상 실재하는 엣지).
4. 타입 rename(update --prefix)으로 기존 예약어 침범.

## 대책(안)
- **예약 prefix 목록**: C + BOOK + 기존 등록 타입 prefix. `types add/update --prefix` 에서 예약어/중복 거부 (대소문자 무시).
- **rules create/rename**: slug 가 XXX-NNN(추적번호 형태)이면 거부 — 규칙 slug 는 단어형만.
- (DEV-184 구현 시) 도서관도 동일 규칙 적용.
- cross-link 인덱스: 충돌 잔존 데이터 방어 — kind 우선순위(quest > campaign > book > rule) 정의해 덮어쓰기 방지.
- 기존 데이터에 이미 충돌이 있으면 check drift 류 진단으로 경고.

관련: DEV-173(규칙 cross-link), DEV-184(도서관), DEV-042(slug=stable identifier).

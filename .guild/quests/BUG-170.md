DEV-266 의 콘솔 트리거 `window.__ogNotify` 가 빌드한 앱에서
`__ogNotify is not defined` (사용자 보고).

## 원인
훅 노출이 `import.meta.env.DEV` 로만 게이트돼 있었다. 이 값은 프런트엔드
**번들 모드**(vite dev server)를 뜻하지 Rust 빌드 프로파일이 아니다 —
디버그로 패키징한 앱도 프런트는 production 번들이라 DEV=false 가 되어
훅이 사라졌다. 사용자가 "디버그 기준으로 말한 것"이었으므로 기대와 실제
게이트가 어긋나 있던 셈.

## 수정 (사용자 선택: A안)
빌드 프로파일은 Rust 만 아니므로 `is_debug_build` Tauri 커맨드
(`cfg!(debug_assertions)`)를 추가하고, ToastHost 가 mount 시 조회해
디버그 빌드면 훅을 노출한다. 릴리스 빌드는 false → 훅 없음(콘솔 깨끗).
dev 서버(`import.meta.env.DEV`)는 종전대로 즉시 노출.
(1차 시도였던 localStorage opt-in `__ogEnableDebug` 는 의도와 달라 폐기.)

## 테스트 방법
1. 디버그 빌드 앱 콘솔에서 `__ogNotify` 가 정의돼 있는지 확인 후
   `__ogNotify.toast('e','error',0); __ogNotify.schema(); __ogNotify.update('available');`
   `for (let i=0;i<8;i++) __ogNotify.toast('m'+i,'info',0);`
   → 5개 + "+N개 더 보기" 칩, error/지속형 유지, 칩 클릭 시 전체 펼침,
   `__ogNotify.toast('m1','info',0)` 재호출 시 ×2 뱃지.
2. 릴리스 빌드에서는 `__ogNotify` 가 undefined 여야 정상.

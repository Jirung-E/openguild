admin: "DEV-422, 복사할때마다 cli 창이 뜬다" (2026-10-11, 윈도우).

## 원인

윈도우에서 도서관 파일을 클립보드에 올릴 때 PowerShell(`Set-Clipboard -LiteralPath`)을 띄운다(`gui/src/commands.rs`
`copy_files_to_clipboard` → `run_tool`). 콘솔 없는 데스크톱 앱이 콘솔 프로그램을 띄우면 **새 콘솔 창이 뜬다** —
플러그인 쪽은 [[BUG-294]] 에서 `CREATE_NO_WINDOW` 로 막았는데 `run_tool` 에는 없었다. [[DEV-422]] 에서 ⌘/Ctrl+C ·
고른 것 복사가 자주 쓰이게 되면서 드러났다.

## 고칠 것

`run_tool` 이 윈도우에서 `CREATE_NO_WINDOW` 로 띄운다.

## 고침 (2026-10-11)

`run_tool` 이 윈도우에서 `CREATE_NO_WINDOW` 로 띄운다 — [[BUG-294]] 의 `core/src/plugins/delivery.rs` 와 같은 방법.
GUI 백엔드가 외부 프로그램을 띄우는 곳은 `run_tool` · `pipe_tool`(리눅스 전용) · `osascript`(맥 전용) 뿐이라
윈도우에서 창이 뜰 수 있는 곳은 여기 하나였다.

확인: 맥 `cargo check` · `just test` 통과. **윈도우 빌드는 여기서 확인 못 했다** — 맥에서 윈도우 대상으로 검사하면
C 의존성(ring)이 컴파일되지 않는다. 같은 코드가 플러그인 쪽에서 이미 윈도우로 빌드되고 있다.

## 테스트 방법

1. 윈도우 앱 → 도서관 → 문서 · 폴더를 고르고 Ctrl+C (또는 [복사]).
2. 검은 창이 번쩍이지 않는다. 탐색기에 붙여넣으면 파일이 들어간다.

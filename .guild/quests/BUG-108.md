replay_before_any_op_yields_snapshot_state 테스트 실패 원인 조사 (사용자 지시로
직접 cargo test 실행해 규명):

core/src/snapshot.rs 의 now_compact() 는 초 단위 타임스탬프
("%Y%m%d-%H%M%S")를 snapshot 디렉토리명으로 쓴다. 같은 초 안에 snapshot 이
두 번 생성되면(테스트처럼 빠른 연속 호출, 또는 replay_to 의 DEV-212
pre_backup 처럼 한 replay_to 호출 안에서 restore 직전 자동 생성) 디렉토리
이름이 충돌한다.

copy_guild_source 가 호출하는 copy_tree() 는 대상 디렉토리를 비우지 않고
파일만 덮어써 병합하므로, 충돌 시 **이전 snapshot 이 이후 상태로 오염**된다.
재현: DEV-001 생성 → snapshot A(DEV-001만) → DEV-002 생성 → replay_to(과거
시점, snapshot A 로 복원) 호출. replay_to 내부에서 DEV-212 pre_backup 용
snapshot B 를 생성하는데, A/B 가 같은 초에 만들어지면 B 의 copy_guild_source
가 A 의 디렉토리에 DEV-002.md 를 병합해버려, 그 다음 A 로 복원해도 DEV-002
가 되살아남 — "과거 시점 복원"이 깨지는 심각한 버그.

디버그: eprintln 으로 snapshot 디렉토리 내용을 restore 전후로 찍어 확인
(before: [DEV-001, DEV-002], snapshot A 원본엔 DEV-001만 있었는데 restore
후에도 DEV-002 존재 — A 가 오염된 것으로 확인).

수정 (core/src/snapshot.rs):
- create_snapshot(): 디렉토리 존재 시 `-01`, `-02` ... 접미사로 유니크화.
- snapshot_time() / ts_to_local_display(): 접미사 허용 위해 앞 15자
  ("YYYYMMDD-HHMMSS" 고정폭)만 파싱 대상으로.

검증: cargo test -p openguild-core --lib replay:: / snapshot:: 전체 통과
(replay 4개, snapshot 16개). cargo clippy --workspace --all-targets
-D warnings 통과. cargo test --workspace --release 전체 통과(core 308 /
server 171 / cli 82, 0 failed).

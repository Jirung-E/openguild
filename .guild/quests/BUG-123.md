admin 보고:
- 도서관 트리 뷰일 때 폴더 접기가 안 됨.
- 폴더 삭제 불가 경고가 시스템 다이얼로그(네이티브 confirm/alert)로 뜸 —
  커스텀 다이얼로그로 떠야 함. 이건 저번에도 비슷하게 지적했었음(네이티브
  다이얼로그 대신 인앱 커스텀 다이얼로그 쓰라고).

## 원인
- 폴더 접기: `LibraryFolderTree.svelte` 에 애초에 접기/펼치기 기능 자체가
  구현돼 있지 않았음(DEV-239 최초 구현부터 없음 — 회귀 아니라 누락).
- 다이얼로그: `library/+page.svelte` 의 `deleteFolder()` 가 네이티브
  `confirm()`/`alert()` 를 그대로 사용 — 앱 전역엔 이미 `showToast`
  (alert 대체) + `ConfirmDialog`(confirm 대체) 컨벤션이 있는데(다른
  페이지들은 이미 적용돼 있음, +layout.svelte 주석 참고) 도서관 폴더
  삭제 경로만 빠져있었음.

## 수정
- `LibraryFolderTree.svelte`: 폴더 행에 토글 화살표(▶/▼) 추가. 부모
  (`library/+page.svelte`)가 `collapsedFolders: Set<string>` 로 상태 관리,
  재귀 컴포넌트에 prop 으로 전파. 접히면 하위 폴더/문서 렌더 스킵.
- `library/+page.svelte`: 문서 삭제와 동일한 패턴으로 `confirmDeleteFolderPath`
  state + `ConfirmDialog` 추가, 실패 시 `alert()` 대신 `showToast(..., 'error')`.
  문서 삭제 실패 alert() 도 같은 이유로 showToast 로 통일.

## 테스트 방법
- `cd gui/frontend && npm run check && npm run check:no-hex && npm test -- --run`.
- 실기: 트리 뷰에서 하위 폴더/문서 있는 폴더의 ▼ 클릭 → 접힘(▶), 다시 클릭
  → 펼침. 비어있지 않은 폴더 삭제 시도 → 실패 메시지가 인앱 toast 로
  뜨는지(네이티브 alert 아님). 삭제 버튼 클릭 시 확인 창이 인앱
  ConfirmDialog 로 뜨는지.

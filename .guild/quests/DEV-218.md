questIndex 에 BOOK 문서 추가(kind='book'). BOOK-NNN 은 XXX-NNN 형식이라 기존 cross-link 정규식(bare+[[..]])에 자동 포함 — refHref 에 book → /library?id= 분기와 자동완성 라벨('도서관 ·')만 추가. DEV-173(규칙 cross-link)과 동일 패턴, 편집기 공통(editor-links + textarea-wikilink). 선행: GUI 페이지.

## 구현 (2026-07-05)
- questIndex.ts: IndexedRef.kind 에 'book' 추가, libraryApi.list() 를 인덱스
  적재에 포함(개별 catch — rules 와 동일), refHref book → `/library?id=`.
- MarkdownView.svelte: guessKind 에 BOOK-NNN 미존재 추정 분기 + KIND_LABEL
  '도서관' (링크 title/미존재 툴팁).
- editor-links.ts KIND_LABEL / textarea-wikilink.ts WikiItem.kind /
  QuestCommentsSection 팝업 라벨('도서관 · ') 에 book 추가.
- 테스트: questIndex.test.ts(refHref book), textarea-wikilink.test.ts
  (BOOK ID [[ 매칭 + 기존 빈-[[ 전체 후보 케이스에 자동 포함).
- ※ DEV-220 결정대로 bare 인식은 없음 — 제목의 "bare 인식"은 DEV-220 이전
  표현. `[[BOOK-NNN]]` 명시형만.

## 테스트 방법
- `cd gui/frontend && npm run check && npm test -- --run` (신규 2 케이스).
- 실기 (GUI, 도서관 문서 1개 이상 만든 뒤):
  1. quest 본문 편집기에서 `[[BOOK` → 자동완성에 '도서관 · 제목' 후보,
     선택 시 `[[BOOK-001]]` 삽입.
  2. 저장 후 렌더에서 BOOK-001 파랑 링크 → 클릭 시 /library 해당 문서.
  3. `[[BOOK-999]]` (미존재) → 빨강 + "존재하지 않는 도서관" 툴팁.
  4. 댓글 textarea 에서도 동일 자동완성/라벨.
  5. 규칙/캠페인/퀘스트 링크 회귀 확인.

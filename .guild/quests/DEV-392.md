## 무엇

관리 페이지의 **태그 정의 편집**(만들기 · 색 · 설명 · 삭제)을 **태그 목록 페이지(`/tags`)** 로
옮기고, 관리 페이지의 태그 섹션을 없앤다.

## 왜

같은 대상을 두 화면이 나눠 갖고 있다.

| | 태그 목록 (`/tags`) | 관리 → 태그 정의 |
|---|---|---|
| 하는 일 | 사용 현황 — 태그별 사용 횟수, 붙은 문서 | 정의 편집 |
| 쓰기 | 없음 | 있음 |
| 보이는 태그 | 쓰이는 것 + 정의만 있는 것(0회) | 정의된 것만 |

목록에서 본 색을 바꾸려면 관리 페이지로 가야 한다. 태그는 퀘스트·문서에 붙이는 일상
분류이지 길드 구조 설정이 아니라 관리 페이지에 있는 것이 어색하다(admin 지적).

## 할 것

- 태그 목록의 줄마다 색·설명 편집, 삭제. 목록 위에 "새 태그 정의".
- 정의 없이 쓰이기만 하는 태그에는 "정의 만들기"(색을 주려면 정의가 필요하다).
- 관리 페이지의 `AdminTagDefsSection` 제거.
- **태그 목록 페이지 i18n** — 지금 문구가 한국어로 박혀 있다("태그 목록", "태그 검색…",
  "사용처 없음" 등). 영어 UI 에서 이 페이지만 한국어로 남는다.
- 웹(원격)에서도 편집이 되는지 — 태그 정의는 길드 공유 데이터라 관리 페이지와 같은 권한.

## 구현

- `/tags` 줄마다: 정의된 태그는 설명 표시 + [편집] [정의 삭제], 쓰이기만 하는 태그는 [정의 만들기]
  (그 이름 그대로 — 이름 입력란을 또 받지 않는다). 편집은 그 줄 아래 한 줄(색·설명·저장·취소).
- 목록 위 [+ 새 태그 정의] — 이름·색·설명. 검색은 설명도 본다.
- 삭제는 확인 창(`ConfirmDialog`) — "문서에 붙은 태그는 남고 색만 기본으로".
- 관리 페이지의 `AdminTagDefsSection` 삭제, `adminTags.*` 문구를 `tags.*` 로 교체.
- 페이지 문구 전부 i18n(제목·개수·검색·로딩·빈 목록·문서 종류).

### 덤으로 고친 것 — 이름 규칙이 코어와 달랐다

예전 관리 화면은 이름을 `^[a-z0-9_]+$` 로 검사했는데 코어 `validate_tag_slug` 는 `-` 도
받는다. `needs-review` 처럼 코어가 받는 이름을 화면이 거절했다. 코어 규칙(`a-z0-9_-`, 32자)에
맞췄다. 한글처럼 코어가 못 받는 이름으로 쓰인 태그에는 [정의 만들기]를 안 그린다(눌러도
실패한다).

## 확인한 것

- 화면 시험 4개(`routes/tags/tags.test.ts`): 정의된 태그의 설명·버튼 / 쓰이기만 하는 태그에서
  그 이름으로 정의 / 한글 이름에는 버튼 없음 / `-` 든 새 이름 저장. 이름 규칙을 옛것으로
  되돌리면 2개 실패.
- `just test` 전체 통과.

## 브라우저로 직접 확인 (admin 요청)

Playwright Chromium 으로 테스트 길드 웹(3100)을 실제로 조작했다.

| 흐름 | 결과 |
|---|---|
| 쓰이기만 하는 `backend` → 정의 만들기 | 이름 입력란 없이 색·설명만, 저장 뒤 [편집][정의 삭제]로 바뀜, 칩 색 반영, `.guild/tags/backend.toml` 생성 |
| 편집 | 저장된 색·설명이 채워져 열림, 수정 반영 |
| 새 정의 `pw-needs-review` | 저장, 펼치면 "사용처 없음 (정의만 있음)" |
| 잘못된 이름 `Bad Name` | 저장 안 됨, 안내 토스트 |
| 검색 | 설명("수정")으로도 걸림 |
| 정의만 있는 태그 삭제 | 확인 창 → 목록에서 사라짐 |
| 쓰이는 태그 정의 삭제 | 태그는 남고 색이 빠지며 [정의 만들기]로 돌아감 |
| 한글 태그(`리팩터링`) | 버튼 없음 |
| 영어 | 제목·개수·버튼·문서 종류 전부 영어 |
| 400px 폭 | 가로 스크롤 없음 |
| 관리 페이지 | 태그 정의 섹션 없음 |
| 콘솔 오류 | 없음 |

만든 정의는 시험 끝에 전부 지웠다(원래 있던 `notify` 만 남음).

### 그 과정에서 찾아 고친 화면 결함

1. **펼침 화살표(›)가 줄마다 다른 자리에 있었다.** 끝에 뒀더니 오른쪽 버튼 수(0·1·2개)에
   따라 밀려 목록이 들쭉날쭉했다 → 맨 앞으로.
2. **좁은 화면에서 검색창 왼쪽에 빈자리.** `margin-left:auto` + 고정 폭이 줄바꿈된 줄에서도
   오른쪽으로 밀었다 → 남은 폭을 채우게.
3. **편집 중인 줄에 [정의 만들기]/[편집] 버튼이 그대로 남아** 아래 줄의 저장·취소와 헷갈렸다 →
   편집 중에는 숨긴다.
4. 이름 규칙 안내 문구 "소문자·숫자·-·_ 만" 이 읽기 어려워 "영문 소문자, 숫자, -, _ 만" 으로.

## 화면에서 "정의" 라는 말을 뺐다

admin: *"애초에 '정의'가 뭔데?"* — 코드 용어(tag def)를 그대로 화면에 올려 무엇을 하는 버튼인지
읽히지 않았다. 정의는 태그에 붙이는 **색과 설명**일 뿐이다.

| 전 | 후 |
|---|---|
| 정의 만들기 | 색 지정 |
| 정의 삭제 | 색·설명 지우기 |
| + 새 태그 정의 | + 새 태그 |
| 사용처 없음 (정의만 있음) | 아직 붙은 곳 없음 |
| 안내: "정의(.guild/tags/)가 없어도 …" | "색과 설명은 선택이고, 달지 않아도 태그는 그대로 쓸 수 있습니다." |
| 삭제 확인 | "색과 설명을 지울까요? 문서에 붙은 태그는 그대로 남습니다. 아무 데도 안 붙은 태그라면 목록에서도 사라집니다." |

브라우저로 확인 — 페이지 본문에 "정의" 가 한 번도 안 나온다. 한글 태그에 [색 지정]이 안 보이던
것은 [[BUG-290]] 에서 코어 규칙을 고쳤다.

## 테스트 방법

- 태그 목록에서 정의를 만들고 색·설명을 바꾸면 퀘스트·도서관·규칙의 태그 색에 반영된다.
- 삭제하면 사용처의 태그는 남고 색만 기본으로 돌아간다.
- 관리 페이지에 태그 섹션이 없다.
- 영어로 바꾸면 태그 목록 페이지 문구도 영어다.

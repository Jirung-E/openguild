## 증상 (admin 보고)

배율을 올려도 크기가 안 변하거나 경계를 넘는 곳들.

- 작업기록 제목 옆 아이콘, 날짜 선택 버튼의 달력 아이콘
- 캠페인·퀘스트 생성/편집의 달력 아이콘
- 캠페인 페이지 '배너' 버튼 아이콘
- 문서 상세 '삭제' 버튼의 휴지통 아이콘
- 홈 컨베이어의 `<` `>` `정지` 버튼 아이콘
- 문서 상세의 '댓글로' '메모로' 버튼 아이콘
- **규칙 페이지 좌측의 버튼·태그·문서제목이 경계를 넘음**
- **도서관 리스트뷰도 같은 현상**(스크린샷)

## 원인 둘

### 1. `Icon.svelte` 가 px 숫자를 그대로 SVG 속성에 넣는다

```svelte
let { name, size = 14 } = $props();
<svg width={size} height={size}>
```

`size` 는 호출측이 px 숫자로 준다(`size={12}`). SVG 의 `width`/`height`
**속성**은 px 단위라 root font-size 를 따라가지 않는다 — 버튼은 커지는데 안의
아이콘만 그대로였다.

[[BUG-246]] 에서 같은 함정을 **TitleBar 와 Nav 의 인라인 SVG** 에 대해 고쳤는데,
공용 컴포넌트인 이쪽은 놓쳤다. 보고된 아이콘이 전부 여기를 거친다.

### 2. 사이드바 폭이 px 고정

```css
routes/library:  grid-template-columns: 260px 1fr;
routes/rules:    grid-template-columns: 240px 1fr;
```

칸은 고정인데 안의 내용만 커지니 넘친다.

**[[BUG-253]] 의 조사가 이걸 놓쳤다.** 그때 훑은 속성이
`width / height / min-* / max-* / font-size` 뿐이라
`grid-template-columns` · `flex-basis` · `flex` 가 빠져 있었다. 다시 훑으니
10건 더 나왔다.

## 수정

**Icon.svelte** — 호출부를 전부 고치는 대신 컴포넌트에서 rem 으로 환산한다.

```ts
const px = $derived(`${size / 16}rem`);   // size=14 → 0.875rem = 기존과 동일
```

16 으로 나누므로 **기본 배율에서 크기가 그대로**다. 호출부 13개 파일을 손대지
않는다.

**인라인 SVG** — `DateField` 의 달력, `SearchPalette` 의 13px 3건. 속성은
폴백으로 두고 CSS 로 덮는다(BUG-246 과 같은 방식).

**고정 폭 10건** — library/rules 사이드바, 컨베이어 카드(200px), 설정
사이드바(160px)와 그리드(180px), 퀘스트 상세(200px), 도서관 그리드(92px).

## 검증 (브라우저 실측, 1400×900)

| 화면 | 배율 1.0 | 배율 2.0 |
|------|---------|---------|
| 작업기록 아이콘 5개 | 12 / 14 / 15 / 16 | **24 / 28 / 30 / 32** |
| 퀘스트 상세 삭제(휴지통) | 14 | **28** |
| 도서관 아이콘 | 15 | **30** |

전부 정확히 2배. 배율 1.0 값은 기존과 같다.

**넘침**: 도서관 사이드바에서 경계를 벗어난 요소 **0건**(수정 전 스크린샷에서는
검색란·체크박스·정렬 셀렉터가 전부 넘쳤다). 규칙 페이지도 200% 스크린샷으로
좌측 목록이 경계 안에 들어오는 것을 확인했다.

## 못 한 것

- **캠페인 배너 버튼 / 캠페인·퀘스트 생성 모달의 달력** 은 화면을 띄워
  확인하지 못했다. 둘 다 `Icon.svelte` 또는 `DateField` 를 쓰므로 같은 수정에
  덮이지만, 눈으로 본 것은 아니다.
- 홈 컨베이어 버튼도 마찬가지 — `Icon.svelte` 경로다.

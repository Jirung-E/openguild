## 증상 (admin 보고)

배율을 올려도 크기가 안 변하거나 경계를 넘는 곳들.

- 작업기록 제목 옆 아이콘, 날짜 선택 버튼의 달력 아이콘
- 캠페인·퀘스트 생성/편집의 달력 아이콘
- 캠페인 페이지 '배너' 버튼 아이콘
- 문서 상세 '삭제' 버튼의 휴지통 아이콘
- 홈 컨베이어의 `<` `>` `정지` 버튼 아이콘
- 문서 상세의 '댓글로' '메모로' 버튼 아이콘
- **규칙 페이지 좌측의 버튼·태그·문서제목이 경계를 넘음**
- **도서관 리스트뷰도 같은 현상**(스크린샷)

## 원인 둘

### 1. `Icon.svelte` 가 px 숫자를 그대로 SVG 속성에 넣는다

```svelte
let { name, size = 14 } = $props();
<svg width={size} height={size}>
```

`size` 는 호출측이 px 숫자로 준다(`size={12}`). SVG 의 `width`/`height`
**속성**은 px 단위라 root font-size 를 따라가지 않는다 — 버튼은 커지는데 안의
아이콘만 그대로였다.

[[BUG-246]] 에서 같은 함정을 **TitleBar 와 Nav 의 인라인 SVG** 에 대해 고쳤는데,
공용 컴포넌트인 이쪽은 놓쳤다. 보고된 아이콘이 전부 여기를 거친다.

### 2. 사이드바 폭이 px 고정

```css
routes/library:  grid-template-columns: 260px 1fr;
routes/rules:    grid-template-columns: 240px 1fr;
```

칸은 고정인데 안의 내용만 커지니 넘친다.

**[[BUG-253]] 의 조사가 이걸 놓쳤다.** 그때 훑은 속성이
`width / height / min-* / max-* / font-size` 뿐이라
`grid-template-columns` · `flex-basis` · `flex` 가 빠져 있었다. 다시 훑으니
10건 더 나왔다.

## 수정

**Icon.svelte** — 호출부를 전부 고치는 대신 컴포넌트에서 rem 으로 환산한다.

```ts
const px = $derived(`${size / 16}rem`);   // size=14 → 0.875rem = 기존과 동일
```

16 으로 나누므로 **기본 배율에서 크기가 그대로**다. 호출부 13개 파일을 손대지
않는다.

**인라인 SVG** — `DateField` 의 달력, `SearchPalette` 의 13px 3건. 속성은
폴백으로 두고 CSS 로 덮는다(BUG-246 과 같은 방식).

**고정 폭 10건** — library/rules 사이드바, 컨베이어 카드(200px), 설정
사이드바(160px)와 그리드(180px), 퀘스트 상세(200px), 도서관 그리드(92px).

## 2차 — admin 재보고 후 (같은 함정 2건 + 정렬 1건)

> * 배너 버튼과 삭제 버튼의 아이콘이 글자와 높이가 달라보임
> * 홈 페이지에서 컨베이어의 조작을 위한 버튼들의 아이콘은 안고쳐졌다.
> * 컨베이어 버튼의 아이콘도 버튼 중앙에 안맞는다.

1차가 **`Icon.svelte` 한 파일만** 보고 끝낸 것이 누락의 원인이다. 위 "못 한
것" 에 적은 "컨베이어도 `Icon.svelte` 경로" 라는 추정 자체가 틀렸다.

### 1. `PlayPauseIcon.svelte` — 같은 px 함정을 가진 두 번째 컴포넌트

컨베이어의 정지/재생 버튼은 `Icon` 이 아니라 **별도 컴포넌트**를 쓴다.
[[BUG-169]] 에서 이모지 `▶`/`⏸` 를 SVG 로 바꾸며 CampaignCarousel /
CampaignConveyor / QuestNodeConveyor 세 곳 공통으로 뽑은 형제다.

```svelte
let { paused = false, size = 11 } = $props();
<svg width={size} height={size} ...>     ← Icon.svelte 와 완전히 같은 결함
```

`Icon.svelte` 와 같은 방식(`size / 16` rem)으로 고쳤다. 기본 배율에서 크기는
그대로다(11 → 0.6875rem).

**`size` prop 을 SVG 속성에 넣는 컴포넌트는 이 둘이 전부**임을 확인했다
(`lib/components` 전수 — `$props` 로 `size` 를 받는 컴포넌트가 `Icon` 과
`PlayPauseIcon` 둘뿐).

### 2. 원형 버튼 안에서 아이콘이 중앙에 안 맞음

`.play-pause` 3곳과 `.arrow` 는 `width/height: 1.8rem` 정사각인데
`display`/`align-items` 가 없었다. 인라인 SVG 는 **기준선 위에 얹히므로**
line box 의 descender 만큼 아래로 밀린다.

`display: inline-flex; align-items: center; justify-content: center` 추가.

### 3. 아이콘 + 글자 버튼의 세로 정렬 (배너 / 삭제)

`Icon.svelte` 주석은 원래 "부모에 `inline-flex; align-items:center` 를 주면
기준선이 맞는다" 고 안내했는데, **호출부가 그걸 안 지킨 곳들**이 있었다 —
퀘스트 상세 `.btn-delete`, 캠페인 상세의 `.back/.btn-delete/.status-badge/
.btn-edit` 공용 규칙(배너 버튼이 여기 해당).

두 겹으로 막았다.

| 수단 | 대상 | 실측 어긋남(200%) |
|------|------|------------------|
| 없음(기존) | — | **2.00px** |
| `Icon.svelte` 에 `vertical-align: middle` | 모든 인라인 사용처 | 1.63px |
| 부모 `inline-flex; align-items:center` | 지목된 버튼들 | **0.23px** |

`vertical-align` 은 x-height 기준이라 완전히는 못 맞춘다 — 그래서 **부모
flex 가 본 수정**이고, `vertical-align` 은 앞으로 나올 새 호출부를 위한
안전망이다. 부모가 flex 인 곳에서는 SVG 가 flex item 이 되어
`vertical-align` 이 무시되므로 **기존 정렬에 영향이 없음**을 브라우저에서
확인했다(위 표의 0.23px 이 `vertical-align: baseline` 을 강제해도 동일).

## 2차 검증 (브라우저 실측, 1400×900, test-guild)

**컨베이어 정지 버튼** — 버튼 28.8px / 아이콘 11px 기준

| | 위 | 아래 | 좌 | 우 |
|---|---|---|---|---|
| 수정 전 | 8.09 | 9.70 | 8.90 | 8.90 |
| 수정 후 | **8.90** | **8.90** | **8.90** | **8.90** |

세로로 1.6px 위에 치우쳐 있던 것이 정확히 중앙으로 왔다.

**배율 200%** — root 16px → 32px

| | 100% | 200% |
|---|---|---|
| 정지 아이콘 | 11 | **22** |
| 정지 버튼 | 28.8 | 57.59 |
| 여백(4방향) | 8.9 | **17.8** (전부 동일) |
| `‹`/`›` 버튼 | 28.8 | 57.59 |

정확히 2배. **화살표는 원래부터 배율을 따라가고 있었다** — 글자(`‹`)라
`font-size: 1rem` 이 이미 rem 이었다. 옆의 정지 버튼만 안 커져서 셋 다
안 변하는 것처럼 보였던 것으로 보인다.

**삭제 버튼**(퀘스트 상세, 200%): 아이콘/글자 중심 차이 2.00px → **0.23px**,
아이콘 28px(=14×2), 간격은 `gap: 0.3em` = 7.68px 하나만 적용(마크업의 공백은
flex 에서 접혀 이중 간격이 안 생기는 것 확인).

**전 페이지 감사** — "아이콘 SVG 와 글자가 같은 부모에 있는데 부모가 flex/grid
가 아닌" 요소를 DOM 에서 세는 스크립트를 `/`, `/quests`, `/quests/{id}`,
`/campaigns`, `/campaigns/{slug}`, `/library`, `/rules`, `/worklog`, `/tags`,
`/settings` 에 돌렸다. 수정 전 `/quests/{id}` 에서 1건(`.btn-delete`),
수정 후 **전 페이지 0건**.

배너 버튼은 Tauri 전용(`{#if isTauri}`)이라 HTTP 화면에서는 렌더되지 않는다 —
같은 공용 CSS 규칙에 걸리는 것은 코드로 확인했으나 **눈으로 본 것은 아니다.**

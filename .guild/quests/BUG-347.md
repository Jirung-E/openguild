**윈도우에서만 깨지는 시험들 + CI 에 윈도우가 없다**(2026-10-02, 윈도우 세션이 `cargo test -p openguild-core --lib`
에서 16개 실패를 보고 — 경로 탈출 하나(BUG-346)를 빼면 전부 시험 쪽).

| 시험 | 원인 | 고침 |
|---|---|---|
| 보드 위치 4개 (`a_position_survives_deleting_the_index` 등) | 열린 `index.db` 를 지우려 했다 — 윈도우는 열린 파일을 못 지운다. Store 를 블록 밖으로 버리는 것만으로는 연결이 바로 안 닫힌다 | 지우기 전에 `index_pool` · `journal_pool` 을 닫는다 |
| `a_source_recorded_with_a_verbatim_prefix_still_works` | 윈도우 `canonicalize` 는 이미 `\\?\` 를 붙여 준다 — 시험이 한 번 더 붙여 `\\?\\\?\C:\…` 를 시험했다 | 떼고 한 번만 붙인다 |
| `changing_an_imported_file_outside_the_folder_does_not_ask_again` | 윈도우 경로를 rhai 글자에 그대로 넣어 `\U` 가 깨진 이스케이프 → 컴파일 실패 | `/` 로 바꿔 넣는다(윈도우에서도 구분자) |
| `sh` 로 훅을 돌리는 시험 15개 | Git Bash 없는 윈도우에 `sh` 가 없다 | `test_env::have_sh()` 가 없으면 건너뛴다(CI 윈도우 러너에는 있어 돈다) |

- **CI 에 윈도우 잡**(`check.yml` `windows`) — 코어 · CLI · 서버 시험. gui 크레이트는 릴리스 워크플로가 윈도우에서 빌드한다.
  지금까지 리눅스 · 맥만 돌아서 이 실패들과 BUG-346 을 몰랐다.

## 시험

- 맥에서 고친 시험들이 그대로 통과한다.
- CI 윈도우 잡이 초록이면 된다. 윈도우 세션으로도 한 번 돌린다.

## 후속 (2026-10-03) — 윈도우에서 다시 돌려 본 결과

윈도우 세션이 45a12a93 을 돌려 보니 Git Bash 없이 1099 통과 / 5 실패, 있으면 1100 / 4.

- **보드 위치 3개 그대로 실패** — 풀 닫기를 넣는 스크립트가 위치를 잘못 세어 **첫 시험에 네 번** 넣고 나머지 셋에는
  안 넣었다(내 실수). 각 시험의 `drop(store)` 앞에 넣었다.
- **`\?\` 시험 그대로 실패 — 시험이 아니라 실제 버그였다.** 소스를 쓰는 길드의 열쇠는 윈도우에서 소문자 · `\` 로
  맞춘다(BUG-327). 그 전에 적힌 옛 열쇠는 `used_in` 만 찾아 줬고, **실제로 싣는 `used_dirs` 는 못 찾아** 그 길드의 소스
  플러그인이 아무 말 없이 안 실렸다. 시험은 옛 열쇠를 적어 그걸 정확히 드러낸 것. → 기록을 읽을 때(`normalize`) 옛 열쇠를
  지금 규칙으로 옮기고 같은 길드끼리 합친다(`rekey`). 찾는 곳 · 쓰는 곳이 한 열쇠만 본다. `rekey` 는 규칙을 꽂아 맥에서도 시험.
- **CLI `a_plugin_from_a_source_runs_in_place_and_leaves_cleanly`**(윈도우에서 처음 돈 CLI 시험) — 시험이 만드는
  플러그인이 `sh` 만 써서 Git Bash 없는 윈도우에서 훅이 안 돌았다. 예제들처럼 `[handlers.action.run.windows]` 로
  PowerShell 갈래를 붙였다.
- 서버 시험 233개, CLI 나머지, CRLF 관련은 윈도우에서 모두 통과.

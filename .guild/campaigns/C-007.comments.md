체크리스트를 맥에서 시험 길드로 확인했습니다(develop 3f26f55d 의 release CLI · 서버). 데스크톱 앱 자리는 같은 코어를 쓰는 서버(`--remote`)가 대신했습니다 — 앱처럼 따로 도는 프로세스라 잠금도 같은 길을 탑니다.

1. 서버(앱 자리)가 두 퀘스트에 번갈아 댓글 30개, 그동안 터미널이 다른 퀘스트에 태그 30개 → 0.9초에 끝, 실패 · "바쁨" 0.
2. 서버 3개 + 터미널 3개가 **같은 퀘스트**에 태그 · 댓글을 동시에 120번 → 1~2초, 실패 0, 태그 60 · 댓글 120 모두 남음. 본문 번호도 61(생성 1 + 태그 60)로 맞음.
3. 새 퀘스트, 제목 한 번 고침 → `version = 2`. 댓글 둘 → 댓글 파일 `version="2"`, 본문은 2 그대로.
4. 메모 · 첨부 · 태그를 더한 뒤 DEV → BUG → 새 번호에 댓글 2 · 메모 · 첨부 · 태그가 다 있고, 본문 번호 3 → 4, 댓글 번호 2 그대로. `check sidecars` "주인 없는 파일 없음".
5. 백업을 잇달아 셋, 동시에 둘 → 같은 초는 `-01` … `-04` 로 이어져 목록 순서가 만든 순서와 같음.
6. 백업 → 제목 고침 → 그 백업으로 복원하면 고치기 전 제목(서버 · 파일 · CLI 모두). 다시 색인하기 약 0.9초(debug). 서버를 여러 번 다시 띄워도 바로 열림.
7. 진짜 길드를 복사해 `check sidecars` → "주인 없는 파일 없음".
8. `wait = true` 훅이 `openguild … quest comment add` 로 답글을 다는 시험 플러그인 → 터미널 · 서버 모두 0.07초에 답글이 붙음. 서버 3 + 터미널 3 이 동시에 댓글 30개 → 최대 0.58초, 답글 30개 모두.
   - 다만 **길드 폴더에서 GUILD_PATH 없이 띄운 서버**에서는 훅의 `--guild "$OPENGUILD_GUILD_DIR"` 가 `.` 이라 답글이 실패(멈추지는 않음). `--guild` 에 상대 경로를 주면 늘 실패하는 버그 → BUG-377. 앱 · CLI 는 절대 경로라 영향 없음.

곁가지: debug 빌드에서 댓글이 수백 개인 퀘스트의 댓글 읽기가 느림(276개에 0.6초, release 0.08초). `extract_attr` 가 부를 때마다 정규식을 새로 만든다 — 실사용 크기에선 문제 아님.

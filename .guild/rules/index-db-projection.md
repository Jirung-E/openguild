# index.db 는 순수 파생 투영 — 역류 금지 · 브랜치 재생성

[[file-truth-db-cache]] 를 **보강**한다. 기본 규칙은 "파일=진리, DB=캐시,
DB-only 권위상태 금지" 를 말하지만, 아래 두 가지를 명시하지 않아 이번에
사고가 났다(도서관 BOOK-001 에 상세·역류 지도).

## 1. DB → 파일 역류 금지

파일 → DB 만 허용. **자가치유(self-heal)가 DB 값을 파일에 되쓰면 안 된다.**
- 실사고: history export(A1)·counter write-back(A2, DEV-242)·`updated_at`
  write-back(B1, BUG-145). 전부 "파일을 신선하게" 라는 선의였지만, 캐시가
  브랜치를 안 따라가므로 **어긋난 캐시가 진리를 오염**시킨다.
- 카운터조차 역류 불필요 — 다음 ID 는 디스크 파일만으로
  `max(파일 카운터, 실존 최대번호)+1`.

## 2. index.db 는 branch-blind — 파일이 바뀌면 다시 만든다

작업폴더에 index.db 는 하나뿐이고 git 이 밑에서 브랜치별로 파일을 갈아끼운다.
DB 는 자기가 어느 브랜치를 반영하는지 모른다. 그러므로 **브랜치 전환 후**
`rm .guild/index.db && openguild reindex` 로 투영을 재생성한다 — 회피책이
아니라 불변식의 일부.
